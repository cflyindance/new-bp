## 一、目标与边界

### 1.1 目标

在**不接入真实终端、不实现真实 Sync API** 的前提下，在 admin-web 演示环境中模拟完整的「保存并下发」体验，包括：

- 下发按钮与确认弹窗
- 下发进度与状态流转（pending → in_progress → success / partial_success / failed）
- 下发记录列表与详情查看
- 失败重试、按门店/产线/设备展开
- 设置页内的「云端版本 vs 已下发版本」状态条

用于产品评审、客户演示、实施培训，验证信息架构与交互流程。

### 1.2 明确不做

| 不做 | 说明 |
|------|------|
| 真实 Push/Pull 协议 | 无 WebSocket/MQTT/终端 ACK |
| 真实配置 payload 序列化 | 不下发实际菜单/设置 JSON 到 POS |
| 后端 API | 全部 localStorage + 前端定时器 |
| 与 POS/Kiosk/eMenu 联调 | 终端团队不参与本阶段 |

### 1.3 设计原则

1. **数据模型对齐正式方案**：复用 `DeploymentBatch` / `DeploymentItem` / `DeploymentTarget` 结构，便于后续替换 mock 引擎为真实服务。
2. **遵循现有工程惯例**：`create*Store` + `localStorage` + `*-ui.ts` render/bind + Hash 路由。
3. **可演示、可重置**：提供种子数据与「清空下发记录」入口，方便反复演示。
4. **保存与下发分离**：设置页仍即时自动保存；下发为独立动作（与正式方案一致）。

## 五、模拟状态机

### 5.1 触发流程

```
用户点击「保存并下发」
    │
    ├─ 1. deployment-trigger-ui 打开确认弹窗
    ├─ 2. 用户确认 → createDeploymentBatch()
    │      · 解析当前 scope（session-scope）
    │      · 解析 originNav（当前 path + catalog）
    │      · 展开 storeIds × domains × targets
    │      · status = pending, progressPercent = 0
    ├─ 3. 写入 deployment-store
    ├─ 4. startSimulation(batchId)
    └─ 5. 打开进度抽屉 / Toast「下发已开始」
```

### 5.2 模拟器时序（`deployment-simulator.ts`）

使用 `setTimeout` / `setInterval` 分阶段推进，**总时长约 8～15 秒**（可配置 `DEPLOYMENT_SIM_SPEED`）。

```
Phase 1 · creating     (0.5s)   batch.status → in_progress, progress 5%
Phase 2 · pushing      (2～8s)  逐个 item: pending → pushing
Phase 3 · acking       (3～10s) 逐个 target: syncing → success | failed | offline
Phase 4 · done         (0.3s)   汇总 batch 终态, progress 100%
```

**单项推进规则：**

```typescript
// 伪代码
function advanceTarget(target: DeploymentTarget): void {
  const roll = Math.random();
  if (roll < 0.05) target.status = 'offline';      // 5% 离线
  else if (roll < 0.10) target.status = 'failed';  // 5% 失败
  else target.status = 'success';

  if (target.status === 'success') {
    target.localVersion = item.configVersion;
    target.ackedAt = now();
  } else if (target.status === 'failed') {
    target.errorDetail = pickRandom(MOCK_ERROR_MESSAGES);
  }
}

function rollupItem(item: DeploymentItem): void {
  const targets = item.targets;
  const allSuccess = targets.every(t => t.status === 'success');
  const anySuccess = targets.some(t => t.status === 'success');
  const allFailed = targets.every(t => ['failed','offline'].includes(t.status));

  if (allSuccess) item.status = 'success';
  else if (allFailed) item.status = 'failed';
  else if (anySuccess) item.status = 'success';  // 部分设备成功仍算 item 成功（可配置）
  else item.status = 'timeout';
}

function rollupBatch(batch: DeploymentBatch): void {
  const items = batch.items;
  batch.successCount = items.filter(i => i.status === 'success').length;
  batch.failedCount = items.filter(i => ['failed','timeout'].includes(i.status)).length;
  batch.pendingCount = items.filter(i => ['pending','pushing'].includes(i.status)).length;

  if (batch.pendingCount > 0) batch.status = 'in_progress';
  else if (batch.failedCount === 0) batch.status = 'success';
  else if (batch.successCount === 0) batch.status = 'failed';
  else batch.status = 'partial_success';
}
```

### 5.3 模拟失败原因库

```typescript
const MOCK_ERROR_MESSAGES = [
  '设备离线，超过 30s 未响应',
  '本地版本冲突，需人工处理',
  '打印机驱动未就绪',
  '网络超时（模拟）',
  '终端存储空间不足',
];
```

### 5.4 重试逻辑

```
用户点击「重试失败项」
    │
    ├─ 筛选 status ∈ { failed, timeout, offline } 的 item/target
    ├─ 重置为 pending / syncing
    ├─ retryCount++
    ├─ batch.status → in_progress
    └─ 重新 startSimulation(batchId, { onlyFailed: true })
```

重试时失败率降低（如 2%），便于演示「重试后成功」。

### 5.5 进度计算

```typescript
progressPercent = Math.round(
  (completedTargets / totalTargets) * 100
);
```

详情页与进度弹窗每 500ms 轮询 store（或监听自定义事件 `menusifu:deployment-updated`）刷新 UI。

## 九、演示脚本建议

### 9.1 场景 A：单店营业时间下发（成功）

1. 切换门店视角 → 门店管理 → 营业时间
2. 修改营业时间（自动保存，状态条显示「有未下发变更」）
3. 点击「保存并下发」→ 确认
4. 观看进度弹窗约 8s → 全部成功
5. 进入系统设置 → 下发记录 → 查看详情

### 9.2 场景 B：连锁品牌菜单下发（部分成功 + 重试）

1. 切换品牌视角 → 商品中心 → 品牌菜单
2. 编辑菜单 →「保存并下发」→ 选择「品牌下全部门店」
3. 模拟器产生 1 店失败 → 列表显示「部分成功」
4. 详情页查看失败设备 → 点击「重试失败项」
5. 重试成功 → 状态变为「成功」

### 9.3 场景 C：Dashboard 告警

1. 使用「重置演示数据」加载含失败批次的种子
2. 回到 Dashboard → 看到下发异常待办
3. 点击跳转下发记录

### 9.4 演示控制面板（可选，P1）

在 `/settings/advanced` 底部增加「下发模拟器」折叠区：

| 控制项 | 说明 |
|--------|------|
| 模拟速度 | 快(3s) / 正常(10s) / 慢(20s) |
| 失败率 | 0% / 5% / 20% |
| 离线率 | 0% / 5% |
| 重置种子数据 | 恢复 5 条历史记录 |
| 清空全部记录 | 删除所有 batch |

## 十一、与真实下发的差异说明

| 维度 | 演示版 | 正式版（见云端下发方案） |
|------|--------|--------------------------|
| 存储 | localStorage | 后端 DB |
| 推进 | 前端 setTimeout | 下发编排服务 + 消息队列 |
| 终端 | 模拟设备清单 | 真实设备心跳 + ACK API |
| payload | 无实际数据 | 按 domain 拉取配置 JSON |
| 离线 | 随机标记 offline | 真实心跳超时判定 |
| 冲突 | 无 | 版本向量 + 冲突策略 |
| 审计 | 仅记录操作人 | 关联 auditLogId + 旧新值 |

**迁移路径：** 保留 `deployment-types.ts` 与 UI 层不变，将 `deployment-simulator.ts` 替换为调用 `POST /api/deployments` + WebSocket 进度推送；`deployment-store.ts` 改为 API client。
