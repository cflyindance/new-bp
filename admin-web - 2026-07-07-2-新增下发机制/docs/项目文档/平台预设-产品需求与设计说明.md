# 平台预设 — 产品需求与设计说明

> 版本：v0.1 · 2026-06-15  
> 状态：设计已确认（产线清单见 §3.2）  
> 关联：`admin-web/src/config/navigation.ts`、`module-settings-catalog.ts`、`foh-settings-line-scope.ts`

---






## 一、背景与目标

餐饮商家后台功能模块多、导航层级深，并非所有**经营业态**与**终端产线**组合都需要完整功能集。例如：快餐 + Kiosk 侧重前厅/后厨，正餐 + POS 侧重桌台/预约等。

**平台预设**允许平台管理员按「业态 × 产线」预先勾选应展示的功能树；商户**首次登录**完成业态/产线选择与功能确认后，侧栏及滑层、设置页仅展示预设范围内内容——**不改变系统既有导航与设置项的定义与数量**。

### 1.1 核心原则（不可违反）

1. **只读源数据**：预设树从 `NAV_MODULES`、`MODULE_SETTINGS_BY_PATH` 及设置 UI 注册表生成，禁止手改分组或遗漏设置项。
2. **结构不变**：运行时仅做可见性过滤；原始层级（一级 → 滑层二级 → 设置三级分组 → 四级设置项）保持不变。
3. **场景分组优先**：前厅等模块的三级分组取**按场景分组**（`groupCatalogItemsByCategory`），不取「按产线视图」侧栏分组。
4. **保存即生效**：预设发布成功后，侧栏与相关页面即时按新快照过滤（演示环境 localStorage；生产对接 API 后同理）。

## 二、三者关系

```
平台预设（管理员配置）
    ↓ 发布快照（业态 × 产线 × version）
首次登录引导（商户选择业态 → 产线 → 功能确认）
    ↓ 写入门店/会话上下文
侧栏 + 滑层 + 设置页（RBAC 之后再按预设过滤）
```

**示例**：平台预设中「快餐 · Kiosk」勾选一级导航「前厅管理中心」「后厨管理中心」：

- 引导页「功能确认」仅展示上述两个一级模块名称；
- 进入系统后侧栏仅显示这两项；
- 点击「前厅管理中心」打开滑层，展示该模块下**已被预设勾选**的二级导航；进入「设置」后同理展示已勾选的三级分组与四级设置项。

## 三、业态与产线

### 3.1 经营业态

左侧列表分三类（与 UI 设计稿一致）：

| 分类 | 枚举 | 预设项 |
|------|------|--------|
| **按服务方式** | `service-mode` | 快餐、休闲餐饮、外卖专营、全功能/不确定 |
| **按品类** | `category` | 茶饮、咖啡、烘焙、火锅、烧烤、自助餐、酒吧、中餐、西餐、日韩料理、正餐 |
| **自定义业态** | `custom` | 用户新增（支持编辑/删除） |

每个业态下对应的**产线列表相同**（见 §3.2）。  
业态可配置「功能画像」标签（核心 / 推荐 / 可选），仅用于预设编辑页参考与「恢复业态推荐默认」，不参与运行时过滤逻辑。

### 3.2 产线标准清单（已确认）

**与 `FOH_LINE_NAV_ORDER` 对齐，共 9 条。**  
代码源：`admin-web/src/config/foh-settings-line-scope.ts`。

| 序号 | id | 展示名 |
|------|-----|--------|
| 1 | `pos` | POS |
| 2 | `pos-go` | POS GO |
| 3 | `paypad` | PayPad |
| 4 | `kiosk` | Kiosk |
| 5 | `emenu` | eMenu |
| 6 | `sdi` | SDI |
| 7 | `online-order` | Online Order |
| 8 | `cds` | CDS |
| 9 | `store-wide` | 全店通用 |

**类型别名**：`ProductLineId = FohLineNavId`（复用现有类型，避免双源维护）。

> 说明：设计稿中「收银 POS」对应本清单中的 `pos`（及必要时 `paypad` 独立配置）；不再使用 5 条精简清单。

## 四、功能入口与页面

### 4.1 系统设置 · 平台预设（列表页）

- **入口**：系统设置滑层新增二级导航「平台预设」→ 路由建议 `#/settings/platform-preset`
- **布局**：左侧经营业态列表 + 右侧产线卡片网格
- **产线卡片信息**：名称、技术标识（如 `fast-food:kiosk`）、业态推荐数 / 当前启用数、版本号、是否已覆盖平台默认
- **操作**：查看详情、变更记录、**配置预设**（主按钮）

### 4.2 配置预设（四列编辑页）

- **路由**：`#/settings/platform-preset/:businessTypeId/:productLineId/edit`
- **标题**：配置预设 · {业态名} · {产线名}
- **四列结构**：

| 列 | 数据源 | 交互 |
|----|--------|------|
| 一级导航 | `NAV_MODULES` | 复选框，多选；带业态推荐标签 |
| 二级导航 | 选中 L1 的 `children`（滑层/折叠项） | 复选框；选中 L1 时级联全选 |
| 三级 / 分组 | 各 hub 的 `groupKey`（场景分组） | 复选框；级联同上 |
| 分组内功能 / 设置 | 各 `seq` 设置项 | 树形只读结构 + 「展示」开关；严格对应系统关系 |

- **级联规则**：
  - 勾选 L1 → 其下全部 L2、L3、L4 设为启用；
  - 取消 L1 → 子树全部取消；
  - 子节点部分选中 → 父节点 indeterminate；运行时以叶子节点 `enabled` 为准。
- **顶栏操作**：变更记录、恢复业态推荐默认
- **底栏**：保存并发布 v{N+1}

### 4.3 首次登录引导

- **触发**：账号首次登录且未完成 onboarding
- **步骤**：① 选择业态 → ② 选择产线 → ③ 功能确认（展示当前组合下已启用的 L1 列表）→ 进入系统
- **数据来源**：对应「业态 × 产线」**已发布**预设快照
- **持久化**：门店上下文（业态 id、产线 id、预设 version）；演示环境 sessionStorage / localStorage

## 五、数据模型

### 5.1 预设节点 ID（稳定键，由构建脚本生成）

```
nav:{moduleId}                           // L1
nav:{moduleId}:{childId}               // L2
settings:{settingsPath}:{groupKey}       // L3
setting:{seq}                            // L4
```

### 5.2 快照结构

```typescript
interface PlatformPresetSnapshot {
  businessTypeId: string;
  productLineId: FohLineNavId;  // 9 条产线之一
  version: number;
  publishedAt: string;
  /** 节点启用与 L4 展示开关 */
  selection: Record<PresetNodeId, { enabled: boolean; display?: boolean }>;
}

interface StoreOnboardingContext {
  businessTypeId: string;
  productLineId: FohLineNavId;
  presetVersion: number;
  completedAt: string;
}
```

### 5.3 版本与变更记录

- 每次「保存并发布」递增 version；
- 变更记录保留：操作人、时间、版本、变更摘要（可选 diff 节点数）；
- 支持查看历史版本（P3）。

## 六、运行时过滤

过滤链顺序：

```
NAV_MODULES
  → filterVisibleNavModules()     // 现有 RBAC + 单店/连锁
  → filterNavByPlatformPreset()   // 新增：业态×产线快照
  → renderSidebar()
```

| 层级 | 过滤点 |
|------|--------|
| L1 侧栏 | 模块 id 不在预设启用集 → 隐藏 |
| L2 滑层/折叠 | child id 未启用 → 隐藏；若模块无可见子项则隐藏 L1 |
| L3 设置侧栏分组 | groupKey 未启用 → 隐藏 |
| L4 设置卡片 | seq 未启用或 `display: false` → 不渲染 |

**前厅设置特殊处理**：生成 L3/L4 树时使用 `groupCatalogItemsByCategory`；按当前 `productLineId` 过滤 `fohSeqAppliesToLine(seq, lineId)` 决定哪些 seq 出现在树中，但分组仍按场景 key 组织。

## 七、树生成与完整性校验

新增脚本（建议）：`scripts/build-platform-preset-tree.mjs`

- 输入：`navigation.ts`、`module-settings-catalog.ts`、设置 seq 注册表
- 输出：`platform-preset-tree.generated.ts`（全量节点清单 + 父子关系）
- CI 校验：
  - L4 节点数 = 目录中 seq 总数（允许按产线 scope 标记「不适用」，但不删除节点定义）；
  - 每个 L3 groupKey 必须存在于对应 hub；
  - 禁止 orphan 节点。
