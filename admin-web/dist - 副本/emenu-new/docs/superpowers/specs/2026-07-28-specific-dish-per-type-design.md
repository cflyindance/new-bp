# 指定菜品每人每轮/每轮独立配置设计

## 背景

“每人每轮/每轮下单菜品数量限制”配置中，每个就餐人数区间包含两类规则：

- 下单菜品总数限制。
- 指定菜品或菜品集限制。

当前指定规则没有独立的作用范围，前台计算和后台展示都直接使用总数规则的 `perType`。因此，将总数规则从“每轮”切换为“每人每轮”时，下面的指定规则也会同步变成“每人每轮”。

本次需求是在保持现有客户行为不变的基础上，让每条指定规则独立选择“每轮”或“每人每轮”。

## 业务规则

`perType` 使用现有枚举：

- `0`：每轮，配置数量不乘就餐人数。
- `1`：每人每轮，配置数量乘有效就餐人数。

指定规则的选择影响：

- 单个指定菜品的最大份数。
- 指定菜品集按“份”限制时，菜品集的总份数。
- 指定菜品集按“种”限制时，菜品集的总种数。
- 指定菜品集按“种”限制时，“每种菜品最多 N 份”的数量。

“每轮相同菜品最多 N 份”保持现有语义，始终按每轮计算，不乘就餐人数。

总数规则的最小值、最大值、`minCountPerRound` 和 `maxCountPerRound` 继续使用外层规则的 `perType`，不受指定规则选择影响。

## 数据结构

在每条 `specificDishLimit` 中增加 `perType`，复用现有枚举，不增加新的配置项或映射结构。

```js
{
  before: 2,
  perType: 1,
  minCount: 1,
  maxCount: 2,
  specificDishLimit: [
    {
      perType: 0,
      specificDishType: 0,
      dishes: [12998],
      quantity: 1,
      unit: 0,
    },
  ],
}
```

外层 `perType` 只控制总数规则；内层 `specificDishLimit[].perType` 控制对应指定规则。

## 后台配置页

文件：`src/components/ConfigCommon/DishQuantityPerRoundConfig.jsx`

- 将指定规则文案中的静态“每轮/每人每轮”文本替换为现有 `perTypeOptions` 选择器。
- 每条指定规则独立读写自身的 `perType`。
- 新增指定规则时，默认使用当前外层总数规则的 `perType`，保持现有操作习惯。
- 老数据缺少内层 `perType` 时，沿用组件现有的兼容方式，将当前外层 `perType` 写入页面配置状态。
- 初始化后，修改外层总数规则不再改变已有指定规则。
- 复用现有翻译和选项，不新增文案键，不抽取 helper，不进行无关重构。

## 前台限制逻辑

文件：`src/hooks/useCheckDishBeforeOrder.js`

命中指定规则后，按以下顺序确定其作用范围：

```js
isDishInConfig.perType ?? matchedRule.perType
```

- 新数据使用指定规则自身的 `perType`。
- 老数据没有内层字段时，回退到外层 `perType`，保持升级前行为。
- 单菜品、菜品集总份数、菜品集总种数和“每种菜品”子限制都使用该结果决定是否乘有效就餐人数。
- “每轮相同菜品”子限制继续使用原始数量，不乘人数。
- 总数限制、购物车提交校验、Buffet 菜品过滤和权限提示流程保持不变。

## 兼容策略

### 未打开后台的老客户

存量全局配置或设备配置中没有内层 `perType`。前台通过回退外层 `matchedRule.perType`，行为与升级前完全一致。

### 打开后台但不保存

页面状态会按现有兼容模式补充内层字段，但不会写入服务端配置，前台持久化行为不变。

### 打开后台并保存

每条老指定规则保存为当时继承的外层 `perType`。保存前后限制数量不变；之后外层和内层可以独立修改。

### 新增指定规则

新规则默认继承当前外层值，首次展示和原有行为一致。用户主动切换内层选择器后才产生新的独立行为。

## 验证范围

### 数据兼容

- 老数据：外层每轮、内层字段缺失。
- 老数据：外层每人每轮、内层字段缺失。
- 老数据打开后台后不保存、保存并刷新。
- 全局配置和设备级配置均能通过前台回退正常运行。

### 独立组合

- 总数每轮 + 指定每轮。
- 总数每轮 + 指定每人每轮。
- 总数每人每轮 + 指定每轮。
- 总数每人每轮 + 指定每人每轮。

### 指定规则类型

- 单个菜品。
- 菜品集按总份数。
- 菜品集按总种数。
- 菜品集按种时的“每种菜品”上限。
- 菜品集按份时的“每轮相同菜品”上限。
- 多条指定规则的新增、删除和分别切换。

### 前台入口

- 菜品卡直接加购。
- 菜品详情页加购。
- 购物车数量加减。
- 提交订单和服务员权限提示。
- 不同就餐人数区间和有效就餐人数。
- 原总数最小值、最大值及每轮兜底值回归。
- Buffet 菜品过滤及旧配置冲突逻辑回归。

### 工程验证

- 对变更文件执行格式和静态检查。
- 执行项目构建。
- 检查 Git 差异和空白错误。
- 使用 Chrome 在后台保存、刷新，并在前台覆盖代表性组合和边界值。
- 验证完成后恢复测试配置和购物车状态；不清理或作废已有订单。

## 变更边界

- 不修改服务端接口，配置仍作为现有 JSON 整体保存。
- 不修改 `perTypes` 枚举和现有翻译。
- 不改变“每轮相同菜品”的业务语义。
- 不重构限制函数，不抽取新 helper。
- 不处理本需求之外的现有规则优先级或校验流程。
