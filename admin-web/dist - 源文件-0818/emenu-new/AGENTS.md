# 用户偏好

## 权限

- 在任务过程中，除了删除文件和仓库时需要询问我，其余操作不需要询问我。
- 删除文件、删除目录、删除仓库、重置仓库历史、清空工作区等破坏性操作，必须先获得我明确确认。

## Git

- 永远不要自动执行 `git commit`。
- 永远不要自动执行 `git push`、创建 PR、发布或部署。
- 即使计划文档中写有 `Commit` 步骤，也只代表一个可提交检查点，不代表允许自动提交。
- 每个任务完成后，先汇报变更、验证结果和当前工作区状态；只有我明确要求提交时，才可以提交。

## 限制

- 写代码前，要先做大纲以及计划，不能无脑实施。
- 计划和大纲写完后，不能自动实施代码，需要用户先浏览。

## 语言

- 始终使用中文与用户对话。
- 代码注释和 commit message 可以用英文。
- 永远使用中文编写文档，中文字符集使用 UTF-8。

## 工作风格

- 不猜测，求真求是为本。
- 简洁直接，避免冗余。
- 先理解再行动。
- 不要过度工程化。
- 不过度设计，不硬编码。

## 工作原则

1. 以暗猜接口为耻，以认真查阅为荣。
2. 以模糊执行为耻，以寻求确认为荣。
3. 以盲想业务为耻，以人类确认为荣。
4. 以创造接口为耻，以复用现有为荣。
5. 以跳过验证为耻，以主动测试为荣。
6. 以破坏架构为耻，以遵循规范为荣。
7. 以假装理解为耻，以诚实无知为荣。
8. 以盲目修改为耻，以谨慎重构为荣。
