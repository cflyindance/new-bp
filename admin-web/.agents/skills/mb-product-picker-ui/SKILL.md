# 后台商品选择规范

## Purpose

后续涉及产线／渠道、组、类、商品的后台商品选择，默认采用本规范。优先复用项目公共商品选择器，不把参考截图做成不可交互图片。

## 使用边界

- 用户本次明确指令优先；与后台通用规范配合，本规范负责商品选择内部及其弹框，不重写全局导航。
- 只确定视觉和选择交互，不推断权限、可选产线、商品来源、规则冲突、计数口径或保存下发行为。
- 新建与当前修改界面应用规范；不自动批量改造其他项目或历史页面。
- 设计源为用户提供的非公开截图，仅本机使用；不自动发布、推送或同步到其他 Agent。

## Workflow / 实现契约

先读取 [设计与交互契约](references/design-contract.md)。有现有实现时先核对真实选择范围、父子勾选语义、取消及保存行为，然后保留它们。

1. 弹框采用浅灰外层、白色内容、左上关闭按钮和标题、右上主确认按钮；内容长时内部滚动。主操作不在底部重复。
2. 白色内容按“可选业务设置 → 适用商品 → 搜索 → 产线／组／类／商品四列”组织。没有额外业务字段时直接展示选择区，不强加时间间隔等设置。
3. 行点击负责浏览下一级，复选框负责选择；产线切换保留各自选择。选中行用浅灰面、蓝色文字，复选框支持未选／半选／全选，产线数量用蓝色浅底徽标。
4. 搜索、清空、产线切换与勾选不得丢失隐藏选择；数量按现有业务口径计算，不使用节点数冒充商品数。只读查看禁止勾选。
5. 若有时间间隔设置且业务支持分秒，使用同时可见的“分”“秒”两个输入框，不能用单个数值加单位单选替代；切换显示或编辑时保持实际时长一致。上下限沿用所属业务，不能从截图推广。
6. 浏览器验证新增、编辑、取消、搜索有／无结果、跨产线保值、半选与全选、计数、只读和键盘操作；以实际截图报告缺口，不宣称已验证真实接口或终端。

## 现有项目复用入口

在 admin-web 中优先复用 `src/config/brand-menu-structure-picker-ui.ts` 和配套 `brand-menu-structure-picker.css`。调用者只提供业务字段与确认／取消逻辑，保留公共选择状态和事件属性。其他项目先找等价组件，不能照抄该项目存储键、演示商品或授权规则。

## Evaluation / Testing

- [来源及安装范围](references/provenance.md)：追溯截图和当前源码，判断是否可以传播。
- [行为评估](references/evals.md)：修改规范或移植到新项目时执行，普通调用按当前范围验证。

## Output / Deliverable

交付项目中的实际组件、样式与必要截图，说明复用入口、验证结果和未验证项；需要维护PRD时遵循项目文档规则，不自动扩大文档范围。安装Skill时给出实际本机路径和传播范围。

## Definition of Done

- 与参考稿的结构、选中态、数量徽标和操作位置一致；[原始参考图](assets/reference.png)只作视觉证据，不作业务数据。
- 选择、半选、搜索、跨产线保值、确认／取消及只读与业务契约一致；完成范围内的浏览器验证。
- 有分秒需求时两个输入同时存在，合计时长不变；未定义业务边界明确保留。
- 给出实际结果与证据限制，不把规范文件存在当作所有界面已经迁移。
