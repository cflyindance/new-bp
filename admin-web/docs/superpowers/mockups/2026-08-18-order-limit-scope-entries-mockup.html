方案 A · 应用条目吸收例外 推荐

「例外覆盖」不再是独立步骤，而是每条应用范围里的一个可选项。

类型场景限购数量 超限授权生效范围应用范围确认发布
  • 步骤数从 7 降到 7（去掉例外步、补回确认步），门店只在应用范围与生效范围出现
  • 「这组店卖什么、限多少」在同一张卡片里读完，不用跨步对照
  • 数据上仍是模板 + 稀疏覆盖，A 场景一条覆盖都不写
  • 代价：一条应用范围承载三件事（店、品、量），卡片信息略密

方案 B · 应用条目 + 独立例外步

应用范围只管店 / 产线 / 商品，数量差异仍单独一步维护。

类型场景限购数量 超限授权生效范围应用范围例外覆盖确认发布
  • 职责更单纯：范围是范围，数量差异是数量差异
  • 例外可跨多条应用范围任意组合门店
  • 代价：门店在两处重复选择，回到了当前版本被诟病的双选问题
  • 步骤达 8 步，与「先规则后应用」的简化目标相悖
