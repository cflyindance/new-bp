# 服务包创建全屏向导设计

## 目标

将服务包列表中的“创建服务包”由弹窗改为独立路由的全屏三步向导，交互结构参考营销中心屏保的全屏创建流程。用户完成产品定义、菜单路由能力选择和最终确认后，可以选择仅保存，或保存并立即发布。

## 范围

- 新增服务包创建向导路由，位于服务包管理路由命名空间下。
- 进入向导后隐藏 M 平台侧栏和常规顶栏，占满应用视口。
- 保留现有服务包列表、详情编辑、版本发布和商家订阅逻辑。
- 本次不改造已有服务包的编辑页面为步骤向导。

## 页面结构

全屏页面分为三个固定区域：

1. 顶部：返回入口、页面标题、三步进度指示。
2. 中部：当前步骤的可滚动内容区。
3. 底部：固定操作栏，承载取消、上一步、下一步、保存和保存并发布。

步骤如下：

### 第一步：产品定义

- 服务包名称，必填。
- 服务包编码，必填且全局唯一，保存时转为大写。
- 展示价格，非负数。
- 计费周期：月、季度、年、一次性。
- 服务包说明，选填。

点击“下一步”前校验必填项、价格格式和编码唯一性，并保留当前输入。

### 第二步：菜单路由能力

- 按现有菜单路由目录分组展示可选页面路由。
- 支持关键词搜索。
- 支持单项勾选和模块级全选/取消。
- 展示已选菜单数量。
- 点击“下一步”前要求至少选择一个菜单路由。

### 第三步：确认并保存

- 汇总名称、编码、价格、周期和说明。
- 按模块汇总已选择的菜单路由，并展示总数。
- 提供“保存”和“保存并发布”两个操作。

“保存”通过一次原子提交创建未发布服务包，并将第二步选择的菜单写入对应草稿，随后返回服务包列表并展示成功反馈。

“保存并发布”通过一次原子提交创建服务包、包含所选路由的草稿及 v1 发布版本，随后返回服务包列表并展示成功反馈。提交前完成全部校验，提交时只写入一次快照；失败时不改变持久化数据，留在确认页展示错误信息并恢复按钮，用户可以直接重试且不会遇到上一次失败产生的重复编码或半成品。

## 路由与状态

- 列表页“创建服务包”跳转到独立创建路由，不再打开创建弹窗。
- 向导状态仅保存在前端运行时内存中，在步骤间切换时不写入正式服务包存储。
- 成功保存后清空向导状态并返回列表。
- 取消、顶部返回或浏览器返回时，若用户已填写或选择内容，则二次确认放弃；无修改时直接返回。
- 刷新创建路由后从第一步空白状态开始。

## 全屏模式

M 平台壳层识别创建向导路由后，只渲染向导内容，不渲染侧栏和常规主区头部，效果与屏保创建流程进入全屏模式一致。退出或保存后回到服务包列表，恢复常规壳层。

## 数据与错误处理

- 新增向导专用原子领域操作 `createServicePackageFromWizard(input)`。输入同时包含产品定义、菜单路由 ID 和 `publish` 标记；该操作读取一次快照，完成名称、编码、价格、菜单 ID、蓝图版本等全部校验，在内存中构造 package、draft、可选的 v1 release 与审计记录，最后只调用一次快照写入。
- `publish: false` 时创建未发布 package，并创建包含所选 `routeNodeIds` 的 revision 1 草稿。
- `publish: true` 时创建已发布 package、包含所选路由的 v1 release，并创建以该 release 为基线的 revision 2 草稿；package 的 active release 指向 v1。
- 原子操作在最终写入前抛错时不得改变存储；最终写入失败时调用方仍保留完整向导内存状态，可原样重试。
- 对重复编码、空名称、未选菜单、草稿版本冲突等错误显示在当前全屏页面内。
- 提交开始后同时禁用“保存”和“保存并发布”；提交结束前忽略重复事件，避免连续点击导致重复创建。失败后重新启用按钮，成功后立即清空向导状态并导航离开。

## 验收标准

- 点击“创建服务包”进入无侧栏、无常规顶栏的全屏三步页面。
- 步骤顺序和名称严格为“产品定义”“菜单路由能力”“确认并保存”。
- 上一步、下一步、取消和返回行为正确，输入在步骤切换中保留。
- “保存”生成未发布服务包，菜单选择保存在草稿中。
- “保存并发布”生成已发布服务包及 v1 版本，可用于商家订阅。
- 保存成功后返回服务包列表并看到新增记录。
- 编码经 trim 和大写标准化后检查唯一性；价格拒绝非数字和负数，按分取整；第二步未选菜单时不能进入确认页。
- 连续点击任一保存按钮只生成一个服务包和一条创建审计记录。
- 顶部返回、取消和浏览器返回在存在输入时均出现“继续编辑 / 放弃”确认；继续编辑保留当前 URL 与输入，放弃返回服务包列表。无输入时直接返回。
- 刷新创建路由后回到第一步空白状态。
- 原子提交校验失败或存储写入失败时仍停留在第三步，输入和菜单选择不丢失，持久化快照中不存在新增 package、draft、release 或 audit；按钮恢复后可重试。
- TypeScript 检查、领域验证脚本和生产前端构建通过。
