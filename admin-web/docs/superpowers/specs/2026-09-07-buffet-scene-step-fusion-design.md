# 自助餐规则场景配置融合设计

> 状态：已确认
> 确认日期：2026-09-07
> 可视化原型：`http://localhost:55814`

## 1. 目标

取消新增/编辑自助餐规则流程中独立的“场景配置”步骤，将其内容按业务语义融合到“规则类型”和“限购数量”，把六步流程缩减为五步：

`规则类型 → 限购数量 → 超限授权 → 生效范围 → 确认发布`

用户只需要依次回答两个问题：

1. 这条规则限制什么、如何统计？
2. 哪些商品参与，在什么条件下具体限制多少？

本次仅调整自助餐规则编辑流程，不影响菜单下单限制模块，不改变既有规则执行语义和数据隔离方式。

## 2. 设计原则

- 决定“怎么计算”的配置放在规则类型。
- 决定“具体是多少”的配置放在限购数量。
- 条件与其控制的额度在同一页面展示，避免跨步骤记忆。
- 普通规则限制周期单选；跨周期只能通过受控组合模板产生。
- 页面不向用户暴露统计桶、区块、矩阵键等实现概念。
- 已有系统默认规则仍可进入每个步骤编辑商品、条件和额度。

## 3. 配置归属

| 原场景配置内容 | 新位置 | 说明 |
| --- | --- | --- |
| 常用模板 | 规则类型 | 快速生成规则结构 |
| 限制周期 | 规则类型 | 决定统计与累计方式 |
| 周期内限购维度 | 规则类型 | 改名为“限制内容”，决定需要填写的额度 |
| 人数区间 | 限购数量 | 是额度生效条件 |
| 轮次区间 | 限购数量 | 是额度生效条件 |
| 商品范围 | 限购数量 | 与实际额度共同配置 |
| 数量矩阵 | 限购数量 | 保存最终可执行额度 |

## 4. 第一步：规则类型

页面自上而下展示：基础信息、常用模板、限购主体、限制周期、限购对象、计量方式、有效人数口径、限制内容、规则预览。

除基础信息外，规则结构遵循“快捷方案 → 限制谁 → 在什么周期内限制 → 限制什么 → 具体限制哪类数量”的认知顺序：

1. 常用模板：作为快捷入口独立置顶；
2. 限购主体：确定额度按整桌还是按有效人数计算；
3. 限制周期：确定额度的累计与重置范围；
4. 限购对象：确定额度作用于菜品、分类还是菜品集；
5. 限制内容：确定需要填写的数量指标。

计量方式是限购对象的从属项，紧随限购对象展示；有效人数口径是限购主体的补充项，仅按人数时展示。两者不改变上述五个主要决策的顺序。

### 4.1 基础信息

保留规则名称和规则描述。名称必填。

### 4.2 常用模板

模板卡片放在基础信息之后、其他规则结构字段之前，区域标题使用“常用模板”，包含：

- 基础整单限购
- 每人每轮＋整桌兜底
- 整单＋每轮保护
- 整单＋分轮次保护
- 分轮次递减
- 自定义配置

选择模板只填充周期和限制内容，不改变已选择的主体、对象、计量方式、门店商品或具体额度。模板虽然位于主体和对象之前，但仍以当前草稿中的主体、对象判断适用性；不适用模板保持禁用并说明原因。主体或对象尚未选择完整时，仅“自定义配置”可用，其他模板禁用并提示先完成缺失字段；字段补齐后立即重新计算模板可用性。用户调整模板填充项后，标记为“已基于模板修改”。模板能力矩阵如下：

| 稳定模板 ID | 模板 | 适用主体/对象 | 周期 | 限制内容 | 其他约束 |
| --- | --- | --- | --- | --- | --- |
| `order-basic` | 基础整单限购 | 全部主体/对象 | 整个订单 | 指定对象额度 | 无总量、无单品保护 |
| `round-party-table-cap` | 每人每轮＋整桌兜底 | 仅按人数；全部对象 | 每轮 | 下单总量、指定对象额度 | 自动显示可选整桌兜底；主体不符时禁用并说明原因 |
| `order-round-protection` | 整单＋每轮保护 | 全部主体；仅菜品集 | 整个订单＋每轮 | 两周期对象额度；每轮单品保护 | 对象不符时禁用；周期只读 |
| `order-multi-round-protection` | 整单＋分轮次保护 | 全部主体/对象 | 整个订单＋分轮次 | 两周期对象额度 | 周期只读 |
| `multi-round-desc` | 分轮次递减 | 全部主体/对象 | 分轮次 | 指定对象额度 | 默认轮次区间为第 1 轮及以上 |
| `custom` | 自定义配置 | 全部主体/对象 | 保留当前合法单周期；否则默认为每轮 | 默认指定对象额度 | 从组合模板切换时默认为每轮并走结构变更确认 |

模板仅提供合法快捷填充，不扩大主体、对象、周期和限制内容的允许组合。不满足适用条件的模板卡片禁用并显示原因。模板不写入或覆盖任何数值；如果模板移除周期或限制内容，必须先按结构变更影响矩阵展示影响，确认后只清除受影响额度，取消后模板选择和草稿都不变化。

主体或对象变化后必须重新校验当前模板。模板不再适用时，不得保留“已选中但禁用”的状态：单周期结构自动转为 `custom`；多周期结构在确认变更前必须要求用户选择一个适用的受控模板或改为单周期，取消时主体、对象、模板和全部草稿保持不变。

### 4.3 限购主体

- 按桌/订单限购：配置额度即整桌实际额度，不显示人数区间。
- 按人数限购：人均额度乘当前订单有效就餐人数，在限购数量中显示人数区间。

### 4.4 限制周期

普通规则只能单选：

- 整个订单
- 每轮
- 分轮次

受控组合模板允许：

- 整个订单＋每轮
- 整个订单＋分轮次

组合模板的周期只读。禁止“每轮＋分轮次”和三个周期同时存在。

### 4.5 限购对象

- 按分类限购：分类内商品共享数量池。
- 按菜品限购：每个选中菜品独立累计。
- 按菜品集限购：多个选中菜品跨产线共享数量池；每家门店至少选择两个成员。

这里只选择对象类型，具体门店、产线和商品在限购数量中选择。

### 4.6 计量方式与有效人数口径

- 计量方式归属规则类型，仅菜品集显示“按份／按种”。分类和菜品固定按份。
- 儿童是否计入有效人数继续归属规则类型，仅按人数主体显示。
- 修改有效人数口径不立即改写已填人均额度；运行时始终按校验时有效人数重新计算。

### 4.7 限制内容

原“周期内限购维度”改名为“限制内容”，根据主体、对象和周期动态展示：

- 下单菜品总数
- 指定分类/菜品/菜品集额度
- 相同菜品保护

菜品集按份时可出现菜品集总份数和相同菜品最大份数；按种时可出现最多菜品种数和每种菜品最大份数。每个启用周期至少选择一项限制内容。

合法能力矩阵：

| 对象 | 计量 | 整个订单 | 每轮/分轮次 |
| --- | --- | --- | --- |
| 分类 | 按份 | 指定分类额度 | 总量、指定分类额度 |
| 菜品 | 按份 | 指定菜品额度 | 总量、指定菜品额度 |
| 菜品集 | 按份 | 菜品集总份数 | 总量、菜品集总份数、相同菜品最大份数 |
| 菜品集 | 按种 | 菜品集最多种数 | 总量、菜品集最多种数、每种菜品最大份数 |

“相同菜品保护”只对菜品集的每轮/分轮次周期开放。整桌总量兜底和整桌对象兜底不是独立限制内容：按人数主体启用对应总量或对象额度时，在限购数量中自动显示为可选补充字段，不纳入必填完成度；关闭对应主限制内容时一并清除。未列出的组合不可选择或发布。

### 4.8 规则预览

页面底部实时生成自然语言摘要，例如：

> 每位食客按分轮次限制指定菜品集总份数，同时限制每轮下单总量和相同菜品最大份数。

组合模板摘要必须说明多个周期同时生效，任一额度超限即拦截。

## 5. 第二步：限购数量

页面自上而下展示：规则上下文、参与门店和商品、人数区间、轮次区间、当前场景、数量配置。

### 5.1 规则上下文

页面顶部用只读摘要展示主体、对象、周期、计量方式和限制内容，并提供“修改规则类型”入口返回第一步。

### 5.2 参与门店和商品

沿用现有按门店独立配置：

- 参与门店下拉
- 产线筛选
- 商品/分类搜索
- 添加商品
- 查看已选商品

商品范围和数量继续按门店独立保存；菜品集成员允许跨产线合并统计。

### 5.3 人数区间

仅按人数限购显示。区间必须从 1 开始、连续、互斥、无空档，最后一个区间为“及以上”。新增区间采用拆分末尾区间，例如把“1 人及以上”按分界值 4 拆为“1～3 人”和“4 人及以上”。

### 5.4 轮次区间

仅分轮次及包含分轮次的受控组合显示。规则与人数区间一致：从第 1 轮开始、连续、互斥、无空档，最后一个区间为“及以上”。

### 5.5 当前配置场景

人数区间和轮次区间通过场景切换器组合，不直接展示大型二维矩阵。例如：

`1～3 人 · 第 1 轮`

切换场景自动保存当前输入。提供“从上一人数区间复制”和“从上一轮次区间复制”。

### 5.6 数量配置

普通规则只展示所选周期。组合模板按照“整个订单 → 每轮/分轮次”的顺序纵向分区。

数量字段由第一步的限制内容决定：

- 总量：最少 M 份、最多 N 份。
- 指定对象额度：每个菜品独立上限，或分类/菜品集共享上限。
- 相同菜品保护：相同菜品最大份数，或每种菜品最大份数。
- 整桌兜底：按人数规则可额外配置整桌总量和整桌对象上限，与人均乘算结果取更严格值。
- 默认单品保护及例外菜品额度：保留现有能力，归属对应门店、周期、人数/轮次场景。

所有上限字段：空值表示未配置，0 表示禁止下单，正整数表示最大份数。“最少”字段：空值表示不设最少值，0 表示最少 0 份，正整数表示最少份数。“最多”字段仍按上限语义处理。最小值不得大于最大值。

## 6. 修改区间后的数据处理

- 未填写任何数量时，区间可以直接调整。
- 已存在数量时，新增、修改或删除区间前必须二次确认。
- 所有人数区间和轮次区间持有不可变 `rangeId`，场景身份为 `partyRangeId + roundRangeId`，不得继续使用数组下标作为身份。
- 拆分末尾区间时，包含原起点的区间继承原 ID；新生成的区间获得新 ID，额度初始为空。
- 编辑边界但保留 ID 时保留其额度；删除区间只删除包含该 ID 的笛卡尔场景，不把额度复制到相邻区间。
- 无法匹配的数据明确清除；任何从相邻场景复制额度的操作都必须由用户显式触发。
- 删除区间时说明会删除哪些人数/轮次数量配置。
- 取消确认不修改草稿。

历史索引键迁移规则：对缺少 `rangeId` 的历史区间按原顺序一次性分配 ID，并建立旧数组索引到新 ID 的映射；使用该映射重写全部门店、周期、总量、对象、整桌兜底、默认/例外保护额度以及当前场景引用。已有合法 `rangeId` 原样保留。迁移必须幂等；重复 ID、越界索引、无法解析或冲突的额度键不得静默删除，草稿进入修复态并阻止发布。迁移只写隔离作者草稿，不修改发布配置和运行快照。

## 7. 历史数据兼容

- 现有合法普通单周期规则按原周期加载。
- 历史多周期只有同时满足以下条件才映射为合法模板：规范化周期集合恰好为“整个订单＋每轮”或“整个订单＋分轮次”；主体和对象满足目标模板适用条件；限制内容满足能力矩阵。限制内容和计量方式按原值加载，不因模板映射而覆盖。不满足任一条件时进入结构修复态，不得标记为合法模板或直接发布。
- 空周期、未知周期、三个周期、每轮＋分轮次均为非法历史组合。
- 打开非法已发布规则时仅创建隔离的修复草稿，不修改原作者配置、已发布配置和运行快照；未知周期需在修复提示中可见。
- 非法组合不得重新发布。选择保留一个周期时只保留该周期额度；“复制拆分”按每个可识别周期生成一条草稿，共享门店商品和通用条件，并分别只携带该周期额度。
- 取消修复或仅保存草稿均不影响运行版本。
- 迁移只改变编辑器呈现，不改变已发布版本的统计桶和运行结果。

## 8. 结构变更影响矩阵

从限购数量返回第一步修改结构时，按下表计算影响并合并为一次确认。弹窗必须列出受影响的门店、周期、人数/轮次场景、商品数量和额度区块；取消后草稿深比较不变。

| 变更 | 商品范围 | 清除数据 | 保留数据 |
| --- | --- | --- | --- |
| 模板 | 按模板字段差异逐项合并 | 下列各差异对应区块 | 未受影响区块 |
| 按桌/订单→按人数 | 保留 | 全部原额度 | 商品、非人数条件；初始化人数区间为“1 人及以上”，禁止把整桌额度解释为人均额度 |
| 按人数→按桌/订单 | 保留 | 全部人均、人数场景及整桌兜底额度 | 商品、非人数条件；人数区间重置为隐藏的单一区间，禁止选择某一人数区间静默折叠 |
| 对象类型 | 清除对象选择 | 对象额度、单品保护和例外额度 | 不依赖对象的总量额度 |
| 周期 | 保留 | 被移除周期全部额度 | 未变化周期额度 |
| 菜品集计量方式 | 清除菜品集对象 | 菜品集对象、默认/例外保护额度 | 不依赖对象的总量额度 |
| 关闭限制内容 | 保留 | 该内容对应额度区块 | 其他内容额度 |
| 有效人数口径 | 保留 | 不清除 | 所有额度；运行时按新有效人数重算 |
| 移除参与门店 | 其他门店不变 | 该门店商品和全部作者额度 | 其他门店配置 |

只有影响预览非空时才二次确认。确认后只执行表中清除项。

## 9. 参与门店与生效门店

- 参与门店是可以维护商品与额度草稿的门店集合。
- 生效门店在“生效范围”选择，必须是参与门店的非空子集。
- 未选为生效的参与门店配置保留在作者草稿，但不进入本次发布快照。
- 移除存在商品或额度的参与门店必须二次确认；确认后删除该门店全部作者草稿数据，并同时从生效门店和生效排除集合移除该门店；取消时三个集合及门店配置均保持不变。

## 10. 六步草稿迁移与页面生命周期

仅对自助餐规则且步骤版本低于五步版的草稿/作者配置执行一次幂等迁移：

| 旧步骤 | 新步骤 |
| --- | --- |
| 1 规则类型 | 1 规则类型 |
| 2 场景配置 | 2 限购数量 |
| 3 限购数量 | 2 限购数量 |
| 4 超限授权 | 3 超限授权 |
| 5 生效范围 | 4 生效范围 |
| 6 确认发布 | 5 确认发布 |

`currentStep`、`highestStep` 均按此映射折叠。旧第 2、3 步保存的门店、产线、区间和当前场景迁入新第 2 步；当前场景引用失效时回退到第一个有效场景并提示。

- 新增规则从第 1 步开始。
- 编辑已发布普通规则和系统默认规则均从第 1 步开始。
- 系统默认规则只修改商品、条件、额度时保持系统默认身份；修改主体、对象、周期、计量方式或限制内容后转为普通规则，并明确提示。
- 第 5 步主按钮保存作者草稿并进入既有独立发布确认页；从发布确认页返回仍回到第 5 步。
- 迁移不得修改已发布配置和运行快照。

## 11. 校验

### 11.1 规则类型

- 规则名称必填。
- 主体和对象必选。
- 普通周期必须且只能选择一个。
- 组合周期必须来自受控模板。
- 每个周期至少选择一项限制内容。

### 11.2 限购数量

- 至少一家参与门店。
- 需要指定对象时至少选择一个有效对象。
- 每家门店的菜品集至少两个成员。
- 人数和轮次区间连续完整。
- 所有启用限制内容都有对应额度。
- 最小值不大于最大值。
- 总量最少和最多至少配置一项；二者都配置时最少不得大于最多。最少为 0 表示没有最低份数要求，最多为 0 表示禁止下单。

## 12. 交互与页面状态

- 步骤导航由六步更新为五步，序号、可达状态和底部“第 N 步”同步更新。
- 从限购数量返回规则类型时保留全部商品和额度。
- 修改主体、对象、周期或限制内容若会使现有数量失效，必须先展示影响范围并确认。
- 确认后只清理不再适用的数据，其他门店和场景配置保持不变。
- 草稿恢复必须回到上次步骤和场景选择。
- 编辑器和发布确认页继续采用全屏模式，返回规则列表后退出全屏。

## 13. 验收标准

1. 新增和编辑自助餐规则均只展示五个步骤。
2. 页面不存在独立“场景配置”步骤。
3. 规则类型自上而下严格展示：基础信息、常用模板、限购主体、限制周期、限购对象、计量方式、有效人数口径、限制内容、规则预览；计量方式只在菜品集时显示，有效人数口径只在按人数时显示，规则预览始终位于最后。
4. 人数区间、轮次区间、门店商品和额度全部在限购数量完成。
5. 按桌/订单规则不显示人数区间。
6. 非分轮次规则不显示轮次区间。
7. 普通周期不可多选；非法组合不可发布。
8. 组合模板按周期纵向分区展示数量。
9. 调整有数据的区间前必须二次确认。
10. 系统默认规则可以完整编辑并选择商品。
11. 历史合法规则无损打开；历史非法组合明确提示修复。
12. 菜单下单限制模块的步骤和数据不受影响。
13. 旧六步草稿分别停留在第 1～6 步时，恢复步骤严格映射为 `1/2/2/3/4/5`，商品、额度和有效场景不变。
14. 新草稿尚未选择主体或对象时，`custom` 模板可用；其他模板均禁用并提示“请先选择限购主体和限购对象”。只缺少其中一个字段时，提示选择缺失字段；字段补齐后立即按当前主体和对象重新计算模板可用性。
15. 应用模板只允许改变限制周期和限制内容；主体、对象、计量方式、参与门店、商品范围及数量值必须保持不变。若模板移除已有结构，确认后仅清除被移除周期或内容对应的额度；取消后模板选择和整份草稿保持不变。
14. 结构变更影响矩阵逐行验证：取消时草稿深比较不变；确认时只删除表中规定数据。
15. 合法单周期及两种受控组合可发布；非法组合在第一步和直接打开发布确认页时均被阻止。
16. 已有合法 `rangeId` 的历史规则打开、保存、发布后 ID 原样不变；缺少 ID 的历史规则首次迁移后，额度按旧索引完整重键且业务语义不变，随后再次打开、保存、发布时新 ID 保持稳定。
17. 菜单下单限制继续显示原六步，菜单旧草稿不迁移，菜单存储键、商品额度和发布结果保持回归基线一致。
18. 总量边界覆盖：仅最少、仅最多、二者均填、空值、0、正整数及最少大于最多。
