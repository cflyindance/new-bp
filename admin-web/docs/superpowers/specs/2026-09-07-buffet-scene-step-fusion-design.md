## 1. 功能与流程

自助餐规则用于限制一笔自助餐订单中，指定菜品、分类或菜品集可以下单的数量，以及每轮下单的菜品总数。

新增和编辑规则均包含五个步骤：

`规则类型 → 限购数量 → 超限授权 → 生效范围 → 确认发布`

| 步骤 | 解决的问题 | 配置内容 |
| --- | --- | --- |
| 1. 规则类型 | 这条规则怎么算、限制什么 | 名称、描述、模板、限购主体、限制周期、限购对象、计量方式、有效人数口径 |
| 2. 限购数量 | 哪家店、哪些商品、具体限多少 | 人数区间、轮次区间、参与门店、商品范围、总量上下限、对象上限、菜品集成员保护 |
| 3. 超限授权 | 超过上限时允许怎样放行 | 授权开关、可选范围、默认范围、权限、原因填写设置 |
| 4. 生效范围 | 规则在哪些条件下适用 | 日期、日历循环、活动时段、会员范围、生效门店 |
| 5. 确认发布 | 本次配置是否完整、可以发布 | 配置复核、完整性检查、冲突检查、发布确认 |

编辑器和发布确认页全屏展示，返回规则列表后退出全屏。保存草稿与发布是不同动作：草稿用于继续编辑，正式规则及运行快照用于执行。

自助餐规则与菜单下单限制使用独立的路由和数据空间。本文描述自助餐规则，不将另一模块的页面或数据作为自助餐规则配置。

阅读方式：第 2～7 章说明五步操作，第 8～10 章说明组合与具体下单例子，第 11 章为研发字段对照，第 12 章为测试核对表，第 13 章说明当前计算接口的实际覆盖范围。

## 2. 基本概念

### 2.1 先分清“按什么算”和“累计多久”

| 名称 | 直白解释 | 例子 |
| --- | --- | --- |
| 按桌/订单限购 | 填多少，整桌最多就是多少，不乘人数 | 牛肉填 4，2 人和 5 人都最多 4 份 |
| 按人数限购 | 普通主额度乘有效人数，得到整桌共享额度 | 每人 2 份，3 人整桌共享 6 份 |
| 整个订单 | 汇总这一订单各轮已点数量 | 整单上限 6，前两轮已点 4，后面还可点 2 |
| 每轮 | 当前轮独立累计，各轮使用相同额度 | 每轮 5 份，第 1、2 轮各自最多 5 份 |
| 分轮次 | 当前轮独立累计，按轮号选择对应额度 | 第 1～2 轮每轮 5 份，第 3 轮起每轮 3 份 |
| 人数区间 | 根据有效人数选择一组数量配置 | 3 人用“1～3 人”，4 人用“4 人及以上” |
| 轮次区间 | 根据轮号选择一组数量配置 | 第 2 轮用“第 1～2 轮”，第 3 轮用“3 轮及以上” |

限购主体与限制周期是两个独立维度。“按桌/订单”不是“只能限制整个订单”；当前可以选择按桌每轮、按桌分轮次。

按人数计算的是整桌共享数量，不追踪每个实名食客分别点了多少。3 人共享 6 份，不等于系统分别记录张三、李四、王五各自的 2 份。

### 2.2 限购对象

| 对象 | 统计方式 | 选择牛肉、羊肉时的含义 |
| --- | --- | --- |
| 菜品 | 每个选中菜品独立计数 | 牛肉上限 2、羊肉上限 2，可分别点 2，共 4 份 |
| 分类 | 同产线、同分类内的全部菜品共享上限 | 肉类上限 2，牛肉、羊肉及该分类其他菜品合计最多 2 |
| 菜品集 | 一条规则选择的成员共用一个数量池 | 集合上限 2，牛肉 1＋羊肉 1 已经满额 |

菜品集的规则：

- 一条规则只包含一个菜品集，不单独填写集合名称或编码。
- 每家参与门店至少选择两个成员。
- 成员可以跨产线，份数或种数合并统计。
- 菜品身份由“产线 ID＋菜品 ID”确定，分类身份由“产线 ID＋分类 ID”确定。显示名称不作为计数依据。
- 同名但不同身份的菜品是两个成员；同名但不同产线的分类是两个独立对象。
- 分类限购统计分类内全部菜品，不是只统计页面展开时显示的部分商品。

### 2.3 份、种、总量和成员保护

| 名称 | 统计什么 | 例子 |
| --- | --- | --- |
| 按份 | 菜品数量之和 | 牛肉 3＋羊肉 1，共 4 份 |
| 按种 | 当前数量大于 0 的不同成员数 | 牛肉 3＋羊肉 1，共 2 种 |
| 每轮下单菜品总数 | 本轮全部菜品的份数之和 | 集合只选肉类，集合外青菜仍计入每轮总数 |
| 指定对象上限 | 一个菜、一个分类或一个菜品集的上限 | 肉类总数不能超过 5 |
| 相同菜品/每种菜品保护 | 菜品集中单个成员的份数上限 | 集合共可点 8 份，但牛肉最多 2 份 |
| 整桌兜底 | 在人均计算值之外，配置整桌固定边界 | 人均算出 6，整桌最多 5，实际最多 5 |

按种时，某菜从 1 份增加到 2 份不增加种数；从 0 增加到 1 才增加一种，减到 0 才释放一种。总量和成员保护始终按份，菜品集选择“按种”不会把这两个字段改成种数。

数量判断使用“本次变更后的最终数量”。已点 2 份，本次加 1 份，用 3 与上限比较，不是只比较本次增加的 1。

## 3. 第一步：规则类型

### 3.1 展示顺序和字段

页面顺序为：基础信息、常用模板、限购主体、限制周期、限购对象、计量方式、有效人数口径、规则预览。

| 字段 | 可选值/初始值 | 当前处理 |
| --- | --- | --- |
| 规则名称 | 必填，最多 60 个字符 | 空白名称不能继续；用于列表及编辑页辨认规则 |
| 规则描述 | 选填，最多 200 个字符 | 说明用途，不参与数量计算 |
| 常用模板 | 10 个模板入口，分四组展示 | 填充计算结构，不填具体数量，不默认选择限购对象 |
| 限购主体 | 按桌/订单、按人数 | 必选；按人数显示人数区间和儿童口径 |
| 限制周期 | 整个订单、每轮、分轮次，或受控组合 | 普通规则单选，组合模板显示两个选中且只读的周期 |
| 限购对象 | 分类、菜品、菜品集 | 必选；决定第二步显示对象行还是集合共享额度 |
| 计量方式 | 菜品集默认按份，可选按种 | 仅菜品集显示；菜品和分类按份 |
| 儿童计入有效人数 | 默认继承门店全局设置，可选计入、不计入 | 仅按人数显示；不改写已填人均数值 |
| 规则预览 | 只读 | 显示“主体 × 对象”摘要；未选完整时提示补选 |

本步骤确定计算方式，不选择具体门店和商品，不填写最终额度。

### 3.2 十个常用模板

| 模板 | 自动带出的主体 | 自动带出的对象 | 限制周期 | 对应数量能力 |
| --- | --- | --- | --- | --- |
| 整单限购 | 按桌/订单 | 用户选择 | 整个订单 | 对象上限 |
| 每轮限购 | 按桌/订单 | 用户选择 | 每轮 | 每轮总量上下限、对象上限 |
| 分轮次限购 | 按桌/订单 | 用户选择 | 分轮次 | 各轮次区间的每轮总量上下限、对象上限 |
| 每人＋整单限购 | 按人数 | 用户选择 | 整个订单 | 人均对象上限，可填写整桌对象上限 |
| 每人＋每轮限购 | 按人数 | 用户选择 | 每轮 | 人均每轮总量上下限、对象上限，可填写整桌每轮上限与下限 |
| 每人＋分轮次限购 | 按人数 | 用户选择 | 分轮次 | 各人数与轮次区间的人均对象额度 |
| 每人每轮＋整桌每轮限购 | 按人数 | 用户选择 | 每轮 | 人均总量/对象上限与整桌每轮上限、下限，分别配置 |
| 整单＋每轮限购 | 按桌/订单 | 用户选择 | 整个订单＋每轮 | 整单对象额度、每轮对象额度；菜品集可配置每轮成员保护 |
| 整单＋分轮次限购 | 按桌/订单 | 用户选择 | 整个订单＋分轮次 | 整单对象额度、不同轮次区间对象额度 |
| 自定义配置 | 保持当前选择 | 保持当前选择 | 保持合法单周期；不满足时使用每轮 | 根据所选主体、对象和周期展示字段 |

页面按以下分组及顺序展示，每组使用三列卡片布局，小屏幕按页面响应式布局排列：

- 基础限购：整单限购 → 每轮限购 → 分轮次限购。
- 人均限购：每人＋整单限购 → 每人＋每轮限购 → 每人＋分轮次限购。
- 组合限购：每人每轮＋整桌每轮限购 → 整单＋每轮限购 → 整单＋分轮次限购。
- 自定义：自定义配置，单独放在最后。

模板只负责填结构，不填具体商品、门店和数量。选择“每人＋整单限购”，会选中按人数和整个订单；用户仍需选择菜品、分类或菜品集，并在第二步填写数量。全部非自定义模板均支持这三种限购对象：未选择对象时保持未选择，已有对象时不因模板默认值自动替换。

“每人＋每轮限购”与“每人每轮＋整桌每轮限购”当前带出的主体、周期和数量区块相同，都支持人均与整桌数量配置。前者用于从人均限制开始配置，后者提醒同时设置整桌限制；模板名称不代表已经填入数量，最终以实际配置为准。

配置示例：

- 分轮次限购：选按菜品，牛肉第 1～2 轮每轮最多 4 份，第 3 轮起每轮最多 2 份；各轮分别累计，不跨轮合并成一个额度。
- 每人＋每轮限购：牛肉人均每轮最多 2 份，3 人整桌本轮共享最多 6 份，不分别记录每位食客的点菜数量。
- 每人每轮＋整桌每轮限购：3 人、人均每轮最多 2 份，同时设置整桌每轮最少 3 份、最多 5 份，本轮合计需达到 3 份且不能超过 5 份。
- 整单＋每轮限购：牛肉整单最多 8 份、每轮最多 3 份；两个条件同时满足，前两轮各点 3 份后，第 3 轮最多还能点 2 份。

模板选择和切换：

- 尚未选择主体或对象时，模板仍可点击，选中后显示唯一选中状态。
- 没有商品或数量的草稿可以直接应用模板。
- 已有数据且切换会影响数据时，先显示影响确认；取消则保留模板与整份草稿。
- 模板本身不填入或覆盖额度。结构改变使数据不再适用时，按第 3.5 节清除对应数据。
- 手动调整模板中的结构后，不展示“已基于模板修改”提示；内部仍记录模板修改状态。单周期与模板约束不匹配时可转为自定义；多周期仍受组合模板约束。
- 菜品集按份、按种切换时，没有已选商品及对象相关额度的数据可直接切换，不弹确认框。存在会被清除的商品、对象额度或成员保护数据时才显示确认；检查范围包括所有配置门店，不仅当前门店。不依赖对象的总量额度保留，单独存在总量额度不会触发此确认。

### 3.3 限制周期

| 周期 | 累计范围 | 数量配置方式 |
| --- | --- | --- |
| 整个订单 | 当前订单各轮累计 | 每个人数场景一组；按桌规则只有一组 |
| 每轮 | 当前订单当前轮 | 每个人数场景一组，各轮复用该组额度 |
| 分轮次 | 当前订单当前轮 | 按人数场景与轮次场景分别配置 |

每轮额度不结转。第 1 轮最多 5，只点了 2，第 2 轮仍最多 5，不是 8。

一个普通规则只能选一个周期。一个受控组合规则可以包含：

- 整个订单＋每轮。
- 整个订单＋分轮次。

组合的两个周期卡片同时选中并只读；修改组合通过切换模板进行，不能单独取消其中一个周期。一条规则不接受“每轮＋分轮次”或三个周期同时选择。

“整单＋每轮限购”和“整单＋分轮次限购”均可使用菜品、分类或菜品集，不默认选择对象。两种模板预设按桌，允许在模板适用范围内改为按人数。两个周期共用当前规则在每家门店选择的对象范围；数量分别填写、分别统计。

### 3.4 有效人数

有效人数 H 是本次计算使用的人数。

例：2 个成人＋1 个儿童，人均上限 2。计入儿童时 H=3，整桌上限 6；不计入时 H=2，上限 4。

页面保存儿童计数选项，数量函数接收已经计算好的 H，不接收成人和儿童明细。因此继承门店设置、区分成人儿童的计算在调用方完成。人数变化后，下一次数量判断使用新的 H，不自动退菜。

### 3.5 修改结构时的数据处理

有受影响商品或数量时显示二次确认。确认后只处理影响范围内的数据，取消时草稿不变。

| 操作 | 商品范围 | 数量和条件处理 |
| --- | --- | --- |
| 按桌改按人数 | 保留 | 清除原额度，初始化“1 人及以上”；固定 5 份不会被解释为每人 5 份 |
| 按人数改按桌 | 保留 | 清除数量和人数场景额度，人数区间转为不显示的单一区间 |
| 修改对象类型 | 清除对象选择 | 清除对象及成员保护额度，保留不依赖对象的总量 |
| 修改周期 | 保留 | 清除被移除周期的数量，保留未变化周期 |
| 菜品集按份/按种切换 | 清除菜品集选择 | 清除集合额度及成员保护，保留不依赖对象的总量 |
| 修改儿童口径 | 保留 | 保留填写值；计算时使用对应有效人数 |
| 清空某类数量 | 保留 | 该类数量全部为空时停止启用该类限制，其他数量不变 |
| 移除参与门店 | 其他门店不变 | 删除该店商品和数量，并从生效门店及排除集合中移除 |

## 4. 第二步：限购数量

### 4.1 页面和操作顺序

页面按适用区间、门店与商品、周期数量纵向展示。

1. 按需设置人数区间、轮次区间。
2. 点击“添加商品”，选择参与门店及商品。
3. 在“配置门店”下拉中选择当前维护门店。
4. 在各周期、各区间卡片中填写总量、对象额度或成员保护。
5. 使用筛选检查配置，按需批量填写、移除或跨门店复制。

每个周期下面展示相应场景卡片。卡片内顺序为：每轮菜品总数、商品/分类/菜品集额度、菜品集内部保护；不适用的部分不展示。数量启用状态由实际填写值决定，用户直接填写对应字段。

### 4.2 人数区间和轮次区间

| 条件 | 是否显示人数区间 | 是否显示轮次区间 |
| --- | --- | --- |
| 按桌＋整个订单 | 否 | 否 |
| 按人数＋整个订单 | 是 | 否 |
| 按桌＋每轮 | 否 | 否 |
| 按人数＋每轮 | 是 | 否 |
| 按桌＋分轮次 | 否 | 是 |
| 按人数＋分轮次 | 是 | 是 |
| 包含分轮次的组合 | 按主体决定 | 是，仅分轮次数量使用 |

区间从 1 开始，连续、不重叠、无空档，最后一个为“及以上”。边界值包含在区间中。

- `1～3、4及以上`有效；3 和 4 各归一个区间。
- `1～3、3及以上`重叠；`1～3、5及以上`缺少 4；均不能通过区间校验。
- 普通按人数草稿初始为“1 人及以上”。新增分界 4 时形成“1～3 人”和“4 人及以上”。
- 分轮次同样从第 1 轮开始，例如“第 1～2 轮、3 轮及以上”。
- 第 8 章六个组合规则初始包含“1～3 人、4 人及以上”，数量为空。

人数、轮次以区间表展示，包含场景、区间、页面显示和操作。不同区间组合有各自数量卡片，不共用一个输入值。

例如，2 个人数区间 × 2 个轮次区间 = 每家门店 4 组分轮次数量。整单＋分轮次还包含整单数量区，整单数量不按轮次拆分。

每个区间保存稳定 `rangeId`。有额度时调整区间先确认；拆分后包含原起点的区间保留 ID，新区间使用新 ID 且额度为空。保留 ID 的边界调整保留该区间额度，删除区间删除对应场景数量，不把额度自动复制给相邻区间。

### 4.3 参与门店、配置门店、生效门店

| 名称 | 含义 |
| --- | --- |
| 参与门店 | 这条规则为哪些门店保存商品和数量配置 |
| 配置门店 | 下拉中正在编辑的那一家门店 |
| 生效门店 | 第四步勾选、本次发布包含的门店 |

商品范围和数量按门店独立保存。切换配置门店不把 A 店内容覆盖到 B 店，工作台的选择状态随上下文切换清空。

生效门店是有配置的参与门店的非空子集。参与但未生效的门店数据保留在作者配置中，不进入本次发布配置。

### 4.4 选择商品和查看已选商品

先选参与门店，再从该门店商品范围选择对象。商品搜索支持该门店各产线的商品；名称搜索按商品或分类名称处理。

- 按菜品：保存选中的具体菜品，各菜品独立填上限。
- 按分类：保存选中的分类，分类下商品共用额度。
- 按菜品集：保存选中的具体成员，每店至少两个，跨产线合并统计。

“查看已选商品”弹窗可按门店、产线和菜单名称搜索，搜索位于产线右侧。弹窗展示已选对象及详情，提供分页、当前页选择、单个删除、批量删除和全部删除；删除有二次确认。

### 4.5 商品表格与额度位置

| 对象 | 列表展示 | 在哪里填数量 |
| --- | --- | --- |
| 菜品 | 每行一个菜，显示商品、分类和产线 | 在菜品行填独立上限 |
| 分类 | 每行一个分类，显示包含商品数量，可查看成员 | 在分类行填共享上限，成员不重复填 |
| 菜品集 | 列出成员、分类、产线和成员保护状态 | 在表格上方填写一次集合共享额度；成员例外在对应操作中设置 |

菜品集共享上限 6，表示成员合计最多 6，不是每个成员各 6。成员表格不会重复保存一份集合额度到每个菜品。

相同菜品保护区位于菜品集额度与成员后，设置统一默认值。例外处理见第 4.8 节。

### 4.6 数量字段何时出现

| 对象/计量 | 整个订单 | 每轮或分轮次 |
| --- | --- | --- |
| 菜品，按份 | 各菜品上限 | 每轮总量、各菜品上限 |
| 分类，按份 | 各分类共享上限 | 每轮总量、各分类共享上限 |
| 菜品集，按份 | 集合总份数 | 每轮总量、集合总份数、成员份数保护 |
| 菜品集，按种 | 集合最多种数 | 每轮总量、集合最多种数、每种份数保护 |

整个订单不提供全单全部菜品的总量上下限，也不提供整单的集合成员保护。按人数的对象行可填写整桌固定对象兜底，包括整个订单周期；每轮/分轮次还可填写整桌总量兜底。

普通规则的整桌兜底选填。第 8 章的六个组合规则中，整桌总量及部分固定对象字段属于组合本身的必填额度。

### 4.7 数量值、计算与填写完整性

| 输入 | 上限字段 | 最少字段 |
| --- | --- | --- |
| 空 | 未配置这项限制 | 不设置最低要求 |
| 0 | 该对象不允许出现正数量 | 最少 0 份 |
| 正整数 | 最大允许份数或种数 | 最少达到的份数 |

合法数值为 `0～999999` 的整数。数量解析将不合法值转为未配置，未配置项再参与完整性校验；不能将“非法值变空”解释为保存了有效额度。

等于上限允许，超过才拦截；等于最少允许，低于才不满足。最少不能大于最多。

设有效人数为 H，人均最多为 X，整桌最多为 T：

`实际最多 = min(X × H, T)`

设人均最少为 M，整桌最少为 D：

`实际最少 = max(M × H, D)`

未配置的项不参与取值。按桌规则的主额度不乘 H；整桌兜底、默认成员保护及例外保护均不乘 H。

例：3 人，人均最少 1、最多 3，整桌最少 4、最多 8。实际最少 `max(3,4)=4`，最多 `min(9,8)=8`。

数量启用与完整性：

- 总量有最少或最多值时启用总量限制；普通规则两者可只填一项。
- 对象有额度时启用对象限制。启用后，被校验门店各场景的各选中对象都需填完整。
- 默认或例外成员额度存在时启用成员保护。
- 周期的启用状态按作者数量归纳，不是每个商品一个开关。
- 清空数量保留商品；一类数量全部为空后该类限制不启用。
- 每个启用周期至少有一项实际数量限制。只有商品没有数量，不能发布。
- 保存草稿允许逐步填写，继续和发布检查完整性。
- 六个组合规则按第 8.2 节检查整组必填值，不套用普通总量仅填一边的规则。

### 4.8 菜品集成员保护和例外

默认保护是集合中每个成员的固定份数上限，按人数规则中也不乘人数。

例：3 人，集合人均 2 份、默认保护 2 份。集合共享上限为 6，但同一个成员仍最多 2。

| 设置 | 当前计算含义 |
| --- | --- |
| 默认 2，牛肉无例外 | 牛肉和其他成员最多各 2 |
| 默认 2，牛肉例外 3 | 牛肉最多 3，其他成员最多 2 |
| 默认 2，牛肉例外 0 | 牛肉禁止下单，其他成员最多 2 |
| 恢复默认 | 移除牛肉例外记录，牛肉重新使用默认 2 |
| 例外记录存在，但例外值为空 | 牛肉不使用默认保护，也没有该例外上限 |

例外值替换默认值，不与默认值再取较小值。清空例外输入和删除例外记录是不同动作。集合共享额度始终另外校验，成员没有保护上限不等于可以突破集合额度。

### 4.9 筛选、批量操作和移除

筛选仅影响当前列表显示，不改变已保存商品范围、数量或统计范围。

| 筛选/操作 | 当前处理 |
| --- | --- |
| 产线 | 显示该产线的已选对象 |
| 分类 | 菜品/菜品集可筛所属分类；按分类限购时不重复显示此筛选 |
| 配置状态 | 未配置、已配置、禁止下单互斥；空、大于 0、0 分别对应三种状态 |
| 商品搜索 | 匹配商品/分类名称，忽略关键词前后空格和英文大小写 |
| 重置 | 恢复当前门店全部列表，不清除商品或数量 |
| 当前页全选 | 只勾选当前筛选结果的当前页 |
| 选择全部筛选结果 | 用户另行点击后，将选择扩大到全部筛选结果 |
| 批量应用 | 只作用于勾选项；菜品/分类填写对象额度，菜品集填写成员例外保护 |
| 单个/批量移除 | 二次确认后移除对象及相关场景数量；取消不变 |

菜品集的配置状态筛选根据成员保护/例外判断，不表示集合共享额度是否完整。普通菜品/分类状态读取主额度；固定组合的实际额度存于整桌额度时，当前状态可能显示未配置，具体见第 13 章。

批量操作完成或门店/场景上下文切换后清空勾选。菜品集成员移除受到至少两个成员约束。

### 4.10 跨门店复制

“复制到其他门店”复制源门店所有启用周期、所有人数/轮次场景的已配置数量，不只复制一个当前卡片。

- 默认只填目标门店空值，目标已有值保留。
- 覆盖已有配置需要明确勾选，先展示预览和影响范围，再确认。
- 取消复制不改变任何门店。
- 目标门店不存在的商品列为跳过项，不自动新增，不按显示名称匹配。
- 预览说明目标门店、相关场景、对象、填入值与覆盖值。

例：A 店牛肉上限 3，B 店相同身份对象已有 2。默认复制后 B 店仍为 2；选择覆盖并确认后为 3。B 店未选此对象时跳过，不自动补选。

## 5. 第三步：超限授权

### 5.1 配置字段

| 字段 | 默认/可选值 | 含义 |
| --- | --- | --- |
| 允许服务员密码授权 | 普通新草稿默认开启 | 保存这条规则是否开放授权入口 |
| 可选范围 | 本次操作、当前轮、当前订单，可多选 | 授权时可选择的持续范围 |
| 默认范围 | 普通轮次草稿默认当前轮 | 属于已允许范围；仅整单规则不提供当前轮，默认通常回到本次操作 |
| 范围权限 | 本次操作默认值班经理、当前轮默认主管、当前订单默认店长 | 页面保存各范围的权限名称 |
| 授权原因必须填写 | 默认勾选 | 保存执行端授权时使用的原因要求 |

开启授权时，至少一个范围，默认范围包含在已选范围内，每个范围都有权限配置。

### 5.2 凭证的数量和作用范围

| 授权范围 | 绑定信息 | 限制 |
| --- | --- | --- |
| 本次操作 | 本次操作编号 | 不自动适用其他操作 |
| 当前轮 | 当前轮号 | 不放行整个订单周期的上限 |
| 当前订单 | 当前订单号 | 不适用其他订单 |

三种凭证还比较门店、规则、版本、周期、目标和批准的最终数量。

牛肉上限 2，批准到 5 后，匹配范围内数量到 5 可放行；到 6 仍超过批准量。不是一经授权就无限下单。一个操作同时超过总量和牛肉上限时，凭证需覆盖两个违反项；仅放行牛肉不放行总量。

最低份数不足、人数和轮次参数错误不由上限授权绕过。自助餐数量授权不处理售罄、停售、年龄或支付限制。

当前数量函数核对传入凭证，不验证真实员工密码、角色或原因正文；开关在凭证判断中的实际边界见第 13 章。

## 6. 第四步：生效范围

| 字段 | 初始值/选项 | 定义与当前校验 |
| --- | --- | --- |
| 开始日期 | 默认当天，页面标必填 | 有结束日期时，结束不早于开始；当前基础校验未单独拒绝空开始日期 |
| 结束日期 | 默认空 | 空表示长期，填写表示限定结束日 |
| 活动周期 | 默认每周、所有星期勾选 | 每天、每周、每月；周/月至少选择一个值 |
| 每周 | 星期选择 | 仅对应星期属于配置的日期范围 |
| 每月 | 1～31 日 | 当月不存在该日时跳过，不自动换成月末 |
| 活动时段 | 默认晚市全时段 | 全天 00:00–23:59，午市 11:00–16:59，晚市 17:00–23:00 |
| 时段组合 | 全天，或午市/晚市 | 全天与午/晚市互斥，午市与晚市可同时选择 |
| 时段设置 | 全时段、分时段 | 分时段起止在对应时段内，开始小于结束；页面不接受一个跨午夜时间对 |
| 会员范围 | 默认全部顾客，可选指定会员等级 | 全部含非会员；指定等级至少勾一个等级 |
| 生效门店 | 从有配置的参与门店中勾选 | 非空子集；未勾选门店作者数据保留但不进入发布配置 |

活动时段是页面内的固定配置值，不是按每家店营业时间动态读取。

生效条件描述的是交集：例如 A 店、周五、晚市、金卡，表示同时满足这些条件的订单。活动周期是日历安排，限制周期是数量累计范围，两者不互相替代。

当前页面保存条件，冲突函数比较条件交集；数量函数不自行按日期和会员筛规则，接收调用方准备的规则列表。时区、临界结束时刻和实际会员识别不在当前数量函数内处理。

## 7. 第五步：确认发布与规则状态

### 7.1 保存、发布、启用和禁用

| 操作 | 当前处理 |
| --- | --- |
| 自动保存 | 约 900 毫秒防抖保存草稿及步骤；失败显示保存失败并保留恢复内容 |
| 保存草稿 | 保存作者配置，不替换正在使用的正式配置 |
| 第五步继续 | 保存草稿并进入独立发布确认页；返回时回第五步 |
| 确认发布 | 检查结构、数量、门店、冲突和静态可满足性，写正式记录及运行快照 |
| 禁用 | 保留正式记录，状态设为禁用，从活动快照移除 |
| 启用 | 重新校验作者配置，按本次生效门店生成发布配置 |
| 复制规则 | 生成可编辑草稿，不复制订单计数和授权凭证 |
| 编辑系统默认规则 | 可进入全部步骤，选择商品、调整数量和条件 |

系统默认规则改变商品、条件、数量时保留默认身份；改变主体、对象、周期或计量方式时转为普通规则。默认身份不是编辑锁。

“已配置”“已发布”“已启用”“处于生效时间内”是不同概念。数量填完不代表已发布；禁用规则保留配置但不进入活动快照。

### 7.2 发布检查

- 名称、主体、对象和周期结构有效。
- 至少一家参与门店；商品范围有效，菜品集每店至少两个成员。
- 人数/轮次区间连续完整。
- 每个启用周期存在数量，已启用数量的必填项完整。
- 最少与最多关系合法；组合规则的整组字段完整。
- 生效门店是有配置的参与门店的非空子集。
- 允许授权时范围、默认范围和权限配置完整。
- 日期、循环、时段和会员配置通过当前校验。
- 与已启用规则执行冲突检查，并进行静态可满足性检查。

任一检查失败不写入本次发布结果。当前冲突和可满足性检查的具体覆盖范围见第 9.3、13 章。

### 7.3 数据保存

当前规则保存在浏览器 localStorage，仓库键为 `buffet-rule:repository:v1`。

- 作者配置保留参与门店的完整商品、数量和编辑进度。
- 发布配置按生效门店裁剪。
- 活动运行快照只包含已启用规则。
- 本地发布使用一次仓库写入维护记录和快照；写入失败不推进快照。
- 本地发布结果不等于远端门店已经接收，也不等于真实订单已使用该快照执行。

浏览器按协议、主机、端口隔离本地数据。`localhost`、`127.0.0.1`或不同端口可以看到不同草稿和规则记录，即使它们提供的是同一份页面代码。

## 8. 系统默认规则和场景组合

### 8.1 三种入口的区别

| 名称 | 入口 | 当前作用 |
| --- | --- | --- |
| 常用模板 | 第一步，10 个入口，四组展示 | 快速带出主体与周期，不默认选择对象，不填写额度 |
| 系统默认规则 | 规则列表，18 个示例 | 可编辑的规则结构，初始禁用，商品、额度和生效门店待配置 |
| 受控周期组合 | 常用模板中的两种组合 | 同一规则同时限制整个订单与当前轮，两周期分别填写数量 |

18 个系统默认规则分为：

- 4 个整单规则：每单指定菜品、每单菜品集、每人每单指定菜品、每人每单菜品集。
- 6 个每轮组合规则：见第 8.2 节。
- 8 个每轮基础规则：整桌/人均总量各一条，整桌/人均指定菜品各一条，整桌/人均菜品集按份各一条，整桌/人均菜品集按种各一条。

分类限购通过限购对象选择配置。系统默认规则是配置入口，不表示每条都已启用，也不表示所有示例可以不经冲突检查同时启用。

### 8.2 六个每轮组合规则

这六条规则各包含“1～3 人”和“4 人及以上”两个人数区间，共提供 12 组场景。每个区间分别填写，人数边界可调整。

字段记号：

- H：当前有效人数。
- M、N：整桌每轮所有菜品的最少、最多份数。
- X：指定菜品或菜品集上限。
- P：菜品集每个成员在本轮最多的份数。

**六个组合中的 M、N、P 都是整桌固定值，不乘人数。只有名称包含“每人每轮”的 X 乘 H。** 这些组合使用人数区间，不代表每个字段都是人均值。

| 编号/列表名称 | 对象 | X 的计算 | P 的计算 | 每个人数区间填写内容 |
| --- | --- | --- | --- | --- |
| C1 每轮总量＋每轮指定菜品 | 一个或多个菜品，独立计数 | 每个菜最多 X 份 | 不适用 | M、N、每个菜的 X |
| C2 每轮总量＋每轮菜品集按份 | 一个菜品集 | 集合合计最多 X 份 | 每个成员最多 P 份 | M、N、X、P |
| C3 每轮总量＋每轮菜品集按种 | 一个菜品集 | 集合最多 X 种 | 每种最多 P 份 | M、N、X、P |
| C4 每轮总量＋每人每轮指定菜品 | 一个或多个菜品，独立计数 | 每个菜最多 X×H 份 | 不适用 | M、N、每个菜的 X |
| C5 每轮总量＋每人每轮菜品集按份 | 一个菜品集 | 集合合计最多 X×H 份 | 每个成员最多 P 份 | M、N、X、P |
| C6 每轮总量＋每人每轮菜品集按种 | 一个菜品集 | 集合最多 X×H 种 | 每种最多 P 份 | M、N、X、P |

组合完整性按整组判断：M、N 都填，所有对象 X 都填，菜品集还填 P。数值可以为 0，但仍检查上下限关系。每轮总量统计全轮所有菜品，不只统计所选对象。

## 9. 数量执行与多规则关系

### 9.1 计算过程

数量函数接收规则、门店、订单、有效人数、当前轮次、已点数量和本次变化。

1. 检查订单模式及必要上下文，匹配规则的生效门店。
2. 用有效人数和轮号定位相应配置。
3. 分别将本次变化合入整单累计量、当前轮累计量。
4. 分别统计全轮总量、对象数量、集合成员份数。
5. 对人均主额度乘 H，与整桌兜底分别取更严格的上下界。
6. 检查读到的全部适用限制；全部通过才返回允许。
7. 对上限违反项比较传入授权凭证；最低值和参数问题不靠授权放行。

日期、日历、会员的规则筛选不在该数量函数中进行，调用输入与覆盖范围见第 11.3、13 章。

只有统计对象、单位、周期相同时，多个上限才可以直接理解为取较小值。全轮最多 8 与牛肉最多 2 是两项独立判断，不是“全轮最多 2”。

### 9.2 加菜、提交、换轮及批量处理

| 操作 | 当前数量判断 |
| --- | --- |
| 加菜、改单 | 检查变更后是否超过上限；不因尚未达到最少值而阻止继续选菜 |
| 提交当前轮、结束轮、下一轮、带未结束轮结账 | 检查上限；当前轮数量大于 0 时检查最少值 |
| 当前轮数量为 0 | 跳过最低值；是否允许空单结账由点餐业务处理 |
| 减少数量 | 与已点数量合并净变化，最终不小于 0；数量降至 0 可释放种数 |
| 一批商品中某一项超限 | 整批返回拒绝，不返回部分已接受商品 |
| 重复操作编号 | 输入的已处理编号列表已包含该编号时，返回重复结果 |

历史计数按“产线＋菜品 ID”合并。本轮计数带轮号标签时只取当前轮，无轮号标签时视为调用方提供的当前轮数据。函数不自行持久化计数或已处理操作编号。

### 9.3 多条规则的共存和冲突

冲突检查针对已启用规则，编辑时排除本规则自身，比较门店与日期、日历、时段、会员的交集。名称和先后顺序不决定冲突。

| 规则组合 | 当前处理 |
| --- | --- |
| 同菜、同周期、同固定/人均方式，分别上限 2 和 3 | 菜品重复额度冲突，值相同也属于重复 |
| 同菜、同周期，固定 5＋人均 2 | 可同时存在；3 人时分别检查 5 和 6，实际最多 5 |
| 同菜整单 8＋每轮 3 | 可同时存在；每轮不超 3 且整单不超 8 |
| 一条每轮 3，另一条分轮次首轮 5、后续 2 | 当前按不同周期允许共存；读到两项额度后首轮最多 3、后续最多 2 |
| 牛肉 2＋肉类分类 5 | 可叠加；牛肉≤2且该分类总和≤5 |
| 牛肉 2＋牛肉/羊肉集合 5 | 可叠加；牛肉≤2且集合≤5 |
| 集合 A+B 与 B+C，同周期、同单位、同固定/人均方式 | 成员 B 重叠，集合冲突检查拦截 |
| 同集合按份 6＋按种 3 | 可作为两个不同约束；重复成员保护仍单独比较 |
| 两条固定整桌每轮总量 | 独立总量与六个组合的总量路径执行重复检查；普通总量＋对象路径不完整编译总量约束 |
| 同分类、同周期、同乘算方式重复 | 当前分类目标未进入新约束编译的目标集合，存在不返回冲突的情况 |

轮次区间未进入新约束的交叉比较，不能将当前冲突结果解释为已经逐一证明所有区间内的配置互不冲突。

默认示例可以同时展示，不意味着同时启用都合法。比如多个组合均填写固定每轮总量时，可能出现总量重复。

## 10. 完整配置与下单例子

以下说明数量函数读到完整配置时的计算结果。例子中的订单已匹配门店等适用条件，未额外获得超限授权。页面保存和发布快照存在的读取边界统一列于第 13 章，不把函数级计算例子视为真实 POS 验收记录。

### 10.1 每单指定菜品最多 4 份

规则类型选按桌/订单、整个订单、菜品。第二步选择 A 店牛肉并填 4，第四步勾选 A 店。

第 1 轮牛肉 2，第 2 轮再点 2，整单累计 4，允许；第 3 轮再点 1，累计 5，被对象上限拦截。人数改变不改变固定 4。

### 10.2 每人每单从菜品集中最多点 2 份

选每人整单限购、菜品集、按份，选择牛肉/羊肉/虾滑，集合额度填 2。

3 人时共享上限 6。牛肉 3＋羊肉 2＋虾滑 1 满额；不是三个菜各有 6 份。同一桌哪位食客点了哪一份不分别追踪。

### 10.3 每轮分类合计最多 5 份

选按桌/订单、每轮、分类，肉类额度填 5。当前轮牛肉 3＋羊肉 2 允许，再点肉类 1 超限；青菜如果属于其他分类，不占肉类额度。下一轮的肉类独立累计。

### 10.4 每人每轮 2 份，同时整桌最多 5 份

选按人数、每轮、菜品或分类，人均对象上限填 2，整桌对象兜底填 5。

2 人实际最多 `min(2×2,5)=4`；3 人实际最多 `min(2×3,5)=5`。对象上限和整桌兜底都存在，不选择其中一项忽略另一项。

### 10.5 六个组合中的 C5

在列表打开“每轮总量＋每人每轮菜品集按份”，选择 A 店牛肉、羊肉、虾滑。

- 1～3 人：M=2、N=8、X=1、P=2。
- 4 人及以上：M=3、N=12、X=1、P=2。

| 动作 | 计算结果 | 原因 |
| --- | --- | --- |
| 3 人，本轮牛肉 2＋羊肉 1，提交 | 允许 | 总量 3 在 2～8 内；集合 3≤1×3；成员均≤2 |
| 本轮再加虾滑 1 | 拦截 | 集合 4>3 |
| 本轮增加集合外青菜 1 | 允许 | 集合仍 3；全轮 4≤8 |
| 下一轮重新牛肉 2＋羊肉 1 | 允许 | 各轮独立累计 |
| 4 人，本轮牛肉 2＋羊肉 2 | 允许 | 使用 4 人及以上组，总量 4、集合 4、成员≤2 |
| 4 人，本轮牛肉 3＋羊肉 1 | 拦截 | 集合未超，但牛肉 3>固定保护 2 |

### 10.6 最少 2、最多 5

普通按桌每轮规则只填写总量最少 2、最多 5，不填写对象额度。

| 动作/最终本轮数量 | 数量结果 |
| --- | --- |
| 加菜到 1 | 允许继续选菜 |
| 提交 1、结束轮或带本轮进入下一轮 | 最低值不足 |
| 提交 2 | 允许，等于最少 |
| 加到 5 | 允许，等于最多 |
| 从 5 再加 1 | 超过上限 |
| 清空到 0 后结束空轮 | 跳过最低检查 |
| 最低值不足时传入上限授权 | 仍不放行最低值 |

### 10.7 集合按种＋成员例外

集合 A～F，整桌每轮最多 2 种，默认每种 2 份，A 例外 3。

A3+B2 是 2 种、5 份，允许；再加 C1 变 3 种，超集合种数；A4+B1 虽只有 2 种，但 A 超过 3。A 从 3 减到 1 仍占一种，减到 0 才释放一种。

不同产线同名牛肉各点 1 时，按两个身份计为 2 种，不按名称合并。

### 10.8 整单＋分轮次

选整单＋分轮次保护。整桌集合整单最多 10；第 1～2 轮每轮最多 4，第 3 轮起每轮最多 2。

第 1 轮 4、第 2 轮 4、第 3 轮 2 均允许，整单正好 10。第 4 轮再点 1，虽然本轮未到 2，仍被整单上限拦截。第 1 轮只点 2 也不会把余额给第 2 轮。

### 10.9 空值、0 和批量拒绝

牛肉上限 0，点牛肉 1 即超限；上限清空表示这格未配置。当对象限制仍启用、牛肉仍被选择时，这格空值使数量配置不完整，不能发布。

整条规则的对象上限全部清空而保留合法总量时，仅总量限制启用。所有数量都为空的周期不能发布。

牛肉已点 2、上限 2，本次牛肉加 1＋青菜加 2，整个操作被拒绝。函数不返回“牛肉失败、青菜已接受”的部分成功结果；返回的候选数量不代表已经写入订单。

### 11.4 主要错误结果

| 错误码 | 含义 |
| --- | --- |
| `TOTAL_LIMIT_EXCEEDED` | 本轮全部菜品总份数超过上限 |
| `TOTAL_MIN_NOT_MET` | 提交类操作的非空轮未达到最少份数 |
| `TARGET_LIMIT_EXCEEDED` | 菜品、分类或集合的份数/种数超限 |
| `SAME_DISH_LIMIT_EXCEEDED` | 集合中某成员份数超过保护值 |

## 13. 当前实现范围与计算边界

本章只说明当前代码实际执行到哪里。它与前面的字段定义共同构成当前实现说明，不表示真实 POS 链路已经完成验证。

### 13.1 场景数据读取和组合快照

| 处理位置 | 当前方式 | 已核对结果 |
| --- | --- | --- |
| 普通编辑器数量键 | 区间有rangeId时，使用稳定区间ID，例如`pr\|rr` | 编辑端数量归属按稳定ID维护 |
| 普通v4数量计算 | `v4Scenario`按人数/轮次索引构造场景键，例如`0\|0` | 同样上限2，索引键下3份被拒绝，仅替换为稳定键时3份被允许 |
| 六个组合的计算识别 | `isComboRule`读取`defaultScenarioKey`，据此使用组合数量键和字段 | 完整组合数据可按C1～C6规则计算 |
| 运行规则编译 | `compileRuntimeRules`当前不复制组合身份字段 | 固定上限2的组合直接计算拒绝3，经过该编译后允许3 |

因此，编辑页能保存某个数量，并不能直接推出所有发布快照都能读取该数量。函数示例中的计算含义与实际读取到哪些字段是两个层面。

### 13.2 冲突和可满足性检查

- 新约束编译读取菜品和菜品集目标，未读取分类目标；重复分类可出现无冲突结果。
- 普通规则同时含总量与对象时，当前不完整编译独立总量约束；独立总量和六个组合有各自检查路径。
- 新约束比较不包含轮次区间的交叉位置。
- 普通规则的静态容量检查会使用已选对象上限估算能否达到全轮最低值。例如全轮最少 3、所选牛肉最多 2，会判容量不足；数量计算本身却统计集合外青菜，牛肉 2＋青菜 1可使总量达到 3。六个组合对这种容量推导使用不同处理。
- 静态检查也存在按索引读取场景的路径，不能用其通过结果代替发布数据读取验证。

这些是当前校验覆盖范围，不作为“所有同范围规则均已完成冲突证明”的结论。

### 13.3 生效条件、人数和授权

| 范围 | 当前处理 |
| --- | --- |
| 日期、日历、时段、会员 | 页面保存、冲突检测比较交集；数量函数不自行完成这些规则筛选 |
| 有效人数 | 使用传入的partySize；不根据成人儿童明细自行生成H |
| 不同规则的儿童口径 | 一次调用中的单个人数值本身不表达多套不同口径人数 |
| 授权身份 | 不验证真实密码、员工角色、原因正文，使用外部传入凭证 |
| 授权开关 | 凭证判断未完整使用enabled；关闭但保留allowedScopes并传匹配预制凭证的样例仍可放行 |
| 授权额度 | 比较范围、目标、版本和批准最终数量，不无限放行 |
| 未识别操作阶段 | 未统一拒绝；最低值检查仅在代码列出的提交类阶段执行 |

例如，2099年才生效的规则直接传入数量函数，函数仍会读取其额度判断当前输入。日期不适用的筛选不由这个函数自动完成。

### 13.4 页面字段和状态

- 整单按人数对象行显示整桌对象兜底，数量函数也读取这一字段；策略辅助字段`tableFallback`只在轮次型周期为真，页面并非完全依据此标志决定显示。
- 开始日期页面标为必填，但基础校验没有单独的空开始日期拒绝分支。
- 普通菜品/分类状态读取`targetLimits`；C1等固定组合的额度在`tableTargetCaps`时，可能出现已填固定额度仍显示未配置。
- 非法数量由解析器转成未配置；输入框错误态与数量完整性不是同一层判断。
- 菜品集空例外记录在计算上不使用默认保护，部分展示文字可能仍显示默认状态。

### 13.5 本地功能与外部执行

当前本地仓库、编辑器和计算函数不自动完成以下外部事务：门店接收确认、真实订单写入、员工认证、退款处理、轮号生成和远端历史计数持久化。

运行函数支持负向数量变化，但退款是否生成负向变化、修改哪一轮，不由该函数自行决定。它支持传入已处理操作编号防重，但不自行保存已处理编号。

本地启用记录和活动快照可以检查；真实 POS 是否使用相同快照执行，不包含在当前已核对结果中。
