# TipOut 新增小费规则 · 订单时间段文案统一设计

## 目标

在“小费管理 → 新增小费规则”页面内，将取值条件中所有面向用户展示的“营业时间段”统一改为“订单时间段”。

## 变更范围

- 仅修改 `dist/TipOut/rule-add.html`。
- 覆盖新增规则页内使用“营业时间段”术语的三类取值条件：小费、加收服务费和手动上报小费。
- 覆盖当前文件中恰好 10 个“营业时间段”字面量：3 个条件新增菜单、1 个条件类型名称映射、3 个时间输入表单标签和 3 个条件摘要。

## 不变范围

- 内部字段名继续使用 `hours`。
- 不修改时间起止值的数据结构、保存逻辑、筛选逻辑或计算逻辑。
- 销售额和 Tip Claim 销售额条件使用的独立术语“营业时间”保持不变。
- 不修改详情页、规则列表页、历史数据和项目文档中的既有术语。
- 不修改其他模块中与营业时间有关的文案。

## 实现方式

直接替换 `dist/TipOut/rule-add.html` 中属于该页面取值条件的用户可见字符串。保留代码标识符和持久化结构，以确保历史规则继续正常读取和编辑。

## 验证

1. 静态搜索确认 `dist/TipOut/rule-add.html` 的 10 个“营业时间段”字面量全部变为“订单时间段”，且“营业时间”字面量未被替换。
2. 检查业务文件 diff，确认仅上述 10 个用户可见字面量发生变化，`hours`、控制流和数据处理均未变化。
3. 在本地开发页面打开新增小费规则，分别验证小费、加收服务费和手动上报小费的条件菜单、时间输入项和摘要文案。
4. 使用包含 `hours.start` / `hours.end` 的既有规则，确认仍能回填同一组时间输入框。
5. 保存三类受影响条件后，确认仍输出原有的 `hours: { start, end }` 数据结构。
