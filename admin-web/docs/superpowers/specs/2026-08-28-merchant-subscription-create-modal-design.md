# 商家订阅新增商家弹窗设计

## 背景

商家订阅页面当前把“开通服务”表单常驻在订阅列表左侧，占用列表空间，也让新增操作始终处于展开状态。目标是让页面默认聚焦订阅列表，并通过“新增商家”入口按需打开开通表单。

## 目标

- 商家订阅页面默认只展示订阅明细列表。
- 页面标题区域右侧提供“＋ 新增商家”主按钮。
- 点击按钮后，以居中模态弹窗展示现有“开通服务”表单。
- 保留集团、品牌、门店三种主体层级以及现有业务规则。

## 页面与交互

### 列表页面

- 删除列表内容区左侧常驻的“开通服务”卡片。
- 订阅明细表扩展为内容区主体，并继续显示记录数量、层级提示、续期和停用操作。
- 在页面标题区右侧放置“＋ 新增商家”按钮。

### 开通服务弹窗

- 弹窗为居中模态框，标题为“开通服务”。
- 表单沿用现有字段：主体层级、开通主体、服务包、生效日期、到期日期和备注。
- 主体层级保留集团、品牌、门店；切换层级时刷新对应主体选项。
- 底部提供“取消”和“确认开通”按钮。
- 点击取消按钮或遮罩关闭弹窗，不创建订阅。
- 没有已发布服务包或没有可选主体时，“确认开通”保持禁用。
- 当前演示实现中的主体和服务包均从同步本地快照读取，不引入异步加载状态。空数据时在对应下拉框下展示“暂无可选主体”或“暂无已发布服务包”，并禁用确认按钮；读取异常时在弹窗顶部展示可重试错误，重新打开弹窗即重新读取快照。

## 状态与数据流

- 页面模块状态增加“新增商家弹窗是否打开”、弹窗业务错误和提交中标记。
- 每次打开弹窗都创建全新的表单：主体层级默认选择“品牌”，生效日期初始化为当天，其余字段使用默认空值；不恢复上一次关闭前的选择或错误。
- 用户切换主体层级时只刷新弹窗内容，不关闭弹窗。
- 切换主体层级时清除原主体值，再加载该层级的首个有效主体；若该层级无主体则保持空值并禁用确认。
- 提交继续调用现有 `createMerchantSubscription`，不修改订阅持久化模型和校验规则。
- 创建成功后关闭弹窗、刷新列表并显示成功提示。
- 创建失败时保持弹窗打开，并保留浏览器表单中的当前选择；业务错误显示在弹窗标题下方的 `role="alert"` / `aria-live="assertive"` 区域，便于修正后重试。用户修改任一相关字段或再次提交时清除旧业务错误。
- 浏览器原生必填和日期约束继续与具体字段关联；业务错误不冒充字段错误。
- 提交调用当前为同步本地操作，但仍以提交中标记防止连续点击；提交中禁用确认、取消、遮罩关闭和 `Escape`，操作完成后按成功或失败分支恢复状态，不存在关闭后异步回写弹窗的问题。
- 取消、遮罩或 `Escape` 关闭时销毁本次表单状态、业务错误和提交状态；再次打开按上述默认值重新初始化。
- 续期、停用、服务包发布等已有弹窗行为不变。

## 可访问性与关闭行为

- 弹窗使用 `role="dialog"` 与 `aria-modal="true"`，标题可被辅助技术关联。
- 打开后将焦点移到第一个可操作字段，并把键盘焦点循环限制在弹窗内；关闭后焦点返回“新增商家”按钮。
- 弹窗打开时背景内容使用 `inert` 或等效焦点/指针隔离，并锁定页面背景滚动；关闭时完整恢复。
- `Escape` 键和遮罩点击与取消按钮执行相同的无副作用关闭行为。
- 表单提交期间阻止重复提交。

## 验证

- 默认页面不存在常驻“开通服务”表单，订阅列表占满主要内容区。
- 点击“新增商家”后显示“开通服务”弹窗。
- 集团、品牌、门店切换后主体选项正确更新，弹窗保持打开。
- 首次和关闭后再次打开均默认选择品牌、生效日期为当天，且不保留上次输入或错误。
- 切换层级会移除旧主体选择；无可选主体或无已发布服务包时显示明确空状态并禁用提交。
- 取消、遮罩和 `Escape` 均可关闭且不新增记录。
- 成功提交后弹窗关闭、列表新增记录并显示成功提示。
- 重复订阅等业务错误发生时弹窗保持打开、表单值保留并显示错误。
- 修改字段或重试会清除旧业务错误；错误区域可被辅助技术及时感知。
- 连续点击确认只创建一条订阅；提交中的关闭入口保持禁用。
- 键盘焦点不能逃出弹窗，背景不可交互且不能滚动，关闭后焦点返回入口按钮。
- 原有续期和停用交互通过回归验证。
