# “菜单与购物车展示”排序与产线范围设计

> 日期：2026-08-10  
> 模块：前厅管理中心 / 设置 / 菜单与购物车展示  
> 状态：用户已确认方案 A，待独立规格审查

## 1. 背景与问题

“菜单与购物车展示”分组目前包含 18 个设置项，但组内顺序、适用产线和部分选项文案与产品要求不一致。主要问题包括：

- 18 项仍按历史子分组排序，没有形成用户指定的完整业务顺序。
- 多个菜单结构设置共用同一套四产线定义，无法表达七产线、四产线和仅 Kiosk 等不同范围。
- 购物车三项共用 eMenu、SDI 两产线，无法分别表达送厨状态、订单价格和售罄隐藏的不同范围。
- 菜单图片展示模式和菜品名称字体大小缺少 Online Order。
- 菜单页面展示积分菜错误复用了旧会员产线集合，实际界面与目录元数据不一致。
- 菜单展示位置、积分菜展示位置目前没有“启用产线”选择，不能表达“多选产线后再按产线单选选项”。
- 菜单图片展示模式的“原始模式”以及积分菜位置的“尾部展示”与目标文案不一致。

## 2. 目标

1. 按用户提供的顺序展示该分组全部 18 项。
2. 每项严格使用其独立的适用产线范围和产线显示顺序。
3. 普通功能支持同时选择多个适用产线。
4. 带枚举选项的功能支持“启用产线复选框 + 当前产线单选值”。
5. 保留菜详情选择、菜品字号输入和图片模式例外菜品等现有扩展能力。
6. 保留既有存储键和有效历史配置；新增能力采用向后兼容的数据迁移。
7. 同步目录描述、产线范围生成数据、基线与设计文档。

## 3. 非目标

- 不调整“菜单与购物车展示”分组名称或所属导航位置。
- 不新增或删除设置项。
- 不修改菜品、菜单、积分、购物车或送厨的下游业务算法。
- 不改变页面统一的草稿、保存、放弃修改机制。
- 不把本次 18 项整体迁移为新的元数据驱动渲染引擎。
- 不重构与本分组无关的前厅设置组件。

## 4. 已确认方案

采用方案 A：在现有设置组件内按功能分别定义产线范围，保留现有组件和存储协议，只对排序、产线范围、启用状态与选项文案做有界修改。

选择该方案的原因：

- 菜详情、图片例外菜品和字号输入均有专用交互，继续复用现有组件风险最低。
- 只拆分错误共享的产线常量，不引入全分组级重构。
- 既有 localStorage 字段可继续读取，历史数据迁移边界清晰。

## 6. 交互设计

### 6.1 普通产线多选

- 保留设置项现有总开关时，总开关控制功能整体启用状态，下面的产线复选框控制适用范围。
- 没有总开关的设置项直接展示产线选择或按产线表格。
- 关闭总开关时，子控件隐藏或禁用，行为沿用各现有组件。
- 重新开启时保留上次选择；如果该设置从未配置，继续沿用现有组件的默认初始化策略，但默认集合必须限制在新的合法产线范围内。

### 6.2 带选项的按产线设置

seq 517、607、526 使用统一语义：

- 每行对应一条适用产线。
- 每行有“启用”复选框。
- 未启用时，该行选项控件禁用，但保留上次选项值。
- 启用后，该行必须且只能选择一个枚举值。
- 主设置页显示全部适用产线；按产线页面只显示当前产线。

seq 607 继续保留按模式选择例外菜品的现有交互。只有产线范围、枚举顺序和文案发生变化。

### 6.3 选项文案与编码

- seq 517：显示顺序为“顶部展示、侧边展示”；底层值继续使用 `top`、`side`。
- seq 607：显示顺序为“默认、大图模式、小图模式”；底层值继续使用 `original`、`large`、`small`。原“原始模式”仅改为“默认”，已有值不迁移。
- seq 526：显示顺序为“顶部展示、底部展示”；底层值继续使用 `top`、`bottom`。原“尾部展示”仅改文案，已有值不迁移。
- 新增的 Online Order 行在没有历史值时使用“默认”（seq 607）或“顶部展示”（seq 517、526）。

## 7. 组件与数据设计

### 7.1 菜单结构设置（515–520、524、528）

现有菜单结构组件从“一套共享产线数组”改为“每个 seq 独立配置合法产线”。读取、规范化、渲染和写入均从当前 seq 的配置取得产线集合，防止一个设置项扩展后误影响其他设置项。

seq 517 在现有按产线位置对象之外增加启用产线状态。旧位置对象仍可读取；旧数据存在时，已包含有效位置值的产线视为启用。写入时保留位置值和启用状态，禁用产线不会丢失其上次位置。

### 7.2 购物车设置（616–618）

现有购物车组件从三项共用两产线改为按 seq 配置：

- 616：eMenu、SDI。
- 617：eMenu、SDI、Kiosk、Online Order。
- 618：POS、POS GO、PayPad、eMenu、SDI、Kiosk、Online Order。

各项继续使用原有 `${seq}-guest-menu-cart-lines` 存储键；读取时过滤非法旧值，写入时按当前 seq 的产品顺序稳定输出。

### 7.3 独立组件

- seq 606、608：只调整产线显示顺序，不改变存储结构。
- seq 607：增加 Online Order，调整枚举文案、顺序及无历史值时的默认模式。
- seq 645：增加 Online Order；新增行使用默认 16px，旧三条产线配置保持不变。
- seq 509：现有 UI 已具备五条目标产线，补正产线范围抽取元数据并统一显示顺序。
- seq 525：停止复用旧 `MEMBER_LOGIN_PRODUCT_LINES`，使用独立的 eMenu、SDI、Kiosk、Online Order 定义。
- seq 526：增加启用产线状态，保留现有位置对象与 `top`/`bottom` 值。

### 7.4 数据兼容原则

- 所有原有 storage id 保持不变。
- 新增启用产线状态使用专用字段，并由现有页面草稿/保存机制统一提交。
- 读取旧数据时只保留新合法范围内的产线；已经不再适用的产线不会重新写回。
- 新增产线不会覆盖已有产线的选择、字号、图片模式或菜品选择。
- 关闭某产线只改变其启用状态，不删除其枚举值、字号或例外菜品配置。
- localStorage 不可用或数据格式错误时回退到组件安全默认值，页面仍可渲染。

## 8. 排序与元数据 SSOT

- `FOH_SETTINGS_ASSIGN_MAP["foh-guest-menu-body"]` 按第 5 节表格顺序维护。
- 运行时组内排序继续由 `settings-intra-group-sort.mjs` 从前厅分组 SSOT 生成。
- 专项验证必须断言运行时排序与 SSOT 完全一致，而不是只检查 seq 集合。
- 目录场景描述同步为新的产线范围与选项文案。
- 产线 scope seed、生成文件和 storage registry 与 UI 常量保持一致。
- 生成器不能再用 `GUEST_DEFAULT` 掩盖 seq 509、525 或各设置项的真实范围。

## 9. 错误与边界处理

- 读取到未知产线、重复产线或非法枚举值时忽略该值。
- 读取旧枚举值 `original`、`bottom` 时正常显示为新文案。
- 仅 Kiosk 的 seq 520 仍使用现有多选控件，不特殊改成全局开关。
- CDS 仅加入 seq 509，不进入其他 17 项。
- POS、POS GO、PayPad 仅加入产品表明确列出的设置项。
- 按产线页面访问不适用产线时，该设置项按现有 scope 过滤规则隐藏，而不是展示空配置行。

## 10. 影响范围

风险等级：中等。改动横跨多个设置 UI 组件、排序 SSOT、产线范围生成和浏览器持久化，但不涉及后端接口、资金、权限或外部写入。

| 路径/模块 | 关系 | 影响 | 验证方式 |

| 菜单结构 UI | 515–520、524、528 实现 | affected | 单元/聚焦测试、E2E |
| 菜单类名、图片模式、菜详情、字体 UI | 独立消费者 | affected | 聚焦测试、E2E |

当前工作区存在前序任务和其他未提交改动。实施时只对目标符号做增量编辑，不覆盖或回滚无关变更；如果发现目标符号存在来源不明的重叠修改，则停止并重新确认。
