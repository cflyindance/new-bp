# eMenu 本地配置后台调味设置设计

## 目标

将 `/emenu-local/seasoning-settings` 从占位页升级为可维护的调味配置工作台。门店管理员先在公共调味库维护调味 Option，再按“商品 → 动作 → Option”的顺序批量建立关联，使食客可以对不同商品选择“添加、少放、多放、不要”等调味要求。

本设计解决以下问题：

- 调味 Option 在门店内统一维护和复用，不随商品重复创建。
- 不同商品可以关联不同动作、不同 Option 和不同价格。
- 同一个 Option 可以同时关联同一商品的多个动作。
- 商品规模不固定时，仍能通过搜索、组 / 类 / 菜三级结构、批量操作和单商品维护完成配置。
- 门店所有 eMenu 终端使用同一份本地配置，不产生设备级分叉。

## 范围

### 本期范围

- 调味关联总览。
- 公共调味库的新增、编辑、启用和停用。
- “商品 → 动作 → Option → 预览确认”的批量关联向导。
- 单商品四动作维护抽屉。
- 关联价格、显示顺序和启用状态。
- 草稿、防误关、冲突检查、原子保存和并发版本校验。
- 门店级配置版本和 eMenu 终端同步契约。
- 查看与编辑权限、操作日志和历史订单快照规则。
- 中英文界面文案、键盘操作和窄屏可用性。

### 不在本期范围

- 品牌或云端向门店下发调味配置。
- 审批、发布计划和配置版本回滚界面。
- 每台 eMenu 设备单独覆盖门店配置。
- 动作类型自定义；首期动作固定为四种。
- 商品分类规则继承、动态条件规则或自动推荐调味。
- 每个动作的最少/最多选择数量限制。
- 配方、库存或厨房用量联动。

## 核心概念

### 公共调味 Option

门店级可复用的调味条目，例如葱、蒜、辣椒、花生。公共库只回答“门店有哪些调味”，不决定它适用于哪个商品或动作。

每个 Option 包含：

- `id`：稳定内部 ID。
- `code`：门店内唯一的稳定编码，用于同步和订单快照识别。
- `name` / `nameEn`：中英文展示名称；英文可为空并按现有国际化降级规则显示。
- `status`：`active` 或 `inactive`。
- `sortOrder`：公共库中的默认排列顺序。
- `createdAt` / `updatedAt`。

公共 Option 不保存销售价格。价格属于具体的“商品 + 动作 + Option”关联。

### 固定动作

| 编码 | 中文 | English | 语义 |
| --- | --- | --- | --- |
| `ADD` | 添加 | Add | 在标准配方之外额外添加 |
| `LESS` | 少放 | Less | 少于标准配方用量 |
| `MORE` | 多放 | More | 多于标准配方用量 |
| `NONE` | 不要 | No | 从标准配方中移除 |

界面和食客端始终按“添加、少放、多放、不要”的顺序展示。动作不可新增、删除、改名或排序。

### 商品调味关联

一条原子关联表示某商品在某动作下允许使用某个 Option：

```ts
type ProductSeasoningRelation = {
  id: string;
  productId: string;
  action: "ADD" | "LESS" | "MORE" | "NONE";
  optionId: string;
  priceDelta: number;
  sortOrder: number;
  status: "active" | "inactive";
  createdAt: string;
  updatedAt: string;
};
```

约束如下：

- `(productId, action, optionId)` 在门店内唯一。
- `priceDelta` 使用门店币种和现有金额精度，默认 `0`，首期不允许负数。
- 同一个 Option 可以出现在同一商品的多个动作中。
- 不建立单独的“批量默认价”继承层。批量向导中的默认价只用于生成候选关联，保存后每条关系拥有自己的最终价格。
- `sortOrder` 只控制同一商品、同一动作内的食客端显示顺序。
- 新建关系的 `status` 固定为 `active`。批量向导不能停用关系；关系启停由关联商品清单或单商品抽屉维护。

## 信息架构

调味设置保留现有一级路由：

```text
/emenu-local/seasoning-settings
```

页面内部使用两个页签，不增加新的一级导航：

1. **调味关联**：默认页，查看和维护动作、Option、商品之间的关系。
2. **公共调味库**：维护公共 Option。

页面右上提供两个稳定入口：

- “公共调味库”：切换到公共调味库页签。
- “批量建立关联”：打开批量向导。

## 调味关联工作台

### 总览表

总览按“动作 + Option”聚合为一行，避免商品量增大后形成巨型商品矩阵。

| 列 | 内容 |
| --- | --- |
| 动作 | 固定动作标签 |
| Option | 公共调味名称 |
| 关联商品 | 已启用关联的商品数量，可打开商品清单 |
| 价格情况 | “全部 ¥0”“全部 ¥1.00”或“¥0–¥1.00，共 2 种价格”等汇总，不暗示持久化继承 |
| 状态 | 启用、部分停用或已停用 |
| 操作 | 查看商品、编辑关系 |

筛选区支持：

- 搜索 Option 名称、编码或商品名称。
- 按动作筛选。
- 按商品分类筛选。
- 按关联状态筛选。
- 清空筛选。

筛选和搜索组合生效。结果为空时区分“公共库为空”“尚未建立关联”和“当前筛选无结果”。

所有可能随商品和关系数量增长的列表均使用服务端搜索、筛选、排序和游标分页，而不是把全量数据加载到浏览器。总览默认按固定动作顺序、Option `sortOrder`、Option 名称和稳定 ID 排序；公共库按 `sortOrder`、名称和稳定 ID 排序；关联商品清单按商品分类顺序、商品 `sortOrder`、名称和稳定 ID 排序。翻页和刷新不能造成重复或漏项。

### 关联商品清单

点击“关联商品”数量后展示当前“动作 + Option”对应的商品清单。清单支持商品搜索、分类筛选、价格编辑、启停和移除关联。移除前显示影响数量并要求确认。

### 单商品维护抽屉

从商品清单或搜索结果进入商品后，在右侧抽屉中同时展示四个动作区域。每个区域支持：

- 从已启用公共 Option 中添加关联。
- 查看 Option 名称和价格。
- 修改价格、启用状态和显示顺序。
- 移除关联。
- 拖动排序，并提供键盘可操作的上移/下移替代方式。

抽屉额外支持“复制自其他商品”和“清空某个动作”。复制前展示将新增、更新和跳过的关系；清空必须二次确认。抽屉关闭时若存在未保存修改，必须确认是否放弃。

## 公共调味库

公共调味库采用可搜索列表，支持新增和编辑 Option。名称必填，编码必填且在门店内唯一。编码创建后默认不可编辑，避免终端同步和历史数据引用失效。

状态规则：

- 新建 Option 默认为启用。
- 启用 Option 可以用于新关联。
- 停用 Option 不允许用于新关联，并从食客端隐藏。
- 已存在关联的 Option 不允许物理删除，只能停用。
- 无关联且从未进入订单快照的 Option 才可以删除；若服务端无法确认历史引用，则仍只允许停用。
- 停用不自动删除关系，后台继续显示历史关系及影响商品数。
- 重新启用后，原有启用关系恢复在食客端可见；关系本身已停用的仍保持停用。

## 批量建立关联

主流程采用四步向导。

### 第一步：选择商品

- 商品菜单按照“组 / 类 / 菜”固定一行三列展示，交互结构参照“前厅关联中心 → 特殊品类 → 菜单结构”，但不展示产线列，也不读取或保存产线字段。
- 点击组或类的内容区域只切换右侧浏览位置，不改变已选商品；切换分支后保留其他分支的选择。
- 组、类和菜均提供复选框。勾选组时级联选择或取消该组下全部可选菜，勾选类时级联选择或取消该类下全部可选菜，菜支持逐项多选。只选中部分下级时，组或类显示半选状态。
- 支持按商品名称或编码搜索。搜索结果保留“组 / 类 / 菜”路径，只展示包含匹配菜品的组和类；清空搜索后恢复完整菜单树，已选商品不丢失。
- “选择全部筛选结果”选择服务端当前搜索条件命中的全部可选商品，包括尚未加载或当前未展开的商品。三级结构已提供组、类级批选，因此不再提供“选择本页”。
- 打开向导时，服务端创建一个短期商品选择草稿并返回 `productSelectionToken`、过期时间和菜单选择版本。客户端不展开保存全部商品 ID；菜品单选、组 / 类级联和“选择全部筛选结果”都通过同一 token 更新草稿，服务端返回已选总数及当前可见节点的 `selectedCount` / `selectableCount`，供父级全选和半选计算。
- 组和类的级联操作覆盖其所有可选后代，包括尚未加载的菜。存在搜索词时，组、类和“选择全部筛选结果”只作用于当前搜索命中的可选菜；操作发生时立即把命中的稳定商品 ID 固化进选择草稿，之后清空或修改搜索不会扩大或缩小已经完成的选择。点击组或类进行浏览不改变选择。
- 菜品逐项选择也写入同一商品选择草稿。切换搜索、组或类时保留此前选择，从而支持跨分支累积；搜索条件变化只更新当前浏览结果，不废弃已固化的选择。进入预览和提交时使用同一 token，不在请求中传递无界商品 ID 数组。
- 商品行显示该商品已有多少调味关系；动作和 Option 尚未选择，因此此步骤不按动作预筛选商品。
- 商品停用或不可在 eMenu 销售时不可选择，并显示原因。
- 父级全选和半选状态只统计可选后代；停用或不可在 eMenu 销售的菜仍可见，但不计入 `selectableCount`。同一商品若出现在多个菜单路径，选择身份始终按 `productId` 去重，所有可见位置同步勾选状态，已选总数只计算一次。
- 顶部持续显示已选商品数量。菜单为空时展示维护菜单商品的空状态；加载失败时保留向导并提供重试。
- 返回本步骤修改商品后，清空已选动作、Option、Option 默认价格、整个预览、候选关系移除、单关系价格覆盖和冲突决策，防止旧下游状态误用于新的商品集合。

#### 菜单结构数据契约

调味模块从服务端读取当前门店真实菜单结构，不复用前厅特殊品类的静态演示树。接口先返回稳定排序的组、类元数据和各节点商品数量；活动类的菜品按游标分页加载，避免一次读取全部商品。菜节点直接携带调味领域使用的商品 ID、商品编码、状态、eMenu 可售状态和已有调味关系数量。商品可出现在多个菜单路径，但选择和提交按 `productId` 去重。

菜单结构选择器是调味模块内的独立组件，复用公共菜单选择器的三列布局、导航与父子级联语义，但使用调味模块的数据接口和状态管理。这样既保持交互一致，也避免调味模块依赖前厅页面状态。服务端按组顺序、类顺序、商品 `sortOrder`、商品名称和稳定 ID 排序。选择草稿 API 负责对未加载后代执行级联、对重复路径按商品 ID 去重并返回节点计数；生成的 `productSelectionToken` 继续作为 `ProductSelector` 交给后续“动作 → Option → 预览确认”和批量提交。

`productSelectionToken` 绑定门店、操作者会话、菜单选择版本和过期时间。商品新增或删除、名称或编码改变、移动组 / 类、菜单路径增删、商品启停或 eMenu 可售状态变化都会使 token 失效；接口返回可识别错误，向导保留在第一步并要求重新选择，不静默改变已选范围。

### 第二步：选择动作

- 单选添加、少放、多放或不要。
- 顶部步骤条和后续页面始终显示当前商品范围与动作。
- 返回本步骤修改动作后，保留商品选择，清空已选 Option、Option 默认价格以及全部预览状态，包括候选关系移除、单关系价格覆盖和冲突决策。

### 第三步：选择 Option

- 从已启用公共调味库中多选。
- 支持名称或编码搜索。
- 每个所选 Option 可填写本批次候选关系使用的默认加价，默认 ¥0。
- 非“添加”动作的价格编辑默认收起，但仍可展开填写。
- 公共库为空时提供“前往公共调味库”，并保留商品和动作草稿；同一会话新增 Option 成功后，向导刷新并基于新的 `seasoningConfigVersion` 重建基础版本，重新校验商品选择和动作，再回到 Option 步骤。若商品快照已失效或校验不通过，则要求重新选择商品，不自动合并其他配置变化。
- 返回本步骤调整 Option 时保留商品和动作，但废弃整个旧预览，清空候选关系移除、单关系价格覆盖和冲突决策后重新生成候选关系。

### 第四步：预览并确认

系统将所选 Option 与商品展开为候选关系。3 个 Option × 18 个商品形成 54 条候选记录。服务端将候选结果固化为短期 `previewToken`，首个响应返回状态汇总、未解决数量和第一页；候选列表按游标分页读取，避免无界响应。预览支持：

- 删除个别候选关系。
- 覆盖单条候选关系，即单个 `(商品, 动作, Option)` 的 `priceDelta`；同一商品的不同 Option 可以保留不同价格。
- 按“新增、完全相同、有差异、关系已停用、不可用”筛选。

候选移除、单关系价格覆盖和冲突决策均通过 `previewToken` 写入服务端预览草稿，而不是只保存在当前页面。翻页、筛选或关闭后返回当前向导时，已完成决策不会丢失；服务端持续返回全量未解决数量，只有该数量为零才允许提交。预览草稿与商品选择草稿使用相同的门店、会话、过期和版本隔离规则。提交只携带 `previewToken` 和期望配置版本，由服务端读取完整预览草稿并原子保存，不传递无界候选数组。

批量向导不提供跨商品统一排序，因为 `sortOrder` 的作用域是单个“商品 + 动作”。新关系固定追加到每个商品该动作下现有启用和停用关系之后，所选 Option 之间按公共 Option `sortOrder`、名称和稳定 ID 排列；已有关系的 `sortOrder` 不变。需要精调的商品在保存后通过单商品抽屉排序。因此，批量冲突比较不把向导计算出的追加位置视为用户覆盖值；既有关系的排序只保留原值。

冲突处理：

| 状态 | 处理 |
| --- | --- |
| 不存在 | 标记“新增”；状态为 `active`，排序按追加规则生成 |
| 已存在且为启用、价格与本次值相同 | 标记“已存在，将跳过”；保留原排序 |
| 已存在且为启用、价格与本次值不同 | 标记“有差异”，必须选择“保留原价格”或“使用本次价格”；保留原排序 |
| 已存在但关系已停用 | 标记“关系已停用”，必须选择“保持停用并跳过”或“重新启用”；重新启用时可同时选择保留原价格或使用本次价格，且保留原排序 |
| Option 在向导期间被停用 | 标记“不可用”，禁止提交该条；用户可移除该候选后继续 |
| 商品选择草稿建立后发生任何菜单选择版本变化 | 整个 `productSelectionToken` 失效，返回商品步骤重新确认，不静默重算或生成局部商品候选 |

用户可以移除不可用记录后继续提交，也可以返回前一步修改选择。未解决的“有差异”“关系已停用”或“不可用”记录存在时，确认按钮不可用。

提交成功后显示明确摘要：

> 已新增 46 条，更新 5 条，跳过 3 条。

关闭或普通导航离开有修改的向导时必须确认放弃。“前往公共调味库”是显式的保存并续办例外：它暂存商品和动作草稿，不弹出放弃确认；返回时按前述版本刷新和重新校验规则继续。向导本身不会内嵌新增、改名或停用公共 Option。

## 食客端选择规则

- 只展示商品、关联和公共 Option 均为启用状态的记录。
- 四种动作按固定顺序分组；组内按关联 `sortOrder` 排序，相同值再按公共 Option `sortOrder` 和名称稳定排序。
- 同一个动作下可以选择多个 Option；首期不设置统一数量上限。
- 同一份商品中，同一个 Option 的动作互斥。例如已选“少放辣椒”后选择“多放辣椒”，自动以最后一次选择替换前一次选择，并提供可感知的状态反馈。
- 不同 Option 之间不互斥，例如可以同时选择“少盐”和“不要葱”。
- `priceDelta = 0` 时不显示加价；大于零时使用门店币种格式显示并计入商品行价格。
- 加入购物车和提交订单时，保存动作编码、Option ID、Option 编码、名称快照、成交价格和排序快照。后续改名、调价、停用或删除关联不改写进行中及历史订单。

## 保存、同步与并发

### 草稿与保存

- 批量向导和单商品抽屉均使用页面草稿；只有点击确认保存才写入门店配置。
- 一次保存中的新增、更新、启停和删除使用同一事务；任一校验失败时整批回滚。
- 服务端再次校验唯一性、引用状态、金额精度和版本号，不信任客户端预览结果。
- 商品选择操作和预览必须使用同一 `productSelectionToken`。服务端校验 token 的门店、会话、过期时间和菜单选择版本；失效时返回可识别错误并要求回到商品步骤重新选择。提交使用由该选择草稿生成的 `previewToken`，并再次校验同一版本链。
- 成功后返回新增、更新、跳过数量以及新的门店配置版本。

### 门店级同步

- 配置由门店本地服务器统一持久化，店内所有 eMenu 终端共用。
- 每次成功保存生成递增的 `seasoningConfigVersion`。
- 终端按现有本地配置同步机制比较版本并拉取完整快照；本设计不引入设备级差异包。
- 新快照完成校验后才替换终端当前配置。下载、解析或校验失败时继续使用上一份完整缓存，并记录可诊断错误。
- 终端首次启动且不存在有效缓存时，显示现有系统约定的配置不可用状态，不使用半份数据。

### 并发

- 编辑草稿记录打开时的配置版本。
- 保存时若版本已变化，服务端返回版本冲突，不静默覆盖。
- 界面提示“配置已被其他人更新”，允许用户刷新后重新执行或重新应用本次选择。
- 首期不实现自动三方合并。

## 权限与审计

- 查看权限：访问总览、公共库和关系详情。
- 编辑权限：新增、更新、启停、移除和批量保存。
- 无编辑权限时隐藏或禁用编辑入口，并保持筛选和查看能力。
- 公共 Option 与商品关联的新增、修改、停用、重新启用和移除均写操作日志，记录操作者、时间、对象、变更前后值和配置版本。

## 错误与空状态

| 场景 | 行为 |
| --- | --- |
| 公共库为空 | 引导先创建 Option |
| 没有商品 | 禁用批量建立，并说明需先维护菜单商品 |
| 搜索无结果 | 保留筛选条件并提供清空筛选 |
| 保存校验失败 | 保留草稿，定位到失败记录，不部分写入 |
| 配置版本冲突 | 阻止覆盖，提示刷新并重新核对 |
| 同步失败 | 后台显示失败状态；终端继续使用上一有效版本 |
| Option 被停用 | 禁止新关联；旧关系后台可见、食客端隐藏 |
| 商品被停用 | 保留关系、食客端隐藏；商品重新启用后按关系状态恢复 |

## 组件与职责

实现应保持以下边界，避免把整个功能继续堆入现有 Shell 文件：

- **Shell 路由层**：继续拥有 eMenu 一级导航和页面挂载，只负责把调味路由交给调味模块。
- **调味页面模块**：页签、筛选、总览、空状态和页面级草稿守卫。
- **公共库模块**：Option 列表、编辑表单和停用规则。
- **批量向导模块**：步骤状态、候选关系展开、冲突分类和提交摘要。
- **菜单结构选择组件**：渲染组 / 类 / 菜三列，维护活动组与活动类，处理父子级联、半选、搜索结果路径和已选商品 ID；不包含产线概念。
- **商品维护模块**：四动作抽屉、关联编辑和排序。
- **领域模块**：动作常量、数据类型、唯一键、金额和互斥选择规则。
- **仓储/服务适配层**：列表读取、事务保存、版本冲突和终端同步契约。UI 不直接操作浏览器存储或拼装网络请求。

## 响应式与无障碍

- 桌面端使用聚合表格和右侧抽屉。
- 中等宽度下抽屉宽度不超过视口，表格允许列收敛但动作、Option 和操作始终可见。
- 窄屏下总览切换为分组列表，单商品维护改为全屏抽屉；批量商品选择仍保持组 / 类 / 菜的顺序关系，可在容器内横向浏览三列，不把三层结构混成单一商品列表。
- 向导步骤可通过键盘前进和返回；多选项、拖动排序和关闭按钮均提供可访问名称与键盘替代操作。
- 颜色不作为动作、状态或冲突的唯一表达方式。
- 焦点在弹窗或抽屉内正确约束，关闭后返回触发入口。

## 验收标准

1. `/emenu-local/seasoning-settings` 渲染真实调味工作台，不再显示占位卡。
2. 调味设置内部只有“调味关联”和“公共调味库”两个页签，不改变现有五个 eMenu 一级导航。
3. 可以新增公共 Option；编码唯一；有关联或历史引用的 Option 只能停用，不能直接删除。
4. 批量建立严格按“商品 → 动作 → Option → 预览确认”执行。修改商品时清空动作、Option、默认价格和全部预览状态；修改动作时保留商品但清空 Option、默认价格和全部预览状态；修改 Option 时保留商品和动作并重建预览。
5. 商品步骤按“组 / 类 / 菜”固定一行三列展示，不包含产线；点击组或类只切换浏览位置，勾选组或类级联选择下级菜，部分选择显示半选状态，菜支持逐项多选，跨分支选择不丢失。
6. 菜品单选、组 / 类级联和“选择全部筛选结果”共用服务端商品选择草稿；未加载后代可被正确选择，搜索中的父级操作只影响当前搜索命中，重复菜单路径按商品 ID 去重。菜单相关数据变化、token 过期或门店 / 会话不匹配会使整个 token 失效并返回商品步骤。
7. 预览正确展开笛卡尔候选关系并按游标分页，区分新增、相同、有差异、关系已停用和不可用记录；跨页决策保存在服务端预览草稿，同一商品的不同 Option 可以使用不同关系价格。
8. 未解决的冲突不能提交；停用关系支持“保持停用并跳过”和“重新启用”，且分别覆盖相同价格与不同价格；成功后显示新增、更新和跳过数量。
9. 同一 `(商品, 动作, Option)` 不产生重复关系；同一 Option 可以关联同一商品的多个动作。
10. 单商品抽屉可同时维护添加、少放、多放、不要四个动作的 Option、价格、状态和顺序。
11. 食客端对同一 Option 的多个动作执行互斥替换，不同 Option 可以同时选择。
12. 价格按关联记录生效；¥0 不显示加价；订单保存名称和成交价格快照。
13. 保存为原子事务；校验失败不产生部分写入，草稿仍可修正。
14. 配置版本冲突不会静默覆盖其他会话的修改；从公共库新增 Option 返回向导时会更新基础版本并重新校验，失败则要求重新选择商品。
15. 保存成功产生新的门店配置版本；同步失败的终端继续使用上一份有效完整缓存。
16. 商品或 Option 停用后食客端隐藏，关系和历史订单仍可解释；重新启用遵循各自关系状态。
17. 查看与编辑权限正确控制入口，关键变更具有操作日志。
18. 中英文、桌面和窄屏均可完成主要流程；键盘焦点、状态文本和排序替代操作可用。
19. 商品搜索保留组 / 类 / 菜路径；停用或不可在 eMenu 销售的菜品不可选；菜单为空和加载失败均有明确状态。
20. TypeScript、结构验证和浏览器主流程测试通过，控制台无新增错误。

## 测试策略

- **领域单元测试**：唯一键、动作顺序、金额校验、排序、食客端同 Option 动作互斥。
- **向导单元测试**：商品先选；组、类级联全选和半选；菜逐项多选；跨组切换保留选择；搜索保留三级路径且父级只操作当前命中；未加载后代级联；重复路径同步与去重；商品变化清空全部下游状态；动作变化保留商品并清空 Option 与预览；Option 变化重建预览；候选分页和跨页决策；停用关系保持/重新启用；不同 Option 的单关系价格覆盖；摘要计数。
- **仓储集成测试**：原子事务、停用引用保护、配置版本递增、并发版本冲突和回滚；商品选择草稿的创建、逐项与范围更新、计数、过期、会话和门店隔离；菜单新增、删除、改名、改编码、移动路径或状态变化使 token 整体失效；预览草稿分页、跨页决策、未解决计数和原子提交；公共库新增 Option 后向导基础版本刷新与重新校验。
- **界面集成测试**：公共库、筛选、批量向导、组 / 类 / 菜三列的一行布局、无产线列、空状态、加载重试、单商品抽屉、普通脏数据离开确认、“前往公共调味库”保存续办例外和权限只读态。
- **终端契约测试**：完整快照校验、旧缓存回退、订单快照在改名和停用后的稳定性。
- **浏览器主路径测试**：创建 Option，批量关联到多商品，单商品修改价格和顺序，模拟并发冲突，再验证窄屏及键盘流程。

## 视觉方向

沿用 eMenu 本地配置 Shell 已确认的浅灰背景、白色一体化工作区、轻描边、低阴影、圆角和蓝色强调色。动作使用标签和明确文字区分；不依赖颜色单独表达语义。总览保持信息密度，但不使用装饰性统计卡或多层卡片嵌套。

视觉伴侣中的确认结果为：

- 主流程更新为“商品 → 动作 → Option”；这是用户在实现验收后的最新确认，替代视觉伴侣阶段的原顺序。
- 总览以“动作 + Option”聚合，不采用全量商品矩阵。
- 保留右侧单商品四动作维护抽屉。
- 批量入口和单商品入口编辑同一份原子关联数据，不形成两套配置。
- 批量商品选择的结构参照前厅特殊品类菜单选择器，但视觉继续使用 eMenu 本地配置后台的浅灰背景、轻描边、圆角、间距和蓝色强调色；不照搬前厅页面容器，也不显示产线维度。
