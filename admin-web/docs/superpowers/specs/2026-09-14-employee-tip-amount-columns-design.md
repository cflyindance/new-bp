# 员工分配汇总金额列设计

## 背景

员工分配汇总列表当前使用“原有小费、净调整、最终获得”三列。净调整合并了扣除与分配获得，用户无法直接核对资金从员工扣入小费池、再从小费池分配给员工的完整过程。

## 目标

- 在员工列表中直接展示小费分配的四段金额链路。
- 让用户无需展开明细即可核对扣除、获得和最终结果。
- 保持现有整数分计算、确认状态、异常校验和排序逻辑不变。

## 非目标

- 不修改日期分配汇总。
- 不修改小费规则、分配算法、确认分配或取消分配逻辑。
- 不修改员工明细页和导出字段。
- 不新增后端接口或持久化字段。
- 不展示可由扣除和分配获得直接推导的“净调整”。

## 表格结构

员工分配汇总列表按以下顺序展示：

`员工｜角色｜班次｜工时｜分配前小费｜扣除｜分配获得｜分配后小费｜状态｜操作`

金额列定义如下：

| 字段 | 数据来源与计算 |
| --- | --- |
| 分配前小费 | 当前筛选日期范围内，员工在已确认且校验通过日期中的原始归属小费合计，对应 `beforeCents` |
| 扣除 | 同一范围内从员工小费扣入小费池的金额合计，对应 `deductedCents` |
| 分配获得 | 同一范围内员工从小费池获得的金额合计，对应 `receivedCents` |
| 分配后小费 | `beforeCents - deductedCents + receivedCents`，对应 `finalAmountCents` |

列表移除“原有小费、净调整、最终获得”的旧展示名称。“净调整”不再占用页面列；底层 `netAdjustmentCents` 可继续保留供既有导出或其他功能使用。

## 状态与金额表现

- 员工所有筛选日期均已确认且校验通过：展示四项正式金额。
- 员工仅部分日期已确认：四项金额仅累计已确认且校验通过的日期，并在“分配后小费”旁显示“已确认部分”。
- 员工没有任何已确认日期：四项金额均显示 `—`，不把尚未确认的预测结果显示为正式金额。
- 员工存在规则引用失效、金额守恒失败、金额缺失或不可解析等异常：四项金额统一显示 `—`，状态显示“异常”，不拼接可信部分金额。
- 金额格式沿用页面现有 `money()` 格式化函数和门店币种规则。

## 视觉与交互

- “扣除”金额使用现有扣除语义的红色样式。
- “分配获得”金额使用现有获得语义的绿色样式。
- “分配后小费”使用加粗样式，作为本行主结果。
- “分配后小费”表头保留现有金额排序交互与 `aria-sort` 状态；底层排序键仍为 `finalAmountCents`。
- 有正式金额的行按已确认有效的 `finalAmountCents` 排序；显示 `—` 的空金额行在升序和倒序下均置于有金额行之后。两行金额相同时按员工显示名称升序排列，保证结果稳定。
- 员工、工时的既有排序能力保持不变。
- 表头与金额单元格保持右侧金额列的对齐规则；窄屏允许沿用现有表格横向滚动，不压缩金额到不可读。

## 数据流

1. `aggregateEmployeeDailyDatasets()` 继续以整数分累计 `beforeCents`、`deductedCents` 和 `receivedCents`。
2. 聚合函数继续计算 `finalAmountCents = beforeCents - deductedCents + receivedCents`。
3. 角色、员工和状态筛选生成 `visibleEmployeeSummaryAggregates`。
4. 列表渲染函数从同一条员工聚合记录读取四项金额，不进行新的浮点运算。
5. 排序继续比较 `finalAmountCents`，筛选与顶部员工指标不受列调整影响。
6. 顶部“已确认最终获得合计”等于当前完整筛选结果集中所有非异常员工的已确认且校验通过日期的 `finalAmountCents` 之和；该合计包含部分确认员工的可信部分，与列表显示金额采用同一口径。

## 可访问性

- 四个表头使用完整中文名称，不仅依赖颜色区分含义。
- “分配后小费”排序按钮提供当前排序方向的 `aria-sort` 状态。
- `—` 表示没有可展示的已确认有效金额，不读作零金额。
- “已确认部分”以文本呈现，不能只通过颜色传达。

## 验收标准

1. 员工列表按指定顺序展示四个金额字段，并移除“净调整”列。
2. 校验通过的金额满足 `分配后小费 = 分配前小费 - 扣除 + 分配获得`。
3. 部分确认员工仅统计已确认且校验通过日期，并展示“已确认部分”。
4. 无已确认数据或存在异常时，四项金额均显示 `—`。
5. “扣除、分配获得、分配后小费”分别使用红色、绿色和加粗的现有语义样式。
6. “分配后小费”排序仍使用 `finalAmountCents`，默认倒序行为不变。
7. 角色、员工、状态筛选后的行数据与顶部员工指标保持一致。
8. 日期分配汇总、员工明细、分配计算和确认逻辑不受影响。
9. 桌面端列对齐正确，窄屏无内容重叠；文本和状态对读屏可识别。
10. 分配后小费排序时，`—` 行在升序和倒序下均置底；金额相同的员工按显示名称升序稳定排列。
11. 部分确认员工的可信金额同时计入列表与顶部“已确认最终获得合计”，两者统计范围一致。
