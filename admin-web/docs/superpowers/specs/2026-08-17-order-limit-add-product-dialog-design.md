# 商品配置「添加商品」弹层设计

> **状态更新（2026-08-18）：部分被替代。** 弹层临时草稿、搜索、门店切换和提交写入仍有效；独立第 2 步、主区摘要 / 查看已选入口和门店卡片添加入口已被 `2026-08-18-order-limit-product-quantity-merge-design.md` 替代。当前入口仅位于第 3 步「限购数量」页顶部；提交后商品按门店 × 人数 × 轮次 × 产线展开进入完整规则列表。

## 背景

数量与频次规则第 2 步「商品配置 > 选择商品」当前在主区内联展示参与门店、搜索商品与产线→组→类→菜矩阵。勾选会立刻写入该门店 `storeConfigs`，「查看已选商品」只是对权威配置的汇总。

运营希望改为：**主流程先点【添加商品】**，在弹层中完成选品并【提交】后，已选结果才进入「查看已选商品」。主区不再长期占用大块矩阵，选品与核对职责分离。

## 目标

- 第 2 步主区去掉内联选品矩阵（含门店下拉、搜索、矩阵/搜索结果表面）。
- 新增【添加商品】入口，弹层承载完整选品模块，并提供【提交】/【取消】。
- 弹层内操作为临时草稿；**仅提交**时写入权威 `storeConfigs`。
- 打开弹层时带入当前门店**已提交**选品，支持增删后整份提交覆盖。
- 不改变门店独立配置、数量矩阵剪枝、发布快照与「查看已选商品」删除语义。

## 已确认决策

| 决策 | 结论 |
|---|---|
| 主区形态 | 仅摘要 +【添加商品】+【查看已选商品】，无内联矩阵 |
| 承载方式 | 页内弹层（非独立全屏路由） |
| 写入时机 | 点【提交】才写入；取消/关遮罩/Esc 丢弃未提交改动 |
| 再次打开 | 加载该门店已提交 `structureByLine`（编辑态） |
| 弹层切门店且有脏数据 | 二次确认后丢弃未提交改动，再加载目标门店已提交配置 |
| 两弹层 | 「添加商品」与「查看已选商品」互斥 |

## 第 2 步主区

「选择商品」标题行：

- 左侧：`选择商品` 标题 + 选品摘要（`MenuPicker.formatSummary`；无有效门店时「未选择门店」；有门店无选品时沿用现有空摘要口径）。
- 右侧：
  - 【添加商品】：主按钮（或与现网主操作同级的实心小按钮）。
  - 【查看已选商品（N）】：次级按钮；`N` 口径与现网一致；`N === 0` 时 disabled。

主区**不再渲染**：

- `data-config-store-select` 参与门店下拉  
- 搜索商品输入框  
- `data-brand-menu-structure-picker` / 搜索结果表面  

可选弱提示：「请通过添加商品为各门店配置限购对象。」

主区摘要仍反映 `draft.activeStoreId` 对应门店的**已提交**配置（无活动门店时按现有空态）。

## 添加商品弹层

### 结构

1. 标题：统一为「添加商品」（不论该门店是否已有已提交选品）。  
2. 关闭按钮（与现有 preview overlay 一致）。  
3. 参与门店（必填下拉，选项为系统全部门店列表，口径与现网第 2 步门店下拉一致）。  
4. 搜索商品（已选门店后可用；占位「搜索当前门店全部产线商品」）。  
5. 选品表面：无搜索词时为产线矩阵；有搜索词时为现有搜索结果列表。  
6. 底栏：【取消】【提交】。

### 打开

- 点击主区【添加商品】。  
- 若此时「查看已选商品」已打开：先关闭已选弹层。  
- 初始化临时状态（见下节）：  
  - `storeId`：若 `draft.activeStoreId` 有效则用之，否则 `""`。  
  - `structureByLine`：若有有效 `storeId`，深拷贝该店已提交结构；否则空结构。  
  - `dirty = false`。  
- 未选门店时：不展示可操作矩阵（或展示「请选择参与门店」空态）；【提交】disabled。

### 关闭

- 【取消】、遮罩点击、Esc、标题栏关闭。  
- 若 `dirty`：先确认「确定放弃未提交的修改？」；确认后关弹层并丢弃草稿。  
- 无 `dirty`：直接关闭。

### 提交

1. 校验已选有效 `storeId`。  
2. 对草稿 `structureByLine` 做与现网一致的归一化。  
3. 调用与现网相同的按门店写入管线（如接受明确 `storeId` 的 `applyActiveStoreStructure` / 等价路径），更新该门店 `productLines`、`targetIds`、失效 `limits` 剪枝。  
4. 将 `draft.activeStoreId` 设为提交的 `storeId`（若尚不一致）。  
5. `markEditorDirty()`，关闭弹层，清空临时状态，刷新摘要与「查看已选商品」计数。  
6. 失败：toast，弹层保持打开，保留草稿。

提交成功前，权威 `storeConfigs` 不得因弹层内勾选而变化。

## 临时状态

在 `editorState` 增加例如：

```text
productAddDialog: {
  open: boolean,
  storeId: string,
  structureByLine: ByLineStructure,
  dirty: boolean,
  // 可选：搜索词、组合输入标记、picker 导航记忆 —— 仅弹层会话，关闭即清
}
```

- 不写入 `editorDraft` / `defaultDraft` / 兼容规则 / 发布快照。  
- 离开第 2 步或卸载编辑器：关闭并丢弃临时状态。若弹层 `open && dirty`，**必须先确认**「确定放弃未提交的修改？」：确认则关弹层并丢弃后继续切步；取消则留在第 2 步且弹层保持打开。

## 弹层内交互

### 门店切换

- `dirty === false`：切换 `storeId`，深拷贝目标门店已提交结构到草稿；清空弹层搜索词；同步 `draft.activeStoreId`。  
- `dirty === true`：确认「切换门店将丢弃当前未提交改动」→ 确认后同上；取消则恢复下拉显示为切换前门店。

### 矩阵与搜索

- 复用现有 BrandMenuStructurePicker 与商品搜索逻辑，但**读写绑定到 `productAddDialog.structureByLine`**，任何变更设 `dirty = true`。  
- 不得在变更时调用权威写入 / `markEditorDirty`（提交前不脏规则草稿的「选品」；可选：也不触发规则 autosave。推荐提交前不 `markEditorDirty`，仅提交成功后标记。）

### 底栏

- 【取消】：走关闭逻辑（含 dirty 确认）。  
- 【提交】：无门店或（可选）结构与打开时完全一致且无意义变更时——仍允许提交（幂等覆盖）；无门店时 disabled。

## 与「查看已选商品」

| | 添加商品 | 查看已选商品 |
|---|---|---|
| 职责 | 按门店编辑选品并提交 | 跨门店汇总与删除 |
| 数据源 | 提交前：临时草稿；提交后：权威配置 | 始终权威配置 |
| 删除 | 弹层内取消勾选，提交后生效 | 现网二次确认删除，立即改权威配置 |

互斥：打开任一侧前关闭另一侧。若在已选中删除了当前弹层门店商品，而添加弹层仍打开——因互斥不会同时存在；若未来放开互斥，打开添加时必须重新从权威配置加载。

## 与现有能力关系

- 门店独立 `storeConfigs`：不变。  
- 参与门店 / `participatingStoreIds`：仍由「该店是否有有效目标」在提交后归一化推导。  
- 第 4 步限购数量、复制到其他产线、场景导航：不在本设计范围；仅消费提交后的目标集合。  
- 规则级「保存草稿」：未提交的弹层选品不进入保存内容。

## 非目标

- 一次提交写入多家门店  
- 独立全屏路由页  
- 弹层内嵌「查看已选」  
- 改变分类/菜品限购语义或搜索匹配规则  
- 在 `structureByLine` 之外另建持久化已选清单  
- 主区保留内联矩阵双入口  

## 验证

专项脚本至少断言：

1. 第 2 步主区渲染含添加商品入口标记（如 `data-product-add-open`），且**不再**在主区渲染 `data-config-store-select` / 主区 `data-brand-menu-structure-picker`（这些标记仅出现在添加弹层容器内）。  
2. 存在添加弹层标记（如 `data-product-add-overlay`）与【提交】标记（如 `data-product-add-submit`）。  
3. 存在临时状态工厂，且不进入 `defaultDraft` / `buildCompatibilityRule`。  
4. 存在「仅提交时调用权威写入」的代码路径可区分（助手函数或提交处理中调用 `applyActiveStoreStructure`，而 picker change 在弹层 open 时不走权威写入）。  
5. 打开/关闭/dirty 切门店相关函数或分支存在。

浏览器验收：

1. 主区无矩阵；点添加商品看到门店+搜索+矩阵+提交。  
2. 弹层勾选后不关弹层：查看已选计数不变；提交后计数增加且列表可见。  
3. 取消/Esc：不写入。  
4. 再次打开：勾选与上次提交一致。  
5. 脏切门店：确认后草稿变为目标店已提交态。  
6. 与查看已选互斥。  
7. 提交后第 4 步目标与完成度正确。  
8. 对已有选品门店在弹层清空全部勾选并提交：权威配置被覆盖为空，该店变为未添加，`查看已选` 的 `N` 与第 4 步目标随之更新。
