## 背景

解耦前流程把同一份门店商品配置拆成两个步骤：

1. 「商品配置」按门店选择商品。
2. 「限购数量」再次按门店、产线、人数和轮次填写数量。

参与商品本身就是数量矩阵的行，拆成两步会导致用户跨步骤核对门店、产线和商品。当前方案在不改变数据模型的前提下，将选品入口和数量矩阵合并到同一步。

## 已确认产品口径

| 项 | 结论 |
|---|---|
| 技术路线 | 暂不解耦；继续使用 `storeConfigs[storeId]` |
| 步骤 | 规则类型 → 场景配置 → 限购数量 → 超限授权 → 生效范围 → 确认发布 |
| 步骤导航 | 页面顶部横向展示，并吸附在标题栏下方；窄屏支持横向滚动 |
| 基础信息 | 规则名称、规则描述迁入「规则类型」 |
| 商品配置 | 删除独立步骤，选品能力并入「限购数量」 |
| 添加入口 | 仅保留限购数量页顶部的全局「添加商品」；门店卡片内不重复提供 |
| 规则展示 | 一行一条商品规则，按门店 × 人数 × 轮次 × 产线 × 商品完整平铺 |
| 筛选 | 支持门店、人数、轮次、产线、数量配置状态和菜单搜索 |
| 分页 | 默认 20 条，可切换 10 / 20 / 50 / 100 条 |
| 批量操作 | 勾选规则后可批量应用数量或批量删除商品，选择可跨当前筛选结果的分页保留 |
| 删除确认 | 未填数量直接移除；已有数量时使用自定义确认框 |
| 数量语义 | 空值 = 未配置；`0` = 禁止；非负整数为有效数量 |

## 信息架构

### 六步流程

1. **规则类型**：规则名称、规则描述、限购主体、统计周期、限购对象。
2. **场景配置**：人数区间；多轮规则配置轮次区间。
3. **限购数量**：添加商品、规则筛选、完整商品规则列表、逐行或批量填写数量。
4. **超限授权**：授权范围、默认范围和权限。
5. **生效范围**：日期、周期、时段、会员和生效门店。
6. **确认发布**：汇总复核并下发。

步骤导航位于页面标题栏下方，桌面端横向等分并吸顶；窄屏保持顶部吸附且允许横向滚动。旧草稿步骤索引执行一次性迁移：原第 4 / 5 步分别映射到新第 5 / 4 步，商品、数量、授权和生效范围数据本身不迁移。

### 区间自动补全

- 人数区间和轮次区间的最后一段必须以“及以上”结尾。
- 当用户把最后一段的“及以上”填写为合法结束数字并让输入框失焦时，自动新增下一段开放区间。
- 新区间起始值为上一段结束值加 1，结束值为“及以上”；例如 `2 至及以上` 改为 `2 至 5` 后自动新增 `6 至及以上`。
- 结束数字必须是大于或等于当前起始值的整数；非法输入不自动新增，由步骤校验提示。
- 自动补全会改变场景矩阵维度，因此沿用区间变更规则清空已有数量配置。

### 限购数量页面

从上到下：

1. 页面标题、说明和全局「添加商品」。
2. 门店、人数场景、轮次、产线筛选和菜单搜索。
3. 批量选择与批量填写工具栏。
4. 完整商品规则列表。
5. 分页与每页条数切换。

无商品时展示空态和全局「添加商品」，不渲染空门店卡片。

## 添加商品

### 入口与弹层

- 仅在限购数量页顶部保留全局「添加商品」。
- 弹层内选择参与门店，再按产线 → 组 → 类 → 菜选择商品。
- 弹层内操作先写临时 `productAddDialog.structureByLine`，点击「提交」后才写入权威 `storeConfigs`。
- 切换门店、取消、关闭、Esc 或点击遮罩时，如有未提交变化，使用自定义确认框确认放弃。

### 提交差异

- 新增商品：生成数量矩阵行，全部场景数量留空。
- 保留商品：原数量不变。
- 取消商品：移除矩阵行并清理该商品所有场景数量。
- 取消项均未配置数量：直接提交。
- 任一取消项已有数量：提交前汇总弹一次自定义确认框，明确删除商品数及已有数量商品数。
- 提交失败：保留弹层和临时选品，使用页面内 Toast 提示。

## 完整商品规则列表

- 添加商品后，将每个已选商品按门店 × 人数 × 轮次 × 产线展开为规则行。
- 字段与「查看已配置规则」一致：配置门店、人数场景、轮次、产线、菜单、限购数量；编辑态增加勾选与移除操作。
- 轮次列随规则周期显示：多轮显示具体轮次区间，选择「每轮」时显示“每轮”，选择「与轮次无关」时显示“与轮次无关”，不使用无语义的 `—`。
- 菜单列同时展示商品或分类名称及所属组 / 分类、分类所含菜品数等辅助信息。
- 门店、人数、轮次和产线均支持「全部」筛选；配置状态支持「全部状态 / 已配置 / 未配置」；菜单搜索匹配菜品或分类名称。
- 配置状态以 `cell.configured` 为准：空值属于未配置，数量 `0` 表示禁止但仍属于已配置。
- 配置状态可与其他筛选和菜单搜索组合生效；切换后回到第一页并清空批量勾选，不修改任何数量数据。
- 筛选区提供“重置筛选”，一键清空门店、人数、轮次、产线、配置状态和菜单搜索，回到第一页并清空批量勾选。
- 默认每页 20 条，可切换 10 / 20 / 50 / 100 条；筛选、搜索和切换每页条数后回到第一页。
- 可逐行填写数量，也可跨当前列表分页勾选多条规则后批量应用数量。
- 批量工具栏不提供“选择本页”和“清空选择”；用户通过各规则行复选框逐项选择或取消，避免误选整页商品规则。
- 批量删除按门店 + 产线 + 商品去重，删除对应商品的全部人数与轮次规则，与单行“移除”语义一致。
- 批量删除的商品均未配置数量时直接执行；任一商品已有数量时只汇总弹出一次自定义确认框，展示所选规则数、去重商品数和已配置商品数。
- 删除完成后清空勾选；删除最后一个商品时沿用参与门店和生效门店清理逻辑。
- 场景矩阵、产线 Tab、组合平铺、分开选择及场景锚点导航不再出现在限购数量主区。
- 新增商品数量默认留空；进入下一步时校验全部门店、产线、商品和场景。
- 缺失数量时禁止离开并提示缺失单元格数量；`0` 视为已配置。

### 行移除

- 商品所有场景均未填数量：直接移除。
- 任一场景已有数量：弹自定义确认框，确认后删除商品及全部场景数量。
- 取消确认后商品和数量完整保留。
- 删除最后一个商品后，该门店不再属于参与门店，并从生效门店集合移除。

## 数据模型

编辑权威保持不变：

```text
editorDraft
├── participatingStoreIds
├── deployStoreIds
├── deployExcludedStoreIds
└── storeConfigs
    └── "<storeId>"
        ├── structureByLine
        ├── productLines
        ├── targetIds
        └── limits
```

`limits` 键继续为：

```text
partyIndex|roundIndex|productLineId|targetId
```

规则筛选、搜索、分页和批量勾选均为界面临时状态，不进入发布数据。

## 兼容

- 历史 `storeConfigs`、商品结构和数量原样读取。
- 原商品配置步骤的数据直接成为限购数量矩阵行。
- 规则名称和描述改在第一步显示。
- 旧 7 步索引一次性映射为新 6 步索引，并写入 `productQuantityMergedVersion = 1` 防止重复迁移。
- 发布物化、兼容顶层字段和运行时消费者保持不变。

## 校验与异常

- 第 1 步：规则名称、主体、周期和对象必填。
- 第 2 步：人数 / 轮次区间连续且最终覆盖“及以上”。
- 第 3 步：至少一个商品或分类；全部数量单元格已配置。
- 第 4 步：授权范围和权限完整。
- 第 5 步：至少一家生效门店，且只能选择已有商品的门店；日期、周期、时段和会员条件有效。
- 第 1～5 步实时校验当前步骤；存在错误时“下一步”按钮禁用，并通过按钮 `title` 提示首个未满足条件。
- 第 6 步“保存并下发”执行全量校验；任一步骤未通过时按钮禁用并提示原因。
- 输入、选择、删除或自动补全导致数据变化后立即刷新按钮状态；点击处理仍保留校验作为兜底，禁止绕过。
- 所有二次确认使用页面内自定义确认框；禁止原生 `alert/confirm/prompt`。

## 验收标准

1. 步骤为 6 步，不出现独立商品配置步骤。
2. 步骤导航在页面顶部横向吸附展示，窄屏可横向滚动。
3. 规则名称和描述位于规则类型。
4. 限购数量页只有顶部一个添加商品入口，门店卡片内无重复按钮。
5. 添加商品后直接生成数量矩阵行，新增行数量为空。
6. 商品按门店、人数、轮次、产线和商品完整展开，一行对应一条可编辑规则。
7. 支持门店、人数、轮次、产线、配置状态筛选及菜单搜索，筛选不修改数量数据。
8. 默认每页 20 条，可切换 10 / 20 / 50 / 100 条并正确分页。
9. 未填数量商品可直接移除；已填数量商品必须二次确认。
10. 弹层批量取消已有数量商品时只汇总确认一次。
11. 支持逐行填写及勾选多条规则后批量应用数量。
12. 支持按商品去重批量删除；涉及已配置数量时只弹一次汇总确认。
13. 主区不再展示场景矩阵、组合平铺、分开选择及锚点导航。
14. `storeConfigs` 数据形状、数量键、发布结果与改造前一致。
15. 任一步骤条件未满足时下一步 / 保存并下发按钮禁用，补全条件后实时恢复可用。
