## 1. 目标与范围

服务商员工通过自己的 M 平台账号进入已授权品牌或门店；在相同商户内，菜单和操作依据各自商家后台访问角色计算。品牌菜单、门店菜单、商家内部员工角色及商业权益继续独立管理。

只开发现有 Vite 原型的本地授权、页面和测试，不新增生产后端。生产服务端接口鉴权、真正令牌撤销为明确交付缺口，不声称由前端拦截完成。

## 2. 已核实的实现基础

- MState 的 employees 只有 id、roleIds；M_ROLE grants 对应 M 平台目录。
- M 平台权限 UI 的角色分配只选择 M 平台角色。
- enterprise-merchant-impersonate 选择品牌主管理员邮箱；brand-access-store 随后以该品牌账号构建商家会话。
- 品牌／门店菜单上限和商业权益已有计算。
- 商家权限 center-domain 已有资源目录、角色权限及绑定范围的计算，可复用纯函数；不能共用商家的角色和员工持久化数据。
- 商户查询、代登录入口没有完整的服务商员工目标对象校验；不能只在按钮上隐藏实现隔离。

## 3. 方案选择与结构

采用独立的“商户访问授权”模型，复用商家权限目录和计算组件。
不将商家菜单塞进 M 平台角色树；不为服务商员工创建品牌内部账号；不继续无条件模拟品牌 Admin。
独立命名空间使服务商授权与品牌内部授权互不覆盖。

三层授权：
1. M 平台角色：页面、编辑与进入后台等平台动作。
2. 商户访问绑定：访问角色与适用品牌／门店一起保存。
3. 商家后台访问角色：从统一商家权限资源目录选择菜单和真实操作。

## 4. 数据定义

| 字段／对象 | 定义 |
| --- | --- |
| schema | 独立本地存储版本 1，不覆盖已有 MState 或商家权限存储 |
| revision | 非负整数，每次成功保存递增；保存比较打开时版本，冲突保留草稿 |
| roles | 服务商专用商家后台访问角色；稳定 UUID、名称 1–30 字、描述 0–160 字；名称去首尾空格后忽略大小写判重 |
| roles[].grants | 使用统一商家资源键；缺失、未知、失效键默认拒绝；保留隐藏节点的已存配置 |
| employees[].employeeId | 对应 enterprise-staff-account-store 的真实 employeeId，不使用品牌账号 ID |
| employees[].bindings | 每条含 id、roleId、scope；一个角色可有多条范围绑定；不提供个人权限例外 |
| scope | 品牌或门店二选一，多选 ID；品牌范围动态包含其当前及后续门店，界面明确标注“含新增门店”；门店范围仅包含明确选中的 MID |
| 管理员范围 | 仅初始演示系统管理员可有明确系统授权“全部品牌／门店＋完整目录”，用于管理和演示；不是未知账号回退。其账号与 M 平台进入后台动作仍需有效 |
| audit | 事件 ID、时间、真实员工 ID／邮箱、目标对象、操作及前后摘要；不含密码 |

新员工默认无商户访问绑定；普通旧员工不从旧 enterprise-rbac 或品牌 Admin 推断授权。
初始系统管理员兼容授权仅绑定已存在的系统身份 ent001，不根据员工名称或邮箱后缀匹配。
缺存储可生成明确初始管理员默认值；损坏、格式不支持、读写失败时拒绝访问并保留原数据，不能回退为全允许。
删除被使用角色需先移除绑定；普通访问角色默认空白，可复制但不复制员工绑定。系统兼容授权不能通过复制角色赋予普通员工。

## 5. 权限计算

### 5.1 M 平台业务对象范围

账号启用、M 页面权限与目标商户范围同时满足才可访问。品牌／门店列表、候选项、计数、详情及从使用情况等入口访问对象均遵守范围。
仅门店授权可看到该店所属品牌的必要名称、BID，但不能进入品牌级完整详情或品牌代管。
品牌范围授权允许品牌入口及其关联门店；门店范围不自动上升为品牌级权限。
服务包全局配置、账号与权限管理不受商户范围代替，继续使用独立管理权限。全局系统使用分析、订阅列表及其下钻包含商户数据时，统一应用目标范围；硬件设备通过所属门店过滤。未知归属不展示，不以缺归属当成公开数据。

### 5.2 进入商家后台

必须同时满足：
- 当前企业账号启用。
- 对应品牌／门店 M 页面可访问。
- 对应“进入商家后台”动作允许；品牌与门店分别登记动作，详情及列表共用动作。
- 目标属于当前服务商业务对象且员工拥有匹配范围绑定。
- 品牌服务状态允许，目标门店存在，且至少有一个可见商家业务菜单。

校验在进入函数内部执行；按钮状态只是展示。失败不写入代管会话、不切换外壳、不写成功日志，展示具体原因。品牌管理员是否开通不再作为服务商代管的凭据来源。

### 5.3 商家后台菜单与操作

对当前目标 t，仅合并 scope 匹配 t 的角色 grants，再使用商家目录的祖先与依赖规则计算有效角色权限。
可见菜单 = 已发布有效目录 ∩ 品牌菜单上限 ∩（门店视角时门店菜单上限）∩ 匹配角色可见权限。
编辑及独立操作还需匹配角色的相应操作授权；页面可见不意味着可编辑。
一个角色的范围不能与另一角色的 grants 交叉组合。
品牌级汇总只查询其授权品牌范围；门店代管固定在该店。多店操作必须逐店检查所需操作，任一目标不允许则整个提交拒绝，保留草稿，不部分写入。
商业权益单独控制可用性：未开通或已到期服务可按已有产品规则保留服务说明入口，但不能越过员工菜单权限或执行业务操作。
未登记目录的商家业务地址默认拒绝。导航和直接地址均使用同一解析器；无权页不能挂载业务内容。
品牌内部权限管理、服务开通等敏感动作不会因访问其他业务菜单自动获准，只能通过目录中明确有效授权使用；授权不能反向赋予服务商员工权限或扩大商户菜单上限。

### 5.4 身份及审计

代管会话保留真实 employeeId、operatorEmail、目标品牌／门店、startedAt、returnPath 和会话 ID。
新增的会话标记明确来源为服务商委托访问；不再使用品牌主管理员作为权限主体。
商家 UserSessionContext 使用服务商员工身份及计算出的权限快照和目标数据范围；不写入或修改品牌内部员工、角色或 Admin。
品牌／门店操作审计与代管开始结束记录保留真实操作者和目标，已有历史记录不重写。

### 6.1 员工与账号／商户访问授权

| 字段／操作 | 逻辑说明 |

| 商户访问范围 | 展示未配置、品牌数或门店数，不把访问范围当成 M 平台角色 |

### 6.2 商家后台访问角色

待补页面图片：角色列表、全屏角色编辑及预览。

权限管理中心内增加“商家后台访问角色”，与现有 M 平台角色分开命名。
角色列表提供新建、编辑、复制、删除、关联员工数。编辑沿用商家真实目录树，可配置可见、只读、编辑及独立操作。
只显示统一目录存在的资源；不另造业务菜单。保存前核对角色差异和受影响员工数。
效果预览允许选择自己获准目标品牌／门店，只读显示上限裁剪后的结果，不保存或实际进入商户。
所有授权管理操作使用独立 M 平台动作，并限制操作者不能授予自己没有的目标范围或菜单／动作；系统管理员按明确系统权限执行，不通过隐藏 UI 绕过。

### 6.3 商户管理和代管模式

待补页面图片：受限员工列表、代管提示、权限失效提示。
列表及详情使用同一进入动作；无范围时不展示目标业务数据。
代管横幅满宽显示真实员工、当前品牌／门店、“按员工授权访问”及退出。
退出还原 M 平台上下文；返回地址重新鉴权，无权则回到首个可访问平台页，不恢复已撤销访问。

## 7. 变更生效与异常

每次进入、导航、敏感操作提交重新读取当前授权。监听本窗口授权事件和跨窗口 storage 事件刷新有效权限，不将会话快照作为长期唯一依据。
账号停用、撤销目标范围、M 平台进入动作撤销、品牌停用使当前代管失效：业务内容停止挂载，提示原因，退出到重新鉴权后的 M 页面；不在撤权后允许保存旧草稿。
仅菜单收窄时重算导航；当前页面失权显示无权提示，禁止提交，草稿不自动保存。角色扩权后按最新授权重算，不修改品牌菜单。
存储不可读／版本不支持按无权处理，明确提示联系管理员，不清空缓存。保存失败不增加 revision、日志或成功提示；审计与授权写入保持同一持久化事务。
同一浏览器原型无法防篡改；服务端接入清单需覆盖对象归属、资源权限、批量目标、操作人和版本校验。

## 8. 验收矩阵

| 输入／操作 | 预期 |
| --- | --- |
| 客服甲绑定订单只读→广州店，财务乙绑定财务只读→广州店 | 两人均可进入广州店，仅看到各自菜单；编辑和导出默认不允许 |
| 甲绑定订单→广州店、财务→上海店 | 广州不出现财务，上海不出现订单；不存在角色与范围笛卡尔积 |
| 仅上海店授权员工直达广州详情或调用代登录函数 | 拒绝，不写代管会话与成功日志 |
| 员工只有门店范围，尝试品牌级代管 | 拒绝，不能从所属品牌名称扩大访问范围 |
| 员工角色含品牌未开通菜单 | 不显示；同菜单未来开通后按当前角色生效 |
| 门店独立关闭菜单 | 门店代管隐藏；品牌菜单不受修改 |
| 有角色菜单但服务试用过期 | 既有服务说明可见规则保留，业务操作被阻断 |
| 代管中账号停用／范围撤销／进入动作撤销 | 当前及另一窗口后续校验拒绝，停止内容与业务写入 |
| 撤销一个菜单但保留范围 | 导航即时收窄；直接地址与已有页面提交拒绝 |
| 新员工、未知账号、损坏授权数据 | 默认拒绝，无 Admin 回退 |
| 无管理权员工调用保存函数 | 拒绝，revision 和审计均不变 |
| 两窗口并发授权、存储写失败 | 拒绝覆盖／明确报错，保留草稿，不产生假成功 |
| 门店新增或迁移到其他品牌 | 品牌范围跟随当前归属；指定 MID 范围不扩大；目标不存在时拒绝 |
| 多店批量操作一店无编辑权限 | 整体拒绝，无部分写入 |
| 普通商家 Admin／内部员工登录 | 沿用原有品牌授权流程，不受服务商授权存储覆盖 |
