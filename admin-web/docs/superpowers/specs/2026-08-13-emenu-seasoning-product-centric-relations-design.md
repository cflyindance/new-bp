# eMenu 调味关联按商品聚合展示设计

## 背景与目标

当前“调味设置 → 调味关联”以“动作 + Option”为主键汇总关系，同一商品的调味配置分散在多行，维护人员无法直接看出一个商品完整包含哪些动作和 Option。

本次将已保存关联的总览改为“商品 → 动作 → Option”结构：商品作为分页和操作主键，每个商品平铺一行，商品内部按动作分组展示 Option。该展示方式与批量建立关联的确认预览保持相同的认知顺序，但信息密度更高。

目标：

- 一个商品的可见动作和 Option 始终在同一商品行内展示，不跨页拆分。
- 同一动作的 Option 优先在一行连续展示，宽度不足时按完整 Option 项自然换行。
- 支持按商品整体编辑和删除关联。
- 支持商品维度的数字分页、筛选和搜索。
- 通过后端按商品聚合并分页，避免前端逐商品请求和不完整聚合。

## 范围

本设计仅修改“调味关联”页签中已保存关联的读取、展示和商品级操作。

以下内容不在本次范围：

- 公共调味库的展示和维护。
- 批量建立关联向导及其确认预览。
- 单商品编辑抽屉内部的动作、Option、价格和状态编辑能力。
- 食客端调味选择、订单快照和终端同步协议。
- 保存原价或加价系数到最终商品关联；最终关联仍只持久化 `priceDelta`，即实际价格。

本设计替代基础调味设置设计中“调味关联总览按动作 + Option 聚合”的视觉方向；其他领域规则继续沿用现有设计。

## 采用方案

采用新增“商品聚合关系分页接口”的方案。服务端先应用搜索和筛选，再以商品为分页单元聚合动作与 Option；前端一次请求得到当前页全部商品及其完整可见关系。

不采用以下方案：

- 先读取商品列表，再逐个调用单商品关系接口：会产生 N+1 请求、局部失败和列表闪动。
- 继续读取动作 + Option 汇总后由前端反向聚合：现有汇总不包含完整商品映射，无法保证结果正确。
- 一次返回全部关系后由前端分页：门店数据增长后传输和渲染成本不可控。

## 页面结构

### 顶部筛选区

保留现有筛选能力，顺序为：

1. 搜索框：搜索商品名称、商品编码、Option 名称或 Option 编码。
2. 动作筛选：全部动作、添加、少放、多放、不要。
3. 分类筛选：全部分类及门店商品分类。
4. 状态筛选：全部状态、已启用、部分停用、已停用。

筛选条件变化后返回第 `1` 页并重新请求。筛选不会改变每页数量。

### 商品行

每个商品占一个顶层行，结构为：

```text
商品名称 / 分类 / 商品编码 / Option 数量          动作 + Option 明细          编辑  删除
```

- 左侧展示商品名称、分类、商品编码和当前可见关系数量。
- 中间按固定动作顺序展示：添加、少放、多放、不要。
- 仅展示至少包含一个可见 Option 的动作。
- 每个动作独占一行，动作名称使用现有标签样式，同时保留明确文字，不仅依赖颜色区分。
- 同一动作下的 Option 使用横向流式布局，优先在一行展示；空间不足时按完整 Option 项换行，不拆分名称和价格。
- 右侧固定展示“编辑”和“删除”，Option 换行时操作区仍保持在商品行右侧顶部。
- 无编辑权限时隐藏“编辑”和“删除”，查看、搜索、筛选和分页仍可使用。

### Option 字段

每个 Option 只展示：

```text
Option 名称（实际价格）
```

- 实际价格来源为最终关联的 `priceDelta`。
- 使用门店币种格式和两位小数，例如 `花生（¥1.00）`、`酱油（¥0.00）`。
- 不展示 Option 编码、输入原价、加价系数、关系状态、排序值或内部 ID。
- 即使实际价格为 `0`，后台总览仍明确展示 `¥0.00`，便于确认配置值。

### 分页区

商品列表底部展示：

- 左侧：单行展示“每页 [数量] 个商品”。
- 右侧：上一页、数字页码、下一页。
- 每页数量支持 `5、10、20、50`，默认 `10`。
- 切换每页数量后返回第 `1` 页。
- 总页数不超过 `7` 时展示全部数字页码。
- 总页数超过 `7` 时始终展示首尾页、当前页前后各 `2` 页，断层使用不可点击的省略号。
- 首页禁用“上一页”，末页禁用“下一页”。
- 无结果时保留每页数量选择器，当前页为 `1`，隐藏数字页码并禁用上一页和下一页。

## 搜索与筛选语义

服务端以关系为基础生成商品可见集合，处理顺序如下：

1. 丢弃无法找到商品或 Option 的孤立关系。
2. 应用分类筛选。
3. 应用动作筛选。
4. 应用搜索规则，得到商品内当前可见关系。
5. 根据当前可见关系计算商品级状态并应用状态筛选。
6. 移除没有任何可见关系的商品。
7. 对商品排序、分页，再聚合本页商品的动作和 Option。

### 动作筛选

- 选择某个动作后，商品行内只返回该动作及其 Option。
- 没有该动作关系的商品不进入结果，也不计入 `totalProducts` 和分页。
- 选择“全部动作”时展示满足其他条件的全部动作。

### 搜索

搜索使用规范化后的不区分大小写包含匹配：

- 如果商品名称或商品编码命中，搜索本身不裁剪该商品的 Option；该商品展示经过动作、分类和状态条件处理后的全部可见关系。
- 如果商品未命中，但一个或多个 Option 名称或编码命中，只展示命中的 Option 及其所属动作，暂时隐藏同商品内其他 Option。
- 同一个 Option 在多个动作下均命中时，各动作下的关系分别展示。
- 商品匹配与 Option 匹配同时成立时，商品匹配优先，即搜索本身不裁剪该商品的 Option。
- 没有匹配关系的商品不进入分页。

### 状态筛选

状态基于当前商品在动作和搜索处理后的可见关系列表计算：

- `active`：可见关系全部启用。
- `mixed`：可见关系同时包含启用和停用。
- `inactive`：可见关系全部停用。

状态只用于筛选，不在 Option 项中额外展示。状态筛选后的商品数量用于分页统计。

## 排序

- 商品按分类 `sortOrder`、商品 `sortOrder`、规范化商品名称、商品 ID 稳定升序。
- 动作固定按 `ADD、LESS、MORE、NONE` 排序。
- 动作内 Option 按关系 `sortOrder`、Option `sortOrder`、规范化 Option 名称、关系 ID 稳定升序。
- 缺失或非有限的排序值排在有效排序值之后。

## API 与类型

保留现有接口：

- `GET /relations/summary`：保留兼容，不再由本页面主列表调用。
- `GET /relations/products`：保留“动作 + Option → 商品”查询兼容能力。
- `GET /products/:productId/relations`：单商品编辑读取。
- `PUT /products/:productId/relations`：单商品原子保存和整商品删除。

新增：

```http
GET /api/v1/emenu-local/seasoning/relations/product-groups
```

查询参数：

```ts
type SeasoningProductGroupQuery = {
  query?: string;
  action?: SeasoningActionCode;
  categoryId?: string;
  status?: "active" | "mixed" | "inactive";
  page?: number;
  limit?: 5 | 10 | 20 | 50;
};
```

响应：

```ts
type SeasoningProductGroupOption = {
  relationId: string;
  optionId: string;
  optionName: string;
  priceDelta: number;
  sortOrder: number;
  status: SeasoningStatus;
};

type SeasoningProductGroupAction = {
  action: SeasoningActionCode;
  items: SeasoningProductGroupOption[];
};

type SeasoningProductGroup = {
  product: SeasoningProduct;
  visibleRelationCount: number;
  status: "active" | "mixed" | "inactive";
  actions: SeasoningProductGroupAction[];
};

type SeasoningProductGroupPage = {
  items: SeasoningProductGroup[];
  page: number;
  pageSize: 5 | 10 | 20 | 50;
  totalPages: number;
  totalProducts: number;
};
```

接口规则：

- `page` 缺省为 `1`，必须是正安全整数；非法值返回 `invalid_page`。
- `limit` 缺省为 `10`，只接受 `5、10、20、50`；非法值返回 `invalid_page_size`。
- `totalPages = ceil(totalProducts / pageSize)`。
- 零商品时返回 `page = 1`、`totalPages = 0`、`items = []`。
- 非零商品且请求页码超过 `totalPages` 时，返回请求页码、真实分页元数据和空 `items`，不静默改写页码。
- 接口只返回当前页商品的明细，不使用逐商品追加请求。
- 响应中的 `status` 供筛选结果校验和兼容使用，当前 Option 视图不展示状态。

## 编辑行为

- 点击“编辑”打开现有单商品关联编辑抽屉。
- 抽屉读取该商品全部关联，不受当前列表搜索和筛选裁剪影响。
- 保存继续调用现有 `PUT /products/:productId/relations`，使用打开抽屉时记录的 `expectedVersion`。
- 保存成功后关闭抽屉、更新页面持有的配置版本，并按当前筛选、页码和每页数量重新读取列表。
- 如果编辑后商品不再满足当前筛选，该商品从当前结果消失，分页元数据同步更新。
- 发生版本冲突时不覆盖其他会话更新，使用现有版本冲突提示和刷新流程。

## 删除行为

- 商品行“删除”表示删除该商品的全部调味关联，不是只删除当前筛选后可见的动作或 Option。
- 点击后显示二次确认，文案必须包含商品名称，并明确“将删除该商品下全部动作与 Option 关联”。
- 确认后复用现有 `PUT /products/:productId/relations`，提交 `relations: []` 和当前 `expectedVersion`，由服务端在一个事务中删除全部关系并递增配置版本。
- 取消确认不发起请求，不改变列表。
- 删除成功后刷新当前筛选结果。
- 如果删除的是当前页最后一个商品且当前页大于 `1`，前端转到上一页后重新请求；其他情况保持当前页。
- 删除失败时保留当前行并显示错误提示；版本冲突不进行静默重试或覆盖。
- 删除操作沿用商品关系变更审计，记录商品、操作者、变更前关系和新配置版本。

## 状态、空态与可访问性

- 初次加载显示列表骨架或统一加载状态，不展示旧结果与新筛选混合状态。
- 加载失败显示“暂时无法读取调味配置”及重试入口；重试保留当前筛选和分页条件。
- 无任何已保存关系时展示全局空态，并保留“批量建立关联”入口。
- 筛选或搜索无结果时展示筛选空态和清空筛选入口。
- 商品、动作、Option 和操作按钮保持清晰的阅读顺序。
- “编辑”和“删除”使用真实按钮并提供包含商品名称的可访问名称。
- 删除确认弹窗正确约束焦点，关闭后焦点返回原“删除”按钮。
- 窄屏下商品信息、操作区和动作明细可纵向重排；不得横向裁掉 Option 或操作入口。
- 颜色不作为动作和危险操作的唯一表达方式。

## 组件与职责

- `seasoning-page`：页签、筛选、分页状态、操作事件和刷新编排。
- `seasoning-overview-ui`：替换为商品聚合行、动作行、Option 流式列表和分页的纯渲染。
- `seasoning-store`：维护商品聚合页、页码、每页数量和筛选条件。
- `seasoning-api`：新增商品聚合读取方法，保留兼容接口。
- 单商品编辑抽屉：继续负责编辑一个商品的完整关系集合。
- 服务适配层：搜索、筛选、商品聚合、排序、分页和原子删除。

## 测试策略

### 服务端与领域测试

- 按商品聚合，同商品不跨页且动作顺序稳定。
- Option 排序和实际价格输出正确，包括 `0` 和两位小数。
- 每页 `5、10、20、50`、默认 `10`、非法页码和非法页大小。
- 动作、分类、状态筛选的商品数量和明细裁剪正确。
- 商品搜索展示完整关系；Option 搜索只展示命中关系；商品命中优先。
- 停用、混合和全部启用关系的商品级状态计算正确。
- 删除提交空关系集合时原子删除全部商品关系并递增版本。
- 版本冲突不写入部分结果。

### 前端测试

- 商品行、动作行和 Option 同行换行布局。
- Option 只显示名称和实际价格。
- 编辑和删除位于商品行右侧，无权限时不展示。
- 筛选和搜索变化返回第一页，每页数量保持不变。
- 数字页码、省略号、首页末页禁用状态和零结果状态。
- 删除确认、取消、成功刷新、失败保留、末页最后一条回退上一页。
- 编辑保存后保持筛选和合理页码，商品不再匹配时正确消失。
- 桌面、窄屏和键盘操作可完成主要流程。

### 浏览器主路径

1. 建立包含多个商品、多个动作和多个 Option 的关联。
2. 返回调味关联总览，验证每个商品只出现一行且明细完整。
3. 使用动作筛选、商品搜索和 Option 搜索验证裁剪规则。
4. 切换每页数量和数字页码。
5. 编辑一个商品后验证当前列表刷新。
6. 删除一个商品整行，验证二次确认、全部关系删除和分页回退。

## 验收标准

1. 调味关联主列表以商品为分页和操作主键，每个商品平铺一行。
2. 商品内按“添加、少放、多放、不要”分组；每个动作独占一行。
3. 同一动作的 Option 优先同一行展示，宽度不足时按完整 Option 项自然换行。
4. 每个 Option 只展示 Option 名称和实际价格，价格为 `0` 时仍显示 `¥0.00`。
5. 编辑和删除固定在商品行右侧，无编辑权限时隐藏。
6. 编辑打开该商品的完整关联配置，不受当前筛选裁剪影响。
7. 删除经二次确认后移除该商品的全部动作和 Option 关联，而非仅移除可见部分。
8. 商品列表使用数字分页，每页支持 `5、10、20、50`，默认 `10`。
9. 动作筛选只展示匹配动作，无匹配动作的商品不参与结果与分页。
10. 商品搜索展示商品的全部可见关系；Option 搜索只展示命中的 Option 及所属动作。
11. 搜索、筛选、编辑和删除后的 `totalProducts`、页码和列表内容保持一致。
12. 服务端一次返回当前页完整商品分组，不产生前端 N+1 请求。
13. 加载失败、空结果、版本冲突和删除失败均有明确且可恢复的界面状态。
14. 现有公共调味库、批量建立关联和食客端协议不受影响。
