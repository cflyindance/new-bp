# 自助餐固定周期场景统一入口设计

## 背景

当前“按人数”或“分轮次”规则通过场景卡片进入“配置额度”，但按桌/订单的“整个订单”和“每轮”仍直接在规则页展开额度表格。同一种额度配置因此出现两套入口、两套页面层级和不同的保存认知。

本次统一以下周期组合：

- 整单限购；
- 每轮限购；
- 整单＋每轮限购；
- 整单＋分轮次限购。

目标是让所有周期场景遵循同一条路径：先选择场景卡片，再进入统一的“配置额度”页面。现有计算口径、额度字段含义和发布数据不因本次交互调整而改变。

## 已确认方案

采用“统一场景卡片”方案，不使用折叠分组，也不在规则页继续直接展开商品表。

| 周期选择 | 规则页展示的场景卡片 |
| --- | --- |
| 整单限购 | `整单限购` |
| 每轮限购 | `每轮限购` |
| 整单＋每轮限购 | `整单限购`、`每轮限购` |
| 整单＋分轮次限购 | `整单限购`、每个轮次区间各一张卡片，例如 `1轮`、`2轮及以上` |

人数维度仍沿用现有分组方式：存在多个人数区间时，以人数区间分组，并在组内展示对应周期卡片。人数与轮次同时存在时，继续使用现有“人数组＋轮次卡片”视觉模型。

## 页面结构

### 规则页

规则页的周期区域只承担场景导航，不直接渲染额度输入、商品筛选、批量设置或商品列表。

每张卡片展示：

- 场景名称；
- `已配置` 或 `未配置`；
- 商品上限配置摘要，格式保持 `商品上限：x / y 项`；
- 进入箭头。

显式配置 `0` 属于已配置，不得按空值处理。菜品集总额度、整桌兜底或总量上下限已配置时，卡片也应显示为已配置。

### 配置额度页

点击任何场景卡片后，打开现有“配置额度”工作台。页头展示：

- 参与门店数量；
- 当前周期；
- 当前人数区间或轮次区间；
- 当前场景在全部可配置场景中的位置。

主体继续复用现有能力：

- 每轮或整单菜品总数；
- 菜品集共享额度与成员保护；
- 商品、分类或菜品集限购数量；
- 门店、产线、分类、状态筛选；
- 添加、删除当前场景商品；
- 当前页全选与批量设置；
- 多门店商品独立配置。

配置页不得因本次入口统一改变额度计算口径或字段可见性。

## 场景模型

新增统一的“周期场景描述”层，由周期选择和区间生成卡片，不再把是否显示卡片绑定为“按人数或分轮次”。

建议每个场景描述至少包含：

```js
{
  period: "order_lifetime" | "per_round" | "multi_round",
  partyIndex: number,
  roundIndex: number,
  title: string,
  uiKey: string
}
```

生成规则：

- `order_lifetime`：每个人数区间生成一个整单场景；按桌/订单且无人数拆分时使用固定 `partyIndex = 0`、`roundIndex = 0`。
- `per_round`：每个人数区间生成一个每轮场景；按桌/订单且无人数拆分时使用固定 `partyIndex = 0`、`roundIndex = 0`。
- `multi_round`：每个人数区间与每个轮次区间做笛卡尔积；按桌/订单时仅展开轮次区间。
- 所有入口、页头位置和“下一场景”共用唯一的 `allScenarios` 平铺序列。序列先按 `order_lifetime → per_round → multi_round` 排序，再按人数区间页面顺序排序，`multi_round` 内最后按轮次区间页面顺序排序。
- 按桌/订单的“整单＋每轮”序列固定为 `[整单限购, 每轮限购]`；“整单＋分轮次”序列固定为 `[整单限购, 第一个轮次区间, ...最后一个轮次区间]`。
- `uiKey` 只用于导航与 DOM 身份，使用 `buffetSceneIdentity(draft, combo)` 生成，即 `period + partyRangeId/all-party + roundRangeId/all-round`。索引不得作为持久身份。

### 存储键与历史兼容

入口层不得新增存储键。所有额度继续写入当前 `periodValues(config, period)` 周期桶，并调用现有工作台的 canonical key helper：

| 数据用途 | 读取与写入规则 |
| --- | --- |
| 普通规则场景额度 | 继续使用 `v4ScenarioKey(partyIndex, roundIndex, draft)` |
| 系统默认组合规则的共享场景额度 | 仅在现有代码已经使用该语义的位置继续使用 `comboScenarioKeyFor(draft, partyIndex)` |
| 商品、分类单元格 | 继续使用现有 `v4TargetCellKey(...)` / `v4TargetKey(...)`，不得由 `uiKey` 代替 |
| 页面行与导航身份 | 使用 `buffetSceneIdentity(...)` / `buffetSceneRowIdentity(...)`，不得写入额度存储 |

读取与写入必须调用同一条现有 helper 路径。历史 key 原位读取、原位更新，不复制、不双写、不清空；打开再保存但未修改内容时，`periodValues` 的 key 集合与值必须完全不变。人数或轮次区间增删仍由现有 rangeId 兼容逻辑处理，本次不改变其迁移规则。

## 交互与保存

- 点击卡片时保存当前规则页上下文，并对全部参与门店的当前场景可变投影建立深拷贝快照。投影至少包含该场景的商品/分类/菜品集成员、总量上下限、目标额度、整桌兜底、相同菜品保护和例外商品。
- dirty 判定比较当前场景的规范化投影与进入时快照，不以是否触发过输入事件判断。
- “保存并返回”逐店校验当前场景，并将全部参与门店作为一次原子保存；成功后关闭配置页、刷新卡片摘要，并将焦点返回原卡片。
- “保存并配置下一场景”执行相同的原子校验和保存，然后按照 `allScenarios` 打开下一张卡片，并为下一场景重新建立全部参与门店快照。上一场景已经成功保存的内容不得被下一场景的放弃操作回滚。
- 当前场景是最后一张时，不展示“保存并配置下一场景”；不得只以禁用态占位。
- 关闭配置页或按 Escape 时，如本场景相对快照存在修改，弹出放弃修改确认；确认后原子恢复全部参与门店的当前场景投影，取消则留在配置页。
- 保存失败或校验失败时不得更新快照基线、不得持久化任一门店的部分结果，并保留当前输入、筛选、页码与滚动上下文，不关闭、不跳转。

## 校验与错误处理

保存或进入下一场景时，只校验当前场景，但必须逐一校验全部参与门店。任一门店失败时，本次保存整体失败；错误消息展示门店名和字段原因，并聚焦第一个错误字段。继续沿用以下校验：

- 数量必须为 `0` 至 `999999` 的整数；
- 最少份数不得大于最多份数；
- 菜品、分类场景至少保留一个限购对象；
- 菜品集场景至少保留两个成员；
- 删除商品只影响当前场景；关闭并放弃修改时恢复快照。

“未配置”与数值 `0` 必须保持不同语义：空值表示未配置，`0` 表示禁止下单。

## 兼容边界

- 不修改运行时限购计算、冲突检测、发布结构和字段含义。
- 不重新设计配置额度页内部布局；只复用并补齐统一入口所需的场景上下文。
- 不改变人数区间、轮次区间的连续性校验。
- 不改变商品选择、跨门店筛选、批量设置和删除逻辑。
- 不清理或重写历史额度；历史整单、每轮、组合周期数据必须原样回显。

## 验收标准

1. 按桌/订单＋整单限购只展示一张 `整单限购` 卡片，点击进入配置额度。
2. 按桌/订单＋每轮限购只展示一张 `每轮限购` 卡片，点击进入配置额度。
3. 整单＋每轮限购同时展示两张卡片，两者配置互不覆盖。
4. 整单＋分轮次限购展示一张整单卡片和全部轮次区间卡片，各场景配置互不覆盖。
5. 有 `P` 个人数区间和 `R` 个轮次区间时，按人数规则的卡片数分别为：整单 `P`、每轮 `P`、整单＋每轮 `2P`、整单＋分轮次 `P + P×R`；按桌/订单对应 `1`、`1`、`2`、`1+R`。
6. 每张卡片的 `(period, partyRangeId/all-party, roundRangeId/all-round)` 唯一，标题和人数分组归属正确。
7. “整单＋每轮”中整单显示 `1/2` 且下一步进入每轮；每轮显示 `2/2` 且不展示下一场景按钮。“整单＋分轮次”从整单开始依次进入各轮次区间。
8. 按人数、按桌/订单、菜品、分类、菜品集以及单门店、多门店均使用相同入口模型。
9. 保存返回后原卡片获得焦点，摘要即时更新；显式 `0` 计为已配置。
10. A、B 两家门店分别修改额度和场景商品后放弃，两店均恢复；保存成功后进入下一场景再放弃，不回滚上一场景。
11. 任一非当前门店出现非法数量、最少大于最多或成员不足时，整体保存失败；修复后可一次保存成功，失败期间筛选、页码、滚动和输入保持。
12. 对已有整单、每轮和组合周期 fixture，打开再保存但不修改时 `periodValues` key 集合和值完全相同；只修改一个场景时，仅该 `period + scenario` 下目标单元变化。
13. 关闭有未保存修改的配置页必须确认；放弃后恢复进入时快照。
14. 浏览器验收覆盖四种周期组合、三种限购对象以及单门店和跨门店配置。

## 测试策略

- 静态校验脚本验证四种周期到 `allScenarios` 的映射、数量公式、唯一 `uiKey`、全局排序和按钮文案。
- fixture 校验比较无修改保存前后的 `periodValues` key 集合和值，并验证单场景修改不会污染其他周期或场景。
- 静态校验脚本验证按桌/订单的整单和每轮不再渲染 `.olf-inline-workbench`。
- 浏览器验收分别创建四种周期规则，逐卡片配置不同额度并检查回显。
- 浏览器验收检查全局场景位置、跨周期连续配置、末场景按钮、关闭放弃、跨门店原子恢复和校验失败保留现场。
- 回归菜品、分类、菜品集，多门店筛选、添加删除、批量设置和显式 `0`。
