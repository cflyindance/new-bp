# 数量与频次规则已选商品预览设计

## 背景

数量与频次规则第 2 步“商品配置”已经支持按配置门店独立选择商品，并可搜索当前门店全部产线商品。用户完成多门店、多产线选择后，目前只能通过门店下拉和层级选择器逐一回看，无法集中核对整个规则已经选择的限购对象，也无法从汇总视图快速移除误选项。

本次在“选择商品”区增加“查看已选商品”入口。弹窗集中展示所有已配置门店的实际限购对象，支持按门店和产线联动筛选、分页、单个删除、批量删除和全部删除。弹窗只派生现有门店商品结构，不新增第二份持久化清单。

## 已确认口径

- 采用商品配置页内弹窗，不跳转独立页面。
- 入口展示所有已配置门店的实际限购对象总数。
- 默认展示全部已配置门店和全部产线。
- 增加“门店”“产线”两个筛选条件。
- 选择门店后，产线下拉只展示该门店存在已选对象的产线。
- 按菜品限购时每行展示一个菜品。
- 按分类限购时每行展示一个分类，并显示该分类包含的菜品数量。
- 单个、批量和全部删除都必须二次确认。
- 默认每页 10 条，可切换 10、20、50 条。
- 删除继续复用现有商品结构级联和数量矩阵剪枝流程。
- 关闭并重新打开弹窗时，筛选、分页和勾选状态恢复默认值。

## 页面与交互

### 入口

在第 2 步“商品配置”的“选择商品”标题区右侧增加次级按钮：

```text
查看已选商品（N）
```

`N` 是所有有效配置门店的实际限购对象数量，而不是展开后的菜品总数：

- 按菜品限购：每个已选菜品计 1。
- 按分类限购：每个已选分类计 1。

没有任何已选对象时按钮禁用，并保持显示“查看已选商品（0）”。按钮数量在层级选择、搜索选择和预览删除后立即更新。

### 弹窗结构

弹窗标题为“查看已选商品（N）”，`N` 为当前规则全部已选对象总数。弹窗主体从上到下分为：

1. 操作区：批量删除、全部删除。
2. 筛选区：门店、产线。
3. 已选对象表格。
4. 分页区：筛选结果总数、页码、每页条数。

弹窗打开后焦点进入标题或第一个可操作控件；按关闭按钮或 `Escape` 关闭后，焦点返回“查看已选商品”入口。

### 筛选

门店筛选默认值为“全部门店”，选项只包含至少有一个已选对象的有效配置门店，顺序沿用系统门店顺序。

产线筛选默认值为“全部产线”：

- 门店为“全部门店”时，产线选项由全部已选对象涉及的产线并集生成。
- 选择具体门店后，产线选项只保留该门店存在已选对象的产线。
- 若原产线筛选在切换门店后不再有效，自动恢复为“全部产线”。

任一筛选变化后清空表格勾选并回到第 1 页。筛选无结果时展示“当前筛选条件下暂无已选商品”，保留两个筛选值，允许用户继续修改。

### 表格

按菜品限购时列为：

```text
勾选 | 配置门店 | 产线 | 商品名称 | 商品分类 | 操作
```

商品分类展示“组 / 分类”路径，商品名称保留现有产线后缀，用于区分跨产线同名菜品。

按分类限购时列为：

```text
勾选 | 配置门店 | 产线 | 分类名称 | 包含菜品 | 操作
```

分类名称展示“组 / 分类”，包含菜品展示“N 个菜品”。分类规则不把分类展开成可单独删除的菜品行，避免删除单个菜品后与分类限购语义冲突。

表格稳定排序规则为：系统门店顺序、选择器产线顺序、菜单树中的组顺序、分类顺序、菜品顺序。相同数据在刷新和重新打开后保持一致。

表头全选只选择当前筛选结果的当前页，不跨页选择。切换页面、筛选条件或每页条数时清空勾选，避免隐藏选择导致误删。

### 分页

- 默认每页 10 条。
- 可切换 10、20、50 条。
- 修改每页条数后回到第 1 页。
- 删除当前页最后一条后，若当前页超出新总页数，自动回到最后一个有效页。
- 标题数量始终显示全部对象总数；分页区“共 N 条”显示当前筛选结果数量。

### 删除

单个、批量和全部删除都先打开二次确认弹窗：

- 单个删除：展示门店、产线和对象名称。
- 批量删除：展示选中对象数量；允许跨门店、跨产线。
- 全部删除：展示全部对象总数，并明确“不受当前筛选条件限制”。

确认后才执行删除。取消确认不改变表格、筛选、分页或勾选状态。

删除成功后：

1. 更新对应门店商品结构。
2. 重算该门店 `productLines` 和 `targetIds`。
3. 删除已失效目标对应的数量矩阵单元格。
4. 更新商品摘要和入口总数。
5. 刷新预览表格、筛选选项和分页。
6. 某门店无任何目标时，将其商品状态改为“未添加”，并沿用现有规则从生效门店选择中移除。

重新加入已经删除的分类或菜品时，其数量矩阵恢复为“未配置”，不得复用删除前的数值。

## 组件与职责

### 品牌菜单结构选择器

`brand-menu-structure-picker.js` 继续作为菜单树、路径、稳定键和级联选择的唯一事实来源。补充一个面向上层的“枚举已选实际目标”能力，输入 `structureByLine` 和叶子层级，返回稳定描述：

```js
{
  lineId,
  lineLabel,
  groupId,
  groupName,
  categoryId,
  categoryName,
  targetKey,
  targetType,
  dishId,
  dishName,
  dishCount,
}
```

- `targetType === "dish"` 时包含菜品字段，`dishCount` 为 `1`。
- `targetType === "category"` 时菜品字段为空，`dishCount` 为分类下菜品数量。

选择器继续提供按节点键选择或取消的接口。预览删除必须调用该接口，不直接操作键数组。

### 订单限购编辑器

`order-limit-flow.js` 负责：

- 遍历有效 `storeConfigs`，组合带门店信息的预览行。
- 维护弹窗临时状态。
- 生成联动筛选选项。
- 计算筛选、分页和当前页选择。
- 发起删除确认。
- 将删除目标转换为 `{ storeId, lineId, targetKey }`。
- 逐门店更新结构，并通过现有 `syncStoreTargetsFromStructure` 和归一化流程剪枝数量矩阵。

预览组件不能单独维护商品选择事实，也不能绕过 `applyActiveStoreStructure` 所依赖的同步语义。为支持跨门店批量删除，可提取接受明确 `storeId` 的共享结构应用函数，保证活动门店和非活动门店使用同一条更新管线。

### 样式

`order-limit-flow.css` 增加：

- 标题区预览入口。
- 宽弹窗与响应式表格容器。
- 筛选区、删除操作区和分页区。
- 选中行、空状态和确认弹窗层级。

视觉继续使用现有白色表面、浅灰边框、蓝色操作态和红色危险操作，不引入新的设计体系。窄屏下筛选条件纵向排列，表格使用局部横向滚动，弹窗本身不产生页面级横向溢出。

## 数据与临时状态

预览不修改草稿模型。临时状态保存在编辑器会话中，例如：

```js
editorState.selectedPreview = {
  open: false,
  storeId: "",
  lineId: "",
  page: 1,
  pageSize: 10,
  selectedRowIds: [],
  confirmAction: null,
};
```

这些字段不进入：

- `editorDraft`。
- `storeConfigs`。
- `authoringDraft`。
- 正式发布快照。
- 本地规则持久化结构。

预览行使用稳定复合 ID：

```text
storeId|lineId|targetKey
```

批量删除先按复合 ID 去重，再按门店分组更新。分类规则的一个分类只产生一行，因此不会因为分类下多个菜品重复删除同一目标。

## 状态同步

预览打开期间，若底层商品结构因其他操作变化，重新渲染时必须重新派生表格数据，并执行以下归一化：

- 移除已不存在的勾选行。
- 移除已不存在的门店或产线筛选值。
- 修正当前页到有效范围。
- 更新标题总数和分页筛选结果数。

弹窗关闭后完整重置预览临时状态。再次打开默认展示全部门店、全部产线、第 1 页、每页 10 条且无勾选。

## 异常与边界

- 删除确认时目标已失效：跳过该目标，刷新预览并提示实际删除数量。
- 跨门店批量删除：每家门店独立更新；任一门店更新失败时不得留下部分同步的 UI 假象，原型内存操作应先计算全部新结构，再统一提交。
- 无有效配置门店：入口禁用。
- 不可用历史门店：沿用现有不可用门店规则，不展示在预览中，也不计入总数。
- 分类或菜品为空：不生成预览行。
- 删除全部后：关闭删除确认，保留主预览弹窗并显示空状态；入口变为禁用，用户关闭后不可再次打开，直到重新选择商品。
- 用户取消删除：不清空当前选择，便于重新确认或调整。

## 可访问性

- 主预览和删除确认使用独立、正确嵌套的对话框语义。
- 所有图标按钮提供可访问名称。
- 表格勾选框名称包含对象和门店信息。
- 禁用的批量删除按钮保持可辨识状态。
- 删除不能只依赖红色表达危险含义，确认文案明确动作结果。
- 支持键盘完成筛选、翻页、勾选、删除确认和关闭。
- 关闭确认弹窗后焦点返回触发删除的控件；关闭主弹窗后返回预览入口。

## 验收标准

1. 商品配置存在已选对象时显示可用的“查看已选商品（N）”入口。
2. `N` 按实际限购对象计数，分类规则不按分类内菜品数重复计数。
3. 弹窗默认展示所有有效配置门店的已选对象。
4. 门店筛选只展示有已选对象的门店。
5. 选择门店后，产线筛选只展示该门店存在已选对象的产线。
6. 门店与产线组合筛选结果正确，切换筛选回到第 1 页并清空勾选。
7. 菜品规则每行展示一个菜品及其分类路径。
8. 分类规则每行展示一个分类及包含菜品数量。
9. 默认每页 10 条，可切换 10、20、50 条。
10. 全选只作用于当前页；翻页和修改页大小会清空勾选。
11. 单个、批量和全部删除都必须二次确认。
12. 全部删除不受当前筛选条件限制，确认文案明确总数。
13. 删除后商品摘要、入口数量、门店状态和预览表格同步更新。
14. 删除后只清理对应门店和目标的数量矩阵，其他门店和有效目标不受影响。
15. 重新加入被删除对象后数量恢复为“未配置”。
16. 删除当前页最后一条后自动修正页码。
17. 关闭并重新打开弹窗后筛选、分页和勾选恢复默认。
18. 既有层级选择、跨产线搜索、门店独立配置、批量数量、生效范围和发布流程不回归。

## 测试方案

### 专项脚本

- 选择器按叶子层级枚举已选分类或菜品，返回稳定路径与目标键。
- 多门店预览行合并和稳定排序。
- 门店与产线联动筛选。
- 10、20、50 分页和删除后的页码修正。
- 当前页全选及切换上下文清空选择。
- 单个、跨门店批量和全部删除确认载荷。
- 分类规则一分类一行和分类目标删除。
- 删除后仅剪枝对应门店的失效数量单元格。
- 预览状态不进入草稿或发布持久化数据。

### 既有回归

继续执行全部 `verify-order-limit-*.mjs`，重点覆盖：

- 门店商品跨产线搜索。
- 门店独立商品与数量配置。
- 生效门店范围。
- 批量数量目标选择。
- 未配置状态和规则列表滚动。

### 浏览器验收

1. 创建按菜品规则，为多个门店和产线选择商品。
2. 打开预览，核对总数、门店、产线、名称和路径。
3. 验证门店与产线联动筛选及无结果状态。
4. 验证 10、20、50 分页、当前页全选和翻页清空。
5. 取消单个、批量和全部删除确认，确认配置未变化。
6. 确认单个和跨门店批量删除，核对摘要和数量矩阵剪枝。
7. 创建按分类规则，核对分类行、包含菜品数和删除整个分类。
8. 删除当前页最后一条及删除全部，核对页码、空状态和入口禁用。
9. 关闭再打开，确认筛选和分页重置。
10. 检查宽屏、窄屏、键盘焦点、Vite 错误遮罩和明显布局溢出。

### 构建验证

- JavaScript 语法检查。
- 新增专项验证脚本。
- 全部订单限购回归脚本。
- 生产构建。
