# 自助餐规则兼容旧 KPOS 数量限制扩展设计

> 状态：方案与可视化流程已确认  
> 日期：2026-08-31  
> 最近决策更新：2026-09-06（限制周期改为“普通规则单选＋受控组合模板”）
> 适用范围：前厅管理中心 / 自助餐规则  
> 权威关系：本文扩展当前自助餐规则，使其覆盖旧 KPOS 的整单与每轮数量限制。涉及多周期组合、菜品集按份/按种、整桌兜底和例外商品时，以本文为准。

## 1. 依据与目标

本文结合以下已验证资料：

- [KPOS「每人每轮/每轮下单菜品数量限制」完整操作调研](./2026-08-31-kpos-per-round-dish-quantity-limit-field-study.md)
- [KPOS「订单下单数量限制」完整操作调研](./2026-08-31-kpos-per-order-dish-quantity-limit-field-study.md)
- [自助餐每轮组合数量规则设计](./2026-08-31-buffet-per-round-quantity-combination-design.md)
- [自助餐规则“菜品集”限购对象设计](./2026-08-31-buffet-dish-set-limit-design.md)

目标：

1. 在当前自助餐规则模块中覆盖旧 KPOS 的整单、每轮、按订单、按人数、菜品和菜品集限制。
2. 普通规则一次只配置一个统计周期；确需整单与轮次双重保护时，通过受控组合模板生成同一业务规则下的周期子规则，共享商品、门店、会员和生效范围。
3. 保持当前六步编辑流程、全屏生命周期和独立数据空间。
4. 使用“周期分区式＋常用模板快捷填充”降低理解和操作成本。
5. 不跟踪具体食客，按人数始终表示配置值乘订单有效就餐人数。

非目标：

- 本期不新增整单菜品总数最少/最多。
- 不建立全局可复用菜品集资料库。
- 不新增菜品集名称字段。
- 不改变菜单下单限制模块的数据和行为。

## 2. 信息架构结论

继续使用六步流程：

```text
规则类型 → 场景配置 → 商品配置与限购数量 → 超限授权 → 生效范围 → 确认发布
```

### 2.1 规则类型

规则类型只保留两个维度：

- 限购主体：按桌/订单、按人数。
- 限购对象：菜品、分类、菜品集。

保留“额度周期”单选。普通规则只允许选择一个周期，避免把不同统计桶和数量矩阵混在同一个自由配置入口中。

跨周期组合不通过自由多选表达。只有选择系统提供的受控组合模板时，系统才可在同一业务规则下生成多个周期子规则。组合模板必须把每个周期及其额度分别展示，不得只显示模板名称。

### 2.2 场景配置

场景配置包含：

1. 常用模板快捷填充。
2. 普通规则的限制周期单选；组合模板的周期只读摘要与分区配置。
3. 按人数规则的人数区间。
4. 分轮次规则的轮次区间。
5. 自然语言规则摘要。

限制周期支持：

- 整个订单。
- 每轮。
- 分轮次。

普通规则必须且只能选择一个周期。选择分轮次后才显示轮次区间；选择按人数后才显示人数区间。

周期组合约束固定如下：

- “每轮”和“分轮次”语义重叠，任何规则或模板都不得同时包含二者。
- “整个订单＋每轮”只允许通过受控组合模板创建。
- “整个订单＋分轮次”只允许通过受控组合模板创建。
- 不提供“整个订单＋每轮＋分轮次”组合。
- 用户从组合模板切换回普通规则时，必须明确选择保留哪个单一周期；系统不得静默丢弃另一个周期配置。

## 3. 常用模板

模板预填周期和数量区块，不产生新的限购主体或限购对象。单周期模板允许继续修改周期；跨周期模板的周期组合固定，只允许分别修改各周期的额度和场景内容。

| 模板 | 默认周期 | 默认区块 |
| --- | --- | --- |
| 基础整单限购 | 整个订单 | 指定对象最大额度 |
| 每人每轮＋整桌兜底 | 每轮 | 每轮总量、指定对象、整桌兜底 |
| 整单＋每轮保护 | 整个订单、每轮 | 整单对象上限、每轮对象上限、单品保护 |
| 整单＋分轮次保护 | 整个订单、分轮次 | 整单对象上限、各轮次区间对象上限 |
| 分轮次递减 | 分轮次 | 各轮次区间指定对象上限 |
| 自定义配置 | 用户单选 | 用户选择一个周期和至少一个数量区块 |

模板选择后必须展示预填结果，禁止用模板名称隐藏真实规则内容。

## 4. 商品统计语义

### 4.1 菜品

- 分类节点只用于快速选择，保存时展开为具体菜品身份。
- 每个选中菜品独立计算额度。
- 菜品身份至少包含 `storeId + productLineId + dishId`。

### 4.2 分类

- 保存正式菜单分类身份。
- 分类内所有有效菜品共享分类额度。
- 分类身份至少包含 `storeId + productLineId + categoryId`。

### 4.3 菜品集

- 一条规则、每家门店恰好一个逻辑菜品集。
- 不增加菜品集名称字段，规则名称承担业务标识。
- 每家生效门店至少有 2 个有效成员。
- 允许跨分类、跨产线选择，所有成员共同消耗一个额度。
- 计量方式支持“份”和“种”。

## 5. 周期分区数量设计

普通规则的限购数量页面只展示选中的单一周期。受控组合模板按以下固定顺序展示其包含的周期分区：

```text
整个订单 → 每轮 → 分轮次
```

### 5.1 整个订单

本期只支持指定对象最大额度，不支持整单总量上下限。

| 对象 | 按桌/订单 | 按人数 |
| --- | --- | --- |
| 菜品 | 每个菜品整单最多 `L` 份 | 每个菜品整单最多 `L × N` 份 |
| 分类 | 每个分类整单共享 `L` 份 | 每个分类整单共享 `L × N` 份 |
| 菜品集 | 集合整单共享 `L` 份或种 | 集合整单共享 `L × N` 份或种 |

`N` 为订单当前有效就餐人数。按人数时允许配置不随人数增长的“整桌整单兜底上限”：

```text
整单有效上限 = min(人均配置值 × N, 整桌整单兜底上限)
```

兜底上限未配置时只执行人均额度。

### 5.2 每轮

提供三个可以独立启用、同时生效的区块。

#### A. 每轮菜品总数

- 支持最少和最多；至少配置一个。
- 按桌/订单直接使用固定值。
- 按人数使用人均值乘 `N`，并允许配置固定整桌每轮最少值和最多值。
- 人均最少与整桌最少同时配置时取更严格的较大值；人均最多与整桌最多同时配置时取更严格的较小值。
- 最少数量只在提交或结束非空当前轮时校验。
- 最大数量在加购、改量和提交时校验。

```text
EffectiveMin = max(PerPersonMin × N, TableMin)
EffectiveMax = min(PerPersonMax × N, TableMax)
```

任一侧未配置时忽略该侧对应项。例如未配置 `TableMin` 时，最低值只使用 `PerPersonMin × N`。

#### B. 每轮指定对象额度

- 菜品：每个菜品独立上限。
- 分类：分类成员共享上限。
- 菜品集：成员共享份数或种数上限。
- 按人数时配置值乘 `N`，并允许整桌每轮兜底上限。

#### C. 每轮单品保护

- 菜品、分类可配置每轮相同菜品最大份数。
- 菜品集按份时配置“集合内每个菜品最多 N 份”。
- 菜品集按种时配置“每种菜品最多 N 份”。
- 支持统一默认上限和例外商品上限。
- 未配置默认上限且未进入例外行的菜品，只受其余命中规则限制。
- 同一菜品不能进入两条例外行。

单品保护只作用于本规则的商品范围，不扩展到门店全部菜单：

- 按菜品：作用于已选菜品。
- 按分类：作用于已选分类当前快照中的成员菜品。
- 按菜品集：作用于菜品集成员。

默认单品上限作用于上述完整范围；例外商品必须从同一范围中选择，并覆盖默认值。本文关于作用域的定义取代《自助餐每轮组合数量规则设计》中“作用于全部有效菜品”的旧定义，以符合“一条规则共享商品范围”的已确认方案。

### 5.3 分轮次

分轮次沿用每轮的三个数量区块，但每个轮次区间保存不同配置。例如：

- 第 1 轮：每人最多 3 份。
- 第 2～3 轮：每人最多 2 份。
- 第 4 轮及以后：每人最多 1 份。

人数区间与轮次区间形成数量矩阵。页面按人数/轮次区间卡片分组展示，不直接向用户暴露大矩阵。

## 6. 菜品集按份与按种

### 6.1 按份

```text
Q_set_piece = Σ 菜品集成员的有效份数
```

集合额度限制 `Q_set_piece`。默认单品上限和例外商品上限继续按份检查。

### 6.2 按种

```text
Q_set_kind = 菜品集内数量大于 0 的不同菜单身份数
```

集合额度限制 `Q_set_kind`。不同规格是否属于同一种，沿用菜单身份规范；本期按稳定菜单身份 `productLineId + dishId` 计种。

按种时仍可通过默认单品上限和例外商品上限限制每种菜品的最大份数。

## 7. 页面交互

### 7.1 商品配置

- 使用“参与门店”下拉切换门店。
- 每家门店独立保存商品范围和数量配置。
- 支持产线筛选、商品/分类搜索和查看已选商品。
- 切换门店时自动保存当前未发布草稿。
- 菜品集不足 2 个有效成员时允许保存草稿，但显示待完善并阻止发布。

### 7.2 限购数量

顶部固定展示：

```text
配置门店：[门店下拉]
当前商品范围：X 个菜品 / Y 条产线
```

每个周期区块按人数区间或轮次区间展示：

- 主额度。
- 整桌固定最少值和兜底上限；仅按人数的每轮总量显示固定最少值，其他最大额度只显示兜底上限。
- 默认单品上限。
- 例外商品列表。
- 实时自然语言预览。

自然语言示例：

```text
3～5 人：每人每轮菜品集最多 3 份，整桌每轮最多 12 份；
集合内每个菜品最多 2 份，五花肉最多 1 份。
```

### 7.3 批量操作

- 勾选多个人数/轮次场景批量应用额度。
- 从上一人数区间复制。
- 从上一轮次区间复制。
- 将当前门店配置复制到其他参与门店。
- 复制后按目标门店菜单身份重新校验。
- 不提供“设为不限制”。
- 清空后统一显示“未配置”。
- `0` 明确表示禁止下单。

## 8. 重复、冲突与可满足性

### 8.1 同一规则内部

- 同主体、同周期、同对象身份不得重复配置。
- 同一菜品不得进入两条例外商品规则。
- 菜品集成员按菜单身份去重。
- 人数区间、轮次区间必须连续、互斥、无空档。

### 8.2 不同规则之间

- 同门店、同生效范围、同主体、同周期、同对象身份的重复规则阻止发布或启用。
- 两个菜品集规则在门店、生效范围、主体和周期均有交集时，只要成员菜单身份集合存在交集，就按菜品集重叠冲突阻止发布或启用；不得仅按菜品集规则 ID 或完整集合是否相等判重。
- 不同主体、不同周期或不同对象维度允许叠加。
- 菜品、分类和菜品集可以交叉命中。
- 所有命中规则共同生效，任一不通过即拒绝操作。

### 8.3 可满足性

发布前必须验证每个门店、人数和轮次组合至少存在一个可下单解。允许保存无解草稿，但阻止发布和启用。

## 9. 运行时统计与计算

按桌/订单：

```text
Effective(value) = value
```

按人数：

```text
PartyLimit = value × N
Effective(value) = min(PartyLimit, configuredTableCap)
```

未配置整桌兜底时，`Effective(value) = PartyLimit`。

对于每轮总量上下限：

```text
EffectiveMin = max(configured(PerPersonMin × N), configured(TableMin))
EffectiveMax = min(configured(PerPersonMax × N), configured(TableMax))
```

其中 `configured(...)` 表示只让已配置项参与合并。若最终同时存在 `EffectiveMin` 和 `EffectiveMax`，必须满足 `EffectiveMin <= EffectiveMax`。

统计桶彼此独立：

- 整单桶：当前订单全部轮次累计。
- 每轮桶：当前订单当前轮累计。
- 分轮次桶：当前轮累计，使用当前轮次区间额度。
- 菜品桶：单品分别累计。
- 分类桶：分类成员合并累计。
- 菜品集份数桶：成员跨产线合并份数。
- 菜品集种数桶：数量大于 0 的不同菜单身份数。

购物车待提交、已提交、已送厨及授权超量的有效数量均进入统计；成功退菜、取消或作废后释放额度。

批量加购采用整批原子校验，失败时不得部分写入。订单版本变化时刷新统计桶后重新校验。

## 10. 校验时机与错误处理

### 10.1 加购和改量

- 校验所有最大额度。
- 返回具体命中规则、已用额度、有效上限和最多可追加数量。
- 多条规则命中时，可追加量取全部剩余额度的最小值。

### 10.2 提交当前轮

- 重新校验全部最大额度。
- 校验当前轮最少数量。
- 最少数量不满足时禁止提交。

### 10.3 订单结束

- 本期没有整单最少数量，因此不新增结束订单拦截。

错误必须指向具体周期和约束，例如：

- 整单菜品集额度已用尽。
- 每轮整桌兜底上限已达到。
- 五花肉例外上限已达到。
- 当前轮最少还需添加 2 份。
- 当前组合无可行下单解。

## 11. 服务员授权

支持：

- 本次操作。
- 当前轮。
- 当前订单。

规则：

- 授权只绕过命中的数量上限。
- 不绕过最低数量、售罄、停售、年龄、支付或数据异常。
- 授权后的超量数量继续进入统计桶。
- 授权记录保存规则版本、门店、订单、周期、对象、原上限和批准后的最终数量。
- 后续超过批准后的最终数量必须重新授权。
- 整单限制不提供“当前轮”授权。

## 12. 生效范围与发布确认

- 只有已经配置有效商品范围的门店可以勾选为生效门店。
- 取消勾选生效门店不删除其草稿商品和数量配置。
- 发布确认页按“整个订单 / 每轮 / 分轮次”折叠展示规则摘要。
- 摘要必须显示限购主体、对象、商品数量、计量方式、人数区间、轮次区间、主额度、整桌兜底、默认单品上限和例外商品。
- 保存草稿不影响门店；保存并发布后生成正式版本。

## 13. 数据模型

仓库 envelope 和自助餐独立存储键保持不变。使用本文能力的单条规则升级为新规则版本。

```ts
type LimitCell = {
  configured: boolean;
  value: number | null;
};

type BoundCell = {
  minConfigured: boolean;
  min: number | null;
  maxConfigured: boolean;
  max: number | null;
};

type PeriodKey = "order_lifetime" | "per_round" | "multi_round";
type MeasureUnit = "piece" | "kind";

type DishIdentity = {
  productLineId: string;
  dishId: string;
};

type CategoryIdentity = {
  productLineId: string;
  categoryId: string;
};

type ExceptionLimit = {
  dishes: DishIdentity[];
  limit: LimitCell;
};

type QuantityBlockPolicy = {
  totalEnabled: boolean;
  targetEnabled: boolean;
  sameDishEnabled: boolean;
};

type PeriodPolicy = {
  enabled: boolean;
  blocks: QuantityBlockPolicy;
};

type ScenarioValues = {
  totalBounds: Record<string, BoundCell>;
  tableTotalBounds: Record<string, BoundCell>;
  targetLimits: Record<string, LimitCell>;
  tableTargetCaps: Record<string, LimitCell>;
  defaultDishLimits: Record<string, LimitCell>;
  exceptionDishLimits: Record<string, ExceptionLimit[]>;
};

type StoreConfig = {
  productLines: string[];
  dishTargets: DishIdentity[];
  categoryTargets: CategoryIdentity[];
  dishSetMembers: DishSetMember[];
  periodValues: Record<PeriodKey, ScenarioValues>;
};

type BuffetRuleExtended = {
  schemaVersion: 4;
  subject: "order" | "party_size";
  targetType: "dish" | "category" | "dish_set";
  enabledPeriods: PeriodKey[];
  measureUnit: MeasureUnit;
  partyRanges: Range[];
  roundRanges: Range[];
  periodPolicies: Record<PeriodKey, PeriodPolicy>;
  storeConfigs: Record<string, StoreConfig>;
};
```

约束：

- 空值使用 `configured=false, value=null`。
- 禁止下单使用 `configured=true, value=0`。
- 正常额度使用 `configured=true, value>0`。
- 所有数量必须是 `0..999999` 的整数。
- 普通规则的 `enabledPeriods` 必须恰好包含一个值且不得重复。
- 受控组合模板的 `enabledPeriods` 仅允许 `order_lifetime + per_round` 或 `order_lifetime + multi_round`；顺序规范化为 `order_lifetime` 在前。
- `per_round` 与 `multi_round` 永远互斥；任何载荷同时包含二者时不得发布或启用。
- 历史多周期载荷继续按原快照运行；进入编辑时若属于上述两个合法组合，则映射到对应组合模板，否则进入“需修复”状态，只允许拆分或选定单周期后保存。
- `order` 规则不展示人数区间；`party_size` 规则的人数区间必须完整覆盖支持范围。
- 周期和三个数量区块的启用状态属于规则级配置，所有门店使用相同组合；数量值和商品范围保存在 `storeConfigs[storeId]` 中。
- 关闭区块时保留其草稿单元格，但发布载荷和运行时忽略该区块；重新开启时恢复草稿值。删除门店时删除该门店全部周期单元格。

矩阵键规范：

```text
ScenarioKey = partyRangeIndex|roundRangeIndex
TargetCellKey = partyRangeIndex|roundRangeIndex|productLineId|targetId
```

- 按桌/订单使用 `partyRangeIndex = 0`。
- 整个订单和每轮使用 `roundRangeIndex = 0`。
- 分轮次使用实际 `roundRangeIndex`。
- 菜品集共享额度、整桌兜底、总量和默认单品上限使用 `ScenarioKey`。
- 菜品、分类逐对象额度使用 `TargetCellKey`。
- `dishTargets`、`categoryTargets`、`dishSetMembers` 和例外商品均显式保存 `productLineId`；不得只用 `dishId` 或 `categoryId`，也不得把不同产线的相同 ID 静默合并。

示例：按人数、分轮次、纽约中城店，第 2 个人数区间、第 3 个轮次区间、Kiosk 产线菜品 A：

```text
storeConfigs["ny-midtown"].periodValues.multi_round
  .targetLimits["1|2|kiosk|dish-a"]
```

## 14. 兼容与升级

- 历史规则按原结构继续运行，仅查看不写回升级。
- 旧规则首次保存受控组合周期、按种、整桌兜底、默认单品上限或例外商品时升级为新版。
- 新版规则关闭新增能力后仍保持新版，禁止版本降级。
- 复制规则复制完整周期策略，但重新校验目标门店商品身份和冲突。
- 草稿、发布、启用、禁用和删除作用于完整业务规则，不允许单独发布周期区块。
- 现有合法 `order_lifetime + per_round` 多周期规则加载为“整单＋每轮保护”模板；合法 `order_lifetime + multi_round` 加载为“整单＋分轮次保护”模板。
- 现有 `per_round + multi_round` 或三周期并存规则保留只读运行快照，但作者态标记“周期组合不再支持”，不得直接再次发布；用户必须拆分规则或选择一个周期。

## 15. 验收标准

1. 普通规则只能选择一个周期，界面不提供自由周期多选。
2. “每轮”和“分轮次”不能同时选择或同时出现在任何可发布规则中。
3. 通过“整单＋每轮保护”模板可同时配置整单和每轮限制，两个周期分别展示与校验。
4. 通过“整单＋分轮次保护”模板可同时配置整单和分轮次限制，两个周期分别展示与校验。
5. 整单指定菜品、分类和菜品集最大额度正确累计全部轮次。
6. 每轮总量、指定对象和单品保护可以组合启用。
7. 按人数额度与整桌兜底上限取更严格结果。
8. 菜品集按份时跨产线合并统计份数。
9. 菜品集按种时统计不同菜单身份数量。
10. 默认单品上限被例外商品额度覆盖，同一菜品不能进入两条例外规则。
11. 分轮次额度随当前轮次区间切换。
12. 人数变化后，未提交当前轮和后续整单操作按最新有效人数重新校验，历史已提交数量不追溯撤销。
13. 菜品、分类、菜品集交叉命中时全部约束同时成立。
14. 批量加购原子校验，失败时不部分写入。
15. `0` 表示禁止，空值表示未配置。
16. 三种授权范围正确，授权超量继续累计。
17. 不完整或无解配置允许保存草稿但不能发布或启用。
18. 合法历史多周期规则映射到组合模板；非法历史组合不可再次发布且不会被静默改写。
19. 旧规则未编辑时运行结果不变。
20. 规则编辑器和发布确认页全屏，返回列表后自动退出全屏。

## 16. 可视化确认

用户已通过可视化伴侣确认：

- 六步编辑流程保持不变。
- 规则类型只保留主体和对象。
- 场景配置使用模板快捷填充；普通规则周期单选，跨周期仅通过受控组合模板展示和配置。
- 限购数量按整个订单、每轮、分轮次纵向分区。
- 按人数支持固定整桌兜底。
- 菜品集支持按份/按种、默认单品上限和例外商品。
- 发布确认按周期复核完整规则。
