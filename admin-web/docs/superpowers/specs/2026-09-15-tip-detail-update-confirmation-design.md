# 小费分配明细更新小费数据确认设计

## 背景

小费分配明细允许用户手工新增员工、录入手工工时、修改分配比例并形成临时调整结果。“更新小费数据”会重新获取当前有效规则并重新计算，如果直接执行，用户可能误以为手工调整仍会保留，实际却被新的计算结果覆盖。

## 目标

在执行更新前明确告知数据覆盖影响，并确保用户确认后以最新规则全量重算；取消或失败时不得改变当前数据。

## 交互设计

点击“更新小费数据”后，系统先打开确认弹窗，不立即读取规则或修改数据。

- 标题：`确认更新小费数据？`
- 正文：`更新后将重新获取当前有效的小费规则并重新计算。当前手工新增的员工、手工工时、分配比例及调整结果将被清除，新的计算结果会覆盖现有数据。如仍需手工调整，请在更新完成后重新录入。`
- 操作：`取消`、`确认更新`
- “确认更新”为警示型主操作；“取消”为默认安全操作。

## 状态与行为

| 条件 / 状态 | 用户操作 | 系统行为 | 用户反馈 |
| --- | --- | --- | --- |
| 可编辑、未发放 | 点击“更新小费数据” | 仅打开确认弹窗，不改变当前数据 | 展示覆盖范围与重新录入提醒 |
| 确认弹窗打开 | 点击“取消”或关闭弹窗 | 关闭弹窗，不读取新规则、不清除数据、不重新计算 | 页面保持原状 |
| 确认弹窗打开 | 点击“确认更新” | 获取当前门店和日期的最新有效规则及原始小费；在临时对象中清除手工数据并全量重算；通过提交前校验后原子替换当前计算结果 | `小费数据已更新，请重新检查并补充需要的手工调整。` |
| 更新过程中 | 重复点击、关闭弹窗或按 Escape | 禁用确认、取消、关闭及遮罩退出；同一更新不得并发执行 | 确认按钮显示处理中状态 |
| 更新过程中 | 离开页面或切换门店、日期 | 作废当前更新上下文；迟到回调不得写入数据或恢复旧页面状态 | 新页面按最新上下文正常加载 |
| 更新任一步骤失败 | 已点击“确认更新” | 不替换旧数据，不保留任何部分更新 | 提示更新失败，当前数据保持不变，可重试 |
| 已发放、结果已锁定 | 尝试更新 | 不打开可执行确认流程，不修改任何数据 | 保持只读锁定并提示已发放不可更新 |

“更新小费数据”仅在正常营业且发放状态为“待发放”的可编辑日期展示。未营业、已发放、异常只读或其他锁定状态均不展示可执行入口。打开弹窗和最终提交时都必须重新校验执行条件，不能只依赖页面首次渲染状态。

## 数据处理边界

确认更新后全量清除并重新生成以下未确认的页面数据：

- 手工新增的员工分配明细；
- 手工录入的工时；
- 人工修改的角色或员工分配比例；
- 基于上述输入产生的金额和临时计算结果。

更新使用当前门店、当前营业日、最新有效规则和最新原始小费作为唯一输入。新计算成功前保留旧数据；只有完整计算成功后才一次性覆盖当前结果。已确认发放的分配快照不属于可覆盖范围。

更新计算必须先在临时对象中完成。最终替换前，系统须在同一写入保护边界内再次确认该日期仍可写，并校验门店、日期、规则版本、原始小费版本或内容指纹、原始草稿或确认快照版本均未变化。若其他页面或标签页已确认发放、重新确认分配、更新原始小费或改变同日基线，系统丢弃本次计算结果、重新读取最新状态且不修改原数据；已发放状态优先，任何迟到回调都不得覆盖只读页面。

规则读取、原始小费读取、计算、提交前校验或最终替换任一步骤失败，均视为本次更新失败。失败前后员工、工时、比例、金额、分配状态、旧确认快照和审计记录必须保持原值。

## 与确认分配的关系

“更新小费数据”只刷新当前明细的计算依据和待确认结果，不等同于“确认分配”。更新完成后，用户必须重新检查结果，必要时重新补充手工调整，再点击“确认分配”或“重新确认分配”写入新的确认快照。

已分配、待发放日期更新成功后，旧确认快照保留用于回滚保护，但领域状态进入“存在未确认更新”。该状态与新草稿原子持久化，也可由“当前草稿版本/指纹与最新确认快照不一致”稳定推导，不能只保存在页面内存中；刷新页面后仍然成立，并通过共享状态通知同步到其他标签页。

“存在未确认更新”时，“确认已发放”按钮继续展示但固定为禁用态，旁边或悬浮提示“请先重新确认分配后再确认发放”。按钮状态必须读取共享领域状态；发放处理函数的领域守卫也必须直接拒绝该日期，即使绕过 UI 调用也不得发放旧快照。用户完成“重新确认分配”、新草稿成为最新确认快照后，系统原子清除该状态并恢复发放按钮。

## 验收要点

- 点击更新按钮必定先显示确认弹窗，确认前数据无变化。
- 弹窗完整列明会被清除的手工数据及更新后需要重新调整。
- 取消、关闭或更新失败时，员工、工时、比例和金额保持不变。
- 确认成功后按最新规则全量重算，原手工调整不残留。
- 更新成功不自动完成确认分配。
- 已分配日期更新成功后进入“存在未确认更新”，重新确认分配前不可确认发放。
- 更新后刷新页面仍保持“存在未确认更新”；其他已打开标签页同步禁用“确认已发放”。
- 绕过 UI 直接触发发放处理时，领域守卫拒绝存在未确认更新的日期；重新确认分配后状态清除且入口恢复。
- 更新期间不可重复提交。
- 已发放日期不可更新。
- 更新计算期间，另一标签页确认发放、重新确认分配或修改同日基线时，本次迟到结果不得覆盖最新状态。
- 更新计算期间原始小费版本或内容指纹发生变化时，本次结果不得提交，并提示重新更新。
- 规则读取、原始小费读取、计算、提交前校验和最终替换分别失败时，更新前后完整状态保持一致。
- 用户确认前不调用规则或原始小费读取逻辑；处理中不可关闭弹窗，离开页面后迟到回调不得写入。
