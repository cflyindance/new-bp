# 分配规则门店筛选区块位置调整设计

## 目标

在原生“小费管理 > 分配规则”页面中，将现有门店筛选区块移动到规则数量统计区块上方，使用户先确定门店范围，再查看对应规则统计与规则列表。

## 页面顺序

调整后的页面结构为：

1. 页面标题、返回入口与新建规则操作。
2. 门店筛选区块。
3. 规则数量统计区块。
4. 规则列表。

门店筛选区块与规则数量统计区块继续使用当前页面的卡片、宽度和纵向间距风格。

## 实现方案

直接在原生规则页模板中移动现有 `tipout-rules-toolbar` DOM 节点，使其位于 `tipout-metric-strip--three` 前方。

继续复用：

- `storeFilter` 元素 ID。
- `renderRulesTable()` 变更事件。
- 当前门店选项生成逻辑。
- 当前筛选后统计与规则列表联动逻辑。
- 当前桌面端与移动端样式。

不采用 CSS `order` 进行视觉重排，确保 DOM 阅读顺序、键盘导航顺序和视觉顺序一致。

## 业务边界

- 不新增或删除门店筛选条件。
- 不修改门店选项、默认值或选中状态。
- 不修改规则数量、小费池数量或加收服务费池数量的计算逻辑。
- 不修改规则列表过滤、编辑、新建或更多操作。
- 不修改旧 `TipOut` 项目，只修改原生规则页面。

## 验收标准

1. 页面标题区下方首先展示门店筛选区块。
2. 规则数量统计区块展示在门店筛选区块下方。
3. 规则列表继续展示在统计区块下方。
4. 切换门店后，统计数字与规则列表继续同步更新。
5. `storeFilter` 仍保持唯一，事件绑定没有重复或失效。
6. 扩展原生小费页面验证脚本，针对 `src/team/tips/templates/rules.html` 明确断言标题区、`tipout-rules-toolbar`、`tipout-metric-strip--three`、规则表格按目标顺序出现。
7. 验证脚本断言 `id="storeFilter"` 在原生规则模板中恰好出现一次，并继续保留 `data-native-onchange="renderRulesTable()"`。
8. 原生小费页面验证脚本通过，且不依赖或修改旧 `dist/TipOut` 页面来验证本次布局。
