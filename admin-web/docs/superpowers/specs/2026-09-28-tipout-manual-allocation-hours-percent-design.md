# TipOut 小费分配明细手动调整工时与比例设计

## 背景与目标

当前按工时分配规则中，打卡员工的“分配工时”为只读；详情页统一考勤刷新还会把未打卡员工的工时、比例和金额重置为零。用户需要在当天小费分配明细中，无论员工是否打卡，都能手动调整分配工时及员工分配比例，并通过确认或重新确认分配保存正确的金额快照。

## 已确认范围

- 适用于所有按工时分配规则的员工行，包含现有小费池汇总分配及计提小费占比／剩余小费分配两种明细模式。
- 非工时分配规则的字段、算法不变；不新增规则配置或修改 POS 考勤原始数据。
- 已发放日期继续完全只读，不允许手动调整或覆盖锁定快照。

## 默认值与人工覆盖

1. 初次计算仍以当前 POS 有效考勤工时为基础并应用规则每日最大工时。未打卡员工默认分配工时、比例及从池分得金额均为零，不阻碍其他员工分配。
2. 打卡／未打卡标签只依据实际考勤，不因人工输入工时或比例而改变。
3. 两类员工的分配工时与员工分配比例均可编辑。人工输入的工时作为本次分配的明确覆盖值；即使超过规则每日最大工时，也采用输入值，不反写规则或 POS 考勤。
4. 修改某员工的工时后，按同角色下各员工当前分配工时重新计算比例；全组工时为零时比例均为零。之后可再手动修改比例。再次修改工时会重新计算同角色比例。
5. 手动比例是实际分配百分比，而非归一化权重。每行须为有限的 `0–100`，同角色合计不得超过 `100%`；不足 `100%` 的金额保持未分配。超过 `100%`、负数或非法值时显示明确错误并阻止确认，不静默调整用户输入。
6. 金额按角色可分配金额乘最终员工比例计算到分；合计 `100%` 时，最后一名正比例员工承接舍入尾差，保证该角色金额守恒；不足 `100%` 时未用比例对应金额保留为未分配。两种明细模式使用同一员工行计算语义。

## 草稿、快照与下游

- 人工编辑只改变当前可写明细草稿并标记“存在未确认修改”；详情页考勤标签更新、输入事件、收集快照及重新确认分配不得悄悄回填覆盖人工工时或比例。
- 切换员工行选中的员工时，对新员工重新获取默认考勤工时与比例，不把前一员工的人工覆盖转给新员工。
- 点击“确认分配”或“重新确认分配”时校验比例和工时，并将最终采用的分配工时、比例、金额及人工工时来源写入该日规则/员工确认快照。原始打卡工时仍独立保存，不受调整影响。
- 员工分配汇总及员工每日小费的“分配工时”从已确认快照读取该规则实际采用值；人工调整来源显示为人工，未确认草稿不得污染已确认跨页汇总。旧快照没有人工来源标记时维持既有兼容读取。
- “更新小费数据”按既有确认提示重新计算并覆盖草稿，人工调整需重新录入；放弃未确认修改则恢复原确认快照；确认已发放后保留锁定快照。

## 验收

1. 同一按工时规则中，打卡与未打卡员工均可编辑工时、比例；未打卡员工默认零且标签不变，人工编辑后可获得金额。
2. 有最大工时为 5 小时的规则：默认按 5 小时，手动输入 8 小时后采用 8 小时；原始打卡工时不变。
3. 改工时重算同角色比例；再改比例按实际输入计算金额；比例不足 100% 留未分配，超过 100% 或输入非法时不保存。
4. 两种按工时分配明细模式的金额、确认快照和重新打开后的回显一致；非工时模式不变。
5. 保存前考勤刷新不清除人工值；确认后员工汇总/每日小费显示快照工时与人工来源；放弃草稿、更新小费数据及已发放锁定各维持对应边界。
