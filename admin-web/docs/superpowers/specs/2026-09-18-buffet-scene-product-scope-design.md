# 自助餐场景独立商品范围设计

## 目标和范围

在人数组合或轮次区间的配置额度弹窗中，支持添加商品、删除商品和批量删除；每家门店、每个周期、每个人数与轮次场景分别保存商品范围和数量。沿用已确认的本地原型布局，不增加新的规则类型或计量方式。

## 页面操作

- 人数区间、轮次区间及两者组合保留场景卡片入口。
- 配置额度弹窗“商品限购数量”标题右侧增加“添加商品”，筛选栏提供批量删除，每行提供删除。
- 商品选择限定当前门店商品来源，已添加商品禁止重复加入；新增商品数量为空。
- 删除提示仅影响当前场景及其商品额度；其他场景的商品与额度不变。
- 批量设置保留按适用数量列展示一个或多个输入的机制。
- 保存并返回与保存下一场景同时保存商品范围和额度；关闭或 Esc 丢弃当前未保存增删及数量，不撤销上一个已保存场景。

## 统计定义

当前场景只限制该场景选择的商品。未加入商品不受本场景商品或菜品集限制，不表示禁止下单。每轮菜品总数仍统计全部商品，不随场景商品范围缩小。

菜品集共享额度只统计当前场景商品；每种最多份数按当前场景商品独立校验。每个菜品集场景保存和发布时至少两个商品；普通菜品场景至少一个商品。按分类规则使用相同场景隔离原则，选择与删除分类，不允许编辑分类内部商品。

整单＋轮次组合的两个周期分别维护范围；未被本轮商品规则选中的菜品，仍可能受到整单周期或其他规则约束。

## 数据和兼容

在门店配置下增加 `scenarioTargets[period][scenarioKey]`，值包含对应对象类型的 `dishTargets`、`categoryTargets`、`dishSetMembers`。使用现有稳定 rangeId 构造场景键；无人数/轮次维度使用规范默认键。编辑、发布编译和计算必须使用一致键解析，并兼容已有索引键读取。

没有显式场景记录的现有数据沿用门店公共商品范围，不重置数量。首次编辑该场景时复制有效范围为独立记录。显式空记录不能回退公共范围，保存和发布应提示补选商品。

门店公共商品来源保留为候选来源和无场景规则配置。添加商品不能修改其他场景；删除只清除当前场景的对应 targetLimits、tableTargetCaps 或 exceptionDishLimits，不清除其他场景记录。集合共享额度保留，但必须重新校验可满足性。

区间拆分、删除及映射沿用稳定 ID 的数量迁移原则，商品范围和额度一起处理；无法明确映射的新场景沿用公共商品范围，数量为空，不自动复制相邻场景。跨门店复制只将源场景可匹配目标门店身份的商品范围与数量一起复制；缺失商品列入预览跳过项，不按名称匹配，复制后商品数不足应明确提示且不能发布。

发布快照、作者配置、运行规则编译必须保留场景商品记录；计算按当前命中的场景取得范围，不取全部场景商品并集。冲突和完整性检查枚举每个场景，不能用某一场景范围代表全部场景。

## 验收和验证

1. 两个人数场景分别选择肥牛＋鲜虾、肥牛＋羊肉，保存刷新后各自恢复，互不影响。
2. 两个轮次场景增删不同商品，第 1 轮和第 2 轮计算命中各自范围，整单累计仍按整单范围执行。
3. 人数＋轮次四个组合及两家门店分别隔离，批量设置只更新当前场景勾选商品。
4. 删除后取消全部恢复，保存后当前场景商品与关联额度消失，其他场景完整。
5. 菜品集共享种数和份数只统计当前商品，集合外菜仍计入全轮总量；商品不足不能保存发布。
6. 现有草稿无场景商品记录时行为与原规则一致；发布再编译再计算必须保持同一限制结果。
7. 覆盖区间增删、跨店复制、分类范围、冲突检查和无场景内联配置回归。

单元测试先暴露范围串扰与快照丢失，再实施数据解析、UI、发布和计算变更；必要浏览器验证覆盖添加、删除、取消、保存及刷新。只修改静态自助餐脚本，不涉及 eMenu vendor 源码；如后续触及构建边界再按项目规则构建。
