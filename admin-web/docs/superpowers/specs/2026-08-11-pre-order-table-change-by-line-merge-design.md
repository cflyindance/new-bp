# “开单前，换桌”按产线三态合并设计

> 日期：2026-08-11
>
> 模块：前厅管理中心 / 设置 / 选桌与开台流程
>
> 状态：用户已确认设计，待独立规格评审

## 1. 背景

“选桌与开台流程”目前使用两条独立设置表达开单前换桌规则：seq 643“开单前,换桌”和 seq 644“开单前,必换桌”。两条设置分别保存适用产线，用户需要在两个位置组合配置，且同一产线可能同时出现在两份配置中，语义容易冲突。

本次以 seq 643 为基础，将两条设置合并为唯一功能“开单前，换桌”，并让 POS、POS GO、PayPad、eMenu、SDI 分别选择“不启用”“可选换桌”或“必须换桌”。seq 644 不再作为独立设置展示，但保留兼容数据镜像，避免旧业务端读取失败。

## 2. 目标

1. 在“选桌与开台流程”中只展示一个“开单前，换桌”功能。
2. 五条目标产线可独立配置三种互斥状态：不启用、可选换桌、必须换桌。
3. 以 seq 643 作为合并功能及新配置的唯一目录身份。
4. 自动迁移 seq 643、seq 644 的历史配置；同一产线冲突时“必须换桌”优先。
5. 新配置变化时同步维护旧产线数组和旧总开关镜像，兼容尚未升级的读取方。
6. 场景视图、按产线视图、搜索、草稿保存与放弃修改保持一致。

## 3. 非目标

- 不增加 Kiosk、Online Order、CDS 或其他未指定产线。
- 不修改换桌、选桌或开单流程在业务端的实际执行算法。
- 不删除 seq 644 的历史 localStorage 数据键。
- 不迁移或重构“选桌与开台流程”中的其他设置。
- 不建设通用三态配置引擎；只提取本功能实施所必需的局部读写和渲染边界。

## 4. 方案选择

采用方案 1：按产线三态矩阵。

对比方案：

| 方案 | 说明 | 取舍 |
| --- | --- | --- |
| 三态矩阵（采用） | 每条产线直接选择“不启用 / 可选换桌 / 必须换桌” | 状态互斥、无非法组合，用户一次即可完成配置 |
| 双层多选 | 先选择启用产线，再选择其中哪些必须换桌 | 接近旧数据结构，但操作分散，存在上下层集合不一致风险 |
| 启用开关 + 模式下拉框 | 每行先启用，再选择可选或必须 | 信息完整，但控件更多，浏览和批量核对效率较低 |

三态矩阵能够直接表达业务状态，并从交互层消除“两项同时开启”的冲突。

## 5. 目录与命名

- 保留 seq 643，标题从“开单前,换桌”统一为“开单前，换桌”。
- seq 644“开单前,必换桌”从配置目录、设置页面、搜索结果和按产线功能列表中移除。
- seq 644 仅保留为历史兼容镜像身份，不作为可编辑目录项。
- “选桌与开台流程”由 8 项变为 7 项，组内顺序调整为：

```text
107、619、111、625、621、643、592
```

- seq 643 的说明更新为：可按产线设置开单前不启用换桌、可选换桌或必须换桌。

## 6. 产线范围与界面

五条产线按以下固定顺序展示：

1. POS
2. POS GO
3. PayPad
4. eMenu
5. SDI

### 6.1 场景视图

“开单前，换桌”标题下直接展示三态矩阵，不再展示独立的 seq 643 或 seq 644 总开关。

| 产线 | 不启用 | 可选换桌 | 必须换桌 |
| --- | --- | --- | --- |
| POS 等五条产线 | 单选 | 单选 | 单选 |

- 每行使用同一单选组，必须且只能选中一个状态。
- 修改一条产线不得联动或覆盖其他产线。
- 控件提供明确的行名和状态名，例如“POS 开单前换桌规则：必须换桌”。
- 鼠标与键盘均可完成选择，焦点样式沿用现有设置页规范。

### 6.2 按产线视图

- 只展示当前产线的一组三态选项，不重复展示其他四条产线。
- 非适用产线不展示 seq 643。
- 按产线视图与场景视图读写同一份主配置，切换视图后状态必须一致。

### 6.3 页面草稿

- 保存后主配置与兼容镜像同时落盘。
- 放弃修改时恢复进入编辑前的主配置，并由恢复后的主配置重新派生兼容镜像。
- 同一 seq 在多个可见投影中出现时，修改后同步刷新所有投影。

## 7. 数据设计

### 7.1 主配置

新增 seq 643 对象型字段：

```text
643-pre-order-change-table-mode-by-line
```

结构为：

```ts
type PreOrderTableChangeMode = "disabled" | "optional" | "required";

type PreOrderTableChangeModeByLine = Record<
  "pos" | "pos-go" | "paypad" | "emenu" | "sdi",
  PreOrderTableChangeMode
>;
```

该对象是合并功能的唯一业务权威来源。合法配置中的每条目标产线都必须具有一个合法状态；缺少单条产线时补为 `disabled`，不得据此改写其他产线。

### 7.2 兼容镜像

继续维护现有字段：

```text
643-pre-order-change-table-lines
644-pre-order-must-change-table-lines
```

派生规则：

- seq 643 产线数组 = 状态为 `optional` 或 `required` 的全部产线。
- seq 644 产线数组 = 状态为 `required` 的全部产线。
- 数组过滤未知 id、去重，并始终按第五节的目标产线顺序保存。
- 旧总开关 `bplant-module-setting-toggle:643` = seq 643 兼容数组是否非空。
- 旧总开关 `bplant-module-setting-toggle:644` = seq 644 兼容数组是否非空。

同步旧总开关是必要的：旧读取逻辑会在数组为空且旧总开关为开启时回填全部旧产线。用户把五条产线全部设为“不启用”后，两个旧总开关必须同步为关闭，避免旧逻辑重新启用配置。

兼容镜像不得反向覆盖已经存在且合法的主配置。任何场景视图、按产线、草稿保存或合法程序化写入都必须经过同一同步函数，由主配置原子派生两份数组和两个旧总开关。

### 7.3 历史配置迁移

仅当主配置字段缺失时执行一次历史迁移。迁移先通过现有兼容读取逻辑获得 seq 643 和 seq 644 的有效产线集合，包括旧总开关开启但产线数组缺失时的既有回填语义，然后逐产线计算：

```text
产线存在于 seq 644 集合 -> required
否则存在于 seq 643 集合 -> optional
否则 -> disabled
```

- 同时存在于两份旧配置时，`required` 优先。
- SDI 若不存在于旧配置则迁移为 `disabled`。
- 迁移结果写入主配置后，立即按第 7.2 节重建兼容镜像。
- 后续加载只读取合法主配置，不重复迁移。

### 7.4 缺失、显式全关闭与损坏状态

- 主配置缺失：执行第 7.3 节迁移。
- 旧配置也完全缺失：五条产线均为 `disabled`；迁移后形成合法主配置。
- 合法主配置全部为 `disabled`：这是有效用户配置，刷新后不得重新启用或再次迁移。
- 主配置 JSON、对象结构或状态值损坏：使用两份兼容镜像恢复内存中的三态结果，但加载阶段不覆盖损坏主配置；用户下一次主动编辑或保存时才写入规范化主配置并重建镜像。
- localStorage 不可用：内存中安全回退为五条产线全部 `disabled`，不抛出未捕获异常。

## 8. 生效语义

每条产线的业务含义固定如下：

| 状态 | 生效语义 |
| --- | --- |
| 不启用 | 开单前不展示或触发换桌步骤 |
| 可选换桌 | 开单前提供换桌选择，用户可跳过并继续开单 |
| 必须换桌 | 开单前必须完成换桌或选桌后才能继续开单 |

本次只配置并输出上述状态，不修改消费这些状态的订单业务算法。旧消费方继续通过 seq 643/644 兼容数组得到等价语义；升级后的消费方应以主配置为准。

- `src/config/module-settings-toggle-ui.ts`：seq 643 不再依赖通用总开关渲染；seq 644 不再作为可见开关项。

- `scripts/lib/foh-settings-line-scope.seed.json`、生成的 scope 与 storage registry：seq 643 登记五条目标产线；seq 644 不再进入可见按产线 scope，但兼容存储键仍可保留登记。
- 分组基线、目录文档和相关验证：同步 7 项结构、标题、产线范围和兼容约束。

生成型文件只能通过已有生成脚本更新。实施前保存目标生成文件差异基线；如生成结果包含目标范围外漂移，应停止并核对工作区现有修改，不得覆盖无关变更。

## 10. 错误与边界处理

- 未知、重复产线 id 在旧数组读取和镜像写入时忽略。
- 非法模式值按第 7.4 节处理，不允许渲染出无选中或多选状态。
- 单次写入只修改目标产线，保留其他四条产线的完整配置。
- 保存主配置或任一镜像失败时不得让页面抛出未捕获异常；内存 UI 仍维持用户本次选择，并在后续保存时重试完整同步。
- seq 644 的旧数据不得因目录移除而被清除。
- 搜索结果、场景视图和按产线视图均不得出现 seq 644 的独立入口。
- SDI 是新增可配产线，升级时默认不启用，不得继承其他产线状态。
