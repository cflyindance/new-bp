# 限购数量「产线优先、场景随后」导航顺序设计

## 背景

限购数量步骤同时依赖三个导航维度：门店、产线、人数/轮次场景。  
原先「分开选择」路径为：**人数/轮次 → 产线 → 矩阵**；而多轮默认的「组合平铺」已是：**产线 → 场景块矩阵**。两条路径顺序不一致，运营切换模式时要重新建立心智。

分析结论（已确认）：编辑对象本质是「某门店 · 某产线菜单行」在各场景上的上限；**应先锁定产线（菜单集合），再配置场景**。

## 目标

- 步骤 4 统一为：**门店 → 产线 →（多轮）场景展示模式 → 场景与数量**。
- 「分开选择」与「组合平铺」共用同一产线优先顺序。
- 不改变 `limits` 键、门店配置与发布模型。

## 已确认决策

| 决策 | 结论 |
|---|---|
| 导航顺序 | 门店 → 产线 →（多轮）展示模式 → 场景与数量 |
| 适用范围 | 多轮分开选择 + 非多轮人数场景；平铺为产线 → 展示模式 → 组合块 |
| 数据模型 | 不变：`partyIndex\|roundIndex\|lineId\|targetId` |
| 完成度 | 产线 Tab 仍按当前门店 × 该产线汇总（多轮跨全部人数×轮次） |
| 全量预览 | 「查看已配置规则」仍挂在产线配置标题旁 |

## 页面结构

### 共用骨架

1. 配置门店  
2. 产线配置区：标题、「查看已配置规则」、产线 Tab  
3. 若 `period === "multi_round"`：场景展示分段（组合平铺 | 分开选择）  
4. **场景与数量区**（随展示模式分支）

### 组合平铺

4a. 纵向人数×轮次组合块（标题 + 块完成度 + 块级批量 + 矩阵）  
不渲染人数/轮次 Tab。

### 分开选择 / 非多轮

人数（及多轮时的轮次）Tab 位于产线与展示模式之后、矩阵上方：

4b. 人数场景 Tab  
4c.（多轮）轮次场景 Tab  
4d. 批量工具条 + 数量矩阵（读写当前 `activePartyIndex` / `activeRoundIndex`）

非多轮：无场景展示分段、无轮次 Tab；人数 Tab 位于产线下方。

## 行为不变项

- 切换门店 / 产线 / 人数 / 轮次：清空批量勾选（平铺清空各块勾选）。  
- 平铺编辑不更新 `activePartyIndex` / `activeRoundIndex`；切回分开选择时恢复原 Tab 索引。  
- 离开步骤 4：展示模式重置为平铺。  
- 批量、单格输入、键结构与现网/平铺设计一致。

## 非目标

- 不改步骤 3 区间配置。  
- 不做「同一场景横比多产线」的宽表。  
- 不把展示模式或 Tab 顺序写入草稿。

## 验证

专项脚本至少断言：

1. `renderStepFour` 拼装中，产线 `lineTabs` 先于场景展示 `sceneToggle`，再先于人数/轮次 `sceneTabsHtml`。  
2. 多轮平铺路径：产线 → 场景展示控件 → `data-scene-block`。  
3. 非多轮仍有人数 Tab，且位于产线之后。  
4. 既有批量 / 平铺 / 已配置规则预览脚本继续通过。

浏览器：

- 分开选择：门店 → 产线 →（多轮）展示分段 → 人数/轮次 → 矩阵。  
- 平铺：门店 → 产线 → 展示分段 → 组合块。  
- 非多轮：门店 → 产线 → 人数 → 矩阵。
