# eMenu 本地配置：展示会员登录入口

日期：2026-08-19  
状态：已确认（2026-08-19）  
范围：eMenu 本地配置后台「全局设置 → 用户设置」，以及 eMenu 食客端两个登录入口的显隐

## 1. 背景与目标

食客端会员登录目前有两条入口：

1. **点单前**：首页点「开始点单」后弹出「会员登录/注册」页。由配置 `isCrmNeedAuthLogin`（id 40，「点单前关闭会员登录/注册页」）控制：开启后首页不再弹出，只能进菜单后再登录。
2. **菜单页**：未登录时，右上角头像、以及横幅「登录/注册会员，可享受会员积分…」。这两处目前没有配置，只要开通了会员且未登录就会显示。

目标：在本地后台用一个功能组 **「展示会员登录入口」** 独立控制这两条入口；开关极性统一为「开 = 展示」。

已确认（方案 A）：

- 分组卡片，**没有**总开关
- 菜单页头像（未登录）与横幅绑成一个子开关
- 已登录后的头像（会员中心 / 退出）始终保留
- 「点单前必须登录/注册会员」（id 34）仍为独立项，不并入本组

## 2. 不在本次范围

- 商家后台 catalog hub seq 623「点单前会员身份策略」（三选一）的对齐或迁移
- 把菜单页头像与横幅拆成两个开关
- 关闭已登录后的会员中心入口
- Kiosk / SDI / Online Order
- 关闭会员能力本身（CRM 未开通时入口本来就不显示）
- 因业务动作触发的登录弹窗（积分兑换、购物车权益等）——本组只管「主动展示的入口」

## 3. 后台信息架构

位置：eMenu 本地配置 → 全局设置 → 用户设置。

现有顺序中，id 34 与 id 40 相邻。本次把 **id 40 那一张独立卡片**换成分组卡片，id 34 仍在其上方：

```
… 登录/注册会员需要验证码
… 点单前必须登录/注册会员          ← 不变（id 34）
… 展示会员登录入口                 ← 替换原「点单前关闭会员登录/注册页」
    [开] 点单前弹出登录/注册页
    [开] 菜单页展示登录入口
… 儿童将不参与下单限制…
```

### 3.1 分组卡片（无总开关）

标题：**展示会员登录入口**  
副文案：控制食客可以在哪些位置打开会员登录/注册页。

卡片头部 **不放** 总开关（避免「总开关开着、两个子开关都关」语义重复）。子开关放在卡片内容区，视觉对齐现有「下单前需要服务员授权」的子项行（左右：文案 / Switch）。

| 子开关 | 默认 | 说明 |
|---|---|---|
| 点单前弹出登录/注册页 | 开 | 关闭后，首页点「开始点单」不再弹出登录页，直接进入菜单 |
| 菜单页展示登录入口 | 开 | 关闭后，菜单页不展示未登录头像，也不展示登录引导横幅 |

「菜单页展示登录入口」同时覆盖：

- 普通菜单顶栏未登录头像（`TopBar` → `CRMLogin` 默认 Person 图标）
- 登录引导横幅（`CRMLogin/Banner`）
- eMenu Pro 主题 `MemberLogin` 按钮的未登录态

### 3.2 与「必须登录」互斥

沿用现有互斥弹窗（`SystemSetting.switch_topic_*`）：

- 「点单前必须登录/注册会员」为开时，「点单前弹出登录/注册页」必须为开，且该项 Switch **置灰不可关**。
- 若在「必须登录」已开时去关「点单前弹出」：拦截。提示：「想要关闭点单前弹出登录/注册页，需要先关闭 **点单前必须登录/注册会员**」。
- 若在「点单前弹出」已关时去开「必须登录」：拦截。提示：「想要打开点单前必须登录/注册会员，需要先打开 **点单前弹出登录/注册页**」。
- 现网 `switch_topic_content` 只有「打开本项 → 先关闭另一项」一种句式，本次为上述两种方向各用一句完整中文，不要硬套旧模板。
- 「菜单页展示登录入口」与「必须登录」**不互斥**，可独立开关。

## 4. 食客端行为

前置条件：未开通会员（`crmStatus === false`）时，两条入口都不展示，本组配置不生效。

| 点单前弹出 | 菜单页入口 | 首页开始点单 | 菜单页未登录 | 菜单页已登录 |
|---|---|---|---|---|
| 开 | 开 | 弹出登录页 | 头像 + 横幅 | 头像（会员中心） |
| 关 | 开 | 不弹，进菜单 | 头像 + 横幅 | 头像（会员中心） |
| 开 | 关 | 弹出登录页 | 无头像、无横幅 | 头像（会员中心） |
| 关 | 关 | 不弹，进菜单 | 无头像、无横幅 | 头像（会员中心） |

第四种合法：门店开通了会员（例如 POS 在用），但不在 eMenu 上主动拉登录。

业务动作触发的登录弹窗（例如未登录时点积分兑换菜 `crm.loginFirst`）**不受本组关闭**。本组只隐藏主动入口，不禁止登录能力。

「稍后登录/注册」仍只出现在非强制登录时，逻辑不变。

## 5. 数据模型

eMenu `globalConfig` 仍按 id + key 存。不做总开关字段。

### 5.1 点单前弹出（沿用 id 40）

保留 `id: 40`、key `isCrmNeedAuthLogin`，**存储极性不改**，避免 POS / 云端仍按旧语义读写时把「展示」读成「关闭」。

- 落库：`value.open === true` 仍表示 **不展示** 点单前登录页（与现网一致）。
- 后台 UI：子开关「点单前弹出登录/注册页」勾选 = `!value.open`。店员只看到「开 = 展示」。
- 食客端读路径：抽一个小函数（例如 `isPreOrderMemberLoginShown`）：默认 `!id40.open`；若「必须登录」（id 34）为开，则**一律返回 true**（覆盖 id 40）。`SetupOrder` 只走该函数，不要只按 `!id40.open` 实现。

不做 `open` 字段翻转，也不加 polarity 标记。旧店无需迁移：以前开了「点单前关闭」的，UI 上「点单前弹出」为关。

### 5.2 菜单页入口（新配置）

新增一项，id 取当前 `systemConfig.js` 最大业务 id 之后（现网最大为 93，实施时用 **94**，若当时已被占用则顺延）：

```js
{
  id: 94,
  key: 'showMenuMemberLoginEntry',
  value: { open: true }
}
```

缺省 / 读不到 → `open: true`（与现网「菜单页总是有入口」一致）。

### 5.3 用户设置列表

`userSettingMap`：删除单独渲染的旧 id 40 卡片；插入分组卡片（内部读写 id 40 与 id 94）。id 94 **不**再单独占一张卡片。

`ALL_CONFIG_ITEM` 纳入 id 94，保证设备/全局配置会下发、会保存。

## 6. 食客端改动点

| 位置 | 现逻辑 | 新逻辑 |
|---|---|---|
| `SetupOrder/index.jsx` | `crmStatus && !isCrmNeedAuthLogin` 则弹登录 | 改为走 `isPreOrderMemberLoginShown`（含必须登录覆盖），不要只判断 `!id40.open` |
| `CRMLogin/Banner.jsx` | `isHideBar`（已登录或未开通 CRM）则隐藏 | 再加：菜单页入口关闭则隐藏 |
| `CRMLogin/index.jsx` 默认头像 | `crmStatus` 为真就显示图标 | 未登录且菜单页入口关闭 → `isShowIcon` 为 false（不渲染图标）；**组件仍挂载**，Dialog 留给业务触发 |
| Pro `MemberLoginButton` | 主题配置有则渲染 | 未登录且菜单页入口关闭 → `renderButton` 不画按钮，**禁止**对整个 `CRMLogin` `return null`。Pro 主题没有 TopBar/`CRMBanner`，页面上唯一的 `CRMLogin` 就在这里；卸掉后积分兑换等 `setOpen(true)` 没有 Dialog 可挂 |
| `useIsMemberLogin.js` 的 `isHideBar` | 只服务横幅占位高度 | 横幅隐藏条件与 Banner 一致（含菜单页入口关闭），避免顶栏留空 |

不改：积分兑换、购物车权益、会员中心内部等 `setOpen(true)` 的业务触发点。

## 8. 错误处理与边界

- CRM 未开通：入口全隐，后台仍可改开关，保存有效，开通会员后再生效。
- id 40 的 `value` 非对象：视为未关闭点单前登录页（与现网默认 `open: false` 一致）。
- id 94 尚未下发到某台设备：菜单页入口视为开。
- 必须登录 + 点单前弹出的互斥：不允许出现「必须登录开、且 id 40 open=true（不展示点单前页）」的已保存状态。读到该非法组合时，食客端以必须登录为准（仍弹出点单前登录）；后台打开用户设置时把「点单前弹出」纠正为开（即把 id 40 写成 `open: false`）。现网互斥弹窗已能拦住大多数写入，读路径纠正作为兜底。

## 9. 验证

1. 四组开关组合下，首页弹窗 / 菜单页未登录头像与横幅 / 已登录头像，符合第 4 节表。
2. 必须登录开启后，「点单前弹出」置灰；试图关闭被拦截。
3. 旧配置 `isCrmNeedAuthLogin.open === true` 的店，升级后「点单前弹出」为关，菜单页入口仍为开（对齐旧「点单前关闭」行为）；落库值不变。
4. 旧配置默认店（id 40 为 `open: false`），升级后两点都为开。
5. 菜单页入口关闭后，未登录点积分兑换菜仍能弹出登录（业务触发不受影响）。
6. eMenu Pro 主题：未登录时不画 MemberLogin 按钮，但 `CRMLogin` 仍挂载；点积分兑换菜仍能弹登录；已登录仍可进会员中心。
7. 未开通 CRM：食客端无入口，与现网一致。
