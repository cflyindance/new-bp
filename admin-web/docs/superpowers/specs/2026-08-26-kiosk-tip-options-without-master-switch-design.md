# Kiosk 小费支付选项取消总开关设计

## 目标

调整 Kiosk 本地配置后台「设置 → 小费设置 → 显示小费选项」：移除布尔总开关，始终展示「信用卡/借记卡」和「柜台支付」两个多选项。小费是否展示只由支付方式明细决定，不再受历史 `tipping-mode.value` 控制。

## 已确认决策

- 采用“彻底废弃总开关运行时语义”的方案。
- `tipping-mode.value` 仅作为旧接口兼容字段保留，不在界面展示，也不参与食客端小费判断。
- 历史配置即使 `value: false`，升级后也不再全局关闭小费。
- 两个支付选项都未勾选时，表示所有支付方式均不展示小费。

## 界面与交互

- 「显示小费选项」标题保留，右侧不再渲染开关。
- 标题下默认、常驻展示两个复选项：
  - `0`：「信用卡/借记卡」；
  - `1`：「柜台支付」。
- 复用现有国际化键 `credit_debit_card` 与 `cash`，确保各语言继续显示对应译文。
- 支付配置仍处于加载状态时，两项暂时禁用，不改写已有选择。
- 只有「支付设置 → 选择支付方式」已启用的对应方式才可勾选。
- 用户取消信用卡或柜台支付后，对应小费选项立即自动取消。
- 重新启用支付方式只恢复可选状态，不自动勾选；但旧数据首次迁移的默认规则除外。

## 数据与迁移

配置结构保持不变：

```js
{
  id: 5,
  key: 'tipping-mode',
  value: false,
  tipPaymentTypes: ['0', '1']
}
```

- `tipPaymentTypes` 是唯一的小费展示控制字段。
- `value` 保存时维持原布尔值，避免无意义的数据改写并兼容旧客户端；新版本忽略它。
- `tipPaymentTypes` 缺失、`null` 或类型非法，视为旧数据：默认解析为当前 `KIOSK_PAYMENT_TYPE` 中已启用的信用卡/柜台支付方式。
- `tipPaymentTypes` 是数组（包括空数组）时视为用户的显式选择；过滤重复值、未知值以及当前未启用的支付方式。
- 显式空数组必须保持为空，不能再次回填默认值。

## 运行时判断

食客端判断某支付方式是否进入小费流程时：

1. 规范化当前订单支付方式；
2. 确认该方式仍存在于运行时 `KIOSK_PAYMENT_TYPE`；
3. 确认该方式存在于解析后的 `tipPaymentTypes`；
4. 不读取、不判断 `tipping-mode.value`。

因此，历史 `value: false` 不会暗中关闭界面已勾选的小费选项，而已从支付设置取消的方式也不会因 Kiosk 残留数据继续展示小费。

## 兼容与边界

- 未加载支付配置时保存其他设置，保留原 `tipPaymentTypes`，避免加载竞态清空数据。
- 支付配置加载完成且为空时，两项均禁用，并将已选值清理为空数组。
- 新版保存的数据仍包含旧 `value` 字段，旧版本回滚后会继续按其旧语义运行；这是兼容保留的已知行为。
- 礼品卡不属于本次小费选项范围。

## 验收标准

1. 「显示小费选项」不再显示总开关。
2. 页面默认、常驻展示「信用卡/借记卡」和「柜台支付」。
3. 历史 `value: false` 且未配置 `tipPaymentTypes` 时，按当前已启用支付方式默认勾选。
4. 历史 `value: false` 且显式配置 `tipPaymentTypes: ['0']` 时，信用卡订单仍进入小费流程，柜台支付订单不进入。
5. 显式 `tipPaymentTypes: []` 时，所有支付方式均不进入小费流程。
6. 未在支付设置中启用的方式不可勾选，也不能被保存或在运行时生效。
7. 已勾选某方式后，在支付设置取消该方式，对应小费选项立即自动取消。
8. 重新启用该支付方式后只恢复可选，不自动勾选。
9. 支付配置加载中不清空原值；加载完成后再执行交集清理。
10. 既有小费金额、比例、No Tip、签名、礼品卡及支付设置保存流程保持不变。

## 验证策略

- 扩展小费支付方式工具测试，覆盖忽略 `value`、历史缺失字段默认迁移、显式空数组与支付方式交集。
- 验证设置组件不再渲染主开关，且两个选项始终可见。
- 运行 KioskLite 测试与构建。
- 重新发布 KioskLite 嵌入包并校验构建元数据及 `index.html` 哈希资源。
- 浏览器验证单支付、双支付、空选择及取消支付方式后的即时联动。

## 非目标

- 不删除后端或持久化数据中的 `value` 字段。
- 不新增配置 ID 或后端接口。
- 不增加礼品卡小费条件。
