# 自助餐菜品集“成员”文案统一为“商品”设计

## 背景与目标

自助餐规则当前使用“成员”描述菜品集中的具体菜品，例如“全部成员跨产线合并统计”“4 个成员”和“成员保护”。该表达偏技术化，与页面中持续使用的“商品”“添加商品”“商品限购数量”不一致。

本次将自助餐业务中所有描述菜品集具体商品的中文“成员”统一改为“商品”，让用户始终以商品为认知对象。

## 适用范围

以下用户或业务可读内容全部纳入：

- 自助餐规则编辑页、配置额度页及相关弹窗；
- 规则列表、摘要、帮助文字、校验提示和错误提示；
- 自动化测试中对上述文案的断言；
- 自助餐验证脚本中的提示、断言消息与业务注释；
- 自助餐权威文档、相关设计文档与实施计划中的业务描述。

代码范围为 `dist/Configuration center/assets/buffet-*.js`、`dist/Configuration center/assets/order-limit-flow.js` 及同目录自助餐页面引用的业务文案；测试范围为 `scripts/verify-buffet-*.mjs`；文档范围为 `docs/superpowers/specs/*buffet*.md` 和 `docs/superpowers/plans/*buffet*.md`。本次不修改真实 POS、Kiosk、eMenu 客户端运行界面或其独立仓库文案，也不修改非自助餐模块。

典型替换包括：

| 原文案 | 新文案 |
| --- | --- |
| 全部成员跨产线合并统计 | 全部商品跨产线合并统计 |
| 4 个成员，跨产线合并统计 | 4 个商品，跨产线合并统计 |
| 菜品集成员 | 菜品集商品 |
| 成员保护 | 商品保护 |
| 至少保留 2 个成员 | 至少保留 2 个商品 |
| 该成员禁止下单 | 该商品禁止下单 |

还需覆盖“成员表”“成员重叠”“菜品集额度与成员”“成员例外”“成员不足”等组合表达，分别改为“商品表”“商品重叠”“菜品集额度与商品”“商品例外”“商品不足”。

“成员”用于人员、组织或非商品语义时不做机械替换。

## 兼容边界

本次只修改中文业务文案，不修改内部数据契约和程序标识。以下内容继续保留：

- `dishSetMembers`、`memberDishId`、`effectiveMemberProtection` 等字段；
- 包含 `member` 的函数名、变量名和测试数据键；
- `DISH_SET_MEMBER_*` 等错误码；
- 已保存草稿、发布快照和运行时数据结构。

该边界避免引入数据迁移、兼容读取或接口联调风险。

## 权威文档规则

《自助餐规则场景配置融合设计》中的业务说明同步使用“商品”术语，包括菜品集商品、商品保护、商品例外和商品重叠等描述。代码标识表格在展示真实字段或错误码时可保留 `member`，但对应中文解释必须使用“商品”。

其他自助餐设计文档中的业务文案同步替换，确保检索到的中文“成员”不再指代菜品集商品。

## 验收标准

1. 配置额度页显示“全部商品跨产线合并统计，只需设置一次”。
2. 当前菜品集显示“N 个商品，跨产线合并统计”。
3. 页面、列表、提示和校验消息不再用“成员”指代商品。
4. 权威文档及相关自助餐设计文档中的业务描述统一为“商品”。
5. 内部字段、错误码和既有草稿结构保持兼容。
6. 相关文案断言、回归脚本和项目构建通过。
7. 兼容性分三层验证，不把派生字段误当成持久化字段：
   - 使用既有旧草稿及发布快照夹具加载、保存并再次加载，断言 `dishSetMembers` 等持久化 `member` 键及其值往返一致；
   - 在全部场景汇总模型测试中断言派生字段 `memberDishId`、`effectiveMemberProtection` 的名称和值保持不变，同时页面展示新文案；
   - 在冲突与运行时测试中显式断言 `DISH_SET_MEMBER_*` 错误码保持不变。
8. 执行以下验证：
   - `node --check "dist/Configuration center/assets/order-limit-flow.js"`
   - `node scripts/verify-buffet-scene-unified-picker.mjs`
   - `node scripts/verify-buffet-all-scene-summary-model.mjs`
   - `node scripts/verify-buffet-v4-runtime.mjs`
   - `node scripts/verify-buffet-v4-conflicts.mjs`
   - `npm.cmd run build`
9. 对上述代码、测试和文档范围执行中文“成员”扫描。允许项仅限：非商品含义，以及为解释兼容边界而引用的旧文案、真实字段名或错误码；其余商品语义命中均视为遗漏。
