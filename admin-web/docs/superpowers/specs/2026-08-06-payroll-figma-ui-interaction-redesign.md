> **模块**：团队管理 → 薪资管理（`/team/payroll-report`，TipOut `payroll.html`）

## 一、背景与目标

当前薪资管理由主后台通过 iframe 嵌入 `dist/TipOut/payroll.html`。页面已经具备薪资期、员工、考勤、薪资汇总、手工调整、TipOut 同步、Employees Detail 与 ADP 导出等完整能力，但信息层级和操作状态与目标设计稿不一致：

- 页面仍以“期列表 → 员工列表 → 工作区”与工作区左侧期数导航为主要结构；
- 关键操作分散，当前/批量 ADP 导出、员工明细、更新与保存的优先级不清晰；
- 员工身份、薪资期和薪资汇总缺少统一的视觉上下文；
- 切换筛选或员工时，对未保存数据的保护不够集中；
- 更新、导出、邮件和保存缺少一致的加载、成功、失败与禁用反馈。

本次目标：

1. 按 Figma 节点 `197:39453` 重构薪资工作区的视觉结构和信息层级；
2. 对齐筛选、员工切换、更新、导出、明细预览、邮件与保存的交互状态；
3. 保留现有薪资计算、保存、TipOut 同步、Employees Detail 和 ADP 数据口径；
4. 在 1440px 桌面端准确还原目标稿，并兼容较窄桌面视口；
5. 保持改动集中、可审查，不引入新的框架或后端契约。

### 1.1 非目标

- 不修改数据库结构或 `db/payroll-p0.schema.sql`；
- 不修改 Payroll API 契约与服务器路由；
- 不改变 Regular、OT、OT2、Paid Break、Tips、SVCW 等计算口径；
- 不改变 TipOut 导入/同步与 ADP 字段映射；
- 不重写主后台 iframe 接入方式；
- 不迁移前端框架或新增 UI 依赖；
- 不把本次改造扩展到团队管理的其他页面。

## 二、方案选择

采用方案 A：保留现有 DOM 标识、业务函数和事件入口，重组 `payroll.html` 的工作区层级，重写作用域内样式，并在 `payroll.js` 增加必要的界面状态适配。

| 方案 | 内容 | 结论 |
|------|------|------|
| **A（采用）** | 重组 HTML、调整 CSS、最小化适配 JS；保留计算与接口 | 还原度与回归风险最平衡 |
| B | 仅覆盖视觉样式，保留现有页面结构 | 与 Figma 的信息层级差异明显 |
| C | 重写薪资页面视图和状态管理 | 改动范围过大，增加计算、保存和导出回归风险 |

## 三、页面结构与信息层级

目标工作区按以下顺序纵向组织：

1. **页面标题与主操作**；
2. **门店、年度、期数上下文筛选**；
3. **员工身份与本期摘要**；
4. **考勤汇总与周明细**；
5. **Manage Payroll 分组录入**。

### 3.1 页面标题与主操作

- 标题使用 `Payroll Management`；中文模式按现有 i18n 显示对应中文；
- 右侧操作按优先级排列：
  1. `Export ADP Report` 下拉菜单；
  2. `Employees Detail`；
  3. `更新员工数据` 主按钮；
- ADP 下拉菜单包含：
  - 导出当前 ADP；
  - 批量导出 ADP；
- 当前/批量导出继续调用现有导出逻辑，不重新计算或复制映射。

### 3.2 上下文筛选

- 门店、年度、期数以紧凑筛选控件排列在标题下方；
- 筛选值共同决定当前薪资上下文；
- 缺少必要筛选时，不渲染错误的空白工作区，而是呈现可理解的空状态；
- 切换筛选前统一检查未保存修改。

### 3.3 员工身份与本期摘要

- 使用 Figma 的深色摘要区域集中显示：
  - 员工头像或姓名首字母；
  - 员工姓名、岗位/角色；
  - Employee ID、SSN、Hire Date；
  - Salary Range、Paycheck；
  - Total Salary、Total Hours；
- “切换员工”位于摘要区域右上方；
- 敏感字段继续沿用现有脱敏/权限行为，本次不扩大可见范围。

### 3.4 考勤汇总与周明细

- 首行展示三张摘要：
  - Work Hours Summary；
  - Hourly Wage Summary；
  - Salary Summary；
- 数字使用等宽数字或 `tabular-nums`，保持纵向对齐；
- 日明细按 Week 分组，周头展示日期范围与本周合计；
- 表格字段与现有数据保持一致，允许按现有能力显示 In/Out、Meal、Regular、Rate、OT/OT2 及对应倍率；
- 宽度不足时优先保持关键字段可读，必要时仅允许明细表局部横向滚动，不让整页横向滚动。

### 3.5 Manage Payroll 分组录入

- 保留当前分组卡片方案，不恢复 12 列单行宽表；
- 分组顺序与目标稿及现有字段语义保持一致：
  1. 小费与服务费：SVCW、Tips；
  2. 扣款与福利分摊：Child sup、Med Ded、Eee 40%、Eer 60%；
  3. 餐休合规：Breakfast、Lunch、Dinner；
  4. 额外收入：Incentive、Sick Hours；
  5. 计薪属性：Exempt；
- 保留全部 `adj-*` 输入 ID，避免破坏现有读写、保存与同步逻辑；
- 字段帮助入口继续存在，并按 Figma 的低干扰样式呈现。

## 四、关键交互与状态

### 4.1 门店、年度和期数切换

| 状态 | 行为 |
|------|------|
| 无未保存修改 | 直接加载新上下文，刷新员工摘要、考勤、汇总和录入项 |
| 有未保存修改 | 弹出切换提示；“继续切换”放弃当前未保存修改，“返回编辑”保持原上下文 |
| 加载中 | 筛选控件进入受控状态，内容区显示结构化加载反馈 |
| 加载失败 | 保留原上下文与原数据，显示原因和重试入口 |

所有上下文切换复用同一套脏数据守卫，禁止门店、年度、期数各自实现不同逻辑。

### 4.2 员工切换

- 点击“切换员工”打开员工选择弹层；
- 列表项显示姓名首字母头像、员工姓名与岗位/角色；
- 有未保存修改时复用 4.1 的切换提示；
- 取消后保持当前员工、输入值与滚动位置；
- 切换成功后刷新员工相关数据，并将工作区滚动到员工摘要顶部。

### 4.3 更新员工数据

- 按钮具备默认、悬停、按压、禁用、更新中状态；
- 更新中禁止再次点击，防止重复请求；
- 更新成功后刷新考勤明细与派生汇总，显示成功 toast；
- 更新失败时保留原数据，显示失败原因与重试能力；
- 更新行为不得静默清除 Manage Payroll 手工输入。

### 4.4 导出与 Employees Detail

- `Export ADP Report` 使用下拉菜单承载当前与批量导出；
- 未选择门店/薪资期、没有数据或权限不足时，对应菜单项禁用并说明原因；
- `Employees Detail` 先打开现有员工薪资详情预览；
- 预览内继续提供下载/导出能力，并按现有能力提供发送到邮箱；
- 邮件发送需具备发送中、成功和失败状态；成功后显示明确反馈，失败可重试。

### 4.5 确定并保存

- 输入变化后标记工作区为未保存状态；
- 点击保存先展示变更确认弹层，包含字段、修改前值和修改后值；
- 没有变更时不进入提交；
- 保存中禁用重复提交及可能破坏上下文的切换操作；
- 保存成功后：
  - 清除未保存状态；
  - 更新本地基线；
  - 显示成功 toast；
- 保存失败后：
  - 保留全部输入；
  - 在确认弹层中显示原因；
  - 允许重试或返回编辑。

### 4.6 通用可用性

- 所有按钮、菜单、输入与弹层具备可见焦点；
- `Esc` 关闭可取消弹层，`Enter` 只触发当前明确主操作；
- 图标按钮提供可访问名称；
- toast 不作为唯一错误载体：需要用户处理的失败同时在相关区域呈现；
- 动效使用 `opacity` 和 `transform`，并尊重 `prefers-reduced-motion`。

## 五、技术设计

### 5.1 架构边界

继续使用现有结构：

```text
主后台 /team/payroll-report
        │
        ▼
iframe → dist/TipOut/payroll.html
        ├── payroll.css             页面样式
        ├── payroll.js              视图、状态与业务编排
        ├── payroll-api-client.js   API 客户端
        ├── payroll-tipout-*.js     TipOut 同步
        ├── payroll-adp-mapping.js  ADP 映射
        └── payroll-detail-export.js Employees Detail 导出
```

本次不拆分或替换现有模块，只在现有边界内调整呈现与交互。

### 5.2 DOM 与事件兼容

- 优先保留现有 ID、`data-action` 和类名挂钩；
- 必须移动元素时，保持事件委托可达；
- 允许新增纯呈现容器和界面状态类；
- 不复制保存、导出、同步函数以适配新结构；
- CSS 继续以 `.payroll-page` 为主要作用域，避免污染 TipOut 其他页面。

### 5.3 界面状态

允许在现有 `state` 基础上补充界面状态，建议至少包含：

```text
dirty                 是否存在未保存修改
pendingContext        待切换的门店/年度/期数/员工
pendingAction         refresh | save | export | email | null
lastActionError       最近一次可恢复操作错误
employeePickerOpen    员工选择弹层状态
exportMenuOpen        ADP 导出菜单状态
```

这些状态只控制交互，不改变业务数据结构。

### 5.4 数据流

```text
门店 / 年度 / 期数
        │
        ▼
当前员工 ──► 考勤日明细 ──► 周汇总 / Pay Period 汇总
   │                                │
   └────────► Manage Payroll 调整项 ─┤
                                    ▼
                              保存确认与提交
                                    │
                 ┌──────────────────┼─────────────────┐
                 ▼                  ▼                 ▼
          Employees Detail      ADP 导出         TipOut 同步
```

- 数据单一事实来源保持不变；
- 视图重组不改变汇总函数调用顺序；
- Employees Detail、ADP 和 TipOut 继续读取现有保存数据与映射。

## 六、异常、空状态与加载状态

| 场景 | 处理 |
|------|------|
| 未选择门店 | 展示引导空状态，禁用依赖门店的导出和更新操作 |
| 薪资期无员工 | 展示空员工状态，保留筛选可用 |
| 员工无考勤 | 摘要显示 0，周明细显示说明性空状态，Manage Payroll 仍按现有规则可编辑 |
| 页面初次加载 | 使用与摘要卡、表格行相匹配的骨架结构，避免布局跳动 |
| 切换加载失败 | 保留原上下文与数据，允许重试 |
| 更新失败 | 保留旧考勤和手工输入，显示错误 |
| 导出失败 | 不生成空文件，菜单内或预览内显示原因 |
| 邮件失败 | 保留预览和收件信息，允许重试 |
| 保存失败 | 保留所有输入与差异预览，允许重试 |

## 七、响应式与视觉规则

- 目标基准：1440px 桌面端；
- 页面内容区使用受控最大宽度，避免超宽屏无边界拉伸；
- 较窄桌面端：
  - 顶部操作允许换行；
  - 三张摘要卡可改为两列或单列；
  - Manage Payroll 组内字段按两列到单列响应；
  - 仅考勤明细表允许局部横向滚动；
- 颜色以现有设计系统的冷灰与品牌蓝为基础；
- 员工摘要使用目标稿的深色高对比区域；
- 数字启用 `font-variant-numeric: tabular-nums`；
- 输入、按钮、菜单和卡片圆角遵循内小外大的层级关系；
- 不引入全局字体或与主后台冲突的全局变量。

## 十一、实施原则

1. 先保行为，再换结构；每次重组后立即验证关键事件；
2. 不复制业务计算、保存、同步或导出逻辑；
3. 优先复用现有变量、组件样式和 i18n；
4. 所有改动保持在薪资模块范围内；
5. 以指定 Figma 节点为视觉基准，以现有业务结果为数据基准。
