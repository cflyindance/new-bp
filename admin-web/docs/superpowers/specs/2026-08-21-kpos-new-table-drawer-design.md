# 商家后台 KPOS 新增桌子侧滑面板设计

## 目标与范围

在商家后台“前厅管理中心 → 餐位平面图”中重新设计“新增桌子”交互，同时保证 KPOS Admin → Table 的新增桌子字段语义、数据模型和保存结果一致。

本功能只覆盖新增桌子流程。区域 CRUD、营运态开台/并台/转台/点餐等不属于本次范围。新增采用区域草稿机制，用户点击“保存区域”后才同步真实 KPOS。

## 已确认决策

- 使用右侧侧滑面板，主画布保持可见。
- 新桌台直接在主画布实时预览，可在创建前拖动。
- KPOS 原生字段置于主表单；商家扩展默认折叠。
- 默认使用当前区域，但允许在面板内切换目标区域。
- 切换区域后在目标区域重新自动寻找空位。
- 点击“创建桌子”只加入区域草稿；点击“保存区域”才整体同步 KPOS。

## 字段模型

### KPOS 原生字段

| 商家后台字段 | KPOS 字段 | 规则 |
| --- | --- | --- |
| 目标区域 | `areaType.id` | 默认当前区域，可切换 |
| 名称 | `table.name` | 必填，目标区域内唯一 |
| 默认人数 | `defaultGuestCount` | 大于 0 的整数 |
| 宽 | `width` | 逻辑像素转 0–1 归一化值 |
| 高 | `height` | 逻辑像素转 0–1 归一化值 |
| 形状 | `shape` | `RECTANGLE`、`ROUND`、`HIBACHI` |
| X 坐标 | `x` | 由自动布局或预览拖动产生 |
| Y 坐标 | `y` | 由自动布局或预览拖动产生 |

新增桌台的 `id` 在草稿阶段使用临时 ID，写入 KPOS 时省略。`status` 和 `currentGuestCount` 是运行态字段，不允许用户编辑；新桌台按 `AVAILABLE`、0 人提交。

### 商家扩展字段

桌位分类、旋转角和按时计价规则默认收纳在“商家扩展（不写入 KPOS）”折叠区。它们以商户租户、KPOS 主机、门店、真实桌台 ID 为联合身份保存，不进入 `SaveSeatingAreaType` XML；同一商户下有权限的管理员可见，读写仍受门店权限校验。草稿阶段先关联临时 ID，服务器回读并认领真实 ID 后原子迁移。

## 组件与交互

点击“新增桌子”后打开右侧侧滑面板，桌面端建议宽度 380–420 px；窄屏占满可用宽度。面板包含：

1. 标题和关闭按钮。
2. KPOS 桌台信息：目标区域、名称、默认人数、形状、宽和高。
3. 默认折叠的商家扩展区。
4. “取消”和“创建桌子”操作。

打开面板时创建仅存在于编辑会话内的预览对象。预览桌台以虚线边框和“预览”标识出现在目标区域画布中。表单字段改变时立即更新；用户可拖动预览调整位置。点击取消、遮罩或关闭按钮时销毁预览，不产生区域草稿和变更记录。

点击“创建桌子”后，预览对象转为目标区域中的正式草稿桌台，面板关闭，页面切换并停留在目标区域，且选中新桌台。页面显示非阻塞提示“已加入草稿，保存区域后同步 KPOS”。

## 自动寻找空位

逻辑画布固定为 `1000 × 650`，现有响应式显示只影响视觉缩放。自动布局采用确定性网格扫描：

1. 从左上角内边距开始，按从左到右、从上到下顺序扫描。
2. 使用当前输入的宽高构造候选矩形，并与现有桌台的轴对齐包围盒比较。
3. 候选桌台与现有桌台之间保留统一安全间距。
4. 第一个不重叠且不越界的位置即为结果。
5. 若找不到完整空位，将预览放置到合法画布范围内，并显示“当前区域空间不足，桌台可能重叠”的警告。桌台仍重叠时首次点击“创建桌子”只打开明确的二次确认；用户确认后才允许创建。拖动到不重叠位置后无需确认。

旋转角属于商家扩展。自动布局和 KPOS 写入的碰撞模型以未旋转的 KPOS 宽高包围盒为准，避免商家视觉旋转改变真实 KPOS 坐标含义。

## 校验与可用状态

- 目标区域必须存在。
- 名称去除首尾空格后不能为空，并且在目标区域内不与现有桌台名称重复；比较使用大小写不敏感规则。
- 默认人数必须为大于 0 的整数。
- 宽、高必须为有限数值，并满足编辑器统一最小尺寸。
- `x/y/width/height` 必须完全位于逻辑画布内。
- 形状只能取三种 KPOS 枚举。
- 真实 KPOS 未连接或会话不可用时禁止把预览转为真实桌台草稿，并引导用户重新连接。

“创建桌子”仅在校验通过时可用。字段级错误显示在对应控件下方；空间不足属于可恢复警告，不与字段错误混用。

每个区域在首次产生草稿修改时固定保存一份服务器基线。再次打开侧滑面板、继续新增或在区域间切换不得覆盖该基线。该区域保存成功并完成回读后才用最新服务器快照替换基线；保存失败时保留原基线与草稿；放弃该区域全部修改时删除该基线。多区域部分成功时只更新已成功区域的基线。

## 草稿与 KPOS 数据流

1. 用户创建桌台后生成临时 ID，并加入目标区域本地草稿。
2. 页面保存状态明确区分“未同步 KPOS”和“已同步”。
3. 用户点击“保存区域”时，客户端重新调用 `ListAreasType` 和 `ListTablesType` 获取最新区域快照。
4. 将最新结构指纹与打开编辑时的基线比较；发生其他终端结构修改时中止保存并要求刷新。
5. 无冲突时把最新运行态合并到已有桌台，并通过一次 `SaveSeatingAreaType` 提交完整目标区域；新增桌台不携带临时 ID。
6. 保存成功后重新读取 KPOS。对每个临时桌台使用 `name/shape/x/y/width/height/defaultGuestCount` 的归一化唯一结构签名认领真实 ID。
7. 只有签名在回读区域中唯一匹配且不存在歧义时才迁移商家扩展字段，并用服务器区域快照替换本地草稿。
8. 完成后更新基线和“已同步”状态。

目标区域切换只影响本次新增桌台。由于 KPOS 按区域整体保存，若用户在多个区域分别创建了草稿，页面级保存应按区域逐个提交；任一区域失败时停止后续写入，已成功的区域通过回读更新基线，失败及未提交区域保留草稿，并明确展示部分成功结果。

## 错误与幂等保护

- 保存按钮进入忙碌状态后禁止重复点击和继续编辑正在提交的区域。
- 会话过期时停止写入并要求重新验证，不自动重放写请求。
- 请求超时或连接中断后先回读服务器：目标指纹匹配则视为成功；基线指纹匹配才允许用户明确重试；两者都不匹配则标记“结果不确定”，禁止自动或盲目重试。
- 含临时 ID 的目标不直接与服务器结构指纹比较。客户端先用每张临时桌台的唯一结构签名在回读区域中建立临时 ID → 真实 ID 映射，再用真实 ID 重建规范化目标快照；只有重建后的目标结构指纹与服务器一致，才判定 KPOS 写入成功。任一临时桌台为 0 匹配或多匹配时进入结果不确定状态，不允许重试。
- 新增桌台回读签名匹配为 0 或多于 1 时，不认领真实 ID、不迁移扩展字段，并要求刷新人工核对。
- KPOS 写入确认成功后，先持久化“服务器已成功”状态和临时 ID → 真实 ID 映射，再迁移商家扩展。若扩展迁移失败，只保留扩展迁移重试任务并提示“桌台已同步，扩展设置待修复”；不得再次调用 KPOS 保存接口。扩展重试必须幂等，并在迁移完成后删除临时扩展记录。
- 同名校验既在创建时执行，也在保存前基于最新服务器快照复检。
- 错误信息必须区分字段错误、并发冲突、认证失效、网络失败和结果不确定。

## 模块边界

- 新增侧滑面板组件：管理表单、字段错误、折叠区和焦点。
- 预览控制器：管理临时预览对象、区域切换、拖动和销毁。
- 自动布局纯函数：输入画布、桌台集合、尺寸和间距，输出候选位置及重叠警告。
- KPOS 映射层：负责字段枚举、坐标归一化和 XML 数据，不依赖 UI。
- 草稿保存协调器：负责基线检查、整区域写入、回读、ID 认领和部分成功状态。
- 商家扩展仓储：负责临时 ID 到真实 ID 的原子迁移。

## 验收与测试

### 纯逻辑测试

- 自动布局扫描顺序、边界、间距、无空位警告和确定性。
- 名称规范化与区域内重复校验。
- 三种形状双向映射。
- 逻辑像素与 KPOS 归一化坐标往返精度。
- 临时 ID 唯一签名认领、0 匹配和多匹配歧义。
- KPOS 已保存但扩展迁移失败时，只重试扩展迁移且不重复写入 KPOS。
- 多区域保存的成功、失败和部分成功状态。
- 区域首次变脏时固定基线、重复打开面板不覆盖基线、成功/失败/放弃时的基线生命周期。

### UI 测试

- 打开、取消、遮罩关闭和 Escape 关闭均正确清理预览。
- 表单变化、区域切换和拖动实时更新预览。
- 字段错误、警告和按钮可用状态。
- 创建后切换目标区域、选中新草稿并显示未同步提示。
- 商家扩展折叠、保存及真实 ID 迁移。
- 同一商户不同管理员的扩展字段可见性，以及无门店权限用户的拒绝访问。
- 空间不足时的重叠警告、二次确认和拖动消除重叠后的直接创建。
- 保存忙碌锁和重复点击保护。

### 集成验证

- 使用指定测试区域完成一次真实 KPOS 新增、整区域保存和回读。
- 核对真实 KPOS Admin → Table 中的名称、人数、形状、位置和尺寸。
- 验证并发修改、会话过期、超时回读和歧义保护。
- 若用户未指定可写测试区域，只进行只读接口验证和模拟写入测试，不修改真实营业数据。

## 非目标

- 不实现区域删除协议。
- 不实现营运态桌台操作。
- 不把商家扩展字段伪造写入 KPOS。
- 不在创建按钮上直接调用单桌写入接口；KPOS 的真实协议仍以整区域快照保存。
