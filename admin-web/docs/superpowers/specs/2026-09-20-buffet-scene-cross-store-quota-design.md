# 自助餐场景跨门店商品额度设计

## 背景

同一条自助餐规则可以选择多家参与门店。不同门店的商品目录和额度可以不同，但当前场景额度页只围绕单一活动门店展示，无法在一个场景中统一查看和维护所有参与门店已经加入的商品。

本次调整将当前场景的多门店商品汇总到同一张额度表格，同时保持门店数据、场景数据和同名商品之间严格隔离。

## 已确认口径

1. 商品范围仅限当前规则的参与门店，不展示品牌下未参与当前规则的门店。
2. 额度页只展示当前场景已经加入的商品，不自动铺开门店完整商品目录。
3. 新商品继续通过“添加商品”加入；添加器沿用参与门店选择及“产线 → 组 → 类 → 菜”的统一选择方式。
4. 多门店商品使用统一表格展示，新增“所属门店”列和门店筛选。
5. 同名商品在不同门店是两条独立记录，可以配置不同额度。
6. 添加、移除和额度修改只影响对应门店的当前场景。

## 页面结构

### 顶部上下文

配置额度弹层继续展示当前人数区间、轮次区间和场景序号，并补充参与门店及当前场景商品统计，例如：

> 场景：1 人及以上 · 第 1 轮｜参与门店 3 家｜当前场景商品 12 个

### 筛选区

商品限购数量卡片的筛选项依次为：

- 搜索商品或分类名称；
- 参与门店，默认“全部参与门店”；
- 产线；
- 分类；
- 配置状态；
- 重置筛选；
- 批量设置入口。

门店筛选只包含当前规则的参与门店。选择单一门店后，产线、分类和状态选项按该门店当前场景中的商品联动收窄；切回全部门店后恢复跨门店选项集合。筛选行为不得改变参与门店、商品范围或额度数据。

产线与分类筛选项的身份使用 `{storeId, filterType, localId}`，不得仅用名称或门店内局部 ID。全部门店模式下，同名产线或分类仍按门店显示为独立选项，标签补充门店名称；本期不提供按名称跨店合并筛选。

### 商品表格

表格至少包含：

| 列 | 说明 |
| --- | --- |
| 选择框 | 表头选择当前筛选与当前分页范围，行选择用于批量操作 |
| 商品 | 商品名称及必要的终端或来源标识 |
| 所属门店 | 明确该记录归属的门店 |
| 产线、分类、编码 | 展示门店目录中的定位信息 |
| 额度字段 | 按当前限购对象与计量方式展示一个或多个输入项 |
| 状态 | 已配置、未配置等 |
| 操作 | 移除当前门店、当前场景中的该商品 |

底部统计显示当前场景“限购对象 N 条、来自 M 家门店”，其中对象数按表格行数计算，不跨门店去重；门店数按当前场景至少存在一条记录的不同 `storeId` 计算。同时显示筛选后的结果数。分页作用于汇总后的跨门店记录，稳定排序依次为参与门店顺序、产线顺序、分类顺序、对象名称、对象身份。

表头全选只作用于当前筛选条件下的当前页可见记录。切换页码、页大小或任一筛选条件时清空选择，筛选变化同时将页码重置为第 1 页。表头复选框的全选、半选和未选状态仅按当前页计算；批量设置只提交当前 `selectedRowKeys`，其他分页和被筛选隐藏的记录不得变化。

## 交互规则

### 添加商品

“添加商品”打开统一商品选择器：

1. 参与门店为必选项，只能选择当前规则的参与门店；
2. 选择门店后，根据限购对象展示对应目录；
3. 当前门店、当前场景已加入的对象默认勾选；
4. 选择器维护 `draftSelectionsByStoreId`、`baselineSelectionsByStoreId` 与 `dirtyStoreIds`。首次进入门店时从该门店当前场景初始化；再次切换回该门店时恢复临时选择；未访问或未修改门店不得参与替换；
5. “确认并返回配置”先校验所有脏门店，再以一次前端草稿事务写回全部 `dirtyStoreIds`。任一门店校验失败时不修改任何门店，并定位到失败门店；
6. 新增对象额度保持“未配置”；保留对象沿用原额度；取消勾选删除该门店当前场景中的对象和额度；
7. “取消”或关闭弹层丢弃所有临时选择，不写入规则草稿；
8. 目录加载失败时保留该门店既有临时状态并允许重试。若门店在弹层打开期间不再属于参与门店，确认时阻止提交并提示重新选择。

### 不同限购对象

| 对象类型 | 选择器与保存对象 | 表格元数据 | 额度字段与批量行为 |
| --- | --- | --- | --- |
| 菜品 `dish` | 产线 → 组 → 类 → 菜；保存菜品目标本身，不展开为其他对象 | 门店、产线、分类、商品编码 | 展示当前周期适用的商品额度字段；批量设置仅应用共同适用字段 |
| 分类 `category` | 产线 → 组 → 类；保存分类目标本身，不保存商品快照 | 门店、产线、分类名称；编码无值时显示“—” | 展示分类目标适用额度；分类商品变化沿用运行时现有分类语义 |
| 菜品集 `dishSet` | 使用现有菜品集商品选择流程；保存菜品集及商品身份，不把商品提升为独立规则目标 | 门店、菜品集名称；无产线或分类时显示“—” | 展示共享额度及商品例外字段；移除菜品集同时清理当前场景商品例外 |

规则编辑时三种目标类型互斥，不提供跨类型混选。批量面板只展示当前规则目标类型和周期共同适用的字段；不存在“跳过部分行后继续提交”的隐式行为。

### 单项配置

每行根据 `storeId` 和场景键定位门店配置。修改某行额度时，只写回该门店、该场景、该商品对应的额度记录。

### 批量设置

批量设置支持同时勾选多家门店的商品。提交时逐行按所属 `storeId` 写回，允许把同一额度值应用到多家门店，但不建立跨门店共享额度。

批量值先对全部选中行执行适用性与格式校验，全部通过后才一次性修改前端规则草稿。任一行存在非整数、负数、超过既有上限、字段不适用或身份异常时，整次批量操作不修改任何行，并提示“门店 + 场景 + 对象类型 + 对象名称/编码 + 字段 + 原因”。空值沿用现有“未配置”语义，`0` 沿用现有“禁止下单”语义。

表头全选和“已选数量”基于当前筛选结果与现有分页规则计算，不得隐式选中被筛选掉的商品。

### 移除商品

移除操作只删除对应门店、当前人数与轮次场景中的商品范围、商品额度及相关场景例外记录。以下数据必须保留：

- 同一门店的其他人数或轮次场景；
- 其他门店的同名商品；
- 规则级参与门店；
- 其他商品及其额度。

## 数据模型与投影

继续以 `storeConfigs[storeId]` 作为门店配置边界，不新增跨门店公共商品额度。

页面渲染时遍历当前规则的参与门店，读取每家门店当前场景的商品范围，并投影为统一行模型：

```text
sceneKey = stableEncode({
  peopleRangeKey: peopleRangeKey | null,
  roundRangeKey: roundRangeKey | null
})

targetIdentity = {
  targetType: dish | category | dishSet,
  targetId
}

rowKey = stableEncode([
  storeId,
  sceneKey,
  targetIdentity.targetType,
  targetIdentity.targetId
])

row = {
  storeId,
  storeName,
  sceneKey,
  targetIdentity,
  targetMeta,
  quotaValues,
  status
}
```

`sceneKey` 优先使用持久化场景 ID；旧数据没有场景 ID 时，使用稳定的人数区间键和轮次区间键规范化生成，不能使用展示文案或数组下标。`rowKey` 必须使用无歧义的稳定编码并包含门店与对象类型，不能直接拼接字符串，也不能只使用商品 ID。名称、编码和数组下标均不得作为身份键；即使不同门店或不同对象类型复用相同局部 ID，也不得发生额度覆盖或选择状态串联。

旧记录缺少 `targetType` 时，仅在当前规则目标类型唯一且目标可在该门店目录中唯一匹配时推导；否则标记为“异常”并禁止修改或移除，等待用户修复来源数据。旧场景键按人数键、轮次键、组合键的既有字段顺序推导；无法唯一推导时同样进入异常状态。

所有写操作都从统一行模型回到所属 `storeConfigs[storeId]`。统一表格只是视图投影，不改变现有按门店存储与发布的结构。

## 校验与错误提示

1. 保存时继续按门店执行现有商品数量、菜品集商品数、待完善额度等校验；任一门店失败即阻止整条规则保存，不产生部分门店成功。
2. 校验失败提示必须包含门店名称、场景、对象类型、对象名称或编码、字段和失败原因。
3. 商品元数据缺失时保留原记录并标记“异常”，不得静默写入其他门店或自动删除。
4. 额度状态固定为：所有适用字段为空是“未配置”；至少一项有值但仍缺少必填项是“部分配置”；全部适用必填项合法是“已配置”；身份或元数据无法解析是“异常”。
5. 参与门店被规则移除后，额度页不再展示该门店；其草稿保留或清理由现有参与门店生命周期规则负责，本功能不新增隐式清理。
6. 旧单门店草稿直接投影为一组行，不迁移、不重置已有额度。

最终保存沿用现有整条规则的统一保存机制：所有门店先完成校验，再一次提交规则草稿。保存失败时保留完整未保存草稿供用户修正和重试，不标记任何门店为已保存。

## 旧数据兼容

| 旧数据形态 | 投影与回写规则 |
| --- | --- |
| 单门店且已有完整 `storeConfigs` | 直接投影为该门店行；只读打开不迁移 |
| 对象缺少 `targetType` | 仅在规则目标类型和目录匹配均唯一时推导，否则标记异常 |
| 仅人数、仅轮次或组合场景 | 按对应稳定区间键生成规范化 `sceneKey` |
| 元数据已失效 | 保留原记录与未知字段，显示异常，不自动删除 |
| 已退出参与门店仍有草稿 | 不进入额度汇总列表，不由本功能清理 |

用户编辑时只修改命中的门店、场景、对象和字段，未知字段原样保留。统一投影不得重排持久化记录，不得把数据复制到其他门店。必须使用旧草稿 fixture 覆盖“打开但不编辑”和“只编辑一条后保存、刷新”的回归验证。

## 验收标准

### 多门店展示与筛选

- 三家参与门店的当前场景商品出现在同一列表，商品数和门店数统计准确。
- 默认展示全部参与门店；选择单店后，只显示该门店记录。
- 门店、产线、分类、状态、搜索和分页可组合使用，重置后恢复默认状态。
- 全选只影响当前筛选下当前页；翻页、改变页大小或筛选条件后清空选择并正确重置页码。
- 全部门店模式下，同 ID 或同名的产线与分类不会跨门店误命中。

### 数据隔离

- 两家门店存在相同商品编码时，可以保存不同额度，刷新后互不覆盖。
- 移除某门店商品不影响其他门店同名商品。
- 当前场景增删商品不影响其他人数或轮次场景。

### 批量操作

- 可同时勾选不同门店商品并批量设置一个或多个适用额度字段。
- 仅勾选记录发生变化，未勾选和被筛选隐藏的记录保持不变。
- 各记录分别写回所属门店配置。
- 任一选中记录校验失败时，整次批量操作不修改任何记录，错误信息可定位门店、场景、对象和字段。

### 兼容与覆盖场景

- 旧单门店规则打开、编辑和保存结果不变。
- 浏览器验收覆盖仅人数、仅轮次、人数与轮次组合三类场景。
- 浏览器验收覆盖菜品、分类和菜品集三类限购对象。
- 覆盖添加、取消勾选、移除、单项编辑、跨门店批量设置和刷新回显。
- 添加器覆盖依次编辑门店 A、B、再返回 A 的临时状态保持，以及取消后完全不写入。
- 使用同局部 ID 的跨门店菜品、分类、菜品集 fixture 验证身份键隔离。
- 使用旧单门店 fixture 验证未编辑保存与只编辑一条记录均不改变其他场景及未知字段。

## 非目标

- 不展示或配置未参与当前规则的品牌门店。
- 不在额度页直接修改规则参与门店。
- 不把门店额度合并为共享额度。
- 不改变规则发布、生效范围和跨门店复制的既有定义。
