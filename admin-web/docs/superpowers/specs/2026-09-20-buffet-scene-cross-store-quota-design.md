# 自助餐场景跨门店商品额度设计

## 背景

同一条自助餐规则可以选择多家参与门店。不同门店的商品目录和额度可以不同，但当前场景额度页只围绕单一活动门店展示，无法在一个场景中统一查看和维护所有参与门店已经加入的商品。

本次调整将当前场景的多门店商品汇总到同一张额度表格，同时保持门店数据、场景数据和同名商品之间严格隔离。

## 已确认口径

1. 商品范围仅限当前规则的参与门店，不展示品牌下未参与当前规则的门店。
2. 额度页只展示当前场景已经加入的商品，不自动铺开门店完整商品目录。
3. 新商品继续通过“添加商品”加入；添加器沿用参与门店选择及“产线 → 组 → 类 → 菜”的统一选择方式。
4. 多门店商品使用统一表格展示，新增“所属门店”列和门店筛选。
5. 同名商品在不同门店是两条独立记录，可以配置不同额度。
6. 添加、移除和额度修改只影响对应门店的当前场景。

## 页面结构

### 顶部上下文

配置额度弹层继续展示当前人数区间、轮次区间和场景序号，并补充参与门店及当前场景商品统计，例如：

> 场景：1 人及以上 · 第 1 轮｜参与门店 3 家｜当前场景商品 12 个

### 筛选区

商品限购数量卡片的筛选项依次为：

- 搜索商品或分类名称；
- 参与门店，默认“全部参与门店”；
- 产线；
- 分类；
- 配置状态；
- 重置筛选；
- 批量设置入口。

门店筛选只包含当前规则的参与门店。选择单一门店后，产线、分类和状态选项按该门店当前场景中的商品联动收窄；切回全部门店后恢复跨门店选项集合。筛选行为不得改变参与门店、商品范围或额度数据。

### 商品表格

表格至少包含：

| 列 | 说明 |
| --- | --- |
| 选择框 | 表头选择当前筛选与当前分页范围，行选择用于批量操作 |
| 商品 | 商品名称及必要的终端或来源标识 |
| 所属门店 | 明确该记录归属的门店 |
| 产线、分类、编码 | 展示门店目录中的定位信息 |
| 额度字段 | 按当前限购对象与计量方式展示一个或多个输入项 |
| 状态 | 已配置、未配置等 |
| 操作 | 移除当前门店、当前场景中的该商品 |

底部统计显示当前场景总商品数及来源门店数。分页作用于汇总后的跨门店记录。

## 交互规则

### 添加商品

“添加商品”打开统一商品选择器：

1. 参与门店为必选项，只能选择当前规则的参与门店；
2. 选择门店后展示该门店的产线、组、类、菜目录；
3. 当前门店、当前场景已加入的对象默认勾选；
4. 确认后，用临时选择结果替换该门店的当前场景商品范围；
5. 新增商品额度保持“未配置”；保留商品沿用原额度；取消勾选删除该门店当前场景中的商品和额度；
6. 切换门店时不得覆盖尚未确认的其他门店选择结果。

### 单项配置

每行根据 `storeId` 和场景键定位门店配置。修改某行额度时，只写回该门店、该场景、该商品对应的额度记录。

### 批量设置

批量设置支持同时勾选多家门店的商品。提交时逐行按所属 `storeId` 写回，允许把同一额度值应用到多家门店，但不建立跨门店共享额度。

表头全选和“已选数量”基于当前筛选结果与现有分页规则计算，不得隐式选中被筛选掉的商品。

### 移除商品

移除操作只删除对应门店、当前人数与轮次场景中的商品范围、商品额度及相关场景例外记录。以下数据必须保留：

- 同一门店的其他人数或轮次场景；
- 其他门店的同名商品；
- 规则级参与门店；
- 其他商品及其额度。

## 数据模型与投影

继续以 `storeConfigs[storeId]` 作为门店配置边界，不新增跨门店公共商品额度。

页面渲染时遍历当前规则的参与门店，读取每家门店当前场景的商品范围，并投影为统一行模型：

```text
rowKey = storeId + sceneKey + targetIdentity
row = {
  storeId,
  storeName,
  sceneKey,
  targetIdentity,
  targetMeta,
  quotaValues,
  status
}
```

`rowKey` 必须包含门店标识，不能只使用商品 ID；即使不同门店复用相同商品编码，也不得发生额度覆盖或选择状态串联。

所有写操作都从统一行模型回到所属 `storeConfigs[storeId]`。统一表格只是视图投影，不改变现有按门店存储与发布的结构。

## 校验与错误提示

1. 保存时继续按门店执行现有商品数量、菜品集成员数、待完善额度等校验。
2. 校验失败提示必须包含门店名称；存在场景维度时同时包含人数或轮次说明。
3. 商品元数据缺失时保留原记录并标记异常，不得静默写入其他门店或自动删除。
4. 参与门店被规则移除后，额度页不再展示该门店；其草稿保留或清理由现有参与门店生命周期规则负责，本功能不新增隐式清理。
5. 旧单门店草稿直接投影为一组行，不迁移、不重置已有额度。

## 验收标准

### 多门店展示与筛选

- 三家参与门店的当前场景商品出现在同一列表，商品数和门店数统计准确。
- 默认展示全部参与门店；选择单店后，只显示该门店记录。
- 门店、产线、分类、状态、搜索和分页可组合使用，重置后恢复默认状态。

### 数据隔离

- 两家门店存在相同商品编码时，可以保存不同额度，刷新后互不覆盖。
- 移除某门店商品不影响其他门店同名商品。
- 当前场景增删商品不影响其他人数或轮次场景。

### 批量操作

- 可同时勾选不同门店商品并批量设置一个或多个适用额度字段。
- 仅勾选记录发生变化，未勾选和被筛选隐藏的记录保持不变。
- 各记录分别写回所属门店配置。

### 兼容与覆盖场景

- 旧单门店规则打开、编辑和保存结果不变。
- 浏览器验收覆盖仅人数、仅轮次、人数与轮次组合三类场景。
- 浏览器验收覆盖菜品、分类和菜品集三类限购对象。
- 覆盖添加、取消勾选、移除、单项编辑、跨门店批量设置和刷新回显。

## 非目标

- 不展示或配置未参与当前规则的品牌门店。
- 不在额度页直接修改规则参与门店。
- 不把门店额度合并为共享额度。
- 不改变规则发布、生效范围和跨门店复制的既有定义。
