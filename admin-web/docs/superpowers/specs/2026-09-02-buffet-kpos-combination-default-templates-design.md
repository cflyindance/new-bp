# 自助餐 KPOS 每轮组合默认模板设计

## 1. 背景与目标

《KPOS「每人每轮/每轮下单菜品数量限制」完整操作调研》已经确认：每个人数区间可以同时配置整桌每轮总量、指定菜品或菜品集额度，以及菜品集内部保护。以“3 人及以下、4 人及以上”两个区间展开后，共有 12 个完整场景。

当前自助餐规则默认目录使用原子规则表达能力：4 条整单规则和 8 条每轮规则。原子规则适合灵活组合，但缺少与旧 KPOS 操作认知一致的“按人数区间一次配置总量＋指定对象＋内部保护”入口，并且按桌每轮规则不能单独表达随人数区间变化的固定整桌额度。

本期目标：

1. 保留现有 4 条整单和 8 条每轮原子默认规则；
2. 新增 6 条“每轮常用组合模板”，每条模板内部支持多个连续人数区间；
3. 默认用两个区间覆盖 12 个旧 KPOS 完整组合场景；
4. 继续复用自助餐规则现有六步编辑、门店商品、授权、生效范围、发布、冲突和运行引擎；
5. 不影响菜单下单限制，也不改写历史自助餐规则、草稿或快照。

## 2. 默认目录

默认规则列表按以下顺序分组：

| 分组 | 数量 | 说明 |
| --- | ---: | --- |
| 整单限制 | 4 | 现有整单原子默认规则 |
| 每轮常用组合模板 | 6 | 新增 C01～C06 |
| 每轮原子规则 | 8 | 现有每轮原子默认规则 |

系统默认目录合计 18 条。所有系统默认规则均：

- 默认禁用；
- 初始业务配置为空；
- 支持完整六步编辑；
- 删除后再次进入列表会按稳定键恢复为空白禁用模板；
- 名称和描述可编辑，但稳定键不依赖名称。

## 3. 六条组合模板

| 编号 | 模板名称 | 总量区块 | 指定对象区块 | 内部保护 |
| --- | --- | --- | --- | --- |
| C01 | 每轮总量＋每轮指定菜品 | 整桌每轮 M～N | 指定菜品整桌每轮 X 份 | 无 |
| C02 | 每轮总量＋每轮菜品集按份 | 整桌每轮 M～N | 菜品集合计整桌每轮 X 份 | 相同菜品整桌每轮 P 份 |
| C03 | 每轮总量＋每轮菜品集按种 | 整桌每轮 M～N | 菜品集整桌每轮 X 种 | 每种菜品整桌每轮 P 份 |
| C04 | 每轮总量＋每人每轮指定菜品 | 整桌每轮 M～N | 指定菜品每人每轮 X 份 | 无 |
| C05 | 每轮总量＋每人每轮菜品集按份 | 整桌每轮 M～N | 菜品集每人每轮 X 份 | 相同菜品整桌每轮 P 份 |
| C06 | 每轮总量＋每人每轮菜品集按种 | 整桌每轮 M～N | 菜品集每人每轮 X 种 | 每种菜品整桌每轮 P 份 |

组合模板不新增限购主体、额度周期或限购对象枚举。它们只预置既有业务区块的组合、计量单位和额度倍率口径。

建议稳定键：

```text
combo|per_round|dish|table
combo|per_round|dish_set|piece|table
combo|per_round|dish_set|kind|table
combo|per_round|dish|party_size
combo|per_round|dish_set|piece|party_size
combo|per_round|dish_set|kind|party_size
```

组合模板使用独立 `defaultVariant` 标识目录身份；冲突和运行时不得读取 `defaultVariant`，仍从区块、对象、计量单位和倍率字段推导业务约束。

## 4. 人数区间

每条组合模板首次创建时默认包含：

1. 3 人及以下；
2. 4 人及以上。

人数区间必须连续、互斥并完整覆盖有效就餐人数。支持：

- 修改分界值；
- 增加中间区间；
- 删除中间区间；
- 自动计算相邻区间上下界。

例如在默认区间中新增“4～6 人”后，系统形成“3 人及以下、4～6 人、7 人及以上”。

区间身份不能只使用数组索引。每个区间应有稳定 `rangeId`；数量矩阵使用 `rangeId` 关联。修改分界但保留区间时沿用原 `rangeId`。删除区间时删除该区间的数量配置。新增区间生成新的 `rangeId`，数量默认为未配置。

当一次操作无法可靠判断原数量配置应迁移到哪个新区间时，不静默复制或合并，相关新区间保持“待重新配置”。

## 5. 数量数据与计算

每家参与门店、每个人数区间独立保存：

```ts
type ComboRangeValues = {
  totalBounds: {
    minConfigured: boolean;
    min: number | null;
    maxConfigured: boolean;
    max: number | null;
  };
  targetLimits: Record<TargetKey, {
    configured: boolean;
    value: number | null;
  }>;
  sameDishLimit?: {
    configured: boolean;
    value: number | null;
  };
};
```

数据继续保存在自助餐规则既有 `storeConfigs` 与周期数量结构中，不新增 repository key。实现时可以在现有 v4 结构内增加组合模板需要的区间键，但不得把目录元数据写入运行快照。

### 5.1 固定整桌额度

C01～C03：

```text
总量范围 = 当前人数区间配置的 M～N
指定对象额度 = 当前人数区间配置的 X
内部保护额度 = 当前人数区间配置的 P
```

M、N、X、P 都不乘人数。

### 5.2 人均指定对象额度

C04～C06：

```text
总量范围 = 当前人数区间配置的 M～N
指定对象最终额度 = X × 当前有效就餐人数
内部保护额度 = 当前人数区间配置的 P
```

只有 X 乘人数；M、N、P 始终是整桌当前轮固定额度。

### 5.3 空值、0 与正整数

- 空值：未配置；允许保存草稿，但阻止启用或发布；
- `0`：有效配置，表示对应维度禁止下单；
- 正整数：有效额度；
- M 与 N 同时配置时必须满足 `M ≤ N`；
- 总量下限在提交本轮时校验；所有上限在加购和提交时校验。

## 6. 六步编辑流程

### 6.1 规则类型

系统默认组合模板锁定 C01～C06 对应的核心组合口径。名称、描述可编辑。核心口径发生变化时沿用现有系统默认身份转换规则，不继续冒充原组合模板。

### 6.2 场景配置

展示人数区间列表及增加、删除、修改分界操作。页面明确说明区间连续、互斥且完整覆盖。组合模板不配置轮次区间，统计周期固定为每轮。

### 6.3 限购数量

按人数区间分区展示，每个区间内配置 M、N、X、P：

- C01/C04 不显示 P；
- C02/C05 显示“相同菜品每轮最多 P 份”；
- C03/C06 显示“每种菜品最多 P 份”；
- C04～C06 的 X 标注“每人每轮”；
- 其余额度标注“整桌每轮”。

商品范围和数量矩阵继续按门店独立保存。切换门店、人数区间或产线时保存当前编辑状态。

### 6.4 超限授权

继续支持本次操作、当前轮、当前订单三种授权范围。授权只绕过当前数量规则，不绕过售罄、停售、年龄或支付限制。

### 6.5 生效范围

继续配置有效日期、活动周期、营业时段、会员范围和实际生效门店。至少选择一家拥有完整商品及数量配置的门店后才允许启用或发布。

### 6.6 确认发布

发布摘要按门店和人数区间展示：

- 人数区间；
- M/N；
- 指定对象与 X；
- X 是否乘人数；
- P 及其固定整桌口径；
- 授权、生效时间、会员和门店。

## 7. 运行时

运行时按以下顺序执行：

1. 根据当前有效就餐人数命中唯一 `rangeId`；
2. 根据当前门店读取该区间的 M/N/X/P；
3. C04～C06 对 X 乘有效就餐人数；
4. 统计当前订单当前轮累计量，不只统计本次提交；
5. 同时计算总量、指定菜品、菜品集和内部保护；
6. 任一上限超限即拦截；提交本轮时再校验下限；
7. 新轮次使用新的每轮统计桶，整单规则使用独立统计桶。

菜品集成员跨产线进入同一个共享统计池。按份统计总份数；按种统计不同菜品标识数量。内部保护始终按单品统计。

## 8. 冲突规则

冲突维度：

```text
门店交集
＋人数区间交集
＋周期交集
＋商品范围交集
＋统计口径相同
```

规则：

- 草稿允许保存重叠配置，但必须显示冲突对象和原因；
- 启用或发布时阻断相同统计口径的重叠规则；
- 不同统计口径允许共同生效，例如总量与指定对象、菜品集按份与按种；
- 组合模板和原子规则一视同仁；
- 冲突不得读取系统默认身份或模板名称；
- 删除或禁用冲突规则后，其他规则可重新通过启用或发布校验。

## 9. 历史迁移与对账

- 现有 4 条整单规则原样保留；
- 现有 8 条每轮原子规则原样保留；
- 对账只补齐缺失的 6 条空白禁用组合模板；
- 相同稳定键只保留一条系统默认身份记录；
- 组合模板不存在历史语义拆分，不自动吸收、合并或改写普通规则；
- 已配置、启用、发布的历史规则以及草稿、当前和历史快照均保持不变；
- 重复进入列表、刷新、重新登录和并发对账必须幂等；
- 菜单下单限制不读取或写入组合模板元数据。

## 10. 错误与边界

- 有效人数未命中唯一人数区间：阻断并提示人数区间配置异常；
- 人数区间重叠、断裂或缺少首尾覆盖：草稿可保存，启用或发布阻断；
- 生效门店缺少商品范围或任一区间 M/N/X/P 必填额度：启用或发布阻断；
- M 大于 N：对应区间显示错误并阻断启用或发布；
- 删除人数区间必须二次确认，并明确该区间数量配置将被删除；
- 修改就餐人数后，下次校验按新的有效人数重新命中区间并重算 X；
- 已经下单的数量不因人数变化被改写，只改变后续校验所使用的区间和额度；若新额度低于已用量，下一次加购或提交立即超限；
- 未知组合稳定键不得静默当作系统默认规则。

## 11. 验收标准

### 11.1 默认目录

- 空数据进入列表生成且仅生成 18 条系统默认规则；
- 分组顺序和数量为 4、6、8；
- 6 条组合模板默认禁用、为空且具有唯一稳定键；
- 重复进入不重复生成。

### 11.2 十二场景

- 每条 C01～C06 默认具有“3 人及以下、4 人及以上”两个区间；
- 两个区间分别配置后，形成 12 个可独立校验的场景；
- 每个区间可配置不同 M、N、X、P；
- C01～C03 的 X 不乘人数；C04～C06 的 X 乘人数；P 始终不乘人数。

### 11.3 编辑与发布

- 人数区间增删改后保持连续、互斥和完整覆盖；
- 新区间数量为空并标记待配置；
- 空额度草稿可保存但不能启用或发布；
- 0、正整数及 M≤N 校验正确；
- 发布摘要按门店、人数区间完整展示计算口径；
- 6 条系统默认组合模板全部支持六步编辑。

### 11.4 冲突与运行

- 组合模板之间、组合模板与原子规则之间按业务口径判断冲突；
- 重叠草稿可保存并显示冲突，启用或发布阻断；
- 总量、指定对象和内部保护共同执行，任一上限超限即拦截；
- 下限只在提交本轮时校验；
- 当前轮累计、人数倍率、跨产线菜品集合并和新轮次重置正确；
- 人数变化后重新命中区间并对后续操作使用新额度。

### 11.5 迁移与回归

- 现有 12 条默认规则及全部普通规则、草稿、发布状态和快照业务数据深等值；
- 对账只补 6 条组合模板且二次执行幂等；
- 自助餐规则现有选品、批量数量、授权、生效范围、发布和列表操作不回归；
- 菜单下单限制路由、数据、默认规则和交互零变化；
- 全部自助餐专项脚本、隔离回归、生产构建和浏览器关键路径通过。

## 12. 不在本期范围

- 把 12 个区间场景拆成 12 条独立系统默认规则；
- 删除或隐藏现有 8 条每轮原子默认规则；
- 自动把历史原子规则合并为组合规则；
- 给整单限制增加人数区间；
- 新增整单全部菜品总量上下限；
- 修改服务员授权的三个范围；
- 复刻尚未通过真实下单验证的旧 KPOS 未确认行为。
