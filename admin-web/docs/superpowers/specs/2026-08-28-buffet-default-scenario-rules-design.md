# 自助餐规则默认场景规则设计

## 目标

自助餐规则列表应始终包含全部 8 个有效业务场景。系统在读取自助餐规则数据时，仅为缺失场景补充一条正式但禁用的默认规则，不覆盖用户已经创建的规则。

## 场景集合

按桌/订单限购只统计整单累计：

1. 按桌/订单 + 每单/整单累计 + 按分类限购
2. 按桌/订单 + 每单/整单累计 + 按菜品限购

按人数限购支持三种统计周期：

3. 按人数 + 每单 + 按分类限购
4. 按人数 + 每单 + 按菜品限购
5. 按人数 + 每轮 + 按分类限购
6. 按人数 + 每轮 + 按菜品限购
7. 按人数 + 分轮次 + 按分类限购
8. 按人数 + 分轮次 + 按菜品限购

## 初始化与补齐规则

- 使用“限购主体 + 统计周期 + 限购对象”作为场景标识。
- 每次加载自助餐规则仓库时检查上述 8 个场景。
- 已存在非草稿规则的场景视为已覆盖，无论其启用或禁用状态，不再补充。
- 草稿不视为正式场景规则；如果某场景只有草稿，仍补充一条正式禁用规则。
- 缺失场景生成一条默认规则，状态为禁用。
- 重复加载必须幂等，不得重复生成同一场景的默认规则。
- 只修改自助餐规则独立数据空间，不读取或写入菜单下单限制数据。

## 默认规则内容

- 规则名称使用场景名称，例如“按人数·每轮·按分类限购”。
- 商品或分类范围为空。
- 数量矩阵保持未配置。
- 生效门店为空。
- 规则状态为禁用，因此不会直接参与运行时限购。
- 默认规则可以通过现有编辑、复制、删除、启用流程继续维护。

## 数据与兼容性

补齐逻辑放在自助餐规则仓库层，由仓库统一生成缺失记录并保存修订版本。列表页面和共享流程引擎仍只消费仓库返回的规则集合，不增加页面专用数据分支。

如果仓库处于损坏只读状态或持锁失败，不写入默认规则，沿用现有错误处理，避免借初始化掩盖数据异常。

## 验证

- 空仓库首次加载生成 8 条禁用规则。
- 部分场景已有正式规则时只补齐缺失场景。
- 同一仓库重复加载不会增加规则数量。
- 只有草稿的场景仍生成正式禁用规则，且草稿保留。
- 用户已有规则的名称、状态和配置不被修改。
- 菜单下单限制仓库不受影响。
- 浏览器列表可见全部 8 个场景，刷新后数量保持不变。
