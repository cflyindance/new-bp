# 自助餐规则默认场景规则设计

## 目标

自助餐规则作者态列表应始终包含全部 8 个有效业务场景。仅列表入口显式调用 `loadForAuthoringList → ensureDefaultScenarios`，为缺失场景补充一条正式但禁用的默认规则，不覆盖用户已经创建的规则。编辑器、只读详情和运行时快照读取保持纯读取，不触发补齐。

## 场景集合

按桌/订单限购只统计整单累计：

1. 按桌/订单 + 每单/整单累计 + 按分类限购
2. 按桌/订单 + 每单/整单累计 + 按菜品限购

按人数限购支持三种统计周期：

3. 按人数 + 每单 + 按分类限购
4. 按人数 + 每单 + 按菜品限购
5. 按人数 + 每轮 + 按分类限购
6. 按人数 + 每轮 + 按菜品限购
7. 按人数 + 分轮次 + 按分类限购
8. 按人数 + 分轮次 + 按菜品限购

## 初始化与补齐规则

- 使用“限购主体 + 统计周期 + 限购对象”作为规范场景键，例如 `order|order_lifetime|category`。
- 仅进入可编辑的自助餐规则列表时检查上述 8 个场景；只读查看、编辑器加载和运行时 `currentSnapshotId` 读取不检查、不写入。
- 已存在结构合法、状态为 `active` 或 `disabled` 且属于 8 个有效场景之一的正式规则视为覆盖。名称不参与覆盖判定，同场景已有多条正式规则时全部保留且不补充。
- 草稿不视为正式场景规则；如果某场景只有草稿，仍补充一条正式禁用规则。
- 未知状态、非法枚举或缺少场景字段的异常规则保留并继续按现有异常逻辑显示，但不阻止补齐对应合法场景。
- 缺失场景生成一条默认规则，状态为禁用。
- 重复加载必须幂等，不得重复生成同一场景的默认规则。
- 只修改自助餐规则独立数据空间，不读取或写入菜单下单限制数据。
- 删除某场景最后一条正式规则，或把最后一条正式规则改为其他场景后，下次返回/刷新作者态列表会重新生成该场景的默认规则。删除默认规则不是永久移除场景。

## 默认规则内容

- 规则名称使用场景名称，例如“按人数·每轮·按分类限购”。
- 记录包含 `origin: system_default` 与不可变的初始 `defaultScenarioKey`，用于诊断来源；场景覆盖仍以规则当前合法的 `subject + period + targetType` 判定。
- ID 使用仓库当前最大数字 ID 加一并在同一锁内连续分配，避免与用户规则、草稿碰撞。
- 正式记录状态为 `disabled`，`publishedSnapshotVersion` 为 `null`，并包含现有正式规则所需的创建/更新时间字段。
- `authoringConfig` 由共享流程的既有默认草稿工厂生成，再写入场景的 `subject`、`period`、`targetType`、名称和描述；授权、条件及兼容字段全部沿用该工厂，避免另建一套默认值。
- 默认按人数规则的 `partyRanges` 初始为 `[{min: 1, max: null}]`，用户可在场景配置中新增人数区间；分轮次场景的 `roundRanges` 初始为 `[{min: 1, max: null}]`，用户可新增轮次区间。按桌/订单规则的人数区间继续固定为底层占位。
- 商品或分类范围为空。
- 数量矩阵保持未配置。
- `storeConfigs` 为空，`participatingStoreIds`、`deployStoreIds` 与 `deployExcludedStoreIds` 均为空。
- 规则状态为禁用，因此不会直接参与运行时限购。
- 默认规则可以通过现有编辑、复制、删除流程维护。未配置商品、数量或生效门店时，直接启用必须由现有完整性校验阻止并引导用户进入编辑。

## 数据与兼容性

补齐逻辑放在自助餐规则仓库层。列表调用作者态加载接口；该接口先纯读取，场景完整时原样返回且不写 storage。存在缺失时，沿用仓库 writer 协议：获取模块锁后重新读取最新 envelope、重新计算缺失集合、保留现有全部字段、在同一临界区生成碰撞安全 ID，并以 `revision + 1` 单次写回。锁失败、revision 冲突或写入失败时不做部分写入。

补齐只更新 `rules` 和 repository `revision`；不得创建、删除或切换发布快照，不修改 `snapshots`、`currentSnapshotId` 及任何已有 active 规则版本。空仓库补齐后 `currentSnapshotId` 仍为 `null`。运行时读取永远不调用作者态补齐接口。

如果仓库处于损坏只读状态或持锁失败，不写入默认规则，沿用现有错误处理，避免借初始化掩盖数据异常。

## 验证

- 空仓库首次加载生成 8 条禁用规则。
- 部分场景已有正式规则时只补齐缺失场景。
- 场景完整时不写 storage，revision 和序列化内容保持不变；重复加载不会增加规则数量。
- 只有草稿的场景仍生成正式禁用规则，且草稿保留。
- 用户已有规则、全部草稿、`snapshots` 和 `currentSnapshotId` 深等值不变；已有多条同场景规则全部保留。
- 两个列表并发补齐，以及补齐与草稿保存、发布竞争后，每个缺失场景最多生成一条且不丢失其他变更。
- 非法规则、损坏 envelope、锁失败与写入失败时不发生部分更新。
- 删除最后一条正式规则或修改其场景后，再次打开列表会补齐原场景。
- 菜单下单限制的全部真实 storage 键和值在补齐前后不变。
- 浏览器列表可见全部 8 个场景，刷新后数量保持不变。
