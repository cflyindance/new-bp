# TipOut 汇总页“新建/查看规则”入口设计

## 背景

小费分配汇总页目前只能通过左侧导航进入“分配规则”。本次在汇总页主操作区补充规则入口，让用户在执行小费分配前能够快速新建或查看规则。

## 目标

- 在“小费分配汇总”标题操作区新增“新建/查看规则”按钮。
- 按钮位于“导出结果”左侧。
- 根据当前规则数据是否为空，直接进入新增页或规则列表页。
- 保持现有规则存储、创建、编辑、删除、复制和小费分配业务逻辑不变。

## 交互设计

### 按钮呈现

- 文案固定为“新建/查看规则”。
- 使用与“导出结果”一致的次级大按钮样式。
- 桌面端操作顺序为：“新建/查看规则” → “导出结果” → “分配小费”。
- 移动端沿用现有标题操作区的自适应换行，不新增固定定位或遮挡处理。

### 点击路由

点击时实时读取 `ruleData.getRules()`：

- 返回空数组或规则数量为 0：在当前窗口跳转到 `rule-add.html?poolKind=tip`，直接全页展示“小费池”新增规则页，跳过规则类型选择弹窗。
- 存在至少一条规则：在当前窗口跳转到 `rules.html`，全页展示规则列表页。

“是否有规则”按当前 `tipout_rules` 的全量规则判断，不按汇总页门店筛选范围判断。

## 实现边界

- 在 `dist/TipOut/index.html` 的标题操作区增加按钮和单一点击处理函数。
- 复用已经加载的 `ruleData.js` 与公开方法 `ruleData.getRules()`。
- 不修改 `ruleData.js`、`rules.html`、`rule-add.html` 的业务行为。
- 不增加新页面、新弹窗、新存储键或规则类型选择逻辑。
- 若 `ruleData` 不可用或读取异常，按无规则处理，进入默认小费池新增页，避免按钮无响应。

## 可访问性

- 使用原生 `button` 元素。
- 支持键盘 Enter 和 Space 的原生激活行为。
- 文案直接表达入口会根据数据状态执行“新建”或“查看”。

## 验收标准

1. “新建/查看规则”显示在“导出结果”左侧，视觉层级与其一致。
2. 无规则时点击后，当前窗口地址变为 `rule-add.html?poolKind=tip`，且不出现池类型选择弹窗。
3. 有至少一条规则时点击后，当前窗口地址变为 `rules.html`。
4. 现有“导出结果”和“分配小费”按钮功能不受影响。
5. 桌面端和移动端按钮均可见、可点击且不遮挡其他操作。
6. 现有 TipOut 自动化回归通过，浏览器控制台无新增错误。
