# 自助餐全部场景商品限购汇总设计

## 1. 背景

自助餐规则支持人数区间、轮次区间、整单与轮次组合、多门店及不同限购对象。当前配置额度页以“进入某个场景后配置”为主，适合编辑单一场景，但无法一次核对同一规则下所有场景、门店和商品的最终限购结果。

本设计在不改变现有场景编辑模型的前提下，增加只读汇总入口。汇总结果直接投影现有场景配置，不保存第二份业务数据。

## 2. 目标与非目标

### 2.1 目标

1. 一次查看当前规则下所有场景的全部商品限购结果。
2. 支持跨门店、周期、人数区间、轮次区间筛选。
3. 让同一商品在不同场景下的额度差异可被发现。
4. 从任一汇总行准确返回对应场景继续编辑。
5. 保持商品、产线、分类、门店字段独立展示。

### 2.2 非目标

1. 不在汇总页直接编辑或批量修改额度。
2. 不新增一份汇总配置数据。
3. 不改变现有场景卡片、添加商品及删除商品的业务作用域。
4. 本期不提供导出、跨规则比较和历史版本比较。

## 3. 入口与页面承载

汇总提供内外两处入口，二者必须复用同一个数据投影、筛选状态模型和汇总弹窗：

1. 最外层“设置限购数量”页面：在“门店与商品数量”区块标题右侧增加两个并列操作。
2. 单场景“配置额度”页面：在“商品限购数量”区块标题右侧增加两个并列操作。

两处操作均为：

- `查看全部配置`：次级按钮；打开只读汇总。
- `+ 添加商品`：主按钮；继续只影响当前场景。

最外层入口代表当前规则的全部参与门店与全部有效场景，不受当前门店下拉框或当前场景卡片影响。单场景入口同样查看全部结果，而不是只查看已打开场景；这样用户从任一层级进入都获得完全一致的认知和数据结果。

当前规则尚未添加任何商品时，两个入口仍保持可见且可点击。汇总弹窗显示空状态“暂无商品配置，请先添加商品”，避免按钮随数据状态跳动。仅在通过关闭、取消或 Escape 解散弹窗时，焦点返回触发本次打开操作的具体入口；从最外层打开时返回最外层，从配置额度页打开时返回配置额度页。通过“进入配置”导航时按第 7 节移动焦点。

汇总使用大尺寸弹窗，建议占可视区域约 90% 宽高。它替换当前配置内容的视觉焦点，不在已有弹窗上叠加需要再次确认的编辑弹窗。

弹窗标题为“全部场景商品配置”，副标题展示：规则名称、规则涉及的场景数、商品数及门店数。

## 4. 表格信息结构

采用“限购对象 × 场景逐行平铺”。一行代表一条可定位的最终配置结果；同一对象在不同门店或场景中可以出现多行。不同对象类型的行模型固定如下：

| 限购对象 | 行粒度 | 商品列展示 | 额度解释 |
| --- | --- | --- | --- |
| 菜品 | 每个已选菜品一行 | 菜品名称 | 本菜品独立额度 |
| 分类 | 每个已选分类一行，不展开成员菜品 | 分类名称 + `分类共享` 标识 | 分类内菜品共享额度 |
| 菜品集按份 | 每个成员菜品一行 | 成员菜品名称 + `菜品集共享` 标识 | 重复展示所属菜品集共享份数；不得解释为成员独立额度 |
| 菜品集按种 | 每个成员菜品一行 | 成员菜品名称 + `菜品集共享` 标识 | 重复展示所属菜品集共享种数，并展示每种最多份数 |

菜品集成员例外在成员行中展示最终成员保护：

- 没有例外记录：继承默认成员保护。
- 存在正数例外：使用例外值替换默认值。
- 存在 `0` 例外：显示“禁止下单”。
- 存在但值为空的例外：显示“该成员未设置保护”，且不继承默认值。
- 没有例外记录且默认值也为空：显示“成员保护未配置”。
- 整单周期没有成员保护字段：显示“—”。

每行唯一键为：

```text
storeId + periodKey + partyRangeId + roundRangeId
+ productLineId + targetType + targetId
+ memberDishId（仅菜品集成员行）+ measureUnit
```

固定字段顺序：

| 字段 | 说明 |
| --- | --- |
| 商品 | 菜品展示商品名称；分类和菜品集成员按上述行模型展示；不得混入产线或编码 |
| 产线 | 独立展示产线名称 |
| 分类 | 独立展示分类名称；不得拼接产线名称 |
| 门店 | 商品所属参与门店 |
| 周期 | 整单、每轮或分轮次 |
| 计算方式 | 按桌或按人数 |
| 人数区间 | 使用规则已配置的区间；不适用时显示“—” |
| 轮次区间 | 使用规则已配置的区间；整单时显示“—” |
| 限购结果 | 展示该行全部实际生效结果：对象额度、整桌封顶、场景总量最小/最大值和成员最终保护 |
| 操作 | `进入配置` |

限购结果按实际存在的字段组合展示。示例：`每人每轮最多 2 种；整桌每轮最多 8 种；本轮总量 2～10 份；每种最多 3 份`。按份显示“最多 N 份”，按种显示“最多 N 种（SPU）”。没有配置的结果片段不展示；整行没有任何额度时显示“未配置”。

默认按“商品名称、门店、周期、人数区间、轮次区间”排序，使同一商品的不同场景相邻。

## 5. 筛选条件

### 5.1 常驻筛选

1. 商品名称：模糊搜索商品名称，不搜索商品编码。
2. 门店：默认全部参与门店。
3. 周期：全部、整单、每轮、分轮次。
4. 人数区间：选项来自当前规则真实配置的区间。
5. 轮次区间：选项来自当前规则真实配置的区间。

### 5.2 更多筛选

1. 产线。
2. 分类。
3. 限购对象：菜品、分类、菜品集。
4. 计算方式：按桌、按人数。
5. 配置状态：已配置、未配置、存在差异。

提供快捷开关“仅看额度存在差异的商品”。差异分组键为：

```text
storeId + productLineId + targetType + targetId
+ memberDishId（仅菜品集）+ measureUnit
```

每个分组在当前周期、人数和轮次筛选得到的适用场景全集中，比较表格“限购结果”实际展示的规范化元组：配置状态、`0` 禁止状态、对象额度、整桌额度、总量最小/最大值，以及归一化后的 `effectiveMemberProtection`。`effectiveMemberProtection` 只保留该成员最终生效状态：继承后的数值、例外正数、禁止、不继承默认或未配置，不比较不会改变最终结果的原始默认值。只有一个适用场景时不算差异；某场景存在目标但额度为空，与另一场景已配置或为 `0` 时算差异；已从该场景商品范围删除的目标不属于该场景全集，不因缺失单独判为差异。

### 5.3 联动规则

1. 选择门店后，只展示该门店存在的产线、分类和商品。
2. 分类筛选身份使用 `storeId + lineId + categoryId`；选择产线后，分类只展示该产线下的分类名称，选项文案不附带产线名称。
3. 周期只选择整单时，清空轮次筛选并置为不适用；周期为“全部”且选择了轮次时，结果排除不适用轮次的整单行。
4. 当前规则不涉及人数区间时，人数筛选置为不适用并禁用。
5. 门店变化后清理已失效的产线、分类和商品条件；产线变化后清理已失效的分类条件。
6. 重置筛选恢复全部结果和默认排序。
7. 页面显示筛选结果条数、去重商品数和门店数。

## 6. 数据投影

汇总行由现有规则草稿实时派生，概念身份如下：

```text
ruleId
+ storeId
+ periodKey
+ partyRangeId（不适用时使用固定值 `not_applicable`）
+ roundRangeId（不适用时使用固定值 `not_applicable`）
+ productLineId
+ targetType
+ targetId / dishId
+ measureUnit
```

场景定位必须使用草稿中的 `partyRanges[].rangeId` 和 `roundRanges[].rangeId`，不得使用数组下标。稳定身份迁移是本功能的前置依赖：目标实现分支若已提供 `BuffetRulePolicy.migrateRangeIdentities`，直接复用；若目标分支尚未包含该 API，则必须先在 `buffet-rule-policy.js` 补齐同等能力并测试，不能降级使用数组索引。迁移器必须幂等：缺失 ID 时生成唯一 ID，将旧索引场景键迁移为稳定 ID 场景键，并设置 `rangeIdentityVersion`；汇总只消费迁移器返回的归一化草稿。迁移结果进入现有编辑草稿并按正常保存流程持久化，打开只读汇总本身不单独触发保存。区间排序不改变 ID，新增区间生成新 ID，复制区间生成新 ID，删除区间后对应汇总身份失效；检测到重复 ID 或迁移冲突时阻止“进入配置”并提示修复。组合周期按每个启用的 `periodKey` 独立生成场景行。

汇总数据全集为“各参与门店 × 各启用周期 × 各适用人数/轮次场景 × 该场景已选限购对象”。目标存在但额度为空时仍生成行并显示“未配置”；显式 `0` 显示“禁止下单”且属于已配置；已从某场景商品范围移除的对象不生成该场景行。商品数、配置状态筛选和差异比较都基于这一全集。

汇总组件不复制、缓存或保存额度；关闭弹窗后不产生草稿变更。

分类限购和菜品集限购需要展开成可读的商品结果时，仍必须保留原始限购对象身份，避免“查看结果后跳回编辑”时错误定位到单品规则。

## 7. 进入配置

点击某行“进入配置”执行：

1. 根据行身份找到原始周期、人数区间、轮次区间和门店。
2. 关闭汇总弹窗。
3. 切换配置额度页的当前场景和当前门店。
4. 打开对应场景的商品配置区域。
5. 将目标商品滚动到可视区域并短暂高亮，同时把焦点移入目标配置区域；此导航动作不把焦点返回汇总入口。

若原场景在查看期间被删除或身份无法解析，应留在汇总弹窗并提示“该场景已不存在，请刷新汇总结果”，不得跳到相似场景。

## 8. 删除与空状态

1. 汇总弹窗不提供删除操作，也不定义新的删除语义。现有场景编辑页从当前场景移除商品后，该目标只在当前场景的汇总中消失，其他场景仍正常显示。
2. 当前筛选无结果时显示“没有符合筛选条件的商品配置”，并提供重置筛选。
3. 当前规则尚未配置任何商品时统一显示“暂无商品配置，请先添加商品”。
4. 目标仍属于当前场景但额度为空时，限购结果显示“未配置”，不得显示为 0；0 显示“禁止下单”。

## 9. 性能与可用性

1. 表头固定，表体独立纵向滚动。
2. 横向字段超出时允许横向滚动，并固定商品列和操作列。
3. 本期固定使用分页，默认每页 20 条并沿用现有分页组件；筛选变化和数据刷新后回到第一页，当前页因数据减少而不存在时回到最后一个有效页。
4. 键盘焦点进入弹窗后限制在弹窗内；通过关闭、取消或 Escape 解散弹窗后回到本次触发的“查看全部配置”按钮。通过“进入配置”导航离开弹窗时，焦点移入目标配置区域。
5. 所有筛选控件和“进入配置”按钮必须有明确可访问名称。

## 10. 验收标准

1. 人数 × 轮次组合存在 6 个场景时，汇总能展示 6 个场景中的全部商品配置。
2. 整单 + 每轮、整单 + 分轮次规则能在同一张表中展示，整单行的轮次为“—”。
3. 同一商品在两个门店和三个场景中配置后，按门店及场景正确拆分为多行。
4. 商品、产线、分类、门店分别位于独立列；商品名称正常显示，不展示商品编码。
5. 产线筛选后，分类只出现该产线的分类，且分类文案不包含产线名称。
6. 人数和轮次筛选选项只来自当前规则已有区间。
7. “仅看额度存在差异的商品”只保留在不同场景中结果不一致的同店商品。
8. 菜品集按份、按种及成员保护结果均使用正确单位展示。
9. 点击“进入配置”能定位原周期、区间、门店及商品，不误跳到索引相同的其他区间。
10. 从当前场景删除商品后，汇总只减少该场景对应行。
11. 查看、筛选和关闭汇总弹窗不会修改草稿或触发保存。
12. 空值、0 和正整数分别显示为“未配置”“禁止下单”和对应最大数量。
13. 在人数或轮次区间前插、重排后，汇总行仍通过原 `rangeId` 定位正确场景；删除区间后点击旧结果提示场景已失效。
14. 分类规则按分类行展示，不展开为成员独立额度；菜品集成员行明确标注共享额度。
15. 菜品集无例外继承默认、正数例外、例外 0、空例外不继承默认及默认空值均按第 4 节语义展示。
16. 跨门店同名分类不被合并；切换门店或产线后失效筛选自动清理。
17. 周期为“全部”并选择轮次区间时，不展示整单行。
18. 筛选变化回到第一页，数据减少后页码修正到有效范围。
19. 两行总量约束不同或成员最终保护不同，即使对象额度相同，也被识别为差异，且差异字段在限购结果中可见。
20. 默认保护值变化但成员正数例外保持不变时，该成员的最终结果不变，不误判为差异。
21. 最外层“门店与商品数量”标题右侧显示“查看全部配置”和“+ 添加商品”，查看按钮使用次级样式、添加按钮使用主样式。
22. 从最外层与单场景配置额度页打开汇总，得到相同的规则全集、筛选结果及“进入配置”定位能力。
23. 尚未添加商品时，最外层“查看全部配置”仍可点击，弹窗显示“暂无商品配置，请先添加商品”；关闭后焦点返回最外层入口。

## 11. 与权威文档的关系

本设计是《自助餐规则场景配置融合设计》的“全部场景结果查看”扩展。实现完成并验收后，应把入口、字段口径、稳定身份和验收编号同步回权威文档，避免形成两套长期规范。
