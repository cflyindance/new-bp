# 服务包菜单能力中文名称设计

## 背景

“选择菜单路由能力”使用菜单路由配置的已发布菜单树。当前转换过程直接采用节点 `name`，导致已配置中文多语言名称的菜单仍可能显示英文。

## 目标

服务包管理中的菜单能力树、搜索结果和确认页统一显示中文名称，同时保持已发布菜单树的节点数量、层级结构、节点顺序、节点标识和可选状态不变。

## 名称解析规则

转换已发布 `MenuDocument` 时，为每个菜单节点按以下优先级生成展示标题。这里的“非空值”指类型为字符串且 `trim()` 后仍有内容；空字符串、纯空白字符串和非字符串值均继续回退：

1. `i18nInfo["zh-CN"]` 的非空值；
2. 节点 `name` 的非空值；
3. 节点 `key` 的非空值；
4. 已解析的节点 ID。

名称仅用于展示与搜索，不回写菜单路由发布文档。

## 实现边界

- 在 `subscription-published-menu-tree.ts` 的已发布菜单转换层集中完成名称解析。
- 选择树、搜索和确认页继续复用转换后的 `title`，不分别实现语言判断。
- 不调整发布状态判断；仍以 `updatedBy.timestamp` 是否存在作为已发布依据。
- 不修改菜单节点 ID、父子关系、顺序、路由、禁用状态或选择逻辑。

## 验证

- 中文和英文名称同时存在时，输出去除首尾空白后的中文名称。
- 中文名称为空字符串、纯空白或非字符串值时，依次回退到 `name`、`key` 和节点 ID；各级回退使用相同的非空判断。
- 转换前后的节点数量、树形结构、顺序、节点 ID、父节点 ID、路由、禁用状态以及 selectable/选择行为完全一致。
- 浏览器验证创建服务包第二步显示中文名称、搜索可按中文名称命中，并在第三步确认页继续显示相同的中文名称。
