# 小费管理门店优先工具栏布局设计

## 目标

调整原生“小费管理”页面的信息层级：先确定门店数据范围，再选择“分配汇总 / 员工对账”视角，最后使用当前视角的筛选条件。此次仅调整页面布局和响应式表现，不改变小费分配、员工对账、导出、规则入口及数据计算逻辑。

## 页面结构

页面顶部拆分为两行：

1. 门店范围行：左侧展示门店筛选，右侧展示“新建/查看规则”。
2. 视图与筛选行：左侧展示“分配汇总 / 员工对账”Tab，右侧展示当前视图可用的筛选条件，筛选组整体右对齐。

汇总指标、数据列表和固定底部操作栏继续位于上述两行下方，顺序及业务职责不变。

## 门店范围行

- 门店是整个页面的数据作用域，独立占据首行左侧。
- “新建/查看规则”是两个视图共享的模块级操作，固定在首行右侧。
- 门店选择沿用现有控件、数据源、默认值和变更处理逻辑。
- 规则入口沿用现有判断逻辑：无规则进入新增页，已有规则进入规则列表。

## 视图与筛选行

### 左侧视图导航

- 保留现有“分配汇总 / 员工对账”页内 Tab。
- Tab 的 URL、浏览器历史、键盘操作、视图状态恢复逻辑不变。
- Tab 始终位于筛选折叠区域之外，不能因筛选条件隐藏而消失。

### 右侧筛选组

- 筛选组在桌面端整体靠右排列。
- 分配汇总依次展示：日期范围、角色、员工、日期顺序。
- 员工对账仅展示日期范围；不展示角色、员工和日期顺序。
- 字段显隐继续由当前视图状态控制，不新增计算、请求或筛选口径。
- 控件的视觉排列顺序与键盘焦点顺序保持一致。

## 响应式规则

- 宽屏（视口宽度不小于 1280px）：首行门店与规则入口左右分布；第二行 Tab 靠左、筛选组靠右并保持单行。
- 中等宽度（769px–1279px）：首行仍左右分布；第二行允许筛选组整体换到 Tab 下方的新行，筛选组保持右对齐，日期范围最小宽度为 340px。
- 移动端（视口宽度不大于 768px）：依次纵向展示门店、规则按钮、Tab、筛选条件；Tab 两项等宽；筛选条件占满可用宽度。
- 数据表继续允许横向滚动，固定底部操作栏不得遮挡最后一行数据。
- 门店控件在宽屏和中等宽度下使用可伸缩宽度；长门店名称在控件内部单行省略，并保留完整的可访问名称。在移动端允许控件占满一行。
- 浏览器缩放至 200% 时按缩放后的 CSS 视口应用上述断点，不得出现内容丢失、控件遮挡或键盘无法到达的情况。

## 状态与业务边界

- 切换 Tab 时保留门店和日期范围共同上下文。
- 门店切换仍触发现有数据刷新与员工筛选更新逻辑。
- 分配汇总中的角色、员工、日期顺序状态继续按现有机制记忆。
- 切换员工对账只隐藏不适用筛选，不清空其已选值；返回分配汇总后恢复显示。
- 分配汇总设置日期、角色、员工和日期顺序后切换至员工对账再返回，四项筛选值必须保持。
- 切换 Tab、浏览器前进/后退及刷新后，门店、日期范围和视图状态继续按现有机制恢复。
- 门店切换后，员工筛选值的保留或清除完全沿用现有有效性处理，不由本次布局调整新增规则。
- 不修改金额、工时、考勤、员工聚合或分配状态的计算公式。
- 不修改分配小费、取消分配、确认分配、导出结果或员工明细入口的行为。
- 所有控件复用现有元素和事件处理函数，不复制控件、不重复绑定事件；Tab 切换不新增数据请求，隐藏筛选不改变既有查询参数口径。

## 可访问性

- 门店 `label` 与现有 `select` 关联保持不变。
- Tab 保持现有 `tablist`、`tab`、`aria-selected`、`tabindex` 和 `aria-controls` 关系。
- 使用 `hidden` 的筛选字段必须在组件局部样式中可靠隐藏，不能被布局样式覆盖。
- DOM 顺序必须与视觉阅读顺序一致，不使用 CSS `order` 反转交互顺序。

## 验收标准

1. 宽屏和中等宽度下，门店筛选独立位于页面首行左侧，“新建/查看规则”位于同一行右侧。
2. 宽屏下，第二行左侧固定为“分配汇总 / 员工对账”Tab，右侧放当前视图筛选条件并整体右对齐；中等宽度空间不足时仅允许筛选组整体换行。
3. 分配汇总依次展示日期范围、角色、员工、日期顺序。
4. 员工对账仅展示日期范围；角色、员工和日期顺序不可见、不可聚焦且不进入可访问树。
5. 两个视图的筛选、指标、列表、底部操作和导出范围符合既有行为。
6. 在 1440px、1024px、375px 三个视口及 200% 缩放下，无内容丢失、控件遮挡、异常截断或键盘不可达。
7. 分配汇总设置四项筛选后往返 Tab，选值保持；切换 Tab、前进/后退和刷新后，共同上下文与视图恢复结果与改造前一致。
8. 门店切换后的员工筛选有效性处理、规则跳转、导出、分配和取消分配结果与改造前一致。
9. 键盘焦点顺序与视觉顺序一致，Tab 的可访问状态正确。
10. 现有小费管理专项校验继续通过；新增两行布局、字段顺序、隐藏筛选、事件处理函数复用断言，并确认 Tab 切换不增加请求、既有操作各触发一次原处理流程。
