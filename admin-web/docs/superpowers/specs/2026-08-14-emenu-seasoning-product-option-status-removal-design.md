# eMenu 单商品调味 Option 状态移除设计

## 1. 目标与范围

单商品调味关联编辑不再提供关系级“启用/停用”设置。用户通过添加或删除动作下的 Option 管理关系是否存在；公共调味库继续负责 Option 本身的启用/停用。

本次范围仅包括单商品编辑弹窗中的“设置动作与 Option”和“预览确认”两步。批量建立关联页面本身没有关系状态字段，保持不变；调味关联主列表的历史状态筛选、后端关系状态字段和旧客户端接口暂时保留。

## 2. 采用方案

采用“前端取消编辑 + 保存统一启用 + 后端兼容保留”方案。

仅隐藏状态而保留不可见的旧值会让用户无法理解或恢复停用关系；直接删除后端字段又会扩大到主列表筛选、旧数据和旧客户端。本方案让当前单商品编辑行为明确，同时保持接口兼容。

## 3. 编辑页面

单商品编辑的 Option 表格只展示：

- 拖动排序
- 批量改价选择
- Option 名称
- 输入原价
- 加价系数
- 实际加价价格
- 删除

移除“状态”表头、启用复选框和“已启用/已停用”文案，并重新分配表格网格宽度。动作拖动、Option 拖动、批量改价、添加 Option 和删除 Option 行为不变。

共享配置工作区在批量模式与单商品模式使用同一渲染组件。移除状态后，两种模式使用同一列结构，不能在批量模式产生布局回归。

## 4. 旧关系与保存规则

打开单商品编辑时，服务端返回的全部关系都进入草稿，包括历史停用关系；草稿中的关系状态统一标准化为 `active`。

因此：

- 用户只打开后取消，不产生写入，原数据不变。
- 用户生成预览但返回编辑，不产生写入，原数据不变。
- 用户最终确认保存时，该商品草稿中保留的所有动作 + Option 关系统一保存为 `active`。
- 用户从草稿删除的关系按现有替换式保存规则删除。
- 新添加的关系继续默认为 `active`。

状态标准化只作用于当前正在编辑并最终保存的商品，不批量修改其他商品，也不在页面加载时自动写库。

## 5. 预览确认

单商品预览按动作分组，列结构改为：

- Option
- 输入原价
- 加价系数
- 实际加价价格

移除“状态”列及状态文案。预览仍为只读，动作和 Option 顺序保持与编辑草稿一致。

## 6. 后端与兼容性

- `SeasoningRelation.status`、单商品读取/保存 API 以及后端状态校验继续保留。
- 前端单商品保存请求对每条保留关系显式发送 `status: "active"`。
- 旧客户端仍可发送 `inactive`，后端继续按当前规则处理。
- 调味关联主列表仍可展示和筛选历史 `active / mixed / inactive` 状态；某商品通过新版单商品编辑保存后，其保留关系将变为 `active`。
- 公共调味库 Option 的状态、分类状态和食客端“仅使用启用 Option”的规则不变。

## 7. 错误与并发处理

版本冲突、重新加载最新数据、覆盖确认和保存失败沿用现有单商品编辑流程。发生冲突并重新载入最新关系后，重新生成的编辑草稿仍把关系状态标准化为 `active`；只有用户再次确认保存才写入。

保存失败时保留当前草稿与弹窗，不得产生部分状态变更。

## 8. 验收与测试

1. 单商品编辑表格不包含“状态”表头、关系状态复选框或启停文案。
2. 单商品预览不包含“状态”列或启停文案。
3. 编辑表格仍可添加、删除、拖动 Option，并可批量修改输入原价。
4. 历史停用关系打开后仍展示在对应动作下，不会因隐藏状态而消失。
5. 取消编辑或只生成预览不改变后端历史状态。
6. 最终保存后，当前商品草稿中所有保留关系均为 `active`，已删除关系不存在。
7. 新增关系保存为 `active`。
8. 版本冲突重新加载后，预览与最终请求仍统一使用 `active`。
9. 批量建立关联的列布局、价格编辑、Option 排序和保存行为不变。
10. 公共调味库的 Option 启用/停用功能以及主列表状态筛选继续可用。
11. TypeScript、结构验证与调味 API 回归验证通过。

## 9. 非目标

- 不删除后端关系状态字段。
- 不迁移所有商品的历史停用关系。
- 不移除调味关联主列表状态筛选。
- 不移除公共调味库 Option 或 Option 分类的启停能力。
