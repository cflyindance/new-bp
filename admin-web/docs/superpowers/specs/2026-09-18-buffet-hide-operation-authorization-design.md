# 自助餐规则：隐藏本次操作授权入口

## 已确认的范围

仅调整自助餐规则的“超限授权”配置界面。隐藏“本次操作”的可操作入口，不删除该授权范围的逻辑，不迁移已有数据，不扩大已有授权范围。菜单下单限制不受影响。

## 界面处理

1. 隐藏“本次操作”的勾选行，包括该行的权限下拉框和辅助说明。
2. “默认授权范围”的可选项不再包含“本次操作”；仍按原规则显示已启用且适用的“当前轮”“当前订单”。纯整单规则仍不支持“当前轮”。
3. 当前默认值为 `operation` 时，显示只读提示“沿用原默认授权范围：本次操作”。该提示不是可选项，不提供重新选择“本次操作”的入口。
4. 存在其他可选范围时，允许用户明确选择一个新默认范围；未选择时保持原值。不得因下拉框首项变化，把原值隐式替换为“当前轮”或“当前订单”。
5. 没有其他可选范围时，不显示空白、可操作的默认范围下拉框，仍保留只读提示。没有任何已启用范围且不存在可沿用默认值时，沿用现有必选校验，不补造默认值。

## 数据与逻辑边界

- 保留 `operation` 枚举、`allowedScopes` 中的已有值、对应权限、默认值和凭证校验分支。
- 不改变新建草稿的初始化规则；任意草稿若按现有逻辑得到 `operation` 默认值，均使用上述只读兼容展示。
- 不修改现有纯整单规则去除 `round` 的规范化行为。本次隐藏不额外修改授权数据。
- 页面打开、刷新、只读查看及保存时，不得仅因入口隐藏而删除或替换 `operation` 数据。
- 用户明确更改其他范围、默认范围、授权开关和原因要求，继续按原交互处理。再次打开仍准确展示已保存值。
- 确认发布等只读摘要可继续显示实际保存的授权范围，不伪装成其他范围。
- 不修改真实权限校验、员工角色、数量批准上限、订单/轮次绑定逻辑，不涉及 eMenu 源码。

## 验收

1. 自助餐规则没有“本次操作”的勾选框、角色选择框或可选默认范围。
2. 原默认为“当前轮”或“当前订单”的配置显示和操作正常。
3. 原默认为“本次操作”的配置显示只读提示，打开与保存不改变原值及其权限。
4. 仅启用“本次操作”的旧规则可继续打开并保留配置，不出现空白下拉框或错误地扩大授权。
5. 明确选择其他已启用范围后，保存及重新打开显示一致；无法通过可选入口再选择“本次操作”。
6. 纯整单规则不出现“当前轮”；关闭授权、原因必填设置正常。
7. 菜单下单限制仍保留原有三个授权入口。
8. 现有 `scripts/verify-buffet-rule-authorization.mjs` 通过，证明 `operationId` 等原授权校验仍保留。
9. 在 main 的本地预览页面验证可见入口和兼容提示；不修改已有正式规则。
