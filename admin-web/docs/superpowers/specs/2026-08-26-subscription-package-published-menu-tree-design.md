# 服务包菜单能力复用已发布菜单树设计

## 目标

服务包创建与编辑中的“菜单路由能力”必须直接镜像“菜单路由配置”当前已发布、生效的菜单结构。两处在节点数量、父子结构、同级顺序和生效状态上保持一致，不再由订阅模块根据静态 `NAV_MODULES` 重新分组。

## 唯一数据源

- 使用 `DEFAULT_NAV_BLUEPRINT_ID` 对应的 `getPublishedNavBlueprint` 快照。
- 不读取 `getNavBlueprintDraft`，未发布的菜单调整不得提前出现在服务包中。
- 根据发布快照的 `navigationSource` 构建生效树：系统来源使用已发布系统树，自定义来源使用已发布自定义树。
- 复用 `buildNavBlueprintGroupsForModule(snapshot, "active")` 生成与菜单路由配置相同的层级和排序。
- 使用发布快照中当前来源对应的 `structureSelection` 过滤未启用节点。节点启用判定为 `selection[resource.key]?.enabled ?? true`，且全部祖先均启用；父节点禁用时整个后代子树不可达并一并过滤。该规则与菜单路由配置的生效树预览共用。

## 订阅菜单树模型

新增只读适配层，把已发布菜单树转换为订阅页面可消费的树节点。每个节点包含：

- `routeNodeId`，值直接等于菜单树的 `resource.key`；
- 标题、路径、层级；
- 原始顺序的 children；
- 是否为目录节点；
- 是否可作为最终菜单能力保存；
- 可保存后代节点数量。

适配层不得自行排序、去重或重新分组。输出的深度优先遍历 `routeNodeId` 序列必须与菜单路由配置生效树一致。服务包继续读写现有 `routeNodeIds` 字段，不新增另一套 key，也不做 ID 转换。

可保存节点采用统一谓词：`resource.path` 为非空字符串、`resource.chainOnly !== true` 且 `resource.level <= 3`。一级至三级中满足谓词的节点即使同时拥有子节点，也代表可访问菜单入口，允许保存自身 `resource.key`；仅用于结构展示的目录、`chainOnly` 链路占位节点及四级设置项不写入服务包，但仍完整显示并参与父子选择状态计算。菜单路由配置与服务包页面必须复用该谓词，禁止各自判断。

## 页面展示与选择

- 创建向导第二步和已有服务包编辑页面统一使用同一个树组件与同一个已发布树适配层。
- 完整展示一级至四级层级，默认按菜单路由配置的展开方式展示一级节点，子级可折叠。
- 父节点复选框代表“父节点自身（若满足可保存谓词）+ 全部可保存后代”。勾选或取消时级联处理这一完整集合，不支持仅选择父节点自身。
- 无子节点的可访问页面节点可以单独选择。父节点对应集合全部选中时为选中，部分选中时为半选，全部未选时为未选。
- 数量统一按可保存菜单能力节点计算，同时显示“发布生效树结构节点总数”；该总数不随搜索或折叠变化。搜索状态另行显示当前匹配的可保存节点数。
- 搜索命中叶子或可访问节点时，保留该节点及其全部祖先；搜索命中目录节点时，保留该目录、全部祖先和该目录的全部原序后代。搜索只影响显示，不改变选择集合或保存结果。

## 保存与兼容

- 服务包草稿和发布版本继续通过现有 `routeNodeIds` 保存 `resource.key`，不复制菜单树。
- 保存前按当前已发布菜单树校验 ID，只接受仍然存在且可保存的节点。
- 已有服务包中的 `routeNodeId` 若已不在当前已发布树中，编辑页单独展示为只读“已失效菜单”列表并显示原 ID。保存草稿时自动从提交的 `routeNodeIds` 中剔除，并在保存按钮附近明确提示“保存后将移除 N 项失效菜单”；取消编辑不改变草稿或已发布版本。失效 ID 不得映射到其他节点。
- 菜单路由配置发布新版本不会自动修改已发布服务包版本。用户下次进入编辑页面时看到最新菜单树和失效提示，重新发布服务包后才更新商家能力。
- 若尚无已发布菜单快照，菜单能力步骤显示空状态并禁止继续或发布，引导先发布菜单路由配置。

## 验收标准

- 服务包菜单树的数据来自已发布快照，修改但未发布的菜单配置不会出现。
- 生效来源为系统树或自定义树时，服务包页面分别镜像对应树。
- 两处树的可见节点数量、层级、标题和同级顺序完全一致。
- 被已发布结构禁用的节点及其不可达后代不出现在服务包树中。
- 父选、子选、半选和模块全选行为正确；覆盖父节点自身已选且后代全选、部分选、全未选三种状态。最终只把满足统一谓词的 `resource.key` 写入现有 `routeNodeIds`。
- 搜索不会打乱原始顺序或丢失祖先链；目录命中保留全部原序后代，其他命中只补齐祖先。
- 创建向导和服务包编辑页展示相同树结构。
- 已失效的历史能力按原 `routeNodeId` 明确展示；取消不改变数据，保存后自动移除且不会替换成其他节点。
- 无已发布快照时无法进入确认保存。
- 新增 `scripts/verify-subscription-published-menu-tree.ts`：对同一发布快照比较菜单路由配置树与订阅适配树的深度优先 `routeNodeId` 序列，并逐节点比较 parent ID、children ID 及顺序。
- 验证脚本分别覆盖 system/custom `navigationSource`、对应 `structureSelection`、来源切换、禁用父节点及不可达后代、搜索规则和空发布快照。
- TypeScript 检查及 `npx.cmd --yes tsx scripts/verify-subscription-published-menu-tree.ts` 通过。
