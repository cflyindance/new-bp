# 商家订阅主体类型列设计

## 背景

商家订阅的“订阅明细”目前将主体类型与主体 ID 合并显示在主体名称下方。用户需要一个独立字段，明确标识每条订阅属于集团、品牌还是门店。

## 目标

- 在订阅明细中增加独立的“主体类型”列。
- 每条记录以中文文字标签展示“集团”“品牌”或“门店”。
- 主体列仅展示主体名称与主体 ID，避免重复展示主体类型。
- 保持现有订阅数据、状态计算、续期、停用及开通服务逻辑不变。

## 页面设计

订阅明细表格的列顺序调整为：

1. 主体
2. 主体类型
3. 服务包
4. 有效期
5. 状态
6. 操作

“主体”列第一行展示主体中文名称，第二行展示主体 ID。“主体类型”列通过清晰的文字标签展示类型，并沿用现有状态标签的视觉语言，保证三种类型均可直接识别，不仅依赖颜色或图标。

## 数据映射

继续使用现有订阅记录的 `subjectType` 字段，不新增或迁移数据：

- `group` → 集团
- `brand` → 品牌
- `store` → 门店

主体名称仍由现有 `subjectLabel` 逻辑解析，主体 ID 直接读取 `subjectId`。

## 边界与异常处理

- 即使主体名称无法解析，现有回退逻辑仍以主体 ID 作为名称显示，主体类型标签不受影响。
- 空列表提示行的 `colspan` 从 5 调整为 6，确保空状态覆盖完整表格宽度。
- 表格保留横向滚动能力，并适当调整最小宽度，避免新增列后内容拥挤。

## 验证方案

- 验证集团、品牌、门店三类订阅分别显示正确的中文主体类型。
- 验证主体列只包含主体名称和 ID，不重复显示主体类型。
- 验证空列表提示横跨全部六列。
- 验证续期、停用等原有操作仍正常可用。
- 执行项目现有的 TypeScript/构建或订阅服务相关验证，并在浏览器中检查表格布局。
