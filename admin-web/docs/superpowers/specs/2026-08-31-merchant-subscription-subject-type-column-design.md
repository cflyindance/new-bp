# 商家订阅主体类型列设计

## 背景

商家订阅的“订阅明细”目前将主体类型与主体 ID 合并显示在主体名称下方。用户需要一个独立字段，明确标识每条订阅属于集团、品牌还是门店。

## 目标

- 在订阅明细中增加独立的“主体类型”列。
- 每条记录以中文文字标签展示“集团”“品牌”或“门店”。
- 主体列仅展示主体名称与主体 ID，避免重复展示主体类型。
- 保持现有订阅数据、状态计算、续期、停用及开通服务逻辑不变。

## 页面设计

订阅明细表格的列顺序调整为：

1. 主体
2. 主体类型
3. 服务包
4. 有效期
5. 状态
6. 操作

第六列表头明确显示“操作”并右对齐，行内操作继续右对齐。“主体”列第一行展示主体中文名称，第二行展示主体 ID。“主体类型”列通过清晰的文字标签展示类型，并沿用现有状态标签的视觉语言，保证三种类型均可直接识别，不仅依赖颜色或图标。

## 数据映射

继续使用现有订阅记录的 `subjectType` 字段，不新增或迁移数据：

- `group` → 集团
- `brand` → 品牌
- `store` → 门店

主体名称仍由现有 `subjectLabel` 逻辑解析，主体 ID 直接读取 `subjectId`。

## 边界与异常处理

- 当主体名称无法解析、名称回退结果与主体 ID 相同时，主体列仅显示一行主体 ID，不重复渲染相同 ID。
- 当运行时数据中的 `subjectType` 缺失或不是 `group`、`brand`、`store` 时，主体类型标签显示“未知”，主体名称显示“未知主体”，第二行仍显示原始主体 ID；页面不修改或迁移原始订阅数据。
- 空列表提示行的 `colspan` 从 5 调整为 6，确保空状态覆盖完整表格宽度。
- 表格最小宽度从 760px 调整为 880px；小于该宽度的容器继续使用现有横向滚动，表头和单元格不得互相覆盖。

## 验证方案

- 验证集团、品牌、门店三类订阅分别显示正确的中文主体类型。
- 验证主体列只包含主体名称和 ID，不重复显示主体类型。
- 验证名称无法解析时只显示一行 ID，不出现重复 ID。
- 验证缺失或异常 `subjectType` 时显示“未知”和“未知主体”，且页面可正常渲染。
- 验证空列表提示横跨全部六列。
- 在浏览器中断言六列表头依次为“主体、主体类型、服务包、有效期、状态、操作”，每条记录包含六个单元格，操作列右对齐。
- 在窄于 880px 的容器中验证可横向滚动且内容不重叠。
- 验证续期、停用等原有操作仍正常可用。
- 执行 `npm run verify:subscription-service` 和 `npm run build`，两条命令均须成功退出。
