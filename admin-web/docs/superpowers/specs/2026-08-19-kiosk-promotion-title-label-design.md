# Kiosk 促销活动标题与活动标签设计

## 背景

Kiosk 当前通过「服务设置 → 展示设置 → 促销中心活动标签标题来源」控制云端促销中心活动文案：

- `0`：按活动规则生成系统默认文案；
- `1`：展示云端 `promotionName`。

该设置目前不控制 Kiosk 本地促销。本地促销也没有独立的中英文活动标题和活动标签，只能展示规则文案。

## 目标

1. 展示设置新增【活动标签】选项。
2. Kiosk 本地促销的新建、编辑表单增加【活动标题】和【活动标签】，二者均支持中英文输入且全部必填。
3. 同一展示设置统一控制本地促销和云端促销中心活动。
4. Kiosk 所有食客可见的促销活动名称按当前 Kiosk 语言展示：
   - 中文语系展示中文；
   - 非中文语系展示英文。
5. 兼容旧本地促销和云端无标签数据，不产生空白活动名称。

## 非目标

- 不修改云端促销中心的创建、编辑能力。
- 不为中文、英文之外的语言新增活动文案输入。
- 不改变促销计算、命中、互斥、排序、启停和适用商品逻辑。
- 不新增第二套展示来源配置。

## 已确认的产品规则

### 展示来源

继续使用 `promotion-center-activity-name`（运行时为 `configMap.id_64`），扩展为三个枚举值：

| 值 | 设置选项 | Kiosk 本地促销 | 云端促销中心 |
|---|---|---|---|
| `0` | 系统默认 | 当前规则文案 | 当前规则 i18n 文案 |
| `1` | 活动名称 | 按语言取活动标题 | `promotionName` |
| `2` | 活动标签 | 按语言取活动标签 | 无标签字段，回退 `promotionName` |

云端 `promotionName` 缺失时继续回退规则文案。

### 本地促销数据

每条 Kiosk 本地促销增加：

```js
activityTitle: {
  zh: '',
  en: '',
},
activityTag: {
  zh: '',
  en: '',
},
```

- `activityTitle.zh`：活动标题中文，必填。
- `activityTitle.en`：活动标题英文，必填。
- `activityTag.zh`：活动标签中文，必填。
- `activityTag.en`：活动标签英文，必填。
- 保存前去除四个值的首尾空格。
- 不把字段塞入 `activityRule`，避免展示元数据与促销计算规则耦合。

### 语言选择

- `zh_cn`、繁体中文及其他以 `zh` 标识的中文语系取 `zh`。
- `en` 取 `en`。
- 法语、西班牙语、日语、韩语、泰语等所有非中文语言均取 `en`。
- 本规则只影响活动标题和活动标签，不改变现有规则文案的多语言翻译机制。

### 兼容与回退

旧本地促销没有新增字段：

- 展示时缺少所选标题或标签，回退当前规则文案。
- 编辑旧活动时显示新增输入框；再次保存必须补齐四个输入。
- 不批量迁移或自动生成旧活动标题、标签。

## 表单设计

在「设置 → 促销活动 → 新建活动 / 编辑活动」中，于【活动类型】下依次增加：

1. 【活动标题】
   - 中文输入框；
   - 英文输入框。
2. 【活动标签】
   - 中文输入框；
   - 英文输入框。

交互规则：

- 四个输入均显示必填标识。
- 任一输入去除首尾空格后为空时，阻止保存并在对应输入处显示错误。
- 新建和编辑使用相同字段与校验。
- 字段不随活动类型切换而清空；切换类型仍只重置活动规则。
- 沿用现有 Ant Design 表单布局，不新增弹窗层级。

## 统一文案解析

新增通用解析器，云端现有解析方法改为调用该解析器。本地促销不得再在各组件内直接决定最终活动名称。解析器输入为一个明确对象：

- `source`：`configMap.id_64`；
- `language`：Kiosk 当前 i18n language；
- `origin`：`local` 或 `cloud`，不通过字段是否存在进行猜测；
- `promotion`：完整本地或云端活动对象；
- `ruleText`：调用点已按现有逻辑生成的规则文案，类型为 `string | string[]`。

配置归一化：

- `source` 先通过 `Number(source)` 数值化；
- 只有 `0`、`1`、`2` 为有效值；
- `undefined`、`null`、空字符串、无法数值化或未知值一律按 `0` 处理。

语言归一化：

- 先转为小写，再将 `_` 转为 `-`；
- 归一化结果等于 `zh` 或以 `zh-` 开头时取中文；
- `zh-CN`、`zh_cn`、`zh-TW`、`ZH-HK` 均归入中文；
- 其余语言统一取英文。

候选文案归一化：

- 只有字符串可作为候选；
- 候选先 `trim()`，纯空格、`null`、非字符串和异常对象均视为缺失；
- 云端 `promotionName` 使用同一规则。

解析顺序：

1. `source = 0`：直接返回规则文案。
2. `source = 1`：
   - 本地：按语言取 `activityTitle`；
   - 云端：取 `promotionName`。
3. `source = 2`：
   - 本地：按语言取 `activityTag`；
   - 云端：取 `promotionName`。
4. 目标值为空时回退规则文案。

返回类型为 `string | string[]`：

- 标题、标签或 `promotionName` 命中时返回单个 `string`；
- 回退规则文案时保持 `ruleText` 原类型，不把数组隐式转为字符串；
- 阶梯活动需要展示匹配档位的调用点，继续在调用解析器前按现有逻辑生成匹配档位规则文案；
- 支持多档规则列表的调用点，在 `source = 0` 或回退时继续得到完整 `string[]`，由原组件按现有方式渲染。

解析器只负责文案选择，不修改活动原始数据，也不参与促销规则计算。

## 数据传播约束

- `activityTitle`、`activityTag` 作为本地活动顶层字段随现有促销配置快照读写。
- 本地活动进入 Redux、活动命中结果、优惠活动列表、菜品标签、购物车派生对象时，必须保留完整活动对象或稳定的活动 ID。
- 首选在派生对象中保留 `promotion` 原对象，由展示点把完整对象交给解析器；禁止只复制旧 `text` 后丢失新增字段。
- 若某条链路只能保留 ID，则必须通过原促销集合按 ID 回查，不能通过标题或规则内容匹配。
- 云端活动继续保留完整 `promotion` 对象，并通过 `origin: 'cloud'` 显式调用。
- 切换 Kiosk 语言或修改 `id_64` 后，所有依赖项必须重新计算，不能把已解析的单语言字符串持久化进活动数据。

## Kiosk 展示范围

所有食客可见的促销“识别名称”统一走解析器，包括：

- 菜单页「优惠活动」卡片标题：切换识别名称；卡片内优惠条件仍保留规则文案。
- 菜品卡片促销标签：该标签承担活动识别，整体切换为规则文案、活动标题或活动标签。
- 促销详情、商品选择和凑单抽屉标题：切换识别名称；金额、数量及操作说明不变。
- 购物车与订单确认页中明确标识活动的名称：切换识别名称；价格计算说明不变。
- 促销互斥、已参与活动等提示中的活动名称插值：切换识别名称；提示句式不变。

纯粹用于说明“满多少减多少、买几赠几、折扣比例、赠品数量”的交易条件文本不切换。若同一区域同时展示活动名称和条件，两部分分开渲染，不能用标题或标签覆盖交易条件。

## 配置与国际化

### 展示设置

- `promotion-center-activity-name` 的 Radio 数量由 2 调整为 3。
- 增加 `promotion-center-activity-name-2`：
  - 中文：【活动标签】；
  - 英文：`Activity Tag`；
  - 其他后台语言补齐对应设置项翻译，避免显示 key。

### 表单文案

至少增加以下 i18n key，并为现有 locale 文件提供对应翻译或英文兜底：

- 活动标题；
- 活动标签；
- 中文；
- 英文；
- 四个必填校验提示。

## 数据流

1. 管理员在本地配置后台创建或编辑本地促销。
2. 表单校验并保存双语活动标题、活动标签至现有本地促销配置快照。
3. Kiosk 加载本地促销配置及 `configMap.id_64`。
4. 展示组件生成原有规则文案。
5. 派生对象保留完整活动对象或稳定 ID。
6. 统一解析器结合来源、语言和配置选择最终活动名称。
7. Kiosk 切换语言后，依赖当前语言的展示项重新计算，不需要重新保存活动。

## 验证方案

### 表单

- 新建活动时四个输入缺任意一个均不能保存。
- 仅输入空格不能保存。
- 保存后重新编辑可正确回填。
- 切换活动类型不会清空标题和标签。
- 编辑旧活动必须补齐四项才能再次保存。

### 本地促销展示

- `id_64 = 0`：中英文环境均展示现有规则文案。
- `id_64 = 1`：中文、繁体中文展示中文标题；英文及其他语言展示英文标题。
- `id_64 = 2`：中文、繁体中文展示中文标签；英文及其他语言展示英文标签。
- 旧活动字段对象缺失、单语缺失、值为 `null`、非字符串、纯空格或结构异常时回退规则文案。
- 规则文案为多档数组时，回退后保持数组，不发生隐式字符串化。

### 云端促销展示

- `id_64 = 0`：展示规则文案。
- `id_64 = 1`：展示 `promotionName`。
- `id_64 = 2`：因云端无标签字段，展示 `promotionName`。
- `promotionName` 缺失时回退规则文案。
- `promotionName` 为纯空格、非字符串时同样视为缺失。

### 配置与语言健壮性

- `id_64` 为数字和数字字符串时结果一致。
- `id_64` 为空、未知值或非法值时按系统默认处理。
- `zh`、`zh_cn`、`zh-CN`、`zh-TW`、`ZH-HK` 均取中文。
- `en` 及所有非中文语言均取英文。

### 展示面

逐项检查优惠活动列表、菜品标签、促销抽屉、购物车、订单确认和互斥提示，确保同一活动在同一语言下使用一致识别名称，同时金额、折扣、数量和赠品条件仍完整显示。

### 设置保存

- 仅修改 Kiosk 配置时，不重复提交未变化的 POS 配置。
- POS 配置未变化时，其接口状态不得阻断 `id_64` 等 Kiosk 配置保存。
- POS 配置确实发生变化时，仍先保存 POS 配置；保存失败应阻断后续流程并提示错误。
- `id_64 = 2` 保存成功后，重新加载页面仍应保持“活动标签”选中。

### 构建

- 运行 kiosklite 相关测试或定向验证脚本。
- 执行 Kiosk embed 构建。
- 在主工作区 Kiosk 本地配置后台验证设置页、促销表单和 Kiosk 语言切换。

## 实施约束

- 权威修改、测试和构建在独立 worktree 完成。
- 同步相同源码和构建产物到主工作区，供本地 Vite 预览。
- 不执行 Git commit、push、PR 或发布，除非用户另行明确要求。
