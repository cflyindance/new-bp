# TipOut 按工作时长分配的每日最大工时设计

## 目标

在小费分配规则的“小费分配方式”中，为“按工作时长占比分配”增加工时口径配置。用户可以按员工实际打卡工时分配，也可以为每位员工设置每日参与分配的最大工时。

## 用户界面

- 仅当“小费分配方式”选择“按工作时长占比分配”时，在该选项下方缩进展示两个单选项。
- 当员工打卡方式为“打卡上班”时，文案为：
  - “按照实际打卡工时”
  - “打卡工时超出最大工时，按最大工时”
- 当员工打卡方式为“不打卡”时，文案随工时来源切换为：
  - “按照实际录入工时”
  - “录入工时超出最大工时，按最大工时”
- 默认选择第一个“实际工时”选项；其文案随员工打卡方式显示为“按照实际打卡工时”或“按照实际录入工时”。
- 选择最大工时模式时，在第二项后展示并启用数字输入框，单位显示为“小时/天”。
- 最大工时输入框使用 `min="0.1"`、`max="24"`、`step="0.1"`。
- 选择实际工时模式时，最大工时输入框隐藏或禁用。
- 切换到其他小费分配方式时隐藏整个工时配置区域，但保留本次编辑会话中的选择和输入值；切回工作时长分配时恢复。
- 小费池规则页和加收服务费池规则页共用相同界面和行为。

## 数据模型

保留现有 `distribution: "hours"`，新增独立配置对象：

```js
workHoursConfig: {
  mode: "actual", // "actual" | "capped"
  maxHoursPerDay: null
}
```

实际工时模式保存：

```js
workHoursConfig: {
  mode: "actual",
  maxHoursPerDay: null
}
```

最大工时模式保存：

```js
workHoursConfig: {
  mode: "capped",
  maxHoursPerDay: 8.5
}
```

当 `distribution` 不是 `hours` 时，不向最终规则数据保存 `workHoursConfig`。编辑页在分配方式之间切换时可以保留临时表单值，但持久化数据只包含当前有效配置。

## 校验

- 最大工时模式下，输入框必填。
- 仅接受数字，范围为 `0.1–24` 小时，最多一位小数。
- 空值、非数字、超出范围或超过一位小数时阻止规则提交，并在工时配置附近显示明确提示。
- 实际工时模式不校验最大工时输入值，并保存 `maxHoursPerDay: null`。

## 计算语义

- 员工打卡方式为“打卡上班”时，工时来源是所选自然日调用 `TipOutAttendance.getDayStatus(employeeName, dateKey).hours` 得到的当天打卡工时；不跨日期预先汇总。
- 员工打卡方式为“不打卡”时，工时来源是详情分配流程中为该员工、该自然日手工录入的工时；每日上限同样作用于该手工录入值。
- 实际工时模式下，每位员工每天的分配权重直接使用其归一化后的当天工时。
- 最大工时模式下，每位员工每天的有效工时为：

```text
min(当天来源工时, maxHoursPerDay)
```

- 同一接收角色内按员工有效工时占比分配该角色金额。
- 工时归一化规则统一为：将输入转换为 number；缺失、`null`、非有限数或负数均按 `0` 处理。
- 当规则配置缺失、模式非法或最大工时非法时，安全回退到当前打卡方式对应的实际工时来源：打卡上班使用实际打卡工时，不打卡使用实际录入工时。
- 当同一角色内所有员工均无可用工时时，保留现有等额分配回退，避免金额丢失。
- 金额继续保留两位小数，并按稳定员工顺序计算；最后一名正权重员工承接分币尾差，保证员工金额之和等于角色金额。全零工时回退时沿用现有等额分配与最后一名员工承接尾差的规则。
- “按员工数量平均分配”和“按订单占比分配”的现有行为不变。

## 两种分配模式的覆盖范围

- 小费池汇总分配（`legacy_pool`）：小费接收角色金额形成后，在角色内部使用统一工时权重拆分给员工。
- 计提小费占比分配（`order_tip_then_residual`）：计提小费接受方和剩余小费接收方形成的角色金额，均在角色内部使用同一工时权重拆分给员工。
- 在 `tipAllocation.js` 中抽取共享的“角色金额按员工权重拆分”能力，供 legacy 流水和 order-tip 流水共同调用，避免两个模式产生不同算法。
- 共享拆分函数接收 `roleAmounts`、规则和员工数组；员工结构至少包含 `{ id?, name, role, hours }`，其中 `hours` 是该员工所选自然日的当前工时来源值。
- 共享拆分函数返回至少 `{ receivedByName, effectiveHoursByName }`。没有匹配员工的角色保留在 `roleAmounts` 中，不虚构员工结果；`receivedByName` 不产生该角色的条目。
- `allocateOrderTipResidual(rule, ctx)` 通过 `ctx.employees` 接收上述员工数组，并在现有 `roleAmounts` 之外返回 `receivedByName` 和 `effectiveHoursByName`；详情与其他调用方以该接口结果渲染员工级分配。
- 详情页不得继续用随机比例代替 `distribution: "hours"` 的员工分配。

## 不打卡手工工时生命周期

- 手工工时仅存在于当前详情页会话，不写入小费规则、`localStorage` 或其他长期存储。
- `detail.html` 维护按“规则 ID + 自然日 `dateKey` + 员工标识”索引的内存状态；员工有稳定 ID 时优先使用 ID，否则使用姓名。
- 首次进入某规则、日期和员工组合时工时为 `0`。输入变化后先按统一工时规则归一化，再更新内存状态并立即重算当前规则、当前日期的员工分配结果。
- 切换日期时读取目标日期独立的内存状态，不跨日期复用或累计。
- 刷新页面或重新进入详情页后手工工时不恢复，重新从 `0` 开始；同一角色全部为 `0` 时触发等额分配回退。
- 手工输入发生在角色金额已经形成之后，重算只重新执行共享的“角色金额按员工权重拆分”，不重复计算小费池、计提金额或剩余金额。

## 新增、编辑与历史兼容

- 新增规则默认使用 `mode: "actual"`。
- 编辑已有 `distribution: "hours"` 但缺少 `workHoursConfig` 的规则时，按实际工时模式回填；文案根据 `rule.clockin` 显示为“按照实际打卡工时”或“按照实际录入工时”。
- 编辑已有有效配置时，完整回填模式和每日最大工时。
- 保存非工时分配方式时，删除旧的持久化 `workHoursConfig`，避免无效配置继续生效。
- 历史规则缺少新字段时仍保持可读、可编辑和可计算。

## 列表与详情展示

- 规则列表和规则详情在工作时长分配方式后展示子配置：
  - `按工作时长占比分配（按照实际打卡工时）`
  - `按工作时长占比分配（按照实际录入工时）`
  - `按工作时长占比分配（每日最多 8.5 小时）`
- 非工作时长分配方式继续显示现有名称，不追加子配置。
- 配置缺失或非法时，按 `rule.clockin` 展示对应的“按照实际打卡工时”或“按照实际录入工时”。列表、两种详情分支和公式说明使用同一格式化规则。

## 实现边界

预计修改以下文件：

- `dist/TipOut/rule-add.html`：界面、显隐、临时状态、校验、收集、保存和编辑回填。
- `dist/TipOut/ruleData.js`：列表摘要中的工时子配置格式化。
- `dist/TipOut/detail.html`：规则详情与公式说明中的工时子配置展示；为 order-tip 详情传入员工日工时；在“不打卡”场景让手工录入工时参与实际/封顶计算。
- `dist/TipOut/index.html`：将员工当天打卡工时传入日分配流水。
- `dist/TipOut/tipAllocation.js`：提供两种 allocation mode 共用的实际/封顶工时权重与金额拆分逻辑。

不修改员工打卡数据源、其他模块的工时设置、订单占比分配逻辑或非 TipOut 页面。

## 验证

1. 验证三种小费分配方式切换时，工时配置区域只在 `hours` 模式显示，且切换回来可恢复临时值。
2. 验证两个工时子选项切换时输入框正确启用、禁用或隐藏。
3. 验证 `0.1`、`24` 可提交；空值、`0`、大于 `24`、非数字和多于一位小数不可提交。
4. 验证新增规则保存的 `workHoursConfig` 结构准确，非工时模式不保存该对象。
5. 验证实际模式与封顶模式均可从编辑页正确回填。
6. 验证缺少 `workHoursConfig` 的历史工时规则默认回填和展示为实际打卡工时。
7. 在“打卡上班”场景使用同一角色内不同当天打卡工时的员工验证比例分配；验证缺失、`null`、非有限数和负数均归一化为 `0`。
8. 在“不打卡”场景验证手工录入工时参与比例分配，并验证实际模式和封顶模式。
9. 验证手工工时录入后立即重算；同一员工在两个日期的值互不影响；刷新或重新进入详情后恢复为 `0`；手工工时不进入规则持久化数据。
10. 使用同一员工连续两天各 `10` 小时、上限 `8` 小时的数据，确认每天有效工时均为 `8` 小时，而不是跨日合计后只保留 `8` 小时。
11. 验证所有员工工时为零时仍等额分配角色金额；使用不可整除金额和包含零权重员工的数据，确认最后一名正权重员工承接尾差且总额守恒。
12. 对共享拆分函数和 `allocateOrderTipResidual(rule, { employees })` 做接口级断言，验证 `receivedByName`、`effectiveHoursByName`、无匹配角色员工和总额守恒。
13. 分别验证 `legacy_pool` 和 `order_tip_then_residual`：后者的计提接收方及剩余接收方都应用工时权重，不再使用随机比例模拟。
14. 分别验证小费池和加收服务费池规则页。
15. 分别验证 `ruleData.js` 的 legacy 列表摘要和 order-tip 列表摘要，以及 `detail.html` 的两种详情分支和公式说明中的工时子配置文案；配置缺失时根据 `clockin` 显示正确的实际工时来源。
