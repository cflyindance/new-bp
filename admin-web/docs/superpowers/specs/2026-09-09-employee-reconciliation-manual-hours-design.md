# 员工对账手动工时展示设计

## 目标

员工对账明细需要准确说明按工时分配小费时所使用的工时来源。除实际打卡工时外，小费分配明细允许按小费池、规则和员工手动录入工时。页面必须展示这两类工时而不混淆含义，也不得改变既有小费计算和已保存的分配结果。

## 范围与约束

- 仅修改原生 `src/team/tips` 页面，不修改旧 TipOut 项目。
- 每个员工、每个日期仍只展示一行，小费金额只展示一次。
- 手动工时属于一条具体分配规则和小费池，不代表实际考勤工时。
- 不对不同小费池的手动工时求和，不用手动工时生成虚构班次或上下班时间。
- 员工对账只读取分配明细已使用的工时，不在详情页重新计算或修改小费。

## 数据模型

逐日员工结果在既有考勤字段外携带实际参与分配的手动工时记录：

```js
manualHourEntries: [
  {
    poolId: 'pool-id',
    poolName: '前厅小费池',
    ruleId: 'rule-id',
    ruleName: '前厅按工时分配',
    hours: 6
  }
]
```

规则如下：

- 一条记录必须具备稳定的 `poolId`、`ruleId` 与非负有限数 `hours`。
- 小费池展示名称使用 `poolName`，缺失时固定显示“未命名小费池”。规则展示名称使用 `ruleName`，缺失时固定显示“未命名规则”。稳定 ID 只用于去重与排序，不直接作为用户可见名称。
- 同一员工、日期、池和规则仅保留实际用于最终分配结果的工时值。
- `punchSessions` 继续作为打卡状态、班次、打卡工时和上下班时间的权威来源。
- `manualHourEntries` 作为手动工时展示的权威来源。
- 金额字段继续使用既有逐日结果，两个工时来源均不得触发详情页重新分配。

## 工时来源与考勤状态

页面根据当天数据生成展示状态：

| 当天数据 | 考勤展示 | 班次与上下班时间 | 工时展示 |
| --- | --- | --- | --- |
| 仅有效打卡记录 | 已打卡 | 展示真实数据 | 展示打卡工时 |
| 存在异常打卡且无手动工时 | 打卡异常 | 展示已有打卡值 | 仅统计有效会话工时 |
| 无打卡且无手动工时 | 未打卡 | `—` | `0 h` |
| 仅有手动工时 | 手动工时 | `—` | 按小费池分行展示 |
| 同时有打卡记录和手动工时 | 混合工时 | 展示真实打卡数据 | 先展示打卡工时，再按池展示手动工时 |

“混合工时”只描述工时来源。若同时存在异常打卡，考勤单元格的主标签固定为“混合工时”，紧邻主标签显示次级橙色标记“打卡异常”，避免异常被隐藏。

## 详情表格

表头保持：

`日期｜考勤｜班次｜工时｜上班时间｜下班时间｜分配前｜扣除｜分配获得｜实际获得｜分配状态`

展示规则：

- 仅手动工时时，“班次”“上班时间”“下班时间”显示 `—`。
- 手动工时按小费池分行展示为“池名称 + 工时”，不生成合计行。
- 混合工时时，工时单元格第一行显示“打卡工时”，后续按小费池分行展示手动工时。
- 多个手动工时记录按小费池展示名称、规则展示名称和稳定标识排序，保证页面及导出顺序一致。
- 同一池若存在多条规则，分别显示规则名称，避免把不同分配口径错误合并。
- 无名称的小费池与规则分别使用“未命名小费池”“未命名规则”，保证同池多规则不会出现空白行。

## 顶部统计

将当前“总工时”指标替换为“手动工时记录”：

`N 个小费池 / M 条记录`

- 小费池数量按当前日期范围与考勤状态筛选后的可见行，对不同 `poolId` 去重。
- 记录数统计当前日期范围与考勤状态筛选后的可见行中有效的 `manualHourEntries`。
- 不展示跨池手动工时总和。
- 其余班次和金额指标维持现有计算口径；班次只统计有效打卡会话。

## 筛选

考勤状态筛选包含：

- 全部状态
- 已打卡
- 未打卡
- 打卡异常
- 手动工时
- 混合工时

筛选状态与表格考勤标签使用同一个展示适配器。混合工时中存在打卡异常时，仍归入“混合工时”；异常信息作为附加标记保留，不让一条日期同时出现在两个互斥筛选结果中。

## 导出

PDF、CSV 和邮箱导出与当前筛选范围完全一致，并增加：

- `工时来源`：打卡工时、手动工时或混合工时。
- `工时`：与页面相同的分行内容。
- `手动工时明细`：池名称、规则名称和该规则使用的工时。
- `考勤备注`：放在“工时来源”之后；仅混合且存在异常打卡的日期输出“打卡异常”，其他日期留空。

每个日期的小费金额仍只导出一次。CSV 多值字段使用单元格内换行并进行标准转义；PDF 和邮件内容保留分行格式。

## 兼容与异常处理

- 历史记录没有 `manualHourEntries` 时，完全沿用现有打卡展示规则。
- 无效手动记录不参与池数、记录数和工时展示；页面不得因此改变金额。
- 手动工时为 `0` 是有效记录，保留展示，以反映该规则实际采用的输入。
- 名称缺失时使用定义的回退文案，稳定标识仍用于去重和排序。
- 同一日金额结果存在但工时来源缺失时，按历史数据处理，不推断或制造手动工时。

## 验收标准

1. 仅手动录入工时的日期显示“手动工时”，班次及上下班时间为 `—`。
2. 同日多个小费池的手动工时分别分行展示，不做合计。
3. 同日既有打卡又有手动工时时显示“混合工时”，并保留真实班次与上下班时间。
4. 混合日期存在异常打卡时，页面与导出均保留异常提示。
5. 顶部展示筛选范围内去重池数和手动工时记录数，不显示跨池工时合计。
6. 六个考勤筛选项均按同一适配器生效；切换到“手动工时”或“混合工时”后，顶部池数和记录数只统计当前可见行。
7. PDF、CSV、邮箱导出与页面顺序和筛选范围一致，并包含工时来源和按池明细。
8. 历史记录展示保持兼容，不虚构打卡时间或手动工时。
9. 金额、分配状态和既有小费计算结果在本功能中不被重新计算或修改。
10. 混合工时同时存在异常打卡时，页面固定展示“混合工时”主标签与“打卡异常”次级标记，导出在“工时来源”后一列输出“考勤备注：打卡异常”。
