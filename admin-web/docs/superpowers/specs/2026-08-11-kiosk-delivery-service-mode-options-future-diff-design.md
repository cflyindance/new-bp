# Kiosk 送餐取餐服务方式与未来版本红框 — 设计说明

> 日期：2026-08-11
> 范围：前厅管理中心 · 设置
> 状态：用户已确认，待独立规格评审

## 1. 背景

前厅设置 seq 489「送餐取餐服务方式」当前与 seq 488、490、491 共用“总开关 + Kiosk 产线勾选”交互，只能表达该功能是否启用，无法表达 Kiosk 具体支持哪一种服务方式。

本次将 seq 489 改造成无总开关的 Kiosk 服务方式多选配置，并把 seq 122「减菜后自动重定向」、seq 139「自动点完套餐」纳入现有未来版本差异功能标记体系。

## 2. 已确认需求

### 2.1 送餐取餐服务方式

- 仅支持 Kiosk 产线，不扩展至其他产线。
- 不展示总开关，进入设置页后直接展示配置项。
- Kiosk 可多选：
  - 柜台自取
  - 服务员送餐到桌
- 默认同时选中两种服务方式。
- 允许只保留任意一种服务方式。
- 不允许两项均未选中；尝试取消最后一项时保持原状态，并提示“请至少保留一种服务方式”。

### 2.2 红框标记

- seq 122「减菜后自动重定向」和 seq 139「自动点完套餐」加入现有未来版本差异设置清单。
- 未来版本中，两项设置行使用项目统一的红色 `outline` 标记。
- MVP 中隐藏这两项设置。
- 不新增常驻红框样式，不改变既有版本切换语义。

## 3. 方案选择

采用方案 A：将 seq 489 从现有 Kiosk 履约展示页共用逻辑中拆出，使用独立业务模块并复用项目现有“产线 × 选项”矩阵组件。

未采用的方案：

- 全面重构 seq 488–491 共用组件：会扩大对另外三个设置的影响面。
- 在主页面中直接写死两个复选框：存储、校验和后续维护会分散。

## 4. 页面与交互设计

### 4.1 场景视图

seq 489 设置行保留标题和功能说明，不渲染右侧总开关。标题下方直接展示一行矩阵：

| 产线 | 服务方式 |
|---|---|
| Kiosk | ☑ 柜台自取　☑ 服务员送餐到桌 |

复选框可独立切换。只剩一项时，继续取消该项不会改变数据，界面立即恢复勾选，并展示统一轻提示“请至少保留一种服务方式”。

### 4.2 按产线视图与搜索编辑

- seq 489 仍只属于 Kiosk 产线；其他产线不展示该设置。
- Kiosk 按产线视图使用同一个配置组件和同一份存储数据。
- Hub 设置搜索结果中的 seq 489 也渲染同一组件，不回退为布尔开关。
- 页面批量保存、草稿和离开确认遵循现有设置页机制；本模块只负责值的规范化、渲染、收集和写入。

### 4.3 可访问性

- 矩阵使用既有表格语义。
- 每个复选框提供包含产线和选项名称的可访问名称，例如“Kiosk 柜台自取”。
- 禁止取消最后一项时，不仅依赖颜色表达结果，同时提供文字提示。

## 5. 数据模型与迁移

### 5.1 新数据结构

使用 seq 489 独立 JSON 存储，结构为产线到服务方式数组的映射：

```json
{
  "kiosk": ["counter-pickup", "waiter-table-delivery"]
}
```

允许值固定为：

- `counter-pickup`：柜台自取
- `waiter-table-delivery`：服务员送餐到桌

### 5.2 规范化规则

读取和写入均执行以下规则：

1. 只保留 `kiosk` 产线。
2. 过滤未知服务方式。
3. 去重并按产品定义顺序存储。
4. 若缺少新数据、数据结构无效或规范化后为空，则回退为两项全选。
5. UI 交互层禁止产生空数组。

### 5.3 旧数据兼容

- 旧的 seq 489 总开关值和 `489-guest-kiosk-flow-page-lines` 不再决定新界面状态。
- 首次没有新结构数据时，一律初始化为两项全选，符合本次确认的默认规则。
- 不删除旧键，保留回滚能力，也避免本次改造产生破坏性数据清理。
- seq 488、490、491 继续使用原有总开关与 Kiosk 产线数据，不发生迁移。

## 6. 代码边界

### 6.1 seq 489 独立模块

新增独立的 Kiosk 服务方式配置模块，职责包括：

- 定义 Kiosk 产线、两个服务方式及稳定 ID。
- 读取、规范化和写入 seq 489 JSON 值。
- 复用 `module-settings-product-line-option-matrix-ui.ts` 渲染和收集矩阵。
- 绑定变更事件，拦截空选择并触发轻提示。
- 向页面渲染、保存和搜索编辑提供统一入口。

### 6.2 从旧共用模块拆分

- `module-settings-order-type-selection-page-ui.ts` 的共用 seq 集合只保留 488、490、491。
- `module-settings-toggle-ui.ts` 不再把 489 注册为总开关设置。
- `main.ts` 为 489 增加专用渲染和绑定分支，并确保分支优先于通用布尔设置。
- AI/表单可编辑能力登记中将 489 视为结构化配置，禁止被通用布尔开关逻辑覆盖。
- 产线范围仍为 Kiosk，不扩展现有前厅产线矩阵。

### 6.3 未来版本差异

- 在 `MVP_HIDDEN_MODULE_SETTING_SEQS` 中加入 122、139。
- 继续由现有 `isFutureVersionDiffModuleSettingSeq()`、`data-future-version-diff` 和统一 CSS 负责红框，不复制样式逻辑。
- 同步更新前厅设置基线、生成资料及专项校验中受 MVP 可见数量影响的预期；复杂版本总数不变。

## 7. 状态流转

1. 页面渲染 seq 489 时读取新 JSON。
2. 读取函数规范化数据；缺失或无效时返回两项全选。
3. 用户变更复选框后，矩阵收集当前 Kiosk 选择。
4. 若结果为空，拒绝写入、恢复最后一项并提示。
5. 若结果有效，进入现有页面草稿/保存链路。
6. 保存或刷新后继续从同一 JSON 还原。

## 8. 异常与边界处理

- `localStorage` 不可用：保持默认两项全选，界面仍可渲染，不抛出未捕获异常。
- 数据包含未知产线或未知选项：静默过滤。
- 数据为空、类型错误或 JSON 解析失败：回退两项全选。
- 快速连续点击导致短暂空选择：以最后一个合法值为准，不持久化空值。
- MVP/未来版本切换：122、139 立即按既有重渲染机制隐藏或显示红框；489 不受版本差异标记影响。
