# 自助餐规则列表筛选与表头设计

## 1. 目标

自助餐规则列表参照“菜单下单限制”的筛选、字段设置和表格交互方式，建立适合自助餐规则业务维度的列表能力。页面继续保留“整单限制”“每轮常用组合模板”“每轮原子规则”三个分组，不改变规则编辑、保存、校验、启禁用和发布逻辑。

## 2. 页面结构

### 2.1 顶部操作

- 页面标题：自助餐规则。
- 右侧主操作：新增规则。
- 结果数量：`筛选 X / 共 Y 条`。

### 2.2 筛选区

第一行展示常用筛选：

1. 规则搜索。
2. 门店。
3. 状态。
4. 限购主体。
5. 额度周期。
6. 限购对象。
7. 重置。

第二行展示：

- 高级筛选入口，展开“人数区间”和“生效时间”。
- 结果数量。
- 字段设置。

### 2.3 规则分组

保留以下顺序：

1. 整单限制。
2. 每轮常用组合模板。
3. 每轮原子规则。
4. 其他规则，仅存在自定义或无法归入前三组的规则时展示。

筛选只过滤分组中的规则，不改变规则原始排序。筛选后没有记录的分组自动隐藏；所有分组都为空时展示“暂无匹配规则”。

## 3. 筛选条件定义

### 3.1 规则搜索

- 搜索范围：规则名称、旧 KPOS 能力编号、旧 KPOS 能力名称。
- 使用包含匹配。
- 忽略输入首尾空格和英文大小写。
- 空输入不参与筛选。

### 3.2 门店

- 业务字段：生效门店，不使用参与门店。
- 默认值：全部门店。
- 门店目录来自新增共享资产 `dist/Configuration center/assets/order-limit-store-catalog.js`，导出 `window.OrderLimitStoreCatalog`，每项结构为 `{ id, name, mid, zone, address, order }`。
- 将 `order-limit-flow.js` 中现有门店目录迁移到该共享资产；规则列表和编辑流程共同读取它，不复制页面私有常量。
- 选项来源：全部规则实际引用的生效门店，按目录 `order` 升序展示。
- 规则引用但目录中不存在的门店 ID 追加在末尾，显示为 `未知门店（<ID>）`。
- 规则包含所选门店 ID 时命中。

### 3.3 状态

- 选项：全部状态、已启用、已禁用、草稿。
- `active` 映射为已启用。
- `disabled` 和历史值 `inactive` 统一映射为已禁用。
- `draft` 映射为草稿。

### 3.4 限购主体

- 选项：全部主体、按桌/订单、按人数。
- 分别匹配 `order`、`party_size`。

### 3.5 额度周期

- 选项：全部周期、整个订单、每轮、多轮。
- 分别匹配 `order_lifetime`、`per_round`、`multi_round`。
- 兼容 `enabledPeriods` 多值结构：只要规则包含所选周期即命中。

### 3.6 限购对象

- 选项：全部对象、菜品、分类、菜品集。
- 分别匹配 `dish`、`category`、`dish_set`。

### 3.7 高级筛选：人数区间

- 输入实际就餐人数，限定为大于等于 1 的整数。
- 规则任一有效人数区间包含输入值时命中。例如输入 `3`，可同时命中 `1–3人` 和 `3–5人`。
- “所有人数”规则命中任意合法人数。
- `subject=order` 视为所有人数，命中任意合法人数。
- `subject=party_size` 时，仅接受 `min`、`max` 均为整数、`min >= 1` 且 `max == null || max >= min` 的区间；单个无效区间跳过。
- `subject=party_size` 且不存在任何有效区间时，不命中具体人数筛选。
- `[{ min: 1, max: null }]` 归一化为“所有人数”。
- 非法值不执行筛选，并在输入框附近提示“请输入大于等于 1 的整数”。

### 3.8 高级筛选：生效时间

- 默认值：全部时间。
- 本筛选仅表示“营业时段”，不包含有效日期和活动周期；后二者通过可选列查看。
- 使用 `effectiveTimeKey` 匹配，`effectiveTimeLabel` 仅负责展示，避免文案调整破坏匹配。
- 新结构优先读取 `conditions.businessHourSlots`；缺失时依次回退 `businessHour`、`businessHourTimeMode`、`businessHourFrom`、`businessHourTo`。
- 若新旧字段均缺失，按编辑器现有归一化规则处理为 `dinner|full`，展示“晚市全时段”，不等同于全天。
- 仅保留 `all`、`lunch`、`dinner`，按此顺序排序、按 ID 去重；同时存在 `all` 和其他时段时只保留 `all`。
- `mode=full` 的稳定片段为 `<slotId>|full`；`mode=custom` 且起止时间完整时为 `<slotId>|custom|<from>|<to>`；无效自定义时间回退为 full。
- 多个时段的 key 使用 `;` 连接。label 使用“全天生效”“午市全时段”“晚市全时段”或“午市 11:30–14:30”等文案，并以 `；` 连接。
- 选项包含全部规则归一化后得到的稳定 key 和展示 label，按 key 精确匹配。

### 3.9 组合规则

- 所有非空条件之间使用“且”关系。
- 任一筛选条件变化后立即更新列表、分组显隐和结果数量。
- 筛选条件只影响当前展示，不修改规则数据。
- 筛选状态本期不持久化，重新进入页面恢复默认。
- 门店、时间等动态选项始终从全部规则生成，不随当前筛选结果收缩。
- 重置清空全部条件、收起高级筛选并恢复完整列表。

## 4. 默认表头

默认展示以下七列：

| 字段 | 展示定义 |
|---|---|
| 规则名称 | 名称和“系统默认”标识；点击名称进入查看 |
| 规则策略 | `限购主体 · 额度周期 · 限购对象 · 计量方式`；组合模板需体现“每轮总量＋对象限额” |
| 人数场景 | 所有人数或人数区间摘要，如 `1–3人、4人及以上` |
| 商品范围 | 如 `指定菜品 12 个`、`菜品集 8 个成员`、`分类 3 个`；无范围显示 `—` |
| 生效门店 | 一家显示门店名；多家显示“首家门店等 N 家”；无门店显示 `0 家` |
| 状态 | 已启用、已禁用、草稿 |
| 操作 | 编辑、复制、启用/禁用、删除；草稿按现有生命周期展示可用操作 |

规则名称固定在左侧；状态和操作固定在右侧。表格超出容器时在表格区域横向滚动。

## 5. 字段设置

### 5.1 固定字段

- 规则名称。
- 状态。
- 操作。

固定字段始终勾选且不可关闭。

### 5.2 默认字段

- 规则策略。
- 人数场景。
- 商品范围。
- 生效门店。

### 5.3 可选字段分组

**旧规则核对**

- 旧 KPOS 调研能力。
- 覆盖结果。

**规则类型**

- 限购主体。
- 额度周期。
- 限购对象。
- 计量方式。

**场景与数量**

- 人数区间。
- 轮次区间。
- 每轮总量。
- 对象限额。
- 相同菜品限额。

**商品配置**

- 参与门店。
- 适用产线。
- 目标商品数。
- 数量完成度。

**超限授权**

- 授权范围。
- 默认授权范围。
- 所需权限。
- 授权原因。

**生效范围**

- 有效日期。
- 活动周期。
- 营业时段。
- 会员范围。

**补充字段**

- 规则描述。

### 5.4 字段设置交互

- 点击“字段设置”打开浮层，按上述业务组展示复选框。
- 切换字段立即更新表头和表格，不刷新页面、不改变筛选条件。
- “恢复默认”恢复固定字段和默认字段。
- 字段偏好使用自助餐规则模块独立、带版本号的本地存储键，不与菜单下单限制共用。
- 加载偏好时剔除无效或已删除字段，并自动补回固定字段。
- 系统默认规则、普通规则和草稿共用同一套字段设置。

## 6. 数据归一化

- 规则数据按 `authoringConfig`、`authoringDraft`、`editorDraft` 的优先顺序读取可用配置，并形成只读列表视图。
- 筛选和表格展示不得回写配置对象。
- 字段为空时统一展示 `—`；选择具体筛选条件时，缺失对应字段的规则不命中。
- KPOS 能力从默认场景的 `legacyCapabilityIds` 映射到能力目录，供搜索和可选列使用。
- KPOS 能力映射仅适用于 `origin=system_default` 且 `defaultScenarioKey` 可识别的规则，不限制状态；草稿也可映射。先直接匹配 `profile.defaultScenarios`，再用 `profile.verifiedLegacyDefaultKey(rule)` 映射旧 key。普通自定义规则、无法识别的 key 或版本统一显示 `—`，且不命中 KPOS 能力搜索。
- 分组首先使用上述可识别默认场景模板的 `group`，系统默认草稿仍留在对应模板分组。
- 自定义规则按以下优先级推导：`defaultVariant` 以 `combo_` 开头进入“每轮常用组合模板”；全部有效周期均为 `order_lifetime` 进入“整单限制”；任一有效周期为 `per_round` 或 `multi_round` 进入“每轮原子规则”；无周期或存在未识别周期进入“其他规则”。限购对象为 `category` 不改变周期分组。
- 本地字段偏好 payload 固定为 `{ version: 1, visible: string[] }`。仅接受 `version === 1`；缺失、损坏或版本不匹配时恢复默认，再剔除无效字段并补回固定字段。

### 6.1 商品范围投影

- 列表统计门店范围优先使用 `deployStoreIds`；草稿没有生效门店时回退 `participatingStoreIds`。
- 每家门店独立统计，不跨门店相加或去重。
- 菜品按 `productLineId + dishId` 去重；分类按 `productLineId + categoryId` 去重；菜品集成员按 `productLineId + dishId` 去重。
- 单门店显示 `<对象名称> N 个`，例如“指定菜品 12 个”或“菜品集 8 个成员”。
- 多门店显示 `N 家 · 每店 min–max 个`；所有门店数量相同时显示 `N 家 · 每店 X 个`。
- 没有可统计门店或目标时显示 `—`。

### 6.2 数量字段投影

只统计启用周期中已启用的 block，并以“门店 × 周期 × 人数区间 × 轮次区间 × 对象”展开场景：

- 每轮总量：读取 `totalBounds`；组合模板读取 `tableTotalBounds`。单场景显示“最少 M / 最多 N”，未配置的一侧显示 `—`。
- 对象限额：读取 `targetLimits`；按整桌兜底的组合模板同时读取 `tableTargetCaps`。单值显示“最多 N 份/种”。
- 相同菜品限额：读取 `defaultDishLimits`，并包含 `exceptionDishLimits` 中已配置的例外商品额度。单值显示“最多 N 份”。
- 某 block 未启用显示 `—`；已启用但没有任何配置值显示“未配置”。
- 同一字段存在多个场景时：总量显示 `N 个场景 · 最少 min–max / 最多 min–max`；上限类显示 `N 个场景 · 上限 min–max`。这里 N 为已展开的场景单元格数，不是去重值数量。
- 额度值 `0` 是有效配置，必须参与最小值、最大值和完成度统计。

### 6.3 数量完成度

- 展示格式为 `已配置数 / 必填数`；必填数为 0 时显示 `—`。
- 统计门店范围与商品范围投影相同：优先生效门店，草稿回退参与门店。
- 对每个启用周期和场景，仅为启用 block 生成必填单元格。
- 总量 block 每个场景计 1 个必填单元格。组合模板只有最小值和最大值都已配置才算完成；普通原子规则任一边已配置即算完成，与现有 `v4QuantityCompletion` 一致。
- 对象 block：菜品/分类按每个目标计 1 个；菜品集按每个场景计 1 个。对应 `targetLimits` 已配置即完成；模板要求的整桌兜底使用 `tableTargetCaps` 对应单元格统计。
- 相同菜品 block 每个场景计 1 个；默认额度已配置，或该场景至少一个例外额度已配置，即算完成，与现有生命周期完成度一致。
- 没有目标但对象 block 已启用时，仍计 1 个未完成单元格，使列表能暴露缺失配置。

## 7. 状态与异常

- 无规则：展示“暂无自助餐规则”和新增入口。
- 有规则但无筛选结果：展示“暂无匹配规则”和重置筛选入口。
- 人数输入非法：保留当前完整列表，不应用非法条件并展示输入提示。
- 本地字段偏好损坏：忽略损坏值并恢复默认字段。
- 未识别状态或枚举：显示 `—`，并可通过“全部”条件查看。

## 8. 验收标准

1. 六个常用筛选、高级筛选、组合筛选和重置均正确工作。
2. 人数值能命中所有包含该人数的区间规则。
3. 结果数量、分组显隐和无结果状态正确。
4. 默认七列表头及内容符合定义。
5. 字段设置支持显示、隐藏、恢复默认和刷新后恢复偏好。
6. 固定字段不能隐藏，横向滚动时固定列仍可查看和操作。
7. 系统默认规则、普通规则和草稿均可正确归一化、筛选和展示。
8. `disabled`、`inactive` 等历史状态兼容正确。
9. 筛选和字段设置不修改规则配置，不影响编辑、复制、启禁用、删除和发布。
10. 自助餐规则字段偏好与菜单下单限制互不影响。

### 8.1 最小验收数据矩阵

实现测试至少包含以下夹具及明确断言：

- 状态：`active`、`disabled`、`inactive`、`draft`、未知状态；断言状态筛选与文案。
- 周期：单个 `order_lifetime`、单个 `per_round`、`multi_round`、多值周期、未知周期；断言筛选和分组。
- 人数：`1–3`、`3–5`、`4及以上`、`1及以上`、非法区间；断言边界值 3、4 的命中结果。
- 门店：单门店、多门店、目录缺失 ID；断言选项顺序、未知门店文案和列摘要。
- 时间：全天、午市全时段、多个时段、自定义时间、仅旧字段、全部字段缺失；断言 key、label 和筛选。
- 商品：多门店商品数相同和不同、跨产线重复 ID；断言按复合键去重和每店范围摘要。
- 数量：组合模板、原子规则、启用/禁用 block、0 值、部分配置和完全配置；断言三个数量摘要及完成度。
- 默认规则：正式、草稿、旧 key、未知 key、自定义规则；断言 KPOS 搜索、能力列和分组。
- 字段偏好：合法版本、损坏 JSON、版本不匹配、包含无效字段；断言恢复和固定字段补回。

## 9. 可视化确认

已通过可视化伴侣确认以下布局：常用筛选单行展示，高级筛选与结果数量/字段设置位于第二行；默认表头使用七列精简方案；规则分组继续保留。
