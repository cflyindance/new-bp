# 员工对账多班次打卡记录设计

## 目标

在员工对账明细中展示每天的上班、下班打卡时间，并正确支持同一员工一天内多次上班和下班的场景。每日小费金额继续按日期汇总，不因班次数量增加而重复展示或重复计算。

## 范围

本次调整覆盖：

- 员工对账逐日明细表。
- 考勤状态筛选。
- 员工对账明细的 CSV、PDF、打印回退和邮件导出内容。
- 原生演示考勤数据中的多打卡会话结构。

员工对账汇总列表、日期任务、小费池分配规则和金额计算不在本次调整范围内。

## 表格结构

员工对账明细表字段顺序为：

`日期｜考勤｜班次｜工时｜上班时间｜下班时间｜分配前｜扣除｜分配获得｜实际获得｜分配状态`

一天始终只展示一条主记录：

- 日期、考勤、班次、工时、小费金额及分配状态均按天展示。
- “上班时间”和“下班时间”单元格允许多行。
- 同一行位置代表同一个打卡会话；例如上班时间第二行必须对应下班时间第二行。
- 打卡会话按上班时间升序排列。

## 打卡会话模型

逐日考勤记录增加 `punchSessions`：

```text
punchSessions:
  - clockIn: "09:02"
    clockOut: "14:10"
    durationHours: 5.13
    status: "complete"
  - clockIn: "17:01"
    clockOut: "21:13"
    durationHours: 4.20
    status: "complete"
```

字段规则：

- `clockIn` 为 `HH:mm` 格式的上班时间。
- `clockOut` 为 `HH:mm` 或 `null`；`null` 表示缺少下班卡。
- `durationHours` 只在完整会话中计入有效工时。
- `status` 当前只需要 `complete` 和 `missing-clock-out`。
- 当 `punchSessions` 字段存在时，它是考勤展示、班次数量、工时合计和考勤筛选状态的权威来源。
- 一个会话只有在 `status` 为 `complete`、`clockIn` 与 `clockOut` 均存在且 `durationHours` 是非负有限数时才算完整；任一条件不满足即按异常会话处理并排除在班次、工时之外。
- 考勤数据生成层必须把现有顶层 `hours` 同步设置为所有完整会话 `durationHours` 的合计，使现有下游小费计算接口保持不变。展示层不反向写入或修正已保存的小费结果。
- 若新格式记录的顶层 `hours` 与会话合计不一致，页面班次、工时、状态和导出以会话计算结果为准，金额仍使用既有逐日小费结果，不触发重新分配。
- 会话按 `clockIn` 升序排列；上班时间相同时保持原始数组顺序，确保页面与导出结果稳定一致。

## 状态规则

### 已打卡

- 至少存在一个完整打卡会话。
- 不存在任何不完整会话。
- 班次等于完整会话数量。
- 工时等于完整会话工时合计。

### 未打卡

- 不存在任何打卡会话。
- 班次显示 `—`。
- 工时显示 `0 h`。
- 上班时间、下班时间均显示 `—`。

### 打卡异常

- 存在至少一个不满足完整会话校验条件的会话，包括 `missing-clock-out`、缺少 `clockIn`、缺少 `clockOut`、`durationHours` 缺失、非有限值或负数，以及未知 `status`。
- 不论是否同时存在完整会话，当日状态均显示“打卡异常”。
- 异常会话的下班时间显示 `—`。
- 异常会话缺少上班时间时，上班时间同样显示 `—`，保证上下班时间多行始终一一对齐。
- 异常会话不计入班次数量和有效工时。
- 已存在的上班时间必须保留展示。

## 筛选

考勤状态筛选项调整为：

`全部状态｜已打卡｜未打卡｜打卡异常`

筛选依据为每天最终计算出的考勤状态。日期范围筛选与状态筛选继续叠加生效。

## 导出

员工对账明细 CSV、PDF、打印回退和邮件生成内容增加“上班时间”“下班时间”字段，顺序与页面一致。

- 多个时间在同一字段内按会话顺序展示。
- CSV 中统一使用 `\n` 连接多个时间，并保持字段正确转义。
- PDF、打印和邮件 HTML 中使用分行展示。
- 缺失下班时间导出为 `—`。
- 每日金额只输出一次，不为每个班次复制金额行。

## 兼容与边界

- 如果旧逐日记录没有 `punchSessions`，不得伪造上班或下班时间，按以下规则只读兼容：
  - `clockStatus` 为“已打卡”且 `hours > 0`：状态保持“已打卡”，班次显示 `1 个班次`，工时使用旧 `hours`，上下班时间均显示 `—`。
  - `clockStatus` 为“已打卡”但 `hours <= 0`：状态显示“打卡异常”，班次显示 `—`，工时显示 `0 h`，上下班时间均显示 `—`。
  - `clockStatus` 为“未打卡”或其他未知值：按“未打卡”处理，班次显示 `—`，工时显示 `0 h`，上下班时间均显示 `—`。
- 不修改已保存的小费分配结果，不触发重新分配。
- 不新增打卡编辑能力；员工对账明细保持只读。
- 跨午夜会话不在本次演示数据范围内；展示层不得通过比较上班和下班的时钟先后来判断完整性，而应统一使用打卡会话模型规定的完整校验条件。

## 验收标准

1. 单班次日期正确展示一组上班、下班时间。
2. 多班次日期在同一日期行内按顺序展示多组时间，且上下班时间逐行对应。
3. 多班次日期只展示一次每日小费金额。
4. 无打卡日期显示“未打卡”、班次 `—`、工时 `0 h`、时间 `—`。
5. 缺少下班卡的日期显示“打卡异常”，下班时间 `—`，异常会话不计入班次和工时。
6. 同时存在完整和异常会话时状态仍为“打卡异常”，完整会话正常计入班次和工时。
7. “打卡异常”筛选只展示异常日期。
8. CSV、PDF、打印回退和邮件内容与页面字段顺序及数据一致。
9. 现有日期筛选、金额、分配状态、返回和导出入口行为保持不变。
10. 缺少上班时间、`durationHours` 非有限值或负数的会话均显示为“打卡异常”，且不计入班次和工时。
