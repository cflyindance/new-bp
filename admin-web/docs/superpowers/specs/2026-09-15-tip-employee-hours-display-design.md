# TipOut 员工工时双口径展示设计

## 状态

已确认。

## 背景与目标

员工分配汇总和员工每日小费当前同时展示班次、工时及上下班时间，信息密度较高，却无法直接辨别考勤原始工时与小费分配实际采用工时。目标是在两个页面统一展示“打卡工时”和“分配工时”，支持核对人工调整前后口径，同时移除不再需要的班次与打卡时间字段。

## 范围

### 员工分配汇总

- 删除“班次”列。
- 将原“工时”拆为“打卡工时”和“分配工时”两列。
- 打卡工时累计当前门店、日期范围及筛选条件内的有效原始打卡工时。
- 分配工时按“小费池 + 规则”分别累计并分行展示，例如“前厅池 · 服务员规则 32 h / 酒吧池 · 酒保规则 18 h”；不同池或规则的工时不得相加为一个数值。
- 原“工时”排序入口改为“打卡工时”排序；分配工时因可能存在多池口径，不提供排序。

### 员工每日小费

- 删除“班次”“上班时间”“下班时间”列。
- 新增“打卡工时”和“分配工时”两列，按日期展示当天口径。
- 同步调整 CSV、PDF 与邮件导出字段，确保导出和页面一致。

### 不在范围内

- 不改变考勤状态判定、打卡记录本身或小费分配公式。
- 不删除底层班次及上下班时间数据；仅从本期两个展示与导出视图移除。
- 不增加工时差值、已调整徽标、悬浮说明或编辑入口。

## 字段定义

| 字段 | 定义 | 数据来源 | 无数据展示 |
| --- | --- | --- | --- |
| 打卡工时 | 考勤系统基于有效打卡记录计算的原始工时，不受小费明细人工调整影响 | 当日原始考勤汇总 | `—` |
| 分配工时 | 各小费池规则在按工时分配时实际采用的最终有效工时，可能等于打卡工时，也可能经过封顶或来自人工修改、不打卡规则的手工录入 | 小费分配草稿或确认快照中按 `poolId + ruleId` 记录的有效工时 | `—` |

所有有效数值最多保留两位小数并带 `h`。无有效打卡记录时，“打卡工时”必须显示 `—`，不得用 `0 h` 或手工录入工时替代。

## 展示与交互

- 两个工时字段独立成列，顺序为“打卡工时”“分配工时”。
- 分配工时按 `poolId + ruleId` 分行展示，显示标签为“小费池名称 · 规则名称”。页面不得把同池多规则或跨池工时求和，也不得任选一条规则值。
- 每条规则的分配工时与当天打卡工时按规范化业务值比较；不一致时仅高亮该行“分配工时”，一致时使用普通样式。
- 高亮只表达“分配采用值与打卡原值不同”，不表达异常、错误或待处理。
- 不打卡规则或没有有效打卡记录时，“打卡工时”为 `—`；只要存在合法手工工时，“分配工时”正常展示。
- 待分配状态可以展示两个工时，但扣除、分配获得和实际获得继续显示 `—`。

## 数据流与状态

1. 页面先读取员工在当前门店和日期下的原始考勤汇总，生成打卡工时。
2. 页面按 `poolId + ruleId` 读取小费分配实际采用的有效工时，生成一条或多条分配工时。
3. 按工时分配且没有封顶或人工修改时，打卡规则的分配工时等于有效打卡工时；存在封顶时展示封顶后实际采用值，存在人工修改时展示修改值。
4. 平均分配、按订单等不使用工时的规则，其分配工时显示 `—`，不参与分配工时汇总、缺失判定或高亮。
5. 小费分配明细修改工时后，只更新对应 `poolId + ruleId` 的分配工时，不修改原始打卡工时。
6. 未分配时读取实时考勤与当前草稿；确认分配时把当时的打卡工时和各规则分配工时一并写入确认快照。
7. 已分配后两个字段均读取确认快照，后续考勤修正不回写旧快照；重新确认分配时用当前考勤和草稿生成新快照。
8. 确认已发放后继续读取锁定快照中的两个工时，并维持现有写保护。
9. 历史快照缺少新字段时，优先从同一快照内的考勤和规则工时数据重建；无法从快照自洽重建时显示 `—`，不得混用当前实时考勤伪造历史值。
10. 明细工时变化后，员工每日小费和员工分配汇总使用现有跨页面同步机制刷新。

### 状态与数据源矩阵

| 分配/发放状态 | 打卡工时来源 | 分配工时来源 | 后续考勤变化 |
| --- | --- | --- | --- |
| 待分配 | 当前有效考勤 | 当前草稿，按 `poolId + ruleId` | 页面刷新后反映最新考勤 |
| 已分配、待发放 | 最近一次确认快照 | 最近一次确认快照，按 `poolId + ruleId` | 不改变已确认展示；重新确认后更新 |
| 存在未确认更新 | 员工汇总、员工每日小费及其导出均展示当前草稿所对应的当前考勤 | 员工汇总、员工每日小费及其导出均展示当前草稿规则工时 | 旧确认金额与发放保护仍按既有状态规则处理；工时列用于核对待重新确认的草稿 |
| 已发放 | 已发放锁定快照 | 已发放锁定快照，按 `poolId + ruleId` | 不改变锁定展示，不允许重新确认 |

## 异常与边界

- 打卡异常但仍存在可确认的有效工时：保留考勤异常状态，并展示可确认的打卡工时。
- 完全没有有效打卡记录：打卡工时显示 `—`。
- 分配工时缺失、负数、非数值或不可确认：显示 `—`，不得回填或覆盖打卡工时。
- 合法 `0` 显示 `0 h`；缺失或非法值显示 `—`，两者不得混淆。
- 工时先按业务精度四舍五入到两位小数，再用于展示和高亮比较，避免浮点误差造成误高亮。
- 已发放状态下只读展示；本功能不得绕过既有快照锁定。

### 缺失值与高亮矩阵

| 打卡工时 | 某池规则的分配工时 | 分配工时高亮 |
| --- | --- | --- |
| 有效值 | 相同有效值 | 否 |
| 有效值 | 不同有效值 | 是 |
| `—` | 有效值（含 `0 h`） | 是 |
| 有效值（含 `0 h`） | `—` | 否；分配值按缺失样式展示，是否允许确认继续沿用既有分配校验，本功能不新增拦截 |
| `—` | `—` | 否 |

### 汇总、排序与导出

- 打卡工时汇总只累计有效打卡值。`Y` 为当前筛选范围内该员工存在每日记录的日期数，`X` 为其中具有有效打卡工时的日期数；部分缺失时显示“`N h（X/Y 天有记录）`”，全部缺失时显示 `—`，无障碍文案为“该员工在所选 Y 个记录日均无有效打卡工时”。
- 分配工时按 `poolId + ruleId` 分别累计有效值。每条规则的 `Y` 为当前筛选范围内员工实际参与该规则且该规则按工时分配的日期数，`X` 为其中具有有效分配工时的日期数；部分缺失时显示“`池名 · 规则名 N h（X/Y 天有记录）`”，全部缺失时显示“`池名 · 规则名 —`”。不同池或规则不得相加。
- 非工时分配规则显示 `—`，不计算或展示 `X/Y`。
- `X/Y 天有记录` 仅用于员工分配汇总及该汇总的 CSV、PDF、邮件导出；员工每日小费及其导出只展示当天值，不显示 `1/1 天有记录`。
- 汇总页面可视文本、无障碍文本和对应导出均保留 `X/Y 天有记录`，不使用仅靠颜色表达的数据完整性标记。
- 打卡工时升降序中，`—` 始终排在所有有效值之后；相同值按员工姓名稳定升序。分配工时不提供排序。
- 员工分配汇总及员工每日小费的 CSV、PDF、邮件导出均使用当前页面筛选范围和同一数据映射。
- 两类导出均删除班次、上班时间、下班时间和旧单一“工时”字段，按顺序输出“打卡工时”“分配工时”。
- 分配工时导出为按 `poolId + ruleId` 分行的文本值；CSV 使用单元格内换行，PDF/邮件使用多行显示。纯文本导出无法承载颜色时，通过保留独立两列和“池名 · 规则名”表达差异。
- 既有“工时来源”“考勤备注”“手动工时明细”继续保留；它们解释来源和异常，不被两个数值字段替代。

### 分配工时身份与命名

- 聚合主键固定为 `poolId + ruleId`，名称仅用于展示，不参与归组。
- 展示名称取筛选范围内日期最新的一条草稿或确认快照所保存的池名称和规则名称；名称只影响展示，不改变合并结果。
- 同名不同池或同池同名规则通过稳定 ID 保持独立；页面重名时追加短标识，例如“前厅池 · 服务员规则（P02/R03）”。
- 跨日期汇总中同一稳定 ID 曾改名时仍合并为一行，并采用筛选范围内最新日期对应的名称；导出与页面使用同一名称。
- 行排序依次按池名称、规则名称、`poolId`、`ruleId` 升序，确保页面和导出稳定一致。

## 验收标准

- 员工分配汇总不再展示班次，并按顺序展示打卡工时、分配工时。
- 员工每日小费不再展示班次、上班时间和下班时间，并展示两个工时字段。
- 打卡 5 小时、明细修改为 6 小时时，页面分别显示 `5 h` 与高亮的 `6 h`。
- 无有效打卡、手工录入 4 小时时，页面分别显示 `—` 与 `4 h`。
- 同一天参与两个小费池且分别采用 6 小时、4 小时时，分配工时分行显示“池名 · 规则名”及其数值；汇总按 `poolId + ruleId` 分别累计，不输出 10 小时总计。
- 同一小费池下两条规则采用不同工时时，两条规则分别成行，不求和、不任选；非工时分配规则显示 `—` 且不高亮。
- 封顶规则未人工修改但实际采用值小于打卡工时时，展示并高亮封顶后的分配工时。
- 两个工时相同时不高亮；仅分配工时不同才高亮。
- 合法 `0 h`、缺失 `—` 及各种组合符合缺失值与高亮矩阵。
- 日期范围内部分日期缺失时，页面和所有导出显示 `X/Y 天有记录`；全部缺失显示 `—`；排序符合规则且日期和角色/员工筛选仍正确生效。
- CSV、PDF 和邮件导出不含班次与上下班时间，并包含打卡工时、分配工时。
- 待分配时修改工时后，员工每日小费、员工汇总和三类导出只更新对应 `poolId + ruleId` 的分配工时，打卡工时保持不变。
- 确认分配后两个工时来自同一确认快照；考勤随后变化不改变旧结果，重新确认后才生成并展示新快照值。
- 已发放后两个工时继续读取锁定快照，修改入口保持不可用。
- 日期排序、考勤筛选、分配状态筛选、金额计算、确认分配及发放锁定回归通过。

## 实现边界

- 应在考勤汇总层明确输出原始打卡工时，在员工分配数据层明确输出实际采用工时，避免 UI 从展示字符串反推数值。
- 员工汇总聚合同时累计两个数值；不得继续用单一 `hours` 同时承载两种口径。
- 页面与导出共享同一行数据映射，避免字段口径漂移。
