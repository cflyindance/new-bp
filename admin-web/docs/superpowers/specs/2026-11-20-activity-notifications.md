# 异常门店通知设计

日期：2026-11-20。变更：ACTIVITY-NOTIFICATION-20261120-01。用户已采纳本轮方案；本轮实现本地演示，不调用真实邮件，不启动系统级定时任务，不提交或推送。

## 范围与入口

系统使用分析新增「异常跟进」，包含异常清单、负责人配置、通知设置、发送记录四个视角。门店异常先做；产线、设备仍通过原分析页排查，不独立触发邮件。页面匹配项目现有列表、弹框和 Token。异常清单行查看门店使用统计，跟进操作使用原生 modal dialog。

## 数据与负责人

复用管理资料映射后的门店身份及既有演示订单，按最后完整自然日计算，统一 Asia/Shanghai。数据完整性错误不推断停用，进入运营排查；从未有单的门店归为待启用，第一期不发送停用邮件。物理设备、License 和原页面统计不变。测试用独立10店数据验证 A6/B4/C10 分组，不伪造线上客户。

人员候选取当前内部员工账号的 ID、姓名、邮箱、启用状态，不复制凭据。品牌默认销售与客户经理；门店销售、客户经理各自独立选择继承、指定人员或无人负责；一个主销售、一名客户经理协同。配置不授予商户访问权限。固定抄送、长期风险主管、异常兜底运营由设置选择。停用、无效邮箱、无该门店访问范围的收件人均不接收门店明细，作为待处理项展示；兜底人也必须具有对应访问范围。按规范化邮箱去重并汇总角色，每人一封且每店一行。发信预览和提交均重新校验账号、归属、权限、数据及版本。

## 异常与通知

门店过去曾使用，最后订单距截止日7～13天、14～29天、至少30天为三级；恢复时退出异常，但保留跟进及通知历史。暂停仅抑制通知，不消除异常；暂停到期日当天仍暂停，下一日恢复。数据错误抑制客户使用提醒，不冒充0单。

默认每日09:00汇总，角色为销售和客户经理，重复间隔7天，长期风险增加主管。首次命中、级别升级立即纳入下一批；未跟进持续异常间隔7天再次纳入；已有跟进只在级别升级时再提醒。负责人变更优先于跟进抑制，当前异常向新负责人发送一次，再执行普通跟进规则。每位收件人的通知成功独立去重，部分失败仅重试失败项；新负责人不继承旧负责人的已通知状态。

暂停期间抑制全部该店邮件（含升级、恢复），保留异常及跟进变化，不累计逐日提醒。到期或手动解除后，下一批仅按当前状态补发一次：仍异常则发当前等级；已恢复则仅向本异常周期内至少一次模拟发送成功且仍有访问权限的收件人发一次恢复摘要。仅预览、始终失败和从未通知的人不收到恢复邮件。补发成功再标记解除暂停已处理；失败可重试。历史异常恢复后再次发生，按新的异常周期处理。

未暂停门店恢复后，在下一批向本异常周期内至少一次模拟发送成功、且仍有访问权限的收件人发送一次恢复摘要；成功后去重，失败可重试。恢复事件不能由人工跟进状态代替，也不能由数据异常或数据缺失推断。

每批仅处理当前操作者有权访问且预览中列明的门店；模拟成功及去重只更新实际发出的收件人—门店—异常周期，不扩展到该收件人的其他门店。历史成功记录不改变，后续负责人或访问范围变更不会隐式补授权限。

本地演示由「检查异常」刷新、按钮触发模拟发送；设置的定时仅表达生产配置，页面明确未接调度。无真实 SMTP，不出现已送达或已读。发送结果为模拟成功/模拟失败；模拟失败可重试。预览展示成功候选、阻断项、角色和门店，每个收件人独立汇总，标记主送/协同/抄送/主管/兜底。

## 跟进、交互与安全

异常状态与跟进状态分别保存。跟进状态待跟进、跟进中、已联系，跟进备注必填1～500字；暂停日期和理由同时填写，日期需晚于当前日，暂停可以取消。记录时间、操作人和历史。刷新/重开保留本地演示配置；保存失败保留草稿，写入前对比 revision，阻止多窗口覆盖。未知/损坏存储明确报错，不重置。弹框关闭、遮罩、Esc一致，有更改时确认放弃，焦点限制于dialog并关闭回到触发点。

新页面独立授权：浏览、跟进、负责人配置、通知配置、发送分别控制；不继承已有分析页的写权限，不自动给普通角色新授权。仅初始系统管理员补全新增资源，保留显式隐藏。当前操作者可访问的门店才参与清单、统计、配置、预览、记录；收件人另检查商户范围。原分析菜单/深链及抽屉回归。
