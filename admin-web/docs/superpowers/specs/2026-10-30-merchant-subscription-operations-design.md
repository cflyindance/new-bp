# 商家订阅状态驱动操作设计

## 背景与目标

商家订阅当前主要支持续期与停用，缺少待生效编辑、撤销、立即生效、重新开通、详情与操作记录等完整生命周期操作。设计目标是参照服务包管理的生命周期思路，为品牌／门店订阅提供状态驱动操作，同时保护成交快照、权益计算与审计历史。

## 已确认原则

- 不提供订阅物理删除；“删除”统一设计为“撤销待生效订阅”，记录永久保留。
- 只有尚未生效且从未产生权益的订阅可以撤销。
- 待生效订阅可编辑主体、服务包、生效／到期时间、成交信息与备注。
- 生效中订阅不得修改主体、服务包、生效时间和成交价快照，只能续期、调整未来到期时间或停用。
- 已到期、已停用、已作废记录只读；重新开通会创建新记录，不恢复或覆盖旧记录。
- 商业权益订阅继续由品牌服务权益页办理，普通订阅列表不提供重复写入口。

## 状态与操作矩阵

| 状态 | 主操作 | 更多操作 |
| --- | --- | --- |
| 待生效 | 编辑 | 立即生效、撤销、查看详情、操作记录 |
| 生效中 | 续期 | 调整到期时间、停用、查看详情、操作记录 |
| 已到期 | 重新开通 | 查看详情、操作记录 |
| 已停用 | 重新开通 | 查看详情、操作记录 |
| 已作废 | 重新开通 | 查看详情、操作记录；旧记录本身永久只读 |

不可执行的高风险操作隐藏；因服务包状态、权限或数据缺失而暂时不可执行的操作保留禁用态，并显示具体原因。列表采用“主操作 + 更多”布局，主体和服务包现有查看入口保持不变。

订阅生命周期状态与服务包状态是两个维度。生命周期状态为已作废、已停用、待生效、已到期、生效中；服务包附加状态为运行中、已下架、已停用、未发布或缺失。列表主状态展示订阅生命周期，服务包异常作为附加标签和操作限制：

| 订阅状态 | 运行中 | 已下架 | 已停用／未发布 | 服务包缺失 |
| --- | --- | --- | --- | --- |
| 待生效 | 编辑、立即生效、撤销 | 受限编辑、撤销；立即生效禁用。受限编辑只允许修改到期时间和备注，主体、服务包、原开始时间及成交快照锁定；到达原开始时间后仍按既有承诺自动生效 | 编辑时必须改选可用服务包，或撤销；不能立即生效 | 仅撤销、查看 |
| 生效中 | 续期、调整到期、停用 | 继续提供能力；允许停用，续期禁用 | 暂停提供能力；仅查看，不能停用订阅 | 仅查看 |
| 已到期／已停用／已作废 | 可重新开通 | 重新开通禁用 | 重新开通禁用 | 重新开通禁用 |

待生效记录不用“停用”，只能撤销；已下架不退出已有有效订阅的路由计算。

## 状态流转

```text
创建
├─ 生效时间 > 当前时间 → 待生效
│  ├─ 编辑 → 待生效
│  ├─ 立即生效 → 生效中
│  ├─ 到达生效时间 → 生效中
│  └─ 撤销 → 已作废
└─ 生效时间 ≤ 当前时间 → 生效中
   ├─ 续期／调整到期时间 → 生效中
   ├─ 到达结束时间 → 已到期
   └─ 停用 → 已停用

已到期／已停用／已作废
└─ 重新开通 → 新建待生效或生效中记录
```

服务包下架时已有有效订阅继续生效，但不能新增或续期。服务包停用时关联订阅暂停提供能力，订阅自身状态不改为已停用；服务包恢复后，仍在有效期内且未停用／撤销的订阅重新参与能力计算。

## 操作定义与影响提示

### 查看详情

右侧抽屉展示主体、服务包及开通版本、菜单能力、开通方式、成交价、有效期、状态、备注、创建／最近操作信息及停用／撤销原因。无数据变更，不需要二次确认。

### 编辑待生效订阅

运行中的服务包允许修改主体、服务包、生效时间、到期时间、成交价及依据和备注。服务包已下架时按既有承诺受限编辑，只允许修改到期时间和备注，主体、服务包、原开始时间及成交快照锁定；若要更换服务包，应撤销旧记录并新增，不能借编辑改写原承诺。服务包已停用或未发布时，保存前必须改选运行中且已上架的服务包。保存前展示逐字段前后对比，并校验主体存在、服务包可开通、时间有效和订阅不重叠。提示明确“不会立即改变当前能力，将在约定时间生效”。

### 立即生效

将开始时间更新为当前时间。确认弹框展示直接主体、品牌继承门店数、新增菜单数及被其他订阅重复覆盖的菜单数。提交前重新校验重叠与服务包状态。

### 续期与调整到期时间

续期只允许延长结束时间，不修改主体、服务包、成交价与发布版本快照。新时间必须晚于原结束时间和当前时间。缩短到期时间使用“调整到期时间”，有原结束时间时必须满足 `当前时间 < 新结束时间 < 原结束时间`；长期订阅必须满足旧结束时间为空且 `新结束时间 > 当前时间`，首次设置结束时间视为缩短，仍需提前结束权限、trim 后 1 至 200 字原因、影响预览与审计。需要立即终止时使用停用。

### 停用

立即退出权益计算，必须填写不超过 200 字的原因。影响预览展示直接主体、继承门店数、该订阅提供的菜单数、实际失去的菜单数及仍由其他订阅覆盖的菜单数。记录永久保留且不直接恢复。

### 撤销

仅待生效且从未产生权益的订阅可执行。撤销原因 trim 后必须为 1 至 200 字；设置作废标记、操作者、时间与原因，不删除记录。提示明确当前能力不减少，但原定未来能力不会生效。

### 重新开通

从已到期、已停用或已作废记录打开新增流程，预填原主体、服务包、成交价依据和备注；不复制原时间、停用／撤销原因及操作日志。提交后创建新 ID。

## 影响预览模型

所有高风险操作使用统一影响摘要。先构造影响上下文集合：门店订阅为目标门店一个上下文；品牌订阅为品牌上下文加该品牌当前全部门店上下文。以下菜单计数均为“上下文—菜单关联数”求和，同一路由在品牌和三家门店出现时计 4，不做跨主体去重：

- `directSubjectCount`：直接主体数，本期固定为 1。
- `inheritedStoreCount`：品牌订阅向下覆盖的门店数；门店订阅为 0。
- `providedRouteCount`：对每个影响上下文，目标订阅可提供路由集合大小之和。
- `lostRouteCount`：对每个上下文计算 `操作前有效路由 - 操作后有效路由`，再求集合大小之和。
- `retainedRouteCount`：对每个上下文计算 `目标订阅提供路由 ∩ 操作后仍有效路由`，再求集合大小之和。
- `gainedRouteCount`：立即生效时，对每个上下文计算 `操作后有效路由 - 操作前有效路由` 并求和。
- `alreadyCoveredRouteCount`：立即生效时，对每个上下文计算 `目标订阅提供路由 ∩ 操作前有效路由` 并求和。

示例：品牌有 2 家门店，目标服务提供 A、B；操作前品牌和门店 1 均由其他订阅覆盖 A，门店 2 无覆盖。立即生效后 `providedRouteCount=6`、`gainedRouteCount=4`（品牌 B、门店 1 B、门店 2 A/B）、`alreadyCoveredRouteCount=2`（品牌 A、门店 1 A）。停用该订阅且其他来源不变时，`lostRouteCount=4`、`retainedRouteCount=2`。

## 并发、权限与审计

影响预览生成确定性快照哈希，覆盖目标订阅全部字段及派生状态、服务包状态与当前发布版本和路由、影响上下文中的其他订阅及其版本字段、品牌—门店归属集合。预览记录 `previewedAt`、影响集合中最近一次订阅开始／结束边界 `nextBoundaryAt`，有效期为 `min(previewedAt + 5 分钟, nextBoundaryAt)`；没有后续边界时只取五分钟。提交时按当前时间重新计算全部相关订阅的派生状态和影响摘要，并与预览逐字段比对。任何依赖变化、跨状态、摘要变化或过期均拒绝并提示“订阅信息或状态已发生变化，请关闭弹窗后重新查看影响”。

权限拆分为查看、新增、编辑待生效、立即生效、续期、提前结束、停用、撤销和查看操作记录。重新开通复用“查看 + 新增”两个权限；缺少任一权限时 UI 不显示入口，存储层直接调用同样拒绝。UI 隐藏不替代存储层校验。

审计事件至少包括 `subscription.update_scheduled`、`subscription.activate_now`、`subscription.extend`、`subscription.adjust_end`、`subscription.disable`、`subscription.cancel` 和 `subscription.reopen`。记录操作前后值、影响摘要、原因、操作者和时间。

## 异常与原子性

- 主体不存在：历史记录显示原 ID，只允许查看，不能编辑或重新开通。
- 服务包不存在：显示未知服务包，仅允许查看。
- 时间重叠：编辑、立即生效、续期和重新开通均阻止提交。
- 权限在弹框打开后变化：提交仍由存储层拒绝。
- 重复点击：提交期间禁用按钮。
- 订阅写入、审计写入和能力刷新必须使用同一快照原子落库，不允许半成功。

## 页面与验证

- 详情与操作记录使用右侧抽屉；编辑使用大尺寸抽屉；影响确认使用居中弹框。
- 验证各状态只显示规定操作，作废记录不被物理删除，生效记录核心字段不可编辑。
- 验证品牌继承门店影响、其他订阅覆盖、服务包下架／停用差异、并发令牌、权限和审计。
- 验证普通订阅与商业权益订阅写入口互斥。
