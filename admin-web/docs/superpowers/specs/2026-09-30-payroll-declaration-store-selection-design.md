# 声明语言模板：指定门店

## 已确认范围

在现有员工声明设置中支持为不同门店维护不同声明。沿用企业通用模板，新增模板可绑定单个指定门店，不提供多门店批量绑定。不改变薪资计算、声明语言偏好、已确认快照与打印规则。

## 页面交互

- 新增语言模板的“模板范围”提供“企业通用／指定门店”，默认企业通用。
- 选择指定门店时显示必填门店选择框，默认当前门店；当前为全部门店时要求主动选择。
- 展示补充：适用门店字段始终可见，企业通用时只读显示“全部门店”，指定门店时可选择。列表按后续确认的五列表格设计，在独立“门店”列显示“全部门店／具体门店名称”，不再仅通过范围副标题暗示归属。
- 门店选项来自当前企业下账号可访问的门店列表，排除“全部门店”等非具体门店项。没有可选门店时禁止保存门店模板并提示原因。
- 切换范围或门店时保留已输入的语言名称、语言代码及正文，不切换薪资主页面的门店。
- 已有模板详情准确回显企业通用或具体门店，范围和门店只读；需要不同归属时另建模板。
- 列表展示具体门店名称而非笼统“门店模板”；企业模板展示“企业通用”。同一语言在不同门店的模板独立保存、审核、发布。

## 数据与隔离

- 复用现有 family.scope.organizationId 和可选 storeId；企业通用不传 storeId。
- 保存时必须使用所选门店，而不是页面原门店。对应仓库请求上下文也应使用目标门店，避免浏览器仓库的范围校验拒绝请求。
- 模板管理列表聚合当前企业通用及账号可访问门店的模板，以 familyId/versionId 去重，使刚创建的其他门店模板仍可见。编辑、发布、停用均按模板自身范围选择仓库。
- 聚合请求有失败时提示未加载的门店，不宣称完整加载；不得将旧企业的结果合并进当前企业。页面重开或企业/权限范围变化时刷新上下文，清理旧仓库缓存；过期异步响应不覆盖新上下文。
- 单店账号仅可选择本店；演示模式同样遵循可访问门店列表。正式服务端仍须验证真实账号权限，前端列表和请求头不能代替服务端授权。
- 员工默认声明语言下拉框只列本门店及企业通用的已发布模板，不引入跨门店聚合结果。同语言的企业/门店模板显示范围以便区分。
- 保留现有显式选择 familyId 的优先级；本次不改为新门店模板自动覆盖员工已选的企业模板。系统默认语言仍沿用现有内置声明。
- 已确认声明使用原快照，不因新增、修改、停用或切换门店而重算。

## 错误与保存

无效或无权限门店不得保存，也不得降级成企业通用模板。请求失败保留表单输入并展示错误，允许重试；保存/发布期间禁用重复提交。沿用先保存草稿、再审核发布的流程。

## 实现边界

主要涉及声明设置控制器、目标范围仓库选择与对应测试；不拓展通用权限系统、不修改员工薪资算法，不迁移既有模板。本补充优先细化 2026-09-29 多语言声明设计中的指定门店交互。

## 验收

1. 企业通用模板保存后无 storeId，原有流程不回归。
2. 选择门店 B 保存发布，记录绑定 B 而非页面原门店 A，列表和详情正确回显 B。
3. 同语言的 A、B、企业模板相互独立；A 员工只能选择 A 和企业已发布模板，B 员工只能选择 B 和企业模板。
4. 单店账号、无门店、全部门店入口、失效门店和接口失败均正确处理，无越权或隐式降级。
5. 范围切换保留输入；关闭重开正确显示归属；发布动作使用模板所属范围。
6. 企业/权限变化后的异步旧响应不会造成串数据；聚合重复项去重。
7. 默认语言、即时保存、历史快照、详细/精简明细及打印声明行为保持不变。

实施时先补失败测试，再修复 UI 与范围数据流，运行相关测试、类型检查，并在本地浏览器验证新增、切换、回显和员工语言隔离。
