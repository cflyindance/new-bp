# Kiosk 支付方式在 marginappconfig 中持久化设计

## 背景与目标

Kiosk 本地配置后台的“服务设置 → 支付 → 选择支付方式”当前主要读取和保存 POS `KIOSK_PAYMENT_TYPE`。用户取消“信用卡/借记卡”并保存后，离开页面再进入时可能重新出现勾选，无法以 `marginappconfig` 中 `KIOSKLITE` 行作为稳定的配置来源。

本设计将全局支付方式选择持久化到 `marginappconfig` 的 `KIOSKLITE` 配置数据中，并保证设置页回读与 Kiosk 点单流程使用同一权威值。

## 权威字段

在 `KIOSKLITE.data.configList` 中新增：

```json
{
  "id": 70,
  "key": "kiosk-payment-types",
  "value": ["0", "1"]
}
```

支付方式编码：

- `"0"`：信用卡/借记卡
- `"1"`：柜台支付/现金
- `"2"`：礼品卡

`id=70` 是全局“选择支付方式”的权威数据。`id=34` 继续表示逐设备支付能力，不承担全局配置职责。

## 设置页数据流

1. 设置页加载 `marginappconfig` 的 `KIOSKLITE` 行。
2. 若存在合法的 `id=70`，支付复选框直接按其 `value` 展示。
3. 是否缺少 `id=70` 必须依据数据库返回的原始 `KIOSKLITE.data.configList` 判断，不能依据合并默认配置后的列表判断。旧数据缺少该字段时，先用 POS `KIOSK_PAYMENT_TYPE` 初始化当前编辑值；默认配置合并不得提前写入 `id=70`，只有用户显式点击保存时才写入并完成惰性迁移。
4. 用户修改支付方式后，当前编辑状态立即更新，但未点击保存前不写数据库。
5. 保存时将当前选择写入 `params.configList[id=70]`，通过现有 `postMarginappConfig` 更新 `marginappconfig`。
6. 保存前必须区分 POS 编辑项：`KIOSK_PAYMENT_TYPE` 是 `id=70` 的兼容镜像；`CHOOSE_ORDER_TYPE` 与 `KIOSK_SEND_MESSAGE` 仍是 POS-only 配置。无有效 `userId` 且后两者存在修改时，必须在写入 `marginappconfig` 之前阻止整次保存，并提示“缺少管理员认证，订单类型或短信设置无法保存”，不得静默丢弃修改或形成部分成功。
7. `marginappconfig` 保存成功后，仅在设置入口提供有效 `userId` 时兼容同步 POS `KIOSK_PAYMENT_TYPE`。本地设置入口只有 Kiosk 设备 session、没有管理员 `userId`，不具备调用 `UpdateSystemConfigurationType` 的认证条件；若当前只有支付方式兼容镜像发生变化，必须跳过 POS 请求并将整次保存视为成功，不显示同步失败警告。
8. 已具备有效 `userId` 的部署继续执行 POS 保存。有效 `userId` 指 JavaScript `number` 类型的有限正整数，或去除首尾空白后仅含十进制数字且数值为正整数的字符串；布尔值、空值、空白、小数、指数形式、`Infinity`、`NaN`、零和负数均无效。
9. 支付方式发生变化且具备有效 `userId` 时保留现有确认框，但必须在任何 `marginappconfig` 或 POS 写入之前展示。确认框授权本次完整保存；取消后整次保存中止、保留页面编辑状态、不发出任何写请求，也不显示保存成功或同步失败。该原子语义同时覆盖支付方式与 POS-only 字段混合修改，避免部分保存。
10. 确认框文案必须描述为“将支付方式同步到 POS 兼容配置”，不得声称会同步到设备设置或修改 `id=34`。
11. 有效 `userId` 场景下 POS 同步真实失败时，`id=70` 已提交的值保持有效且仍为权威数据；页面显示“支付方式已保存，但 POS 兼容同步失败，请重试”的独立警告。当前重试入口为用户再次点击“保存”；允许幂等重存 `marginappconfig`，但同步值必须从已提交并规范化的 `id=70` 生成，不得用旧 POS 值反向覆盖 `id=70`。
12. 返回并重新进入服务设置时，必须再次从 `id=70` 回读，不得由 POS 值覆盖。

## 双价格与设备能力

- 双价格配置不得自动向全局支付方式补入信用卡或现金。
- `id=34` 保留逐设备能力配置。
- 服务设置保存和双价格同步不得批量修改 `id=34`；只有设备设置流程可以修改逐设备能力。
- 双价格不得修改 `id=70`，也不得在进入 Kiosk、返回首页或刷新时向 POS 重新补入 `"0"`、`"1"`。
- Kiosk 实际可用支付方式为：全局 `id=70` 与当前设备 `id=34` 能力的交集。
- 当前环境没有 `deviceId`、`id=34` 缺失、当前设备未找到或设备缺少 `devicePaymentType` 时，设备能力回退为信用卡、现金、礼品卡全部允许；最终仍由全局 `id=70` 限制实际可用方式。

## Kiosk 运行时

- 点单支付流程优先读取 `selfConfig.configList[id=70]`。
- 旧数据缺少 `id=70` 时，兼容回退到 `systemConfig.KIOSK_PAYMENT_TYPE`。
- 只有“原始持久化数据中完全缺少 `id=70`”才允许回退 POS。字段存在但不是数组，或数组规范化后为空，均视为权威配置损坏：设置页显示配置错误并阻止保存前静默回填；运行时返回无可用支付方式并阻止进入支付，不得回退 POS 重新启用支付方式。
- 支付方式页面展示、单一支付方式自动跳转、小费支付方式门禁均使用同一个解析结果，避免设置页与运行时口径不一致。

## 校验与错误处理

- `value` 必须是数组，只保留 `"0"`、`"1"`、`"2"`，去重并按数字排序。
- 至少保留一种支付方式；空选择沿用现有页面校验并阻止保存。
- `marginappconfig` 保存失败时保留编辑状态、提示失败并且不得调用 POS 同步。
- POS 兼容同步的认证门禁以有效正整数 `userId` 为准；无效值不得生成 SOAP 请求。
- 无有效 `userId` 时，只有 `KIOSK_PAYMENT_TYPE` 发生变化才允许跳过同步并成功保存；`CHOOSE_ORDER_TYPE` 或 `KIOSK_SEND_MESSAGE` 发生变化必须在 `marginappconfig` 写入前阻止整次保存。
- 有有效 `userId` 时，POS 兼容同步失败必须明确提示“主配置已保存、兼容同步失败”；重新加载必须继续显示 `id=70` 的已提交值。再次点击保存可幂等重写 `marginappconfig`，随后从已提交的 `id=70` 重试 POS 同步，且不得读取旧 POS 值。
- 确认框取消属于用户取消整次保存，不属于接口失败；不发出 margin 或 POS 请求，也不显示失败警告。

## 测试与验收

### 单元测试

- 新配置默认包含 `id=70`。
- 合法值规范化、未知值过滤、去重和排序。
- 分别覆盖 `id=70` 缺失、类型错误、规范化后为空和合法值；仅缺失允许回退 POS。
- 有 `id=70` 时始终优先于 POS，重新加载不得被不同的 POS 值覆盖。
- 旧数据库行缺少 `id=70` 时，在默认配置合并前识别缺失、回退 POS 初始化编辑态，并仅在显式保存参数中新增该字段。
- 双价格开启时不会自动补回信用卡或现金。
- 服务设置保存和双价格流程不修改 `id=34`；设备设置仍可独立修改 `id=34`。
- Kiosk 支付路由使用 `id=70` 与 `id=34` 的交集，并覆盖无 `deviceId`、缺少 `id=34`、当前设备不存在和缺少 `devicePaymentType` 的全能力回退。
- `marginappconfig` 失败时不调用 POS；margin 保存成功而 POS 失败时，重新加载仍使用 `id=70`，重试传给 POS 的是规范化后的 `id=70` 值。
- 缺少 `userId` 且只有支付方式变化时不调用 `saveKioskConfigFromPos`，保存流程正常成功。
- 缺少 `userId` 且订单类型或短信变化时，在 margin 写入前阻止保存；覆盖支付方式与 POS-only 字段混合修改场景。
- `userId` 校验覆盖正整数 number、十进制正整数字符串，以及空白、小数、指数、布尔、`Infinity`、`NaN`、零和负数。
- 有效 `userId` 时，在任何写入前执行确认框；覆盖支付方式单独修改、支付方式与 POS-only 字段混合修改，以及取消后 margin/POS 均零调用。
- 确认框文案只说明 POS 兼容配置，不提设备设置或 `id=34`；确认后的接口失败才提示。
- 支付页面、自动跳转和小费门禁全部调用共享支付方式解析器。
- Kiosk 启动、返回首页和双价格初始化均不会向 POS 补回被取消的支付方式。

### 浏览器自测

1. 进入“设置 → 服务设置 → 支付”。
2. 确认“信用卡/借记卡”已勾选，取消勾选并保存成功。
3. 点击左下角返回。
4. 再次进入“服务设置 → 支付”。
5. 确认“信用卡/借记卡”保持未勾选。
6. 确认本地设置入口没有出现“POS compatibility sync failed”警告。
7. 在无管理员 `userId` 的本地入口修改订单类型或短信，确认保存被阻止且 margin 配置没有部分提交。
8. 在具备有效 `userId` 的入口确认 POS 同步确认框在写入前展示，文案为“POS 兼容配置”；取消后 margin 和 POS 均未写入，确认后真实接口失败才出现警告。
9. 进入 Kiosk 点单流程，确认支付行为仅包含保存后允许的方式。
10. 重新启动或刷新本地服务后再次回读，确认配置仍保持。

## 影响范围与回滚

影响范围包括服务设置保存/加载、支付方式解析、点单支付路由和小费支付方式门禁。旧数据通过回退逻辑兼容，不要求一次性迁移数据库。

若需要回滚，可停止读取 `id=70` 并恢复 POS 字段作为权威来源；已有 `id=70` 数据留在 JSON 中不会影响旧版本解析。
