# KPOS「每人每轮/每轮下单菜品数量限制」完整操作调研

> 调研日期：2026-08-31  
> 调研入口：KPOS → admin → eMenu → 全局设置 → 下单设置  
> 调研方式：在未保存表单中逐项切换、增加和删除配置；未点击“保存”。

## 1. 调研目的

完整确认历史 KPOS 中“每人每轮/每轮下单菜品数量限制”的配置能力、选项联动和业务含义，为自助餐规则的组合数量方案提供依据。

## 2. 已验证的配置维度

### 2.1 就餐人数区间

支持三种区间形态：

- 首段：`N 人及以下`。
- 中间段：`N 人到 M 人`。
- 末段：`N 人及以上`。

点击顶部“增加”会插入一个中间区间。人数区间自动连续且互斥，例如：

1. 原配置为“2 人及以下、3 人及以上”。
2. 新增中间区间并将上限填写为 5。
3. 系统自动形成“2 人及以下、3～5 人、6 人及以上”。
4. 删除中间区间后，自动恢复为“2 人及以下、3 人及以上”。

结论：人数条件是一组完整覆盖有效就餐人数的连续分段，而不是彼此独立、可以重叠的条件。

### 2.2 下单菜品总数

总量周期支持：

| 选择 | 页面展示 | 业务含义 |
| --- | --- | --- |
| 每轮 | 每轮下单菜品总数最少、最多 | 整桌当前轮总量限制 |
| 每人每轮 | 每人每轮总数最少、最多，并额外展示每轮总数最少、最多 | 人均额度与整桌兜底额度同时配置 |

选择“每人每轮”后，系统不是仅把文案改成人均，而是增加整桌“每轮”第二层限制。建议运行时额度为：

```text
当前轮最终上限 = min(每人每轮上限 × 当前有效就餐人数, 每轮上限)
```

整桌每轮上限留空时，只执行人均换算额度；具体空值语义仍需结合保存接口确认。

### 2.3 指定对象规则

每个人数区间可新增多条指定对象规则。单条规则包含：

- 额度周期：`每轮`、`每人每轮`。
- 限购对象：`菜品`、`菜品集`。
- 最大额度。

可形成以下四个基础组合：

| 额度周期 | 限购对象 | 含义 |
| --- | --- | --- |
| 每轮 | 菜品 | 指定菜品整桌每轮最多 N 份 |
| 每人每轮 | 菜品 | 指定菜品整桌本轮额度为 N × 有效就餐人数 |
| 每轮 | 菜品集 | 集合内商品整桌每轮合并统计 |
| 每人每轮 | 菜品集 | 集合额度按 N × 有效就餐人数换算后合并统计 |

同一人数区间可同时配置多条不同周期、不同对象的规则；规则行支持增加和删除。

## 3. 菜品与菜品集的差异

### 3.1 菜品

- 支持通过分类与菜品树选择一个或多个菜品。
- 计量单位固定为“份”，单位下拉禁用。
- 不展示菜品集内部的“相同菜品”附加上限。
- 多个普通菜品究竟分别统计还是共享额度，配置页面不能证明，需要真实下单验证。

### 3.2 菜品集

- 通过分类与菜品树多选组成集合。
- 计量单位支持`份`和`种`。
- 会展示菜品集内部的单品上限。
- 内部单品上限支持增加多条，并可指定适用菜品。
- 前端交互允许仅选择一个菜品作为菜品集；是否在保存时校验至少两个，尚未确认。

## 4. 菜品集计量方式

### 4.1 按“份”统计

表达式：

```text
每轮/每人每轮指定菜品集最多 N 份
```

集合内所有菜品按份数合并累计。选择“份”后，系统增加：

```text
每轮相同菜品［指定菜品］最多 M 份
```

该附加规则用于防止集合额度被单一菜品全部占用。即使父规则选择“每人每轮”，附加规则仍显示“每轮相同菜品”，说明其口径是整桌当前轮，不随人数放大。

### 4.2 按“种”统计

表达式：

```text
每轮/每人每轮指定菜品集最多 N 种菜品
```

此时统计不同菜品种类数。例如 A 点 3 份、B 点 2 份，共计 2 种。选择“种”后，附加规则变为：

```text
每种菜品［指定菜品］最多 M 份
```

因此按种统计实际包含两层限制：

1. 集合内最多选择多少种菜品。
2. 指定菜品每种最多下单多少份。

## 5. 完整场景矩阵

当前组合功能可以表达：

1. 每轮菜品总数最少/最多。
2. 每人每轮菜品总数最少/最多。
3. 人均总量限制之外，再设置整桌每轮兜底上限。
4. 每轮指定菜品最多份数。
5. 每人每轮指定菜品最多份数。
6. 每轮指定菜品集最多总份数。
7. 每人每轮指定菜品集最多总份数。
8. 每轮指定菜品集最多菜品种数。
9. 每人每轮指定菜品集最多菜品种数。
10. 菜品集按份统计时，限制其中相同菜品每轮最大份数。
11. 菜品集按种统计时，限制其中每种菜品最大份数。
12. 同一人数区间混合配置多条“每轮”和“每人每轮”规则。
13. 不同人数区间使用完全不同的总量与指定对象规则。

## 6. 与旧独立设置的关系

启用组合功能后，以下旧设置显示“已设置：每人每轮/每轮下单菜品数量限制规则”：

- 每轮下单指定菜品数量限制。
- 每位食客每轮下单菜品总数限制。
- 每位食客每轮下单指定菜品数量限制。

结论：组合功能会接管旧独立能力，旧设置不应再与组合规则并行叠加，以避免重复配置和重复拦截。

## 7. 建议采用的运行时规则

- “每轮”统一统计当前订单当前轮累计数量，不仅统计本次提交数量。
- “按人数”只使用`单人额度 × 当前有效就餐人数`，不识别具体食客身份。
- 普通“菜品”按单品分别统计。
- “菜品集”内多个菜品合并统计，并支持跨产线合并。
- 同时命中总量、指定菜品、菜品集和同菜品上限时，所有规则共同生效，任一规则超限即拦截。
- 上限应在加购和提交时校验；下限应在提交本轮时校验。
- 服务员授权只绕过当前数量规则，不绕过售罄、停售、年龄或支付限制。

## 8. 仍需真实下单验证

以下行为无法仅从配置页面确认：

1. 历史实现的“每轮”是当前轮累计统计，还是仅统计本次提交。
2. 普通“菜品”一次选择多个菜品时，是逐个菜品分别统计，还是多个菜品共享额度。
3. 菜品集是否在保存时强制至少选择两个菜品。
4. 空输入与数值 0 在保存接口及运行时中的准确语义。
5. 最小值大于最大值时，保存端采用何种校验和提示。

以上未验证项不应直接继承历史实现，需在新自助餐规则中明确产品定义并补充接口测试。
