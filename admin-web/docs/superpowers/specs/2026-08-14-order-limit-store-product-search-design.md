# 数量与频次规则门店商品跨产线搜索设计

## 背景

数量与频次规则的第 2 步“商品配置”已经支持通过“配置门店”下拉切换门店，并按门店独立保存商品范围和数量矩阵。当前商品选择仍依赖“产线 → 组 → 类 → 菜”逐级浏览；当门店商品较多、用户已知商品名称时，需要逐个产线查找，效率较低。

本次在选定配置门店后增加商品搜索，搜索当前门店全部产线的商品。搜索只改变商品查找方式，不改变门店独立配置、分类/菜品限购语义、草稿模型或发布快照。

## 已确认口径

- 采用商品配置页内的统一搜索结果面板，不增加弹窗。
- 搜索范围为当前配置门店下的全部产线。
- 搜索结果展示商品及其产线、组、分类完整路径。
- 按菜品限购时，搜索结果直接选择或取消具体菜品。
- 按分类限购时，选择搜索命中的商品会自动选择其所属分类。
- 同一分类下的其他搜索结果同步展示“已按分类加入”。
- 清空搜索后恢复现有层级选择器，已有选择保持不变。
- 切换配置门店时清空搜索词。

## 页面与交互

### 搜索入口

只有选择了有效配置门店后，才在“配置门店”下拉与商品结构选择器之间展示搜索框。搜索框标签为“搜索商品”，占位文案为“搜索当前门店全部产线商品”。

未选择门店时继续展示现有空状态“请选择门店后配置商品”，不展示搜索框，避免产生无门店上下文的搜索结果。

### 非搜索状态

搜索词为空时，页面保持现有“产线 → 组 → 类 → 菜”结构及选择方式，不改变产线按钮、父子级联、半选状态和商品摘要。

### 搜索状态

输入去除首尾空白后，只要搜索词非空，就临时隐藏层级选择器并展示统一结果列表。匹配规则为商品名称不区分大小写的包含匹配；当前模拟菜单数据没有商品编码，本次不增加虚构的编码搜索。

搜索结果覆盖当前门店菜单目录中的全部产线，每条结果展示：

- 商品名称。
- 产线名称。
- 组名称。
- 分类名称。
- 选择控件与当前状态。

同名商品在不同产线中作为不同结果展示，其产线和选择状态分别保存。结果顺序按现有产线顺序，再按菜单树中的组、分类和商品顺序，保证刷新和重复搜索稳定。

无命中时展示“当前门店全部产线中未找到相关商品”，同时保留搜索输入，方便继续修改或清空。

### 按菜品限购

结果行的勾选框直接控制该产线下具体商品节点。勾选后加入当前门店的商品范围；取消后移除该商品。若所属组或分类因此达到全选、部分选择或未选择，继续使用现有级联计算更新父级状态。

### 按分类限购

搜索仍以商品为命中对象，帮助用户通过已知商品定位分类；实际选择节点必须是该商品所属分类：

- 勾选某个结果时，选择该结果对应产线下的所属分类，并自动包含该分类全部商品。
- 取消某个已选结果时，取消整个所属分类，与原分类选择器的取消行为一致。
- 同一分类下的全部搜索结果共享选择状态。
- 已选结果展示“已按分类加入”，明确实际限购对象是分类而不是单个商品。

不同产线中的同名分类仍是独立节点，选择 Kiosk 分类不会自动选择 eMenu 或 SDI 的分类。

### 状态切换

- 清空搜索词：立即恢复层级选择器，并按当前 `structureByLine` 恢复选择、全选和半选状态。
- 切换配置门店：清空搜索词，再读取新门店独立商品配置。
- 切换限购对象：沿用现有重置确认；完成重置后清空搜索词。
- 离开第 2 步：清空搜索词。返回时展示非搜索状态，不把上一次临时查询带入新的操作上下文。

## 组件边界

### 品牌菜单结构选择器

`brand-menu-structure-picker.js` 继续作为菜单树和选择级联的唯一事实来源，补充两个通用能力：

1. 枚举全部产线商品及路径信息，返回稳定结果描述：

```js
{
  lineId,
  lineLabel,
  groupId,
  groupName,
  categoryId,
  categoryName,
  dishId,
  dishName,
  dishKey,
  categoryKey,
}
```

2. 按产线和节点键执行选择或取消，内部复用现有 `cascade`、父级同步和 `normalizeByLine`，返回新的 `structureByLine`。

选择器不感知“订单限购”业务，也不决定按菜品还是按分类；订单限购页面根据 `targetType` 选择 `dishKey` 或 `categoryKey`。

### 订单限购规则编辑器

`order-limit-flow.js` 负责：

- 维护临时搜索词。
- 按搜索词过滤选择器提供的全产线商品描述。
- 渲染搜索框、结果、空状态和“已按分类加入”状态。
- 根据限购对象把结果操作转换为菜品键或分类键。
- 将新的 `structureByLine` 交回现有商品结构变更流程。

商品结构变更后继续调用现有 `syncStoreTargetsFromStructure`、`normalizeStoreDraft`、自动保存和重新渲染逻辑，确保商品摘要、门店“已添加”状态以及数量矩阵同步行为不产生第二套实现。

### 样式

`order-limit-flow.css` 增加搜索框、搜索结果行、路径文字、分类状态提示和空状态样式。保持现有白底、浅灰边框、蓝色选择态和紧凑表单尺寸，不引入新的弹窗、卡片嵌套或视觉体系。

## 数据与状态

搜索词只存在于编辑器会话临时状态，例如：

```js
editorState.productSearchQuery = "肥牛";
```

搜索词不进入：

- `editorDraft`。
- `storeConfigs`。
- `authoringDraft`。
- 正式运行快照。
- 本地规则持久化结构。

商品选择仍只写入当前门店：

```js
draft.storeConfigs[draft.activeStoreId].structureByLine
```

因此搜索和层级浏览只是同一配置的两个视图。切换视图、刷新页面或重新编辑规则不会产生需要迁移的新字段。

## 数量矩阵联动

搜索结果选择必须复用现有结构变更管线：

1. 更新当前门店 `structureByLine`。
2. 重新计算 `productLines` 和 `targetIds`。
3. 保留仍然对应有效目标的数量单元格。
4. 删除已移除目标的数量单元格。
5. 新增目标在第 4 步显示“未配置”。

按分类限购时，一个搜索结果的取消会移除整个分类目标，因此该分类对应的数量单元格全部删除；再次加入后恢复为“未配置”，不得复用已移除分类的旧数量。

## 异常与边界

- 当前门店无菜单商品：显示无结果状态，不创建空选中节点。
- 搜索词只含空白：按空搜索处理并显示层级选择器。
- 搜索结果操作时节点已从菜单树失效：忽略操作，重新枚举并刷新结果，不写入悬空键。
- 门店 ID 已失效：沿用现有门店归一化，清空活动门店和搜索词。
- 搜索结果较多：当前菜单选择器持有完整本地树，本次按稳定顺序渲染完整命中集；不为现有小型本地数据提前引入分页或服务端查询协议。
- 输入法组合期间不提交不完整查询；组合结束后再更新结果。
- 搜索框和结果勾选框支持键盘访问，结果状态不能只依赖颜色表达。

## 验收标准

1. 未选择配置门店时不展示商品搜索框。
2. 选择门店后展示搜索框，空搜索时仍显示原层级选择器。
3. 搜索可以同时返回 Kiosk、eMenu、SDI 的命中商品。
4. 每条结果展示商品、产线、组和分类信息。
5. 同名商品在不同产线分别显示并保持独立选择状态。
6. 按菜品限购时可独立选择和取消具体商品。
7. 按分类限购时选择商品自动选择其所属分类，并显示“已按分类加入”。
8. 同分类多个命中结果同步选择状态；取消任一结果会取消整个分类。
9. 清空搜索后原层级选择器正确恢复全部选择和半选状态。
10. 搜索操作后的商品摘要、门店状态和草稿自动保存正常。
11. A、B 门店搜索和商品选择互不覆盖；切换门店后搜索词被清空。
12. 通过搜索新增或移除目标后，数量矩阵按现有规则保留有效项、删除失效项、新增项恢复未配置。
13. 刷新、重新编辑和发布后不保存搜索词，商品配置保持正确。
14. 无结果、空白搜索、输入法输入和失效节点场景无报错。
15. 既有商品结构选择、批量数量、生效门店、发布裁剪和作者草稿恢复流程不回归。

## 测试方案

### 静态专项验证

- 选择器导出全产线商品枚举和节点选择接口。
- 商品配置渲染搜索框、结果和分类提示。
- 搜索词只存在于临时编辑器状态，不进入持久化模型。
- 搜索选择复用现有商品结构变更同步函数。

### 单元式脚本场景

- 全产线枚举包含每条结果的完整路径和稳定键。
- 菜品键选择只影响目标产线和菜品。
- 分类键选择包含完整分类，并正确更新父级状态。
- 分类取消移除完整分类。
- 查询大小写、首尾空格、无结果和同名跨产线行为正确。

### 既有回归

继续执行标题焦点、规则列表滚动、未配置状态、批量目标选择、门店独立配置和门店生效范围专项脚本。

### 浏览器流程

1. 新建按菜品限购规则，选择 A 门店。
2. 搜索一个跨产线存在的商品，分别选择不同产线结果。
3. 清空搜索，确认层级选择器状态与摘要正确。
4. 切换 B 门店，确认搜索词清空且 A 的选择不出现。
5. 新建或切换为按分类限购，搜索具体商品并确认所属分类自动加入。
6. 搜索同分类另一商品，确认同步显示“已按分类加入”。
7. 取消结果并确认整个分类取消。
8. 完成数量、生效范围与发布，重新编辑后确认门店商品配置仍在且搜索词为空。
9. 检查页面无 Vite 错误遮罩、控制台错误或明显布局溢出。

### 构建验证

执行 JavaScript 语法检查、全部订单限购专项脚本和生产构建。
