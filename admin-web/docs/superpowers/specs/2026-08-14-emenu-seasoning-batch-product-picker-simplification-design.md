# eMenu 调味批量关联商品选择简化设计

## 1. 目标与范围

简化“批量建立关联”的商品选择界面，只向用户展示当前可在 eMenu 正常销售的商品，并移除不必要的批量入口、说明文案和商品内部编码。

本次同时移除“新增动作”弹窗中的辅助说明文案。商品选择仍保留“组 + 类 + 菜”三列结构、组/类复选框、商品多选和名称/内部编码搜索能力。

本次不删除商品主数据，不改变已有调味关联数据，也不改变服务端面向旧客户端的搜索范围选择协议。

## 2. 商品可见范围

商品进入批量选择器前必须同时满足：

- 商品状态为启用；
- 商品允许在 eMenu 销售。

过滤在菜单结构数据层完成，而不是仅在页面中隐藏。停用商品及不可在 eMenu 销售的商品不进入返回给选择器的组、类、菜结果，因此页面不再展示“商品已停用”或“不可在 eMenu 销售”等不可用原因。

过滤只影响本次批量选择器中的候选商品，不删除商品，也不清理该商品历史上已经建立的调味关联。

## 3. 菜单结构与选择规则

- 继续使用一行三列的“组 + 类 + 菜”结构。
- 组和类的商品数量、已选数量、全选/半选状态，只基于当前查询范围内的可用商品计算。
- 勾选组或类时，只选中当前搜索范围内、属于该组或类的可用商品。
- 点击组名或类名只切换右侧浏览内容，既有交互不变。
- 菜品行只展示商品名称和选中状态，不展示商品 ID 或内部编码。
- 搜索仍匹配商品名称和内部编码；内部编码只作为检索字段，不出现在结果行中。
- 若搜索结果没有可用商品，按既有空状态展示，不回退显示不可用商品。

## 4. 移除的界面内容

商品选择步骤移除：

- “选择全部筛选结果”按钮及其前端点击处理；
- “勾选‘组’或‘类’会选择当前搜索范围内的全部可用菜品；点击名称只切换右侧浏览内容。”说明文案；
- 菜品行中的商品 ID / 内部编码；
- 不可用商品及其“商品已停用”“不可在 eMenu 销售”状态文案。

新增动作弹窗移除：

- “可一次选择多个动作，添加后再逐个配置 Option。”说明文案。

该动作选择器由批量新增和单商品编辑共用，因此两个入口中的上述文案一并移除，功能与多选能力保持不变。

## 5. 服务端与兼容性

菜单结构查询在匹配商品集合阶段先排除停用或不可在 eMenu 销售的商品，再进行名称/内部编码搜索、分组聚合、计数和选择状态计算，确保服务端返回值与页面显示一致。

前端不再发起“选择全部筛选结果”的搜索范围选择请求。服务端现有 `scope.level = "search"` 写接口继续保留，避免旧客户端或历史调用失效；本次不新增或删除 API 字段。

组、类范围选择仍由服务端基于同一套可用商品过滤规则处理，防止不可见商品被隐式选中。

## 6. 异常与边界

- 一个组内没有可用商品时，该组不进入菜单结构结果。
- 一个类内没有可用商品时，该类不进入菜单结构结果。
- 搜索命中某个不可用商品的名称或内部编码时，该商品仍不返回。
- 已经选中的商品如果在后续请求前变为停用或不可销售，下一次加载时从候选及选择状态中排除；最终提交仍沿用现有服务端有效性校验。
- 搜索条件变化后，组/类计数和半选状态以新的可用结果集重新计算。

## 7. 验收与测试

- 商品选择步骤不再出现“选择全部筛选结果”按钮和对应说明文案。
- 菜品行不展示商品 ID 或内部编码，但使用内部编码搜索仍能找到对应的可用商品。
- 停用商品和不可在 eMenu 销售的商品在默认列表、名称搜索和内部编码搜索中均不展示。
- 组、类数量只统计可用商品；组/类全选和取消选择不会包含不可用商品。
- 组、类复选框以及三列浏览结构保持可用。
- 批量新增和单商品编辑的新增动作弹窗均不再出现辅助说明文案，多动作选择功能不受影响。
- 服务端仍接受旧客户端的搜索范围选择请求，并且只处理可用商品。
- 现有批量关联预览、保存、商品行编辑与删除流程不回归。
