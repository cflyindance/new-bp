# 员工详情分配状态筛选设计

## 目标

在员工分配详情页现有日期范围和考勤状态筛选后新增“分配状态”下拉框，让用户只查看已分配或待分配的逐日记录。

## 交互设计

- 筛选项名称：`分配状态`。
- 选项依次为：`全部状态`、`已分配`、`待分配`。
- 默认选择 `全部状态`。
- 分配状态与日期范围、考勤状态采用 AND 关系。
- 同一员工详情内修改日期范围、考勤状态或日期排序时，保留当前分配状态选择。
- 重新进入员工详情或从员工 A 切换到员工 B 时，分配状态重置为 `全部状态`，日期排序重置为倒序。
- 无匹配结果时沿用员工详情当前空状态。

## 数据规则

- 使用逐日记录现有的分配状态，不新增第二套状态来源。
- 已确认分配的记录匹配 `已分配`；其余记录匹配 `待分配`。
- 分配状态筛选决定汇总卡片、列表以及 PDF、CSV、邮件导出包含哪些记录，避免页面与导出口径不一致。
- 页面日期正序/倒序只影响列表显示顺序；PDF、CSV、邮件继续沿用既有导出顺序，不随页面排序切换而改变。

## 实现边界

- 在员工详情模板中新增原生 `select`，保持与考勤状态筛选相同的视觉与键盘交互。
- 扩展员工详情纯筛选函数，使其同时接收考勤状态和分配状态。
- 将当前分配状态写入页面视图状态和导出快照。
- 不修改日期分配汇总、员工分配汇总列表或分配业务状态机。

## 验收标准

1. 初次进入员工详情时，分配状态默认为“全部状态”。
2. 选择“已分配”后，仅显示已分配记录；选择“待分配”后，仅显示待分配记录。
3. 分配状态能与日期范围、考勤状态组合筛选。
4. 汇总卡片仅统计筛选后的记录。
5. PDF、CSV、邮件导出与当前筛选结果一致，并包含当前分配状态筛选说明。
6. 同页修改日期范围、考勤状态或日期排序时保留分配状态；页面排序不改变三种导出的既有行序。
7. 重新进入详情或切换到另一员工时，分配状态恢复“全部状态”，日期恢复倒序。

## 验证

- 为纯筛选函数补充全部、已分配、待分配及组合筛选断言。
- 为模板、程序与导出数据契约补充静态验证。
- 补充分配状态的同页保留、重新进入重置、切换员工重置以及导出顺序不受页面排序影响的断言。
- 运行团队小费原生视图验证脚本与项目构建。
