# 菜单配置表单快捷锚点设计

## 目标

在菜单节点配置表单顶部提供快捷锚点，使用户能够在长表单中快速定位“基础信息”“层级与页面”“高级设置”，同时保持全部表单内容连续展示。

本设计采用已确认的视觉方案 A“标题栏内双层吸顶”。

## 页面结构

菜单配置标题、取消和确认按钮继续位于吸顶标题栏第一行。标题栏第二行新增水平锚点导航，顺序固定为：

1. 基础信息
2. 层级与页面
3. 高级设置

标题栏与锚点导航作为整体吸顶。锚点使用文本标签和底部强调线表达当前状态，不使用分段按钮外观，避免被理解为内容切换器。

表单三个目标区块提供稳定的定位标识。滚动定位时应预留吸顶标题栏高度，确保目标区块标题完整可见。

## 交互规则

- 点击锚点后，仅让右侧菜单详情滚动容器滚动至目标区块。默认使用平滑滚动；当系统启用 `prefers-reduced-motion: reduce` 时使用即时滚动。
- 滚动高亮以“吸顶标题栏底边下方 16px”为判定线：活动锚点为其区块标题顶部已到达或越过判定线的最后一个区块。
- 右侧容器位于第一个区块标题之前或处于顶部时，“基础信息”为活动锚点；滚动到容器底部时，“高级设置”为活动锚点。
- 活动锚点使用主题色文字和底部强调线，其余锚点使用中性色。
- 选择另一个菜单、新增一级菜单或新增子菜单时，右侧详情滚动位置重置到顶部，活动锚点重置为“基础信息”。
- 点击锚点只改变右侧详情滚动位置，不折叠、隐藏或切换表单内容。
- 锚点交互不得改变左侧菜单树的滚动位置。
- 锚点使用原生按钮语义，支持 Tab 聚焦和回车/空格触发，并提供清晰可见的焦点样式。活动锚点暴露 `aria-current="location"`。

## 状态边界

- 锚点活动状态属于编辑器界面临时状态，不写入菜单节点或导出 JSON。
- 新增与编辑模式使用相同的锚点结构和行为。
- 表单因菜单用途切换而重新渲染时，必须保存并恢复右侧滚动位置，并在新 DOM 稳定后按滚动判定线重新计算活动锚点。若原活动区块在新 DOM 中不存在，则回退到“基础信息”。选择不同菜单或进入新增模式时才重置。

## 不变范围

- 不新增、删除或重命名菜单 JSON 字段。
- 不改变表单字段映射、字段校验、服务权限选择、草稿保存和发布拦截逻辑。
- 不改变左侧菜单树选择、展开、搜索及滚动规则。

## 验收标准

- 新增和编辑菜单时，顶部均展示三个锚点，且标题栏与锚点在右侧表单滚动时保持可见。
- 点击每个锚点均能定位到对应区块，目标标题不被吸顶区域遮挡。
- 手动滚动经过三个区块时，活动锚点随当前位置正确变化。
- 顶部、区块交界和容器底部的活动锚点分别符合既定滚动判定规则。
- 切换菜单或进入新增模式后回到表单顶部，“基础信息”成为活动锚点。
- 菜单用途切换触发局部重渲染后，右侧滚动位置被恢复，并在 DOM 稳定后重新计算活动锚点；目标区块不存在时回退到“基础信息”。
- 锚点操作不会改变左侧菜单树的滚动位置。
- 锚点点击只滚动右侧详情容器，不改变、不折叠、不隐藏也不重新挂载任何表单内容。
- 三个锚点均可通过 Tab 聚焦和回车/空格触发，焦点样式清晰可见，活动项带有 `aria-current="location"`。
- 系统启用减少动态效果时，锚点定位不使用平滑滚动。
- 对相同输入，导出 JSON、校验结果、草稿保存结果和发布拦截结果与改造前一致。
- 相关菜单配置回归测试通过。
