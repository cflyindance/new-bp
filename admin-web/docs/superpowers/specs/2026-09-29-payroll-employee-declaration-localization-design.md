# 薪资员工声明多语言设计

## 1. 背景与目标

薪资管理的员工明细当前在底部展示固定声明。不同员工可能使用不同语言；员工需要能够阅读并确认声明，打印、PDF 与邮件中的声明也必须与页面确认内容一致。

本方案在现有“详细明细 / 精简明细”与打印导出能力上增加受控的多语言声明，不改变考勤、工时、薪资、小费或 Gratuity 的计算逻辑，也不提供机器翻译或工资发放能力。

目标：

- 企业可维护任意语言的声明模板及版本。
- 员工资料保存默认声明语言。
- 员工明细允许针对单个薪资期临时切换语言，不改变员工默认值。
- 页面、打印、PDF 与邮件复用同一份已渲染声明。
- 支持“仅员工语言”和“员工语言 + 英文”两种打印格式。
- 历史记录保留确认时的完整正文与版本，不随模板后续修改而变化。

## 2. 已确认方案

采用“企业声明模板库 + 员工默认语言”方案。

不采用以下方式：

- 不允许在每次查看员工明细时任意编辑正文。这会造成同语言员工文案不一致且无法可靠审计。
- 不让系统根据姓名、国籍、地址或浏览器语言猜测员工语言。
- 不在模板缺失时静默回退到英文，否则员工可能确认其无法理解的内容。
- 不允许门店直接覆盖企业已发布模板。

## 3. 权限与职责

### 3.1 企业管理员

- 创建语言模板。
- 编辑草稿。
- 审核并发布模板版本。
- 基于已发布模板创建新版本。
- 停用不再使用的模板。
- 创建门店专用模板并完成独立审核。

### 3.2 门店管理员

- 为员工选择企业已发布或本门店已发布的模板语言。
- 在员工本期明细中临时切换已发布模板。
- 选择本期单语或双语打印。
- 不能直接修改已发布正文。

### 3.3 普通查看者

- 查看当前及历史声明。
- 按权限打印、导出或发送既有声明快照。

## 4. 信息架构与交互

### 4.1 企业声明模板库

模板列表至少展示：

- 语言名称及标准语言代码。
- 模板范围：企业通用或指定门店。
- 版本号。
- 状态。
- 创建人、审核人、发布时间与最后更新时间。
- 被员工或门店使用的数量。

模板详情包含正文编辑器、受控变量插入区和预览区。正文保存原始 Unicode 文本，输入什么语言就按原文展示；系统不自动翻译或改写。

### 4.2 员工资料

新增“默认声明语言”字段，候选项仅包含当前员工所属门店可使用的已发布模板。

新增“默认打印格式”字段：

- 仅员工语言，默认值。
- 员工语言 + English。

员工没有默认语言时，必须由管理员明确选择后才能完成需要声明确认的薪资明细操作。

### 4.3 员工明细

声明区域显示：

- 当前语言。
- 模板版本。
- 完整渲染正文。
- 当前打印格式。
- 已确认记录显示确认时间和快照状态。

未确认的薪资期允许选择“沿用员工默认”或临时切换其他已发布语言。临时选择只作用于当前员工、当前薪资期，不回写员工资料。

已确认记录为只读。模板之后升级、停用或员工默认语言改变，都不得改变该记录。

### 4.4 打印、PDF 与邮件

导出入口继续沿用详细明细与精简明细的既有选择，不再重复选择声明语言。声明语言来自当前薪资记录的选择或冻结快照。

打印格式：

- **仅员工语言**：只输出员工语言正文。
- **员工语言 + English**：先输出员工语言，后输出英文基准模板，并以清晰标题区分。

若员工语言本身是英文，双语选项按单语输出，不重复正文。

打印语言模式分为三个层次：员工资料保存默认值；未确认薪资期可保存期次 override；持久声明快照冻结最终模式。已确认后不得把单语快照临时扩展为双语。需要双语重导时，快照必须已经同时冻结主语言和英文正文；输出操作可以在该快照允许的模式内选择单语或双语，但不得重新解析当前模板。

打印、直接下载 PDF、批量 PDF、邮件 PDF 与页面预览必须调用同一份声明渲染结果。详细版和精简版只允许改变布局，不允许改变文本、金额或模板版本。

每次打印或导出创建独立的 `operation export snapshot`，用于保证该次异步任务前后一致；失败时不改变薪资记录。只有“员工确认成功”或“薪资期锁定成功”的服务端事务创建持久声明快照。预览、打印、PDF、CSV、邮件或批量导出均不得隐式锁定薪资记录。若业务以后要求首次正式输出留档，应新增不可变输出记录，而不是把导出副作用混入薪资确认状态。

## 5. 模板生命周期

模板状态为：

1. **草稿**：可编辑，不可分配或用于确认、打印和导出。
2. **已发布**：可分配，不可原地覆盖正文。
3. **已停用**：不可用于新的分配；历史快照与既有已确认记录仍可查看和输出。

修改已发布模板时，系统复制为新草稿版本。新版本发布后：

- 新的未确认薪资记录默认使用最新可用版本。
- 已确认记录继续使用原版本快照。
- 已经打开但尚未确认的页面在确认前检查版本；发现版本变化时提示用户重新预览，不静默替换。

## 6. 受控变量

第一期支持以下变量：

- `employee_name`
- `pay_period_start`
- `pay_period_end`
- `regular_hours`
- `overtime_hours`
- `total_hours`
- `tips_amount`
- `gratuity_amount`
- `store_name`
- `confirmation_date`

变量由系统选择器插入，禁止用户输入任意脚本、HTML 或计算公式。金额、日期与数字按模板语言对应的 locale 格式化，但底层数值必须来自同一份薪资快照。

发布前校验：

- 不存在未知变量。
- 必需变量没有丢失。
- HTML、脚本与不可打印控制字符被拒绝。
- 文本长度在打印与存储限制内。
- 从右到左语言可正确预览方向、标点和数字。

## 7. 数据模型

### 7.1 声明模板

建议字段：

- `organizationId`
- `storeId`，企业模板为空
- `localeCode`，使用标准 BCP 47 语言标签
- `languageDisplayName`
- `version`
- `status`
- `bodySource`
- `variableSchemaVersion`
- `createdBy`、`createdAt`
- `reviewedBy`、`reviewedAt`
- `publishedAt`、`retiredAt`

模板身份拆为：

- `templateFamilyId`：范围与语言组合的稳定身份，员工偏好引用该字段。
- `templateVersionId`：单个不可变发布版本，声明快照引用该字段。

上方模板实体不再另设含义重叠的 `templateId`；所有接口、存储与审计统一使用 family ID 和 version ID。

同一范围、同一语言允许存在多个历史版本，但同一时刻只能有一个 active 已发布版本。发布新版本、切换 active 版本和停用旧版本必须在同一事务完成。

模板解析顺序固定为：员工明确选择的适用 family → 门店默认 family → 企业默认 family。主语言和双语英文分别按相同顺序解析，预览必须显示来源范围。员工不得引用其他租户或不适用于其门店的 family。

### 7.2 员工偏好

- `employeeId`
- `defaultDeclarationTemplateFamilyId`
- `defaultDeclarationLocaleCode`
- `defaultPrintLanguageMode`: `employee-only | bilingual-english`
- `updatedBy`、`updatedAt`

### 7.3 薪资记录声明快照

员工确认或薪资期锁定事务成功时冻结：

- 员工与薪资期标识。
- 主语言代码、template family ID、template version ID、版本号及来源范围。
- 主语言原模板正文。
- 变量名与冻结值。
- 主语言渲染后的完整正文。
- 双语时的英文 template family ID、template version ID、版本、来源范围、原文与渲染正文。
- 打印语言模式。
- 冻结人、冻结时间与冻结原因。
- 内容校验哈希。

系统不得在历史查看或再次导出时用当前模板重新渲染旧记录。`confirmation_date` 只表示员工真实确认时间，不等同于锁定时间、导出时间或快照时间。确认事务以服务端权威时间填充该变量并完成最终渲染；重新导出继续使用原确认时间。

确认前预览将 `confirmation_date` 显示为“确认后生成”的明确占位，不使用客户端时间。模板包含该变量时，未确认记录不得正式打印、PDF、邮件、CSV 或批量导出，也不得在未确认状态直接锁定；界面提示先完成员工确认。模板不包含该变量时，未确认导出可以创建仅限本次操作的 export snapshot，未确认锁定也可创建持久快照，但快照的 `confirmedAt` 必须为空并独立记录服务端 `lockedAt`，不得把锁定日期代入声明。确认时对预览使用的 active version 做乐观锁检查，版本已变化则拒绝确认并要求重新预览。

内容校验哈希使用带版本的 canonical payload：UTF-8 编码、字符串使用 Unicode NFC、对象 key 在每一层按 Unicode code point 递归排序、金额与工时使用数据契约规定的小数定点字符串，包含主语言与英文的 version ID、语言代码、打印模式、原始模板正文、变量冻结值和渲染正文；算法为 `SHA-256(canonical-json-v1)`。后续算法升级必须保留算法版本。

## 8. 回退与异常处理

- 默认语言无已发布模板：阻止确认、打印、PDF 与邮件，提示先配置模板。
- 双语模式缺少英文模板：阻止双语输出，可由有权限用户明确改为仅员工语言。
- 模板被停用：未确认记录要求重新选择；已确认记录继续使用快照。
- 变量数据缺失：预览明确标红缺失字段，禁止冻结，不以空字符串静默替代法务关键金额。
- 模板引用 `confirmation_date` 且员工尚未确认：只允许带占位符预览，禁止正式输出和直接锁定。
- 字体不支持字符：输出前执行字体覆盖检查；不能保证可读时阻止导出并提示缺少对应字体。
- 正文过长：页面完整展示；打印按既有分页策略分页，不缩小到不可读字号。
- RTL 语言：声明正文使用该语言方向，表格数字和金额维持可读的局部 LTR。

超长声明分页时，声明正文允许按段落拆页；每个续页重复声明标题、语言及模板版本。签名线和门店信息保持不可拆分，并且只出现在声明正文结束后。单个不可拆段落超过一页时必须在安全文本边界拆分，禁止裁切。

正文始终按纯文本存储。页面、打印、PDF、邮件和 CSV 消费端统一执行上下文对应的转义。所有模板与偏好读写由服务端校验 tenant、organization、store 和 employee 作用域，禁止仅依赖前端隐藏控件。已发布版本和审计事件不可变。Unicode 校验允许合法 RTL isolate 字符，拒绝未配对 isolate、会造成视觉伪装的 bidi override 以及除换行和制表外的不可打印控制字符。

## 9. 与既有薪资功能的关系

本方案扩展 `2026-09-03-payroll-dual-detail-export-design.md`：

本节是多语言声明启用后的窄域规范，涉及声明的可读字号、尾块分页和 CSV 声明值时优先于既有文档；既有文档的其他布局、分页与兼容规则继续有效。实施计划必须把这三项覆盖作为同一变更交付，禁止只实现新模板界面而保留相冲突的旧分页行为。

- 详细明细与精简明细均使用声明快照。
- 强制一页先执行可读性检查；声明区域计算字号低于 7pt 时阻止 `fit-one-page`，提示改用分页，不得裁切正文。本规则是多语言声明启用后的窄域例外，并已同步到既有规范。
- 旧详细 CSV 与精简 CSV schema、列顺序及文件名保持不变，仅把既有 `declaration` 列写为主语言冻结正文。语言、版本、英文正文只进入审计数据和 PDF，不向旧 CSV 增加列。将来需要这些字段时必须新增显式 CSV V2 导出选项与版本化文件名。
- 批量导出按每位员工自己的快照语言生成，同一合并 PDF 可以包含多种语言。

现有固定英文 `declarationBodyEn` 只能作为迁移输入，不能继续作为所有员工的运行时唯一来源。

## 10. 迁移策略

1. 将当前英文声明导入为企业级 English V1，并标记为已发布。
2. 现有员工默认语言不根据个人信息自动推断；迁移工具允许管理员显式批量选择 English V1 或其他已发布 family，并记录操作者。
3. 历史记录若只有固定英文文本，标记为“历史英文声明”，保留原文，不伪造模板审核信息。
4. 使用分阶段 feature flag：先开放模板配置与批量迁移，展示完成率；达到企业确认的启用条件后，才打开缺失模板的阻断校验。
5. 历史记录继续读取旧固定英文快照，不进入新模板解析；模板功能与声明快照读写完成后，再切换页面、打印、PDF、邮件和批量导出消费者。

## 11. 验收标准

- 企业管理员能创建任意语言草稿，插入受控变量、预览并发布。
- 门店管理员只能选择适用范围内的已发布模板。
- 员工资料保存默认语言与默认打印格式。
- 当前薪资期可临时切换语言且不改变员工默认值。
- 缺少主语言模板时无法确认或输出，不自动回退英文。
- 单语打印只出现员工语言；双语打印依次出现员工语言和英文。
- 英文员工选择双语时只输出一份英文正文。
- 页面、详细 PDF、精简 PDF、邮件 PDF 与批量 PDF 的声明正文、金额及版本一致。
- 已确认记录在模板升级、停用或员工语言改变后保持不变。
- 中文、西班牙语、越南语、阿拉伯语等 Unicode 文本能正确显示和打印。
- A4 分页不裁切声明、签名或关键金额；长文本触发分页提示。
- 无权限用户不能创建、发布、停用模板或修改员工默认语言。
- 审计记录能定位模板版本、审核人、冻结人、冻结时间及完整快照。
- 企业与门店同时存在同语言模板时按既定优先级解析，且页面显示来源。
- 模板发布、停用与员工确认并发时不会出现预览版本与冻结版本不一致。
- 预览不创建持久快照；导出失败不改变薪资确认或锁定状态。
- `confirmation_date` 只来自员工确认事务；锁定与导出不会生成或改写确认日期。
- 覆盖单语/双语 × 详细/精简 × print/PDF/email/batch/CSV 的自动化矩阵。
- 覆盖超长 RTL、CJK、越南语声明、字体缺失、英文模板缺失、历史重导和迁移未完成员工。

## 12. 非目标

- 不提供自动翻译、翻译质量保证或法律意见。
- 不依据国籍自动选择语言。
- 不改变薪资、工时、小费、Gratuity 或加班计算。
- 不执行工资自动发放。
- 不允许自由 HTML、脚本或自定义计算表达式。

## 13. 法务与内容治理边界

系统保证版本、来源、展示和历史留痕一致，但不判断声明内容是否满足各州或地区法规。企业应由有资质人员审核基准英文及每个译文。产品界面应明确记录“由谁审核、何时审核、对应哪个版本”，不得使用“系统认证翻译”等误导性表达。
