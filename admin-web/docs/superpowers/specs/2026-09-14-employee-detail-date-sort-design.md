# 员工详情日期排序设计

## 背景

员工分配汇总详情按日期逐行展示考勤和小费结果，但当前固定按日期顺序排列，日期表头不可操作。较长日期范围下，用户进入详情后无法优先看到最近日期，也无法按核对需要切换顺序。

## 目标

- 员工详情默认按日期倒序展示，最近日期优先。
- 日期表头支持点击，在顺序与倒序之间切换。
- 交互和视觉语义参照日期分配汇总的日期排序表头。
- 排序与日期范围、考勤状态筛选正确联动。

## 非目标

- 不修改员工详情的默认日期范围。
- 不修改日期分配汇总的排序状态或记忆。
- 不持久化员工详情的排序方向。
- 不改变员工详情导出顺序、金额统计、考勤计算或分配结果。

## 排序状态

员工详情维护独立的页面级排序状态：

- 每次员工详情路由激活时将排序状态设为 `desc`；若同一详情组件被复用且员工 ID 发生变化，也必须重置为 `desc`，不依赖浏览器整页刷新。
- 不读取或写入 `localStorage`、`sessionStorage`、URL 参数或汇总页历史状态。
- 同一次详情页停留期间，用户切换日期范围或考勤状态后保留当前排序方向。
- 离开详情并重新进入任意员工详情时，排序恢复为 `desc`；从员工 A 直接切换到员工 B 时同样恢复为 `desc`。

## 数据流

1. 员工详情路由激活或详情上下文切换到不同员工 ID 时，初始化页面排序状态为 `desc`。
2. 详情快照提供 `dailyRows`、允许的日期范围及员工信息。
3. 日期范围和考勤状态先筛选出当前可见明细。
4. 对筛选后的新数组按稳定日期键排序，不原地修改快照中的 `dailyRows`。
5. `desc` 按日期从新到旧排列；`asc` 按日期从旧到新排列。
6. 排序完成的数组同时交给表格渲染；顶部汇总继续基于筛选结果计算，不受行顺序影响。

日期比较使用行数据中的 ISO `YYYY-MM-DD` 日期键。若防御性处理遇到相同日期，保持原始相对顺序；缺失或无效日期不参与正常日期比较并稳定置于有效日期之后，但不改变现有异常提示逻辑。

## 表头交互

日期列标题替换为可点击按钮，沿用日期分配汇总的表头排序样式：

- 默认显示“日期 ↓”。
- 倒序时日期表头设置 `aria-sort="descending"`。
- 顺序时显示“日期 ↑”，并设置 `aria-sort="ascending"`。
- 点击表头按钮切换 `asc`/`desc`，仅重新排序并渲染当前筛选结果。
- 按钮支持键盘聚焦，并可通过 Enter 或 Space 触发浏览器原生按钮点击。
- 按钮的可访问名称说明当前方向和点击后的目标方向；箭头设置 `aria-hidden="true"`。

## 筛选联动

- 日期范围或考勤状态变化时，先应用筛选，再应用当前详情页排序方向。
- 筛选变化不重置排序方向。
- 空结果继续展示当前空状态；表头仍保留当前排序方向。
- 重新激活详情路由或员工 ID 变化时才重置为倒序。

## 导出与汇总

本次排序仅影响页面列表。CSV、PDF 和邮件导出的字段、数据范围及顺序保持现有行为。顶部班次、手动工时、分配前、扣除、分配获得和实际获得继续根据筛选后的同一行集合汇总，不因升序或倒序改变数值。

## 验收标准

1. 每次进入员工详情，当前筛选范围内最近日期显示在第一行。
2. 日期表头默认显示倒序箭头并具有 `aria-sort="descending"`。
3. 点击日期表头后按日期顺序排列，并同步更新箭头与 `aria-sort`。
4. 再次点击恢复倒序。
5. 修改日期范围或考勤状态后保留本次页面当前排序方向，并对筛选后结果排序。
6. 离开并重新进入员工详情后恢复默认倒序，不继承上次选择；SPA 未整页刷新的导航同样适用。
7. 排序不修改快照原数组，不改变顶部汇总数值。
8. 无有效行时空状态正常，表头交互无报错。
9. 日期分配汇总的排序记忆、员工详情导出以及现有金额和考勤逻辑均不受影响。
10. 从员工 A 切换到员工 B 时重置为倒序；同一员工详情内仅修改日期范围或考勤状态时不重置。
