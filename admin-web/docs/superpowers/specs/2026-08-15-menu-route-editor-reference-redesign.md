# 菜单路由编辑器参考稿重设计

日期：2026-08-15  
状态：已获用户确认，待实现

## 1. 目标

把现有菜单路由配置页重设计为面向产品经理、测试和技术运维的可视化编辑工具。交互严格参考 `C:\Users\27273\Downloads\deepseek_html_20260815_782a21.html`，视觉风格参考项目内“屏保”和“薪资管理”页面。

本次解决第三方系统或其他项目新增页面后，无需研发手工编辑 JSON，即可把页面配置为商家后台的一级、二级或三级菜单并发布。

## 2. 设计边界

- 最多支持三级菜单。
- 一级、二级菜单允许仅作为目录容器，也允许配置自身页面。
- 三级菜单必须配置可打开的页面。
- 每个可打开节点只支持两种页面类型：项目内页面、iframe 嵌入。
- “仅支持”约束仅作用于新建节点和本次可编辑节点；加载到的旧 `external`、`micro-app` 或第四级节点必须只读展示并原样保留，不能在往返保存中丢失或转换。
- 保留保存草稿、保存并发布、放弃修改、导出 JSON。
- 不提供 JSON 导入或旧数据迁移。
- 交互参考 HTML 不作为数据格式参考。
- 导出的 JSON 继续遵守原 `edit jason.txt` 的字段白名单和省略逻辑，不新增 `parentId`、`title`、`component`、`sort`、`permission`、`isHidden`、`keepAlive`、`loadStrategy`、`iframeUrl` 等参考 HTML 的演示字段。

## 3. 页面结构

页面采用参考 HTML 的上下分区与左右主工作区，而不再使用当前三栏工作台。

### 3.1 顶部工具栏

- 左侧显示“菜单路由配置”及当前配置名称。
- 右侧依次提供保存草稿、保存并发布、导出 JSON。
- 显示当前状态：已保存、有未保存修改、校验失败或已恢复草稿。
- 发布前执行全量校验；有错误时阻止发布并定位首个错误节点。

### 3.2 左侧菜单树

- 固定宽度，独立滚动。
- 顶部提供搜索、全部展开、全部收起和新增一级菜单。
- 节点行显示名称、页面类型、隐藏状态和校验状态。
- 旧 `external`、`micro-app` 和第四级节点显示“兼容保留”标识；可以查看，但不可编辑、复制、移动或继续添加子节点。
- 节点悬停显示添加子菜单、编辑、复制和删除操作。
- 支持拖拽同级排序及调整父子关系；禁止超过三级、禁止拖入自身后代。
- 选中节点后，右侧显示只读摘要和快捷操作。

### 3.3 右侧节点详情

- 未选中节点时显示空状态和新增入口。
- 选中节点时显示名称、层级、Key、路径、有效页面类型、国际化、权限与显示设置摘要。
- 编辑操作始终打开独立弹窗，不在详情区直接修改，严格遵循参考 HTML 的新增/编辑模式。

### 3.4 底部商家后台预览

- 展示商家后台侧栏菜单结构，并同步高亮当前节点。
- 支持 zh-CN、zh-HK、en-US 三种语言切换。
- 预览只表达菜单层级、显示名称和页面打开方式，不实际加载外部地址或 iframe。
- 目录节点显示展开状态；可打开节点显示“项目内”或“iframe”标识。

## 4. 新增与编辑弹窗

新增一级菜单、添加子菜单和编辑节点复用同一弹窗组件，标题和提交文案随场景变化。

### 4.1 基本信息

- 菜单名称：映射 `name`。
- 节点 ID：映射 `id`，新增时自动生成，允许高级用户修改。
- Key：映射 `key`。
- 父级菜单：通过树结构决定，不导出额外字段。
- 图标：映射 `icon`。
- 多语言：映射 `i18nKey` 与 `i18nInfo`。

### 4.2 页面配置

一级、二级提供“仅目录 / 配置页面”开关；三级强制配置页面且不显示“仅目录”。

配置页面时提供分段按钮：

- 项目内页面：写入 `type: "inner"`，页面地址写入 `path`。
- iframe 嵌入：固定写入 `type: "iframe"`，商家后台承载路由写入 `path`，嵌入地址写入顶层 `url`；iframe 节点禁止生成 `microAppConfig`。

目录节点省略 `type`、`path`、`url` 和嵌入配置，并通过非空 `children` 表达层级。为了避免与原“缺失 `type` 时继承祖先类型”的规则冲突，本次同步收紧运行时判定优先级：节点具有非空 `children` 且自身没有 `path`、`url` 时，先判定为纯目录，不再继承祖先页面类型；只有节点自身存在页面地址时才允许继承祖先类型。该规则不增加 JSON 字段。

切换类型时不立即删除另一类型已有值；仅在提交弹窗时按目标类型清理不兼容字段，提交前给出说明。`inner` 提交后删除 `url` 和 `microAppConfig`；`iframe` 提交后保留 `path` 和顶层 `url`，删除 `microAppConfig`；切换为目录时删除 `type`、`path`、`url` 和 `microAppConfig`。

### 4.3 高级设置

- 权限配置映射 `accessControl`。
- 显示设置映射 `display`。
- 高级区域默认折叠，减少非研发用户的认知负担。
- 未出现在原 JSON 字段白名单中的参考 HTML 表单项不实现。

### 4.4 校验

- 名称、ID、Key 按原 JSON 规则校验。
- 三级节点必须选择类型并提供对应地址。
- 选择项目内页面时必须填写合法站内路径。
- 选择 iframe 时必须填写合法的 HTTP/HTTPS 地址，并配置商家后台承载路径。
- 重复 ID 或 Key 为错误，阻止发布。
- 重复路径为警告，允许发布。
- 最大层级、拖拽循环和非法父节点在交互发生时立即阻止。

## 5. 数据流与兼容性

1. 进入页面时优先加载共享草稿，否则加载当前发布版本。
2. UI 始终操作树形 `MenuDocument`，弹窗仅编辑当前节点的临时副本。
3. 点击确认后才把副本写回树，并重新执行校验。
4. 保存草稿更新共享草稿，不改变发布版本。
5. 保存并发布先保存、再通过版本条件发布；并发冲突继续使用现有 ETag/If-Match 处理。
6. 导出使用白名单序列化器，保持原 JSON 的字段名称、省略行为、显式 `false`/`null` 和字段顺序。
7. 旧 `external`、`micro-app` 和第四级子树进入兼容只读模式；允许编辑其他受支持节点并发布，但序列化器必须完整保留兼容子树的原白名单字段、层级和顺序。
8. 新增和拖拽操作不得产生新的第四级节点；包含兼容第四级后代的祖先不可被移动到更深层级。

## 6. 视觉规范

- 延续屏保页和薪资管理页的白色页面、浅灰背景、细边框、低阴影和紧凑密度。
- 主色沿用项目青绿色；危险操作使用红色，警告使用琥珀色。
- 卡片圆角、输入框高度、按钮层级、弹窗遮罩与表格/工具栏密度参考上述页面，不复制参考 HTML 的 Element 蓝色主题。
- 不使用渐变、重阴影或装饰性大标题。
- 关键操作固定在顶部工具栏和弹窗底部，滚动时保持可见。

## 7. 状态与错误处理

- 草稿恢复、保存成功、发布成功使用非阻塞状态提示。
- 删除包含子节点的菜单必须二次确认并明确影响数量。
- “放弃修改”只撤销当前浏览器中尚未保存的修改：有共享草稿时重新读取共享草稿，否则读取当前发布版本；它不删除共享草稿。若未来需要删除共享草稿并回到发布版本，应作为独立操作另行设计。
- 离开有未保存修改的页面触发离开确认。
- 仓储加载失败显示重试入口；并发发布冲突保留当前编辑内容并提示刷新对比。
- iframe 地址只做格式校验和安全提示，编辑器预览不发起第三方请求。

## 8. 验收标准

- 可新增一级、二级、三级菜单，且无法创建第四级。
- 一级、二级可以保存为目录；三级目录提交被阻止。
- 两种页面类型可正确切换并显示对应字段。
- 新增与编辑均通过独立弹窗完成。
- 菜单树支持搜索、展开/收起、复制、删除和拖拽。
- 底部预览同步层级、语言、选中态和页面类型。
- 保存草稿、发布、放弃、导出流程可用。
- 导出结果通过原参考 JSON 兼容性测试，且不包含新增业务字段。
- 原参考文件中的第四级节点、`external`、`micro-app` 节点在无修改加载并导出后保持字段、层级和顺序不变。
- 兼容只读节点不能被编辑、复制、移动、删除或添加子节点；其受支持兄弟节点仍可编辑并发布。
- 在带页面类型的祖先下新建纯目录时，运行时和预览均把它识别为目录，不继承为可点击页面。
- iframe 节点只生成 `type`、`path` 和顶层 `url` 等原允许字段，不生成 `microAppConfig`。
- `inner → iframe → 目录` 类型切换分别按规则清理不兼容字段，且取消弹窗不改变原节点。
- 放弃未保存修改时恢复共享草稿或发布版本，且不会删除共享草稿。
- 桌面端布局与屏保、薪资管理页面在颜色、边框、按钮、弹窗和信息密度上保持一致。
- 生产构建通过，浏览器控制台无错误。
