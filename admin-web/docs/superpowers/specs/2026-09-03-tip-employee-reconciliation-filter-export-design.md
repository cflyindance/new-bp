# 员工对账明细考勤筛选与导出设计

## 目标

在原生“小费管理 > 员工对账明细”页面增加考勤状态筛选，并支持 PDF、CSV、邮箱导出。所有筛选和导出只读取现有员工对账快照，不重新计算或修改小费分配结果。

## 已确认范围

- 考勤筛选只有三个选项：`全部状态`、`已打卡`、`未打卡`。
- 系统不存在“无需打卡”记录或状态。
- 行记录仅在 `clockStatus === '已打卡'` 时视为已打卡；缺失、非法值以及其他值统一视为未打卡。
- “CVS”按“CSV”文件导出实现。
- 导出内容严格使用当前日期范围与考勤状态共同筛选后的结果。

## 页面交互

### 筛选区

在现有起止日期控件右侧增加“考勤状态”下拉框，默认值为“全部状态”。

筛选顺序为：

1. 先按起止日期（包含边界日期）筛选员工逐日记录。
2. 再按考勤状态筛选。
3. 使用最终可见记录重新计算页面六项汇总指标并渲染明细表。

修改日期时保留当前考勤状态；重新进入员工明细页时恢复默认“全部状态”。

筛选后无记录时，六项汇总指标显示零值，表格区域显示“当前筛选条件下暂无对账明细”，不混用员工快照不存在的异常状态。

### 导出入口

在页面标题区右侧增加“导出结果”按钮，点击后展示三个操作：

- 导出 PDF
- 导出 CSV
- 发送至邮箱

当前筛选结果为空时不执行导出，并提示“当前筛选条件下没有可导出的数据”。

点击页面其他区域或选择一个导出操作后关闭菜单。

### 邮箱弹窗

复用当前小费汇总页的邮箱弹窗视觉与校验规则：

- 支持输入一个或多个邮箱地址。
- 支持选择 PDF 或 CSV 格式。
- 邮箱格式无效时阻止提交并显示错误提示。
- 提交时固化当前筛选快照，并按所选 PDF 或 CSV 格式生成同口径的待发送内容；发送过程不改变任何分配数据。
- 本项目当前没有真实邮件服务，本次沿用现有原型式发送交互：完成地址与格式校验后显示模拟发送结果，不宣称邮件或附件已实际送达。

## 导出内容

PDF 与 CSV 使用一致的数据列：

- 日期
- 考勤状态
- 班次 / 工时
- 分配前
- 扣除
- 分配获得
- 实际获得
- 分配状态

导出页眉包含员工姓名、角色、当前起止日期。门店不在页面明细中展示，但可继续作为导出元数据保留，不改变路由与现有快照结构。

文件名使用“员工姓名 + 起止日期”，并移除操作系统不允许的文件名字符。

PDF 优先使用浏览器打印输出，以保证中文员工名、角色、列名和状态可读；不走当前未嵌入中文字体的 jsPDF 文本绘制路径。

CSV 使用标准字段转义；对以 `=`、`+`、`-`、`@` 开头的文本字段增加安全前缀，避免表格软件将快照文本作为公式执行。

## 技术方案

采用现有导出能力复用方案：

- 在员工明细程序中增加统一的考勤状态归一化函数，并由表格展示、筛选、导出共同调用，避免状态口径不一致。
- 维护当前员工快照、当前筛选条件和当前可见行，汇总与导出均从同一份可见行数据生成。
- 复用现有 PDF 生成、CSV 下载、邮箱弹窗和通知基础能力；增加员工明细数据适配器和明细列定义，不改动日期任务汇总页的导出结构。
- 员工明细模板新增自身的导出菜单与邮箱弹窗 DOM，员工明细运行时加载现有导出基础脚本。
- 员工明细使用独立的数据收集与导出入口，不调用仅适用于日期任务汇总页的 `collectExportData` 或 `exportAs`；共享的菜单关闭、通知和校验能力保持兼容。

## 业务边界

- 不修改小费计算、分配、覆盖、考勤数据来源或员工快照生成逻辑。
- 不新增“无需打卡”状态。
- 不向后端写入筛选状态。
- 不修改旧 `TipOut` 项目，只修改原生页面实现。
- 本次不引入新的后端邮件服务；邮箱操作属于与当前项目一致的交互模拟，并在成功提示中使用“已提交发送”口径。

## 验收标准

1. 员工明细默认展示全部考勤记录，且不再出现“无需打卡”。
2. 选择“已打卡”或“未打卡”后，表格和六项汇总同步更新。
3. 缺失或非法 `clockStatus` 的记录归入“未打卡”。
4. 修改日期后保留考勤筛选，并按两项条件的交集更新页面。
5. PDF、CSV 均基于当前筛选结果，列与页面明细含义一致；PDF 中中文文本可读，CSV 文本完成转义和公式注入防护。
6. 邮箱弹窗基于当前筛选结果生成所选格式的待发送内容，正确完成地址与格式校验，并明确保持当前项目的模拟发送行为。
7. 员工明细视图包含独立导出菜单和邮箱弹窗，运行时依赖完整，且不会误调用日期任务汇总页的数据收集函数。
8. 空结果不可导出，提示明确。
9. 日期任务汇总页原有导出与小费分配业务逻辑不受影响。
10. 原生小费页面验证脚本与生产构建通过。
