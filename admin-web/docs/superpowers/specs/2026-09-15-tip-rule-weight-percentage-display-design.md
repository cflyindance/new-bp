# 小费规则员工权重换算百分比展示设计

## 背景

小费规则编辑器当前以数值权重配置员工间的相对分配关系。用户难以直观看出 `1`、`0.5`、`1.1` 的倍率含义，但直接将权重字段改成实际分配百分比会改变既有规则数据与计算语义。

## 目标

保留员工权重的数据结构和计算逻辑，在规则设置页面增加只读的“权重换算百分比”展示，帮助用户理解倍率，不产生第二套可编辑数据。

## 字段定义

| 字段 | 数据来源 | 是否可编辑 | 计算/展示规则 |
| --- | --- | --- | --- |
| 员工权重 | `employeeWeights` 中当前员工的权重值 | 是 | 保留当前录入、校验、保存和计算逻辑 |
| 权重换算百分比 | 当前员工权重派生 | 否 | `员工权重 × 100%`；`1 → 100%`、`0.5 → 50%`、`1.1 → 110%` |
| 员工分配比例 | 小费分配明细根据同组员工权重归一化后的实际结果 | 否 | 反映该员工在当前角色可分配金额中的最终占比，可能不同于权重换算百分比 |

“权重换算百分比”是倍率的等价表达，不要求同组员工合计为 100%，不参与新的计算，也不写入规则数据。百分比按十进制结果四舍五入至最多两位小数并去除无意义的末尾零，不使用科学计数法，例如 `0.3333 → 33.33%`、`0.125 → 12.5%`、`0 → 0%`。

## 页面与交互

员工权重弹窗的员工列表增加“权重换算百分比”列，位于“员工权重”右侧。

| 条件 / 状态 | 用户操作 | 系统行为 | UI 反馈 |
| --- | --- | --- | --- |
| 打开员工权重弹窗 | 查看员工行 | 从该行权重实时派生百分比 | 同行展示权重输入框和只读换算百分比 |
| 权重为 `1` | 查看 | 计算 `1 × 100%` | 展示 `100%` |
| 权重为 `0.5` | 查看 | 计算 `0.5 × 100%` | 展示 `50%` |
| 权重为 `1.1` | 查看 | 计算 `1.1 × 100%` | 展示 `110%` |
| 修改权重输入 | 输入有效数值 | 实时重新计算同一行的换算百分比 | 不需保存即可看到最新换算结果 |
| 权重为空、负数或不是有限数字 | 输入或清空 | 不参与换算 | 展示 `—`，沿用现有保存回退逻辑 |
| 保存员工权重 | 点击保存 | 仍仅写入 `employeeWeights` 权重值 | 保存结果和分配计算与改动前一致 |

本次不修改规则行中的员工权重摘要。派生百分比仅出现在员工权重弹窗中，不得标为“员工分配比例”。

## 数据与兼容性

- 不新增持久化字段，不迁移旧规则。
- 不修改 `employeeWeights` 的层级、键名或数值。
- 不修改按权重分配、归一化、金额尾差或员工分配比例算法。
- 已有规则打开后直接根据旧权重派生百分比。
- 旧规则缺少某员工权重时，继续复用现有默认有效权重 `1`，因此派生列展示 `100%`；展示层不得另建默认值。
- 派生列复用现有业务有效权重口径：数值必须有限且不小于 `0`。现有 `step=0.1` 仅作为输入控件的增减步长，不作为旧数据或派生展示的拒绝条件；因此旧规则中的 `0.3333` 等高精度权重仍可换算。输入过程中的空值、负数、`-`、`.`、`Infinity` 等无法形成有限非负数的状态展示 `—`。
- 复制、编辑、保存规则时只处理原权重，派生百分比不得回写。

## 验收要点

- 权重弹窗存在“员工权重”和“权重换算百分比”两个语义明确的字段。
- `1`、`0.5`、`1.1` 分别展示 `100%`、`50%`、`110%`。
- `0`、`0.3333`、`0.125` 分别展示 `0%`、`33.33%`、`12.5%`，不出现浮点尾数或科学计数法。
- 修改权重时同行百分比实时更新。
- 空值、负数及输入过程中的无效值展示 `—`，不出现 `NaN%` 或 `Infinity%`。
- 旧规则缺少员工权重时，输入框沿用默认值 `1`，换算列展示 `100%`。
- 多名员工的换算值只更新各自同行，互不覆盖。
- 保存前后的 `employeeWeights` 数据结构与数值完全不变。
- 复制或再次编辑规则后，序列化的 `employeeWeights` 与改动前逐字段一致，派生百分比不进入数据。
- 相同规则、员工与金额输入下，改动前后的最终分配金额一致。
- 页面不把“权重换算百分比”描述为实际“员工分配比例”。
