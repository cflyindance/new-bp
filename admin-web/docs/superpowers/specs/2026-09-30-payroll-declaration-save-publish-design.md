# 模板保存与发布交互调整

用户已确认：保存草稿成功后关闭编辑弹框；“审核并发布”改为“保存并发布”，无需先保存草稿；新增页面不展示当前状态。列表与已有模板详情的状态展示保留。

## 统一保存流程

两个按钮并列，分别触发 save-only 与 save-and-publish 模式，不是同时发送两个请求。共用字段及变量校验，校验失败保留弹框、输入和错误提示。提交期间锁定两按钮与编辑字段，防止重复点击。

新模板依次创建 family、保存草稿；已有草稿原位更新，不重复创建版本。创建新版本沿用现有流程。保存并发布在草稿保存成功后，使用该次返回的 versionId 和本次保存后的 family revision 发布；不得发布旧正文或旧草稿版本。

保存草稿成功后关闭编辑弹框，刷新列表并保留筛选，提示“草稿已保存”。保存并发布成功后关闭弹框，刷新列表，提示“模板已保存并发布”。弹框关闭后焦点回列表新增按钮；若筛选隐藏新状态，保留筛选不擅自重置。

## 分步失败

保存失败不发布，保留输入。family 已创建而草稿失败时保留 familyId 供重试，避免重复模板。

草稿成功、发布失败时保留编辑弹框，明确“草稿已保存，但发布失败：原因”，保留版本 ID 和最新已知 revision；允许重试或另行保存草稿。并发冲突不得自动覆盖他人更新，要求刷新后处理。输入与成功保存的草稿不能因刷新失败丢失。

发布已成功但列表刷新失败时，不报告“发布失败”，应提示发布成功、列表刷新失败，并允许重新加载。相同原则适用于仅保存草稿。关闭/切换组织门店后旧响应不污染新页面。已有已发布与已停用只读边界不变。

## 范围与验收

仅调整 settings 控制器、按钮文案和新增页面状态字段；使用现有草稿/发布 repository，不改权限、员工关联、历史快照或计算逻辑。

自动化覆盖：无模板直接保存并发布、已有草稿修改并发布、单独保存关闭、重复点击保护、校验失败、保存失败、发布失败、刷新失败、切换范围失效回调。renderer 验证新增无状态字段、详情仍有状态、旧按钮文案消失。浏览器使用独立验收模板验证保存关闭与直接发布，不删除用户模板。

此补充规格覆盖旧流程中“先保存草稿再审核发布”的交互要求，其余状态操作规则不变。
