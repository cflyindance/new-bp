# 数量与频次规则参与门店下拉设计

## 目标

统一“商品配置”和“限购数量”两个步骤中的门店表达：商品配置明确门店是规则的参与门店；限购数量用单选下拉切换参与门店，不再使用横向门店 Tab。

## 商品配置

第 2 步“商品配置”的门店字段保持现有原生单选下拉和全部门店选项，仅调整可见文案：

- 字段标签由“配置门店”改为“参与门店”。
- 空选项由“请选择配置门店”改为“请选择参与门店”。
- 数据字段、商品搜索、商品选择和按门店独立保存逻辑保持不变。

选择某家门店并为其选择商品后，该门店进入可配置数量的参与门店集合。仅选择门店但未选择商品，不构成可配置数量的参与门店。

## 限购数量

第 4 步“限购数量”继续保留“配置门店”字段含义，但将当前的门店 Tab 替换为原生单选下拉：

- 字段标签为“配置门店”。
- 下拉选项只来自 `addedStoreIds(draft)`，即已经在商品配置中选择了商品的门店。
- 下拉当前值继续使用 `draft.activeStoreId`。
- 不展示未选择商品的门店，也不提供禁用空门店选项。
- 正常进入第 4 步时至少已有一家参与门店；如状态异常导致没有参与门店，显示禁用的“暂无参与门店”占位，不渲染可误操作的空数量矩阵。

进入第 4 步时，如果 `activeStoreId` 不在参与门店集合中，沿用 `normalizeActiveDimensions(draft, true)` 自动选择第一家参与门店。渲染前记录原活动门店；归一化后如门店发生变化，必须同步退出批量模式并清空批量勾选，防止相同目标 ID 在不同门店间错误映射。

当参与门店集合为空时，归一化必须将 `activeStoreId` 和 `activeLineId` 都清空，并退出批量模式。第 4 步只显示禁用的“暂无参与门店”占位，不渲染产线 Tab、批量设置入口或数量矩阵。

## 切换行为与数据边界

限购数量门店下拉发生 `change` 时：

1. 仅接受参与门店集合中的门店 ID。
2. 清空并退出批量设置状态，避免上一门店的临时勾选带入下一门店。
3. 更新 `draft.activeStoreId`。
4. 调用 `normalizeActiveDimensions(draft, true)`，将活动产线归一化为新门店已有产线。
5. 重新渲染当前步骤，展示新门店自己的产线、商品和数量矩阵。

除手动 `change` 外，任何归一化路径只要实际改变了 `activeStoreId`，同样必须退出批量模式并清空批量勾选。自动选择第一家门店与手动选择门店使用相同的数据隔离规则。

切换操作不修改 `storeConfigs` 中任何门店的商品范围和数量数据，不修改 `deployStoreIds` 或 `deployExcludedStoreIds`，也不新增持久化字段。各门店数据继续独立保存。

## 结构与样式

- 商品配置继续使用现有 `.olf-config-store-select` 结构和样式。
- 限购数量增加独立的门店字段类与 `data-limit-store-select` 事件标记，复用 `.olf-select` 控件样式。
- 删除第 4 步门店 Tab 的渲染和 `data-limit-store-tab` 事件入口。
- 不修改人数、轮次和产线 Tab；这些维度仍使用现有 Tab 交互。

## 验证

- 更新现有门店独立配置验证，断言第 4 步使用 `data-limit-store-select`，且不再渲染 `data-limit-store-tab`。
- 断言第 2 步显示“参与门店”和“请选择参与门店”，不再显示原门店字段文案。
- 断言第 4 步下拉只由 `addedStoreIds(draft)` 生成选项。
- 断言门店下拉切换会清空批量状态、更新 `activeStoreId`、归一化活动维度并重新渲染。
- 断言自动归一化导致门店变化时同样清空批量状态。
- 断言无参与门店时活动门店和产线均为空，并隐藏产线、批量入口与数量矩阵。
- 执行 JavaScript 语法检查、全部数量与频次专项脚本、生产构建和本地浏览器验收。

浏览器验收至少覆盖两个拥有不同产线且可含相同目标 ID 的参与门店，分别验证手动切换、自动归一化和无参与门店三种路径不会串用数量矩阵或批量勾选。

## 非目标

- 不改变商品配置中可浏览的全部门店范围。
- 不改变“生效范围”步骤的生效门店勾选逻辑。
- 不改变商品范围、数量矩阵、草稿或发布快照的数据模型。
- 不把人数、轮次或产线 Tab 改为下拉。
