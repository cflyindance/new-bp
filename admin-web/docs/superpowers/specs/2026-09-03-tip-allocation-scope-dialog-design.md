# 小费分配范围弹窗设计

## 目标

在原生“小费管理 > 小费分配汇总”中，将“分配小费 / 重新分配小费”改为先选择门店和日期范围，再调用现有分配流程。分配算法、规则来源、结果存储和薪资同步逻辑保持不变。

## 已确认方案

采用居中模态弹窗。点击页面主操作按钮只打开弹窗，不立即执行分配。弹窗默认带入页面当前门店、开始日期和结束日期，允许用户修改后提交。

## 弹窗结构

- 标题：“分配小费”。
- 关闭按钮，带“关闭分配小费弹窗”可访问名称。
- 说明：“如果选择的日期已经分配过小费，新的分配结果会覆盖旧的结果。”
- 门店下拉框。
- 必填开始日期。
- 必填结束日期。
- 次操作：“取消”。
- 主操作：“分配小费”。

## 打开与关闭

- 点击现有 `#allocateBtn` 打开弹窗。
- 每次打开均从页面 `#storeSelect`、`#dateStart`、`#dateEnd` 重新读取默认值，不沿用上次取消时的草稿。
- 关闭按钮、取消按钮、遮罩点击和 `Esc` 均关闭弹窗，不执行分配、不修改页面筛选和已分配状态。
- 打开时焦点进入门店选择；关闭后焦点返回 `#allocateBtn`。

## 校验

- 门店、开始日期、结束日期均为必填。
- 日期使用本地业务日期 `YYYY-MM-DD`，起止均包含。
- 开始日期晚于结束日期时阻止提交，并在日期区域展示错误提示。
- 校验失败时不关闭弹窗、不修改页面筛选、不执行分配。

## 提交与数据流

1. 通过校验后，把弹窗的门店、开始日期和结束日期写回页面现有三个筛选控件。
2. 关闭弹窗。
3. 调用抽取后的现有分配执行函数；该函数继续执行规则存在校验、缓存失效、日期标记、列表刷新、薪资同步和成功提示。
4. 若选择范围包含已分配日期，直接覆盖该范围结果，不显示第二个确认框。
5. 页面刷新后展示弹窗所选门店和日期范围的结果。

## 失败场景

- 没有分配规则：沿用现有错误提示与规则页跳转行为；弹窗提交本身不绕过该校验。
- 分配执行发生既有异常：沿用现有错误处理，不新增数据回滚策略。

## 兼容性边界

- “取消分配”继续直接作用于页面当前筛选范围，不纳入本次弹窗。
- 日期任务与员工对账继续共享页面筛选和逐日数据。
- 分配完成后的薪资同步使用弹窗最终选择的门店和日期。
- 不修改旧 `dist/TipOut` 页面。

## 验收

- 主操作按钮点击后只打开弹窗，未提交前已分配日期集合不变。
- 弹窗默认值与页面筛选一致；取消后重开会再次读取页面筛选。
- 关闭、取消、遮罩与 `Esc` 均无数据副作用，焦点正确返回。
- 空门店、空日期、倒置日期均无法提交并显示明确错误。
- 有效提交后页面筛选同步，所选闭区间完成分配，已有结果直接覆盖且无二次确认。
- 薪资同步收到弹窗最终门店和日期参数。
- 现有规则缺失行为、取消分配、日期任务、员工对账和未分配金额展示回归测试保持通过。
- 原生页面验证脚本与生产构建成功退出。
