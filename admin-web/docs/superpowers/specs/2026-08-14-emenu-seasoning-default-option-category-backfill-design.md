# eMenu 调味系统示例 Option 默认分类补充设计

## 1. 背景与目标

新建的调味数据库已经把系统示例 Option 分配到“香辛料、基础调味、酱料”。旧门店数据库升级分类功能时，现有 Option 会统一进入“未分类”，导致“添加 Option”弹窗中的三个默认分类没有可选数据。

本次增加一次幂等的数据补充：仅识别系统示例 Option，并在它仍处于“未分类”时按照固定编码写入默认分类。页面结构、Option 选择交互、门店自建 Option 和已完成的人工分类均不改变。

## 2. 采用方案

采用固定系统 Option ID 与编码的双重映射，不使用名称关键词推断，也不重建整套调味数据。

固定 ID 与编码组合比名称稳定，不受中英文名称修改影响，也不会把复用相同编码的门店自建记录误认为系统示例；限制为“当前仍处于未分类”并且“迁移尚未执行”可以保护门店人工配置。该补充在数据库标准化阶段只评估一次。

## 3. 默认映射

| 默认分类 | 系统示例 Option ID / 编码 |
| --- | --- |
| 香辛料 | `o-cilantro / CILANTRO`、`o-scallion / SCALLION`、`o-garlic / GARLIC`、`o-chili / CHILI`、`o-pepper / BLACK_PEPPER`、`o-ginger / GINGER`、`o-onion / ONION`、`o-cumin / CUMIN` |
| 基础调味 | `o-peanut / PEANUT`、`o-salt / SALT`、`o-sugar / SUGAR`、`o-vinegar / VINEGAR`、`o-sesame / SESAME` |
| 酱料 | `o-soy / SOY_SAUCE`、`o-sesame-oil / SESAME_OIL`、`o-mustard / MUSTARD`、`o-mayo / MAYO`、`o-ketchup / KETCHUP`、`o-hot-sauce / HOT_SAUCE`、`o-cheese / CHEESE` |

ID 必须精确匹配，编码比较使用标准化后的大写值；只有两者同时匹配才视为系统示例。仅 ID 或仅编码命中的记录继续保留在“未分类”。

## 4. 数据处理规则

数据库增加持久化迁移标记 `migrations.defaultOptionCategoryBackfillV1`。数据库加载时先执行现有基础校验；仅当该标记不是 `true` 时，按以下顺序执行一次性补充：

1. 校验并创建缺失的三个默认分类与系统“未分类”，遵循下述编码冲突规则。
2. 把分类引用缺失或无效的 Option 归入“未分类”。
3. 遍历当前位于“未分类”的 Option；固定 ID 与编码同时命中映射，并且目标分类处于启用状态时，将其 `categoryId` 更新为目标默认分类。
4. 其他 Option 不做任何修改，并把迁移标记写为 `true`，表示已完成评估。

三个默认分类继续保持普通门店分类语义，迁移完成后允许按现有规则停用或在无引用时删除。迁移标记为 `true` 后，标准化流程不得重建已被管理员删除的默认分类、不得重新启用已停用分类，也不得再次自动移动 Option。新建种子数据库预置该标记为 `true`。

默认分类使用固定 ID 与固定 code。迁移尚未执行时：

- 固定 ID 与 code 均存在且对应同一分类时，使用该分类并保留其名称和启停状态。
- 固定 ID 缺失且固定 code 未被占用时，创建缺失的默认分类。
- 固定 ID 缺失但固定 code 已被其他 ID 占用时，不得创建重复 code，也不得把系统 Option 移入占码的门店分类；记录该分类冲突，对应 Option 保持“未分类”，迁移继续完成。
- 固定 ID 已存在但 code 与固定值不一致时，不自动改写该普通分类；将其视为默认分类冲突并跳过对应 Option 的回填。

系统“未分类”使用固定 `id = option-category-uncategorized` 与 `code = UNCATEGORIZED`。它是安全回退目标，不能借用其他 ID 的同码分类。固定 ID 存在、固定 code 未被其他分类占用时，可以恢复该系统分类的固定 code 与受保护属性。若固定 ID 缺失但 code 已被其他分类占用，或者固定 ID 存在但固定 code 已被其他 ID 占用，迁移必须以 `option_category_migration_conflict` 失败；不得写迁移标记、不得提升版本、不得写审计、不得修改原数据库文件，也不得回退到全新种子数据。

仅以下条件同时满足时允许回填：

- Option 当前分类为系统“未分类”，或旧数据在同一次标准化中刚被归入“未分类”。
- Option 的固定 ID 与编码同时命中系统示例映射。
- 目标默认分类的固定 ID 与 code 正确对应且处于启用状态。

以下数据不得被移动：

- 已属于任意有效分类的 Option，包括门店手工创建的分类。
- 编码未命中的门店自建 Option。
- 门店自建 Option 即使名称或编码与系统示例相同，但 ID 与编码组合不完全一致。

Option 的启用状态、名称、价格、排序以及商品动作关联均保持不变。

## 5. 幂等性与审计

分类创建、无效引用修复、系统示例回填和迁移标记写入属于同一次分类标准化事务。迁移尚未评估时，即使没有可移动 Option，也必须持久化“已评估”标记，避免后续覆盖人工操作。本轮事务只允许：

- 配置版本相对加载前整体提升一次。
- 相对加载前追加一条现有 `migrate_option_categories` 审计记录，审计详情包含 `defaultOptionCategoryBackfillV1: true`、实际移动数量和普通默认分类冲突列表；没有冲突时列表为空。
- 持久化数据库一次。

第二次及后续加载以迁移标记为准，不再执行补充，不重复提升版本，也不重复写入审计。管理员之后把系统示例 Option 手工移回“未分类”，仍须保持该选择。

本次不新增人工触发按钮、不新增 API，也不允许通过该迁移覆盖人工分类。

## 6. 失败与兼容处理

- 迁移尚未执行且目标默认分类缺失、固定 code 也未被占用时，标准化流程创建该分类后再执行回填；迁移完成后不得自动重建。
- 迁移尚未执行但目标默认分类已被停用时，保留停用状态，对应系统 Option 留在“未分类”，迁移仍标记为已评估。
- 普通默认分类发生 ID/code 冲突时，跳过该分类的创建和回填，迁移仍标记为已评估；审计详情记录冲突分类 code 与占用者 ID，便于后续人工处理。
- 系统“未分类”发生 ID/code 冲突时中止加载，不产生任何迁移写入。
- Option 缺少编码、编码为空或编码未知时，保持在“未分类”，数据库仍可正常加载。
- 若旧库存在重复编码，仅固定 ID 与编码均匹配的系统记录允许回填；其他同码记录留在“未分类”。本次不承担重复数据清理。
- 迁移持久化必须使用现有原子写。写入或替换失败时，保留原数据库文件、让本次加载失败并返回服务端错误；不得捕获该异常后以内存中的全新种子数据库继续服务。

## 7. 验收与测试

自动化验证至少覆盖：

1. 无分类字段的旧数据库升级后，`o-cilantro / CILANTRO`、`o-salt / SALT`、`o-soy / SOY_SAUCE` 分别进入三个默认分类。
2. 全部固定系统示例 ID 与编码组合均进入表格规定的分类。
3. 未知编码的门店自建 Option 保留在“未分类”。
4. 已手工放入其他有效分类的系统编码 Option 不被移动。
5. Option 状态、排序及动作关联在回填前后不变。
6. 同编码但不同 ID 的门店记录，以及同 ID 但编码已变更的记录，均不被移动。
7. 本轮第一次评估相对加载前只提升一次版本并追加一条迁移审计；第二次加载版本和审计数量不变，不依赖历史审计总数。
8. 迁移完成后把系统示例 Option 人工移回“未分类”，再次加载不会自动移走。
9. 迁移完成后删除无引用默认分类或停用默认分类，再次加载不会重建或重新启用。
10. 迁移前目标分类已停用时，对应 Option 保持“未分类”，分类状态保持停用，迁移标记仍完成。
11. 新建数据库预置迁移标记，分类结果与旧数据库回填结果一致。
12. 模拟迁移原子写失败时，原数据库内容保持不变，请求返回错误，不能返回全新种子数据。
13. 默认分类固定 ID 缺失但固定 code 被其他 ID 占用时，不产生重复 code、不移动对应 Option，迁移完成且审计记录冲突。
14. 默认分类固定 ID 存在但 code 不匹配时，不改写该分类、不移动对应 Option，迁移完成且审计记录冲突。
15. 系统“未分类”固定 ID/code 被不同分类占用时，迁移失败且数据库、版本、审计和迁移标记均保持原样。
16. “添加 Option”弹窗加载后，三个启用且无冲突的默认分类展示对应 Option，“未分类”只展示未命中或因冲突未迁移的数据。

## 8. 非目标

- 不根据 Option 名称自动猜测分类。
- 不自动归类门店后续新建的 Option。
- 不增加批量移动分类或自动整理入口。
- 不调整“类 + Option”选择器的视觉与交互。
