# eMenu 商品划线价配置设计

## 背景与目标

eMenu 前端已经读取并展示商品的 `strikethroughPrice`，商品卡片、商品详情和价格列表均已有划线价展示能力，但配置后台没有面向运营人员的维护入口。

本功能在 eMenu 配置后台新增独立的【商品划线价】业务页，让有权限的用户按“商品组 / 商品类 / 菜”选择商品，批量设置、逐项调整或清除划线价，并安全保存及下发到 eMenu。

## 已确认的信息架构

- 【商品划线价】与【设置】同级，位于【设置】菜单正下方。
- 【商品划线价】是独立业务页面，不属于【设置】的子页面。
- 面包屑为 `eMenu / 商品划线价`。
- 路由、权限、保存流程和操作记录独立管理，不接入普通开关型设置项的保存逻辑。

## 范围

### 本期包含

- 按商品组、商品类和商品选择配置对象。
- 跨组、跨类、跨页和跨搜索结果保留选择。
- 批量设置统一划线价。
- 批量清除划线价。
- 批量操作后逐个调整商品划线价。
- 预览实际变更后批量保存和下发。
- 服务端校验、并发冲突处理、事务写入、下发重试及操作记录。

### 本期不包含

- 规格级或多价格项的独立划线价。
- 根据折扣率自动反推划线价。
- 定时或周期性改变划线价。
- 修改商品售价、促销价、会员价或订单计价逻辑。
- 将派生折扣率作为独立业务字段持久化。

## 核心流程

页面采用三步向导：

1. 选择商品。
2. 设置划线价。
3. 确认保存。

返回上一步时保留选择和编辑草稿。存在未保存修改时，离开页面需要二次确认。

## 第一步：选择商品

### 选择结构

复用现有“组 / 类 / 菜”三级选择模式：

- 第一列为商品组。
- 第二列为当前商品组下的商品类。
- 第三列为当前商品类下的商品。
- 商品组和商品类支持整组勾选，并显示全选、半选和未选状态。
- 商品以唯一商品 ID 去重；同一商品出现在多个菜单结构中时只选择和提交一次。

### 商品信息与筛选

商品行展示：

- 商品名称。
- 商品编号。
- 当前售价。
- 当前划线价。
- 可配置状态及不可配置原因。

页面支持：

- 按商品名称或编号搜索。
- 筛选全部、已设置划线价、未设置划线价。
- 跨页、切换组类和搜索后保留已选商品。
- 持续展示“已选 N 个商品”。
- 打开已选清单并移除商品。

已停用、已删除或不可用于 eMenu 的商品不可选择，并显示原因。

## 第二步：设置划线价

### 编辑表格

表格列为：

`选择 | 商品 | 当前售价 | 当前划线价 | 新划线价 | 折扣预览 | 状态 | 操作`

### 批量操作

- 【批量设置】：输入统一划线价，应用到当前勾选行；默认勾选全部已选商品。
- 【批量清除】：将当前勾选行的新划线价置空，保存后 eMenu 不再展示划线价。
- 批量操作后仍允许逐行编辑或清空“新划线价”。
- 每行提供【恢复原值】，仅撤销该行尚未保存的修改。

### 展示预览

编辑后实时展示价格效果及派生折扣。例如售价 `$28.00`、划线价 `$40.00` 时，展示为 `7.0 折`。

折扣值只用于预览，由售价与划线价派生，不单独保存。

### 校验规则

- 新划线价为空表示清除。
- 非空金额必须大于 0、最多两位小数，且不超过 `9,999,999.99`。
- 非空划线价必须严格大于该商品当前售价。
- 不合法行就地显示错误原因。
- 存在任意错误行时不能进入确认页。
- 未发生变化的商品不进入预览和最终提交。
- 进入第三步前由服务端按最新商品数据重新校验；售价变化导致规则不再满足时，返回最新值和错误并要求修改。

金额必须用最小货币单位或规范十进制运算，不得用二进制浮点数直接比较或计算。

## 第三步：确认保存

确认页只显示实际发生变化的商品，并按以下类型汇总数量：

- 新增划线价。
- 修改划线价。
- 清除划线价。

每行展示商品、当前售价、原划线价、新划线价和折扣预览。

用户确认后执行一次批量保存，不允许只保存其中一部分。

## 数据模型

沿用既有字段 `strikethroughPrice`，不新增同义字段：

- 有效金额：eMenu 同时展示当前售价和划线价。
- `null`：清除划线价，eMenu 只展示当前售价。

客户端和接口使用规范十进制字符串表达金额，例如 `"39.90"`。服务端在领域层转换为最小货币单位或等价的精确十进制类型。商品级划线价允许范围为 `0.01` 至 `9,999,999.99`；货币仍沿用商品所属商户或门店的既有币种，不允许在本页面切换币种。

第一期只维护商品主售价对应的商品级 `strikethroughPrice`。若商品存在规格或多个售价，规格级划线价不在本期范围内，也不得将商品级值隐式复制成多个规格级值。

## 接口设计

### 查询商品

`GET /emenu/strikethrough-prices/products`

查询参数支持商品组、商品类、关键词、配置状态、游标或页码。响应至少包含商品唯一 ID、名称、编号、当前售价、现有划线价、数据版本、可配置状态和不可配置原因。

### 预览变更

`POST /emenu/strikethrough-prices/preview`

请求按商品表达最终目标值：

```json
{
  "changes": [
    { "productId": "p-101", "expectedVersion": "v17", "strikethroughPrice": "39.90" },
    { "productId": "p-102", "expectedVersion": "v08", "strikethroughPrice": null }
  ]
}
```

`expectedVersion` 必须使用第一步商品查询返回的数据版本。服务端在生成预览前比较该版本与当前商品版本；只要售价、划线价或可配置状态在用户编辑期间发生变化，就将该商品归入并发冲突或不可配置项，不得用服务端最新值替换请求基线后继续生成可提交预览。

服务端重新读取商品并返回：

- 新增、修改、清除和未变化项。
- 最新售价与最新划线价。
- 不可配置项及原因。
- 并发冲突项。
- 可用于最终提交的短期预览令牌或等价版本凭据。

### 批量保存

`POST /emenu/strikethrough-prices/batch`

请求携带预览令牌或等价版本凭据及幂等键。服务端不能信任客户端自行计算的折扣或旧价格，必须再次确认预览仍有效后再写入。

### 重新下发

`POST /emenu/strikethrough-prices/deployments/{batchId}/retry`

仅允许对“价格已保存、下发未成功”的批次重试。请求携带新的重试幂等键；相同幂等键不得重复创建任务，同一批次已有进行中的下发任务时返回现有任务状态。重试只读取已保存的批次快照并下发，不重新写入商品划线价。

## 保存、并发与下发

### 保存事务

1. 按商品 ID 读取最新商品状态、售价、划线价和版本。
2. 校验商品存在、可配置、金额格式合法且划线价严格大于售价。
3. 检查预览版本，发现其他用户已修改同一商品时返回冲突，不静默覆盖。
4. 在一个事务中写入全部有效变更。
5. 写入操作记录并创建 eMenu 下发任务。
6. 返回保存状态和下发状态。

任何数据库写入失败都必须整批回滚。重复保存请求使用幂等键避免重复写入和重复创建下发任务。

### 下发失败

保存成功但 eMenu 下发或缓存刷新失败时：

- 不回滚已经成功保存的价格配置。
- 页面显示“已保存、下发失败”。
- 提供【重新下发】。
- 重试仅重建或重试下发，不重复修改商品价格。

## 权限与审计

权限拆分为：

- 查看商品划线价。
- 管理商品划线价。
- 查看操作记录。

“管理商品划线价”同时授权预览、保存、保存后的自动下发以及失败后的重新下发。本期不提供“只保存、不下发”模式，也不拆分单独的下发权限；用户没有管理权限时页面只读。服务端必须执行同等鉴权，不得只依赖前端禁用控件。

操作记录包含：

- 操作人和操作时间。
- 品牌、商户或门店范围。
- 商品 ID、商品名称。
- 原划线价和新划线价。
- 请求幂等键或批次标识。
- 保存结果和下发结果。

## 异常处理

- 商品已删除、停用或不再属于可配置范围：阻止该商品提交并说明原因。
- 商品售价变化：使用最新售价重新校验，失败项返回第二步修改。
- 商品划线价被并发修改：返回原草稿值和服务端最新值，由用户重新确认。
- 预览令牌过期：保留客户端草稿，重新发起预览。
- 校验失败：不写入任何商品，保留页面草稿。
- 数据库失败：事务回滚，允许使用相同草稿重试。
- 下发失败：保存结果保留，允许单独重试下发。

## 验收标准

1. 【商品划线价】位于【设置】正下方，二者同级。
2. 面包屑为 `eMenu / 商品划线价`。
3. 可跨商品组、商品类、分页和搜索结果选择多个商品，选择不丢失。
4. 父级选择正确呈现全选、半选和未选状态。
5. 同一商品出现在多个菜单结构时只选择、预览和提交一次。
6. 批量设置统一价格后可修改单个商品价格。
7. 可对全部或部分商品批量清除划线价。
8. 划线价为空表示清除；小于或等于售价时禁止继续。
9. 金额精度、`0.01` 与 `9,999,999.99` 边界、超出范围和其他非法输入得到明确提示。
10. 确认页只展示实际变更，并正确区分新增、修改和清除。
11. 商品停用、删除、售价变化或划线价并发变化时不静默覆盖。
12. 批量写入失败时整批回滚。
13. 保存成功而下发失败时可单独重试下发。
14. 保存并同步后，eMenu 商品卡、详情和价格列表正确展示或移除划线价。
15. 无编辑权限的账号无法通过页面或接口提交。
16. 操作记录能还原每个商品的修改前后值及下发结果。

## 测试策略

- 领域单元测试：金额解析、精度、边界、划线价与售价比较、折扣派生、去重和变更分类。
- 组件测试：三级选择、半选状态、跨页保留、部分批量操作、逐行覆盖、清除和恢复原值。
- 接口测试：鉴权、预览、事务回滚、幂等、并发冲突和过期预览。
- 集成测试：保存后创建下发任务、下发失败重试、操作记录完整性。
- eMenu 回归测试：无划线价、有效划线价、清除划线价在商品卡、详情和价格列表中的展示；订单计价不受影响。
- 浏览器验收：桌面布局、窄屏重排、键盘操作、错误聚焦、未保存离开保护和只读权限状态。

## 已知现状依据

现有 eMenu 菜单转换逻辑已经读取 `strikethroughPrice` 并计算展示折扣；商品卡、商品详情及价格列表也已按该字段渲染划线价格。因此本设计把工作重点限定在配置入口、批量编辑、持久化与下发，不重复建设终端展示模型。
