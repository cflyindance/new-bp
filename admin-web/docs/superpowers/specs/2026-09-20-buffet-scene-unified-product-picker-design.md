# 自助餐当前场景统一商品范围选择器设计

## 1. 目标

“配置额度”页中的当前场景商品/分类范围使用与规则主入口“添加商品”一致的选择交互。用户既可以勾选新对象，也可以取消已选对象；变更只作用于当前门店、当前人数与轮次场景。按菜品和菜品集限购采用“产线 → 组 → 类 → 菜”四级结构；按分类限购采用统一选择器现有的“产线 → 组 → 类”结构。

## 2. 适用范围

- 按菜品限购：选择器叶子层级为“菜”。
- 按分类限购：选择器叶子层级为“类”。
- 按菜品集限购：选择器叶子层级为“菜”，添加后成为当前场景菜品集成员。
- 适用于整单、每轮、分轮次，以及人数区间与轮次区间组合形成的所有额度场景。

## 3. 页面结构

弹窗标题根据规则对象显示为“选择当前场景商品”或“选择当前场景分类”。弹窗包含：

1. 当前参与门店：展示当前额度场景所属门店，只读，不允许在弹窗内切换。
2. 搜索框：搜索当前门店全部产线中的商品或分类。
3. 商品选择区域：按菜品和菜品集限购依次展示产线、组、类、菜。
4. 分类选择区域：按分类限购依次展示产线、组、类，不展示“菜”列，与主入口分类选择保持一致。
5. 底部操作：取消、确认并返回配置。

视觉、间距、选中态、数量标记和按钮样式直接复用主入口“添加商品”弹窗。

## 4. 选择交互

- 产线采用单选导航，切换后展示该产线下的组、类、菜。
- 组、类、菜支持逐级选择，父级选择状态与下级商品联动。
- 按分类限购时，在“类”层完成选择，不要求继续选择具体菜品。
- 搜索结果仍保留所属产线、组、类信息，选择结果与当前模式的层级结构同步。
- 当前场景已有对象默认保持选中，但允许取消勾选。
- 取消勾选表示从当前场景删除该对象；重新勾选表示保留或重新加入当前场景。
- 其他场景已经使用、但当前场景尚未使用的对象仍可选择。

## 5. 数据范围与保存

- 选择器以当前门店菜单目录为候选范围。
- 提交结果以弹窗最终勾选范围覆盖当前门店、当前人数区间、当前轮次区间对应的场景范围。
- 新增对象的数量额度默认为未配置，用户返回额度页后继续填写。
- 被取消勾选对象在当前场景中的商品额度、整桌兜底额度或同菜品例外额度一并删除。
- 不修改该门店其他场景，也不修改其他门店。
- 取消或关闭弹窗时不保存本次选择。
- 保存额度场景后，新增对象及其额度随草稿保存；刷新后保持不变。

## 6. 规则约束

- 点击“确认并返回配置”时，按菜品或分类限购至少保留一个有效对象，否则停留在选择器并提示。
- 点击“确认并返回配置”时，按菜品集限购至少保留两个有效成员，否则停留在选择器并提示；保存额度场景时继续保留同一校验作为防御。
- 已从当前场景删除的对象可再次通过选择器添加。
- 商品不存在或不属于当前门店菜单时，不允许写入场景范围。
- 添加对象时不得覆盖当前场景中其他对象已有的额度。

## 7. 组件与数据流

1. 场景额度弹窗提供当前门店、规则对象类型及当前场景范围。
2. 统一商品选择组件读取当前门店的 `structureByLine` 菜单结构。
3. 组件以当前场景已选对象初始化选中状态，所有对象均可勾选或取消。
4. 用户提交后，组件返回最终选中对象集合。
5. 场景处理逻辑计算新增与删除对象：新增对象额度为空，删除对象同步清除当前场景额度，然后重新渲染额度弹窗。

主入口和场景入口共用菜单树渲染、选择联动、搜索和结果转换逻辑，场景入口只负责范围隔离和提交目标。

## 8. 验收标准

- 按菜品和菜品集限购展示“产线、组、类、菜”，按分类限购展示“产线、组、类”，布局与主入口对应模式一致。
- 菜品、分类和菜品集三种限购对象均使用正确叶子层级。
- 父子选择、半选状态、搜索和数量统计行为与主入口一致。
- 已有对象默认选中且可以取消；取消后只从当前场景删除。
- 不同人数、轮次及组合场景可维护不同对象范围。
- 不同门店的场景对象互不影响。
- 新增对象额度默认为未配置，保留对象额度不被覆盖，被删除对象的当前场景额度被清除。
- 保存草稿并刷新后，场景对象与额度保持一致。
- 取消和关闭弹窗不产生数据变更。
- 浏览器控制台无新增错误，相关自动化测试通过。
