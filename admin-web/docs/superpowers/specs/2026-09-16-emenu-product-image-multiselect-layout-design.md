# eMenu Pro 商品图片组件与多选排版设计

> 模块：前厅管理中心 → eMenu Pro
>
> 日期：2026-09-16
>
> 状态：产品方案已确认，已根据首轮规格评审修订

## 1. 背景

eMenu Pro 当前主要面向对菜单视觉呈现要求较高的商家。平面设计师先完成整页菜单设计稿，再将设计图作为页面背景上传到 eMenu Pro，最后把商品相关组件拖放到对应位置并绑定商品。该流程适合有内部设计团队或第三方设计公司的客户。

另一类客户不需要复杂视觉设计，只需要以常规九宫格等规整方式展示商品。现有流程仍要求先制作背景图，使用门槛和交付成本偏高。

本设计在现有自由画布内新增商品图片组件和多选排版能力，让运营人员不依赖设计稿也能完成普通商品菜单，同时保持原有高视觉菜单工作流不变。

## 2. 目标与非目标

### 2.1 目标

1. 用户可在空白菜单页添加只展示商品主图的商品图片组件。
2. 用户既可添加单个组件，也可批量选择商品，为每个商品创建一个独立组件。
3. 用户可多选组件，并进行对齐、平均分布和统一尺寸操作。
4. 对齐基准可在“所选组件”和“当前画布”之间切换。
5. 新能力与现有背景图、自由布局和商品相关组件兼容。
6. 商品数据异常在编辑和发布环节有明确、可定位的反馈。

### 2.2 非目标

MVP 不包含：

- 自动生成九宫格页面；
- 永久网格容器或响应式自动重排；
- 跨页面对齐；
- 组件分组；
- 批量生成或绑定商品名称、价格组件；
- 智能布局推荐或模板市场。

## 3. 方案选择

### 3.1 采用方案：增强现有自由画布

在当前 eMenu Pro 编辑器中增加：

- 商品图片组件；
- 单个及批量创建入口；
- 多选状态和主对象；
- 对齐、分布、统一尺寸工具栏；
- 对应的撤销、保存和发布校验。

该方案不引入新的页面模型或父子容器，能同时满足规整九宫格与自由排版，并降低对现有菜单数据的影响。

### 3.2 未采用方案

#### 商品网格容器

由容器管理列数、间距和尺寸，九宫格效率更高，但会引入父子组件、容器内外拖动和布局模式转换等新概念，不适合作为本期 MVP。

#### 独立模板向导

通过选择商品和模板自动生成整页菜单，新手路径最短，但会扩大到模板、分页、重新生成和后续同步规则，超出已确认的手动排版边界。

## 4. 用户场景与流程

### 4.1 原有高视觉菜单

上传菜单设计图 → 添加商品交互组件 → 绑定商品 → 预览并发布。

该流程保持不变。

### 4.2 新增普通商品菜单

1. 用户新建或进入空白菜单页。
2. 用户从组件库添加单个商品图片组件，或打开批量选择商品弹窗。
3. 系统为每个商品创建一个独立图片组件。
4. 批量创建完成后，所有新组件保持选中。
5. 用户通过对齐、分布和统一尺寸完成规整排版。
6. 用户按需添加现有商品名称、价格等独立组件。
7. 用户预览并发布菜单。

## 5. 商品图片组件

### 5.1 职责

商品图片组件只显示一个已绑定商品的主图，不显示名称、价格、售罄文案或操作按钮。名称、价格等信息继续由现有独立组件承担。

### 5.2 数据

组件沿用现有 eMenu Pro 的持久化结构，不引入平行字段。新实例至少保存：

- 组件注册 key：`component: "DishImage"`；
- 商品 ID：`props.itemId`，统一写为字符串；
- 图片适配方式：`props.imageFit`，MVP 支持 `cover` 和 `contain`，默认 `cover`；
- 圆角：`style.borderRadius`；
- 透明度：`style.opacity`；
- 位置和尺寸：`style.left`、`style.top`、`style.width`、`style.height`；
- 现有组件模型要求的通用字段，如实例 ID、层级、锁定状态和可见状态。

组件不复制或固化商品图片 URL。编辑器和运行时根据 `props.itemId` 解析商品当前主图，因此商品主图更新后菜单自动展示新图。

示例：

```json
{
  "id": "generated-stable-id",
  "component": "DishImage",
  "props": {
    "itemId": "101",
    "imageFit": "cover"
  },
  "style": {
    "left": 96,
    "top": 128,
    "width": 180,
    "height": 180,
    "borderRadius": 8,
    "opacity": 1
  }
}
```

### 5.2.1 实现与数据合同

- 当前仓库只包含 `dist/emenu-pro/assets/*.js` 编译产物和 `dist/emenu-pro/embedded-*.js` 嵌入扩展，不包含 eMenu Pro 编辑器的权威源码。
- 商品图片组件注册、画布选择、多选变换、历史记录、保存和运行时渲染必须在 eMenu Pro 权威源码中实现；不得直接修改哈希 bundle 作为正式方案。
- 本仓库的 `dist/emenu-pro` 是消费和发布产物；`embedded-*.js` 只承担宿主嵌入、入口增强或兼容桥接，不得建立第二套菜单持久化模型。
- 实现计划必须把“取得并挂载 eMenu Pro 权威源码”列为 Task 0，并记录源码路径、构建命令、历史机制、保存/发布扩展点和 `dist/emenu-pro` 发布命令。设计完成后可以编写带门禁的实现计划，但 Task 0 未通过前禁止修改功能代码或哈希 bundle。
- 编辑器、预览和运行端使用同一组件注册 key `DishImage` 和同一 `component / props / style` 合同，不允许在发布阶段临时转换成另一种组件结构。
- 旧菜单不含 `DishImage`，读取行为不变。含 `DishImage` 的菜单需要编辑器与运行端双重能力门禁；兼容门禁见第 14 节。

### 5.3 单个创建

- 用户可从组件库添加商品图片组件。
- 未绑定时，组件显示“选择商品”占位状态。
- 用户可在右侧属性面板绑定或重新绑定商品。
- 未绑定组件不得通过发布校验。

### 5.4 批量创建

- 商品范围为当前菜单 `groupId + categoryId` 对应分类的 `saleItems`，与已有商品批量绑定能力一致；不跨菜单或跨分类选取。
- 搜索字段为商品名称、商品编码；默认按分类内现有顺序展示，分页沿用 `saleItems` 查询接口。
- 商品分类和权限由商品接口返回；无权访问的商品不展示。
- 同一次批量选择中，同一商品只能选择一次。
- 当前页已存在 `component === "DishImage"` 且 `String(props.itemId)` 相同的商品默认禁选并标记“已在画布”；用户仍可通过单个创建后重新绑定的方式主动产生重复实例。
- 每个商品创建一个独立组件。
- 批量创建是一个原子事务：全部成功或全部回滚。
- 批量创建可以一次撤销和重做。
- 创建成功后，本批新组件替换原选择并保持全部选中；主对象按 `top → left → stable ID` 的空间顺序取第一个。
- 弹窗打开时记录 `pageId`、`groupId` 和 `categoryId`；任一上下文变化时关闭弹窗并清空选择。
- 提交前重新读取当前页、分类、编辑权限和最新 `saleItems`，确认所选商品仍属于当前分类且可访问；再次执行精确重复检查和容量计算。
- 页面变化、权限撤销、商品失效、出现重复或容量不足时整批不提交，刷新商品列表并显示明确原因。

### 5.5 初始尺寸与摆放

- 所有批量创建的组件使用 `180 × 180` 逻辑像素的默认尺寸。
- 算法统一使用未缩放逻辑画布，不使用浏览器视口坐标。
- 起点为画布内容区左上角内边距 `(24, 24)`，水平和垂直间距均为 `16` 逻辑像素。
- 商品按当前分类 `saleItems` 的稳定顺序排列，从左到右、从上到下换行。
- 列数为 `floor((canvasWidth - 48 + 16) / (180 + 16))`，行数按同一公式由画布高度计算。
- “不重叠”只保证本批新组件彼此不重叠；已有组件不参与自动避让。
- 临时摆放只写入组件初始坐标，不建立永久网格、约束或父子关系。
- 创建前预计算容量。画布无法容纳本批全部组件时整批不创建，并提示“当前画布最多可放置 N 个默认尺寸组件，请减少商品或先调整画布”；不得边创建边失败，也不得把组件放到画布外。

### 5.6 商品查询与主图解析合同

- 商品查询复用当前分类 `saleItems` 的权威接口；正式接入前必须由 eMenu Pro 服务合同补充图片字段，mock 和 fixture 同步增加该字段。
- 建议标准化字段为 `primaryImage.url`，并允许服务端同时返回 `primaryImage.thumbnailUrl`；编辑器优先缩略图，预览和运行端优先原图 URL。
- 若现网接口字段不同，只能在统一商品适配层映射，不得由组件分别猜测字段名。
- 主图选择顺序为：当前菜单语言图片 → 商品默认主图 → 无图状态。MVP 不允许组件上传或固化替代图片。
- “权威数据明确无主图”“商品不存在或无权”“图片 HTTP 请求失败”必须保留为三个不同状态。
- 商品状态校验接口超时、离线或返回不可判定结果时，保存编辑稿不受影响，但发布默认阻止并允许重试；不得降级为“临时图片失败可发布”。

## 6. 商品与图片异常

### 6.1 商品缺少图片

- 仍创建商品图片组件，不静默跳过。
- 编辑态显示统一缺图占位图和“请补充商品图片”标记。
- 发布时列出缺图商品并要求二次确认，用户确认后可继续发布。

### 6.2 商品已删除或无法访问

- 保留组件位置、尺寸和商品 ID，避免布局坍塌。
- 编辑态显示“商品已失效”。
- 发布校验阻止发布，并支持定位到问题组件。

### 6.3 图片临时加载失败

- 编辑器提供重试。
- 运行时显示通用占位图。
- 不改变组件布局，不阻止发布。

此规则只适用于商品状态接口已确认商品有效且存在主图 URL、但图片资源请求失败的情况。

## 7. 多选模型

### 7.1 适用范围

多选排版能力适用于现有组件，不限于商品图片组件。不同类型组件允许混合选择，但每条命令只有在全部所选组件都满足该命令能力时才启用：

- 对齐和分布要求全部所选组件均可移动；
- 等宽、等高、等宽高要求全部所选组件均可缩放；
- 不采用“只处理可操作子集”的隐式行为。

锁定组件不进入框选结果，也不参与对齐、分布或统一尺寸。隐藏组件不进入画布选择。

执行命令前重新校验组件是否存在、可见、未锁定以及能力是否仍满足；任一组件状态变化时整次操作失败并刷新选择，不产生部分结果。

### 7.2 选择方式

- 单击组件：选择该组件并清除原选择。
- `Shift + 单击`：把组件加入选择，或从选择中移除。
- 在画布空白处拖动：框选完全落入选择框的未锁定可见组件。
- 单击画布空白处且未形成框选：清除选择。

### 7.3 多选状态

- 画布显示包含全部所选组件的整体选择框。
- 多选工具栏显示所选组件数量。
- 执行排版操作后保持原选择状态。
- 选择集合和主对象属于编辑会话状态，不写入菜单数据。

MVP 不支持通过右侧属性面板批量修改公共属性，避免额外引入 mixed value、批量校验和历史记录语义。

### 7.4 主对象

- 最后通过单击加入选择的组件为主对象，并使用更深的选择边框标识。
- 主对象是统一尺寸操作的尺寸来源。
- 纯框选没有明确的最后单击对象时，以空间顺序最靠左上方的组件作为主对象；排序先比较 `y`，相同再比较 `x`，最后以稳定组件 ID 打破并列。
- 主对象被移出选择后，按上述空间顺序选择新的主对象。

## 8. 排版工具栏

选择至少两个组件时，在画布附近显示浮动工具栏。工具栏包含：

- 左对齐；
- 水平居中对齐；
- 右对齐；
- 顶对齐；
- 垂直居中对齐；
- 底对齐；
- 水平平均分布；
- 垂直平均分布；
- 等宽；
- 等高；
- 等宽高；
- 对齐基准：“所选组件”或“当前画布”。

不满足启用条件的操作保持可见但禁用，悬停说明原因。

## 9. 对齐规则

所有几何算法使用未缩放逻辑画布坐标和组件的轴对齐边界框，不受 zoom、pan 或 CSS transform 影响。MVP 不支持旋转组件参与多选排版。画布内容区定义为闭区间 `[0, canvasWidth] × [0, canvasHeight]`。

### 9.1 基准为所选组件

系统计算所有所选组件的整体边界框：

- 左、右、顶、底对齐到整体边界框对应边；
- 水平居中对齐到整体边界框的垂直中心线；
- 垂直居中对齐到整体边界框的水平中心线。

至少选择两个可移动组件时启用。

### 9.2 基准为当前画布

以当前菜单页面内容区为基准：

- 边缘对齐到画布内容区对应边；
- 中心对齐到画布内容区对应中心线。

所有所选组件分别对齐到同一画布基准。操作不得改变组件尺寸。

## 10. 平均分布规则

- 至少选择三个可移动组件时启用。
- 水平分布按组件中心点的 `x` 坐标排序；垂直分布按中心点的 `y` 坐标排序。
- 保持排序后最外侧两个组件不动。
- 调整中间组件，使相邻组件中心点距离相等。
- 组件尺寸保持不变。
- 中心点相同时，水平分布依次按 `centerY`、稳定组件 ID 排序；垂直分布依次按 `centerX`、稳定组件 ID 排序。
- 坐标结果四舍五入到 `0.01` 逻辑像素；测试允许 `0.01` 逻辑像素误差，避免连续操作产生不可见浮点漂移。
- 本期“平均分布”明确指中心点等距，而不是边缘间隙等距。不同尺寸组件或端点跨度不足时可能产生重叠，这是已确认行为；操作完成后由第 13.2 节的重叠警告提示用户。

## 11. 统一尺寸规则

- 至少选择两个可缩放组件时启用。
- 等宽：把其他所选组件宽度设置为主对象宽度，高度不变。
- 等高：把其他所选组件高度设置为主对象高度，宽度不变。
- 等宽高：把其他所选组件宽高设置为主对象宽高。
- 主对象自身尺寸和位置不变。
- 其他组件保持 `style.left` 和 `style.top` 不变，从右侧和底部改变尺寸。
- 尺寸变化不得突破现有组件的最小、最大尺寸约束，也不得使任一组件越出逻辑画布；执行前统一预检。
- 任一组件无法应用目标尺寸时，本次操作不产生部分结果，并提示具体原因；不得自动 clamp，否则无法保证统一尺寸结果。

## 12. 历史记录与反馈

- 每次对齐、分布、统一尺寸或批量创建都作为单个历史命令。
- 撤销和重做应恢复或重新应用该次操作涉及的全部组件。
- 操作成功后显示短暂轻提示，例如“已将 9 个组件设为等宽高”。
- 操作失败不得留下部分坐标、尺寸或组件变更。
- 选择集合始终剔除已删除、隐藏或锁定的组件 ID，并按第 7.4 节重新确定主对象。
- 撤销批量创建会删除本批组件，并从选择集合移除对应 ID；若选择中没有其他组件，则清空选择。
- 重做批量创建会恢复本批组件，并恢复这批组件的选择状态和主对象。
- 撤销或重做几何操作只恢复菜单数据，之后再用当前有效组件 ID 收敛选择状态。

## 13. 保存与发布

### 13.1 保存

- 排版操作完成后，只保存各组件最终位置和尺寸。
- 不保存整体选择框、临时行列、对齐基准或主对象。
- 保存失败时保持当前编辑状态，并允许重试。

### 13.2 发布校验

| 状态 | 处理 |
| --- | --- |
| 商品图片组件未绑定商品 | 阻止发布并定位组件 |
| 商品已删除或无权访问 | 阻止发布并定位组件 |
| 商品缺少主图 | 警告并列出商品；二次确认后可发布 |
| 图片临时加载失败 | 不阻止发布 |
| 组件尺寸为零 | 阻止发布并定位组件 |
| 组件超出画布或完全重叠 | 警告并允许定位，不自动修改布局 |

判定统一使用未缩放逻辑画布的轴对齐边界框和 `0.01` 逻辑像素容差：

- 越界：任一边满足 `left < -0.01`、`top < -0.01`、`right > canvasWidth + 0.01` 或 `bottom > canvasHeight + 0.01`。
- 完全重叠：两个可见组件四条边分别在容差内相等；不根据透明度和层级推断是否“看不见”，一个组件仅覆盖另一个但边界不相等不算完全重叠。
- 同一组件只报告一次；问题按页面顺序、`top`、`left`、稳定组件 ID 排序，定位操作按此顺序循环。

## 14. 兼容性与权限

- 现有菜单数据不迁移、不重写。
- 现有背景图、组件和发布流程保持不变。
- 新组件可与现有商品名称、价格、按钮等组件混合使用。
- 沿用现有菜单编辑权限和发布权限，不新增独立权限。
- 不具备编辑权限的用户只能查看，不能多选或执行排版操作。
- 运行端通过能力合同返回 `supportedComponentTypes`，支持本需求的运行端必须包含 `DishImage`；不以字符串版本号猜测兼容性。
- 发布服务对本次发布的全部目标门店或产线检查能力。任一目标缺少 `DishImage`、能力查询失败、超时或离线时，默认阻止发布，列出目标并允许重试。
- 编辑器加载菜单时声明 `editorCapabilities.supportedComponentTypes` 或等价 schema capability。含 `DishImage` 的菜单只能由声明支持该组件的编辑器进入可编辑态；其他编辑器只能只读打开。
- 保存和发布接口必须再次校验编辑器 capability；不支持 `DishImage` 的编辑器请求由服务端拒绝，不依赖前端自觉保护。
- 权威源码接入后的 Task 0 必须验证未知组件在反序列化阶段被原样保留，不会在进入只读门禁前被过滤；若旧编辑器会提前丢弃未知节点，则服务端必须在返回可编辑数据前完成 capability 协商并只返回只读快照。
- 交付顺序必须是：先发布能够渲染但尚不创建 `DishImage` 的兼容运行端，再开放编辑器创建入口，最后开放发布。
- 回滚编辑器开关只禁止新增和发布，不删除已有组件；运行端兼容能力必须保留到所有含 `DishImage` 的菜单下线。

## 15. 架构边界

建议按以下职责拆分，避免把选择、几何算法和商品解析耦合在画布组件中：

1. **商品图片组件渲染器**：根据商品 ID 解析和展示主图，处理缺图及失效状态。
2. **批量创建服务**：校验选择、生成组件数据、计算初始位置，并以单个事务提交。
3. **选择状态管理器**：维护选择集合、主对象和框选行为，仅存在于编辑会话。
4. **几何排版服务**：接收组件边界和排版命令，返回确定性的目标坐标与尺寸，不直接操作 DOM。
5. **历史命令适配器**：把批量创建和几何操作接入现有撤销、重做机制。
6. **发布校验器**：聚合未绑定、商品失效、缺图、越界和运行端兼容问题。

## 15.1 影响范围与交付验证

### 权威实现范围

- eMenu Pro 权威编辑器源码：组件注册、选择模型、几何服务、历史命令、保存与校验；源码位置是进入实现前的 Gate G0。
- eMenu Pro 运行端源码：`DishImage` 渲染和 `supportedComponentTypes` 能力合同。
- 本仓库 `dist/emenu-pro`：由权威源码构建发布的静态产物。
- 本仓库 `dist/emenu-pro/embedded-*.js`：仅在确有宿主入口或嵌入兼容需求时修改。
- mock、fixture 和 focused verifier：补充商品图片字段、组件结构和几何算法覆盖。

### 构建与验证

- 若实现最终修改 `vendor/emenu-new`，必须从本项目根运行 `npm run build:emenu-new-embed -- --skip-install`，并检查 `dist/emenu-new/index.html` 新哈希、`dist/emenu-new/.emenu-embed-build.json` 及本次 `builtAt`；但 `vendor/emenu-new` 不是本需求默认实现位置。
- eMenu Pro 权威源码接入后，实施计划必须写明其正式构建命令，并验证最新产物发布到 `dist/emenu-pro`；不得手改哈希 bundle。
- 从本项目根执行 `npm run build` 后，必须确认 `dist/emenu-pro/index.html` 仍引用本次 eMenu Pro 产物、`DishImage` 相关 bundle 或资源仍存在，且 focused verifier 继续通过，防止主项目构建清空或回退 eMenu Pro 产物。
- 构建后运行商品图片、批量创建、选择、几何算法、历史记录、发布校验和旧菜单回归测试。
- 浏览器验证前重新加载 eMenu iframe；仍显示旧资源时强制刷新，再验证单个创建、9 商品批量创建、多选排版、保存刷新、发布门禁及旧菜单回归。
- 发布采用能力开关分阶段开放，并保留关闭编辑器入口的回滚开关。

## 16. 验收标准

1. 用户可添加单个商品图片组件并绑定、重新绑定商品。
2. 用户可一次选择多个商品，每个商品创建一个独立组件。
3. 批量创建的组件尺寸一致、互不重叠；创建后用本批组件替换原选择，且空间顺序第一个为主对象。
4. 用户可通过单击、`Shift + 单击`和空白区域拖框多选组件。
5. 框选只包含完全落入选择框的未锁定可见组件。
6. 多选工具栏显示正确的选择数量和操作启用状态。
7. 用户可执行左、水平居中、右、顶、垂直居中和底对齐。
8. 用户可切换“所选组件”和“当前画布”对齐基准。
9. 用户选择至少三个组件时，可执行水平和垂直平均分布。
10. 平均分布保持最外侧两个组件不动，使中间组件中心点等距。
11. 用户可执行等宽、等高和等宽高，尺寸来源为主对象。
12. 多选操作适用于支持移动或缩放的不同类型组件。
13. 锁定和隐藏组件不参与多选排版。
14. 每次批量创建或排版操作可一次撤销和重做。
15. 商品主图更新后，组件无需重新绑定即可展示新主图。
16. 商品缺图时编辑器显示占位和警告，发布需二次确认。
17. 商品失效或组件未绑定时发布被阻止，并可定位问题组件。
18. 操作失败不产生部分组件、部分坐标或部分尺寸变更。
19. 现有菜单打开、编辑、预览和发布行为不受影响。
20. 含新组件的菜单不能发布到不支持该组件的运行端。

## 18. 后续演进

若数据证明普通网格菜单成为高频场景，可在本设计的独立组件与几何排版能力之上继续增加商品网格容器或模板向导。后续能力应复用商品图片渲染、商品状态校验和几何算法，而不是建立第二套编辑器。
