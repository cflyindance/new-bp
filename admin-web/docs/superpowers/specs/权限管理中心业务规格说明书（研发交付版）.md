## 继承来源与恢复标记（PERM-SETTING-20261019-02）

版本记录：2026-10-19，研发V2.18配对产品V3.18/个人V2.18。替代旧设置项缺省hidden规则，不替代上级最严格约束。

Resource新增inheritFrom?:string与parentChoiceKey?:string。分类inheritFrom指向setting-page键，设置项指向所属setting-category键；合并设置的relatedGrantKeys同步登记继承来源。仅设置类型参与，不将action/content自动升级为编辑；既有ceilingKeys继续限制实际权限。页面上限缺省edit不变，分类不再缺省独立edit，而从页面读取。

configuredAccess先取独立值，缺省沿inheritFrom递归，最后使用资源defaultAccess；循环返回hidden。核心可见性使用同一原始继承计算但不递归业务page，防止父子循环。roleAccess/resolveAccess仍校验祖先、旧页面拒绝、依赖和ceilings；员工范围内角色取并集，个人父级例外参与未配置子项的继承，不影响其他门店。

每个可继承资源登记setting-parent-choice:<resourceKey>，type=setting、compatibilityOnly=true，不展示为业务项。当值为read表示明确继承父级；其他值/缺省不构成该标记。applySettingParentChoice删除当前资源及合并关联资源的独立grant，并写对应标记read；不改同级。角色中无独立值本就默认继承，标记主要用于员工覆盖角色独立值。明确hidden/read/edit或员工inherit操作会清除该项标记，随后按原写入/删除流程处理。schema、Access枚举与原键不变，标记由同一次本地持久化写入；旧明确授权保留。

UI parentInherited回调区分角色缺省、明确父级标记和员工跟随角色；继承项三态选中有效父级值，显示继承父级；独立项展示保存值，上限导致当前收紧时保留提示。恢复继承只作用当前门店当前资源；上级hidden时禁用局部修改，read时edit禁用，事件边界仍拒绝越级edit。单设置项页同样保留三级结构。

测试：新增verify-permission-setting-inheritance覆盖read/edit默认选中、hidden/read独立收紧、恢复继承、存储重载、门店隔离、跟随角色与父级差异；旧clock/settings测试仅更新已被本轮替代的缺省hidden预期，仍检验明确拒绝与旧page拒绝。默认继承可能新增原未配置设置项的read/edit权限，此为已确认变更；不宣称生产已切换或全仓测试通过。浏览器实页/截图待补。

## 3. 计算顺序与算例

1. 查员工、目标门店、资源；任一不存在，返回 hidden。
2. 过滤 scope 覆盖当前门店的绑定。
3. 先按 resource.type 校验每个原始角色值，越权/不适用值归一为 hidden，再取最大值：hidden=0、read=1、edit=2。
4. 当前门店存在个人值则覆盖，否则继承角色并集。
5. 个人值也按类型归一化；父资源以同一员工/门店上下文递归计算，父 hidden 则子最终 hidden。然后校验 requires 全部依赖；任一 hidden 则本项 hidden。两类门控均保留持久化原值。递归每条分支复制 seen 集合，允许共享祖先的 DAG，不把重复祖先误判为循环；当前分支循环默认拒绝。
6. 效果预览过滤隐藏内容/字段/设置；独立动作最终 edit 才显示整行。统一对象按 §5.5 聚合内容及全部编辑/保存有效结果，内容可见但不全允许则只读，不重复列映射动作。可见叶子页面不因内容/动作/设置全隐藏而消失，纯目录无可见后代才移除；只读设置没有编辑按钮。

以下动作算例均假设该动作已登记的 content/field 依赖 read；不满足时按步骤 5 返回 hidden，不从动作允许推导内容授权。

| 输入 | 结果 |
|---|---|
| A 店绑定新增员（页面 read、新增 edit、编辑 hidden），B 店无绑定 | A 新增允许编辑禁止，B 页面及动作拒绝 |
| A 店另有查看角色，个人新增 hidden | A 页面可见、新增禁止，不受角色允许覆盖 |
| 删除 A 店新增例外 | 恢复到角色新增允许，B 不变 |
| 页面改 hidden，下级新增仍存 edit | 新增最终 hidden；恢复页面后新增恢复允许 |
| 商品模块/商品管理 read，调味 hidden、标签 read，各自页面 read | 调味页面/动作最终 hidden；标签页面 read；只改变调味导航键不修改标签或子项 |
| 商品管理 hidden，调味/标签仍存 read | 两个子树均 hidden；恢复商品管理后原 read 和动作 edit 恢复 |
| A 店个人调味 hidden、B 店继承 | A 调味子树 hidden，B 按本店角色计算；删除 A 导航覆盖恢复本店角色基线，标签和 B 不变 |

## 4. 写入、状态与异常

写入 key 为 `menusifu:permission-center-local:v4`。首次映射旧角色和员工明确 stores/brands/regions 范围；all 或无范围不自动迁移为全门店。旧 key 完整保留，未审计动作不从旧通用 CRUD 自动开放。

`center-navigation-migration.ts` 只对 navigationVersion 缺失的数据生成克隆兼容视图：旧角色缺失的中间导航键设 read，原模块及所有叶子/动作/设置原值不动；原先无中间门控，因此不增加原资源生效结果。员工已存在的各店正向个人覆盖，其祖先中间导航没有适用角色提供 read 时，仅补必要祖先 read；显式 hidden 不覆盖，无覆盖的员工不新增例外。缺失门店不参与计算、不扩大绑定范围。标记设 1，version 和日志不变、读取不写；正常保存校验版本后一次写入标记、配置及审计，失败保留原存储。已标记数据不再自动补键；新角色 grants 空，新导航缺失按 hidden。复制保留源的导航权限，不复制成员。

迁移验收：将原目录恢复为“叶子直挂模块”，对每个旧角色及每个员工/门店组合比较所有旧资源，兼容前后结果必须逐项相等；重复迁移幂等。兼容视图中补充的个人导航键是支撑旧个人允许的必要记录，不表示新增业务动作允许。

保存前重新读取版本，校验角色名称、对象引用、范围、值域和删除约束，再构造日志与新版本，单次 setItem。写成功才更新内存视图；存储配额或序列化错误不显示成功，不清草稿。localStorage 的版本校验不是服务端原子并发控制，生产仍需事务与版本比较。

| 当前状态 | 操作 | 工作台结果 | 真实服务 |
|---|---|---|---|
| 无记录 | 记录邀请 | 新员工 pending、无绑定无例外 | 不发邮件、不生成密码 |
| pending | 重新记录邀请 | pending，加入员工草稿 | 不发邮件 |
| pending | 撤销邀请 | revoked，保留授权与员工 | 不调用令牌撤销 API |
| revoked | 重新记录邀请 | pending | 不发邮件 |
| enabled | 停用 | disabled，保留授权 | 尚不影响旧登录服务 |
| disabled | 启用 | enabled | 尚不影响旧登录服务 |

员工详情的上述状态变更加入草稿；须点保存并确认后持久化。取消整个详情则不写入。邮件实际送达、接受、过期、重置凭据和撤销会话均未实现，不输出伪成功。
