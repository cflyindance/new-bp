## 1. 实施边界

商家权限中心已接入新本地工作台；企业后台保留旧实现。新模型不自动替换旧会话权限或真实登录，当前结果用于配置及效果预览。严禁对外宣称后台 API 已受本模型保护。

模块职责：`center-domain.ts` 为纯计算；`center-catalog.ts` 读取导航和设置目录；`center-actions.ts` 逐项登记动作的 id/title/source/control；`center-persistence.ts` 为校验与本地版本写入；`center-store.ts` 负责旧数据只读初始化；`center-editor.ts` 共享编辑/预览；`center-ui.ts` 为页面流程；`center.css` 为作用域内样式。`rbac-ui.ts` 只在 merchant 分支转入新中心。

## 2. 数据对象与字段

### 2.1 CenterState

| 字段 | 逻辑说明 |
|---|---|
| schema | 数值，目前为 1；不识别的版本显示错误，不覆盖原始内容。 |
| navigationVersion | 可选数值；缺失表示旧扁平父级模型，读取时兼容为 1；1 表示已补齐中间导航门控。其他值拒绝读取/保存。兼容读取不改变 version，不写存储；下一次正常成功保存持久化。 |
| version | 非负整数，首次 0；每次成功写入加 1；无单位，不做金额/舍入处理。 |
| roles | 角色数组；ID 唯一；新角色默认空 grants。 |
| employees | 员工数组；ID 唯一，非空邮箱大小写不敏感唯一。 |
| logs | 审计数组，新记录置顶；本地可被用户修改，不是不可篡改审计。 |

### 2.2 角色 Role

| 字段 | 逻辑说明 |
|---|---|
| id | 字符串，新增生成 UUID；资料编辑保留；复制生成新 ID。 |
| name | 字符串，去首尾空格后必填，最多 30 字，同名拒绝；当前按精确名称比较。 |
| description | 字符串，可空，最多 160 字；空展示为 —。 |
| system | 布尔；迁移自旧角色，新增/复制为 false；true 时阻止删除。 |
| grants | 资源键到 `hidden/read/edit` 的映射；缺失按 hidden。模块/中间导航/页面使用 hidden/read，动作 hidden/edit，设置使用三态。旧数据兼容例外见 §4，不用于新角色或后续新增资源。 |

### 2.3 员工 Employee

| 字段 | 逻辑说明 |
|---|---|
| id | 旧员工 ID 或邀请时 UUID，邀请不创建密码。 |
| name | 姓名必填、最多 30 字；邀请提交去首尾空格。 |
| email | 无账号时空字符串；邀请为格式合法邮箱、最多 254 字，去空格并转小写。包括已撤销邀请在内的邮箱都参与查重。 |
| status | `unopened/pending/revoked/enabled/disabled`，只表示工作台记录状态；不得据此推断实际会话已撤销。 |
| bindings | 角色绑定数组；每条含 id、roleId、scope；不存全局 roleIds 并集作为授权事实。 |
| overrides | `storeId → resourceKey → Access`；没有值表示继承，恢复继承删除该键；不复制完整角色树。 |
| migrationReview | 布尔可选；旧数据缺少明确范围时为 true，显示待复核；管理员显式分配范围后本地标为 false。不删除旧授权。 |

### 2.4 Binding / Scope / Store

| 字段 | 逻辑说明 |
|---|---|
| binding.id | UUID，移除只删除对应绑定。 |
| binding.roleId | 必须存在于 roles；角色删除后不允许残留引用。 |
| scope.mode | `stores/brands/regions`；本地新授权默认 stores。 |
| scope.ids | 非空字符串数组；至少选 1 项；未知门店不会凭空命中。 |
| store.id | M 平台门店 ID，比较时用于指定门店和个人例外索引。 |
| store.brand | 项目 merchantId；动态品牌匹配此字段。 |
| store.region | 项目 regionName；当前沿用项目区域标识，生产改名/唯一性需接口明确。 |
| store.title | storeName，仅作展示，不用于权限判断。 |

动态范围在计算时匹配当前门店元数据，新增门店符合品牌/区域即命中。品牌/集团自身资源如何授权仍为 `PERM-OPEN-02`，不得把门店命中规则当作其答案。

### 2.5 资源及审计

| 字段 | 逻辑说明 |
|---|---|
| resource.key | `module:<id>`、`navigation:<moduleId>:<nodeId>`、`page:<path>`、`action:<path>:<id>`、`setting:<path>:<seq>`；中间导航使用真实 id，无 id 时以真实 path 代替；不随标题/顺序变化。原页面、动作、设置键保留，改路由/ID 必须迁移。 |
| resource.type | module/navigation/page/action/setting；navigation 表示有真实下级的中间导航，值域 hidden/read；设置分类和门店管理公共目录仍只组织内容。 |
| resource.parent | 模块→任意层数中间导航→页面→动作/设置；记录直接父级而非跳到模块。未知或循环父级默认拒绝。 |
| resource.seq | 设置项序号；其他类型不适用。 |
| audit.objectId | 当前角色或员工 ID；全局和员工页签共用同一记录。 |
| audit.actor | 当前会话姓名，无会话上下文时为“本地管理员”；非可信服务端身份。 |
| audit.at | ISO 时间字符串；UI 使用浏览器本地时间展示。 |
| audit.before / after | 对象 JSON 快照；删除后值 null；不存登录密码。 |
| audit.action | 中文操作名；邀请明确标记本地模拟。 |

## 3. 计算顺序与算例

1. 查员工、目标门店、资源；任一不存在，返回 hidden。
2. 过滤 scope 覆盖当前门店的绑定。
3. 同资源角色值取最大值：hidden=0、read=1、edit=2。
4. 当前门店存在个人值则覆盖，否则继承角色并集。
5. 父资源以同一员工/门店上下文递归计算；父 hidden 则子最终 hidden，下级持久化值不改变。
6. 效果预览过滤隐藏页面/设置及空分组。动作无权仍显示禁用按钮。

| 输入 | 结果 |
|---|---|
| A 店绑定新增员（页面 read、新增 edit、编辑 hidden），B 店无绑定 | A 新增允许编辑禁止，B 页面及动作拒绝 |
| A 店另有查看角色，个人新增 hidden | A 页面可见、新增禁止，不受角色允许覆盖 |
| 删除 A 店新增例外 | 恢复到角色新增允许，B 不变 |
| 页面改 hidden，下级新增仍存 edit | 新增最终 hidden；恢复页面后新增恢复允许 |
| 商品模块/商品管理 read，调味 hidden、标签 read，各自页面 read | 调味页面/动作最终 hidden；标签页面 read；只改变调味导航键不修改标签或子项 |
| 商品管理 hidden，调味/标签仍存 read | 两个子树均 hidden；恢复商品管理后原 read 和动作 edit 恢复 |
| A 店个人调味 hidden、B 店继承 | A 调味子树 hidden，B 按本店角色计算；删除 A 导航覆盖恢复本店角色基线，标签和 B 不变 |
| 角色 1 提供页面 read，角色 2 提供动作 edit，同门店 | 合并后父可见且动作允许；先逐角色裁掉动作会产生错误结果 |
| 动态品牌 B，新增门店 C.brand=B | C 自动命中该绑定 |
| 批量目标 A、B，B 无操作权限 | 返回 B 为无权集合，不能静默跳过执行 A |

当前 `resolveAccess` 返回的是功能配置效果，未代替真实账号会话和服务端 API 鉴权。`deniedStores` 是领域校验函数，尚未接入各业务批量提交链路。

## 4. 写入、状态与异常

写入 key 为 `menusifu:permission-center-local:v4`。首次映射旧角色和员工明确 stores/brands/regions 范围；all 或无范围不自动迁移为全门店。旧 key 完整保留，未审计动作不从旧通用 CRUD 自动开放。

`center-navigation-migration.ts` 只对 navigationVersion 缺失的数据生成克隆兼容视图：旧角色缺失的中间导航键设 read，原模块及所有叶子/动作/设置原值不动；原先无中间门控，因此不增加原资源生效结果。员工已存在的各店正向个人覆盖，其祖先中间导航没有适用角色提供 read 时，仅补必要祖先 read；显式 hidden 不覆盖，无覆盖的员工不新增例外。缺失门店不参与计算、不扩大绑定范围。标记设 1，version 和日志不变、读取不写；正常保存校验版本后一次写入标记、配置及审计，失败保留原存储。已标记数据不再自动补键；新角色 grants 空，新导航缺失按 hidden。复制保留源的导航权限，不复制成员。

迁移验收：将原目录恢复为“叶子直挂模块”，对每个旧角色及每个员工/门店组合比较所有旧资源，兼容前后结果必须逐项相等；重复迁移幂等。兼容视图中补充的个人导航键是支撑旧个人允许的必要记录，不表示新增业务动作允许。

保存前重新读取版本，校验角色名称、对象引用、范围、值域和删除约束，再构造日志与新版本，单次 setItem。写成功才更新内存视图；存储配额或序列化错误不显示成功，不清草稿。localStorage 的版本校验不是服务端原子并发控制，生产仍需事务与版本比较。

| 当前状态 | 操作 | 工作台结果 | 真实服务 |
|---|---|---|---|
| 无记录 | 记录邀请 | 新员工 pending、无绑定无例外 | 不发邮件、不生成密码 |
| pending | 重新记录邀请 | pending，加入员工草稿 | 不发邮件 |
| pending | 撤销邀请 | revoked，保留授权与员工 | 不调用令牌撤销 API |
| revoked | 重新记录邀请 | pending | 不发邮件 |
| enabled | 停用 | disabled，保留授权 | 尚不影响旧登录服务 |
| disabled | 启用 | enabled | 尚不影响旧登录服务 |

员工详情的上述状态变更加入草稿；须点保存并确认后持久化。取消整个详情则不写入。邮件实际送达、接受、过期、重置凭据和撤销会话均未实现，不输出伪成功。
