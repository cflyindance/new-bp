# 分配工时明细展示规则名称与规则类型

日期：2026-09-28  
状态：已确认

## 目标与范围

员工分配汇总与员工每日小费详情中的“分配工时明细”弹框统一展示规则名称、规则类型，使同名小费池下的多条规则易于区分。只调整工时明细记录与两个弹框；不修改分配工时、金额计算或规则编辑行为。

## 字段口径

- 原“规则”列改名“规则名称”，值仍为记录保存的 `ruleName`。
- 新增“规则类型”列，口径为池类型：`poolKind=surcharge` 显示“加收服务费池”，`poolKind=tip` 显示“小费池”。现有规则未声明 `poolKind` 时，在生成新工时记录时按现有默认小费池规则记为 `tip`。
- 旧工时记录没有类型字段时显示“—”，不根据可能已修改或删除的当前规则猜测历史类型。
- 列顺序：小费池、规则名称、规则类型、工时来源、分配工时。保留原弹框的其他视觉与交互。

## 数据流

每日员工工时记录生成时写入 `poolKind`。共享工时标准化与跨日期汇总保留该字段，两处弹框只根据工时记录中的类型显示文案。手动补录产生、但已无法对应有效规则的记录保持类型未知。跨日期汇总按小费池、规则及记录类型分组：`tip`、`surcharge` 与缺失类型是三个独立组，即使池与规则 ID 相同，也不得将旧的未知类型工时合入已知类型组。

## 验收

1. 两处弹框均有“规则名称”和“规则类型”两列，且每行列数与表头一致。
2. 小费池与加收服务费池分别显示正确类型；未声明类型的现有默认小费规则显示“小费池”。
3. 历史工时记录缺少类型时显示“—”；同池、同规则的新旧记录混合时，未知类型与 `tip`、`surcharge` 分行汇总，不互相污染。
4. 工时值、工时来源、汇总触发按钮及弹框关闭交互保持原样。
