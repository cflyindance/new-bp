# 自助餐当前场景商品支持全部门店设计

## 1. 背景

“配置额度 → 添加当前场景商品”目前只从 `addedStoreIds(draft)` 生成门店下拉，因此用户只能调整已经参与规则且已有商品的门店。业务需要在同一场景内直接选择系统中的任意门店商品；如果选择了尚未参与规则的门店商品，保存时应自动把该门店加入规则参与范围。

## 2. 目标

1. 当前场景商品选择器展示全部可用门店。
2. 用户在未参与门店选择商品并保存时，自动建立门店配置并加入规则参与范围。
3. 新增商品只进入当前场景，额度初始为未配置。
4. 未参与门店未选择商品时不加入规则。
5. 删除全部商品后不自动移出参与门店。
6. 保持产线、组、类、菜的统一商品选择交互。

## 3. 门店展示

门店下拉使用全局 `stores` 中所有有效门店，而不是 `addedStoreIds(draft)`。排序沿用全局门店顺序。

- 已参与门店：显示门店名称。
- 未参与门店：显示“门店名称（未参与）”。
- 初始选中仍优先使用当前配置门店；若当前门店无效，则选择第一个有效门店。
- 切换门店时分别保留该门店在本次弹窗中的临时勾选状态。
- 搜索和“产线 → 组 → 类 → 菜”结构读取当前选中门店的商品目录；门店目录不可用时显示空状态，不自动创建门店配置。

## 4. 临时状态与只读初始化

打开选择器和切换到未参与门店时不得直接修改正式草稿。

选择器为每个访问过的门店维护：

- 是否原本参与；
- 当前场景原始商品集合；
- 本次临时商品集合；
- 是否发生用户修改。

对未参与门店，原始场景集合为空。仅浏览、搜索、切换门店或关闭弹窗不会创建 `storeConfigs`、不会修改 `participatingStoreIds`、`deployStoreIds` 或场景额度。

## 5. 保存事务

点击“确认并返回配置”后先完整校验所有已修改门店，再一次性提交：

1. 未参与门店只有在普通商品/分类最终至少选择 1 个对象，或菜品集最终至少选择 2 个商品时才能自动加入。
2. 已参与门店允许把当前场景清空；菜品集清空表示删除该门店当前场景的菜品集商品，不按“新建菜品集”执行最少 2 个商品校验。
3. 未参与门店最终选择为空时忽略，不加入规则；未参与门店选择不足菜品集最少 2 个商品时阻止整次保存。
4. 任一门店校验失败时，所有门店均不写入，选择器保持打开并显示具体门店错误。
5. 校验全部通过后：
   - 为有选择结果的未参与门店创建标准门店配置；
   - 将门店 ID 加入 `participatingStoreIds`，去重并保持全局门店顺序；
   - 用首次选择结果建立该门店的基础商品结构和 `targetIds`，使 `addedStoreIds(draft)` 能识别该门店；
   - 把所选商品、分类或菜品集商品写入当前场景的 `scenarioTargets`；
   - 新增对象的 `targetLimits`、`tableTargetCaps` 或商品保护保持未配置；
   - 已有门店取消勾选时只删除当前场景对象及该场景对应额度。
6. 保存后调用既有部署选择归一化规则：`deployStoreIds = addedStoreIds(draft) - deployExcludedStoreIds`。新增门店若不在排除列表则默认加入 `deployStoreIds`；若此前已在 `deployExcludedStoreIds` 中则继续排除。任何情况下都不得清空、重建或删除既有排除项。用户随后仍可在“生效范围”步骤主动调整。

## 6. 删除与门店保留

取消勾选、单行移除或批量删除只影响当前场景。

当某门店当前场景或所有场景都没有商品时：

- 不自动从 `participatingStoreIds` 移除；
- 不自动删除 `storeConfigs[storeId]`；
- 不因删除商品而自动修改 `deployStoreIds` 或排除项；
- 用户需要通过既有门店范围管理主动移除门店。

这能避免一次场景编辑意外改变整条规则的门店边界。

`targetIds` 与基础 `structureByLine` 表示门店已纳入规则的基础可选商品池，不是各场景目标的实时并集。场景新增可以扩充该基础池；场景取消勾选、单行移除和批量删除只清理 `scenarioTargets` 及该场景额度，不缩减基础池。因此即使全部场景暂时为空，`addedStoreIds(draft)`、门店筛选和门店范围管理仍能识别该门店；“查看全部配置”和跨门店商品列表没有场景行时显示为空，不伪造商品配置。只有用户通过门店范围管理主动移除门店时，才清理基础池和门店配置。

## 7. 文案

- 字段名仍为“参与门店”。
- 未参与选项追加“（未参与）”。
- 帮助文案调整为：“可从全部门店选择当前场景商品；选择未参与门店的商品并保存后，该门店将自动加入规则。取消勾选仅删除所属门店当前场景商品及额度，不会自动移出门店。”
- 保存成功后回到配置额度页，新门店商品立即出现在跨门店商品表中。

## 8. 数据一致性

- 门店 ID 必须存在于全局 `stores`。
- 参与门店数组、门店配置和商品目标必须去重。
- 新建门店配置使用现有 `createEmptyStoreConfig` / `normalizeStoreConfig` / 商品结构同步能力，禁止构造另一套兼容结构。
- 写入当前场景时继续使用稳定场景键和稳定商品身份。
- 保存前使用快照或先构造变更集，确保跨门店校验失败不会留下半完成配置。
- 关闭或取消选择器时正式草稿保持不变。

## 9. 验收标准

1. 规则当前只有 A 店参与时，门店下拉同时展示 A、B、C 等全部有效门店，B、C 标记“未参与”。
2. 只切换到 B 店后取消，B 店不加入参与范围，也不产生门店配置。
3. 在 B 店选择商品并保存后，B 店加入 `participatingStoreIds`，当前场景商品表立即显示 B 店商品。
4. B 店新增商品额度均为未配置，不复制 A 店额度。
5. 在 A、B 两店分别修改后一次保存，两店结果同时生效。
6. 未参与门店不满足加入所需最少对象数时，全部修改均不落盘；已参与门店允许合法清空当前场景。
7. 普通商品、分类和菜品集三种对象都支持从未参与门店加入；菜品集遵守至少 2 个商品。
8. 人数区间、轮次区间和组合场景只修改当前场景，其他场景不增加该商品。
9. 在当前场景取消 B 店全部商品后，相关当前场景额度被删除，但 B 店仍保留在参与门店范围。
10. 保存草稿并重新打开后，新门店、当前场景商品和未配置额度正确回显。
11. 门店筛选、“查看全部配置”和跨门店商品列表能识别新加入门店。
12. 新门店不在排除列表时随归一化加入 `deployStoreIds`；已排除门店保持排除，既有 `deployExcludedStoreIds` 完整保留。
13. 已参与门店可把普通商品、分类或菜品集当前场景清空；清空只删除场景目标与额度，基础商品池和参与门店身份保留。
14. 全部场景清空后，门店仍出现在参与门店管理和门店筛选中；当前场景表及全部配置汇总不产生虚假商品行。
