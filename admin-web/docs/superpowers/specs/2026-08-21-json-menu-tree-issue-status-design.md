# 菜单树错误与警告状态设计

## 目标

在菜单路由配置的左侧菜单树中，清晰标记存在错误或警告的菜单节点，并让父级菜单汇总展示其后代节点的问题状态，帮助用户快速发现和定位问题。

## 范围

- 仅调整左侧菜单树的问题状态展示与定位交互。
- 不修改现有校验规则、`MenuValidationIssue` 数据结构、JSON 导入导出格式或发布逻辑。
- 延续当前菜单名称下不展示 Key、仅展示菜单层级的方案。

## 状态计算

每个菜单节点分别计算：

1. 自身问题：`issue.path` 与当前节点路径完全一致。
2. 后代问题：`issue.path` 以当前节点路径为前缀，且路径长度更长。
3. 错误数与警告数分别统计，不相互覆盖。
4. 根配置字段等没有节点路径的问题仅保留在顶部总数中，不映射到菜单节点。

## 视觉规则

### 当前节点自身存在问题

- 在节点右侧、菜单类型标签之前展示问题标签。
- 错误标签使用红色，文案为 `N 错误`。
- 警告标签使用橙色，文案为 `N 警告`。
- 同时存在两种状态时同时展示，错误在前。
- 节点卡片增加对应状态强调：错误优先使用红色边框/浅红背景，只有警告时使用橙色边框/浅橙背景。
- 选中态仍保留青绿色左侧选中条，问题颜色用于边框和状态标签，避免丢失当前选中反馈。

### 仅后代节点存在问题

- 父级展示汇总标签，文案分别为 `子菜单 N 错误`、`子菜单 N 警告`。
- 汇总标签使用弱化的红色或橙色样式，避免与父级自身问题混淆。
- 父级不使用错误背景，仅通过汇总标签提示。

### 类型标签

`目录`、`项目内`、`iframe`、`兼容保留`、`隐藏`等现有标签继续保留；问题标签排列在类型标签左侧。

## 交互规则

- 点击自身问题标签：选中当前菜单，并定位该节点的第一个对应问题。
- 点击父级汇总标签：展开必要的父级路径，选中第一个存在对应问题的后代菜单。
- 定位顺序遵循菜单树顺序；同一节点上错误优先于警告。
- 点击问题标签不触发新增、拖拽、展开收起或“更多”菜单。
- 顶部“定位问题”功能保持现有行为。

## 可访问性

- 问题标签使用 `button`，提供明确的 `title` 和 `aria-label`。
- 不仅依赖颜色表达状态，标签必须包含“错误”或“警告”文字及数量。
- 保留键盘焦点样式。

## 验证

1. 自身错误、自身警告、两者同时存在时，标签数量和卡片强调正确。
2. 子菜单有问题时，一级和二级父级显示正确的汇总数量。
3. 无问题节点不显示问题状态。
4. 点击自身标签定位当前节点；点击汇总标签定位首个对应后代节点。
5. 菜单 Key 不重新出现在名称下方，但仍可用于搜索。
6. TypeScript 检查和现有菜单树滚动保持验证通过。
