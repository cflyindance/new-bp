# 菜单树错误与警告状态设计

## 目标

在菜单路由配置的左侧菜单树中，清晰标记存在错误或警告的菜单节点，并让父级菜单汇总展示其后代节点的问题状态，帮助用户快速发现和定位问题。

## 范围

- 仅调整左侧菜单树的问题状态展示与定位交互。
- 不修改现有校验规则、`MenuValidationIssue` 数据结构、JSON 导入导出格式或发布逻辑。
- 延续当前菜单名称下不展示 Key、仅展示菜单层级的方案。

## 状态计算

每个菜单节点分别计算：

1. 自身问题：`issue.path` 与当前节点路径逐段完全一致。
2. 后代问题：当前节点路径是 `issue.path` 的严格逐段前缀，且 `issue.path` 更长；禁止对编码字符串使用 `startsWith` 判断，避免 `1` 与 `10` 等路径误判。
3. 错误数与警告数分别统计，不相互覆盖；`N` 表示校验问题记录数，而不是不同节点数或直接子菜单数。
4. 每个严格祖先汇总所有后代层级的问题，包括子菜单和更深层孙菜单。
5. 没有路径或路径无法解析到现有节点的问题仅保留在顶部总数中，不映射到菜单节点。

## 视觉规则

### 当前节点自身存在问题

- 在节点右侧、菜单类型标签之前展示问题标签。
- 错误标签使用红色，文案为 `N 错误`。
- 警告标签使用橙色，文案为 `N 警告`。
- 同时存在两种状态时同时展示，错误在前。
- 节点卡片增加对应状态强调：错误优先使用红色边框/浅红背景，只有警告时使用橙色边框/浅橙背景。
- 选中态的青绿色左侧内嵌条始终保留；自身错误或警告继续控制边框和浅色背景，错误优先于警告。

### 后代节点存在问题

- 父级展示汇总标签，文案分别为 `子菜单 N 错误`、`子菜单 N 警告`。
- 汇总标签使用弱化的红色或橙色样式，避免与父级自身问题混淆。
- 自身问题标签与严格后代汇总标签独立计算；节点同时存在自身和后代问题时，两组标签同时展示。
- 只有自身问题影响卡片边框和背景；仅有后代问题时，父级只显示汇总标签。
- 标签顺序固定为：自身错误、自身警告、子菜单错误、子菜单警告、菜单类型、隐藏状态。

### 类型标签

`目录`、`项目内`、`iframe`、`兼容保留`、`隐藏`等现有标签继续保留；问题标签排列在类型标签左侧。问题标签区域允许换行，标签使用短文案和紧凑间距；在菜单树最小宽度 340px 时不得产生水平滚动，菜单名称、添加和更多操作仍可使用。

## 交互规则

- 点击自身错误或警告标签：选中当前菜单；标签严重级别决定对应问题类型。
- 点击子菜单错误标签：选择深度优先菜单树顺序中的第一个、存在错误的严格后代；子菜单警告标签同理只定位警告。
- “错误优先于警告”仅表示标签视觉排列，不改变用户点击标签所指定的严重级别。
- 问题定位先清空当前搜索条件，将目标的所有祖先加入展开集合，选中目标并重建右侧编辑区，然后重新渲染菜单树。
- 渲染后将目标菜单滚动到可见区域，并把焦点移动到目标节点对应严重级别的自身问题标签。
- 主动点击问题标签允许调整菜单树滚动位置；普通选择和重新渲染仍保持现有滚动位置。
- 点击问题标签不触发新增、拖拽、展开收起或“更多”菜单。
- 顶部“定位问题”保持现有基于问题数组循环定位的行为，不套用子菜单标签的深度优先规则。

## 可访问性

- 问题标签使用 `button`，提供明确的 `title` 和 `aria-label`。
- 不仅依赖颜色表达状态，标签必须包含“错误”或“警告”文字及数量。
- 保留键盘焦点样式。

## 验证

1. 自身错误、自身警告、两者同时存在时，标签数量和卡片强调正确。
2. 节点同时具有自身与后代问题时，两组标签同时展示；错误背景优先，青绿色选中条保留。
3. 子菜单及孙菜单有问题时，一级和二级父级按问题记录数汇总；兄弟分支均计入对应祖先。
4. 无问题节点不显示问题状态；根字段问题和无法解析的路径不进入节点标签。
5. 路径逐段前缀判断可区分 `[1]` 与 `[10]` 等相似编码路径。
6. 点击自身标签定位当前节点；点击汇总错误或警告标签分别定位首个同严重级别后代，即使更早的后代存在另一严重级别。
7. 搜索生效或祖先收起时，问题定位会清空搜索、展开祖先、显示目标、滚动到目标并聚焦对应标签。
8. Enter/Space 可触发问题标签，且不触发展开、添加、更多或拖拽副作用。
9. 340px 最小宽度下同时展示四种问题标签和类型/隐藏标签时无水平滚动，菜单名称与操作可用。
10. 菜单 Key 不重新出现在名称下方，但仍可用于搜索。
11. TypeScript 检查和普通菜单树重渲染的滚动保持验证通过。
