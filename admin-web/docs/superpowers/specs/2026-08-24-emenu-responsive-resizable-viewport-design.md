# eMenu 顾客端可缩放与自适应视口设计

## 背景

当前 eMenu 顾客端的主要布局直接依赖浏览器视口。例如菜单行宽度使用 `calc(100vw - 241px)`，列表高度使用 `window.innerHeight` 或 `calc(100vh - ...)`。这种实现能适配窗口变化，但无法把菜单区域作为独立容器调整，也无法在顾客改变显示大小后稳定重排菜品卡片。

本设计让顾客在 eMenu 页面内调整菜单区域的宽度、高度和显示大小，并让菜单在横屏与竖屏平板中自动重排。门店负责默认展示，顾客调整仅影响当前点餐会话。

## 目标

- 顾客可通过显示大小按钮、双指或 `Ctrl + 滚轮`、边缘拖拽三种方式调整菜单。
- 显示大小变化和菜单可用宽度变化共同决定卡片尺寸与列数。
- 横屏、竖屏和平板旋转后均保持菜单可读、可点且不遮挡关键流程。
- 门店可配置默认显示；顾客调整在新开台、退出或会话过期后失效。
- 尺寸变化不重新请求菜单数据，并尽量保持当前分类与滚动位置。

## 非目标

- 不要求手机端与平板端拥有完全相同的布局质量；手机只需保持基本可用。
- 不允许顾客永久修改门店默认配置。
- 不把浏览器原生页面缩放作为业务状态来源。
- 不重做 eMenu 主题、菜品卡片内容或下单流程。
- 不让弹窗、购物车或结账确认层跟随菜单容器自由缩放。

## 方案选择

采用“响应式布局 + 显示密度档位 + 有边界的连续缩放”。

未采用整页等比例缩放，因为小视口下会使文字和点击区域过小，竖屏也不会真正重排。未采用完全自由画布，因为极端尺寸会造成遮挡、误触和不可控的测试组合。

## 页面模型

页面分成两个坐标空间：

1. **屏幕层**：顶部栏、购物车、结账按钮、弹窗和遮罩。始终相对真实屏幕定位。
2. **菜单视口层**：分类导航、分类标题、菜品网格和菜单滚动区。顾客调整的是这一层。

菜单视口小于可用屏幕时，在屏幕层的可用内容区中居中，露出的区域继续使用当前 eMenu 页面背景。顶部栏保持固定，不参与自由拉伸。

## 架构与组件

### `ViewportLayoutController`

所有尺寸变化的唯一入口。它监听屏幕旋转、窗口变化、预设按钮、拖拽、双指缩放和 `Ctrl + 滚轮`，统一输出：

- 菜单容器宽度和高度；
- 显示比例；
- 横屏或竖屏；
- 密度档位；
- 当前列数；
- 本次变化来源。

现有菜单组件不再直接以 `window.innerWidth`、`window.innerHeight`、`100vw` 或 `100vh` 作为内部布局依据，而是消费控制器提供的容器测量结果。

### `DisplaySizeControl`

位于右上角，提供：

- 小：85%；
- 标准：100%；
- 大：120%；
- 连续调节：75%～140%，步长 5%；
- 恢复门店默认。

控制器在按钮上显示当前比例。达到上下限时继续缩放不改变状态，并给出轻量触觉或视觉反馈；没有触觉能力时只显示视觉反馈。

连续调节使用原生范围输入：左右或上下方向键按 5% 调整，`PageUp` / `PageDown` 按 10% 调整，`Home` 到 75%，`End` 到 140%。当前比例通过可见文本和 `aria-valuetext` 同步表达。

### `ResizableMenuViewport`

包裹分类导航和菜品列表。它提供右侧、底部和右下角三个手柄：

- 右侧调整宽度；
- 底部调整高度；
- 右下角同时调整宽高。

手柄视觉宽度约 6 px，触摸命中区域至少 24 px。只有从命中区域开始的移动才进入拉伸状态，避免抢占菜单滚动。

### `ResponsiveMenuGrid`

使用菜单容器的内容宽度计算网格，而不是浏览器宽度。计算时扣除分类导航宽度、内容内边距和列间距，再结合当前显示比例下的卡片最小宽度决定列数。

推荐规则：

- 横屏常规状态 3～6 列，极窄状态允许 2 列；
- 竖屏 2～4 列；
- 卡片不能满足最小宽度时优先减列，不继续压缩；
- 分类导航无法与至少两列卡片共存时，切换为顶部分类入口；
- 列数使用稳定阈值和少量迟滞区间，避免临界宽度拖拽时反复跳列。

密度只改变结构密度，不绕过文字和触控下限：

| 密度 | 卡片最小宽度 | 网格间距 | 卡片内容内边距 |
| --- | ---: | ---: | ---: |
| `compact` | 144 px | 12 px | 12 px |
| `standard` | 168 px | 16 px | 16 px |
| `comfortable` | 192 px | 20 px | 20 px |

显示比例再作用于卡片内容、图片高度和文字尺寸令牌；计算列数时使用“密度卡片最小宽度 × 显示比例”。如果结果违反 14 px 正文或 44×44 px 触控下限，控制器以可访问性下限为准。密度不会单独缩小文字。

### `DisplayPreferenceStore`

负责合并门店默认值与当前会话覆盖值。它不永久写回门店配置。

## 门店配置管理与下发

本功能的门店默认配置属于本次实施范围。它沿用现有 eMenu 配置通路，不新增独立接口：

- 在现有系统设置的“菜单显示”区域（`components/AdminSettings/SettingMenuDisplay.jsx`）增加“顾客显示调整”配置组。
- 在 `constants/systemConfig.js` 的 `ALL_CONFIG_ITEM` 中增加一个向后兼容的全局配置项，值为本设计的 `EmenuDisplayDefaults`。
- 保存继续通过 `systemConfig.slice.js` 的 `effects.setConfig()` 和既有 `setEmenuConfig` 请求写入 eMenu 配置 JSON。
- eMenu 启动继续通过既有 `getEmenuConfig` 流程取得配置；`DisplayPreferenceStore` 从合并后的全局配置读取默认值。
- 本期只支持门店全局默认，不增加单设备覆盖。现有配置 JSON 缺少新字段时使用默认值，不要求数据迁移或新增后端端点。

如果既有服务端对配置项 ID 存在白名单校验，则补充该 ID 属于本功能的接口适配工作；不改变现有配置数据模型。

## 配置与状态

门店默认配置：

```ts
type EmenuDisplayDefaults = {
  scale: number
  widthRatio: number
  heightRatio: number
  density: "compact" | "standard" | "comfortable"
  allowGuestResize: boolean
  allowPinchZoom: boolean
  allowDragResize: boolean
}
```

默认建议值为 `scale: 1`、`widthRatio: 1`、`heightRatio: 1`、`density: "standard"`，三个顾客调整能力均开启。

运行时状态：

```ts
type EmenuViewportState = {
  width: number
  height: number
  scale: number
  density: "compact" | "standard" | "comfortable"
  orientation: "landscape" | "portrait"
  columns: number
  source:
    | "store-default"
    | "preset"
    | "gesture"
    | "drag"
    | "window-resize"
    | "rotation"
    | "fallback"
}
```

`width` 与 `height` 是经过安全裁剪后的 CSS 像素值。门店配置使用比例，避免把某一设备的像素尺寸直接迁移到另一设备。

三个能力开关按以下优先级解释：

- `allowGuestResize` 是主开关。关闭后隐藏显示大小入口和拖拽手柄，并禁用双指、`Ctrl + 滚轮`及所有顾客主动调整；容器仍响应真实屏幕变化和旋转。
- `allowPinchZoom` 只在主开关开启时生效，控制双指和 `Ctrl + 滚轮`连续缩放；不影响显示大小按钮。
- `allowDragResize` 只在主开关开启时生效，控制右侧、底部和右下角手柄；不影响显示大小按钮。
- 主开关开启而两个子开关都关闭时，顾客仍可使用显示大小预设和连续滑杆。

## 尺寸与可访问性边界

- 菜单区域宽度限制为当前可用内容宽度的 60%～100%。
- 菜单区域高度限制为当前可用内容高度的 55%～100%。
- 显示比例限制为 75%～140%。
- 交互控件最终显示尺寸不小于 44×44 CSS px。
- 正文最终显示尺寸不小于 14 CSS px。
- 菜品图片保持既有裁切比例，不按容器宽高非等比拉伸。
- 弹窗、购物车、结账层相对屏幕层定位，不被菜单视口裁切。

如果缩放与可访问性下限冲突，可访问性下限优先。此时控制器停止继续缩小视觉内容，并通过减列或折叠分类栏消化空间。

## 交互规则

### 预设与连续缩放

三档预设和连续缩放修改同一个 `scale`。双指缩放与 `Ctrl + 滚轮` 每次归一到 5% 步长，避免产生大量无法复现的小数状态。

双指开始后暂停菜品点击，手势结束约 150 ms 后恢复。普通单指滚动不触发缩放；普通滚轮仍滚动列表，只有按住 `Ctrl` 时调整比例。

### 拖拽

拖拽高频事件通过 `requestAnimationFrame` 合并。拖动过程中更新容器几何和轻量网格预览；释放后再执行虚拟列表的完整测量。

释放时将宽高吸附到 5% 比例步长。若用户拖到边界之外，视觉上表现为轻微阻尼，最终值仍裁剪到安全范围。

### 屏幕旋转

旋转时保留 `scale` 和密度档位，根据新方向重新计算宽高和列数。宽高会先按原比例映射，再裁剪到新方向的安全范围。

### 模态流程

打开菜品弹窗、购物车或结账确认时，如果正在拖拽或缩放，立即结束当前手势并提交最后一个合法状态。模态层打开期间禁止开始新的拖拽或缩放。

## 状态生命周期

1. eMenu 启动后读取门店默认配置。
2. 控制器按当前设备的可用内容区裁剪默认配置。
3. 顾客调整后，在当前点餐会话中建立覆盖值。
4. 切换分类、搜索、打开购物车或临时刷新菜单数据时保留覆盖值。
5. 屏幕旋转时转换覆盖值，不恢复门店默认。
6. 新开台、退出登录或点餐会话过期时清除覆盖值。
7. 下一会话重新从门店默认配置开始。

会话覆盖值应与当前桌台或订单会话标识绑定，不能只依赖设备级 `localStorage`，避免上一桌顾客的偏好影响下一桌。

## 滚动与虚拟列表

改变列数会使分类行高度发生变化。重排前记录：

- 当前可见分类 ID；
- 该分类标题相对菜单视口顶部的偏移量。

重排与虚拟列表重新测量完成后，恢复到同一分类并尽量保持原偏移。若该分类已被菜单更新删除，则定位到相邻有效分类；如果没有有效分类，则回到列表顶部。

现有 `RightContent` 的固定 `calc(100vw - 241px)`、`window.innerHeight - listGap` 和固定断点 `Grid` 列宽是首要迁移点。`OrderListWrapper` 中基于 `100vh` 的内容高度也要改为消费菜单视口层的可用高度。

## 异常与降级

- 配置缺失、解析失败或数值非法：使用 100%、全宽、全高、标准密度。
- `ResizeObserver` 不可用：降级为窗口 `resize`、旋转事件和显式交互后的同步测量。
- 设备不支持多点触控：保留预设按钮、连续调节和拖拽。
- 运行时得到 `NaN`、无限值或越界尺寸：裁剪到安全值，并对同一会话只记录一次诊断日志。
- 低性能设备拖拽掉帧：拖动过程中保持当前列数，仅在释放后重算列数；这是性能降级，不改变最终结果。
- 当前菜单为空：保留显示控制，但隐藏拖拽手柄，避免无内容状态出现无意义的画布调整。

## 性能要求

- 连续拖拽与缩放目标接近 60 fps。
- 高频指针事件必须通过 `requestAnimationFrame` 合并。
- 尺寸变化不能触发菜单数据重新请求。
- 虚拟列表只在跨列、方向变化或交互结束时做完整测量。
- 不在每个菜品卡片中单独监听窗口尺寸。
- 稳定状态下不应持续触发尺寸观察回路。

## 测试与验收

### 功能测试

- 三种入口修改同一状态，不发生覆盖或跳变。
- 横竖屏切换后保留缩放档位，重新计算合法宽高和列数。
- 新开台恢复门店默认；当前会话内切换分类、搜索和打开购物车后仍保留顾客设置。
- 拖拽、滚动、菜品点击和双指缩放不互相误触。
- 弹窗、购物车和结账确认不被菜单视口裁切。
- 禁用任一门店能力开关后，对应顾客入口和手势均不可用。

### 视口矩阵

- 横屏：1024×768、1280×800、1366×768、1920×1080。
- 竖屏：768×1024、800×1280、1080×1920。
- 每个视口验证 75%、100%、120%、140%。
- 每个视口验证最小和最大宽高，以及旋转后的状态恢复。

### 布局与可访问性测试

- 卡片不低于最小可读宽度，文字、价格和加购按钮不重叠。
- 交互控件不小于 44×44 CSS px，正文不小于 14 CSS px。
- 临界宽度附近缓慢拖动时，列数不来回抖动。
- 图片不出现非等比拉伸。
- 分类导航切换模式后不遮挡菜品区。
- 键盘焦点、读屏名称和缩放后的焦点顺序保持正确。

### 性能测试

- 在目标平板上记录拖拽和缩放帧率。
- 验证连续交互不会重复请求菜单数据。
- 验证虚拟列表完整重算只发生在规定时点。
- 验证反复旋转和缩放后不存在持续的 `ResizeObserver` 循环或内存增长。

## 推进方式

采用分阶段上线：

1. 先引入容器测量和响应式网格，但保持默认 100% 全宽全高，确保现有视觉不回归。
2. 接入门店默认配置和显示大小按钮。
3. 接入拖拽和手势，使用功能开关按门店或设备灰度启用。
4. 完成横竖屏矩阵与性能验证后再默认开启顾客调整能力。

如运行环境出现严重性能或兼容问题，可关闭 `allowPinchZoom` 或 `allowDragResize`，保留响应式网格和显示大小预设，不需要回退整个容器架构。
