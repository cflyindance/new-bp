# 前厅“消息类型提醒”文案统一设计

## 背景

前厅管理中心的 `foh-pos-order-alerts` 分组已合并员工端通知类型、新单语音播报、新订单提醒、追单提醒和指定菜品提醒。现有标题“订单消息提醒”不能完整覆盖“员工端通知类型”等非纯订单类内容，因此统一调整为“消息类型提醒”。

## 目标

- 所有用户可见的“订单消息提醒”统一展示为“消息类型提醒”。
- 配置目录、关联提示、映射表、生成源和设计文档保持一致。
- 保持现有 5 项配置的分组、顺序、数据及交互不变。

## 设计

### 展示文案

将 `foh-pos-order-alerts` 对应标题改为“消息类型提醒”，并同步以下引用：

- 前厅设置二级导航标题。
- 331、332、637、638、639 五项配置的 `groupTitle`。
- 由设置目录标题派生的站内搜索结果、权限导航和平台预设树。
- 消息中心跳转前厅设置的关联提示。
- 桌边服务依赖通知类型的说明。
- 配置映射表、设计文档、生成脚本及校验提示。

站内搜索和权限导航继续读取同一设置目录，不新增单独别名；平台预设树只同步目标分组标题，不借机重新生成其他导航数据。

### 保持不变

- 分组键继续使用 `foh-pos-order-alerts`。
- 路由继续使用 `/operations/queue-call/settings/foh-pos-order-alerts`。
- 旧 `foh-pos-notification-control` 地址继续跳转至该路由。
- 五项配置顺序继续为 331、332、638、639、637。
- 本次不调整任何开关、表单、存储键或业务规则。

## 数据流

生成源与运行时目录均使用相同的新标题；映射表和设计文档同步更新，避免后续重新生成时把旧标题写回。内部标识与路由不变，因此无需数据迁移。

## 验证

- 检索活跃代码、生成源、映射表和当前产品文档，确认不再把旧名称作为现行展示文案；本规格及历史迁移记录可在明确说明“原名称”时保留旧词。
- 专项校验确认目标分组存在、旧分组不存在、五项顺序不变、旧链接正常跳转。
- 运行前厅产线范围校验与 TypeScript 类型检查。
- 执行生产构建，并在页面确认前厅导航、站内搜索、权限导航及平台预设树显示“消息类型提醒”。

## 非目标

- 不重命名 `foh-pos-order-alerts`。
- 不修改“新订单提醒”等分组内功能名称。
- 不改变通知的适用产线、默认值或持久化方式。
