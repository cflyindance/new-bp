# 递归菜单导航滑层设计

## 背景与目标

当前后台的一级菜单存在多种二级导航表现：部分模块使用侧滑层，部分模块直接进入默认内容，部分模块在主导航内展开。随着菜单出现三级、四级结构，交互规则不一致，用户难以预判点击结果。

本次统一为“先导航，再内容”：只要菜单节点存在子节点，点击该节点就进入独立导航滑层的下一层；只有点击没有子节点的叶子菜单时，才展示对应业务内容。

## 已确认方案

采用 A1：固定宽度、单面板逐级替换。

1. 点击带子节点的一级菜单，只打开独立导航滑层，不切换到默认子页面。
2. 点击带子节点的二级或更深层菜单，当前列表向左退出，下一级列表从右进入。
3. 点击叶子菜单，切换到其路由、关闭整组滑层并展示业务内容。
4. 滑层标题显示当前列表的父节点名称。
5. 返回按钮按导航栈逐级回退；位于第一层时返回则关闭滑层。
6. 无论菜单深度如何，滑层保持固定宽度，不横向叠加多个面板。

## 适用范围

规则由菜单节点是否声明 `children` 自动决定，不依赖模块名称或单独白名单。新的递归滑层取代 `subNavPlacement` 对全局菜单层级的分流：原 `sheet`、`sidebar`、`tabs` 类型的全局模块子导航统一进入递归滑层，`subNavPlacement` 标记在迁移完成后废弃。业务内容内部用于切换同一页面视图的局部 Tab 不属于全局菜单层级，继续保留。

- 一级节点声明子节点：使用导航滑层。
- 二级、三级或更深节点声明子节点：继续在同一滑层递归下钻。
- 没有子节点的节点：视为叶子菜单，进入对应内容。
- 只有一个子节点时仍遵守同一规则，避免点击行为随子项数量变化。
- 不包含子节点的一级菜单保持直接进入内容的现有行为。

## 组件与状态设计

### 统一递归菜单模型

建立单一的规范化递归节点结构，作为渲染、搜索、权限过滤、激活态、标题解析和路径扁平化的共同数据源：

```ts
interface NavigationNode {
  id: string;
  title: string;
  titleEn?: string;
  route?: string;
  matchPrefixes?: string[];
  children?: NavigationNode[];
  chainOnly?: boolean;
}
```

- `id` 在整棵导航树中稳定且唯一，用于返回焦点与测试定位。
- 分支节点声明非空 `children`，其 `route` 仅可用于兼容旧深链，不参与点击导航。
- 叶子节点不声明 `children`，并且必须有有效 `route`。
- 权限、平台预设与连锁条件在规范化树上递归过滤。

迁移时以现有路由常量为输入，建立显式适配器，不复制路径字符串。至少覆盖现有的 Product Center、Marketing、Promotions、Members、Gift Cards、Reports、Print、Reservations、Finance、Store Menu、Device Management 及其他使用专用侧栏常量的模块。适配器必须保留稳定 ID，并把现有 `sidebarChildren` 转为真正的递归 `children`。`navModuleChildrenAsSheetSubnav`、标题查找、`flattenNavPaths` 及专用 sheet renderer 逐步改为遍历同一规范化树；迁移后不得再由专用渲染器维护第二份层级关系。

### 导航滑层

滑层维护一个导航栈，每一项包含：

- 当前父节点标识与标题；
- 当前层级待展示的子节点列表；
- 必要的来源节点信息，用于返回上一级。

打开一级菜单时初始化导航栈。点击分支节点时压栈并播放前进动画；点击返回时出栈并播放反向动画；点击叶子节点或关闭滑层时清空导航栈。

导航栈、当前根节点、查询词、动画状态与触发元素均为临时 UI 状态，不写入 `sessionStorage`，也不由当前路由反推恢复。打开另一个一级节点会先清空旧栈，再以新节点初始化。现有按路由自动打开 sheet 及恢复 sheet 开关状态的逻辑需要移除。

### 动画与布局

- 前进：当前列表向左退出，下一层从右侧进入。
- 返回：当前列表向右退出，上一层从左侧进入。
- 动画期间避免重复点击造成多次压栈或路由跳转。
- 延续当前滑层的宽度、遮罩、层级和视觉样式，窄屏不增加横向面板。
- 尊重 `prefers-reduced-motion`，需要减少动画时直接完成状态替换。

## 路由与内容行为

- 打开分支节点不更改当前业务路由，原内容保持不变。
- 点击叶子节点后使用现有路由机制导航，关闭滑层并在主区域渲染目标内容。
- 直接访问、刷新或通过浏览器前进/后退进入深层路由时，继续直接展示目标内容，导航滑层保持关闭。
- 当前路由仅用于叶子项高亮或上下文提示，不应导致打开一级菜单时自动进入默认子项。
- 现有 `defaultChildPath` 可继续服务旧链接重定向，但不用于一级菜单点击。

## 搜索规则

- 搜索框只过滤当前面板层级的菜单项；现有跨层级或联动主内容区的 hub 搜索行为退出使用。
- 打开、下钻、返回、叶子导航和关闭时均清空查询词。
- 搜索无结果时显示“未找到匹配菜单”的明确空状态，不改变规范化树。
- 从搜索结果点击分支节点时，下一层展示该节点完整的、经权限过滤后的子节点，不继承当前过滤结果。
- 搜索结果中的分支节点仍然只负责下钻，叶子节点仍然负责打开内容。

## 可访问性与键盘行为

- 分支节点使用按钮语义并提供可感知的后向箭头与辅助文本，不使用不符合逐级替换语义的 `aria-expanded`。
- 叶子节点保持链接语义。
- 滑层沿用 `role="dialog" aria-modal="true"`，打开期间焦点限制在滑层内，背景区域不可交互。
- 打开或下钻后，焦点进入当前层第一个可用菜单项；若没有可用项，则进入带 `tabindex="-1"` 的层级标题。
- 返回后按稳定节点 ID 恢复到触发下钻的节点；若该节点已被过滤或移除，则聚焦当前层第一个可用项，仍不存在时聚焦标题。
- `Escape` 关闭整个滑层；滑层内的返回按钮只回退一个层级。
- 滑层关闭后焦点回到最初触发的一级菜单。

## 异常与边界处理

- 未声明 `children` 的节点才是 authored leaf；声明了 `children` 的节点始终是 declared branch。
- 规范化与权限过滤按递归顺序进行。declared branch 若过滤后没有任何可见后代，则从其父级列表隐藏；不得重新解释为叶子，也不得使用其兼容路由进入无权限内容。
- authored leaf 缺少有效路由时禁用并在开发环境输出可定位的配置提示。
- 搜索造成的当前层零匹配仅显示搜索空状态，不影响节点权限与分支分类。
- 叶子节点缺少路由时保持当前内容，不关闭滑层，并显示现有项目规范内的非阻塞错误提示。
- 菜单因权限或平台预设被过滤后，再判断是否存在子节点，避免进入空层。

## 验收标准

1. 任意存在子菜单的一级菜单，点击后仅显示独立导航滑层，不加载默认子页面。
2. 二级节点存在三级节点时，点击后二级列表向左退出，三级列表从右进入。
3. 三级节点存在四级节点时，行为与上一条一致，不增加面板宽度。
4. 点击任意叶子菜单后，滑层关闭且对应内容正确展示。
5. 返回按钮可逐层回退；第一层返回关闭滑层。
6. 直接打开任意叶子路由可正常展示内容。
7. 权限过滤、搜索过滤及单子项场景不会产生空白滑层。
8. 键盘焦点、`Escape` 和减少动态效果设置符合上述规则。
9. 刷新、深链及浏览器前进/后退不会自动打开或恢复导航滑层。
10. 原 `tabs` / `sidebar` 全局子导航均从递归树进入滑层；业务页面内部局部 Tab 保持可用。

## 验证方案

- 单元验证：节点分类、导航栈压栈/出栈、过滤后节点判断、叶子路由选择。
- DOM 交互验证：一级打开、二至四级下钻、逐级返回、关闭、焦点恢复、动画期间防重复操作。
- 回归验证：现有二级滑层模块、没有子项的一级入口、直接深链、浏览器前进/后退、搜索及权限过滤。
- 浏览器验证：桌面与窄屏分别检查滑层宽度、遮罩、动画方向、内容保持和叶子页面加载。
