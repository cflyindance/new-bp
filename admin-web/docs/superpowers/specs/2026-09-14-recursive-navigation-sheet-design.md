# 递归菜单导航滑层设计

## 背景与目标

当前后台的一级菜单存在多种二级导航表现：部分模块使用侧滑层，部分模块直接进入默认内容，部分模块在主导航内展开。随着菜单出现三级、四级结构，交互规则不一致，用户难以预判点击结果。

本次统一为“先导航，再内容”：只要菜单节点存在子节点，点击该节点就进入独立导航滑层的下一层；只有点击没有子节点的叶子菜单时，才展示对应业务内容。

## 已确认方案

采用 A1：固定宽度、单面板逐级替换。

1. 点击带子节点的一级菜单，只打开独立导航滑层，不切换到默认子页面。
2. 点击带子节点的二级或更深层菜单，当前列表向左退出，下一级列表从右进入。
3. 点击叶子菜单，切换到其路由、关闭整组滑层并展示业务内容。
4. 滑层标题显示当前列表的父节点名称。
5. 返回按钮按导航栈逐级回退；位于第一层时返回则关闭滑层。
6. 无论菜单深度如何，滑层保持固定宽度，不横向叠加多个面板。

## 适用范围

规则由菜单节点是否存在 `children` 自动决定，不依赖模块名称或单独白名单。

- 一级节点存在子节点：使用导航滑层。
- 二级、三级或更深节点存在子节点：继续在同一滑层递归下钻。
- 没有子节点的节点：视为叶子菜单，进入对应内容。
- 只有一个子节点时仍遵守同一规则，避免点击行为随子项数量变化。
- 不包含子节点的一级菜单保持直接进入内容的现有行为。

## 组件与状态设计

### 菜单模型

沿用现有 `NavModule` / `NavItem` 菜单数据结构，通过 `children` 判断节点类型。若当前数据中的深层导航由单独常量描述，应在进入递归渲染前转换为统一节点结构；不复制业务路由配置。

### 导航滑层

滑层维护一个导航栈，每一项包含：

- 当前父节点标识与标题；
- 当前层级待展示的子节点列表；
- 必要的来源节点信息，用于返回上一级。

打开一级菜单时初始化导航栈。点击分支节点时压栈并播放前进动画；点击返回时出栈并播放反向动画；点击叶子节点或关闭滑层时清空导航栈。

### 动画与布局

- 前进：当前列表向左退出，下一层从右侧进入。
- 返回：当前列表向右退出，上一层从左侧进入。
- 动画期间避免重复点击造成多次压栈或路由跳转。
- 延续当前滑层的宽度、遮罩、层级和视觉样式，窄屏不增加横向面板。
- 尊重 `prefers-reduced-motion`，需要减少动画时直接完成状态替换。

## 路由与内容行为

- 打开分支节点不更改当前业务路由，原内容保持不变。
- 点击叶子节点后使用现有路由机制导航，关闭滑层并在主区域渲染目标内容。
- 直接访问、刷新或通过浏览器前进/后退进入深层路由时，继续直接展示目标内容，不强制先打开导航滑层。
- 当前路由仅用于叶子项高亮或上下文提示，不应导致打开一级菜单时自动进入默认子项。
- 现有 `defaultChildPath` 可继续服务旧链接重定向，但不用于一级菜单点击。

## 搜索规则

- 搜索框只过滤当前层级的菜单项。
- 下钻后搜索范围切换为新层级，并清空上一层查询，避免产生不可见过滤状态。
- 返回上一层时恢复该层列表；是否恢复查询以现有搜索体验为准，首版优先清空以保持可理解性。
- 搜索结果中的分支节点仍然只负责下钻，叶子节点仍然负责打开内容。

## 可访问性与键盘行为

- 分支节点使用按钮语义，并通过 `aria-haspopup` / `aria-expanded` 表达其可下钻状态。
- 叶子节点保持链接语义。
- 打开滑层后焦点进入滑层标题或首个菜单项；下钻后焦点移动到新层首项；返回后焦点恢复到触发下钻的节点。
- `Escape` 关闭整个滑层；滑层内的返回按钮只回退一个层级。
- 滑层关闭后焦点回到最初触发的一级菜单。

## 异常与边界处理

- 子节点为空数组按叶子节点处理。
- 分支节点缺少可用子项时不进入空白层，并在开发环境输出可定位的配置提示。
- 叶子节点缺少路由时保持当前内容，不关闭滑层，并显示现有项目规范内的非阻塞错误提示。
- 菜单因权限或平台预设被过滤后，再判断是否存在子节点，避免进入空层。

## 验收标准

1. 任意存在子菜单的一级菜单，点击后仅显示独立导航滑层，不加载默认子页面。
2. 二级节点存在三级节点时，点击后二级列表向左退出，三级列表从右进入。
3. 三级节点存在四级节点时，行为与上一条一致，不增加面板宽度。
4. 点击任意叶子菜单后，滑层关闭且对应内容正确展示。
5. 返回按钮可逐层回退；第一层返回关闭滑层。
6. 直接打开任意叶子路由可正常展示内容。
7. 权限过滤、搜索过滤及单子项场景不会产生空白滑层。
8. 键盘焦点、`Escape` 和减少动态效果设置符合上述规则。

## 验证方案

- 单元验证：节点分类、导航栈压栈/出栈、过滤后节点判断、叶子路由选择。
- DOM 交互验证：一级打开、二至四级下钻、逐级返回、关闭、焦点恢复、动画期间防重复操作。
- 回归验证：现有二级滑层模块、没有子项的一级入口、直接深链、浏览器前进/后退、搜索及权限过滤。
- 浏览器验证：桌面与窄屏分别检查滑层宽度、遮罩、动画方向、内容保持和叶子页面加载。
