# 员工声明模板批量分配

日期：2026-09-30。用户已确认完整交互流程及允许覆盖员工原模板。

## 目标与边界

从员工声明设置的模板详情中，批量修改适用员工的默认声明模板，确认后直接保存。不需要再点击薪资页面的“确定并保存”。保留现有五列表格，不新增操作列；不修改考勤、薪资金额、已确认声明快照或周期覆盖设置。

入口选择模板详情内“批量分配员工”，而非给列表增加列或要求逐一编辑员工。详情入口保留现有列表结构并减少重复操作。

## 交互

1. 模板详情存在有效已发布版本时展示“批量分配员工”。纯草稿、已停用且无有效发布版本不可分配。存在新版草稿但仍有有效发布版本时，明确本次分配使用当前已发布模板，不使用草稿正文。
2. 独立选择面板展示模板名称、适用范围及员工表格：复选框、员工姓名、工号、门店、当前模板。允许按门店筛选及姓名/工号搜索。门店模板固定对应门店；企业模板可筛选授权门店。
3. 初始不勾选。全选仅选择当前筛选结果中可分配的员工；改变筛选清空勾选，避免隐藏选择。已使用当前模板显示“已应用”且不能重复选择。
4. 确认前显示“将为 X 名员工应用此模板，其中 Y 名员工的原模板将被替换”。Y 仅统计原来选择其他自定义模板者；系统默认不计入替换人数。零选择不可提交。
5. 保存期间禁用重复提交和选择变更。完成后列出成功、失败、跳过数量；失败保留逐项原因，可仅重试失败员工。成功项不重复保存。无员工、加载失败均有明确状态，不把请求失败解释为无员工。

## 范围与数据来源

候选员工来自薪资模块现有员工数据适配层，不另建硬编码员工清单，不仅取当前期有考勤的人。对已有周期员工去重并结合现有员工名册，统一映射为薪资员工标识；不能可靠对应员工标识的名册项不可直接写入，提示数据不完整。身份以组织、门店、员工 ID 联合定位，不按姓名去重或跨店替换。

企业模板可分配范围为账号可访问门店内员工；门店模板为上述集合与模板绑定门店的交集。门店通过稳定 ID 匹配，旧数据只有门店名称时仅允许唯一精确别名映射；歧义或无映射条目不可选。单店账号不扩大为全品牌。客户端过滤不是正式权限边界，正式接口必须服务端校验组织、门店、员工归属与模板可用性。

当前仓库声明 repository 仅有 saveEmployeePreference，没有读取偏好的方法；runtime 从员工对象取默认模板。需增加按门店读取员工偏好的能力，并让单员工编辑、批量面板与声明渲染使用同一持久化偏好来源。不存在已保存偏好时兼容现有员工偏好；两者都没有才显示系统默认。读取失败不可回退为默认并继续覆盖。

## 保存与同步

将批量编排独立于设置渲染器，通过员工适配器提供候选清单与同步能力，通过门店 scoped repository 读取、保存偏好。沿用单员工保存契约，逐项处理并保留结果；不假装整批具有事务原子性。保留员工现有打印模式，缺省沿用 employee-only，不重新增加打印格式字段。

提交前重新获取有效发布状态及已选员工当前偏好、归属。若原模板变更导致确认内容变化，更新替换提示并要求再次确认；若模板失效或员工越界则不写入该员工并报告原因。切换组织/门店导致的过期异步响应不更新当前页面；后续未发出的写入停止，已完成写入不伪装回滚。

成功保存后同步对应员工的运行时默认偏好与编辑基线，并失效未确认声明的展示缓存；不覆盖其他未保存考勤或薪资草稿。重新打开员工编辑、切换期次、刷新页面后仍可读取已保存选择。已确认声明继续展示与打印原快照。正式 API 不能因失败静默降级到浏览器存储；演示模式沿用明确启用的本地存储，跨设备不共享。

## 验收

- 企业/门店、单店/多店权限组合正确；不同门店同名员工不串写，当前期无考勤员工不被无故漏掉。
- 支持搜索、筛选、当前结果全选；改变筛选清空选择；已应用跳过；允许覆盖并准确提示人数。
- 发布版与新版草稿并存时仅应用有效发布版；停用、范围变化和读取失败阻止错误写入。
- 部分失败后仅重试失败项；重复点击不重复提交；切换范围不混入旧响应。
- 单员工编辑与批量分配互相可见，刷新及切换期次后保持；不要求薪资页再次保存。
- 历史声明快照、考勤、金额、打印模式及其他未保存草稿保持不变。
- 自动化覆盖范围过滤、偏好读取、覆盖计数、结果聚合、重试及缓存同步；浏览器验收从模板详情分配到员工详情展示的完整路径。
