# Kiosk 小费前置后的支付方式路由澄清

## 目标

明确 `tip-procedure = 2`「支付方式选择页面之前」的实际点单行为：本次功能只交换“小费选择页面”和现有“支付方式选择页面”的先后顺序，不新建支付页面，也不改变信用卡或柜台支付按钮原有的后续动作。

## 页面顺序

双支付、双小费且选择值 `2` 时：

```text
完成点单前置步骤
  → 小费选择页面 /tippingPanel
  → 现有支付方式选择页面 /paymentType
  → 用户选择的支付流程
```

支付方式选择页必须使用现有页面和现有卡片布局，展示「信用卡/借记卡」与「柜台支付」，与用户提供的截图一致。

## 支付按钮行为

### 信用卡/借记卡

点击后复用现有信用卡处理函数：

1. 写入信用卡支付方式；
2. 不再次进入小费选择页；
3. 执行现有售罄复检与信用卡最低金额校验；
4. 进入信用卡刷卡支付页面；
5. 支付成功后沿用既有签名/订单完成流程，不进入“刷卡之后”小费流程。

### 柜台支付

点击后复用现有柜台支付处理函数：

1. 若 Dual Price 且已开启「柜台支付确认对话框」，继续展示现有确认框；
2. 用户确认后写入柜台支付方式；
3. 执行现有售罄复检和营业时间检查；
4. 直接创建订单并进入订单完成流程；
5. 不进入信用卡页面，也不再次进入小费选择页。

## 小费状态

- 小费页确认后保存的小费金额，在支付方式页选择信用卡或柜台支付时都必须保留并进入订单数据。
- 支付方式页通过订单级“支付方式选择前小费已完成”标志识别该场景，禁止信用卡分支再次跳回小费页。
- 从支付方式页返回小费页时可修改小费；再次确认后仍返回同一个现有支付方式页。
- 从小费页继续返回原点单入口时，按主规格清除本轮小费金额、选择元数据和完成标志。

本澄清规格继承主规格 `2026-08-26-kiosk-tip-before-payment-method-design.md` 的全部状态与异常规则；不能把“复用现有按钮行为”理解为绕过主规格新增的资格复核和安全回退。

## 支付页进入与选择防护

- 值 `2` 的 `/paymentType` 页面在信用卡和柜台支付两个分支实际执行前，都必须确认订单级 `completedBeforePaymentMethod` 标志存在，并重新确认所选方式当前仍可用。
- 完成标志缺失、刷新恢复状态不完整或异常直接进入 `/paymentType` 时，两个分支都不得直接支付/建单，必须交回统一支付入口重新判定；不能只保护信用卡分支。
- 小费页不能只依赖 `location.state.nextStep`。路由 state 丢失时必须结合订单级完成标志、选择元数据和统一入口恢复继续目标；仍无法确定时按主规格清理本轮小费并安全回退。
- 支付页停留期间若能力退化为单一方式，按主规格重新解析：唯一方式允许小费时保留并进入该方式；不允许小费或目标不明确时先清除小费金额、选择元数据和完成标志，再安全继续。

### 礼品卡

现有 `/paymentType` 可能同时展示礼品卡。本次不隐藏或复制礼品卡入口，但值 `2` 下选择礼品卡前必须按主规格清除预选小费金额、选择元数据和完成标志，再沿用礼品卡既有流程，不能把卡/柜台支付的小费带入礼品卡订单。

### 提交防重边界

本次必须保证流程防重：完成标志缺失不能绕过小费，信用卡不能重复进入小费页。订单接口级幂等机制不在本次新增范围，但支付页进入 loading 或确认提交后应沿用/补齐本地 in-flight 点击保护，信用卡按钮、柜台支付按钮及 DP 确认回调在请求完成前不得重复触发支付或重复建单。

## 与其他流程的关系

- `tip-procedure = 0`「刷卡之前」保持原顺序：支付方式页 → 小费页 → 信用卡支付。
- `tip-procedure = 1`「刷卡之后」保持现有支付后小费流程。
- 单支付方式不展示支付方式选择页。值 `2` 资格失效并回退为值 `0`；唯一方式允许小费时按“小费页 → 唯一支付流程”，唯一方式不允许小费时清除预支付小费状态并安全进入该方式。
- 本次不复制 `/paymentType` 页面，不增加新的信用卡或柜台支付提交实现。

## 验收标准

1. 值 `2` 时，小费确认后进入截图所示的现有支付方式选择页。
2. 在该页选择信用卡后进入信用卡校验与刷卡支付，不重复进入小费页。
3. 在该页选择柜台支付后，未配置确认框时直接建单完成。
4. 配置了现有柜台支付确认框时先弹框，确认后建单完成。
5. 两个支付分支都保留此前选择的小费金额。
6. 柜台支付不进入信用卡支付页；信用卡支付完成后不进入“刷卡之后”小费页。
7. 返回小费页修改后，再次确认仍进入同一个现有支付方式选择页。
8. 值 `0`、值 `1` 和单支付方式流程无回归。
9. 值 `2` 下异常直达或刷新支付方式页且订单完成标志缺失时，信用卡与柜台支付都不能绕过小费直接执行。
10. 路由 state 丢失时可从订单级状态恢复；无法恢复时清理本轮小费并安全回退。
11. 支付页能力退化为单一方式时按主规格保留或清理小费，不携带失效小费建单。
12. 选择礼品卡前清除本轮预选小费状态，礼品卡流程保持不变。
13. 支付或建单请求处理中，重复点击支付按钮或 DP 确认按钮不会重复触发请求。

## 验证策略

- 增加值 `2` 的信用卡/柜台支付分支行为测试。
- 覆盖柜台支付确认框开启与关闭。
- 验证两条分支的订单小费金额、目标路由和小费页防重。
- 覆盖信用卡、柜台支付在完成标志缺失、刷新、异常直达和能力退化时的共同安全回退。
- 覆盖礼品卡清理预选小费，以及按钮连点/DP 重复确认的本地提交防重。
- 运行 KioskLite 全量测试与生产嵌入构建，并发布校验 `dist/kpos/kiosklite`。
