# Kiosk 小费前置后的支付方式路由澄清

> 文档状态：现行权威合并规格，优先级高于同主题的阶段性设计稿。
> 本文记录最终确认的页面顺序、运行时裁决和按钮业务职责；字段存储细节同时维护在
> `dist/kiosklite/selfConfigList配置说明文档.md`。
> 支付方式集合与流程资格以 [Kiosk 小费支付方式与流程资格统一设计](./2026-08-26-kiosk-tip-payment-methods-and-procedure-eligibility-design.md) 为准。

## 三项设置的最终关系

1. 「支付设置 → 选择支付方式」定义 Kiosk 可配置的支付方式，`0` 为信用卡/借记卡，`1` 为柜台支付，`2` 为礼品卡。
2. 「小费设置 → 显示小费选项」没有总开关，默认、常驻展示三种对应多选项；只有支付设置已启用的对应方式才可勾选。
3. 已勾选的小费方式若从支付设置中取消，必须立即自动取消对应勾选；重新启用支付方式只恢复可选，不自动勾选。
4. 值 `0`、`1` 仅在信用卡支付和信用卡小费都启用时可选；值 `2` 仅在至少启用两种支付方式且所有已启用方式都勾选小费时可选。资格失效后优先回退值 `0`，值 `0` 也无效时清空。
5. 设置页负责配置合法性；点单运行时只要读取到值 `2` 或字符串 `'2'`，就必须执行本文定义的前置流程，不允许再次按支付能力或小费选项降级为旧的“小费页 → 直接信用卡支付”。

## 目标

明确 `tip-procedure = 2`「支付方式选择页面之前」的实际点单行为：本次功能只交换“小费选择页面”和现有“支付方式选择页面”的先后顺序，不新建支付页面，也不改变信用卡或柜台支付按钮原有的后续动作。

## 页面顺序

双支付、双小费且选择值 `2` 时：

```text
完成点单前置步骤
  → 小费选择页面 /tippingPanel
  → 现有支付方式选择页面 /paymentType
  → 用户选择的支付流程
```

支付方式选择页必须使用现有页面和现有卡片布局，并按当前已启用支付方式展示「信用卡/借记卡」「柜台支付」「礼品卡」中的对应选项；用户截图用于说明既有页面样式，不限制支付方式范围。

### 完整业务验收路径

两种流程共享的点单前置步骤为：

```text
开始点单 → 堂食 → 添加商品 → 查看订单 → 结账 → 跳过手机号和姓名
```

- 值 `0`“刷卡之前”：前置步骤 → Payment Method 选择信用卡 → 选择小费 → 发起信用卡支付请求。
- 值 `2`“支付方式选择页面之前”：前置步骤 → 选择小费并确认 → Payment Method → 选择信用卡 → 发起信用卡支付请求。
- 值 `2` 选择柜台支付：前置步骤 → 选择小费并确认 → Payment Method → 柜台支付确认框（仅配置开启时）→ 创建订单并完成。
- 值 `2` 选择礼品卡：前置步骤 → 选择小费并确认 → Payment Method → 现有礼品卡支付流程；全过程保留本轮小费金额、选择元数据和完成标志。

禁止出现的错误路径是：值 `2` 时“选择小费并确认 → 直接发起信用卡支付请求”，因为它跳过了 Payment Method 页和用户的支付方式选择。

### 与值 0、值 1 的对照

| `tip-procedure` | 名称 | 信用卡结账页面顺序 |
|---|---|---|
| `0` | 刷卡之前 | `/paymentType` → `/tippingPanel` → `/cardPayment` |
| `1` | 刷卡之后 | 信用卡支付 → 既有支付后小费流程 |
| `2` | 支付方式选择页面之前 | `/tippingPanel` → `/paymentType` → `/cardPayment` |

单支付方式通常不会显示 `/paymentType`；但若运行时实际读取到值 `2`，仍以值 `2` 为硬路由规则展示该页，防止重新落入“小费确认即发起信用卡支付”的旧分支。

## 按钮职责迁移

### 小费页「确认」按钮

值 `2` 时仅负责：

1. 校验并保存本次小费金额；
2. 保存选择元数据（预设比例、自定义金额或 No Tip）；
3. 写入订单级 `completedBeforePaymentMethod = true`；
4. 完成既有售罄复检；
5. 跳转 `/paymentType`。

该按钮不得写入信用卡支付方式、不得执行信用卡最低消费校验、不得进入 `/cardPayment`、不得调用支付接口。

### 支付方式页「信用卡/借记卡」按钮

该按钮承接原小费确认按钮中与信用卡支付相关的后续业务：写入信用卡支付方式，确认前置小费已完成，执行售罄复检和信用卡最低消费校验，再进入 `/cardPayment` 发起支付。此前保存的小费必须保留，且不得再次进入小费页。

### 支付方式页「柜台支付」按钮

保留既有柜台支付职责和既有确认框。无需确认框时直接写入柜台支付方式、执行售罄及营业时间检查、创建订单并完成；需要确认框时确认后执行同一流程。不得进入信用卡支付页，也不得再次进入小费页。

## 支付按钮行为

### 信用卡/借记卡

点击后复用现有信用卡处理函数：

1. 写入信用卡支付方式；
2. 不再次进入小费选择页；
3. 执行现有售罄复检与信用卡最低金额校验；
4. 进入信用卡刷卡支付页面；
5. 支付成功后沿用既有签名/订单完成流程，不进入“刷卡之后”小费流程。

### 柜台支付

点击后复用现有柜台支付处理函数：

1. 若 Dual Price 且已开启「柜台支付确认对话框」，继续展示现有确认框；
2. 用户确认后写入柜台支付方式；
3. 执行现有售罄复检和营业时间检查；
4. 直接创建订单并进入订单完成流程；
5. 不进入信用卡页面，也不再次进入小费选择页。

## 小费状态

- 小费页确认后保存的小费金额，在支付方式页选择信用卡或柜台支付时都必须保留并进入订单数据。
- 支付方式页通过订单级“支付方式选择前小费已完成”标志识别该场景，禁止信用卡分支再次跳回小费页。
- 从支付方式页返回小费页时可修改小费；再次确认后仍返回同一个现有支付方式页。
- 从小费页继续返回原点单入口时，按主规格清除本轮小费金额、选择元数据和完成标志。

本澄清规格继承主规格 `2026-08-26-kiosk-tip-before-payment-method-design.md` 的全部状态与异常规则；不能把“复用现有按钮行为”理解为绕过主规格新增的资格复核和安全回退。

## 支付页进入与选择防护

- 值 `2` 的 `/paymentType` 页面在信用卡、柜台支付和礼品卡任一分支实际执行前，都必须确认订单级 `completedBeforePaymentMethod` 标志存在，并重新确认所选方式当前仍可用。
- 完成标志缺失、刷新恢复状态不完整或异常直接进入 `/paymentType` 时，任何分支都不得直接支付/建单，必须交回统一支付入口重新判定。
- 小费页不能只依赖 `location.state.nextStep`。路由 state 丢失时必须结合订单级完成标志、选择元数据和统一入口恢复继续目标；仍无法确定时按主规格清理本轮小费并安全回退。
- 支付页停留期间若能力退化，只允许当前仍可用的支付按钮执行；不可用按钮隐藏或阻止提交。此处检查不得让流程回到“小费确认后直接支付”的旧分支。

### 礼品卡

礼品卡已纳入小费支付方式。值 `2` 下选择礼品卡时保留预选小费金额、选择元数据和完成标志，并进入现有礼品卡支付流程；不得清除小费或再次进入小费页。

### 提交防重边界

本次必须保证流程防重：完成标志缺失不能绕过小费，信用卡不能重复进入小费页。订单接口级幂等机制不在本次新增范围，但支付页进入 loading 或确认提交后应沿用/补齐本地 in-flight 点击保护，信用卡按钮、柜台支付按钮及 DP 确认回调在请求完成前不得重复触发支付或重复建单。

## 与其他流程的关系

- `tip-procedure = 0`「刷卡之前」保持原顺序：支付方式页 → 小费页 → 信用卡支付。
- `tip-procedure = 1`「刷卡之后」保持现有支付后小费流程。
- 正常配置下，单支付方式不具备值 `2` 的选择资格，设置页会回退为值 `0`，因此沿用单支付既有流程。若运行时仍读取到值 `2`，必须展示支付方式选择页并由用户点击当前可用方式，不能由小费确认直接支付。
- 本次不复制 `/paymentType` 页面，不增加新的信用卡或柜台支付提交实现。

## 验收标准

1. 值 `2` 时，小费确认后进入截图所示的现有支付方式选择页。
2. 在该页选择信用卡后进入信用卡校验与刷卡支付，不重复进入小费页。
3. 在该页选择柜台支付后，未配置确认框时直接建单完成。
4. 配置了现有柜台支付确认框时先弹框，确认后建单完成。
5. 两个支付分支都保留此前选择的小费金额。
6. 柜台支付不进入信用卡支付页；信用卡支付完成后不进入“刷卡之后”小费页。
7. 返回小费页修改后，再次确认仍进入同一个现有支付方式选择页。
8. 值 `0`、值 `1` 和单支付方式流程无回归。
9. 值 `2` 下异常直达或刷新支付方式页且订单完成标志缺失时，信用卡、柜台支付和礼品卡都不能绕过小费直接执行。
10. 路由 state 丢失时可从订单级状态恢复；无法恢复时清理本轮小费并安全回退。
11. 支付页能力退化为单一方式时只允许可用按钮提交，同时保留值 `2` 的“小费页 → 支付方式页”顺序。
12. 选择礼品卡时保留本轮预选小费状态，并沿用礼品卡支付流程。
13. 支付或建单请求处理中，重复点击支付按钮或 DP 确认按钮不会重复触发请求。

## 验证策略

- 增加值 `2` 的信用卡/柜台支付分支行为测试。
- 覆盖柜台支付确认框开启与关闭。
- 验证两条分支的订单小费金额、目标路由和小费页防重。
- 覆盖信用卡、柜台支付和礼品卡在完成标志缺失、刷新、异常直达和能力退化时的共同安全回退。
- 覆盖礼品卡保留预选小费金额、选择元数据和完成标志，并验证不会再次进入小费页；同时覆盖按钮连点/DP 重复确认的本地提交防重。
- 运行 KioskLite 全量测试与生产嵌入构建，并发布校验 `dist/kpos/kiosklite`。
