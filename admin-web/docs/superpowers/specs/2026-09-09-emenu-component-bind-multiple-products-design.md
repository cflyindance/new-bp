# eMenu Pro 组件绑定批量商品设计

> 模块：前厅管理中心 → eMenu Pro 菜单设计器  
> 日期：2026-09-09  
> 状态：已确认，待实施

## 1. 背景

现有“批量添加商品组件”以商品为主语：单选一个商品，再多选多个组件。运营还需要反向批量操作：单选一种商品组件，为当前分类下的多个商品分别创建并绑定该组件。

## 2. 目标与非目标

### 2.1 目标

- 在“批量添加商品组件”左侧新增“组件绑定批量商品”入口。
- 单选一种商品组件，多选当前分类下的商品。
- 每个选中商品生成一个独立的同类型组件实例，并将该商品 ID 写入实例的 `props.itemId`。
- 已存在“同组件类型 + 同商品绑定”的实例时跳过，保护用户已有排版。
- 新实例按商品勾选顺序纵向排列。

### 2.2 非目标

- 保留现有“批量添加商品组件”的入口与主流程；为兼容同类型多实例，将其绑定查询和删除行为收紧为按“组件类型 + 商品 ID”精确匹配。
- 不引入一个组件实例绑定多个商品的数组字段。
- 不在新弹窗中提供批量删除。
- 不修改已有匹配实例的位置、样式或属性。
- 不改变右侧组件拖拽和默认商品绑定能力。

## 3. 入口与可用状态

底栏顺序：

```text
[组件绑定批量商品] [批量添加商品组件] [删除菜单] [保存]
```

新入口与现有批量入口使用相同作用域及禁用规则：

- 作用于当前选中的菜单页。
- 商品来自当前页 `groupId + categoryId` 对应分类的 `saleItems`。
- 未选中有效菜单页时禁用。
- 模板已发布、页面操作不可编辑时禁用。

## 4. 弹窗交互

```text
┌ 组件绑定批量商品 ───────────────────────────┐
│ 当前菜单组 › 当前分类                        │
├──────────────────┬──────────────────────────┤
│ 商品组件（单选）  │ 商品（多选）              │
│ ○ 加购            │ ☑ 蜜汁鸡翅               │
│ ● 菜品名称        │ ☑ 炭烤羊排               │
│ ○ 销售价          │ ☐ 孜然牛肉串             │
│ ○ 会员价          │                          │
│ ○ 售罄            │                          │
├──────────────────┴──────────────────────────┤
│                         [取消] [添加到当前页(2)]│
└─────────────────────────────────────────────┘
```

### 4.1 选择规则

- 左侧五种商品组件使用单选：
  - `AddToCartImageBtn`（加购）
  - `SoldOutImage`（售罄）
  - `DishName`（菜品名称）
  - `SalePrice`（销售价）
  - `MemberPrice`（会员价）
- 右侧商品列表使用多选，选择顺序决定新实例的纵向排列顺序。
- 弹窗每次打开时清空上次组件和商品选择，避免误操作。
- 未选择组件或未选择商品时，“添加到当前页”按钮禁用。

### 4.2 已绑定状态

商品行应显示当前组件类型的绑定状态：

- 未绑定：可勾选。
- 已在画布：当前页已存在相同 `component` 且 `props.itemId` 等于该商品 ID；默认不勾选，并显示“已在画布”。
- 提交时必须再次去重，不能只依赖界面状态。
- `selectedProductIds` 是去重的有序集合：首次勾选追加到末尾，取消时移除，再次勾选时追加到末尾。
- MVP 不提供“全选”，避免引入已绑定商品是否参与全选的额外规则。

### 4.3 提交结果

- 计算待创建商品：选中商品减去当前页已有匹配实例。
- 待创建数量为 0 时不 dispatch，提示“所选商品均已绑定”。
- 创建成功后弹窗保持打开，刷新绑定状态并清空本次商品选择，便于继续选择另一组件。
- Toast 显示“已为 N 个商品添加〈组件名称〉”；若同时跳过已有项，追加“，跳过 M 个已绑定商品”。

## 5. 数据与布局

### 5.1 实例数据

每个商品创建一个独立实例：

```js
{
  ...cloneJson(BLOCK_LIBRARY[selectedType]),
  id: generateId(),
  props: {
    ...cloneJson(BLOCK_LIBRARY[selectedType].props),
    itemId: String(product.id)
  }
}
```

新增或改造递归克隆函数，为根节点及任意深度子节点生成全新 ID。仅根节点写入 `itemId` 和绝对布局，后代保留模板属性。不同商品实例之间的所有节点 ID 必须唯一。除 `itemId` 与布局坐标外，实例结构沿用现有 `BLOCK_LIBRARY`。

### 5.2 纵向布局

- 以现有批量绑定逻辑使用的画布安全起点为基准。
- 按商品勾选顺序从上向下排列。
- 相邻实例使用固定间距，沿用现有 `STACK_GAP`。
- 下一个实例的 Y 坐标为上一个实例 Y + 实例高度 + 间距。
- X 坐标保持一致。
- 不移动或重排已有实例；如超出画布可视高度，仍保留连续坐标，由用户后续调整。

## 6. 技术方案

在现有 `dist/emenu-pro/embedded-product-binding.js` 内扩展第二种批量模式，共用以下能力：

- Redux store 定位与 `paletteSlice` 读取。
- 当前页和当前分类商品解析。
- `PRODUCT_COMPONENT_TYPES`、`COMPONENT_META`、`BLOCK_LIBRARY`。
- ID 生成、深拷贝、递归组件树 ID 补齐、页面 children 写入、Toast。

### 6.1 多实例兼容

绑定查询统一扫描当前页全部顶层 `children`，按精确二元组 `(component, String(props.itemId))` 判断。

- 新入口：精确匹配存在时跳过，否则新增。
- 现有“批量添加商品组件”入口：精确匹配存在时显示已绑定；不存在时允许新增，不删除或替换绑定其他商品的同类型实例。
- 现有移除操作：只删除当前所选商品的精确匹配实例，不影响其他商品。
- 不再以“同类型第一个实例”作为绑定状态真源，也不再执行同类型跨商品静默替换。

新增状态与 DOM 使用独立命名，避免与现有商品主导模式互相污染：

```js
state.componentToProducts = {
  open: false,
  selectedType: null,
  selectedProductIds: [],
  pageId: null,
  categoryKey: null,
};
```

新增入口插入到现有 `#emenu-batch-binding-trigger` 之前。CSS 追加到 `dist/emenu-pro/embedded-shell.css`，复用现有弹窗遮罩、按钮和双栏基础样式，仅新增组件单选列表、商品复选列表与状态样式。

## 7. 边界与错误处理

- 当前分类无商品：右侧展示“当前分类暂无商品”，确认按钮禁用。
- Redux store、当前页或分类数据不可用：不执行写入并显示错误 Toast。
- 弹窗记录 `pageId` 与 `categoryKey`。任一变化时清空组件和商品选择，刷新标题、商品列表和绑定状态，避免将旧选择提交到新页面。
- 发布态在弹窗打开期间发生变化：关闭弹窗并同步禁用两个批量入口。
- 提交前重新读取 store、当前 `pageId`、分类、编辑态及 `saleItems`；将选择与当前商品集合求交。页面变化、数据不可用或不可编辑时不得 dispatch，并显示明确 Toast；进入发布态时关闭弹窗。
- 商品 ID 比较统一转为字符串，写入 `props.itemId` 时也使用字符串。
- 不触碰 host globals、EventBus 或其他 sibling 页面。

## 8. 验收标准

1. “组件绑定批量商品”显示在“批量添加商品组件”左侧。
2. 未选页或发布态下两个批量入口均正确禁用。
3. 弹窗左侧组件只能单选，右侧商品可以多选。
4. 选择一种组件和 3 个未绑定商品后，当前页新增 3 个独立实例，各自 `itemId` 正确。
5. 新实例按商品勾选顺序纵向排列；取消后重新勾选的商品排列在末尾。
6. 已有“同类型 + 同商品”实例被跳过，位置和属性不变。
7. 精确匹配位于第二个及以后同类型实例时仍正确跳过。
8. 现有批量入口新增或移除一个商品的组件时，不删除其他商品的同类型实例。
9. `MemberPrice` 等含子节点组件批量创建后，所有根节点和后代节点 ID 均唯一。
10. 全部已存在时不修改页面数据，并给出明确提示。
11. 切换菜单页或进入发布态后，旧选择不能写入错误页面。
12. 现有“批量添加商品组件”流程、默认商品绑定和单组件属性编辑通过回归验证。

## 9. 影响范围

- Owner：eMenu Pro 嵌入扩展层。

  - `dist/emenu-pro/embedded-product-binding.js`
  - `dist/emenu-pro/embedded-shell.css`

  - 现有页面组件和营销组件分组规则

## 10. 构建与验证

本需求默认只修改 `dist/emenu-pro/embedded-product-binding.js`、`dist/emenu-pro/embedded-shell.css` 及 focused verifier，不修改 `vendor/emenu-new`。

- 执行 `node --check dist/emenu-pro/embedded-product-binding.js`。
- 执行 focused verifier，覆盖精确匹配、多实例跳过、旧入口隔离、顺序布局及递归 ID 唯一性。
- 从项目根执行 `npm run build`，确认成功退出。
- 构建后确认 `dist/emenu-pro/index.html` 仍引用 `embedded-shell.css` 与 `embedded-product-binding.js`，且扩展脚本未被构建流程丢失。
- 浏览器验证前强制刷新父页面并重新加载 eMenu Pro iframe。
- 仅当实施中实际修改 `vendor/emenu-new` 时，额外执行 `npm run build:emenu-new-embed -- --skip-install`，并校验 `dist/emenu-new/index.html` 引用本次哈希资源、`dist/emenu-new/.emenu-embed-build.json` 存在且 `builtAt` 为本次构建时间。
