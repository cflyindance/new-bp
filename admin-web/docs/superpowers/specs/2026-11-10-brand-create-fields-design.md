## 范围与规则
- 联系人选填，保留最多 30 字；空白按未提供保存，核对展示“—”。品牌名称原必填和 60 字限制保持。
- 创建品牌信息与核对弹框不显示品牌编码输入或自动生成占位。确认创建时沿用 BID 发号，code 默认等于 bid，B 加八位数字，例如 B00001234。预览／取消不分配编号；持久化失败不更新成功状态或消耗已保存序列；历史品牌及内部演示种子显式 code 保留。
- 创建表单和核对弹框移除时区；兼容对象时区仍采用原默认 Asia/Shanghai，不迁移历史值。
- 经营业态、产线为分组必选，各至少一个；POS 默认勾选保持。下一步、步骤跳转、最终创建与服务创建入口均校验，错误分项提示。
- 原三步、菜单选择、门店归属检查、品牌 Admin 开通流程和草稿保护保持。创建后编号与 BID 相同时，详情页头只显示一次。

## 方案
复用既有 BID 生成器作为默认品牌编码，避免另设编号序列。纯校验函数供 UI 与创建方法共用；CreateMerchantInput 的联系人、编码、时区可省略。只改变无显式 code 的默认生成，内部演示门店的代码前缀是种子补齐标记，保留其兼容性。BID 分配同时避开历史 B+8 位 code 的占用。

## 影响文件
brand-access-ui.ts 负责表单、核对和创建参数；brand-create-validation.ts 负责字段校验；enterprise-merchant-store.ts/type.ts 负责可选输入与默认值；enterprise-merchant-bid.ts 负责编号占用；enterprise-merchant-ui.ts 负责避免页头重复编号。
