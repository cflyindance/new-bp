# 移除批量“设为禁止”快捷功能设计
> [!IMPORTANT]
> **文档状态（截至 2026-08-19）：当前有效**
> **当前重建适用性：** 移除批量设为禁止的交互结论仍适用于当前限购数量页。
> **替代 / 权威指向：** [文档索引](../README.md)；[当前产品 SPEC](../../../../产品PRD/exports/2026-08-19-menu-order-limit/SPEC.md)。


## 背景

“限购数量 > 产线配置 > 批量设置”当前同时提供数量输入、【应用数量】和【设为禁止】。由于输入 `0` 后点击【应用数量】已经能够表达禁止下单，【设为禁止】属于重复快捷入口。

## 目标

- 从批量设置工具栏移除【设为禁止】按钮。
- 移除仅服务于该按钮的 `zero` 批量应用模式。
- 保留通过批量数量输入 `0` 后点击【应用数量】设置禁止下单的能力。
- 保持单项数量输入、批量选择和数量矩阵数据结构不变。

## 交互设计

批量工具栏保留：

1. 已选数量。
2. 全选当前产线。
3. 清空选择。
4. 数量输入框。
5. 【应用数量】。
6. 【取消】。

不再展示【设为禁止】。

批量数量输入规则保持不变：

- 输入 `0` 并点击【应用数量】：所选商品或分类保存为 `configured: true, value: 0`，表示禁止下单。
- 输入大于 `0` 的有效整数并点击【应用数量】：所选目标使用该数量作为上限。
- 输入为空、负数或非整数：提示“请输入大于或等于 0 的整数”，不应用批量配置。只有明确输入 `0` 才表示禁止下单。

单项数量输入 `0` 的语义保持不变。

## 代码与数据处理

- 两处批量工具栏渲染均删除 `data-apply-batch="zero"` 按钮。
- 批量应用事件只接受 `data-apply-batch="value"`。
- 批量应用先校验输入框不是空字符串，再将其转换为数字；空输入不得隐式转换成 `0`。
- 批量值始终从 `batchLimitValue` 输入框读取，不再根据 `zero` 模式生成数值。
- 不修改 `configured` / `value` 结构、保存草稿、复制规则、发布快照及历史规则兼容逻辑。

## 验收标准

- 普通和兼容批量工具栏均不再出现【设为禁止】。
- 源码中不再存在 `data-apply-batch="zero"` 或专用 `zero` 模式分支。
- 批量输入 `0` 后点击【应用数量】，所选目标仍保存为禁止下单。
- 批量输入为空时点击【应用数量】，显示校验提示且不修改所选目标。
- 【应用数量】、【取消】、批量选择和清空功能正常。
- 单项输入 `0` 的行为不变。
- 全部订单限购验证和 JavaScript 语法检查通过。
