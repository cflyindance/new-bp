# 自助餐场景额度商品表格独立列设计

## 背景

“配置额度”弹窗中的限购商品表格目前将产线、分类、门店和商品编码混合展示，商品名称还带有产线后缀。信息难以按列扫描，并产生重复内容。

## 目标

在不改变筛选、批量设置、跨门店额度保存和场景商品增删逻辑的前提下，将商品相关信息拆分为语义清晰的独立列。

## 表格结构

采用已确认的方案 A。商品或菜品集成员限购的列顺序为：

1. 勾选
2. 商品
3. 产线
4. 分类
5. 门店
6. 限购数量
7. 状态
8. 操作

分类限购没有独立商品实体，避免重复展示同一分类；其列顺序为：勾选、分类、产线、门店、限购数量、状态、操作。

展示规则：

- 商品列优先展示行模型的 `shortName`；缺失时回退 `name`，并仅移除与当前产线完全匹配的末尾后缀。不展示 `key`、商品编码或其他标识字段。
- 不再由视图层把产线名称拼接到商品名称后。优先使用已有 `shortName`；旧数据只有完整名称时，仅移除与当前产线名称完全一致的末尾 `（产线）`。例如“可乐（eMenu）”在产线为 `eMenu` 时展示“可乐”，其他括号内容不裁剪。
- 产线、分类和门店各自独立成列。
- 不在其他列中重复展示商品编码。
- 空结果行的跨列数量与新表头保持一致。
- 产线或分类缺失时展示 `—`；门店优先展示门店名称，名称不可用时展示门店标识，二者均不可用时展示 `—`。

## 行为保持

- 门店、状态和关键词筛选行为不变。
- 产线筛选选项只展示产线名称，不展示门店名称或其他前缀。
- 分类筛选选项只展示分类名称，不展示门店名称或其他前缀。
- “参与门店”指当前规则 `addedStoreIds(draft)` 返回的门店；选项和结果仅来自这些门店在当前人数/轮次场景已加载的限购对象行，不包含集团其他可用门店。
- 全部门店模式下，同名产线合并为一个选项；选择后匹配所有参与门店当前场景中同名产线的数据。名称取 `row.lineLabel`，比较键为 `String(row.lineLabel).trim()`；严格区分大小写，不做模糊匹配、全半角转换或其他标准化。
- 全部门店模式下，同名分类合并为一个选项；选择后匹配所有参与门店当前场景中同名分类的数据。名称取 `row.categoryName`，比较键为 `String(row.categoryName).trim()`；严格区分大小写，不做模糊匹配、全半角转换或其他标准化。
- 指定门店模式下，选项仍只展示名称，并仅从该门店当前场景的行集合生成。产线选项适用于商品、菜品集成员和分类限购行；分类选项取商品或菜品集成员行的 `row.categoryName`，分类限购不展示分类筛选器。
- 门店筛选变化时清空当前产线与分类筛选，随后按新的门店范围重新生成选项，避免保留范围外的已选值。
- `lineLabel` 或 `categoryName` 缺失、为 `null`/`undefined`，或首尾空格清理后为空时，不生成筛选选项，也不参与名称筛选匹配；表格单元格仍按展示规则显示 `—`。
- 合并仅改变筛选选项与匹配条件；额度编辑、批量操作和商品增删继续使用门店 ID 与限购对象 ID 定位数据。
- 跨门店默认集合展示行为不变。
- 单项额度、批量额度、状态和移除操作的数据归属不变。
- 添加或删除商品仍只影响对应门店的当前场景。
- 分页、当前页全选和批量删除行为不变。

## 样式

- 使用现有表格视觉体系，不新增设计语言。
- 为产线、分类、门店提供独立列宽，商品列保留较高视觉优先级。
- 在弹窗宽度不足时继续使用现有横向滚动，不压缩额度输入框或操作按钮。

## 验收标准

- 商品或菜品集成员限购表头依次展示勾选、商品、产线、分类、门店、限购数量、状态和操作。
- 分类限购表头依次展示勾选、分类、产线、门店、限购数量、状态和操作，不重复分类列。
- 商品行各字段与表头严格对应。
- 配置额度弹窗的限购对象表格不展示商品编码；添加商品弹窗等其他流程保持现状。
- 商品列优先展示 `shortName`；回退完整名称时只移除与当前产线完全匹配的末尾后缀，不增加视图层产线后缀。
- 当前页全选和单行勾选仍对应正确的门店与限购对象记录。
- 全部门店与单门店筛选下的行数和门店归属正确。
- 产线和分类下拉不含门店前缀，同名选项只出现一次。
- 选择合并后的同名产线或分类时，结果包含所有参与门店中的同名数据；指定门店后只包含该门店数据。
- 切换门店筛选后，已选产线和分类被清空，并依据新的门店范围重新生成选项。
- 分类限购场景不展示分类筛选器；商品和菜品集成员场景正常展示分类筛选器。
- 空或缺失的产线、分类名称不会生成空白、`null` 或 `undefined` 筛选项。
- 编辑单项额度、批量设置额度及移除商品仍写入正确门店和当前场景。
- 相关静态验证、语法检查和本地浏览器验收通过。
