# 自助餐双计量全宽布局设计

## 目标

配置额度页中，菜品集的“按份限制”和“按种限制（SPU）”以一行两列展示，并共同撑满弹框内容宽度，提升输入区的可读性与空间利用率。

## 布局

- “当前菜品集”名称及商品数量独占第一行。
- 双计量卡片位于第二行，使用等宽两列网格，各占一半可用宽度。
- 每张卡片内部继续使用两列展示“每人”与“整桌”输入项。
- 使用浏览器视口媒体查询响应：视口宽度大于 `720px` 时保持双计量两列；视口宽度小于或等于 `720px` 时，双计量卡片和卡片内部输入项降为单列，避免输入框被过度压缩。弹框自身宽度不作为断点测量对象。

## 实现边界

- 仅调整菜品集双计量区域的 CSS 布局及对应布局回归脚本，不改变计量数据、校验、保存或汇总逻辑。
- 保留现有启用态边框、背景色、字段文案和单位。
- 不影响商品列表及其他限购对象类型。

## 验收标准

1. 常规弹框宽度下，两张卡片处于同一行且等宽撑满内容区。
2. “当前菜品集”信息不占用双计量卡片的横向空间。
3. 两张卡片内部输入框完整可见，无横向滚动条。
4. 视口宽度大于 `720px` 时，两张卡片等宽、满宽且位于同一行；视口宽度小于或等于 `720px` 时，卡片与内部输入项均切换为单列。
5. 更新 `scripts/verify-buffet-dual-measure-editor.mjs`，校验父容器单列、双计量区域等宽两列、`720px` 媒体查询及窄屏单列规则。
6. 浏览器分别在 `1024px` 和 `720px` 视口验收卡片布局、输入完整性以及页面无横向滚动。
7. 现有自助餐布局与双计量回归脚本通过。
