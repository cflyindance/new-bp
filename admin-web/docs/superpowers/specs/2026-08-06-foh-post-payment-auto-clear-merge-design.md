# 前厅“付款后自动清桌”配置合并设计

## 背景

前厅管理中心“清桌与换企台”当前同时展示：

- `169 付款后清桌模式`：主开关与适用产线多选。
- `534 自动清桌`：主开关与各产线超时分钟数。

两个入口都控制自动清桌，但触发语义和参数拆散，容易造成重复配置。现将 `169` 合并至 `534`，以一个入口统一配置付款后的自动清桌行为。

## 目标

- “清桌与换企台”只保留一个自动清桌入口，标题为“付款后自动清桌”。
- 保留各产线超时分钟数，统一解释为付款完成后的等待时间。
- 迁移已有 `169` 与 `534` 配置，避免已启用门店丢失设置。
- `169` 从设置目录、搜索、权限导航和平台预设中退役，不再被重新生成。

## 合并模型

### 唯一配置项

- 以 `seq 534` 为合并后的唯一配置项。
- 标题：`付款后自动清桌`。
- 功能描述：付款完成后，按各产线设置的超时分钟数自动清桌。
- 产线：eMenu、Kiosk、POS、POS GO、PayPad、SDI。
- 分钟数为 `0` 时，该产线不启用付款后自动清桌。

### 退役项

- `seq 169` 标记为已合并至 `534`。
- 从目录生成排除表、前厅分组分配、组内排序、产线范围矩阵及运行时可见目录中移除。
- 删除仅服务于 `169` 的独立渲染与事件绑定代码；历史存储键只用于一次性迁移，不再作为界面数据源。

### 分组结果

“清桌与换企台”最终按以下顺序展示 4 项：

1. 534 付款后自动清桌
2. 642 清桌按钮
3. 351 清桌通知
4. 347 更换企台

## 数据迁移

迁移在 `534` 配置首次读取时幂等执行：

1. 读取现有 `534` 主开关与各产线分钟数。
2. 读取旧 `169` 主开关及选中产线。
3. 迁移前先按现有 0–999 规则归一化 `534` 分钟值：字段缺失、`null`、空字符串、字符串 `"0"`、非有限数、非法值和负数均按 `0` 处理；只有归一化后大于 `0` 的有效值享有优先权。
4. 对旧 `169` 已选择、且 `534` 归一化分钟数为 `0` 的相同产线，写入默认 `60` 分钟。
5. 若 `169` 或 `534` 任一主开关已开启，则保持合并后的 `534` 主开关开启。
6. 已存在的非零 `534` 分钟数优先，不被旧 `169` 覆盖。
7. `169` 不包含 Kiosk，因此不会凭空为 Kiosk 写入迁移值；已有 `534` Kiosk 值继续保留。
8. 迁移标记必须与目标 `534` 配置使用同一门店/租户配置作用域，不得使用跨作用域的全局单例标记；当前本地原型通过同一设置存储适配层保存，接入后端时与 `534` 记录共同按门店/租户落库。
9. 只有分钟数据与合并后的主开关均成功写入后才能记录迁移完成；任一写入失败时不写标记，下次加载允许重试。
10. 标记存在后不再读取旧 `169` 回填，因此用户迁移后主动把某产线改为 `0`，刷新或再次进入页面时仍保持 `0`。

若浏览器存储不可用，页面继续使用现有容错方式，不阻塞渲染。

## 验证

- 专项校验确认 `169` 不再出现在运行时目录与“清桌与换企台”分组。
- 专项校验确认 `534` 标题、描述、4 项顺序和退役排除规则正确。
- 数据迁移测试覆盖分钟值缺失、`null`、`"0"`、非法值、负数与有效非零值，并确认只有有效非零 `534` 值优先。
- 主开关测试覆盖仅 169 开、仅 534 开、均关、均开四种组合，结果符合逻辑 OR。
- 迁移测试明确断言：Kiosk 不会由 `169` 生成 `60`；迁移后用户把产线改回 `0`，再次加载不会被旧 `169` 恢复；写入失败不记录标记；重复加载幂等。
- 运行前厅产线范围校验、TypeScript 类型检查及生产构建。
- 浏览器验证分组只显示一个“付款后自动清桌”，保留六条产线分钟输入，旧标题不再出现。

## 非目标

- 不修改清桌按钮、清桌通知或更换企台的业务逻辑。
- 不改变 `534` 的分钟范围与默认值（0–999，迁移默认 60）。
- 不删除旧 `169` 本地存储数据；仅停止把它作为当前配置源。
