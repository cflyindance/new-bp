# 菜单外部链接编辑设计

## 目标

在菜单路由配置的“菜单用途”中开放外部链接配置。发布后商家后台点击该菜单时，以浏览器新窗口打开 URL；编辑器预览不请求该网址。

## JSON 约束

- 严格沿用参考 JSON 字段，不新增 `target`、`openMode` 等字段。
- 外部链接节点写入 `type: "external"`、`path` 和 `url`。
- `external` 的打开语义固定为新窗口，不提供当前窗口/新窗口切换。
- 切换为 `external` 时删除 `microAppConfig`；切换为其他用途时按对应规则清理不适用字段。

## 表单

- 菜单用途顺序：仅目录、项目内页面、iframe 嵌入、外部链接。
- 外部链接展示两个必填字段：商家后台路由地址、外部链接地址。
- 外部链接地址仅接受 `http://` 或 `https://`。
- 外部链接可配置为一级、二级或三级菜单；一级、二级仍可同时包含子菜单。

## 校验与兼容

- `EditableMenuNodeType` 增加 `external`。
- 可打开菜单仍要求非空 `path`。
- `external` 要求有效 HTTP(S) `url`，且不得生成 `microAppConfig`。
- 既有 `external` 节点不再作为兼容保护节点，可在编辑器中修改。
- `micro-app` 和历史第四级节点继续只读保护。
- 导入、导出和发布不迁移旧数据。

## 树与预览

- 菜单树类型标签显示“外链”，使用独立的紫色弱强调样式。
- 详情和商家菜单预览显示外部 URL，并明确“发布后在新窗口打开”。
- 编辑器预览不调用 `window.open`，不请求第三方页面。
- 商家后台运行时按既有 `external` 语义使用新窗口，并应采用 `noopener` 安全隔离；本次编辑器改动不新增 JSON 字段。

## 验证

1. 新增或编辑外部链接节点可保存 `type/path/url`。
2. 非 HTTP(S) URL 被阻止并显示明确错误。
3. `external` 与 inner/iframe/directory 相互切换时字段清理正确。
4. 既有 external 节点可编辑，micro-app 仍只读。
5. 树和预览显示“外链/新窗口打开”，但预览不发起外部请求。
6. 导出字段完全匹配参考 JSON，不包含打开方式新字段。
7. 参考兼容、权限规则、菜单树问题状态和 TypeScript 回归通过。
