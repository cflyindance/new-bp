# 员工分配汇总角色卡片设计

## 背景与目标

“员工分配汇总”目前只能逐个员工查看分配结果，管理者无法快速判断各角色在筛选周期内贡献了多少原始小费、扣除了多少、获得了多少以及最终保留多少小费。

本次在员工列表上方增加“角色汇总”区域，以角色卡片呈现分配前小费、扣除、分配获得、分配后小费，并与现有筛选条件和员工列表联动。日期分配汇总、员工详情和分配计算流程不在本次修改范围内。

## 页面结构

员工分配汇总页面自上而下保持以下层级：

1. 门店与日期范围。
2. “日期分配汇总 / 员工分配汇总”切换及角色、员工、分配状态筛选。
3. 新增“角色汇总”区域。
4. 现有员工列表。

角色汇总采用响应式卡片布局。宽屏每行展示三至四张卡片，容器宽度不足时自动换行。没有符合当前筛选条件的角色时不展示空卡片，并显示角色汇总空状态。

每张卡片包含：

- 角色名称。
- 当前筛选结果中的去重员工人数。
- 分配前小费。
- 扣除。
- 分配获得。
- 分配后小费。
- 当筛选周期同时包含已分配和待分配记录时，显示“部分待分配”提示。

## 数据口径

角色归属以员工每天实际参与分配时记录的角色为准，不使用员工当前主角色回写历史数据。

- 同一员工在不同日期或不同分配记录中使用不同角色时，分别计入对应角色。
- 一笔员工日期分配结果只能进入一个角色汇总，避免金额重复。
- 角色名称为空时归入“未设置角色”。
- 员工人数按角色内员工 ID 去重；同一员工可分别出现在多个角色的人数中。

角色卡片遵循当前门店、日期范围、角色、员工与分配状态筛选。角色筛选已选中时，只展示该角色卡片。员工筛选选中部分员工时，卡片金额和人数只统计这些员工。

金额口径：

- `分配前小费`：所有符合条件记录的分配前金额之和，包括待分配记录。
- `扣除`、`分配获得`、`分配后小费`：只统计已分配记录。
- 某角色没有任何已分配记录时，后三项显示 `—`，不得将待分配预测值展示为正式结果。
- 已分配与待分配记录并存时，后三项展示已分配记录合计，并显示“部分待分配”。
- 全部记录已分配时不显示待分配提示。

角色汇总应满足已分配数据的金额关系：`分配后小费 = 分配前小费（已分配部分） - 扣除 + 分配获得`。因为卡片的“分配前小费”同时包含待分配记录，混合状态卡片不使用四列直接做等式校验；测试应分别校验已分配子集守恒。

## 交互

角色卡片是可操作控件：

- 点击某张卡片后，将右上角角色筛选同步为该角色，重新计算员工候选项、角色卡片和员工列表。
- 再次点击当前角色卡片，角色筛选恢复“全部角色”。
- 角色筛选通过下拉框变更时，角色卡片同步刷新。
- 卡片支持键盘聚焦，并可通过 Enter 或 Space 触发选择。
- 选中卡片需有清晰的视觉高亮和 `aria-pressed="true"` 状态。
- 点击卡片不改变门店、日期、员工或分配状态筛选。
- 不新增角色详情页，也不改变现有员工行点击进入员工详情的行为。

## 技术设计

在 `tipout-summary-ui.js.txt` 中增加独立、无副作用的角色聚合函数。输入必须是筛选日期范围内尚未按员工合并的逐日数据集（`dailyRows[].employeeResults[]`），不能使用员工汇总列表作为输入。聚合前先在每条逐日员工结果上应用员工范围与分配状态筛选，再按该记录携带的实际角色分组；这样才能保留同一员工跨日期的角色变化。输出为按角色分组的展示模型，至少包含：

- `role`
- `employeeIds`
- `employeeCount`
- `beforeCents`
- `deductedCents`
- `receivedCents`
- `finalAmountCents`
- `allocatedRecordCount`
- `pendingRecordCount`
- `status`

`status` 仅允许以下枚举值：

- `complete`：该角色符合筛选范围的记录全部已分配。
- `partial`：该角色同时存在已分配和待分配记录，界面显示“部分待分配”。
- `pending`：该角色记录全部待分配，后三项金额显示 `—`。

卡片默认按“分配后小费”降序排列；没有已分配结果的卡片排在有结果的卡片之后，同金额时按角色名称升序排列。金额展示复用现有员工汇总的货币格式化方法、正负号和语义颜色。

聚合函数只负责数据归集，不访问 DOM。`distribution.js.txt` 从同一份逐日数据分别生成角色汇总和员工汇总，二者应用相同的门店、日期、员工范围与分配状态条件；角色筛选既用于限制角色卡片，也用于限制员工列表。模板新增角色汇总容器；样式放入现有 tips 页面样式文件。

角色点击沿用现有 `employeeSummaryFilters.role` 状态与 `handleEmployeeSummaryRoleChange` 刷新链路，避免引入第二份角色选择状态。

## 异常与空状态

- 没有符合筛选条件的数据：角色汇总区域显示“当前筛选条件下暂无角色汇总”。
- 角色缺失：统一显示“未设置角色”。
- 金额字段缺失或不可解析：按现有金额标准化规则处理为 0；不得输出 `NaN`。
- 员工人数识别优先复用现有员工目录解析后的稳定 `employeeId`；若逐日记录尚未标准化，则依次使用 `employeeId`、`rosterEmployeeId` 和记录中的稳定 `id`。完全没有稳定 ID 的记录仍计入角色金额，但不计入员工人数，禁止用日期、数组下标或“姓名 + 角色”生成可能重复的人员标识。
- 待分配记录中的扣除、分配获得、分配后金额即使已有预测值，也不得计入角色正式结果。

## 验收与测试

1. 角色卡片位于筛选区和员工列表之间，并在不同宽度下正常换行。
2. 每张卡片展示角色、人数和四项金额。
3. 单角色、多个角色、多角色员工和未设置角色的聚合结果正确。
4. 同一员工跨日期使用不同角色时，金额按实际角色拆分且总额不重复。
5. 待分配角色只展示分配前，其他三项为 `—`。
6. 混合分配状态只统计已分配的后三项，并展示“部分待分配”。
7. 门店、日期、角色、员工与分配状态变化后，卡片和员工列表使用相同范围刷新。
8. 点击卡片与角色筛选双向联动；再次点击恢复全部角色。
9. 键盘操作、焦点状态与 `aria-pressed` 正确。
10. 现有员工列表排序、员工详情跳转和导出功能回归通过。

## 非目标

- 不修改小费分配算法。
- 不新增或修改角色、员工主数据。
- 不新增角色详情页面。
- 不改变日期分配汇总页面。
- 不增加新的后端接口或持久化状态。
