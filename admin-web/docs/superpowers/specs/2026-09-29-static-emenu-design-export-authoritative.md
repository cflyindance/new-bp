## 0. 当前有效交付定义：独立菜单设计后台

### 0.1 已确认范围

用户确认：独立项目、新标签页、免登录、复用全局悬浮球。第一阶段唯一目标仍为静态电子菜单设计与图片/PDF导出。

- 在全局悬浮球“周边产品”分类新增“菜单设计”，同时覆盖平铺卡片与下拉入口。
- 点击后新标签页打开菜单设计的独立入口。原商家后台不导航、不退出登录、不修改视角或草稿。
- 独立项目拥有自己的源码目录、HTML入口和构建命令，不导入商家后台的主启动程序，不以链接旧原型作为完成。
- 可同仓库维护、同域部署；“独立”不要求另建Git仓库。共享全局悬浮球源组件，而非复制一套外观相似的控件。
- 菜单设计页面首次打开、刷新和直接访问都无需商家或PIT登录；其他后台原有认证与代管限制保持不变。
- 菜单设计后台保留可拖动、展开、关闭、键盘可操作的全局悬浮球；当前产品显示为“菜单设计”。切换到其他产品进入对应既有入口，目标系统仍自行校验登录和权限。
- 页面布局与原型保持一致：项目首页、三步输入、成品编辑及导出。此次不新增模板管理、素材管理、用户管理等未定义模块。

### 0.2 当前设计主流程（替代历史八步流程）

用途规格 → 选择模板（上传图需点击分析并确认发送）→ 选择商品 → AI生成 → 成品微调与图片/PDF导出。

- 图库可直接选择；上传参考图需真实分析成功后才能继续，失败或取消保留图片和草稿。无需A/B样稿选择和额外分析确认步骤。
- 品牌色、Logo、主推商品、补充要求在商品页可选设置中，不增加必经步骤。
- 缺少名称或有效价格阻断生成；缺图默认文字排版；超容量自动分页，不丢商品。
- 复用已验证的本机Codex图片分析和布局建议，由程序绑定商品名称、价格与图片；AI失败明确报错，不静默降级为模拟结果。
- AI调用前确认向OpenAI发送的材料及账户额度使用。参考图中的文字和图像随整图发送；不额外上传商品表名称、价格、商品图、Logo或登录凭据。
- 草稿在当前浏览器本机保存。更换浏览器、域名或清理站点存储不会自动找回；不承诺云同步、多用户协作或历史原型自动跨域迁移。
- 导出保持PNG/JPG、多页图片ZIP和栅格PDF。用户需确认商品事实和栅格PDF限制，不宣称矢量、字体嵌入或专业印刷交付。

### 0.3 免登录与AI边界

2026-09-30 登录连续性修复验证记录（不改变 v1.1 范围）：从已登录商家页新开的同源菜单设计页面，切回其他视角时向原标签页核对当前账号，成功后沿用登录状态。源页退出、关闭、刷新导致通道失效或进入受限代管状态时不放行；直接免登录打开的菜单设计不自动获得商家身份。旧菜单设计标签页需从更新后的商家入口重新打开。实现与单元测试已补充，真实已登录跨标签页回归仍待用户登录后验证。配对研发版 v1.0 第2节记录同一修复。

免登录仅针对菜单设计页面，不意味着绕过其他后台认证。静态页面可独立部署；本机AI服务仍仅监听回环地址，严格校验来源及请求令牌。部署到非本机环境时不得自动使用访问者或开发者的Codex账户；不可用时明确提示，本次不建设公网AI服务。

## 历史方案 v1.0（非本次有效验收范围）

## 1. 权威声明

### 1.1 产品目的

本工具的第一阶段唯一主目标是：

> 面向餐厅经营者、品牌运营和实施人员，通过引导流程收集菜单数据、品牌素材、输出用途与视觉偏好，自动生成可继续编辑的单页或多页静态电子菜单，并导出为高清图片或 PDF 文件。

本工具交付的是可使用、可复用、可再次编辑的菜单设计成品，而不是一次性的 AI 效果图。

### 1.2 Phase 1 唯一主链路

```text
选择用途与规格
    → 提供菜单和品牌材料
    → 自动检查材料质量
    → 确认经营重点与视觉方向
    → 自动生成页面结构与排版
    → 用户局部调整
    → 导出前检查
    → 导出图片或 PDF
```

任何 Phase 1 功能均必须直接服务于上述主链路。无法直接提升“生成质量、编辑效率、导出可靠性”的能力，不得进入 Phase 1。

### 1.3 产品不是

Phase 1 明确不建设以下产品：

- 在线点餐、加购、结账或支付系统。
- POS 运行时菜单发布系统。
- 门店设备远程下发和在线状态管理系统。
- 自动 A/B 测试或经营转化优化平台。
- 连锁品牌多级审批和复杂权限平台。
- 通用海报、宣传册或全品类平面设计软件。
- 完全自由、无约束的 AI 画布生成工具。
- 专业印前制版系统。

如果后续需要互动点餐或设备发布能力，必须作为独立阶段和独立模块立项，不得反向改变本阶段的静态设计与导出主链路。

### 1.4 静态成品边界

- PNG、JPG 和普通 PDF 均按静态视觉成品定义。
- PDF 可以包含文本、二维码和链接外观，但 Phase 1 不承诺可交互点餐能力。
- 设计画布中的按钮类元素在静态导出时只能呈现为视觉元素，不具备运行时业务行为。
- 如果设计中包含二维码，其内容必须由用户提供或明确确认，系统不得自行推断交易地址。

## 2. 问题定义

### 2.1 用户当前任务

餐厅在制作电视屏菜单、竖屏菜单、打印菜单或可分享 PDF 时，通常需要经历：整理商品资料、检查图片、确定尺寸、选择风格、规划页面、逐项排版、反复校稿、导出不同格式。

不懂设计的用户面临三个核心困难：

1. 不知道应提供哪些材料，也不知道材料是否合格。
2. 不知道字号、列数、商品密度、页面数量等专业参数如何决定。
3. 即使获得一张 AI 效果图，也难以准确修改、稳定复现和导出可用文件。

### 2.2 目标任务陈述

> 当用户需要制作餐厅菜单时，只需提供真实菜单信息和品牌材料，并完成少量业务选择，系统就能生成一套专业、完整、可编辑、经过质量检查，并可直接导出为图片或 PDF 的静态电子菜单。

### 2.3 设计原则

1. **业务选择优先于设计参数**：询问“突出招牌还是展示更多”，不直接要求用户决定列数和字号。
2. **系统已知内容不得重复询问**：可从菜单、品牌或输出规格推导的信息应自动填写。
3. **先检查材料，再进入生成**：禁止把缺失或错误数据包装成看似完成的设计。
4. **结构化生成，不生成不可编辑截图**：生成结果必须保留页面、组件和商品绑定关系。
5. **AI 负责理解，规则负责正确**：大模型不得直接控制价格、坐标、分页和导出事实。
6. **先确认代表页，再生成全量页面**：避免生成完成后才发现方向错误。
7. **同一设计只维护一个真实来源**：图片与 PDF 必须从同一页面模型生成。
8. **导出成功不等于文件可用**：必须完成尺寸、字体、清晰度、页序和内容一致性校验。

## 3. 目标用户与职责

### 3.1 Phase 1 主要用户

| 用户 | 主要任务 | 产品应承担的工作 |
|---|---|---|
| 餐厅经营者 / 店长 | 快速制作或更新菜单 | 降低设计参数理解成本，提供可靠默认值 |
| 品牌运营 | 保持品牌一致并制作活动菜单 | 复用品牌资产、模板和设计配方 |
| 实施 / 客户成功 | 帮助商家快速交付菜单 | 标准化材料检查、生成和导出流程 |

### 3.2 用户必须确认的事实

- 商品名称、价格、描述和分类是否真实。
- 哪些商品或活动需要重点展示。
- Logo、图片和字体等素材是否有合法使用权。
- 菜单用于什么场景和设备。
- 最终设计与导出设置是否可以交付。

### 3.3 系统不得替用户决定的事实

- 商品价格、折扣、库存和售罄事实。
- 菜品成分、过敏原、营养和酒类属性。
- 门店地址、二维码目标地址和联系方式。
- 用户未提供的品牌承诺或营销事实。

## 4. 输出物定义

### 4.1 可编辑设计项目

每次设计必须首先形成一个可保存、可重新打开的项目，而不是直接形成最终图片。

项目至少保存：

- 项目 ID、名称、创建人与更新时间。
- 菜单数据快照及其版本。
- 品牌资产和素材清单。
- 输出规格。
- 设计意图。
- 模板与设计配方版本。
- 页面结构和页面顺序。
- 组件与商品绑定。
- 图片裁切焦点。
- 用户锁定项。
- 用户手动调整项。
- 最近一次导出配置和导出结果。

项目采用两级状态：

- `DraftState`：自动保存的可变工作状态，用于持续编辑；不可直接作为正式导出的来源。
- `ProjectVersion`：用户执行导出或主动保存版本时，由当前草稿冻结得到的不可变快照；正式导出必须引用一个明确的 `projectVersionId`。

每个 `ProjectVersion` 必须固定包含其使用的 `CatalogSnapshot`、素材哈希、页面模型、模板与规则版本。实时菜单数据变化不得悄悄改变既有版本。用户选择刷新菜单数据时，系统必须先展示差异，再从刷新后的数据创建新草稿和新版本；旧版本仍可打开和重新导出。

### 4.2 图片输出

Phase 1 支持：

- PNG：默认无损图片格式，适合菜单屏和继续加工。
- JPG：适合对文件体积敏感的分享场景，可选择质量档位。
- 单页项目导出一个文件。
- 多页项目按稳定规则生成全部页面，并以一个 ZIP 文件作为正式交付物；ZIP 内包含全部图片和 `export-manifest.json`。

多页图片命名规则：

```text
{baseName}-{页码两位}-{pageSlug}.{格式}
示例：晚餐菜单-01-首页.png
```

Phase 1 只允许用户编辑一个 `baseName`。系统必须先将其规范化为 Unicode NFC、去除首尾空白、把连续空白折叠为单个空格，并拒绝控制字符、路径分隔符和 Windows 保留文件名。`pageSlug` 由页面名称按相同规则生成；重名时追加稳定的页面 ID 短后缀。

正式文件命名规则：

- 单页 PNG/JPG：`{baseName}-{页码两位}-{pageSlug}.{ext}`。
- 多页 PNG/JPG 外层文件：`{baseName}-images.zip`。
- ZIP 内页面：使用上述单页图片命名规则，并按请求中的页面顺序写入。
- PDF：`{baseName}.pdf`。
- ZIP 内 `export-manifest.json` 名称固定，不接受用户修改。

规范化后的 `baseName`、外层文件名和 `pageId → resolvedFileName` 完整映射必须进入 `ExportInputFingerprint`。

图片导出必须保证：

- 像素尺寸与 4.4 节定义的派生像素尺寸完全一致。
- 页面内容不得超出画布。
- 字体、图片裁切和颜色与预览一致。
- 多次使用相同项目版本和相同导出参数时，输出结果一致。

多页图片必须先在临时区域完成全部页面渲染和校验，再一次性生成 ZIP。任一页面失败时不得产生正式 ZIP，也不得把散落的部分图片作为成功结果提供给用户。

ZIP 内的 `export-manifest.json` 记录各页面文件名、页面 ID、顺序和图片哈希，但不记录 ZIP 自身哈希；系统持久化的外部 `ExportManifest` 在打包完成后追加 ZIP 文件名与 ZIP 哈希，避免自引用。ZIP 条目顺序必须按导出页面顺序固定，压缩算法和级别由导出器版本固定；条目时间使用 `ProjectVersion` 的 UTC 冻结时间，并截断到 ZIP 支持的 2 秒精度，确保相同指纹得到相同 ZIP 内容。

### 4.3 PDF 输出

Phase 1 支持：

- 单页 PDF。
- 按项目页面顺序合并的多页 PDF。
- `SCREEN` PDF profile。
- `PRINT_STANDARD` PDF profile。

PDF 导出必须保证：

- 页面尺寸、方向、数量和顺序正确。
- 文本优先保持为可缩放文字；无法嵌入的字体必须在导出前提示替代方案。
- 图片不得因导出过程产生非预期拉伸、裁切或明显降质。
- 导出内容与图片导出使用同一页面模型。
- 用户可明确选择导出当前页或全部页面。
- 以毫米定义的画布按实际物理尺寸生成 PDF 页面；以像素定义的画布按 `96 px = 1 inch`、`72 pt = 1 inch` 转换为 PDF 页面尺寸。

Phase 1 不承诺：

- CMYK 专色管理。
- PDF/X 标准交付。
- 印刷厂 ICC 配置文件转换。
- 自动拼版。

### 4.4 输出规格与换算契约

Phase 1 使用以下命名规格：

| Profile ID | 场景 | 逻辑规格 | 图片派生规则 | PDF 派生规则 |
|---|---|---|---|---|
| `SCREEN_LANDSCAPE_FHD` | 横屏电子屏 | 1920 × 1080 px | 原尺寸 | 按 96 px/in 转换 |
| `SCREEN_LANDSCAPE_4K` | 4K 横屏电子屏 | 3840 × 2160 px | 原尺寸 | 按 96 px/in 转换 |
| `SCREEN_PORTRAIT_FHD` | 竖屏电子屏 | 1080 × 1920 px | 原尺寸 | 按 96 px/in 转换 |
| `SCREEN_PORTRAIT_4K` | 4K 竖屏电子屏 | 2160 × 3840 px | 原尺寸 | 按 96 px/in 转换 |
| `PRINT_A4` | A4 打印 / PDF | 210 × 297 mm | 按 300 dpi 换算 | 210 × 297 mm |
| `PRINT_A3` | A3 打印 / PDF | 297 × 420 mm | 按 300 dpi 换算 | 297 × 420 mm |
| `CUSTOM_PX` | 自定义屏幕 | 用户输入 px | 原尺寸 | 按 96 px/in 转换 |
| `CUSTOM_MM` | 自定义物理页面 | 用户输入 mm | 按用户选择的 150 或 300 dpi 换算 | 按输入 mm 输出 |

确定性换算规则：

- `px` 规格导出 PNG/JPG 时，输出尺寸就是 `OutputProfile.width × OutputProfile.height`，Phase 1 不提供额外倍率；需要更高分辨率时选择或新建更大的显式规格。
- `mm` 规格导出 PNG/JPG 时，像素值按 `roundHalfUp(mm ÷ 25.4 × rasterDpi)` 计算，宽高分别计算。
- `mm` 规格的 `rasterDpi` 必填，只能为 150 或 300；A4、A3 默认 300。
- `px` 规格导出 PDF 时，页面点数按 `px × 72 ÷ 96` 计算，不进行整数取整。
- `mm` 规格导出 PDF 时，页面点数按 `mm ÷ 25.4 × 72` 计算，不进行整数取整。
- 页面方向通过宽高值表达，不允许导出器再次交换宽高。
- Phase 1 所有输出使用 sRGB；专业 CMYK 与 ICC 转换仍属于范围外。

格式质量档位固定为：

| 格式 | 档位 | 契约 |
|---|---|---|
| PNG | `LOSSLESS` | 无损，不提供质量滑杆 |
| JPG | `STANDARD` | 编码质量 90 |
| JPG | `HIGH` | 编码质量 95 |
| PDF | `SCREEN` | sRGB，按页面规格输出，图片不主动放大 |
| PDF | `PRINT_STANDARD` | sRGB，物理页面规格，所用栅格图片按 300 dpi 目标检查 |

格式与规格的合法组合固定如下：

| 导出格式 / profile | `px` OutputProfile | `mm` OutputProfile |
|---|---|---|
| PNG `LOSSLESS` | 允许，使用屏幕像素密度规则 | 允许，使用 `rasterDpi` 与打印 dpi 规则 |
| JPG `STANDARD` / `HIGH` | 允许，使用屏幕像素密度规则 | 允许，使用 `rasterDpi` 与打印 dpi 规则 |
| PDF `SCREEN` | 允许，按 96 px/in 转换页面尺寸并使用屏幕像素密度规则 | 不允许 |
| PDF `PRINT_STANDARD` | 不允许 | 允许，保持物理页面尺寸并使用 300 dpi 打印检查规则 |

界面不得展示不合法组合，接口收到不合法组合时必须返回 `EXPORT_PROFILE_INCOMPATIBLE`，不得自动替用户转换 profile 或规格单位。

系统应优先让用户选择使用场景，再自动带出规格；高级设置只允许修改本节明确支持的字段。

## 5. 端到端用户流程

### 5.1 流程总览

| 阶段 | 用户主要动作 | 系统主要动作 | 阶段产物 |
|---|---|---|---|
| 1. 创建任务 | 选择新建设计或继续编辑 | 创建项目或恢复项目 | 项目工作区 |
| 2. 选择用途 | 选择屏幕、打印或分享场景 | 推荐画布规格 | 输出规格 |
| 3. 提供材料 | 选择菜单、上传图片和品牌素材 | 建立数据与素材清单 | 输入快照 |
| 4. 材料体检 | 处理阻断问题 | 检查完整性与质量 | 体检报告 |
| 5. 确认意图 | 选择经营重点与内容密度 | 形成结构化设计简报 | 设计意图 |
| 6. 选择方向 | 比较代表页方案 | 生成 2–3 个真实内容方案 | 已选视觉方向 |
| 7. 确认结构 | 调整分类、主推和页序 | 规划分页与页面结构 | 页面计划 |
| 8. 完整生成 | 等待并检查结果 | 生成全部页面和组件 | 可编辑设计项目 |
| 9. 局部调整 | 使用有限编辑操作、锁定组件或重生成当前页 | 保留锁定组件并重排当前页其余内容 | 审定稿 |
| 10. 导出检查 | 处理阻断项并确认警告 | 执行内容与输出预检 | 可导出状态 |
| 11. 导出成品 | 选择格式和页面范围 | 生成、校验并保存文件 | 图片 / PDF |

### 5.2 创建任务

入口提供：

- 新建菜单设计。
- 打开已有设计。
- 复制已有设计为新项目。

复制项目时必须形成新的项目版本，不得与源项目共享可变页面数据。

### 5.3 选择成品用途

用户先回答“成品用在哪里”，而不是先填写宽高：

- 横屏电子屏。
- 竖屏电子屏。
- 打印菜单。
- PDF 分享。
- 自定义用途。

系统根据用途推荐规格、方向和清晰度。用户可以接受推荐，也可以进入高级设置修改。

### 5.4 提供菜单和品牌材料

Phase 1 输入来源：

- 读取当前系统内已有的结构化商品菜单。
- 在项目内手动修正展示名称、描述和排序，但不得回写商品业务事实。
- 上传 Logo、菜品图片、背景图、装饰图和品牌参考图。
- 选择需要出现在菜单中的分类和商品。

Phase 1 不包括旧菜单 OCR、外部网站抓取和任意 Excel 模板自动识别。这些能力需要独立定义数据准确率与纠错流程后再进入后续阶段。

### 5.5 材料体检

体检结果分为三级：

| 级别 | 含义 | 处理方式 |
|---|---|---|
| BLOCKER | 无法形成可靠成品 | 修复前不可进入完整生成或导出 |
| WARNING | 可以继续，但成品质量存在风险 | 用户确认或修复后继续 |
| INFO | 非阻断优化建议 | 可忽略 |

必须检查：

- 商品是否有稳定 ID、名称、分类和有效价格文本。
- 商品图片是否缺失、过小、模糊、比例异常或无法读取。
- Logo 是否可用。
- 菜名、描述和多语言文本是否可能溢出。
- 输出规格与素材清晰度是否匹配。
- 商品数量是否超过当前模板与画布容量。
- 项目引用的字体是否可用于预览和导出。

系统可以建议裁切、压缩、占位和布局降级，但不得自动修改价格或补造商品事实。

### 5.6 获取经营意图

引导问题仅保留对成品有显著影响的选择：

- 主要目标：突出招牌、快速浏览、展示更多商品、品牌展示。
- 主推商品：选择 1–5 个。
- 内容密度：图片主导、图文均衡、文字高密度。
- 必须出现的内容：活动说明、品牌介绍、二维码或联系方式。
- 视觉倾向：通过参考图和真实内容方案选择，不要求用户理解专业风格术语。

系统据此形成 `DesignIntent`，后续所有生成行为必须可追溯到这份意图。

### 5.7 选择视觉方向

系统使用用户真实商品先生成 2–3 个代表页方案。每个方案至少包含：

- 一个封面或首页代表区。
- 一个典型分类页。
- 真实菜名、价格和图片。
- 方案适用场景与取舍说明。

用户选定方向前不得生成完整多页菜单。

### 5.8 确认页面结构

系统推荐：

- 分类顺序。
- 页面数量。
- 每页商品容量。
- 首页、分类页和信息页的组合。
- 主推商品位置。
- 缺图商品的降级版式。

用户可以：

- 调整分类或页面顺序。
- 锁定主推商品。
- 排除不需要导出的商品。
- 确认是否展示描述、标签和二维码。

系统不得通过缩小到不可读字号、隐藏价格或静默删除商品来解决容量冲突。容量不足时按以下顺序处理：

```text
增加页面
    → 更换卡片变体
    → 调整列数或密度
    → 移除非必要装饰
    → 请求用户选择
```

### 5.9 完整生成

生成器输出结构化页面，而不是扁平图片。每个页面由可识别组件组成，例如：

- 页面背景。
- Logo 与品牌标题。
- 分类标题。
- 商品图片。
- 商品名称。
- 商品描述。
- 价格。
- 标签。
- 活动区。
- 二维码。
- 页码与辅助说明。

商品组件必须通过稳定 ID 绑定真实商品。AI 不得通过菜名猜测绑定关系。

### 5.10 编辑与局部重生成

Phase 1 的编辑能力采用有限操作集，不建设通用设计软件。

语义编辑只支持：

1. 在图片主导、图文均衡、文字高密度三种密度间切换。
2. 显示或隐藏模板声明为可选的商品描述和标签。
3. 将商品设为主推或取消主推。
4. 在当前模板允许的商品卡变体之间切换。
5. 在当前品牌配方允许的颜色与字体预设之间切换。
6. 调整分类、页面和商品的展示顺序。
7. 使用当前设计配方重新生成当前页。

精细编辑只支持：

- 移动和缩放当前页已有组件。
- 替换图片并调整裁切焦点。
- 修改允许覆盖的字体预设、颜色、对齐和层级。
- 编辑用户自行添加的静态文案。
- 商品名称、价格等业务事实只能回到内容层修正，不能在画布中产生脱离 `CatalogSnapshot` 的覆盖值。

锁定与重生成的最小范围：

- Phase 1 只支持锁定单个组件，不支持区域锁、层级锁或跨页锁。
- Phase 1 只支持重新生成当前页，不支持任意区域重生成或一次选择多页重生成。
- 当前页重生成时，锁定组件的位置、尺寸、内容引用和样式保持不变，其余组件重新布局。
- 若锁定组件导致硬约束无法满足，重生成失败并列出冲突组件；系统不得移动或解除锁定。
- 重生成完成后只提供结构化摘要：新增、删除、移动或改变变体的组件清单；Phase 1 不提供像素级视觉差异工具。

### 5.11 导出前检查

导出前必须重新检查：

- 当前 `ProjectVersion` 引用的 `CatalogSnapshot` 是否完整，并检查其来源版本是否落后于实时菜单。
- 是否存在空价格、空名称或失效图片。
- 是否存在文本溢出、遮挡或越界。
- 页面尺寸和方向是否匹配输出用途。
- 图片分辨率是否满足目标输出。
- 字体是否可以正确导出。
- PDF 页面顺序是否正确。
- 页面包含二维码组件时，二维码是否存在且能够被识别；没有二维码组件时该检查不适用。

具体适用条件、阈值、严重级别和放行规则以第 9 节矩阵为准。存在 BLOCKER 时禁用导出；WARNING 必须在导出确认界面逐项确认并写入 `ExportManifest`。

如果实时菜单版本晚于当前 `CatalogSnapshot`，系统必须阻止用户直接进入最终导出，并要求二选一：

- 刷新菜单数据：展示差异后创建新草稿和新 `ProjectVersion`，重新执行预检。
- 保留当前快照：用户明确确认“按已保存内容导出”，记录确认人、来源版本差异和时间，然后允许当前版本继续导出。

无论选择哪一种，导出器只读取冻结后的 `ProjectVersion`，绝不在导出过程中读取或混入实时菜单数据。

### 5.12 导出与结果确认

用户选择：

- PNG、JPG 或 PDF。
- 当前页或全部页面。
- 第 4.4 节定义的格式质量档位。
- 一个用户可编辑的 `baseName`；具体文件名由第 4.2 节规则生成。

系统完成导出后必须验证：

- 文件存在且可读取。
- 图片尺寸正确。
- PDF 页数、页面尺寸和顺序正确。
- 导出清单与实际文件一致。

单页 PNG/JPG 的正式交付物是单个图片文件；多页 PNG/JPG 的正式交付物是包含全部页面和 `export-manifest.json` 的单个 ZIP；PDF 的正式交付物是一个单页或多页 PDF。

如果任一页面生成失败，多页导出任务整体标记为失败，不得把不完整结果标记为成功。已完成的临时文件可以用于诊断，但不能作为正式交付物。只有完成全部文件校验并成功原子发布最终文件或 ZIP 后，任务才能进入成功状态。

## 6. 交互工作台设计

### 6.1 页面结构

推荐采用三栏工作台：

```text
┌──────────────┬────────────────────────────────┬──────────────────┐
│ 流程与页面    │            菜单画布             │ 智能建议与检查    │
│              │                                │                  │
│ 当前步骤      │ 真实内容预览                   │ 推荐理由          │
│ 页面列表      │ 选中组件与安全区               │ 材料问题          │
│ 完成状态      │ 缩放与页面切换                 │ 约束冲突          │
│              │                                │ 快捷语义修改      │
└──────────────┴────────────────────────────────┴──────────────────┘
```

### 6.2 交互原则

- 每一步只询问会显著改变结果的问题。
- 每个选择最多提供 2–4 个清晰选项，并标出推荐项。
- 用户可以选择“使用系统推荐”。
- 页面中心始终使用真实菜单数据预览。
- 系统每次自动决定都应提供简短理由。
- 用户离开页面前自动保存项目草稿。
- 导出是明确的结束动作，不与设计过程混在同一个按钮中。

### 6.3 关键状态

工作台至少覆盖：

- 无项目。
- 项目初始化。
- 材料不完整。
- 生成中。
- 生成失败。
- 可编辑。
- 存在导出阻断项。
- 可导出。
- 导出中。
- 导出成功。
- 导出失败。

任何失败状态均不得丢失已保存的设计项目和用户编辑。

## 7. 生成系统设计

### 7.1 推荐方案

采用“AI 规划 + 模板配方 + 规则约束 + 确定性编译”的混合方案。

不采用以下极端方案：

- 纯模板方案：稳定但无法适应商品数量、图片质量和品牌差异。
- 纯 AI 页面生成：创意强，但难以复现、编辑、质检和可靠导出。

### 7.2 生成链路

```text
CatalogSnapshot + AssetManifest + OutputProfile
                     +
                 DesignIntent
                     ↓
               DesignBrief / IR
                     ↓
             模板与配方候选选择
                     ↓
                 约束求解
                     ↓
               页面与组件编译
                     ↓
               统一页面渲染树
                  ↙       ↘
          编辑器预览       导出渲染器
                           ↙       ↘
                      PNG/JPG      PDF
```

### 7.3 AI 职责

AI 可以：

- 把自然语言经营目标转换为结构化设计意图。
- 识别品牌色和图片主体焦点。
- 推荐模板、密度和视觉方向。
- 对用户提供的描述进行不改变事实的润色建议。
- 解释布局取舍和质检问题。
- 将语义修改转换为受控参数。

AI 不可以：

- 生成或修改价格、商品状态和业务事实。
- 直接输出任意 CSS、脚本或最终绝对坐标。
- 静默隐藏商品或删除价格。
- 绕过质量检查。
- 自动替用户确认导出。

### 7.4 模板与设计配方

模板不是一张完整背景图，而是：

- 页面类型。
- 布局区域和插槽。
- 支持的商品容量范围。
- 可用组件和卡片变体。
- 字体、颜色、间距、圆角等 Token。
- 响应输出规格的布局规则。
- 缺图、长文本和容量不足时的降级策略。

设计配方保存“为什么这样排”，而不仅保存最终坐标。它至少包含：

- 模板及版本。
- 内容密度。
- 主推优先级。
- 商品卡变体。
- 图片比例和裁切规则。
- 分页规则。
- 文本显示策略。
- 品牌 Token。

### 7.5 约束级别

| 级别 | 示例 | 系统行为 |
|---|---|---|
| 硬约束 | 价格不可缺失、文本不可越界、页面不可超出画布 | 不满足时禁止生成完成或导出 |
| 业务约束 | 指定商品必须出现、品牌色必须使用、二维码不可更改 | 生成器必须满足；冲突时请求用户选择 |
| 软目标 | 留白、视觉节奏、图片占比、主推突出度 | 用于候选评分和推荐 |

### 7.6 确定性与可复现

每次完整生成保存 `BuildManifest`：

- 输入数据快照 ID。
- 素材内容哈希。
- 输出规格。
- 模板和配方版本。
- 规则包版本。
- 结构化 Design IR。
- 用户覆盖补丁。
- 生成随机种子。
- 渲染器版本。

相同 `BuildManifest` 必须产生相同的页面结构；`BuildManifest` 不代表某一次格式导出。AI 模型变化不得改变已经保存的项目版本。

每次导出另外形成 `ExportInputFingerprint`，其输入必须包括：

- `projectVersionId`。
- 页面 ID 及顺序。
- PNG、JPG 或 PDF 格式。
- 第 4.4 节定义的质量档位。
- `OutputProfile` 完整值。
- JPG 编码质量或 PDF profile。
- 规范化后的 `baseName`、外层文件名和完整 `pageId → resolvedFileName` 映射。
- 文件命名规则版本。
- 导出器版本。
- 已确认 WARNING 和实时数据差异决策。

相同 `ExportInputFingerprint` 必须产生相同的正式交付内容和文件哈希。导出时间记录在外部 `ExportManifest` 中，不写入影响成品哈希的文件内容；如格式库必须写入时间元数据，必须使用项目版本的固定时间值。

## 8. 核心数据对象

### 8.1 `StaticMenuProject`

项目根对象，关联输入、设计、页面和导出记录。

### 8.2 `ProjectVersion`

不可变的正式设计版本，至少包含：

- 项目版本 ID 和父版本 ID。
- 冻结时间和创建人。
- `CatalogSnapshot`。
- `AssetManifest`。
- `OutputProfile`。
- `BuildManifest`。
- 全部 `PageDocument`。
- 版本说明。

导出必须引用 `ProjectVersion`；实时菜单和可变草稿不得成为导出器的直接输入。

### 8.3 `OutputProfile`

至少包含：

- Profile ID。
- 用途类型。
- 单位：px 或 mm。
- 宽度和高度。
- 横竖方向。
- 色彩空间，Phase 1 固定为 sRGB。
- `mm` 规格使用的 `rasterDpi`；`px` 规格必须为空。
- 上、右、下、左安全区数值及其单位；未显式设置时使用画布对应边长的 3%。

“是否在编辑器中显示安全区”属于用户界面偏好，保存在 `DraftState`，不参与页面模型和导出指纹。

### 8.4 `CatalogSnapshot`

至少包含：

- 快照 ID 和生成时间。
- 来源菜单 ID 和来源版本号。
- 菜单、分类和商品的稳定 ID。
- 展示名称、描述和结构化 `PriceDisplay`。
- 商品排序。
- 图片引用。
- 用户明确选择的商品范围。

`PriceDisplay` 只能是以下三种已校验形态：

- `FIXED`：最小货币单位整数金额与 ISO 货币代码，由确定性格式化器生成展示文本。
- `RANGE`：同一货币下的最小与最大金额，且最小金额不大于最大金额。
- `LABEL`：用户明确确认的非空价格标签，例如“时价”；必须保存确认人和确认时间。

不满足上述任一结构即视为无效价格。价格按原始业务数据保存和显示，禁止经过 AI 改写。

### 8.5 `AssetManifest`

至少包含：

- 素材 ID、类型和来源。
- 文件哈希。
- 像素尺寸和文件格式。
- 原始宽高比。
- `blurScore` 与图像质量分析器版本。
- 裁切焦点。
- 透明背景信息。
- 质量检查结果。
- 用户确认的使用权状态。

### 8.6 `DesignIntent`

至少包含：

- 主要经营目标。
- 主推商品 ID。
- 内容密度。
- 必须出现的内容。
- 用户选择的视觉方向。
- 品牌约束。

### 8.7 `PageDocument`

至少包含：

- 页面 ID、类型、名称和顺序。
- 画布规格。
- 组件树。
- 商品绑定。
- 样式 Token。
- 图片裁切参数。
- 锁定状态。
- 用户覆盖项。

### 8.8 `ExportManifest`

至少包含：

- 导出任务 ID。
- `projectVersionId`。
- `ExportInputFingerprint`。
- 导出格式、质量档位和页面 ID 顺序。
- 完整 `OutputProfile`。
- JPG 编码质量或 PDF profile。
- 规范化后的 `baseName`、外层文件名和完整 `pageId → resolvedFileName` 映射。
- 文件命名规则版本和导出器版本。
- 实时菜单版本比较结果和用户决策。
- 被用户确认的 WARNING 清单、确认人和确认时间。
- 文件清单和文件哈希。
- 预检结果。
- 导出时间和最终状态。

## 9. 自动质检规范

### 9.1 严重级别与放行规则

| 级别 | 是否允许导出 | 处理要求 |
|---|---|---|
| BLOCKER | 否 | 必须修复并重新预检；不可通过确认绕过 |
| WARNING | 有条件允许 | 用户必须逐项确认；确认记录写入 `ExportManifest` |
| INFO | 是 | 展示建议，不要求确认 |
| N/A | 是 | 当前项目或当前格式不适用，不展示为问题 |

预检规则必须使用稳定规则 ID。实现可以增加更严格的检查，但不得降低本节规定的严重级别。

### 9.2 导出前确定性预检矩阵

| Rule ID | 适用条件 | 判定阈值 | 级别 | 修复或确认方式 |
|---|---|---|---|---|
| `CATEGORY_VALID` | 用户选择导出的分类 | 分类稳定 ID 或名称缺失，或分类没有任何已选有效商品 | BLOCKER | 修正分类数据或从导出范围移除该分类 |
| `CONTENT_REQUIRED_FIELD` | 被导出的商品组件 | 商品 ID 或展示名称缺失 | BLOCKER | 返回内容层补齐真实数据 |
| `PRICE_DISPLAY_VALID` | 被导出的商品组件 | `PriceDisplay` 不满足第 8.4 节的 `FIXED`、`RANGE` 或已确认 `LABEL` 结构 | BLOCKER | 返回内容层修复真实价格数据 |
| `CONTENT_BINDING_VALID` | 被导出的商品组件 | 商品 ID 不存在于版本内 `CatalogSnapshot`，或同一组件绑定多个商品 | BLOCKER | 修正绑定并创建新版本 |
| `CONTENT_SELECTION_COMPLETE` | 用户已确认商品范围 | 任一已选商品未出现在页面计划且未被用户明确排除 | BLOCKER | 增加页面、恢复商品或明确排除 |
| `TEMPLATE_CAPACITY` | 已生成页面计划 | 任一页面商品数超过模板声明的上限，或全部页面容量之和小于未排除商品数 | BLOCKER | 增加页面、切换模板或调整商品范围 |
| `CONTENT_FACT_UNCHANGED` | 名称、价格等业务事实 | 页面值与 `CatalogSnapshot` 不一致 | BLOCKER | 从快照恢复或刷新数据并创建新版本 |
| `CATALOG_FRESHNESS` | 来源菜单可查询实时版本 | 实时版本比快照新且用户尚未选择处理方式 | BLOCKER | 刷新为新版本，或明确确认按旧快照导出 |
| `CATALOG_FRESHNESS_ACK` | 用户选择按旧快照导出 | 已记录来源版本差异、确认人和时间 | WARNING | 逐项确认后允许导出 |
| `ASSET_READABLE` | 页面实际引用素材 | 文件缺失、解码失败或哈希不匹配 | BLOCKER | 替换或恢复素材 |
| `LOGO_REQUIRED` | 模板声明 Logo 必需，或用户选择展示 Logo | Logo 缺失、不可读取或无有效可见区域 | BLOCKER | 上传可用 Logo 或切换不要求 Logo 的模板 |
| `LOGO_OPTIONAL_MISSING` | 模板声明 Logo 可选且用户未选择展示 | Logo 缺失 | N/A | 无需处理 |
| `IMAGE_SCREEN_DENSITY` | `px` 规格且页面使用栅格图 | 裁切后有效源像素与目标渲染像素之比低于 0.75 | BLOCKER | 换图、缩小渲染区域或更换无图变体 |
| `IMAGE_SCREEN_DENSITY_WARN` | `px` 规格且页面使用栅格图 | 上述比例大于等于 0.75 且小于 1.0 | WARNING | 换图或确认可能模糊 |
| `IMAGE_PRINT_DPI` | `mm` 规格且页面使用栅格图 | 裁切后有效分辨率低于 150 dpi | BLOCKER | 换图、缩小图片区域或更换无图变体 |
| `IMAGE_PRINT_DPI_WARN` | `mm` 规格且页面使用栅格图 | 裁切后有效分辨率为 150–299 dpi | WARNING | 换图或确认打印清晰度风险 |
| `IMAGE_BLUR_BLOCKER` | 页面实际引用的栅格图 | 版本化图像分析器 `blurScore` 小于 15 | BLOCKER | 换图或改用无图变体 |
| `IMAGE_BLUR_WARN` | 页面实际引用的栅格图 | `blurScore` 为 15–34 | WARNING | 换图或确认模糊风险 |
| `IMAGE_ASPECT_RATIO_WARN` | 非背景、非横幅类栅格图 | 原图宽高比小于 0.25 或大于 4.0 | WARNING | 预览裁切、更换图片或确认异常比例 |
| `IMAGE_CROP_RETENTION_WARN` | 页面实际引用且发生裁切的栅格图 | 最终裁切保留面积小于原图面积的 35%，或保留的主体焦点框面积低于 90% | WARNING | 调整焦点、换图或确认裁切 |
| `IMAGE_REQUIRED_MISSING` | 当前卡片或模板将图片声明为必需 | 商品无可用图片 | BLOCKER | 上传图片或切换支持无图降级的变体 |
| `IMAGE_FALLBACK_USED` | 模板支持无图降级且已启用 | 使用经模板声明的无图变体 | INFO | 无需确认 |
| `GEOMETRY_BOUNDS` | 所有可见非出血组件 | 包围盒越出画布或安全区要求 | BLOCKER | 自动重排或手动修正 |
| `GEOMETRY_OVERLAP` | 未声明允许叠放的可见组件 | 实际包围盒相交超过 1 个输出像素 | BLOCKER | 自动重排或手动修正 |
| `TEXT_OVERFLOW` | 所有可见文本组件 | 排版后存在裁切、溢出或省略了必需字段 | BLOCKER | 改变卡片、分页或调整文案区域 |
| `TEXT_MIN_SIZE_SCREEN` | `px` 规格的正文和业务文本 | 小于 24 px；纯装饰文字不适用 | BLOCKER | 调整布局或增加页面，不允许继续缩小 |
| `TEXT_MIN_SIZE_PRINT` | `mm` 规格的正文和业务文本 | 小于 9 pt；纯装饰文字不适用 | BLOCKER | 调整布局或增加页面，不允许继续缩小 |
| `TEXT_CONTRAST` | 正文和业务文本 | 普通文本对比度低于 4.5:1；大号文本低于 3:1 | BLOCKER | 更换文字色、背景或增加遮罩 |
| `FONT_AVAILABLE` | 无需替换的原字体，或已确认替换后的最终生效字体 | 字体文件不可读取或许可状态未确认 | BLOCKER | 上传合规字体或选择替代字体 |
| `FONT_SUBSTITUTION_PENDING` | 原字体不可导出且系统已提供替代字体 | 用户尚未预览并确认替换结果 | BLOCKER | 完成替换预览并明确确认，或选择其他可导出字体 |
| `FONT_SUBSTITUTION` | 原字体不可导出但存在替代字体 | 用户已预览并确认替换结果，且替代字体通过 `FONT_AVAILABLE` | WARNING | 记录原字体、替代字体、确认人和时间 |
| `QR_PAYLOAD` | 页面包含二维码组件 | 内容为空或不是支持的文本 / URL | BLOCKER | 提供或修正二维码内容 |
| `QR_SCANNABLE` | 页面包含二维码组件 | 按最终输出尺寸渲染后无法被检测器识别 | BLOCKER | 增大尺寸、提高对比度或减少遮挡 |
| `QR_NOT_PRESENT` | 页面不包含二维码组件 | 不检查二维码 | N/A | 无需处理 |
| `OUTPUT_PROFILE_COMPATIBILITY` | 所有导出请求 | 格式、PDF profile 与 `OutputProfile` 单位不符合第 4.4 节合法组合表 | BLOCKER | 重新选择合法规格或 profile |
| `PAGE_ORDER` | 多页导出 | 导出页 ID 或顺序与请求不一致 | BLOCKER | 终止任务并重新导出 |
| `OUTPUT_DIMENSION` | 图片导出 | 实际像素尺寸不等于第 4.4 节派生尺寸 | BLOCKER | 终止任务并修复导出器 |
| `PDF_PAGE_CONTRACT` | PDF 导出 | 页数、页序或页面物理尺寸不一致 | BLOCKER | 终止任务并修复导出器 |
| `OUTPUT_PARSEABLE` | 所有格式 | 文件无法被对应解析器重新打开 | BLOCKER | 终止任务，不发布文件 |
| `OUTPUT_MANIFEST_MATCH` | 所有格式 | 文件名、数量或哈希与 `ExportManifest` 不一致 | BLOCKER | 终止任务并重新生成清单 |

`blurScore` 是由版本化图像质量分析器输出的 0–100 整数，100 表示最清晰。分析器算法和版本必须记录在 `AssetManifest`；同一算法版本和同一文件哈希必须得到相同分数。更换算法版本必须重新体检素材，不得沿用旧阈值结论。

Logo 的“有效可见区域”定义为：栅格 Logo 解码后宽高均大于 0，且透明度大于 5% 的像素至少占画布 1%；矢量 Logo 必须具有非空 `viewBox` 和至少一个可见绘制节点。Logo 一旦进入页面，还必须同时通过对应的屏幕密度或打印 dpi 规则。

大号文本定义为：屏幕规格字号不小于 32 px，或打印规格字号不小于 18 pt。安全区由模板和 `OutputProfile` 共同声明；没有额外出血能力的 Phase 1 预设默认安全区为画布四边内缩 3%。

### 9.3 导出后验证

导出器完成渲染后、正式发布文件前，必须再次执行：

- 图片尺寸、格式和 JPG 编码质量验证。
- PDF 页数、页序、物理页面尺寸和可解析性验证。
- 字体嵌入或已确认替代结果验证。
- ZIP 文件完整性、内部页文件数量和 `export-manifest.json` 验证。
- 文件清单和内容哈希与 `ExportManifest` 一致性验证。

任何导出后 BLOCKER 都会使整个导出任务失败，不向用户发布正式文件。

### 9.4 极端场景检查

至少使用以下数据验证模板和导出：

- 超长菜名。
- 中英文混排。
- 无图片商品。
- 低分辨率图片。
- 价格位数较长。
- 分类只有一个商品。
- 分类商品数量超过单页容量。
- Logo 为透明 PNG。
- 多页项目页面重排后再次导出。
- 每一种合法与非法的格式 / profile / 单位组合。
- 字体替换待确认与已确认两种状态。
- 中文、重复页名、控制字符和系统保留文件名输入。
- 同一 `ExportInputFingerprint` 连续导出两次并比较文件哈希。

## 10. 错误处理与恢复

| 场景 | 要求 |
|---|---|
| 菜单数据缺失 | 标记具体商品和字段，不允许生成假数据 |
| 素材无法读取 | 保留原素材记录，允许替换，不导致整个项目丢失 |
| AI 推荐失败 | 回退到确定性默认设计配方，允许用户继续 |
| 布局约束无法满足 | 说明冲突，并按既定降级顺序处理 |
| 字体无法导出 | 提供字体替换预览，用户确认后才能导出 |
| 实时菜单晚于项目快照 | 阻止直接导出，要求刷新为新版本或明确确认旧快照 |
| 单页渲染失败 | 整体导出失败，明确失败页和原因 |
| 多页图片打包失败 | 不发布 ZIP，保留临时诊断信息并允许按相同输入重试 |
| PDF 合并失败 | 不产生正式成功记录，保留项目和诊断信息 |
| 浏览器或页面意外关闭 | 从最近一次自动保存状态恢复 |

所有重试必须保持幂等：重复执行同一个 `ExportInputFingerprint` 不得修改设计项目本身，并必须保持正式交付内容与文件哈希一致。

## 11. 与现有 eMenu Pro 的关系

当前项目已有页面画布、商品组件、商品绑定和布局能力，可作为静态菜单生成与编辑的基础能力：

- 商品组件批量绑定：`docs/项目文档/eMenu-Pro-商品组件批量绑定设计方案.md`
- 商品组件默认绑定：`docs/项目文档/eMenu-Pro-商品组件默认绑定设计方案.md`
- 画布布局核心：`dist/emenu-pro/embedded-layout-core.js`

Phase 1 推荐沿用结构化组件和稳定商品 ID 绑定，而不是另造一套不可编辑的图片生成器。

需要新增的产品能力是：

- 引导式设计简报。
- 静态菜单专用组件与模板配方。
- 材料质量检查。
- 页面自动规划和完整菜单生成。
- 统一页面渲染模型。
- PNG / JPG 导出器。
- 单页 / 多页 PDF 导出器。
- 导出前预检和导出清单。

运行时加购、购物车、售罄交互等组件不作为静态成品功能。若复用其视觉样式，导出时必须转换为静态表现或排除。

## 12. Phase 1 MVP 范围

### 12.1 必须包含

- 新建、保存、复制和重新打开设计项目。

- 3 套经过验证的布局骨架。
- 图片主导、图文均衡、文字高密度三种密度方向。
- 自动分页、商品绑定和缺图降级。

- 连锁品牌复杂审批。

- 区域级或跨页级锁定与局部重生成。
- 像素级版本视觉差异工具。

## 13. 验收标准

### 13.1 主流程验收

1. 用户可以选择一个已有餐厅菜单并创建静态菜单项目。
2. 用户可以选择横屏、竖屏、A4、A3 或自定义规格。
3. 系统能够识别阻断生成或导出的关键数据与素材问题。
4. 用户可以通过少量业务选择获得至少两个使用真实内容的代表页方案。
5. 用户选择方向后，系统可以生成全部页面并保持商品和价格正确。
6. 用户可以执行第 5.10 节定义的有限编辑、锁定单个组件，并重新生成当前页。
7. 系统可以对全部页面执行导出前检查。
8. 用户可以把当前页导出为 PNG/JPG，把全部页面导出为 ZIP 图片包，并把当前页或全部页面导出为 PDF。
9. 导出文件的尺寸、页数、顺序、内容和字体结果符合所选配置。
10. 用户关闭并重新打开项目后，能够继续编辑；任一正式导出均可追溯到不可变 `ProjectVersion`。
11. 当实时菜单晚于项目快照时，系统必须要求刷新为新版本或明确确认按旧快照导出。

### 13.2 正确性底线

- 商品名称与价格不得被 AI 擅自修改。
- 商品绑定错误数必须为 0。
- 存在内容越界、缺失价格或无法渲染字体等 BLOCKER 时不得导出。
- 相同 `BuildManifest` 必须得到相同页面结构；相同 `ExportInputFingerprint` 必须得到相同正式文件内容与哈希。
- `px` 与 `mm` 规格的图片 / PDF 尺寸必须严格遵守第 4.4 节的换算与取整规则。
- 多页 PDF 不得缺页、乱序或混用不同页面尺寸。
- 多页图片只有在全部页面成功后才可产生正式 ZIP；不得交付部分成功结果。
- 导出失败不得破坏项目或覆盖最近一次成功导出。

### 13.3 体验目标

- 从选择已有菜单到看到首个代表页方案：目标不超过 2 分钟。
- 从创建项目到完成一次有效导出：目标不超过 30 分钟。
- 大多数目标用户无需修改底层网格、字号和坐标即可完成导出。
- 后续改价、换图或增减商品时，用户可在原项目上继续工作，无需从零开始。

## 14. 成功指标

### 14.1 核心指标

- 成功导出率：进入导出流程的项目中，成功获得可读取成品文件的比例。
- 首轮可用率：首轮完整生成后无需结构性重做的项目比例。
- 完成时长：从创建项目到首次成功导出的中位时间。
- 阻断准确率：真正影响成品的缺失数据、溢出和导出问题被预检发现的比例。
- 再编辑率：用户重新打开既有项目进行更新，而不是重新创建项目的比例。

### 14.2 MVP 目标值

- 成功导出率不低于 95%。
- 商品名称、价格和绑定正确率为 100%。
- 首轮可用率不低于 60%。
- 首次有效导出中位时长不超过 30 分钟。
- BLOCKER 遗漏导致的无效成品比例为 0。

## 15. 决策记录

| 决策 | 结论 | 原因 |
|---|---|---|
| Phase 1 产品目标 | 静态电子菜单设计与图片 / PDF 导出 | 用户已明确确认为第一阶段唯一主目标 |
| 产品形态 | 约束式智能共创 | 同时保证易用性、可编辑性、正确性和可复现性 |
| 生成方式 | AI 规划 + 模板配方 + 规则约束 + 确定性编译 | 避免纯 AI 页面不可控、不可复现的问题 |
| 核心中间产物 | 可编辑结构化页面项目 | 支持修改、重开、局部重生成和多格式导出 |
| 图片和 PDF | 使用同一页面模型生成 | 防止不同格式内容不一致 |
| Phase 1 互动能力 | 不支持在线点餐业务行为 | 图片和普通 PDF 是静态成品，互动点餐属于独立产品阶段 |
| 专业印前能力 | 不进入 Phase 1 | CMYK、PDF/X 和 ICC 会显著扩大范围，应独立设计 |
