# 菜单下单限制移除“不限制”配置设计

## 背景

数量与频次规则的「限购数量 > 产线配置」目前允许在单行操作或批量操作中把目标明确设置为“不限制”。产品口径调整后，该页面只需要支持填写限购数量和以 `0` 表示禁止，不再提供“不限制”配置。

## 目标

- 移除产线配置表的「操作」列及每行「设为不限制」按钮。
- 移除批量设置操作条中的「设为不限制」按钮。
- 历史上已配置为“不限制”的单元格统一恢复为「未配置」。
- 保留现有单项数量输入、批量勾选、批量应用数量及批量设为禁止能力。

## 页面与交互

产线配置表保留：批量模式选择列、菜品或分类、人均上限或订单上限、状态、实际限额。普通模式不展示选择列，所有模式均不再展示「操作」列。

批量操作条保留「应用数量」「设为禁止」「取消」，不再展示「设为不限制」。进入批量模式仍默认不选目标，成功应用或切换人数、轮次、产线后仍自动退出并清空选择。

## 数据归一化

所有草稿读取入口通过同一个幂等归一化函数遍历 `draft.limits`，包括编辑器、门店选择页和发布确认页：

- `configured === true && value === null` 代表历史“不限制”状态。
- 将其归一化为 `{ configured: false, value: null }`，页面显示「未配置」。
- 其他正整数和 `0` 原样保留。

归一化作用于当前规则的全部人数、轮次、产线和目标单元格，避免未访问的场景继续残留旧状态。只要发现历史“不限制”状态，就立即把归一化后的草稿写回规则存储，而不是依赖用户后续编辑或手动保存；刷新页面后仍保持「未配置」。重复执行归一化不应继续产生变化。

门店选择页、发布确认页以及最终发布校验必须使用归一化后的草稿，禁止通过直接 URL 进入后绕过未配置校验。持久化后的 `editorDraft.limits` 及对外兼容的 `limits` 输出均不得继续包含 `{ configured: true, value: null }`。

## 文案与校验

- 页面说明改为：空输入表示未配置，`0` 表示禁止。
- 缺失配置提示只引导用户输入数量或 `0`。
- 完成度和发布校验仍以 `configured === true` 计算，因此被归一化的历史“不限制”单元格视为未配置，必须重新填写数量或 `0` 才能完成发布。

## 代码清理

- 删除 `data-set-unlimited` 单项操作渲染及事件处理。
- 删除 `data-apply-batch="unlimited"` 批量操作渲染。
- 批量应用逻辑只处理数值和 `0` 两种模式。
- 保留底层 `value: null` 对未配置状态的表达，不引入新字段或数据结构。

## 验收标准

1. 普通产线配置表无「操作」列，无任何单行「设为不限制」按钮。
2. 批量设置操作条无「设为不限制」按钮。
3. 菜品规则和分类规则均符合以上表现。
4. 历史 `{ configured: true, value: null }` 数据打开后显示为「未配置」，并计入未完成数量。
5. 单项填写正整数或 `0` 正常。
6. 批量勾选后可应用正整数或设为禁止，且只影响已勾选目标。
7. 批量模式的默认不选、全选、清空、取消和上下文切换清理行为不回归。
8. 页面说明和校验提示不再引导用户设置“不限制”。
9. 既有规则列表滚动、标题焦点和批量目标选择回归检查通过。
10. 历史“不限制”状态归一化后立即持久化，刷新页面仍显示为「未配置」。
11. 历史草稿直接进入门店选择页或发布确认页时也会先归一化，且不能绕过未配置校验。
12. 重复读取同一份已归一化草稿不会产生额外数据变化。
