# 菜品集共享额度双计量说明与示例设计

## 背景与目标

配置额度页已把“按份限制”和“按种限制（SPU）”并列放入同一“菜品集共享额度”卡片，但标题问号仍展示旧的按份专属说明，两个子卡没有独立问号。配置人员无法直接判断两种计量的统计口径及共同生效关系。

本方案只修正说明文案与问号入口，不改变计量、保存、校验或运行逻辑。

## 展示规则

1. 共享额度标题旁保留问号，改为解释双计量整体关系。
2. “按份限制”“按种限制（SPU）”标题旁各增加同款问号；开关关闭时问号仍可查看。
3. 三个浮层均使用现有“说明／示例”两段式，支持点击打开、点外部或按 `Esc` 关闭，并有分别可识别的 `aria-label`。
4. 示例统一写“当前场景”，避免在整单、每轮、分轮次之间误用周期文案。当前场景和门店内跨产线合并统计；不同门店的额度分别计算。
5. “按份”和“按种”可单独启用、同时启用或全部关闭。两项同时启用时分别校验，均需满足；全部关闭时该场景的共享额度为未配置。已启用的计量至少配置一个上限。

## 文案对应关系

| 入口 | 说明 | 示例 |
| --- | --- | --- |
| 菜品集共享额度 | 当前场景选中的商品合并统计；按份统计总份数，按种统计不同商品种数。两项可单独或同时启用；同时启用时须分别满足。同一门店跨产线合并，不同门店额度不共享。 | 牛肉 3 份、羊肉 2 份，合计 5 份、2 种。若本场景按份最多 5 份且按种最多 2 种，当前符合两项限制；再加牛肉 1 份超按份，再加虾滑 1 份则同时超两项。 |
| 按份限制 | 当前场景菜品集商品的份数相加，同一商品点多份按实际份数计入。人均上限乘订单有效人数，整桌上限不乘人数；两者同时配置时取更严格的上限。 | 3 人就餐，每人最多 2 份、整桌最多 5 份，则当前场景合计最多 5 份；牛肉 3 份加羊肉 2 份正好达到上限。 |
| 按种限制（SPU） | 统计当前场景至少点 1 份的不同商品种数，同一商品点多份仍算 1 种。人均上限乘订单有效人数，整桌上限不乘人数；两者同时配置时取更严格的上限。 | 3 人就餐，每人最多 1 种、整桌最多 2 种，则当前场景最多 2 种；牛肉 3 份与羊肉 2 份算 2 种，再加虾滑会超限。 |

按种的商品身份沿用现有 `productLineId + ":" + dishId`；文案不得暗示跨产线同名商品自动视为同一 SPU。示例中的牛肉、羊肉、虾滑均指三个不同商品身份。

## 实施与验收边界

- 更新 `buffetRuleHelpContent` 的共享额度内容，将旧按份专属说明替换为整体说明，并新增按份、按种子卡说明；`renderBuffetSharedQuotaPanel` 和子卡标题分别调用相应帮助内容。
- 不修改子卡开关、字段、单位、额度计算和商品保护说明。
- 扩展帮助内容静态验证，确认三个入口及文案，并在浏览器验证关闭状态的子卡仍能打开问号、双计量并列时浮层不遮挡或裁切。
