# TipOut 员工工时简化汇总与规则明细弹框设计

## 状态

已确认。

## 背景与目标

员工分配汇总当前在“打卡工时”中展示 `X/Y 天有记录`，并在“分配工时”列直接罗列每个小费池和规则的累计工时，导致列表信息密度过高。新方案将列表收敛为可快速核对的简洁结果，同时保留点击查看规则级明细的审计能力。

本文覆盖 `2026-09-15-tip-employee-hours-display-design.md` 中以下旧规则：

- 打卡工时不再展示 `X/Y 天有记录`。
- 分配工时不再在列表中逐条展示小费池和规则。
- 分配工时不再把多个规则值强行相加为员工实际工时；存在不同有效值时显示“多口径（N）”。

未被本文修改的快照、发放锁定、缺失值、日期排序及导出审计规则继续有效。

## 字段定义与计算顺序

### 打卡工时

打卡工时表示员工最初产生的原始打卡记录计算结果。POS 后续人工修正考勤时，原始打卡工时保持不变。例如原始打卡为 8 小时、POS 修正为 10 小时，打卡工时仍展示 `8 h`。

- 员工分配汇总：累计筛选日期范围内的有效原始打卡工时，只显示数值，例如 `175.25 h`。
- 员工每日小费：显示当天原始打卡工时。
- 无有效原始打卡记录时显示 `—`。
- 不再显示“X/Y 天有记录”或任何完整性后缀。

### 规则分配工时

每条按工时分配的规则独立计算实际采用工时，计算顺序如下：

1. 打卡规则优先读取 POS 当前有效考勤工时；若 POS 未修正，则使用原始打卡工时。
2. 规则设置最大工时时，在上一步结果上应用封顶：`实际采用工时 = min(POS 当前有效考勤工时, 最大工时)`。
3. 未打卡规则读取该 `poolId + ruleId + dateKey + employeeId` 对应的手工录入工时；不同规则可录入不同值。
4. 平均分配、按订单等非工时规则没有分配工时，展示 `—`。

示例：

| 场景 | 打卡工时 | 规则分配工时 |
| --- | --- | --- |
| 原始打卡 8h，无 POS 修正、无封顶 | `8 h` | `8 h` |
| 原始打卡 8h，POS 修正为 10h | `8 h` | `10 h` |
| 原始打卡 8h，最大工时 5h | `8 h` | `5 h` |
| 无打卡，规则 A 手工 4h、规则 B 手工 6h | `—` | A 为 `4 h`，B 为 `6 h` |

### 列表分配工时摘要

员工汇总先按 `poolId + ruleId` 分别累计筛选日期范围内的有效规则分配工时；员工每日小费只读取当天各规则的有效值。然后对有效结果去重：

- 没有有效工时规则：显示 `—`，不可点击。
- 所有有效工时规则结果相同：显示唯一数值，例如 `159 h ›`，可点击。
- 存在两个或以上不同有效结果：显示 `多口径（N）›`，可点击。`N` 表示不同有效数值的数量，而不是规则数量；相同数值的多条规则只形成一个口径。
- 非工时规则不参与 N，也不影响唯一值判断。
- 数值按两位小数规范化后再去重，避免浮点误差制造假多口径。
- 每日规则工时先按四舍五入规范化到两位小数，再参与跨日累计；跨日累计结果再次按四舍五入规范化到两位小数，摘要与弹框展示同一规范化结果。
- 不对不同规则的工时求和，因为规则工时是分配口径，不等同于员工实际工作总时长。

## 页面与交互

### 员工分配汇总

- “打卡工时”只显示累计数值或 `—`。
- “分配工时”只显示唯一数值、`多口径（N）` 或 `—`。
- 唯一数值和“多口径”使用链接式按钮与右箭头，点击打开“分配工时明细”弹框。
- 保留打卡工时排序；分配工时不提供排序。

### 员工每日小费

- 逐日行的“打卡工时”只显示当天原始打卡值或 `—`。
- 逐日行的“分配工时”使用与员工汇总相同的摘要规则并支持点击。
- 页面顶部的分配工时汇总同样使用摘要规则并支持点击，弹框上下文为当前员工与筛选日期范围。

### 分配工时明细弹框

弹框展示上下文：

- 员工汇总或详情顶部入口：员工名称、门店和筛选日期范围。
- 员工每日行入口：员工名称、门店和具体日期。

员工汇总或详情顶部的日期范围弹框按 `poolId + ruleId` 每条规则展示一条跨日汇总，不展开“规则 × 日期”明细；员工每日行弹框每条规则展示当天一条记录。明细按小费池名称、规则名称、`poolId`、`ruleId` 稳定排序，每条规则展示：

| 字段 | 说明 |
| --- | --- |
| 小费池 | 当前展示名称；身份仍以 `poolId` 为准 |
| 规则 | 当前展示名称；身份仍以 `ruleId` 为准 |
| 工时来源 | `原始打卡`、`POS 修正`、`最大工时`、`手工录入`、`混合来源`或`不适用` |
| 分配工时 | 规则实际采用值；非工时规则或缺失值为 `—` |

单日来源判断优先级：最大工时实际生效时显示“最大工时”；否则 POS 值与原始值不同时显示“POS 修正”；未打卡规则显示“手工录入”；其余打卡规则显示“原始打卡”；非工时规则显示“不适用”。日期范围内同一规则的有效日期具有两个或以上不同来源时，汇总行显示“混合来源”；全部有效日期来源一致时显示该唯一来源。日期范围弹框不额外展开每天来源，逐日审计通过员工每日小费行入口完成。

日期范围累计只加入有效日期：缺失值不计入累计，合法 `0 h` 计入有效口径；部分日期缺失时仍展示其余有效日期累计，全部日期缺失时显示 `—`。例如三天依次为 `4 h`、缺失、`0 h`，规则累计为 `4 h`；三天全部缺失时为 `—`。

弹框支持右上角关闭、底部取消、点击遮罩关闭和 Esc 关闭。打开后焦点进入弹框；关闭后焦点返回触发入口。弹框有明确标题、`role="dialog"`、`aria-modal="true"` 和可关联的说明文本。

## 数据与状态

- 原始打卡工时、POS 当前有效考勤工时和规则实际采用工时必须作为不同结构化字段保存，UI 不从展示文本反推。
- 待分配读取当前原始打卡、POS 当前考勤、规则配置和草稿手工工时。
- 确认分配时，将原始打卡工时、POS 有效考勤工时、最大工时配置及最终规则采用工时写入同一确认快照。
- 已分配、待发放读取确认快照；重新确认后生成新快照。
- 已发放读取锁定快照，不使用随后变化的实时考勤或规则配置。
- 存在未确认更新时，员工页面按既有规则展示当前草稿工时；已确认金额与发放保护保持不变。
- 历史快照缺少新字段时，只能从同一快照自洽重建；不能用实时 POS 考勤补写历史结果。无法重建时显示 `—`。
- 弹框及导出中的小费池和规则名称来自对应草稿、确认快照或锁定快照。跨日同一稳定 ID 曾改名时使用筛选范围内最新业务日期所保存的名称；历史确认或已发放结果不得读取当前规则名称覆盖快照名称。

## 导出

- 页面列表采用简化摘要，但员工分配汇总和员工每日小费的 CSV、PDF、邮件继续导出各小费池与规则的分配工时明细，满足审计需求。
- 导出保留“打卡工时”与“分配工时”独立字段；打卡工时不再包含 `X/Y 天有记录`。
- 分配工时明细按弹框相同粒度和排序输出，包含“小费池 · 规则名称、工时来源、实际采用工时”；日期范围导出每条规则一条跨日汇总，来源可能为“混合来源”，员工每日导出为当天规则记录。
- 非工时规则输出 `—`；不同规则不得合并或求和。

## 异常与边界

- POS 修正值、最大工时或手工工时为负数、非数值或缺失时，该规则分配工时显示 `—`，并沿用既有确认校验；本功能不新增分配阻断。
- 合法 `0 h` 是有效值，参与唯一值或多口径判断；缺失 `—` 不参与。
- 最大工时大于 POS 当前工时时不算封顶生效，来源仍显示“POS 修正”或“原始打卡”。
- 同名不同池或规则仍按稳定 ID 分开；弹框重名时追加短 ID。
- 多条规则都为同一有效值时，摘要只显示该值，但弹框仍展示全部规则。
- 弹框没有可用规则时不打开；入口展示 `—`。

## 验收标准

- 打卡工时只显示数值，不再出现“X/Y 天有记录”。
- 员工汇总和员工每日小费列表不直接展示小费池规则明细。
- 原始打卡 8h、POS 修正 10h 时，页面显示打卡工时 `8 h`、分配工时 `10 h`，弹框来源为“POS 修正”。
- 原始打卡 8h、最大工时 5h 时，页面显示打卡工时 `8 h`、分配工时 `5 h`，弹框来源为“最大工时”。
- 无打卡且两条规则手工输入 4h/6h 时，列表显示“多口径（2）”，弹框分别展示两条规则及 4h、6h。
- 多条规则采用值都为 8h 时，列表只显示 `8 h`，弹框仍展示全部规则。
- 唯一值和“多口径”均可打开弹框，`—` 不可点击；键盘和焦点行为符合设计。
- CSV、PDF、邮件保留规则级明细与来源，且不包含 `X/Y 天有记录`。
- 待分配、已分配、未确认更新、已发放及旧快照场景符合数据状态规则。
- 角色/员工/日期筛选、打卡工时排序、金额、确认分配及发放锁定回归通过。
