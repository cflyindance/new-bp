# KPOS Admin → Table 完整复刻设计

## 目标与边界

在商家后台“前厅管理 → 餐位平面图”中完整复刻真实 KPOS `Admin → Table` 的桌台配置编辑能力。页面直接读取和写入商家绑定主机的 KPOS 桌台数据，但不包含营业前台的开台、换台、并台、点餐或订单操作。

本设计建立在现有 KPOS 主机绑定、PC/POS License 会话、Admin 密码验证、浏览器加密记密以及 `ListAreasType`、`ListTablesType`、`SaveSeatingAreaType` 接入之上。

## 真实功能基线

从目标主机 `192.168.96.96:22080` 的 Table 实现确认以下能力：

- 区域切换、区域新增、重命名、删除和整体保存。
- 桌台新增、属性编辑、删除与画布拖拽。
- 单选、多选和选中基准桌台。
- 左、右、上、下边缘对齐。
- 水平中心线、垂直中心线对齐。
- 水平、垂直等间距分布；少于三张桌时禁用。
- 统一宽度、统一高度。
- 宽度增加/减少 5px，高度增加/减少 5px。
- 向左、右、上、下移动 5px，并限制在画布范围内。
- `RECTANGLE`、`ROUND`、`HIBACHI` 三种 KPOS 形状。
- 通过 `SaveSeatingAreaType` 提交完整区域快照。

## 界面设计

采用已确认的 C 混合方案：保留当前区域标签、主画布和右侧属性面板，在画布顶部增加折叠式批量工具栏。

工具栏分组为：

1. 选择：多选模式、全选、取消选择。
2. 对齐：左、水平居中、右、上、垂直居中、下。
3. 分布：水平等距、垂直等距。
4. 统一尺寸：统一宽度、统一高度。
5. 缩放：增宽、减宽、增高、减高。
6. 微调：左、右、上、下移动。

默认单选。多选模式支持点击切换选择；桌台选择集合仅存在于当前区域，切换区域时清空。首个选中桌台是对齐和统一尺寸的基准桌台，并在视觉上显示基准标记。工具按钮提供中文标签、图标、tooltip、键盘焦点态和禁用原因。

## 数据模型与映射

KPOS 字段完整映射：

| 商家后台 | KPOS |
|---|---|
| `id` | `id` |
| `name` | `name` |
| `seats` | `defaultGuestCount` |
| `x/y` | `x/y`，KPOS 的 0–1 归一化值与画布像素互转 |
| `width/height` | `width/height`，KPOS 的 0–1 归一化值与画布像素互转 |
| `rectangle` | `RECTANGLE` |
| `circle` | `ROUND` |
| `oval` | `HIBACHI` |

真实 Wire fixture 中 `ApiReader.setOneTable` 只序列化 `id/name/shape/x/y/width/height/defaultGuestCount/currentGuestCount/status`。因此 `status` 和 `currentGuestCount` 是服务器运行态字段，显示但不作为用户可编辑属性。截图中的“桌子类别”在 Wire 中表现为桌台所属区域，而不是桌台上的独立 category 字段；跨区域移动在保存协议验证完成前不开放。

商家后台原有的 `category`、`rotation`、`durationBillingRuleId` 放入单独折叠的“商家扩展”区，并明确标记“不写入 KPOS”。扩展仓储使用 IndexedDB，记录键为“登录商家用户 + 规范化 KPOS 主机 + KPOS storeId + KPOS 桌台 ID”，不使用 License，因此更换同主机 License 不会丢失绑定。服务器连续 30 天不存在的桌台记录可清理；临时 ID 的扩展记录在保存回读后原子迁移到服务器 ID。

形状 fixture 明确给出 `s → RECTANGLE`、`r → ROUND`、`h → HIBACHI`。商家后台内部为兼容旧数据可继续使用 `oval` 作为 `HIBACHI` 的存储别名，但真实模式 UI 必须显示“Hibachi / 长桌”，不可显示成泛化的“椭圆”。

新区域和新桌台使用临时 ID。保存成功后必须重新读取服务器快照，以 KPOS 返回的数据替换临时对象并完成扩展字段重绑定。

## 几何操作规则

- 编辑器逻辑画布固定为 `1000 × 650`。读取公式为 `xPx = round(x * 1000)`、`yPx = round(y * 650)`、`widthPx = round(width * 1000)`、`heightPx = round(height * 650)`；若服务器返回值大于 1，则按旧版像素数据兼容读取。保存公式为 `x = round6(xPx / 1000)`、`y = round6(yPx / 650)`、`width = round6(widthPx / 1000)`、`height = round6(heightPx / 650)`，左上角为原点。视觉画布响应式缩放只使用 CSS transform，不改变逻辑坐标。
- 拖拽、单桌移动和缩放不得让桌台越出画布，交互时按边界钳制。
- 批量对齐、分布和统一尺寸若任一结果越界，整次操作禁用/拒绝，不对个别桌台钳制，以免破坏对齐关系。
- 减宽不得低于 60px，减高不得低于 40px，与真实实现一致。
- 对齐与统一尺寸要求至少两张桌；分布要求至少三张桌。
- 水平分布按左边缘排序，保留首尾外边界并均匀计算中间空隙；垂直分布同理。若首尾跨度小于所有桌台宽度/高度之和，产生负间距，则操作禁用并提示先扩大间距。
- 批量操作作为一次草稿变更记录，可由页面级“放弃修改”整体回滚。

## 新增、删除与保存

所有编辑先写入页面草稿，不立即请求 KPOS。点击“保存区域图”才提交当前区域快照。

删除规则：

- `status` 为空或 `AVAILABLE` 且 `currentGuestCount` 为 0 的桌台允许删除。
- 其他状态或当前人数大于 0 时禁止删除，并明确提示需先在 POS 清台。
- 区域非空时禁止删除区域，必须先删除并保存完桌台。
- 删除操作要求二次确认，确认后仍可在提交前通过“放弃修改”恢复。

区域删除必须使用从真实 KPOS 行为确认的协议；在未确认独立删除请求或空快照语义之前，按钮保持禁用而不是推测请求格式。

## 并发、冲突与运行态保护

初次读取时为每个区域保存服务器基线指纹，指纹覆盖区域名称及桌台的结构字段，不覆盖运行态字段。

保存流程：

1. 重新执行 `ListAreasType` 和当前区域的 `ListTablesType`。
2. 比较服务器结构指纹与进入编辑时的基线。
3. 若结构已被其他终端修改，阻止保存并提供“刷新服务器版本”选项，不做自动覆盖。
4. 若无结构冲突，将最新 `status/currentGuestCount` 合并到待提交桌台；同时找出“基线存在但草稿已删除”的每张桌台，用最新运行态重新执行删除资格检查。任一桌台已占用则中止整个保存。
5. 调用一次 `SaveSeatingAreaType` 提交完整区域。
6. 保存成功后重新读取区域和桌台，更新 ID、基线及页面状态。

每次写入前生成本地操作指纹，包含主机、storeId、区域 ID、基线结构指纹和目标结构指纹。请求超时或连接中断后必须先读回服务器：若服务器结构指纹等于目标指纹，视为已成功；若等于基线指纹，才允许用户明确重试；若两者都不等于，则进入“结果不确定”状态并禁止重试，要求刷新和人工核对。包含临时 ID 的快照还需按区域内 `name/shape/x/y/width/height/defaultGuestCount` 唯一结构签名对账；签名不唯一时不得自动认领服务器 ID，也不得重试，以防重复新增。会话过期时停止写入、清除连接态并要求重新验证；不自动重放写请求。

## 状态与反馈

- 顶部持续显示真实 KPOS 主机、License、最后同步时间和连接状态。
- 读取中显示骨架/加载态；失败时保留上一次已读取数据但进入只读状态。
- 保存期间锁定当前区域的编辑和保存按钮，防止重复提交。
- 成功提示包含区域名称和桌台数量；失败提示保留 KPOS 返回的安全错误摘要。
- 未连接时页面保留本地演示模式，并明确标记“未连接真实 KPOS”。

## 测试与验收

自动验证覆盖：

- SOAP XML 生成、解析、形状与比例映射。
- KPOS 运行态字段合并且不被编辑值覆盖。
- 临时 ID 在保存后被服务器 ID 替换。
- 写响应丢失后的基线/目标/不确定三分支对账，以及新增桌台唯一签名和歧义保护。
- 所有对齐、分布、统一尺寸、缩放和微调计算。
- 最小尺寸、画布边界、批量操作原子拒绝、负间距和选择数量禁用规则。
- 空闲/占用桌台删除保护及非空区域删除保护。
- 结构指纹冲突、请求失败、会话过期和重试状态。
- 关闭并重新进入页面后的扩展字段合并。

真实主机验收分两阶段：先完成 License、区域和桌台只读核对；再由用户选择专用测试区域执行新增、编辑、批量布局、删除及保存回读。不得在未指定测试区域时写入真实数据。
