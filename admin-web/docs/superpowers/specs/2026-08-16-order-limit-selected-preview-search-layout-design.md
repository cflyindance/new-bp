# 已选商品搜索与操作区布局设计

## 背景

“商品配置 > 查看已选商品”弹窗当前只支持门店和产线筛选，筛选条件位于顶部工具栏右侧；【批量删除】【全部删除】位于顶部左侧；底部分页左侧显示“共 N 条”。需要增加商品/分类名称搜索，并重新组织筛选与删除操作的位置。

## 目标

- 支持按商品名称或分类名称搜索已选目标。
- 搜索、门店和产线筛选在同一行展示，并位于“查看已选商品”标题下方。
- 将【批量删除】【全部删除】移动到底部原“共 N 条”的位置。
- 移除底部“共 N 条”文案。
- 保持现有删除确认、分页和每页条数行为不变。

## 筛选设计

弹窗标题和关闭按钮下方新增统一筛选行，顺序为：

1. 搜索商品/分类名称。
2. 门店。
3. 产线。

搜索输入框占用剩余宽度，门店和产线下拉保持紧凑固定宽度。窄屏时允许换行并改为纵向排列。

搜索规则：

- 菜品限购规则只匹配 `dishName`。
- 分类限购规则只匹配 `categoryName`。
- 不匹配门店名称、产线名称、组名或完整分类路径。
- 对输入执行去除首尾空白和不区分大小写的包含匹配。
- 支持中文输入法组合输入，组合期间不重绘弹窗；组合结束后应用搜索。

搜索、门店或产线条件变化时，统一回到第 1 页并清空当前勾选，避免隐藏记录仍参与批量删除。

## 底部操作区

底部左侧删除“共 N 条”，改为：

- 【批量删除】：仅删除当前明确勾选的记录，未勾选时禁用。
- 【全部删除】：删除规则中全部已选目标，不受搜索、门店或产线筛选影响；没有任何已选目标时禁用。

底部右侧继续展示上一页、页码、下一页和每页条数。窄屏时删除操作区与分页区分行展示。

表格行内【删除】及其二次确认保持不变。

## 状态与数据流

在弹窗临时状态中新增：

- `query`：已提交的搜索字符串。
- `searchComposing`：中文输入法组合状态。

搜索状态只属于弹窗，不写入规则草稿、兼容输出或发布快照。关闭并重新打开弹窗时重置为空。

筛选顺序为：全量已选目标 → 搜索条件 → 门店 → 产线 → 分页。搜索与现有门店/产线条件组合生效。

## 空态

- 存在已选目标但筛选无结果：显示“当前筛选条件下暂无已选商品”，提示调整搜索、门店或产线。
- 全量目标为空时，入口按钮继续禁用，沿用现有行为。

## 验收标准

- 标题下方同一筛选区按“搜索、门店、产线”顺序展示。
- 菜品规则只按商品名称搜索；分类规则只按分类名称搜索。
- 搜索支持包含匹配、忽略大小写和中文输入法组合输入。
- 任一筛选变化后页码回到 1，勾选清空。
- 顶部不再出现【批量删除】【全部删除】。
- 底部左侧显示两个删除按钮，不再显示“共 N 条”。
- 两种删除操作的范围和二次确认保持不变。
- 分页和每页条数功能保持正常。
- 相关静态验证、JavaScript 语法检查和浏览器验收通过。
