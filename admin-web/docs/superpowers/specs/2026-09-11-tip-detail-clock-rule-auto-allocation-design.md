# 小费分配明细纯打卡规则自动分配设计

## 背景与目标

当前未分配日期进入小费分配明细后，均需要用户点击“确认分配”。本次调整让不需要人工补充信息的纯打卡规则日期自动完成分配；凡是包含不打卡规则、需要人工录入员工或工时的日期，继续保留人工确认流程。

本次只改变未分配日期进入明细时的触发方式，不改变规则计算公式、正式结果结构、重新确认分配、取消分配和薪资同步口径。

## 自动分配资格

进入明细页，以及在明细页切换日期或门店并完成规则渲染后，按当前完整门店标识和 ISO 日期检查资格。

同时满足以下条件时自动分配：

1. 当前门店和日期状态为“未分配”。
2. 当前门店存在至少一条适用于该日期的有效小费规则。
3. 所有适用规则的打卡设置均为打卡规则，即不存在 `clockin === "noclock"` 的规则。
4. 规则引用的角色和员工均有效。
5. 当前打卡数据、金额和比例通过现有确认分配校验。

只要适用规则中存在一条不打卡规则，当天整体不执行自动分配。即使部分员工已经补录工时，也必须由用户完成员工和工时信息后点击“确认分配”。不对同一天拆分“部分自动、部分手动”状态。

无规则、规则失效、员工或角色失效、打卡数据异常、金额或比例非法时不执行自动分配。

## 交互与状态

### 纯打卡规则日期

- 页面先完成规则与明细渲染，再启动自动确认，避免从未完成的 DOM 或计算状态生成结果。
- 自动确认期间主按钮禁用，文案显示“分配中…”。
- 成功后沿用现有正式确认链路：保存 `tipout_allocation_results_v1` 快照、加入 `tipout_allocated`、刷新汇总快照、同步薪资 Tips/SVCW。
- 成功后当天状态为“已分配”，按钮切换为“重新确认分配”，提示“已根据打卡规则自动完成分配”。
- 已分配日期再次进入或重新渲染时不得自动执行，也不得出现覆盖确认框。

### 包含不打卡规则的日期

- 不启动自动确认，不弹出阻断对话框。
- 明细保持可编辑，主按钮显示“确认分配”。
- 用户录入所需员工与工时后，继续使用现有手动确认逻辑。

### 自动分配失败

- 不写入正式快照和已分配状态；写入阶段失败时沿用现有回滚能力。
- 页面保持未分配，按钮恢复为“确认分配”。
- 提示具体可操作原因；薪资同步失败时沿用现有语义：正式结果保留，提示用户重试，此时日期已经是已分配状态。

## 防重复与生命周期

- 自动分配资格检查封装为独立函数，渲染函数只负责在渲染完成后调度。
- 使用 `store + date` 作为页面生命周期内的执行键，记录“执行中”和“已尝试”状态，防止一次渲染链、多次事件或薪资同步造成重复提交。
- 已尝试但因校验失败的同一页面状态不会在每次重绘时循环提示；当用户切换日期或门店后使用新的执行键。
- 正式已分配状态是跨页面的最终幂等边界。页面刷新后若该日期已分配，直接跳过自动分配。
- 自动流程不调用“重新确认分配”分支，因此不显示覆盖提示。

## 与取消分配的关系

汇总页“取消分配”逻辑保持不变，继续作为演示数据重置使用。取消后日期恢复未分配；用户再次进入该日期明细时：

- 若当前全部适用规则均为打卡规则，则按当前规则和最新打卡数据重新自动分配并覆盖旧快照。
- 若当前存在不打卡规则，则保持未分配，等待人工录入和确认。

## 实现边界

- 复用 `collectDetailAllocationSnapshot`、`TipOutAllocationResults.validate/commit` 和 `TipOutPayrollBridge.syncAfterAllocation`，不新增第二套分配计算。
- 将“是否全部为打卡规则”的判定放在明细程序中，基于 `ruleData.getRulesForStore(store)` 返回的当前适用规则。
- 将现有确认分配的保存、同步、通知流程抽成可供手动和自动入口共同调用的内部执行函数；手动重新确认仍保留覆盖确认。
- 不修改小费规则编辑器、不新增规则字段、不新增列表状态、不修改取消分配函数。

## 验收标准

1. 未分配日期仅包含打卡规则时，进入明细后自动完成分配。
2. 纯打卡日期自动分配成功后显示“已分配”和“重新确认分配”。
3. 在明细页切换到另一个纯打卡未分配日期时同样自动分配。
4. 任一适用规则为不打卡规则时，当天不自动分配，并显示“确认分配”。
5. 混合规则日期不会只分配打卡规则部分。
6. 已分配日期进入或重绘时不会再次自动执行或弹出覆盖提示。
7. 自动分配校验失败时不产生正式结果，页面保持未分配并显示明确原因。
8. 自动分配的正式结果、汇总金额和薪资 Tips/SVCW 一致。
9. 取消纯打卡日期后再次进入明细，会基于最新规则和打卡数据重新自动分配。
10. 取消分配、手动确认和重新确认分配的既有逻辑保持不变。

## 验证策略

- 自动测试纯打卡、多条纯打卡、纯不打卡和混合规则的资格判定。
- 自动测试未分配、已分配、执行中、已尝试和切换门店/日期的幂等行为。
- 自动测试自动入口复用正式快照、汇总和薪资同步链路。
- 自动测试校验失败、结果写入失败和薪资同步失败的状态及提示。
- 回归测试手动确认、重新确认覆盖、取消分配和员工对账读取。
- 浏览器验证进入明细与切换日期两种触发方式。
