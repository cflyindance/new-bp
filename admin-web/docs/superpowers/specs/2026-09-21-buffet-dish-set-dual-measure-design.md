# 自助餐菜品集双计量场景配置设计

## 1. 背景与目标

现有菜品集规则在规则类型步骤选择唯一的 `measureUnit`：按份或按种（SPU）。该选择对整条规则生效，导致同一条规则无法在一个人数与轮次场景内同时约束总份数和商品种数，也无法让不同场景采用不同计量组合。

本方案将菜品集计量方式移入“配置额度”，并把按份、按种建模为两个可独立启用且可共同生效的场景约束。目标如下：

- 每个“门店 × 人数区间 × 周期/轮次区间”场景独立选择按份、按种或二者同时启用。
- 同时启用时，两类上限共同生效；达到上限的当前结果仍允许，下一次导致任一上限被超过的操作才被拒绝。
- 保留现有商品级份数保护，不因双计量重复两套商品输入。
- 旧规则按原计量方式无损迁移，不自动增加另一类限制。
- 场景卡片、批量设置和全部配置汇总能够准确表达双计量结果。

本设计仅适用于限购对象为“按照菜品集限购”的规则。菜品和分类继续按份计算。

## 2. 已确认决策

1. 计量方式从规则级基础字段移入场景“配置额度”。
2. 每个场景独立启用“按份限制”和“按种限制（SPU）”。
3. 同一场景允许同时启用两种计量；两者为 AND 关系，分别计数、共同判定，只有超过上限才拒绝。
4. 每种计量都支持人均上限和整桌上限；其中任一层级可以不配置。
5. 商品明细只保留一套“单个商品最多份数”，始终按份计算。
6. 至少启用一种计量方式；每种已启用计量至少填写一个有效上限。

## 3. 术语与计算语义

| 名称 | 统计对象 | 示例 |
| --- | --- | --- |
| 按份 | 菜品集内商品数量之和 | 牛肉 3 份＋羊肉 1 份＝4 份 |
| 按种（SPU） | 菜品集中数量大于 0 的不同 SPU 数 | 牛肉 3 份＋羊肉 1 份＝2 种 |
| 商品份数保护 | 菜品集中单个商品的份数上限 | 集合允许 5 份，但牛肉最多 2 份 |

按种时，同一商品从 1 份增加到 2 份不增加种数；从 0 增加到 1 才增加一种，数量减到 0 才释放一种。商品份数保护始终以份为单位。

“种”的稳定身份不是商品名称，也不是跨产线业务上可能同名的抽象 SPU。当前实现统一使用 `kindKey = productLineId + ":" + dishId`：

- 同一产线、同一 `dishId` 的规格/SKU 数量合并后大于 0，只计 1 种。
- 同一产线不同 `dishId` 分别计种，即使名称相同也不合并。
- 不同产线分别计种，即使上游声明为同一 SPU 或名称相同也不合并。
- 商品从正数减至 0 时释放对应 `kindKey`；负向操作不得使最终数量小于 0。

页面继续使用易理解的“种（SPU）”文案，但研发、接口和测试均以 `kindKey` 为唯一判定口径。

同一场景设置“每人每轮最多 5 份”和“每人每轮最多 3 种”时：

- 已点牛肉 2 份、羊肉 2 份，使用 4 份、2 种。
- 再点牛肉 1 份后使用 5 份、2 种，允许并达到份数上限。
- 再点虾滑 1 份会变为 6 份、3 种，因份数超限而拒绝。
- 若已点牛肉、羊肉、虾滑各 1 份，再点第四种商品，即使总份数未满，也因种数超限而拒绝。

所有判断均使用本次变更后的最终数量。按份与按种不互相换算。

## 4. 页面与交互设计

### 4.1 第一步：规则类型

限购对象选择“按照菜品集限购”后，不再显示规则级“计量方式”。规则预览只描述“按照菜品集限购”，不提前承诺按份或按种。

历史系统默认规则入口名称中带“按份”或“按种”的，继续按名称为初始场景开启对应计量；用户进入配置额度后可以增加另一种计量。10 个常用模板本身不携带计量方式，具体规则见第 9 节。

### 4.2 配置额度页

商品列表上方保留独立的“菜品集共享额度”卡片。卡片内展示两个并列区块：

#### 按份限制

- 独立开关，默认状态由模板或历史数据决定。
- 开启后显示“每人每轮最多 / 每人整单最多”和“整桌每轮最多 / 整桌整单最多”，标签随周期变化。
- 单位统一显示“份”。

#### 按种限制（SPU）

- 独立开关，默认状态由模板或历史数据决定。
- 开启后显示与按份相同的主体和周期层级。
- 单位统一显示“种（SPU）”。

字段由“主体 × 周期”共同决定：

| 主体 | 周期 | 共享额度字段 | 执行口径 |
| --- | --- | --- | --- |
| `order` | `entire_order` | 每单最多 | 固定整桌额度，不乘人数 |
| `order` | `per_round` | 每轮最多 | 固定整桌额度，不乘人数 |
| `order` | `round_range` | 当前轮次区间每轮最多 | 固定整桌额度，不乘人数 |
| `party_size` | `entire_order` | 每人每单最多＋整桌整单最多 | `min(人均值 × H, 整桌值)`；只配一项则使用该项 |
| `party_size` | `per_round` | 每人每轮最多＋整桌每轮最多 | `min(人均值 × H, 整桌值)`；只配一项则使用该项 |
| `party_size` | `round_range` | 当前轮次区间的每人每轮最多＋整桌每轮最多 | 按命中区间计算上述更严格值 |

`entire_order + per_round`、`entire_order + round_range` 等组合周期分别在各自 `period` 场景中保存额度；整单累计与当前轮累计分别判断，任一适用周期超限即拒绝。

开关规则：

- 两个开关不能同时关闭。
- 关闭无数据的计量直接收起。
- 关闭已有数值的计量时，确认框明确提示只清除当前场景该计量额度，不清除商品、另一计量额度、每轮总量或商品份数保护。
- 取消确认保持原状态和数值。

### 4.3 商品限购数量

商品表不因双计量增加第二套商品额度。每行仍只有现有的商品级份数保护字段，字段文案随主体和周期显示，例如“单个商品每人每轮最多”。

商品名称、产线、分类、门店、状态和操作继续遵循既有统一表格规范。双计量只改变共享额度卡片与汇总信息，不改变商品选择范围。

### 4.4 场景卡片摘要

场景卡片分行展示已启用计量：

- `按份：每人每轮 5 份；整桌未配置`
- `按种：每人每轮 3 种；整桌每轮 8 种`
- `商品限制：2 / 4 项已配置`

只启用一种计量时不显示另一种“未配置”，避免把未启用误解为漏填。

### 4.5 查看全部配置

全部配置汇总表增加“计量方式”筛选：全部、按份、按种、按份＋按种。共享额度使用独立列展示按份和按种结果，不把两种单位拼入一个不可排序的输入字段。

建议列为：场景、商品、产线、分类、门店、按份共享额度、按种共享额度、商品最多份数、状态。若汇总以商品平铺，同一场景共享额度可在每行重复显示，导出时也保持相同结构。

## 5. 数据模型

现有规则级 `measureUnit: piece | kind` 只作为旧结构兼容字段。新结构按场景保存：

```text
sceneQuota
├─ measures
│  ├─ piece
│  │  ├─ enabled
│  │  ├─ perPersonMax
│  │  └─ perTableMax
│  └─ kind
│     ├─ enabled
│     ├─ perPersonMax
│     └─ perTableMax
└─ productLimits
   └─ productKey → maxPieces
```

`quotaSchemaVersion=2` 是规则作者配置根节点的唯一版本字段，不在每个 `sceneQuota` 内重复保存。`productKey` 统一定义为 `productLineId + ":" + dishId`，不得只使用可能跨产线重复的 `productId/dishId`。

实际落库可继续沿用按门店、人数区间、轮次区间组织的 map，但必须满足：

- `piece` 与 `kind` 使用不同命名空间，不能复用同一 `targetLimits` 后依赖规则级单位解释。
- `enabled` 是显式状态，不通过“字段是否为空”推断计量是否启用。
- 商品份数保护与共享额度分离，避免关闭某个计量时误删商品配置。
- 序列化后仍能唯一定位门店、人数区间、周期和轮次区间。
- `kind` 计数器按 `productLineId:dishId` 保存或实时归并，规格/SKU 不是独立种数键。

场景稳定键为：

```text
storeId + period + partyRangeId + roundRangeId
```

`entire_order` 不使用轮次区间时 `roundRangeId` 固定为空标识；`per_round` 使用固定轮次场景标识；`round_range` 必须保存真实 `rangeId`。筛选、排序、分页及当前活动门店不进入场景键。

## 6. 历史规则兼容

读取旧规则时执行内存适配，不立即改写已发布数据。版本判定以 `quotaSchemaVersion` 为准：缺失或为 `1` 使用旧结构适配；为 `2` 只读新结构，不再回退读取旧字段，避免新旧值混用。

| 旧数据 | 新页面初始状态 |
| --- | --- |
| `measureUnit=piece` | 所有已有场景仅开启按份，旧共享额度迁入 `piece` |
| `measureUnit=kind` | 所有已有场景仅开启按种，旧共享额度迁入 `kind` |
| 商品份数保护 | 原样迁入 `productLimits` |
| 无对象额度的空场景 | 按原计量方式开启，但保持额度为空并标记待配置 |

逐字段映射如下：

| 旧字段 | 新字段 | 说明 |
| --- | --- | --- |
| `subject=party_size`、`measureUnit=piece`＋`targetLimits` | `measures.piece.perPersonMax` | 保留 `configured/value`，用于普通按人数及 C5 |
| `subject=party_size`、`measureUnit=kind`＋`targetLimits` | `measures.kind.perPersonMax` | 保留 `configured/value`，用于普通按人数及 C6 |
| `subject=order`、`measureUnit=piece`＋`targetLimits` | `measures.piece.perTableMax` | 普通按桌规则的主额度不乘人数 |
| `subject=order`、`measureUnit=kind`＋`targetLimits` | `measures.kind.perTableMax` | 普通按桌规则的主额度不乘人数 |
| `measureUnit=piece`＋`tableTargetCaps` | `measures.piece.perTableMax` | 用于普通整桌兜底及 C2 |
| `measureUnit=kind`＋`tableTargetCaps` | `measures.kind.perTableMax` | 用于普通整桌兜底及 C3 |
| `defaultDishLimits` | `productLimits.defaultMaxPieces` | C2/C3/C5/C6 与普通菜品集规则均原样保留 |
| `exceptionDishLimits` | `productLimits.exceptions[productKey]` | 保留覆盖默认值的语义 |
| `totalBounds/tableTotalBounds` | 原总量命名空间 | 与双计量无关，不迁入 `measures` |

整单＋每轮、整单＋分轮次等组合按各自 `period` 分别迁移；每个旧 map 的门店、`partyRangeId`、`roundRangeId` 和对象键保持不变。适配器不得用数组下标重建区间键。

首次以新结构打开旧草稿时展示一次非阻断提示：“已按原计量方式转换场景额度，请确认后保存。”只有用户保存或发布时才写入新结构。

迁移保存是幂等的：首次成功保存写入 `quotaSchemaVersion=2`；再次打开只读新结构，不重复迁移。保存新结构时可以暂存旧字段用于审计，但新客户端和发布编译器不得再读取旧字段。回滚到保存前使用草稿版本历史或服务端原作者配置快照，不把新结构反向压缩成单一 `measureUnit`。

接口与客户端能力门槛定案如下：

- 读取接口返回 `quotaSchemaVersion` 和 `requiredCapability: buffet_dish_set_dual_measure_v1`。
- 不具备该能力的旧客户端允许查看规则摘要，但编辑、复制、启用和发布接口返回 `409 UNSUPPORTED_BUFFET_QUOTA_SCHEMA`，不得静默降级。
- 新客户端保存时必须带 `quotaSchemaVersion=2`；服务端拒绝缺少版本的双计量写入。
- 发布快照编译为 `constraints[]`，每项包含 `metric: piece|kind|product_piece`、场景稳定键、主体、周期、上限和对象身份；运行端只执行快照，不依赖作者配置中的旧 `measureUnit`。

## 7. 批量设置

共享额度的批量设置以“当前配置额度页选中的场景集合”为作用范围，不依赖商品行勾选。商品行勾选只用于批量设置商品份数保护。批量设置面板展示两个独立区块：“批量设置按份额度”和“批量设置按种额度”。每个区块包含计量处理方式：

- 不处理：保持所选对象或场景原值。
- 启用并设置：开启该计量并写入本次填写的非空字段。
- 关闭并清除：需要二次确认，只清除该计量。

空输入不覆盖已有值；显式 `0` 代表禁止下单。批量应用前显示影响场景数；商品份数保护的批量操作另行显示商品数。批量操作先对全部目标场景做预校验，再一次性提交：任一场景会变成“两种计量全关”或“计量已启用但全部额度为空”时，整批不应用并列出失败场景，不允许部分成功。应用后在当前页面更新摘要，但仍需“保存并返回”才写入草稿。

场景复制时，复制双计量开关、共享额度和商品份数保护；复制结果是独立数据，后续修改来源场景不会联动目标场景。

## 8. 校验、状态与错误处理

### 8.1 场景完整性

每个菜品集场景必须满足：

1. 至少启用一种计量。
2. 每种已启用计量至少填写一个适用于当前主体和周期的上限。
3. 输入为非负整数；`0` 表示禁止下单，空值表示该层级不限制。
4. 人均值与整桌值同时存在时分别生效，实际上限为 `min(人均上限 × 有效人数 H, 整桌上限)`；只配置一项时使用该项。
5. 商品份数保护独立校验，不要求小于共享份数上限，因为人数和整桌口径可能不同。

### 8.2 状态文案

- 任一已启用计量存在显式 `0`：按现有优先级显示“禁止下单”。
- 所有已启用计量均满足完整性：显示“已配置”。
- 已启用计量缺少必需额度：显示“未配置”。
- 关闭状态不参与完整性判断，也不显示为缺失。

### 8.3 运行时判定

运行端分别生成 `piece`、`kind` 和 `product_piece` 约束。一次加菜操作统一评估所有适用约束；任一约束失败则整次操作失败，不允许部分接受。

返回结构使用 `violations[]`，而不是只返回一个模糊错误。每项至少包含：

```text
code: DISH_SET_PIECE_LIMIT_EXCEEDED |
      DISH_SET_KIND_LIMIT_EXCEEDED |
      SAME_DISH_LIMIT_EXCEEDED
metric: piece | kind | product_piece
sceneKey
targetKey
configuredLimit
candidateValue
```

同时违反多项时全部返回，展示顺序固定为商品份数保护、按种、按份，避免客户端因遍历顺序产生不同主提示。兼容层可把前两项映射为旧 `TARGET_LIMIT_EXCEEDED`，但新客户端必须读取 `violations[]`。

超限授权按 `ruleId + ruleVersion + metric + sceneKey + targetKey + approvedLimit` 定位：按份和按种共享约束的 `targetKey` 固定为 `dish_set:${ruleId}`；商品保护的 `targetKey` 为 `productLineId:dishId`。授权某一项只覆盖该项，不得顺带放行另一项；一次操作同时违反按份和按种时，必须同时具备两项有效授权。最低值及参数错误仍不可授权。

超限提示应指出具体触发项，例如：

- “已达到本场景每人每轮 5 份上限。”
- “已达到本场景整桌每轮 8 种（SPU）上限。”
- “单锅已达到每人每轮 2 份上限。”

## 9. 模板与默认规则影响

10 个常用模板不包含独立的“菜品集按份模板/按种模板”，也不初始化计量。它们只设置主体和周期结构；限购对象仍由用户选择。用户选择菜品集后，新建的首个场景默认开启按份以延续当前默认体验，之后可以按场景增加按种。按场景修改计量属于额度内容，不单独触发 `buffetTemplateModified`；只有原有模板结构字段被修改时才沿用既有规则标记模板已调整。

C2～C6 属于 18 个系统默认规则，不是 10 个常用模板。C2/C5 入口初始只开启按份，C3/C6 入口初始只开启按种。18 个系统默认规则的目录身份暂不合并或删除：若用户在配置额度中开启第二种计量，该草稿转为普通规则并清除 `defaultScenarioKey/defaultCatalogVersion`，避免原默认目录名称与实际双计量不一致；此变化不使用 `buffetTemplateModified` 表达。后续如要合并默认目录，应单独设计迁移，不纳入本次范围。

## 10. 不在本次范围

- 不让菜品或分类支持按种。
- 不按就餐人分别记录实名消费；人均上限仍按有效人数换算为桌级执行额度。
- 不在按种下新增第二套商品级“每种最多”字段。
- 不自动推导按份和按种之间的等价值。
- 不改变参与门店、商品选择器及跨门店商品加入规则。

| DM-04 | 同场景开启 5 份＋3 种 | 两类约束同时生成；达到上限允许，任一超过均拦截 |
| DM-05 | 牛肉从 1 份加到 2 份 | 份数加 1，种数不变 |
| DM-06 | 新增第四种商品 | 即使份数未满，3 种上限仍拦截 |
| DM-07 | 两种计量同时关闭 | 页面阻止并提示至少保留一种 |
| DM-08 | 关闭已有按种额度后取消确认 | 开关和原值保持不变 |
| DM-09 | 确认关闭已有按种额度 | 只清除当前场景按种值，按份和商品值保留 |
| DM-10 | 按份批量设置选择“不处理按种” | 所选场景按种值保持不变 |
| DM-11 | 复制双计量场景 | 目标获得独立副本，修改来源不联动 |
| DM-12 | 打开旧按份规则 | 仅开启按份，原额度与商品保护完整保留 |
| DM-13 | 打开旧按种规则 | 仅开启按种，原额度与商品保护完整保留 |
| DM-14 | 全部配置筛选“按份＋按种” | 只显示同时开启两种计量的场景 |
| DM-15 | 商品表展示双计量场景 | 每行仍只有一套商品最多份数输入 |
| DM-16 | 显式配置额度 0 | 状态显示禁止下单，运行时拒绝对应范围商品 |
| DM-17 | 两个已启用计量之一未填写任何额度 | 当前场景保持未配置，发布检查定位该场景与计量 |
| DM-18 | 组合周期在不同轮次启用不同计量 | 各轮次只执行自身场景保存的计量组合 |
| DM-19 | 同产线同 `dishId` 的两个规格均有数量 | 合并为一个 `kindKey`，只计 1 种 |
| DM-20 | 同名商品来自不同产线或不同 `dishId` | 分别计种，不按名称或上游 SPU 合并 |
| DM-21 | 商品数量从 1 减到 0 | 释放一种；负向操作不得产生负数 |
| DM-22 | C2/C3/C5/C6 旧规则迁移 | X、P、场景稳定键和单位均无损，重复打开不再次迁移 |
| DM-23 | 整单＋分轮次旧组合迁移 | 各周期、人数和轮次区间分别保留，未用数组下标重建键 |
| DM-24 | 双计量草稿由旧客户端编辑或发布 | 返回 409 和能力错误，不降级、不覆盖 |
| DM-25 | 一次操作同时超过按份和按种 | `violations[]` 同时返回两项，顺序稳定，整批拒绝 |

## 12. 权威文档同步要求

实施时必须同步更新《自助餐规则场景配置融合设计》中以下内容，使其成为最终权威口径：

- 第一步字段表：移除菜品集全局计量方式。
- 份、种与商品保护定义：补充同场景双计量共同生效。
- 数据清理表：把“按份/按种切换”改为场景计量开关的局部清理。
- 数量字段出现规则、组合模板、默认规则目录和冲突规则。
- 数据模型：以场景级 `measures.piece/kind` 替代规则级唯一 `measureUnit`。
- QA 用例：替换单选切换用例并加入本设计 DM-01～DM-18。

在权威文档完成同步前，不应把本方案视为已完成实施。
