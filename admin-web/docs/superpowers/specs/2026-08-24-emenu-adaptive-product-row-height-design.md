# eMenu 自适应商品行高设计

> 状态：最终确认、已实施、已完成真实菜单验收
>
> 权威范围：eMenu 普通小尺寸商品卡片的标题、标签、价格/操作区、同行等高及虚拟列表行高
>
> 最后确认日期：2026-08-24

## 背景

eMenu 小尺寸商品卡片原先为标题和内容区设置固定高度。即使一行中的所有商品都只有一行标题，标题区域仍保留第二行空白；同时 `TextTags` 在没有标签时仍以 `visibility: hidden` 渲染固定 `18px` 高度和 `8px` 上边距，额外形成约 `26px` 的隐藏标签占位。这两类无内容间距导致标题与价格之间出现明显空白，菜单纵向密度偏低。

商品列表列数不是固定值。现有列表根据 `viewport.columns` 自适应；常见验收列数为每行 2、3、4 个商品，横屏当前最多可达到 6 列。因此方案不能依赖固定列数或按商品索引手动分组。

## 目标

- 不展示没有内容的标题或标签占位间距。
- 同一视觉行中的商品卡片保持等高，价格和操作按钮保持底部对齐。
- 每一视觉行只由该行真实内容最多的商品决定高度。
- 支持 `viewport.columns` 当前允许的全部列数（重点覆盖 2、3、4 列及横屏 6 列），以及视口变化后的自动重新分行。
- 保持现有图片尺寸、字体、配色、卡片宽度、列数算法和业务交互不变。

## 非目标

- 不修改大尺寸商品卡片布局。
- 不调整商品图片比例或高度。
- 不改变标题最多两行的截断规则。
- 不改变标签、价格、会员价、划线价或数量操作的业务显示条件。
- 不逐商品测量，也不按列数在组件中重复计算商品分组。

## 方案选择

### 方案 A：固定两行标题占位

保持当前固定高度。对齐稳定，但全为一行标题时仍存在无意义空白，不能达到目标。

### 方案 B：按视觉行取最大实际高度（采用）

取消卡片内部的固定标题占位和固定内容区最小高度，让标题按真实的一行或两行高度参与布局。商品列表继续使用 CSS Grid；Grid 根据当前列数自动形成视觉行，并把同一行卡片拉伸到该行最高卡片的高度。卡片内部使用纵向 Flex，使价格和操作区域贴底。

卡片内部无需感知当前列数。由于外层使用 `VariableSizeList` 且每个视觉行是一个虚拟列表项，需要用 `ResizeObserver` 测量已经渲染的视觉行容器，将其真实高度同步给虚拟列表。视口变化后，Grid 自动重新排版，观察器再更新对应虚拟行高度。

### 方案 C：每张卡片独立高度

每张卡片完全按自身内容收缩。空间最紧凑，但同一行价格、按钮和卡片底部不对齐，视觉节奏不稳定，不采用。

## 视觉与交互规则

### 标题

- 标题最多显示两行，超出部分沿用现有省略规则。
- 标题容器不预留固定两行高度。
- 一行标题只占一行真实高度；两行标题占两行真实高度。

### 标签与组合菜图标

- `displayTextLabels.length === 0` 且 `showCombinationIcon === false` 时，整个 `textTagsWrapper` 不渲染，高度为 `0`，不保留 margin、隐藏节点或空白行。
- 存在至少一个文本标签、折扣标签或组合菜图标时，标签区域正常渲染并作为真实内容参与本行高度计算。
- 文本标签由 `displayTextLabels` 统一提供：包括 `allTextLabel`，以及存在 `strikethDiscount` 时生成的折扣标签。
- 组合菜图标由 `showCombinationIcon` 控制；只有配置开启、当前商品属于组合菜 A 侧、B 侧有商品且数量大于 0 时显示。
- 不修改共享 `TextTags` 组件的全局空值行为，避免改变大卡片或其他调用方；空标签消除只在小商品卡片入口完成。

### 同一视觉行

- 当本行标题全部为一行且没有其他额外内容时，整行减少一行标题的高度。
- 当本行至少有一个两行标题时，该商品决定本行所需标题高度。
- 其他一行标题商品随 Grid 等高，但价格与操作区贴底，不在标题节点中渲染空白占位。
- 标签、组合菜图标、会员价、划线价等已展示的真实内容可以自然增加本行高度；未展示内容不得保留布局占位。

### 自适应列数

- 每行 2 个商品时，每 2 个实际排在同一视觉行的商品共同决定该行高度。
- 每行 3 个商品时，每 3 个实际排在同一视觉行的商品共同决定该行高度。
- 每行 4 个商品时，每 4 个实际排在同一视觉行的商品共同决定该行高度。
- 其他列数（包括横屏 6 列）同样按浏览器实际形成的视觉行计算，不新增专用分支。
- 最后一行不足当前列数时，只在剩余商品之间计算行高。
- 调整视口导致列数变化时，由 CSS Grid 自动重新分行和计算行高。
- 虚拟列表项高度随重新排版后的 Grid 行真实高度更新，滚动偏移随之校正。

### 价格与操作

- 价格和数量操作区域位于卡片内容区底部。
- 同一视觉行中的价格与操作按钮保持底部对齐。
- 隐藏价格时不渲染价格文字占位；操作区域仍按现有规则展示并贴底。
- 隐藏价格时，数量/详情操作区域保持在右侧，不因移除价格占位而左移。

## 字段与派生状态定义

| 字段/状态 | 来源 | 布局含义 |
| --- | --- | --- |
| `viewport.columns` | `EmenuViewportContext` / `resolveEmenuGrid` | 当前 Grid 列数；决定哪些商品属于同一视觉行，不由卡片组件自行计算。 |
| `viewport.gap` | `EmenuViewportContext` | 商品横向间距，同时作为相邻虚拟商品行的纵向间距；在 `itemSize` 中只追加一次。 |
| `name` / 翻译标题 | 商品数据与 i18n | 最多两行；按真实一行或两行高度参与布局。 |
| `allTextLabel` | 商品标签数据 | 真实文本标签来源；空数组不得产生标签行。 |
| `strikethDiscount` | 划线价折扣派生数据 | 非空时转换为一项文本标签并加入 `displayTextLabels`。 |
| `displayTextLabels` | `SmallContent` 派生 | `allTextLabel` 与折扣标签的合并结果；长度大于 0 才需要文本标签区域。 |
| `showCombinationIcon` | 组合菜配置派生 | 是否显示组合菜星标；为真时即使没有文本标签，也属于真实标签行内容。 |
| `isShowPrice` | 价格显示策略 | 为假时价格节点不参与布局；操作区仍靠右贴底。 |
| `showPrice` | 价格展示派生值 | 普通价格主行内容。 |
| `isHasBenefitPrice` / `benefitPrice` | 会员价策略 | 存在时作为真实附加价格内容增加本行高度。 |
| `strikethroughPrice` | 商品划线价 | 满足既有显示条件时作为真实价格内容增加本行高度。 |
| `rowSize[index]` | 虚拟列表本地状态 | 对应视觉行最终交给 `VariableSizeList` 的高度。 |
| `isLargeRow` | `virtualListData` | 标记包含大卡片的视觉行；该行通常由大卡片真实高度决定。 |

### 混合大卡片与小卡片

- 现有分行逻辑允许一个大卡片与若干小卡片处于同一 Grid 行，大卡片占两列。
- 混合行由该行最高的真实卡片决定虚拟行高度，通常由大卡片决定；该行不承诺获得与纯小卡片行相同的压缩效果。
- 小卡片仍填满所在 Grid 轨道，内部价格和操作区贴至卡片底部。
- 不修改大卡片内部布局、尺寸或业务行为。

## 实现结构

涉及区域：

- `vendor/emenu-new/src/components/DishItemCard/SmallContent.module.less`
- `vendor/emenu-new/src/components/DishItemCard/SmallContent.jsx`
- `vendor/emenu-new/src/components/DishItemCard/index.jsx`（仅在外层高度传递需要时调整样式）
- `vendor/emenu-new/src/components/RightContent/index.jsx`
- `vendor/emenu-new/src/components/OldOrderPage/RightContent.jsx`（如果该旧入口仍共享同一商品卡片行为，则同步虚拟行高策略）

样式结构：

1. 保留商品列表现有的 `gridTemplateColumns: repeat(viewport.columns, minmax(0, 1fr))`。
2. Grid 内的商品子项包装层、`DishItemCard` 小卡片根节点、`SmallContent`、`contentOuterWrapper` 和 `contentArea` 建立明确的 `height: 100%`/纵向 Flex 高度传递链；相关节点使用兼容现有全局设置的 `box-sizing: border-box`，确保 padding 不额外撑破测量高度。这条高度链只存在于内层 Grid 及卡片之间，不得连接到 `react-window` 的估算高度。
3. 内容区改为纵向 Flex，并移除固定 `151px` 高度和最小高度。
4. 标题行移除固定 `48px` 高度，保留最多两行截断。
5. 价格操作行通过自动上边距贴至内容区底部。
6. 标签行仅在 `showCombinationIcon || displayTextLabels.length > 0` 时渲染；条件为假时连同 `textTagsWrapper` 一起省略。
7. `isShowPrice` 为假时不再用 `visibility: hidden` 保留价格节点高度；价格节点不渲染或不参与布局，操作区域使用 `margin-left: auto` 保持右侧位置。
8. 每个 `cateList` 使用两层容器：外层仅接收并保留 `react-window` 提供的绝对定位 `style`（其中包含当前 `itemSize` 高度）；内层是无固定高度、无 `height: 100%`、不继承外层估算高度的 Grid 内容包装层。`ResizeObserver` 只观察内层包装层，读取其内容自然撑开的真实块尺寸，禁止观察外层虚拟定位节点。
9. 最终 `itemSize` 定义为 `Math.ceil(内层 Grid 实测高度) + viewport.gap`。`viewport.gap`（当前默认 16px）同时作为商品横向间距和相邻商品视觉行的纵向间距，仅在虚拟行高度中追加一次；内层包装层不得再设置底部 margin/padding，外层也不得重复追加行间距。分类标题行和火锅特殊行沿用各自既有高度规则。
10. 更新行高后调用 `listRef.current.resetAfterIndex(rowIndex)`，使 `VariableSizeList` 重算当前行及后续行偏移。
11. 首次渲染仍提供安全的估算高度，测量完成后替换为真实高度，避免 `itemSize` 未定义；估算值不能作为稳定最终高度。估算 `style.height` 写入后应触发一次重新测量，避免初次测量早于 `rowSize` 初始化。
12. `viewport.columns`、`viewport.gap`、字体/语言、商品内容、标签或价格显示状态变化导致尺寸变化时，由观察器更新；列数变化仍沿用现有分类定位恢复逻辑。
13. 组件卸载、虚拟行复用或观察目标变化时必须断开旧观察器，避免监听泄漏和把高度写入错误索引。
14. 不添加逐商品 DOM 高度读取，也不在渲染组件中重新实现 `virtualListData` 的按列数分组。

## 边界与降级

- 标题超过两行时继续截断，不允许无限撑高卡片。
- 标签、组合菜图标、会员价或划线价出现时，以真实渲染高度为准。
- 无文本标签且无组合菜图标时，标签容器必须完全不存在；不得改回 `visibility: hidden`、固定高度或空数组占位。
- 内容差异较大的商品同处一行时，短内容卡片的弹性空间位于标题/标签与底部操作区之间。
- 大、小卡片混合行按本行最高真实卡片设置虚拟行高；纯小卡片行才体现一行标题带来的主要压缩收益。
- CSS Grid 不可用不属于支持场景；当前 eMenu 运行环境已经依赖 Grid。
- 不改变点击处理、禁用态、售罄遮罩或数量按钮的命中区域。
- 行高测量值相同时不更新状态；观察器回调不得形成尺寸—状态更新循环。

## 验收方案

### 布局组合

在每行 2、3、4 个商品下分别验证，并在横屏 6 列下补充回归：

- 全部一行标题。
- 一行与两行标题混合。
- 全部两行标题。
- 标题超过两行并被截断。
- 最后一行不足当前列数。
- 大卡片与小卡片混合的视觉行。
- 无标签、仅文本标签、仅组合菜图标、文本标签与组合图标同时存在。

### 内容组合

覆盖普通价格、会员价、划线价、标签、组合菜图标、隐藏价格、详情按钮和数量操作按钮。确认真实内容可以撑高本行，同时不存在隐藏内容占位；隐藏价格时操作区域仍靠右。

### 响应式行为

连续调整 eMenu 视口，使列数在 2、3、4 之间变化，并在横屏 6 列回归，确认：

- 商品自动重新分行。
- 每行高度按新的同行商品重新计算。
- 最后一行不继承上一行高度。
- 图片、标题截断、卡片间距和滚动行为保持稳定。
- 快速连续缩放时没有卡片重叠、裁切、明显跳动或无限更新。

### 虚拟滚动与分类定位

使用一行标题、两行标题、价格/标签高度不同以及大/小卡片混合的数据验证：

- 行与行之间不存在由旧 `310px`/`400px` 最终高度造成的多余空白。
- 各虚拟行之间不重叠、不裁切，滚动条总高度与实际内容一致。
- 从顶部和底部快速滚动时，虚拟行复用后高度仍对应正确索引。
- 点击左侧分类、程序化 `scrollToItem` 和滚动联动更新分类均定位正确。
- 列数切换后重置偏移并恢复当前分类位置，不跳转到错误分类。

## 成功标准

- 全为一行标题的视觉行不再保留第二行标题空白。
- 无标签且无组合菜图标的商品不渲染标签行，标签区域实测高度为 `0`。
- 存在两行标题时，同一视觉行卡片等高，价格和操作区底部对齐。
- 存在真实标签或组合菜图标时正常展示，并参与同行高度计算。
- 2、3、4、6 列及列数切换均可正确重新测量和更新虚拟滚动偏移。
- 没有业务行为、图片尺寸或其他菜单样式回归。
