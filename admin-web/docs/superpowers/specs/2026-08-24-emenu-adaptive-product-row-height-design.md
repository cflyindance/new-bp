# eMenu 自适应商品行高设计

## 背景

eMenu 小尺寸商品卡片目前为标题和内容区设置固定高度。即使一行中的所有商品都只有一行标题，标题区域仍保留第二行空白，导致标题与价格之间出现明显的无内容间距，菜单纵向密度偏低。

商品列表列数不是固定值。现有列表根据 `viewport.columns` 自适应为每行 2、3 或 4 个商品，因此方案不能依赖固定列数或按商品索引手动分组。

## 目标

- 不展示没有内容的标题占位间距。
- 同一视觉行中的商品卡片保持等高，价格和操作按钮保持底部对齐。
- 每一视觉行只由该行真实内容最多的商品决定高度。
- 支持每行 2、3、4 个商品，以及视口变化后的自动重新分行。
- 保持现有图片尺寸、字体、配色、卡片宽度、列数算法和业务交互不变。

## 非目标

- 不修改大尺寸商品卡片布局。
- 不调整商品图片比例或高度。
- 不改变标题最多两行的截断规则。
- 不改变标签、价格、会员价、划线价或数量操作的业务显示条件。
- 不引入 JavaScript DOM 测量或按列数计算商品分组。

## 方案选择

### 方案 A：固定两行标题占位

保持当前固定高度。对齐稳定，但全为一行标题时仍存在无意义空白，不能达到目标。

### 方案 B：按视觉行取最大实际高度（采用）

取消卡片内部的固定标题占位和固定内容区最小高度，让标题按真实的一行或两行高度参与布局。商品列表继续使用 CSS Grid；Grid 根据当前列数自动形成视觉行，并把同一行卡片拉伸到该行最高卡片的高度。卡片内部使用纵向 Flex，使价格和操作区域贴底。

该方案无需感知当前是 2、3 还是 4 列，也无需运行时测量，浏览器在视口变化后会自动重新计算每一行的高度。

### 方案 C：每张卡片独立高度

每张卡片完全按自身内容收缩。空间最紧凑，但同一行价格、按钮和卡片底部不对齐，视觉节奏不稳定，不采用。

## 视觉与交互规则

### 标题

- 标题最多显示两行，超出部分沿用现有省略规则。
- 标题容器不预留固定两行高度。
- 一行标题只占一行真实高度；两行标题占两行真实高度。

### 同一视觉行

- 当本行标题全部为一行且没有其他额外内容时，整行减少一行标题的高度。
- 当本行至少有一个两行标题时，该商品决定本行所需标题高度。
- 其他一行标题商品随 Grid 等高，但价格与操作区贴底，不在标题节点中渲染空白占位。
- 标签、会员价、划线价等已展示的真实内容可以自然增加本行高度。

### 自适应列数

- 每行 2 个商品时，每 2 个实际排在同一视觉行的商品共同决定该行高度。
- 每行 3 个商品时，每 3 个实际排在同一视觉行的商品共同决定该行高度。
- 每行 4 个商品时，每 4 个实际排在同一视觉行的商品共同决定该行高度。
- 最后一行不足当前列数时，只在剩余商品之间计算行高。
- 调整视口导致列数变化时，由 CSS Grid 自动重新分行和计算行高。

### 价格与操作

- 价格和数量操作区域位于卡片内容区底部。
- 同一视觉行中的价格与操作按钮保持底部对齐。
- 隐藏价格时不渲染价格文字占位；操作区域仍按现有规则展示并贴底。

## 实现结构

涉及区域：

- `vendor/emenu-new/src/components/DishItemCard/SmallContent.module.less`
- 如验证发现外层未提供完整高度传递，可最小范围调整 `SmallContent.jsx` 或 `DishItemCard/index.jsx` 的容器样式；不得加入行分组测量逻辑。

样式结构：

1. 保留商品列表现有的 `gridTemplateColumns: repeat(viewport.columns, minmax(0, 1fr))`。
2. 让小卡片根节点及内容外层能够填满 Grid 单元格高度。
3. 内容区改为纵向 Flex，并移除固定 `151px` 高度和最小高度。
4. 标题行移除固定 `48px` 高度，保留最多两行截断。
5. 价格操作行通过自动上边距贴至内容区底部。
6. 不添加 `ResizeObserver`、DOM 高度读取或基于 `viewport.columns` 的 JavaScript 分组。

## 边界与降级

- 标题超过两行时继续截断，不允许无限撑高卡片。
- 标签、组合菜图标、会员价或划线价出现时，以真实渲染高度为准。
- 内容差异较大的商品同处一行时，短内容卡片的弹性空间位于标题/标签与底部操作区之间。
- CSS Grid 不可用不属于支持场景；当前 eMenu 运行环境已经依赖 Grid。
- 不改变点击处理、禁用态、售罄遮罩或数量按钮的命中区域。

## 验收方案

### 布局组合

在每行 2、3、4 个商品下分别验证：

- 全部一行标题。
- 一行与两行标题混合。
- 全部两行标题。
- 标题超过两行并被截断。
- 最后一行不足当前列数。

### 内容组合

覆盖普通价格、会员价、划线价、标签、组合菜图标、隐藏价格、详情按钮和数量操作按钮。确认真实内容可以撑高本行，同时不存在隐藏内容占位。

### 响应式行为

连续调整 eMenu 视口，使列数在 2、3、4 之间变化，确认：

- 商品自动重新分行。
- 每行高度按新的同行商品重新计算。
- 最后一行不继承上一行高度。
- 图片、标题截断、卡片间距和滚动行为保持稳定。

### 构建与浏览器验证

修改 `vendor/emenu-new` 后必须从项目根目录执行：

```bash
npm run build:emenu-new-embed -- --skip-install
```

构建成功后检查：

1. `dist/emenu-new/index.html` 引用本次生成的哈希资源。
2. `dist/emenu-new/.emenu-embed-build.json` 存在，且 `builtAt` 为本次构建时间。
3. 构建命令成功退出。

浏览器验证前重新加载 eMenu iframe；若仍加载旧资源，执行强制刷新后再验证。

## 成功标准

- 全为一行标题的视觉行不再保留第二行标题空白。
- 存在两行标题时，同一视觉行卡片等高，价格和操作区底部对齐。
- 2、3、4 列及列数切换均无需额外脚本即可正确工作。
- 没有业务行为、图片尺寸或其他菜单样式回归。
