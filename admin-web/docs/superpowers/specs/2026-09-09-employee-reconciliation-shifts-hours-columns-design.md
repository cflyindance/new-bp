# 员工对账“班次 / 工时”字段拆分设计

## 目标

将员工对账中的组合字段“班次 / 工时”统一拆成两个平级字段“班次”和“工时”，提高横向比较、导出分析和字段语义的清晰度。此次调整只改变展示与导出结构，不改变考勤、小费计算、筛选或状态逻辑。

## 范围

涉及以下原生小费管理界面与输出：

- 员工对账汇总列表。
- 员工对账明细的逐日列表。
- 员工对账 CSV 导出。
- 员工对账 PDF 导出及打印回退页面。
- 员工对账邮件内容或邮件预览中复用的导出字段。

日期任务视图、日期任务详情、小费池计算与分配规则不在本次变更范围内。

## 界面设计

### 员工对账汇总

表头由：

`员工｜角色｜班次 / 工时｜分配前｜扣除｜分配获得｜实际获得｜状态｜操作`

调整为：

`员工｜角色｜班次｜工时｜分配前｜扣除｜分配获得｜实际获得｜状态｜操作`

- 班次显示整数与单位，例如 `6 个班次`。
- 工时沿用现有格式化规则，例如 `43.5 h`。
- 两列均为独立单行值，不再使用主次双行结构。

### 员工对账明细

表头由：

`日期｜考勤｜班次 / 工时｜分配前｜扣除｜分配获得｜实际获得｜分配状态`

调整为：

`日期｜考勤｜班次｜工时｜分配前｜扣除｜分配获得｜实际获得｜分配状态`

- 当日有有效工时：班次显示 `1 个班次`，工时显示格式化小时数。
- 当日无有效工时：班次显示 `—`，工时显示 `0 h`。
- 顶部汇总卡片中现有“班次”和“总工时”已经分离，保持不变。

## 数据与导出

- 汇总列表继续读取现有聚合对象的 `shifts` 和 `hours`。
- 明细列表继续读取逐日记录的工时，并沿用当前“工时大于 0 即计 1 个班次”的演示规则。
- 导出数据模型由组合字符串 `shiftHours` 调整为两个字段：`shifts`、`hours`。
- CSV、PDF、打印回退及邮件预览中的表头和行数据同步拆分。
- 金额、考勤状态、分配状态及日期筛选范围不做任何修改。

## 布局策略

- 新增一列后，优先压缩角色、状态、操作及金额列的空白，不压缩员工姓名的可读性。
- 桌面端维持单行表格；较窄视口允许表格容器横向滚动，不将两个字段重新合并。
- 班次与工时采用与现有数值列一致的字号和对齐方式。

## 异常与兼容

- `shifts` 或 `hours` 缺失时按现有数值格式化策略回退为 `0`。
- 明细无工时时，班次必须显示 `—`，避免误解为存在零时长班次。
- 不迁移、不重算现有本地存储数据。

## 验收标准

1. 员工对账汇总表存在独立“班次”“工时”表头及单独单元格。
2. 员工对账明细表存在独立“班次”“工时”表头及单独单元格。
3. 无工时明细显示班次 `—`、工时 `0 h`。
4. CSV、PDF、打印回退与邮件相关输出均不再出现“班次 / 工时”组合字段。
5. 日期筛选、考勤筛选、员工跳转、金额与状态数据保持原行为。
6. 原生小费管理专项回归与生产构建通过。
