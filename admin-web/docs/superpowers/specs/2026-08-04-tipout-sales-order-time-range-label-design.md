# TipOut 销售额取值条件“订单时间段”文案设计

## 目标

在“团队管理 → 小费管理 → 新增小费规则”页面中，将普通销售额和计提小费接受方销售额的取值条件术语从“营业时间”统一为“订单时间段”。

## 变更范围

- 仅修改 `dist/TipOut/rule-add.html`。
- 覆盖普通销售额取值条件：新增条件菜单、条件卡标题和保存后的规则摘要。
- 覆盖计提小费接受方销售额取值条件：新增条件菜单、条件卡标题和保存后的规则摘要。
- 修改当前文件中属于上述两个销售额分支的 7 个用户可见“营业时间”字面量：2 个菜单项、2 个条件类型名称映射、2 个时间输入标签和 1 个共享摘要标签。

## 与现有规格的关系

本设计扩展 `2026-08-04-tipout-order-time-range-label-design.md` 的页面文案统一范围。该现有规格曾明确保留销售额和 Tip Claim 销售额的“营业时间”术语；本设计以用户后续确认的新需求为准，同时覆盖并替代旧规格“不变范围”中保留销售额术语的条款，以及旧规格“验证”中要求“营业时间”字面量不被替换的子断言。旧规格的其余范围和验证要求继续有效。

## 不变范围

- 内部条件类型和字段名继续使用 `hours`。
- 起止时间继续使用 `{ start, end }` 数据结构。
- 不修改条件收集、回填、校验、保存、筛选或计算逻辑。
- 不修改销售额以外的“营业时间”文案。
- 不修改详情页、规则列表页或其他模块。

## 实现方式

精确替换两个销售额分支的 7 个用户可见字面量，不抽取新常量、不重构现有函数。普通销售额与计提销售额继续共用现有摘要格式化逻辑，只将摘要前缀改为“订单时间段”。

## 验证

1. 静态搜索确认上述 7 个销售额相关“营业时间”字面量均已替换为“订单时间段”。
2. 检查文件差异，确认 `hours`、`hours.start`、`hours.end` 和控制流未发生变化。
3. 在普通销售额分支打开取值条件，确认菜单、条件卡标题和保存摘要均显示“订单时间段”。
4. 在计提小费接受方销售额分支执行同样的新增、输入起止时间和保存操作，确认三处文案一致。
5. 确认两个分支保存后仍输出原有 `hours: { start, end }` 数据结构，已有规则也能正常回填。
