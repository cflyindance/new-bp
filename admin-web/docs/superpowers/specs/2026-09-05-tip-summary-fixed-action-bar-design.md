# 小费分配汇总固定操作栏设计

## 背景与目标

小费分配汇总当前将“取消分配”“导出结果”“分配小费”放在页面顶部。列表较长时，用户需要回到顶部才能继续操作。本次仅调整原生页面的入口位置和不同汇总视图下的导出对象，不改变取消分配、分配小费、规则管理等既有业务逻辑。

## 已确认范围

- 仅修改原生小费管理页面，不修改旧 TipOut 项目。
- 页面顶部标题区仅保留“新建/查看规则”。
- 使用一条共用的固定底部操作栏，并根据当前汇总视图切换可见操作。
- 日期任务模式展示“取消分配”“导出结果”“分配小费/重新分配小费”。
- 员工对账模式仅展示“导出结果”。
- 保留导出结果现有的 PDF、CSV、邮箱三种方式。

## 页面布局

固定操作栏位于原生小费汇总内容区底部，固定在当前可视窗口中。操作按钮右对齐，延续当前按钮顺序和视觉层级：

1. 取消分配（次要按钮）
2. 导出结果（次要按钮及格式菜单）
3. 分配小费或重新分配小费（主要按钮）

员工对账模式下，仅保留右侧的“导出结果”。内容区增加与操作栏高度匹配的底部留白，确保最后一行列表数据不会被遮挡。

“新建/查看规则”继续位于标题栏右侧，其跳转和无规则判断逻辑不变。

## 视图状态与操作显示

页面继续以现有 `activeSummaryView` 作为视图状态来源：

| 当前视图 | 取消分配 | 导出结果 | 分配小费 |
| --- | --- | --- | --- |
| 日期任务 | 显示 | 显示 | 显示 |
| 员工对账 | 隐藏 | 显示 | 隐藏 |

切换视图时由现有 `syncSummaryViewUi()` 统一同步列表面板和固定操作栏，不创建两套相互独立的操作栏。首次加载、带员工视图参数的深链、历史返回和页面恢复也必须经过同一同步入口，避免操作按钮与当前视图不一致。

员工对账模式隐藏角色和员工筛选控件。员工对账列表与员工对账导出共用仅按日期范围和门店生成的员工数据源，不经过日期任务的角色/员工筛选。切回日期任务时恢复并继续使用切换前的角色和员工筛选值，不清空用户选择。

## 导出行为

### 日期任务

保留日期任务现有逐日分配结果的数据结构和格式生成逻辑，但修正数据收集范围。导出范围以页面当前选择的开始日期、结束日期、门店、角色和员工筛选条件为准。只有已产生分配结果的日期进入导出；待分配日期没有分配结果，不进入导出。PDF、CSV、邮箱三种入口使用相同范围。

### 员工对账

新增员工对账汇总数据收集入口，数据来源与当前员工对账列表一致：

- 使用当前选择的开始日期、结束日期和门店。
- 员工对账模式不展示角色和员工筛选条件，因此忽略之前在日期任务中选中的角色/员工值，导出当前员工对账列表中去重后的全部员工。
- 不导出日期任务逐日记录。
- 字段与员工对账列表保持一致，包括员工、角色、班次/工时、分配前、扣除、分配获得、实际获得和状态。
- PDF、CSV、邮箱三种入口均使用员工对账汇总数据。

点击“导出结果”时，根据 `activeSummaryView` 决定使用日期任务导出数据还是员工对账导出数据：

- 日期任务继续使用逐日明细导出契约。
- 员工对账使用独立的汇总导出契约和格式化分支，列名依次为员工、角色、班次/工时、分配前、扣除、分配获得、实际获得、状态；PDF 和 CSV 均将班次与工时合并为一个字段，格式为“6 个班次 / 43.5 h”；金额展示格式与页面列表保持一致，文件标题和文件名明确标识“员工对账”。
- PDF 和 CSV 在用户选择格式时采集当前视图和当前筛选的数据。
- 邮箱在用户点击发送时重新采集当前视图和当前筛选的数据，并使用对应视图的数据集；弹窗打开后发生的视图或筛选变化，以发送时状态为准。
- 对应数据集为空时，PDF、CSV 和邮箱均沿用统一的空数据提示，不生成或发送空结果。

既有文件下载和邮箱弹窗交互保持不变，仅为员工对账增加对应的数据契约和生成分支。

## 业务逻辑保护

- 取消分配仍直接调用现有取消分配处理函数，处理范围和副作用不变。
- 分配小费仍调用现有时间和门店选择对话框；按钮文案仍由当前分配状态决定。
- 规则入口、规则数量判断及页面跳转不变。
- 不改变现有分配结果、金额计算、状态判断和数据持久化方式。

## 异常与边界状态

- 当前导出范围无数据时，沿用现有空数据提示，不生成空文件。
- 导出菜单在视图切换、页面点击其他区域或开始导出后关闭，避免悬浮菜单残留。
- 页面宽度较小时操作栏允许保持右对齐并适当换行，但不得遮挡页面内容。
- 员工对账列表中的同一员工只导出一条汇总记录。

## 验收标准

1. 三个日期任务操作按钮不再出现在标题区，且固定显示在页面底部。
2. 日期任务模式显示三个操作，员工对账模式只显示导出结果。
3. 长列表滚动到底部时，最后一行不被操作栏遮挡。
4. 日期任务导出严格使用当前日期范围及已有筛选条件，且只包含已产生分配结果的日期。
5. 员工对账导出严格使用当前日期范围、门店和当前去重员工列表。
6. PDF、CSV、邮箱在两种视图下均使用对应视图的数据集。
7. 取消分配、分配小费和新建/查看规则的既有业务流程无回归。
8. 直接打开员工对账视图、历史返回及页面恢复后，操作栏均只显示导出结果；切换视图时已打开的导出菜单会关闭。
9. 日期范围非法、范围内全部待分配或员工对账列表为空时，不生成或发送空结果。
10. 员工按稳定员工 ID 去重，同名但 ID 不同的员工分别保留。
11. 窄屏以及应用侧栏展开、收起状态下，固定操作栏均不遮挡列表和主要导航。
