# 菜单路由服务与权限关联选择设计

## 背景

菜单路由编辑器已将“服务名称”和“功能权限”合并为“服务与权限”，但当前弹窗把服务和权限作为两个互不关联的列表展示，用户无法判断某项功能权限属于哪个服务。

本次调整只改善可视化配置关系，不改变参考 JSON 的字段结构，也不负责旧数据迁移。

## 目标

- 明确展示每个服务订阅及其所属功能权限。
- 同时支持服务多选和权限多选。
- 保持现有 JSON 字段和导出格式不变。
- 编辑菜单时能根据当前文档中的已有配置自动归纳服务与权限关系。

## 交互方案

弹窗采用左右分栏结构：

- 左侧为服务列表，每个服务带复选框和已选权限数量。
- 右侧为当前服务对应的功能权限列表。
- 点击左侧服务名称只切换右侧当前服务，不改变勾选状态。
- 勾选左侧服务时，自动勾选该服务下的全部功能权限。
- 取消勾选左侧服务时，自动取消该服务下的全部功能权限。
- 右侧权限可以逐项取消或重新勾选。
- 服务复选框只表达该服务是否处于显式已选服务集合；权限选择程度通过旁边的 `0/N`、`部分`、`N/N` 数量状态表达，不用权限数量反向覆盖服务复选框。
- 新勾选左侧服务时自动全选权限；打开弹窗时若旧值已有服务但权限为空，则保留服务勾选并显示 `0/N`，不会因初始化而自动补齐权限。
- 服务状态与该服务自己的权限集合独立保存，不由其他服务的共享权限反向推导。
- 在右侧从零勾选某个服务的一项权限时，自动将该服务加入已选服务集合并显示半选；逐项清空该服务的最后一项权限时，自动将该服务移出已选服务集合。
- 多个服务包含同一权限时，各服务在弹窗内独立维护该权限的选择状态；保存时再合并为全局去重权限集合。取消一个服务只清空该服务自己的选择，不影响其他服务的选择。
- 所有服务都使用显式服务选择状态；没有关联权限的服务勾选后写入 `serviceName`，取消后移除。
- 弹窗“取消”不修改编辑草稿；“确定”才把本次选择写入右侧菜单编辑表单的草稿；最终仍需点击表单“确认写入”才修改菜单树。

### 权限列表排版

- 左侧服务订阅固定使用单列布局，每行只展示一个服务，所有视口均不切换为多列。
- 右侧当前服务的功能权限固定使用单列布局，每行只展示一个权限。
- “未归属权限”同样使用单列布局，保持弹窗内部扫描方式一致。
- 权限名称不因单列调整而截断；复选框、服务计数、选择状态和保存逻辑保持不变。
- 桌面与窄屏均使用一行一个权限，不在宽屏恢复双列。

## 关联关系归纳

编辑器遍历当前菜单文档中的所有节点，按以下规则构建服务权限目录：

1. 将 `accessControl.serviceName` 按英文逗号或中文逗号拆分为服务集合。
2. 读取同一节点的 `accessControl.permission.value` 作为权限集合。
3. 对该节点中的每个服务，都关联该节点的全部权限。
4. 合并所有节点的结果，并对服务名和权限值去重。
5. 当前编辑草稿中的服务和权限也加入目录，保证未在其他节点出现的已有值仍可反显。

参考 JSON 无法表达多服务节点中逐项权限的独立归属，因此多服务节点的权限视为这些服务共同拥有。这是仅使用原字段时唯一可稳定还原的规则。

## 数据写回

不新增任何 JSON 字段：

- 已选服务去重后，以英文逗号和空格连接，写入 `accessControl.serviceName`。
- 各服务的已选权限与未归属权限合并、去重后，写入 `accessControl.permission.value`。
- 权限存在时保持 `accessControl.permission.rule = "some"`。
- 服务为空时删除 `serviceName`；权限为空时删除 `permission`。
- `accessControl` 没有其他内容时，沿用现有清理逻辑删除空对象。

## 组件与状态

服务权限选择器使用弹窗内部临时状态，至少包含：

- 服务到权限集合的映射。
- 当前查看的服务。
- 已选服务集合。
- 每个服务各自的已选权限集合。
- 未归属权限的独立已选集合。

弹窗打开时从菜单编辑草稿初始化，弹窗关闭时丢弃临时状态，确定时才调用现有草稿写入逻辑。

初始化时，`serviceName` 中的每个服务都直接加入已选服务集合；权限集合按当前权限并集与服务目录的交集建立。服务即使拥有权限目录但交集为空，也保持显式选中。用户未操作直接确定时，必须原样保留该服务和空权限状态。

## 边界与异常处理

- 没有关联权限的服务仍可显示，并使用独立的服务选中状态，勾选后只产生 `serviceName`，不产生权限值。
- 当前草稿中存在无法归属的权限时，在右侧增加“未归属权限”分组，避免静默丢失；该分组不是新 JSON 字段。未归属权限可逐项勾选或取消，不参与任何服务的选中或半选计算，取消全部服务时仍予以保留，除非用户主动取消这些权限或点击清空。
- 服务或权限名称为空时不进入选择目录。
- 重复服务和重复权限只展示一次。
- 当文档中没有可归纳的数据时，继续使用现有参考值作为候选目录，并按已知共现关系组织；未知权限进入“未归属权限”。
- 由于导出结构只保存服务集合和权限并集，无法永久保存“共享权限只为某一个服务勾选”的细粒度状态。再次打开时，对每个已选服务使用“当前权限并集与该服务权限目录的交集”进行反显。该限制源自参考 JSON，不通过新增字段规避。

## 验证范围

- 单个服务全选、取消全选。
- 多个服务同时选择。
- 右侧逐项选择造成左侧半选状态。
- 多个服务共享权限时取消其中一个服务。
- 共享权限下取消一个服务后，该服务保持未选，另一个服务及其共享权限保持选中。
- 从零逐项选择权限时自动选择服务，逐项清空最后一项时自动取消服务。
- 共享权限在不同服务右侧的独立选择，以及保存时的权限并集去重。
- 没有关联权限服务的选择、取消、反显和写回。
- 有权限目录但旧值只有服务、没有权限时，显示服务已选和 `0/N`；无操作确定与导出往返仍保留服务且不自动新增权限。
- 仅有未归属权限、取消全部服务以及未归属权限主动清空。
- 已有单服务、已有多服务和未归属权限的反显。
- 清空、取消、确定与最终确认写入的状态边界。
- 弹窗关闭再打开、导出后重新导入的往返行为不丢失可由原 JSON 表达的数据。
- 导出 JSON 不包含新增字段，并通过现有参考文件兼容性校验。
- 当前服务权限与未归属权限在所有视口下均为单列，每行只有一个权限复选项。
- 左侧服务订阅在所有视口下均为单列，每行只有一个服务复选项。
