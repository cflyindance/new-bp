# 员工声明：系统默认语言

用户已确认采用第一种方案并要求实现：系统默认语言使用现有内置英文声明，不跟随管理后台界面语言。

## 行为

- 员工信息的默认声明语言第一项为“系统默认语言”；新员工及未配置员工默认选中。
- 现有明确选择的已发布模板不批量覆盖；可手动切回系统默认语言。
- 使用现有空偏好值表示系统默认，避免为所有员工制造模板记录。已有明确但失效的模板仍提示异常，不能静默回退。
- 系统默认直接使用现有英文声明原文和员工的小费、服务费变量；没有自定义模板也能预览、打印及导出。显示状态为就绪而非未配置。
- 英文系统默认只输出一份英文；不依赖后台 UI 中英文选项。其他自定义模板的双语逻辑不改变。
- 历史声明快照优先，不因员工当前语言改变而重写历史正文。
- 模板加载失败不影响选择系统默认；仍显示模板读取失败提示，不声称自定义模板已加载。
- 系统默认沿用现有无自定义偏好的薪资保存流程；不新增后端接口或重写历史快照。
- 员工编辑弹框点击“确认”独立保存基础信息、声明语言及打印格式，不需要再点击薪资“确定并保存”；不同时提交考勤与金额草稿。保存失败保留弹框和输入。示例场景保持当前页面演示边界，不写入实际薪资快照。
- 薪资确认前重新解析当前已发布声明版本，不提交切换语言前的缓存版本；已经冻结的历史声明不重复提交版本确认。

## 范围和验证

修改语言下拉文案、声明解析器默认分支及 runtime 数据连接；源脚本和对应静态镜像保持一致。不修改发薪、考勤、金额计算、模板发布或权限。

测试覆盖默认英文、变量替换、无模板、失效模板不回退、已有快照优先、同语言不重复、选择自定义后切回默认。浏览器验证默认选中、确认/取消及详细/精简明细英文正文。保留原工作区其他修改，不自动提交或推送。
