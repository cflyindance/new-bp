# 员工分配汇总状态口径设计

## 目标

将员工分配汇总中的“状态”明确为“分配状态”，并严格依据当前门店与所选日期范围内该员工逐日结果的分配完成度展示。

## 状态定义

对进入当前汇总结果集的每位员工，统计所选日期范围内的有效逐日记录：

- 所有记录均已分配：`已完成`。
- 同时存在已分配和未分配记录：`部分待分配`。
- 所有记录均未分配：`待分配`。

分配状态只表达分配完成度。考勤异常、工时异常或金额校验异常不得将该字段改写为“异常”，这些信息继续在员工详情的对应字段中呈现。

## 空记录边界

若员工在所选日期范围内没有任何有效逐日记录，则不应进入员工分配汇总列表，因此不产生分配状态。

## 页面与筛选

- 员工列表表头由 `状态` 改为 `分配状态`。
- 筛选标签由 `状态` 改为 `分配状态`。
- 筛选选项依次为：`全部状态`、`已完成`、`部分待分配`、`待分配`。
- 删除筛选项 `异常` 和状态文案 `待处理`。
- 状态筛选与门店、日期、角色、员工筛选继续采用 AND 关系。

## 数据与样式

- 状态来源为聚合记录中的 `confirmedDays`、`pendingAllocationDays` 或等价的逐日 `allocated` 计数，不建立第二套状态数据。
- `已完成` 使用完成态样式；`部分待分配` 与 `待分配` 使用待处理色系，但文案必须明确区分。
- 排序、金额汇总、员工详情快照和导出仍使用同一日期范围内的员工聚合数据。

## 验收标准

1. 页面筛选标签与表头均显示“分配状态”。
2. 全部已分配的员工显示“已完成”。
3. 部分日期已分配的员工显示“部分待分配”。
4. 全部未分配的员工显示“待分配”。
5. 筛选下拉只包含四个约定选项，并能准确过滤三种状态。
6. 存在考勤或数据异常时，分配状态仍只按分配完成度计算。
7. 切换日期范围后，状态依据新范围重新聚合。
8. 原生视图验证脚本与项目构建通过。

## 验证策略

- 为全分配、部分分配、全未分配分别增加聚合断言。
- 增加异常数据不覆盖分配状态的断言。
- 增加三个状态各自的筛选断言。
- 静态验证新标签、表头与选项存在，旧文案 `待处理`、`异常` 不再作为员工分配状态出现。
- 浏览器验证不同员工及日期范围下的显示和筛选。
