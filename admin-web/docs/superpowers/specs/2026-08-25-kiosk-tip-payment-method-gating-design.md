# Kiosk 小费选择按支付方式联动设计

## 目标

在 Kiosk 本地配置后台的「设置 → 小费设置」中，为「显示小费选项」增加“信用卡”和“现金”两个多选条件，并与「支付设置 → 选择支付方式」保持强一致：只有已启用的支付方式才能配置展示小费；支付方式被取消后，对应小费条件自动取消。

## 当前实现

- Kiosk 本地设置由 `dist/kiosklite/src/container/configApp/serviceSetting/` 渲染。
- 「显示小费选项」为 `configList` 中 `id: 5`、`key: "tipping-mode"` 的布尔配置。
- 「选择支付方式」来自 POS 配置 `KIOSK_PAYMENT_TYPE`，值中 `0` 表示信用卡、`1` 表示现金、`2` 表示礼品卡。
- 服务设置保存时已经读取并同步 `KIOSK_PAYMENT_TYPE`，因此小费条件可复用同一份当前编辑态支付配置，无需新增接口。

## 数据设计

将 `tipping-mode` 的 `value` 规范化为：

```js
{
  enabled: true,
  paymentTypes: ['0', '1']
}
```

- `enabled`：是否显示小费选择。
- `paymentTypes`：允许显示小费选择的支付方式；`0` 为信用卡，`1` 为现金。
- 礼品卡不在本次范围内。

### 旧数据兼容

- 布尔值 `true` 读取为 `{ enabled: true, paymentTypes: [] }`。
- 布尔值 `false` 读取为 `{ enabled: false, paymentTypes: [] }`。
- 新结构读取时过滤未知支付方式并去重。
- 不因旧值为 `true` 自动勾选信用卡或现金，避免未经用户确认改变既有支付流程。
- 保存后写入新结构；不新增配置 ID。

## 界面与交互

### 主开关

- 「显示小费选项」沿用现有开关样式。
- 开关关闭时隐藏“信用卡”“现金”多选区。
- 开关关闭不强制清空已选支付条件；重新开启时可恢复仍然有效的选择，但保存前仍会执行支付方式交集校验。

### 支付条件多选

- 开关开启后，在同一设置项下方显示“信用卡”“现金”两个复选项。
- `KIOSK_PAYMENT_TYPE` 包含 `0` 时，信用卡可勾选；否则禁用且保持未勾选。
- `KIOSK_PAYMENT_TYPE` 包含 `1` 时，现金可勾选；否则禁用且保持未勾选。
- 用户取消「选择支付方式」中的信用卡或现金后，对应小费条件立即自动取消。
- 重新启用某支付方式时，对应小费条件恢复可选，但不会自动勾选。
- 多选允许为空；开启主开关但未选择支付条件时不阻止保存。

## 状态流

1. 加载 `configList`，规范化 `tipping-mode` 旧值或新值。
2. 从当前编辑态 `KIOSK_PAYMENT_TYPE` 计算可用支付方式集合。
3. 渲染主开关和两个支付条件复选项。
4. 支付方式变化时，对 `tipping-mode.paymentTypes` 与可用集合取交集并刷新界面。
5. 小费条件点击时，仅允许加入当前可用集合中的支付方式。
6. 保存前再次取交集，将规范化后的新结构写回 `configList`。

## 组件边界

- `ServiceItem` 负责渲染 `tipping-mode` 专用界面，并把主开关/复选框操作上抛。
- `serviceSetting/index.js` 负责持有 `configList`、读取 `posDetail` 的当前支付方式，以及执行支付变化后的联动清理和保存前兜底。
- 数据规范化与集合求交封装为小型纯函数，便于独立验证，不把业务判断散落在 JSX 中。
- 继续使用现有 `Checkbox`、`Switch` 和样式体系，不引入新依赖。

## 异常与边界处理

- `KIOSK_PAYMENT_TYPE` 缺失或值为空时，信用卡和现金均禁用，已选条件清空。
- `posDetail` 尚未加载时按无可用支付方式处理；加载完成后重新计算。
- 旧配置、非法对象、未知数组值均通过规范化函数转为安全结构。
- 即使界面事件遗漏，保存前校验也不会写入未启用支付方式对应的小费条件。

## 验收标准

1. 「显示小费选项」关闭时不展示信用卡/现金多选。
2. 开启后展示信用卡和现金，可同时选择。
3. 支付设置仅启用信用卡时：信用卡可选，现金禁用且不可被保存为已选。
4. 支付设置仅启用现金时：现金可选，信用卡禁用且不可被保存为已选。
5. 两者均启用时，两项均可多选。
6. 已勾选信用卡后取消信用卡支付，信用卡小费条件立即自动取消；现金同理。
7. 重新启用支付方式后对应项只恢复可选，不自动勾选。
8. 旧布尔配置能正常加载并在保存后迁移为新结构。
9. 其他小费设置、礼品卡支付和设备支付方式同步逻辑保持不变。

## 验证策略

- 为数据规范化、支付方式交集和自动取消行为增加可执行校验。
- 运行项目既有类型检查/构建。
- 重新构建 KioskLite 嵌入产物，并确认设置 iframe 使用最新资源。
- 浏览器验证信用卡、现金、双支付三种组合以及支付方式取消后的即时联动。

## 非目标

- 不增加礼品卡小费条件。
- 不改变食客端小费金额、比例、No Tip 或签名流程。
- 不改变 POS 的支付方式定义与设备支付方式同步规则。
- 不新增后端接口或配置 ID。
