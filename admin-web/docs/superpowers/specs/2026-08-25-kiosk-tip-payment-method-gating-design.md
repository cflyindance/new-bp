# Kiosk 小费选择按支付方式联动设计

## 目标

在 Kiosk 本地配置后台的「设置 → 小费设置」中，为「显示小费选项」增加“信用卡”和“现金”两个多选条件，并与「支付设置 → 选择支付方式」保持强一致：只有已启用的支付方式才能配置展示小费；支付方式被取消后，对应小费条件自动取消。

## 当前实现

- Kiosk 本地设置由 `dist/kiosklite/src/container/configApp/serviceSetting/` 渲染。
- 「显示小费选项」为 `configList` 中 `id: 5`、`key: "tipping-mode"` 的布尔配置。
- 「选择支付方式」来自 POS 配置 `KIOSK_PAYMENT_TYPE`，值中 `0` 表示信用卡、`1` 表示现金、`2` 表示礼品卡。
- 服务设置保存时已经读取并同步 `KIOSK_PAYMENT_TYPE`，因此小费条件可复用同一份当前编辑态支付配置，无需新增接口。

## 数据设计

保持 `tipping-mode.value` 为现有布尔值，在同一配置项上增加可选字段：

```js
{
  id: 5,
  key: 'tipping-mode',
  value: true,
  tipPaymentTypes: ['0', '1']
}
```

- `value`：是否显示小费选择，继续使用布尔值，保证既有运行时消费者与旧版本兼容。
- `tipPaymentTypes`：允许显示小费选择的支付方式；`0` 为信用卡，`1` 为现金。
- 礼品卡不在本次范围内。

### 旧数据兼容

- `tipPaymentTypes` 缺失代表旧数据的“全部当前可用支付方式”，从而保持升级前的小费展示行为。
- 设置页首次读取旧数据时，信用卡/现金复选框显示为当前 `KIOSK_PAYMENT_TYPE` 中已启用的对应方式。
- 保存后写入显式的 `tipPaymentTypes`；`value` 始终保持布尔值，不新增配置 ID。
- `tipPaymentTypes` 为数组时过滤未知值并去重，再与当前可用支付方式取交集。
- `tipPaymentTypes` 为 `null`、对象或其他非法类型时按缺失的旧数据处理，避免升级后意外关闭原有小费流程。
- 旧版本回滚时仍按布尔 `value` 控制小费总开关；它会忽略新增字段，但不会把关闭状态误判为开启。

## 界面与交互

### 主开关

- 「显示小费选项」沿用现有开关样式。
- 开关关闭时隐藏“信用卡”“现金”多选区。
- 开关关闭不强制清空已选支付条件；重新开启时可恢复仍然有效的选择，但保存前仍会执行支付方式交集校验。

### 支付条件多选

- 开关开启后，在同一设置项下方显示“信用卡”“现金”两个复选项。
- `KIOSK_PAYMENT_TYPE` 包含 `0` 时，信用卡可勾选；否则禁用且保持未勾选。
- `KIOSK_PAYMENT_TYPE` 包含 `1` 时，现金可勾选；否则禁用且保持未勾选。
- 用户取消「选择支付方式」中的信用卡或现金后，对应小费条件立即自动取消。
- 重新启用某支付方式时，对应小费条件恢复可选，但不会自动勾选。
- 多选允许为空；开启主开关但未选择支付条件时不阻止保存。

## 状态流

1. 加载 `configList`，保持 `tipping-mode.value` 的布尔语义，并规范化可选的 `tipPaymentTypes`。
2. 从当前编辑态 `KIOSK_PAYMENT_TYPE` 计算可用支付方式集合。
3. 渲染主开关和两个支付条件复选项。
4. 支付方式变化时，对 `tipping-mode.tipPaymentTypes` 与可用集合取交集并刷新界面。
5. 小费条件点击时，仅允许加入当前可用集合中的支付方式。
6. 保存前再次取交集，将规范化后的 `tipPaymentTypes` 写回 `configList`，并保持 `value` 为布尔值。
7. 食客端进入小费流程前，用当前订单支付方式、`value`、`tipPaymentTypes` 与运行时 `KIOSK_PAYMENT_TYPE` 共同判断是否展示小费。

## 组件边界

- `ServiceItem` 负责渲染 `tipping-mode` 专用界面，并把主开关/复选框操作上抛。
- `serviceSetting/index.js` 负责持有 `configList`、读取 `posDetail` 的当前支付方式，以及执行支付变化后的联动清理和保存前兜底。
- 新增共享的小费支付条件工具，负责规范化、集合求交及 `isTipEnabledForPaymentType` 判断；设置页与食客端复用，不把业务判断散落在 JSX 中。
- `cardPayment/index.js` 与 `connectionError/index.js` 等全部 `id:5` 运行时消费方改用共享判断，避免继续把新增条件忽略掉。
- 继续使用现有 `Checkbox`、`Switch` 和样式体系，不引入新依赖。

## 异常与边界处理

- `KIOSK_PAYMENT_TYPE` 缺失或值为空时，信用卡和现金均禁用，已选条件清空。
- `posDetail` 尚未加载时暂时禁用选项，但不改写或清空配置；加载完成后再计算交集，避免加载竞态造成数据丢失。
- `KIOSK_PAYMENT_TYPE` 规范化同时支持当前逗号分隔的 `app:value` 字符串和数组输入；空项、重复项和未知值会被过滤。
- 旧配置、非法 `tipPaymentTypes`、未知数组值均通过规范化函数转为安全结构。
- 即使界面事件遗漏，保存前校验也不会写入未启用支付方式对应的小费条件。

### 分步保存失败

当前流程先保存 POS 支付配置，再保存 Kiosk 配置，无法提供跨接口原子事务。因此本设计保证“运行时与界面强一致”，并采用以下对账策略：

- POS 保存成功后即以最新支付方式为准；Kiosk 保存失败时提示现有失败反馈，不回滚已成功的 POS 保存。
- 食客端每次判断都将 `tipPaymentTypes` 与运行时 `KIOSK_PAYMENT_TYPE` 取交集，因此旧的 Kiosk 持久化值不会让已关闭的支付方式继续展示小费。
- 设置页重新加载时按已持久化的 POS 支付方式清理界面中的失效选择；下次成功保存时将交集结果持久化。
- 不在加载时静默发起自动保存，避免无用户操作的写请求。

## 验收标准

1. 「显示小费选项」关闭时不展示信用卡/现金多选。
2. 开启后展示信用卡和现金，可同时选择。
3. 支付设置仅启用信用卡时：信用卡可选，现金禁用且不可被保存为已选。
4. 支付设置仅启用现金时：现金可选，信用卡禁用且不可被保存为已选。
5. 两者均启用时，两项均可多选。
6. 已勾选信用卡后取消信用卡支付，信用卡小费条件立即自动取消；现金同理。
7. 重新启用支付方式后对应项只恢复可选，不自动勾选。
8. 旧布尔配置能正常加载并在保存后迁移为新结构。
9. 旧数据缺少 `tipPaymentTypes` 时，保存其他设置不会改变升级前对当前可用信用卡/现金支付展示小费的行为。
10. `tipPaymentTypes` 为重复值、未知值、`null` 或非法对象时可安全规范化；保存不会保留未知或未启用方式。
11. `KIOSK_PAYMENT_TYPE` 缺失、为空或尚未加载时不可误选；尚未加载不会清空原配置。
12. 即使伪造或残留了失效选择，保存前与食客端运行时都会过滤。
13. POS 保存成功而 Kiosk 保存失败后，已取消的支付方式不会在食客端继续触发小费；重新加载可显示正确禁用/取消状态。
14. 信用卡订单只在信用卡小费条件开启时进入小费流程；现金订单只在现金小费条件开启时进入小费流程。
15. 其他小费金额、比例、No Tip、签名行为、礼品卡支付和设备支付方式同步逻辑保持不变。

## 验证策略

- 为旧数据兼容、非法输入规范化、支付方式交集、自动取消和保存前过滤增加可执行校验。
- 为信用卡/现金运行时分流以及 POS 成功、Kiosk 失败后的运行时过滤增加行为校验。
- 运行项目既有类型检查/构建。
- 重新构建 KioskLite 嵌入产物，并确认设置 iframe 使用最新资源。
- 浏览器验证信用卡、现金、双支付三种组合以及支付方式取消后的即时联动。

## 非目标

- 不增加礼品卡小费条件。
- 除“是否按当前支付方式进入小费展示”外，不改变食客端小费金额、比例、No Tip 或签名流程。
- 不改变 POS 的支付方式定义与设备支付方式同步规则。
- 不新增后端接口或配置 ID。
