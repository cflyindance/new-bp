# 营销中心屏保流程全屏覆盖设计

## 背景

营销中心的屏保功能通过同源 iframe 嵌入主应用。屏保列表需要继续显示在主内容区；用户从列表进入新建或编辑流程后，页面需要覆盖整个浏览器视口，并位于侧边导航栏和顶部栏之上。

## 目标

- 屏保列表页保持现有嵌入布局。
- 进入新建或编辑屏保后，将屏保 iframe 提升为顶层全屏页面。
- 门店选择、渠道选择、生效时间等后续步骤持续保持全屏。
- 完成流程或返回屏保列表时退出全屏，并恢复原有侧边栏和顶部栏布局。

## 非目标

- 不重构屏保功能为主应用原生路由。
- 不改变屏保页面现有表单、数据存储和步骤顺序。
- 不改变营销中心其他嵌入页面的布局。

## 方案

在主应用中为营销中心屏保 iframe 增加稳定的数据标识，并在每次主应用挂载后绑定 iframe `load` 监听器。监听器读取同源 iframe 当前页面的文件名，维护一次屏保全屏流程状态：

- 加载 `screensaver-create.html` 或 `screensaver-edit.html`：进入全屏状态。
- 加载 `kiosk-theme-list.html`：退出全屏状态。
- 加载 `store-select.html`、`channel-select.html`、`effective-time.html` 等其他页面：保持当前状态，确保整个后续流程不中途退出全屏。

全屏状态直接作用于现有 iframe：使用固定定位覆盖视口，宽高占满视口，并设置高于侧边栏、顶部栏和普通浮层的层级及不透明背景。这样可以保留同一个 iframe 的浏览上下文、表单草稿和前进/返回行为，避免复制页面或重新加载流程。

退出全屏时，完整移除新增的内联样式和状态属性，使 iframe 回到原有主内容区尺寸。主应用自身因路由切换重新挂载时，旧 iframe 会被销毁，全屏状态也随之自然清理。

## 状态边界

全屏生命周期以页面导航为准，而不是对每个后续步骤维护固定白名单：

1. 新建或编辑页开启全屏。
2. 中间页面继续沿用当前全屏状态。
3. 列表页明确关闭全屏。

该规则允许流程新增步骤而无需同步修改父应用，同时满足“直到完成或返回屏保列表”的要求。

## 异常处理

- iframe 与主应用当前为同源；读取地址时仍使用 `try/catch`，防止未来资源来源变化导致父页面脚本中断。
- 地址读取失败时保持当前状态，不错误退出正在进行的全屏流程。
- 重复触发同一状态应为幂等操作，不重复绑定监听器或累积样式。

## 验证

- 屏保列表页仍位于营销中心主内容区，侧边栏和顶部栏可见。
- 从空状态和列表状态分别点击“新建”，页面覆盖整个视口。
- 点击已有屏保的“编辑”，页面同样覆盖整个视口。
- 新建和编辑流程进入门店、渠道、生效时间等步骤后继续全屏。
- 使用流程内返回按钮逐步返回时仍保持全屏；回到列表后恢复普通布局。
- 完成流程返回列表后恢复普通布局。
- 运行 TypeScript 检查和生产构建，确认静态嵌入资源仍被正确保留。
