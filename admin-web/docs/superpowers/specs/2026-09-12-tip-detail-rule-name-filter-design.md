# 小费分配明细规则名称筛选设计

## 背景与目标

小费分配明细页在同一门店、同一日期可能同时展示多条适用规则。随着规则数量增加，运营人员难以快速聚焦指定规则并核对对应金额、员工分配结果及公式详情。

本次在原生小费分配明细页增加“规则名称”多选筛选，使用户能按规则缩小查看范围，并保证页面各展示区块使用一致口径。

## 交互设计

- 筛选控件位于页面顶部筛选栏，排列顺序为：门店、日期、规则名称。
- 使用项目现有多选下拉交互，支持逐项勾选、全选、已选标签展示和清空。
- 选项来自当前门店、当前日期的全部适用小费规则，按页面原有规则顺序展示。
- 首次进入页面，以及切换门店或日期后，默认选择全部适用规则。
- “全选”与具体规则选项保持双向同步：全部子项选中时全选为选中，部分选中时为半选状态。
- 用户取消全部规则时，页面展示明确空状态，不使用 `$0.00` 表示无匹配结果。

## 联动范围

选择发生变化后，以下区域同步按已选规则刷新：

1. 顶部金额与数量概览：入池金额、已分配、未分配、规则数量。
2. 小费池执行结果列表。
3. 规则对应的员工分配明细卡片。
4. 规则公式与配置详情。

概览口径固定为：

- `originalTips` 是日期级来源金额，只要选择非空就保持当天金额，不随规则数量重复累加。
- `poolAmount`、`allocatedAmount`、`unallocatedAmount` 只聚合已选规则的贡献值。
- 规则数量是已选规则数。
- 多条规则属于同一小费池时，先按已选规则分别计算，再按小费池 ID 汇总选中子集的金额；执行状态只反映该选中子集。不得要求同池全部规则均被选中才显示该池。
- 没有选中规则时，金额概览显示 `—`，规则数量显示 `0`。

## 分配提交边界

规则名称筛选仅控制页面查看范围，不改变当天分配任务的业务范围。

- 页面可隐藏未选规则的展示卡片，但必须保留当天全部适用规则的计算状态。
- 点击“确认分配”时，仍对当天全部适用规则执行校验并提交。
- 未显示规则存在无效员工、工时、金额或比例时，确认分配仍需阻止，并提示具体规则名称与错误原因。
- 筛选不得导致确认结果遗漏规则或覆盖为部分分配结果。
- `selectedRuleIds` 是纯展示状态，禁止进入自动分配、全量校验、确认快照、持久化或薪资同步的业务范围计算。
- 确认快照必须从完整规则状态仓生成，禁止遍历筛选后的 DOM 或可见卡片生成。
- 提交前必须断言快照中的规则 ID 集合与当前门店、日期的全部适用规则 ID 集合完全一致；不一致时阻止提交且不得覆盖原结果。
- 清空选择时“确认分配”仍保持可用，但空状态明确提示“确认分配仍将处理当天全部 N 条规则”。

## 数据流与状态

页面加载门店和日期后，先生成完整的规则执行数据集 `allRuleResults`，再根据所选规则 ID 派生 `visibleRuleResults`。

- 完整数据集用于编辑状态保存、全量校验和确认分配。
- 可见数据集用于概览、执行结果、员工明细和公式详情渲染。
- 筛选状态使用稳定的规则 ID，不使用可能重复或变化的规则名称作为内部键。
- 门店或日期变化时，清理旧筛选状态，并用新数据集的全部规则 ID 初始化选择。
- 筛选变化仅调用可见视图渲染入口，不重新执行完整页面初始化，也不得调用自动分配调度或薪资同步。
- 自动分配只在门店、日期的完整数据集初始化结束后评估一次，并始终使用完整适用规则集合。
- 工时、比例和员工等编辑值立即写入以 `store + date + ruleId + employeeId` 为键的页面状态；规则隐藏后再显示时必须恢复编辑值。
- 切换门店或日期时沿用页面现有行为：未确认的页面态编辑被丢弃，由目标门店、日期的数据重新初始化；本次不新增保存草稿或离开确认弹窗。
- 已确认日期重新分配时，以重新打开页面时解析出的当前适用规则集合为准；页面停留期间规则数据变化时，提交前完整性断言失败并要求刷新，不静默混用历史和当前规则。

## 异常与空状态

- 当前门店和日期没有适用规则：下拉禁用，显示“暂无适用规则”，页面沿用现有无规则引导。
- 有适用规则但用户未选择任何规则：展示“当前未选择规则，请在规则名称中选择”的空状态。
- 已选规则随后失效或被删除：刷新选项并移除失效 ID；若没有剩余选择则进入未选择空状态。
- 规则名称重复：所有同名选项统一显示“规则名称 · 小费池名称”；若仍重复，再追加稳定规则 ID 的短标识。内部始终以完整规则 ID 区分。
- 隐藏规则校验失败：错误信息显示可区分的规则标签与原因，并提供“查看该规则”动作；点击后把规则加入已选集合，滚动并聚焦到首个错误字段。提交失败不得改变已保存结果。

## 可访问性

- 下拉触发器暴露“规则名称”标签及当前选择摘要。
- 全选和规则选项使用真实复选框，支持键盘操作。
- 半选状态设置 `indeterminate`，并通过 `aria-checked="mixed"` 表达。
- 筛选刷新后维持焦点位置，不主动将焦点移动到结果区。

## 验收标准

1. 规则名称筛选支持多选、全选、取消全选和部分选择。
2. 默认选中当前门店、日期下全部适用规则。
3. 筛选后概览、执行结果、员工明细、规则公式同步变化，且金额与数量计算正确。
4. 未选择规则时显示空状态及 `—`，不伪造零金额。
5. 切换门店或日期后，规则选项与默认全选状态正确刷新。
6. 确认分配始终提交当天全部适用规则；筛选不造成部分提交。
7. 隐藏规则存在校验错误时，确认分配仍被阻止并能定位具体规则。
8. 多条同名规则仍能独立选择并正确筛选。
9. A、B、C 三条规则只显示 A 时，确认结果仍包含 A、B、C；已有完整结果重新确认也不得删除 B、C。
10. 切换规则、全选或清空均不触发自动分配、不新增或覆盖结果，也不触发薪资同步。
11. 两条规则共享同一小费池时，选择其中一条只展示该规则贡献金额；同时选择两条时按池 ID 汇总，金额等于两条贡献之和且不重复计算原始小费。
12. 编辑规则 A 的员工工时后隐藏再显示 A，编辑值保持；确认后全量快照包含该编辑值和其他隐藏规则。
13. 隐藏规则校验失败时，确认被阻止；“查看该规则”可恢复显示并定位错误，原有已确认结果不被覆盖。
