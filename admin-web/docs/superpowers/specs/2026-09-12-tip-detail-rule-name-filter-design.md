# 小费分配明细规则名称筛选设计

## 背景与目标

小费分配明细页在同一门店、同一日期可能同时展示多条适用规则。随着规则数量增加，运营人员难以快速聚焦指定规则并核对对应金额、员工分配结果及公式详情。

本次在原生小费分配明细页增加“规则名称”多选筛选，使用户能按规则缩小查看范围，并保证页面各展示区块使用一致口径。

## 交互设计

- 筛选控件位于页面顶部筛选栏，排列顺序为：门店、日期、规则名称。
- 使用项目现有多选下拉交互，支持逐项勾选、全选、已选标签展示和清空。
- 选项来自当前门店、当前日期的全部适用小费规则，按页面原有规则顺序展示。
- 首次进入页面，以及切换门店或日期后，默认选择全部适用规则。
- “全选”与具体规则选项保持双向同步：全部子项选中时全选为选中，部分选中时为半选状态。
- 用户取消全部规则时，页面展示明确空状态，不使用 `$0.00` 表示无匹配结果。

## 联动范围

选择发生变化后，以下区域同步按已选规则刷新：

1. 顶部金额与数量概览：入池金额、已分配、未分配、规则数量。
2. 小费池执行结果列表。
3. 规则对应的员工分配明细卡片。
4. 规则公式与配置详情。

原始小费属于日期级来源金额，不因规则筛选而重复累加；在至少选择一条规则时保持当天原始小费口径。没有选中规则时，所有概览值显示 `—`，规则数量显示 `0`。

## 分配提交边界

规则名称筛选仅控制页面查看范围，不改变当天分配任务的业务范围。

- 页面可隐藏未选规则的展示卡片，但必须保留当天全部适用规则的计算状态。
- 点击“确认分配”时，仍对当天全部适用规则执行校验并提交。
- 未显示规则存在无效员工、工时、金额或比例时，确认分配仍需阻止，并提示具体规则名称与错误原因。
- 筛选不得导致确认结果遗漏规则或覆盖为部分分配结果。

## 数据流与状态

页面加载门店和日期后，先生成完整的规则执行数据集 `allRuleResults`，再根据所选规则 ID 派生 `visibleRuleResults`。

- 完整数据集用于编辑状态保存、全量校验和确认分配。
- 可见数据集用于概览、执行结果、员工明细和公式详情渲染。
- 筛选状态使用稳定的规则 ID，不使用可能重复或变化的规则名称作为内部键。
- 门店或日期变化时，清理旧筛选状态，并用新数据集的全部规则 ID 初始化选择。

## 异常与空状态

- 当前门店和日期没有适用规则：下拉禁用，显示“暂无适用规则”，页面沿用现有无规则引导。
- 有适用规则但用户未选择任何规则：展示“当前未选择规则，请在规则名称中选择”的空状态。
- 已选规则随后失效或被删除：刷新选项并移除失效 ID；若没有剩余选择则进入未选择空状态。
- 规则名称重复：下拉显示名称，必要时附加小费池名称；内部仍以规则 ID 区分。

## 可访问性

- 下拉触发器暴露“规则名称”标签及当前选择摘要。
- 全选和规则选项使用真实复选框，支持键盘操作。
- 半选状态设置 `indeterminate`，并通过 `aria-checked="mixed"` 表达。
- 筛选刷新后维持焦点位置，不主动将焦点移动到结果区。

## 验收标准

1. 规则名称筛选支持多选、全选、取消全选和部分选择。
2. 默认选中当前门店、日期下全部适用规则。
3. 筛选后概览、执行结果、员工明细、规则公式同步变化，且金额与数量计算正确。
4. 未选择规则时显示空状态及 `—`，不伪造零金额。
5. 切换门店或日期后，规则选项与默认全选状态正确刷新。
6. 确认分配始终提交当天全部适用规则；筛选不造成部分提交。
7. 隐藏规则存在校验错误时，确认分配仍被阻止并能定位具体规则。
8. 多条同名规则仍能独立选择并正确筛选。
