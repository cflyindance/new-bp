# “按照时段显示菜单”六产线与共享矩阵设计

> 日期：2026-08-10
> 模块：前厅管理中心 / 设置 / POS 菜单与界面
> 设置项：seq 348「按照时段显示菜单」
> 状态：独立评审已批准，待用户复核

## 1. 背景与问题

「按照时段显示菜单」的专用实现文件仍然存在，但当前应用入口没有导入和调用它，因此设置页不会渲染其订单类型矩阵，也不会绑定复选框保存事件。

现有实现还只声明 POS、POS GO、PayPad 三条产线，无法满足 eMenu、Kiosk、POS、POS GO、PayPad、SDI 六条产线分别配置菜单类型的需求。

## 2. 目标

1. 恢复 seq 348 在设置页中的完整运行时接入，并直接展示配置矩阵。
2. 支持以下六条产线分别配置菜单类型：
   - eMenu
   - Kiosk
   - POS
   - POS GO
   - PayPad
   - SDI
3. 每条产线均可多选以下菜单类型：
   - Dinein
   - Delivery
   - Pick Up
   - ToGo
4. 抽取可复用的“产线 × 订单类型”多选矩阵，使 seq 132「点单显示座位」与 seq 348 复用同一套通用交互能力。
5. 保持两个设置项的数据、存储键和历史兼容逻辑相互独立。

## 3. 非目标

- 不改变菜单时段的创建、编辑或匹配算法。
- 不修改订单类型的业务编码。
- 不将 seq 132 扩展到六条产线；它仍只适用于 POS、POS GO、PayPad。
- 不合并 seq 132 与 seq 348 的存储数据。
- 不迁移或恢复已退役的 seq 176、177。
- 不调整其他前厅设置项的分组或导航结构。

## 4. 已确认产品决策

| 决策项 | 结论 |
| --- | --- |
| 实现方式 | 采用方案 C：抽取共享矩阵能力 |
| seq 348 产线 | eMenu、Kiosk、POS、POS GO、PayPad、SDI |
| 菜单类型 | Dinein、Delivery、Pick Up、ToGo |
| 选择方式 | 每条产线独立多选 |
| Pick Up 编码 | 显示 `Pick Up`，底层继续使用 `pick-up` |
| seq 132 范围 | 保持 POS、POS GO、PayPad，不扩展 |
| 历史数据 | 保留现有三条产线的数据；新增产线默认空选 |
| 开关 | seq 348 不展示、不读取也不写入开关；空选即未启用 |
| 保存 | 变更进入当前页面草稿，通过页面现有保存栏提交 |

## 5. 交互设计

### 5.1 seq 348 设置行

- 形式参照「可自动送厨的订单支付状态」：不展示独立开关，标题下方直接展示矩阵。
- 矩阵第一列为产线，第二列为“按时段显示菜单的订单类型（多选）”。
- 产线展示顺序固定为：eMenu、Kiosk、POS、POS GO、PayPad、SDI。
- 每行订单类型展示顺序固定为：Dinein、Delivery、Pick Up、ToGo。
- 每条产线可选择零到四种类型；零选表示该产线不启用按时段显示菜单。
- 勾选变化后立即写入当前页面草稿，不增加组件内“保存”按钮；用户通过页面已有保存栏统一提交。
- 完整设置页直接展示六行矩阵；按产线设置页复用现有行抑制逻辑，只展示当前产线对应的一行。两个视图均不提供全局或当前产线开关。

### 5.2 无障碍与状态

- 每个复选框的可访问名称由“产线 + 菜单类型”组成。
- 事件绑定必须具备幂等保护，重复挂载不能重复注册监听器。
- seq 132 与 seq 348 同页挂载时，DOM 标识和事件处理必须完全隔离。

## 6. 共享组件设计

新增一个通用的“产线 × 订单类型多选矩阵”模块。该模块不感知具体 seq、业务标题或 localStorage 键，通过配置和回调完成复用。

### 6.1 通用模块职责

- 接收产线定义、订单类型定义、DOM 数据属性前缀和列标题。
- 根据已保存值渲染表格与复选框。
- 创建完整的空值映射。
- 过滤未知产线和非法订单类型。
- 按配置顺序规范化和收集多选值。
- 绑定复选框变更事件，并通过回调交给业务模块保存。

### 6.2 通用模块不负责

- 不直接读写 localStorage。
- 不执行旧数据迁移。
- 不决定主开关的存储方式。
- 不决定页面草稿的提交或取消行为。
- 不共享不同设置项的数据。

### 6.3 业务包装层

seq 132 与 seq 348 各自保留业务模块，用于定义：

- 适用产线。
- 订单类型及文案。
- 存储键。
- 旧数据迁移规则。
- 面板标题。
- 面板专属 DOM 标识。

seq 132 的旧版“先选产线”迁移及主开关兼容逻辑必须原样保留。共享组件只替换重复的矩阵渲染、规范化和事件收集代码；seq 132 的面板显隐仍由其业务包装层负责。

seq 348 不再属于开关型设置。现有 `bplant-module-setting-toggle:348` 值不删除，但运行时忽略该值；无需新增全局开关或按产线启用状态。

## 7. 数据与兼容性

### 7.1 seq 348 存储

继续使用：

```text
348-timed-menu-order-types-by-line
```

目标结构示例：

```json
{
  "emenu": ["dine-in", "to-go"],
  "kiosk": ["dine-in"],
  "pos": ["dine-in", "delivery"],
  "pos-go": ["pick-up"],
  "paypad": [],
  "sdi": ["delivery", "to-go"]
}
```

合法订单类型编码固定为：

```text
dine-in, delivery, pick-up, to-go
```

### 7.2 向后兼容

- 读取只包含 `pos`、`pos-go`、`paypad` 的旧对象时，保留这些值。
- `emenu`、`kiosk`、`sdi` 缺失时规范化为空数组。
- 未知产线键不参与 UI，也不写回目标结构。
- 非法订单类型、非数组值和重复值被过滤。
- 写入时始终按产线和订单类型的配置顺序生成稳定结构。
- 勾选写入页面草稿；点击页面保存栏后才提交到持久化存储。取消或离开时遵循现有页面草稿机制。

### 7.3 seq 132 存储

继续使用：

```text
132-order-display-seat-order-types-by-line
```

其历史产线迁移、主开关迁移及默认全选行为保持不变。

## 8. 应用入口恢复

seq 348 必须重新接入以下运行时链路：

1. 导入业务模块提供的识别、渲染和绑定函数。
2. 设置项分派时使用 seq 348 专用无开关设置行，而不是通用开关行。
3. 完整设置页直接渲染六行矩阵；按产线设置页通过既有 `applyFohByLineUiSuppressions` 只显示当前产线行。
4. 页面挂载完成后绑定矩阵的 change 事件。

分派逻辑只保留一个 seq 348 分支，避免同一设置项出现重复或不可达判断。seq 348 从通用开关序列中移除，应用入口不再注册其开关联动副作用。

## 9. Catalog 与产线范围

- seq 348 的场景说明更新为六条产线及四种菜单类型。
- 产线范围生成结果必须将 seq 348 标记为 eMenu、Kiosk、POS、POS GO、PayPad、SDI。
- 对应的行范围 seed、生成文件和基线保持一致。
- `348-timed-menu-order-types-by-line` 是对象型矩阵，不是 `*-lines` 数组；seq 348 必须从通用产线数组存储注册表移除，不能交给 lines codec 读写。
- 按产线视图的可见范围来自静态六产线 scope，不由矩阵当前勾选结果反向改变。
- seq 176、177 继续退役，不重新出现在设置目录。

## 10. 错误与边界处理

- localStorage 不可用或数据解析失败时，返回六条产线的空映射，页面仍可渲染。
- 同一类型重复出现时仅保留一次。
- 不允许共享组件抛出因缺失产线键导致的运行时异常。
- 页面草稿被取消时恢复上次已保存值；刷新前未点击保存时不宣称配置已持久化。

### 11.3 浏览器 E2E

## 12. 影响范围与风险

风险级别：中等。原因是修改共享的设置 UI 交互能力，并同时影响两个设置项及页面草稿链路，但不涉及后端接口、资金、权限或跨系统写入。

| 路径/模块 | 关系 | 影响判断 | 验证方式 |
| --- | --- | --- | --- |
| seq 348 业务模块 | 故障目标 | affected | 聚焦测试 + E2E |
| 应用入口 | 直接调用方 | affected | 类型检查 + E2E |
| 共享矩阵模块 | 新共享实现 | affected | 单元/聚焦测试 |
| seq 132 业务模块 | 共享消费者 | affected | 迁移回归 + E2E |
| 页面草稿/保存栏 | 数据写入链路 | affected（复用、不改协议） | 保存/取消 E2E |
| 按产线设置视图 | 共享调用方 | affected | 按产线 E2E |
| Catalog 与行范围 | 元数据生产者 | affected | 生成校验 |
| seq 176、177 | 退役项 | not affected | 目录排除校验 |
| 菜单时段匹配算法 | 下游业务 | not affected | 本次不修改 |

当前工作区存在其他未提交修改。实施时只对上述目标位置做增量编辑，不覆盖或回滚无关变更；若发现目标行存在来源不明的重叠修改，则停止实施并重新确认。
