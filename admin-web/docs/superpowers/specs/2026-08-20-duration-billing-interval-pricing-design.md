## 目标

在现有「按时长单价」之外增加「按区间计价」。两种计价方式只能二选一；区间计价按实际时长落入的区间收取该档固定总价。

## 计价方式

### 按时长单价

保留现有金额、单位时长和不足一个单位向上取整逻辑。例如 ¥5/30 分钟。

### 按区间计价

示例：

- 1–30 分钟：¥10
- 31–60 分钟：¥18
- 61 分钟以上：¥25

实际时长只收取命中区间的固定价格，不累加前面区间费用。

## 表单交互

1. 新建和编辑抽屉增加「计价方式」单选：`按时长单价`、`按区间计价`。
2. 两种方式互斥，只展示当前方式的编辑区域。
3. 新建规则默认选择「按时长单价」，保持现有操作习惯。
4. 切换方式时保留当前抽屉内另一方式的未保存草稿；保存时只提交当前选中方式。
5. 编辑已有规则时根据 `pricing.type` 自动选中对应方式。

## 区间编辑器

1. 至少包含一个有限区间和一个末档“以上”区间。
2. 第一档起点固定为 1 分钟。
3. 有限区间只填写结束分钟和固定价格；下一档起点自动显示为上一档结束分钟 + 1。
4. 最后一档固定为“X 分钟以上”，X 自动等于上一档结束分钟 + 1，只填写固定价格。
5. 用户可在末档之前新增有限区间，也可删除有限区间；末档不可删除。
6. 结束分钟必须是正整数并严格递增；所有价格必须大于 0，最多两位小数。
7. 通过自动起点和固定末档保证区间连续、无重叠、无断档，并覆盖所有大于等于 1 分钟的时长。

## 数据模型

扩展现有 `pricing.type` 判别联合：

- `unit`：现有单价模式。
- `interval`：新的区间固定总价模式。
- `tiered`：保留给旧版未正式开放的时钟时段结构，不与新区间模式共用判别值。

`interval` 规则使用分钟边界：

```ts
type DurationBillingInterval = {
  endMinutes: number | null; // null 表示“以上”末档
  amount: number;
};

type DurationBillingIntervalPricing = {
  type: "interval";
  intervals: DurationBillingInterval[];
};
```

现有读取、列表、启停和回写逻辑继续原样保留旧 `tiered.tiers` 记录，不迁移、不删除、不猜测其区间含义；编辑旧 `tiered` 规则时提示旧结构暂不支持编辑。现有 `unit` 规则完全兼容。新区间模式的 stored normalizer、validator、upsert、重读和摘要全部使用 `interval.intervals`，不复用现有 `allowTiered` feature gate。

## 存储级校验

`intervals` 必须同时满足：

1. 至少两档：一个或多个有限区间，加一个“以上”末档。
2. `endMinutes: null` 恰好出现一次且只能是最后一档。
3. 有限档的 `endMinutes` 必须是有限正整数，并严格递增。
4. 每档 `amount` 必须是有限数、大于 0，且最多两位小数。
5. Store 校验独立于 DOM 的 `min`、`step`，直接传入 `NaN`、`Infinity`、小数分钟、多个或中间 `null` 均必须拒绝。

`upsertDurationBillingRule` 必须直接接受合法 `interval` 规则，写入后由 `listDurationBillingRules` 重读仍保持相同结构。

## 计价解析

本次提供纯函数 `resolveDurationBillingIntervalAmount(pricing: DurationBillingIntervalPricing, durationMinutes: number): number | null`：

- `interval` 按向上取整后的实际分钟命中第一档 `duration <= endMinutes`，否则命中末档并返回固定总价。
- 1、30、31、60、61 分钟分别命中预期边界。
- 0、负数、`NaN`、`Infinity` 返回 `null`，不产生费用。
- 该函数只接受新区间模式；现有 `unit` 继续使用原单位取整逻辑，legacy `tiered` 不进入该函数。
- 本次后台配置和规则快照可使用该函数；具体订单加收落账链路仍按原按时计价实施计划推进，不在本次扩大修改范围。

## 展示摘要

- 单价模式：`¥5/30min`
- 区间模式：`1–30min ¥10 · 31–60min ¥18 · 61min以上 ¥25`
- 区间较多时列表最多展示前三档，后接 ` · 共 N 档`，其中 N 是总档数。例如四档显示前三档后追加 `· 共 4 档`；完整内容在编辑抽屉展示。

## 校验与错误反馈

- 未形成“有限区间 + 以上末档”：提示「请至少设置一个时间区间和一个以上区间」。
- 结束分钟无效或未递增：提示「区间结束时间必须按分钟递增」。
- 金额无效：提示「请填写大于 0 且最多两位小数的区间价格」。
- 校验失败时不关闭抽屉，不写入规则存储。

## 草稿生命周期

- 只在同一次抽屉打开期间，切换两种计价方式时保留两套未保存草稿。
- 取消、关闭或保存后清空当前抽屉草稿。
- 每次新建使用两套默认值；编辑规则只回填已保存的计价方式，另一方式初始化为默认值。
- 从编辑规则 A 切换到规则 B 时必须完全重置两套草稿，禁止跨规则复用。

## 验收标准

1. 新建规则可在两种计价方式中二选一，界面不会同时提交两套配置。
2. 单价模式创建、编辑和摘要保持原行为。
3. 可创建 1–30、31–60、61 以上三档规则并正确显示摘要。
4. 末档始终为“以上”且不可删除；删除/新增有限档后起点自动连续重算。
5. 非递增终点、零/负金额、缺少有限档或末档时保存失败。
6. 编辑区间规则能完整回填；切换模式再切回时未保存草稿仍在。
7. 旧 `unit` 规则和旧场景兼容逻辑不受影响。
8. 存储、UI 静态契约、TypeScript 与独立生产构建验证通过。
9. Store 测试覆盖：中间/多个 `null`、`NaN`、`Infinity`、小数分钟、三位小数金额均被拒绝；合法 interval 保存并重读成功。
10. 纯计价测试覆盖 1、30、31、60、61 分钟以及 0、负数和非有限时长。
11. 四档摘要只展示前三档并追加 `共 4 档`。
12. 旧 `tiered.tiers` 记录经过读取、启停或保存其他规则后，`pricing.tiers` 及除 `enabled`、`updatedAt` 外的字段保持结构等价；点击编辑只提示旧结构暂不支持，绝不进入可保存表单。
13. 取消后重新新建、编辑 A 后编辑 B、保存后再次编辑均不会串用上一轮草稿。
