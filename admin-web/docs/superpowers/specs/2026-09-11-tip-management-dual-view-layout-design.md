# 小费管理双视角页面布局设计

## 目标

小费管理的“分配汇总”和“员工对账”采用同一页面内的 Tab 切换。两个视角共享小费分配上下文，但分别提供按日期和按员工的查看方式。调整只改变信息架构和交互组织，不改变既有分配业务规则。

## 信息架构

侧栏继续保留“小费分配”作为入口，页面内容区不重复展示“小费分配”标题。内容区顶部直接展示两个一级视角 Tab：

- 分配汇总：按日期查看分配任务与分配结果。
- 员工对账：按员工查看选定周期内的汇总与明细入口。

“分配规则”仍是小费管理下的独立页面，不并入视角 Tab。

## 页面布局

从上到下依次为：

1. 顶部视角栏：左侧为“分配汇总 / 员工对账”Tab，右侧为“新建/查看规则”。
2. 筛选区域：根据当前视角展示相应筛选条件。
3. 指标区域：展示当前视角对应的汇总指标。
4. 数据列表：按日期或员工展示结果。
5. 固定底部操作栏：根据当前视角展示可用操作。

Tab 始终位于筛选区域之外，不受筛选区域折叠状态影响。

## 分配汇总视角

### 筛选条件

- 日期范围，默认今天往前一个月且包含今天。
- 门店。
- 角色。
- 员工。
- 日期顺序，默认倒序并记忆用户选择。

### 汇总指标

- 原始小费。
- 入池金额。
- 已分配。
- 未分配。
- 小费池数量。

### 列表

列表按日期展示，每个日期只出现一次。日期表头与“日期顺序”筛选联动，支持顺序和倒序切换。点击日期或“查看明细”进入对应日期的小费分配明细。

### 底部操作

- 取消分配。
- 导出结果：导出当前日期范围、门店及筛选条件下的日期任务结果。
- 分配小费。

## 员工对账视角

### 筛选条件

当前阶段仅保留共享的日期范围和门店上下文，不展示角色、员工和日期顺序筛选。后续如员工数量或业务复杂度增长，再单独设计员工对账筛选能力。

### 汇总指标

- 员工数。
- 班次。
- 工时。
- 分配前。
- 扣除。
- 分配获得。
- 实际获得。

### 列表

列表按员工唯一聚合，同一员工在选定周期内只出现一次。展示员工、角色、班次、工时、分配前、扣除、分配获得、实际获得、状态和操作。点击员工或操作入口进入该员工周期内的对账明细。

员工范围来源于有效小费规则的接收方角色及角色下员工，并与“角色与员工”主数据保持一致。角色或员工失效时，沿用既有规则校验和阻止分配逻辑。

### 数据来源与聚合口径

- 员工身份使用“角色与员工”主数据中的稳定员工 ID 去重，不按姓名去重。
- 班次、工时与考勤状态复用现有员工对账数据源及现有口径；手动录入工时继续读取小费分配明细中已保存的手动工时记录。
- 分配前、扣除、分配获得、实际获得复用当前小费分配结果快照中的员工级字段，按员工 ID 和选定日期范围求和。
- 列表分配状态由周期内现有逐日分配状态聚合，不触发重新计算；具体显示规则沿用当前员工对账实现。
- 指标使用列表同一份聚合结果计算，确保指标与列表合计一致。此次布局方案不得创建新的金额、工时或状态计算公式。

### 底部操作

仅展示“导出结果”，导出当前日期范围和门店下的员工对账结果。

## Tab 交互

- 默认进入“分配汇总”。
- 点击 Tab 立即切换内容，不打开新页面、不弹窗。
- 支持键盘左右方向键切换，并正确维护 `role="tablist"`、`role="tab"`、`aria-selected`、`tabindex` 和 `aria-controls`。
- 切换时保留日期范围和门店等共同上下文。
- 每个视角独有的筛选状态分别保留；返回该视角时恢复此前状态。
- URL 使用视角参数记录状态：分配汇总使用默认路由或 `view=date`，员工对账使用 `view=employee`。
- 刷新、浏览器前进后退以及从明细页返回时，恢复 URL 对应的视角。

### URL 与历史规则

- 规范 URL 为：分配汇总使用 `/team/tips/distribution`，员工对账使用 `/team/tips/distribution?view=employee`。
- 用户主动点击 Tab 时新增一条浏览器历史记录，使浏览器后退可以返回上一个视角。
- 首次加载遇到 `view=date` 或未知 `view` 值时，使用替换当前历史记录的方式规范化为无 `view` 参数的分配汇总 URL，不新增历史记录。
- 程序恢复视角时不得再次写入历史，避免前进后退形成循环记录。

### 明细返回与筛选恢复

- 进入日期明细时，返回目标固定为分配汇总规范 URL；进入员工明细时，返回目标固定为带 `view=employee` 的员工对账 URL。
- 日期范围、门店和各视角独有筛选继续使用当前页面已有的状态保存机制；明细入口只传递现有日期、门店、来源视角和返回方式参数，不新增业务字段。
- 如果已有返回历史可用，返回按钮优先回到上一条小费分配页面历史；没有可用历史时使用上述固定目标 URL。
- 返回汇总页后，先恢复已保存的共同筛选，再恢复目标视角的独有筛选；缺少已保存值时使用该筛选的默认值。

## 新建/查看规则

“新建/查看规则”属于整个小费分配模块，在两个视角下均可见。点击后沿用既有逻辑：

- 无规则时直接进入小费池新增页。
- 已有规则时进入规则列表页。

## 响应式布局

- 桌面端：Tab 与规则按钮左右分布；筛选字段尽量保持单行。
- 窄屏端：顶部区域改为纵向排列，Tab 占满可用宽度，两个 Tab 等宽；规则按钮另起一行。
- 数据列表可横向滚动，不压缩关键金额和状态字段。
- 固定底部操作栏不得遮挡最后一行数据，内容区预留相应底部空间。

## 状态与异常处理

- 数据加载中：指标与列表显示统一加载状态，Tab 仍可操作。
- 空数据：在当前视角的列表区域展示空状态，不隐藏筛选条件和 Tab。
- URL 包含未知 `view` 值时回退到“分配汇总”。
- 切换视角不触发小费重新计算或分配，仅切换展示数据。
- 导出、分配和取消分配继续使用既有错误提示与权限校验。

## 权限边界

- “分配汇总”和“员工对账”继承同一个“小费分配”页面访问权限，不新增独立权限点。
- 只有具备小费分配页面查看权限的用户才能访问员工对账视角及员工对账明细。
- 分配、取消分配、规则编辑和导出继续执行各自现有的操作权限校验；切换到员工对账不会提升用户权限。
- 用户直接访问无权限的员工对账 URL 时，沿用小费分配页面现有的无权限处理，不渲染员工数据。

## 验收标准

1. 页面内不再显示独立的“小费分配”可见标题。
2. “分配汇总 / 员工对账”Tab 位于原页面标题区域且始终可见。
3. 两个 Tab 的点击、键盘、刷新、前进后退和明细返回行为正确。
4. 切换视角后共同筛选上下文得到保留。
5. 两个视角分别展示规定的筛选条件、指标、列表和底部操作。
6. 分配、取消分配、导出、规则入口以及明细入口的既有业务逻辑不变。
7. 桌面端和窄屏端布局均无重叠、溢出或底部操作栏遮挡。
8. 点击 Tab 会产生可后退的历史记录；未知或冗余视角参数会被替换为规范 URL，且不形成历史循环。
9. 从日期明细和员工明细返回时恢复正确视角、共同筛选和各视角独有筛选；无历史记录时仍能回到规定的兜底 URL。
10. 员工以稳定员工 ID 唯一聚合，指标与列表来自同一现有数据口径且合计一致。
11. 无小费分配查看权限的用户不能通过员工对账 URL 或员工明细入口读取数据。
