# 1. 背景与目标

## 1.1 业务场景

门店服务员持 eMenu 进入 KTV/VIP 包间，需完成：

1. 为包间**开单并开始计时**；
2. 将 eMenu 交给食客，食客在计时期间**继续点餐**；
3. 离店前由服务员**授权结束计时**，系统按规则计算**计时费用**并与点单费用一并结算。

## 1.2 核心目标

- 支持配置**按时计价规则**（按时长单价或时段阶梯）。
- 规则创建后**绑定到具体桌位（包间）**。
- eMenu 选桌后展示**开单计时**；计时中可点单；**结束计时需服务员授权**。
- 与现有 seq 443（功能总闸）、餐位平面图、eMenu 选桌/登录流程衔接，不重复造轮子。

## 1.3 非目标（首期）

- 不新增「前厅管理中心」二级导航页（规则管理内嵌 seq 443 设置，见场景 1 方案 B）。
- 不实现食客自助结束计时。
- 不将计时费与点单费合并为单一不可分项（须分开展示）。
- 不保证离线场景下计时精度（以服务端/订单时间戳为准）。

# 2. 术语

| 术语 | 定义 |
|---|---|
| 按时计价规则 | 描述「多长时间收多少钱」的配置对象，含单价模式或时段阶梯模式 |
| 功能总闸 | seq 443「按照时长收费」主开关及 KTV/VIP 场景多选 |
| 桌位绑定 | 餐位平面图中桌位 `durationBillingRuleId` 指向某条规则 |
| 计时单 | 开单计时后创建的会话/订单扩展状态，记录 `startedAt`、规则快照、状态 |
| 规则快照 | 开单时复制的规则内容，进行中订单计价不受后台规则后续修改影响 |
| 计时费 | 按规则与时长计算的费用，作为订单**加收项** |
| 点单费 | 计时期间点餐产生的商品金额，与计时费分开展示 |


# 4. 场景 1 · 按时计价规则（方案 B）

## 4.1 入口与信息架构

**路径（不新增 L2）：**

```text
前厅管理中心 → 设置 → 食客端·下单与规则 → 计时与自助餐规则
  └─ 按照时长收费（seq 443）
       ├─ 主开关
       ├─ 适用场景多选：KTV / VIP包间（已有）
       └─ [443 开启后展开] 按时计价规则管理
            ├─ 规则列表
            ├─ + 新建规则
            └─ 抽屉：编辑规则
```

**与同分组其他 seq 的职责分离：**

| 能力 | seq | 职责 |
|---|---|---|
| 按时计价 / 规则库 | 443 | **怎么算钱** |
| 用餐时长限制 | 674 | **限制最长用餐时间**（可选并存） |
| 展示/倒计时/提示 | 577–580 | **怎么展示时长**（UI 可复用，不算价） |

## 4.2 规则列表（内嵌区）

443 主开关开启后，在同设置卡片下方展示规则管理区。

**列表字段：**

| 字段 | 说明 |
|---|---|
| 规则名称 | 如「工作日白天」「周末黄金档」 |
| 适用场景 | KTV / VIP包间（须被 443 场景勾选包含） |
| 计价模式摘要 | 如「¥5/30min」或「09:00–18:00 ¥10/h · 18:00–24:00 ¥20/h」 |
| 状态 | 启用 / 停用 |
| 操作 | 编辑、停用/启用、删除（删除需二次确认，自定义对话框） |

**交互：**

- 「+ 新建规则」→ 右侧**抽屉**打开编辑表单（定稿：抽屉，避免同页过长）。
- 443 关闭 → 规则管理区整体隐藏（数据保留，再次开启可恢复展示）。
- 443 场景取消勾选某场景 → 该场景下已有规则标记为不可用或编辑时禁止保存。

## 4.3 规则编辑（抽屉）

### 4.3.1 基本信息

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 规则名称 | 文本 | 是 | 1–32 字 |
| 适用场景 | 多选 | 是 | KTV / VIP包间，须在 443 已勾选范围内 |
| 状态 | 开关 | 是 | 启用 / 停用 |
| 备注 | 文本 | 否 | 内部说明 |

### 4.3.2 计价模式（二选一）

**模式 A：按时长单价**

| 字段 | 说明 | 示例 |
|---|---|---|
| 金额 | 每单位金额 | ¥5 |
| 单位时长 | 分钟数 | 30（即每 5 元 / 30 分钟） |
| 进位规则 | 不足 1 单位 | 向上取整到 1 单位（默认） |

**模式 B：时段阶梯**

| 字段 | 说明 |
|---|---|
| 时段列表 | 多条，每条：开始时间、结束时间、计价方式 |
| 单段计价 | 该时段内按「金额/单位时长」或「该时段封顶价」 |

示例：

- 09:00–18:00：¥10 / 60min  
- 18:00–24:00：¥20 / 60min  

**可选扩展（P1 可先做字段预留）：**

- 最低消费（开单后最低计时费）
- 封顶时长（超过后不再累加或按封顶价）
- 跨日处理（结束时间早于开始时间视为次日）

### 4.3.3 生效范围

| 字段 | 说明 |
|---|---|
| 适用门店 | 默认当前门店；连锁视角可多选（与下发机制对齐） |
| 适用产线 | 固定 eMenu（首期）；结构预留 POS 扩展 |

### 4.3.4 保存与校验

- 名称必填；至少一种计价模式完整配置。
- 时段阶梯各段不可重叠（同规则内）。
- 删除规则：若仍有桌位绑定，提示「N 个桌位仍绑定此规则，确认删除？」（自定义确认对话框）。
- 保存后写入规则库；**不影响进行中计时单**（见 5.3）。

## 4.4 数据模型（规则）

```typescript
type DurationBillingScene = "ktv" | "vip-room";

type DurationBillingPricingMode =
  | { type: "unit"; amount: number; unitMinutes: number; roundUp: boolean }
  | {
      type: "tiered";
      tiers: Array<{
        start: string; // "HH:mm"
        end: string;
        amount: number;
        unitMinutes: number;
        roundUp?: boolean;
      }>;
    };

type DurationBillingRule = {
  id: string;
  name: string;
  scenes: DurationBillingScene[];
  enabled: boolean;
  remark?: string;
  pricing: DurationBillingPricingMode;
  storeIds: string[];
  lines: ("emenu")[];
  createdAt: string;
  updatedAt: string;
};
```

存储：首期可与餐位平面图类似按门店隔离（localStorage / 后续下发 API）；与 seq 443 开关联动展示。

# 5. 场景 2 · 餐位平面图绑定规则

## 5.1 入口

**路径：** 前厅管理中心 → 餐位平面图（seq 428）→ 选中桌位 → 编辑弹窗

## 5.2 新增字段

在现有桌位表单（名称、座位数、形状、类别等）中增加：

| 字段 | 类型 | 说明 |
|---|---|---|
| 按时计价规则 | 下拉单选 | 可选「不绑定」+ 已启用且场景匹配的规则列表 |

## 5.3 展示条件

同时满足才展示该字段：

1. seq 443 在当前门店/场景下**已开启**；
2. 桌位**类别**为包间类（如 `private` / 扩展 KTV 类别，与平面图 `FloorPlanTableCategory` 对齐）；
3. 至少存在一条**启用**且场景与桌位用途匹配的规则。

否则：字段隐藏或禁用，并提示「请先在设置中启用按照时长收费并创建规则」。

## 5.4 画布视觉

- 已绑定规则的包间桌位：角标或图标（如 ⏱ / 「计时」）+ tooltip 规则名称。
- 未绑定：无角标；eMenu 侧不展示开单计时。

## 5.5 绑定语义

| 情况 | 行为 |
|---|---|
| 未绑定 | eMenu 选该桌后不展示「开单计时」 |
| 已绑定 | eMenu 选桌后读取 `durationBillingRuleId`，展示规则摘要 |
| 规则停用 | 绑定保留但 eMenu 开单时提示规则不可用，禁止新开计时 |
| 规则删除 | 绑定点清空；保存平面图时校验 |
| 规则内容变更 | **仅影响新开计时单**；进行中订单使用**开单时规则快照** |

## 5.6 桌位模型扩展

```typescript
type FloorPlanTable = {
  // ...existing fields
  durationBillingRuleId?: string | null;
};
```

## 5.7 批量绑定（P2）

- 多选桌位 → 「批量绑定按时计价规则」。
- 首期可不做，单桌编辑即可满足 KTV 包间场景。

# 6. 场景 3 · eMenu 开单计时与结束计时

## 6.1 前置条件

| 条件 | 说明 |
|---|---|
| 产线 | eMenu |
| 443 | 门店已开启，场景含 KTV/VIP |
| 桌位 | 已绑定启用状态的规则 |
| 服务员 | 开单/结束操作需服务员登录（现有 AdminLogin / 服务员模式） |

## 6.2 流程

```text
1. 服务员登录 eMenu
2. 选择包间桌位（仅展示已绑定规则的包间可开计时，或选桌后判断）
3. 进入首页
   - 未计时：展示「开单计时」主按钮 + 规则摘要
4. 点击「开单计时」
   - 创建/关联计时单，记录 startedAt + 规则快照
   - 状态 → timing
5. 计时中
   - 顶部计时条：已用时长 + 预估计时费
   - 点单、购物车、服务等入口正常可用（食客模式）
6. 结束计时
   - 仅服务员入口；触发 seq 346 主页密码授权
   - 确认：时长、计时费、点单费分项
7. 计时费写入订单加收项；进入结账或继续点单（按门店策略）
```

## 6.3 首页状态 UI

### 6.3.1 未开计时（idle）

| 区域 | 内容 |
|---|---|
| 桌位信息 | 包间名、绑定规则名称摘要 |
| 主操作 | **开单计时**（醒目主按钮） |
| 可见性 | 仅服务员登录可见；食客未登录不展示 |

### 6.3.2 计时中（timing）

| 区域 | 内容 |
|---|---|
| 计时条（顶部常驻） | 已用时长 `HH:MM:SS`；右侧预估计时费 |
| 主内容 | 常规点餐首页（分类、商品） |
| 结束入口 | 「结束计时」— 弱样式或服务员菜单内，避免食客误触 |

计时条展示可复用 seq 577/578 的产线配置（正计时 vs 倒计时）；**计价逻辑独立于 674 用餐时长限制**。

### 6.3.3 已结束（ended）

- 计时条显示最终时长与计时费（只读）。
- 若仍有未结账点单，引导结账；清台逻辑与现有清桌流程一致。

## 6.4 结束计时授权

**定稿：复用 seq 346「主页密码权限」**（eMenu 产线启用时）。

| 步骤 | 说明 |
|---|---|
| 1 | 服务员点击「结束计时」 |
| 2 | 自定义确认对话框：展示时长、计时费、点单费分项 |
| 3 | 输入服务员 PIN/密码（与 346 同一套校验） |
| 4 | 校验通过 → 写入 `endedAt`，计算最终计时费，状态 → ended |
| 5 | 失败 → Toast 提示，保持 timing 状态 |

不使用 `window.confirm` / `alert`；统一 `openConfirmDialog` / `showAppToast`。

## 6.5 计时费计算

**输入：** 规则快照、`startedAt`、`endedAt`（或当前时间用于预估）

**单价模式：**

```text
units = ceil((endedAt - startedAt) / unitMinutes)   // roundUp 为 true 时
fee = units * amount
```

**时段阶梯模式：**

- 按时间轴切段，每段适用对应 tier 的单价规则；
- 跨段分别计算后求和（实现细则在 emenu 子 spec 展开）。

**预估 vs 结算：**

- 计时中：按当前时间实时预估，定时刷新（如 30s 或每分钟）。
- 结束：以 `endedAt` 一次性结算，写入订单。

## 6.6 订单与费用

| 项目 | 处理 |
|---|---|
| 计时费 | 订单**加收项**（surcharge），名称如「包间计时费」 |
| 点单费 | 原有 line items |
| 展示 | 结账页/购物车摘要分开展示，禁止合并为一行「总计」蒙混 |

扩展字段建议（eMenu 订单 `emenuKioskextendedInfo` 或等价结构）：

```typescript
type DurationBillingSession = {
  status: "idle" | "timing" | "ended";
  ruleSnapshot: DurationBillingRule;
  startedAt?: string;
  endedAt?: string;
  estimatedFee?: number;
  finalFee?: number;
  authorizedBy?: string; // staff id
};
```

## 6.7 状态机

```text
idle ──[开单计时/服务员]──► timing ──[结束计时+授权/服务员]──► ended
  ▲                              │
  └──────── 清台/新单 ────────────┘（ended 后开新单回到 idle）
```

| 状态 | 食客可点单 | 服务员可开单 | 服务员可结束 |
|---|---|---|---|
| idle | 视门店策略 | 是 | 否 |
| timing | 是 | 否 | 是（需授权） |
| ended | 视门店策略 | 否（需新单） | 否 |

## 6.8 权限矩阵

| 操作 | 服务员 | 食客 |
|---|---|---|
| 选桌 | 是 | 否（首期） |
| 开单计时 | 是（已登录） | 否 |
| 点单/加菜 | 是 | 是（timing） |
| 查看预估计时费 | 是 | 是（只读） |
| 结束计时 | 是（346 授权） | 否 |

# 8. 异常与边界

| 场景 | 处理 |
|---|---|
| 443 关闭 | 规则管理隐藏；已绑定桌位 eMenu 不可新开计时 |
| 规则停用 | 不可新开计时；进行中按快照继续 |
| 桌位未绑定规则 | 无「开单计时」入口 |
| 换桌 | 计时单绑定原桌位；换桌需先结束或迁移策略（首期：必须先结束） |
| 一桌多单 | 与 seq 592「不允许一桌多单」协调：计时单与点餐单同一 order 或扩展字段挂载 |
| 网络中断 | 开单/结束以服务端时间为准；恢复后同步 |
| 设备被食客长按结束 | 无授权入口，仅服务员可见结束 |

# 9. 验收标准

## 9.1 场景 1（后台规则）

- [ ] 443 关闭时规则管理区不可见；开启后可见列表与新建。
- [ ] 可创建单价规则（如 ¥5/30min）并保存。
- [ ] 可创建时段阶梯规则并保存；重叠时段校验失败。
- [ ] 删除已绑定规则时有二次确认及绑定数量提示。

## 9.2 场景 2（平面图）

- [ ] 包间桌位编辑可下拉选择规则；非包间类别不展示字段。
- [ ] 443 未开启时字段禁用并提示。
- [ ] 画布已绑定桌位有角标；保存后持久化。

## 9.3 场景 3（eMenu）

- [ ] 服务员选已绑定桌位 → 首页见「开单计时」。
- [ ] 开单后计时条走动，预估费用更新。
- [ ] 计时中可正常加购、送厨（与现有点餐一致）。
- [ ] 食客无法结束计时。
- [ ] 服务员结束需 346 密码；成功后计时费写入加收项。
- [ ] 结账页计时费与点单费分开展示。
