# 按时计价规则

> 权威设计文档（SSOT）  
> 最后更新：2026-08-25
> 模块：前厅管理中心 / 设置 / 计时与自助餐规则

## 功能范围与目标

门店按 KPOS 商品创建、编辑和删除按时计价区间。KPOS `HourlyRate` 是唯一权威数据源；后台与 eMenu 均不得再以浏览器 localStorage 规则作为运行时事实。后台规则不区分 KTV 或 VIP 包间，不依赖 seq 443「按照时长收费」总闸。

本功能完全遵循 KPOS 原生 `HourlyRate` 行模型。每个时间区间独立选择一种收费方式，同一商品的多个区间允许混合使用：

- 固定收费：进入该区间后收取一次 `fixPrice`。
- 按单位计费：该区间内按 `price / step` 计费，不足一个单位向上取整。

最终费用为所有已经进入区间的费用累计值，不再使用“只收取命中档”的旧逻辑。

## 当前有效口径

1. 「计时与自助餐规则」直接展示组级「按时计价规则」管理区。
2. 不展示「按照时长收费」功能项，不选择 KTV / VIP 包间。
3. 每个区间行独立选择「固定收费」或「按单位计费」，两种字段在同一行只能二选一；不同区间允许混合。
4. 区间必须从 0 分钟开始连续排列，不允许断档或重叠；最后一档可设置为“以上”。
5. 每个 KPOS 商品只对应一组按时计费区间；商品名称就是规则名称，不再维护自定义规则名、启用状态和备注。
6. 存在至少一条 KPOS `HourlyRate` 即表示该商品已启用按时计费；删除全部区间即删除该商品的计费规则。
7. 正式 KTV 计时收费必须使用主机 POS 返回的商品，并以普通订单商品行承载费用，不再生成独立计时 surcharge。

## 页面与交互设计

### 规则列表

列表按商品展示 KPOS 返回的计价摘要及编辑/删除操作，不提供独立启停按钮。

- 单价摘要：`0–200min ¥5/30min`
- 混合摘要：`0–200min 固定 ¥100 · 200–300min ¥5/30min · 300min以上 ¥10/60min`
- 超过三档时只展示前三档并追加 `· 共 N 档`。

### 规则抽屉

通用字段只有计时收费商品和计价区间。规则名称只读取商品名称；不再保存独立启用状态和备注。

规则必须从主机 POS 的 KTV 商品列表中选择一个商品。该列表与编辑桌子中的【KTV/卡拉OK】房间完全同源，统一调用 `FindSaleItemsType` 并传入 `onlyKTVItem=true`。每个商品最多存在一组规则；已配置商品不可重复新建。

每个区间行使用独立单选控件：

- `固定收费`：只填写固定金额并只提交 `fixPrice`。
- `按单位计费`：填写金额和单位分钟，只提交 `price + step`。

切换单行收费方式时保留当前抽屉周期内的另一组草稿，但保存时只提交该行选中的字段。取消、关闭、保存或打开另一条规则时重置草稿。

旧 `tiered.tiers` 仅能通过显式一次性迁移入口预览；常规列表与编辑流程不得读取该结构，也不得把它作为 KPOS 查询失败时的回退数据。

### 区间编辑器

1. 第一档起点固定为 0 分钟。
2. 有限档填写结束分钟、收费方式及对应价格字段。
3. 下一档起点自动等于上一档结束分钟，边界按 `[from,to)` 处理。
4. 最后一档可填写结束分钟，也可选择“无上限”；`to` 缺省时展示“X 分钟以上”。
5. 至少保留一个区间；可新增和删除任意非首档区间，删除后重新连续计算起点。

## 字段、数据模型与存储

规则直接存储在当前主机 KPOS 的按时计费数据中，使用 `/kpos/ws/kposService`。运行时禁止读取或写入 `bplant-duration-billing-rules:v1`；该键只允许作为一次性人工迁移来源，迁移完成后不参与回退。

```ts
type DurationBillingRate = {
  id?: string;
  fromMinutes: number;
  toMinutes: number | null;
  charge:
    | { type: "fixed"; amount: number }
    | { type: "unit"; amount: number; unitMinutes: number; roundUp: true };
};

type KposHourlyRate = {
  id: string;
  saleItemId: string;
  from: number;       // KPOS 为 0 基边界
  to?: number;        // 缺省表示以上
  step?: number;      // 按时长单价的单位分钟
  price?: number;     // 按时长单价
  fixPrice?: number;  // 区间固定总价
};
```

KPOS SOAP 契约已经在 `192.168.96.96:22080` 实机确认：

- 查询：`ListHourlyRatesBySaleItemType`，返回 `saleItems[].id` 与 `saleItems[].hourlyRates[]`。
- 新建/修改：`SaveHourlyRateType`，提交 `<hourlyRate>` 中的 `id/from/to/step/price/fixPrice/saleItemId`；新建不传 `id`。
- 删除区间：`DeleteHourlyRateType`，提交区间 `id`。
- 商品：`FindSaleItemsType(true)`。

UI 与 KPOS 一一映射：`0–200` 固定 ¥100 写入 `from=0,to=200,fixPrice=100`；`200–300` 每 30 分钟 ¥5 写入 `from=200,to=300,price=5,step=30`；`300+` 每 60 分钟 ¥10 写入 `from=300,to` 缺省、`price=10,step=60`。读取时执行逆映射。

区间边界按 KPOS 相邻边界模型保存：首档必须 `from=0`，有限档要求 `to` 为正整数，相邻档必须 `next.from === previous.to`，只有最后一档可以缺省 `to`。UI 与 KPOS 均使用 0 基半开区间 `[from,to)`，不再转换成旧的 1 基标签。

严格解析规则：

- `fixed` 行：`fixPrice>0`，`price/step` 必须缺省。
- `unit` 行：`price>0`、`step` 为正整数、`fixPrice` 必须缺省；不足一个单位向上取整。
- 同一商品允许 fixed 与 unit 行混合；单条有限范围 unit（例如实机 `from=0,to=100,price=5,step=10`）属于合法 KPOS 规则。
- 读取 `hourlyRates[]` 后先按 `from` 升序规范化，再执行连续性校验；同起点重复行、排序后重叠仍判非法。快照 hash、差异比较、保存后回读验收均使用这一规范化顺序，不能依赖 SOAP 原始数组顺序。
- XML 缺字段、空字符串归一为缺省；数值 `0` 不视为缺省且属于非法价格/步长。
- 同一行同时存在 `price` 与 `fixPrice`、unit 缺少 `step`、非法数值、首档非 0、断档、重叠或多个无上限档时，该商品进入只读错误态；其他商品仍正常读取和新建。唯一例外是本客户端已记录目标快照的整组替换中断，此时进入下述专用“替换恢复态”。
- 旧 `roundUp=false`、无商品绑定、重复商品绑定或 legacy `tiered.tiers` 不可自动迁移，只能在迁移预览中显示原因。

餐位平面图的 KTV 桌台继续把绑定商品保存为 KPOS `defaultSaleItemId`。该商品 ID 同时作为计时规则关联键，不再依赖本地 `durationBillingRuleId`。桌台从 KTV 切换为其他类型时清空商品绑定；存在进行中计时会话时禁止切换类型或商品。

## 业务规则与异常处理

### 区间校验

- 至少一档，首档 `from=0`；后一档 `from` 必须等于前一档 `to`。
- 每档结束分钟必须大于开始分钟；最后一档可填写有限 `to`，也可留空表示无上限。无上限档至多一个且只能位于最后。
- 每档必须且只能选择一种收费方式：固定收费填写 `fixPrice`；按单位收费填写 `price` 与正整数 `step`。
- 金额必须为有限数、大于 0 且最多两位小数；时间边界和 `step` 必须为非负/正整数。
- DOM 限制之外，Store 必须再次执行完整校验。

错误提示：

- 档位不足：`请至少设置一个时间区间`
- 时间无效：`时间区间必须从 0 分钟开始且连续、不重叠`
- 收费方式无效：`每个时间区间必须选择固定收费或按单位收费，且只能选择一种`
- 金额无效：`请填写大于 0 且最多两位小数的收费金额`

### 区间求价

`resolveDurationBillingAmount(rates, durationMinutes)` 先把正数时长向上取整到分钟，再计算每个区间与 `[0, durationMinutes)` 的交集时长并累计：

- 未进入的区间计费为 0。
- 固定收费区间只要交集时长大于 0，就累计一次 `fixPrice`。
- 按单位收费区间累计 `ceil(交集分钟数 / step) * price`。
- `durationMinutes` 为 0 时返回 0；负数、`NaN`、`Infinity` 或规则非法时返回 `null`。

示例规则为 `0–200min 固定 ¥100`、`200–300min ¥5/30min`、`300min以上 ¥10/60min`，直接测试期望为：`0→¥0`、`1→¥100`、`199→¥100`、`200→¥100`、`201→¥105`、`250→¥110`、`300→¥120`、`301→¥130`。

## 关联模块及上下游影响

- eMenu KPOS 规则读取：通过 `ListHourlyRatesBySaleItemType` 获取当前主机规则，按桌台 `defaultSaleItemId` 精确匹配并注入规则快照；禁止回退浏览器规则键。
- eMenu 数据路径：生产 eMenu 与 KPOS 同源，直接以 `credentials: include` POST `/kpos/ws/kposService`；不经商家后台 localStorage 或 iframe 消息桥接。桌台加载、切桌后查询一次；Landing 开单事务必须强制 fresh 查询。仅允许 30 秒内展示缓存，缓存键为 `location.origin + PC License/instanceName`，切换主机、License 或身份时立即失效。SOAP 超时、Fault、空响应或认证失效时不展示/不允许开单，并显示可诊断错误，不回退旧缓存或 localStorage。
- eMenu 计时会话：开单时冻结规则快照并写入 `emenu_table.currentOrder.emenuKioskextendedInfo.durationBilling`；计时中每 30 秒更新预估费用，结束时固化最终费用和授权信息，同时保留扩展字段中的其他业务数据。
- 主机 POS 商品同步：规则编辑器与桌台【KTV/卡拉OK】房间共用 `loadKposKtvSaleItems()`、主机、License、SOAP 请求和连接级缓存。主机未连接或读取失败时不允许保存规则。
- 餐位平面图：桌台类型明确选择 `KTV` 后显示计时商品字段；商品存在 KPOS HourlyRate 才具备计时能力，不检查 seq 443。
- eMenu：通过 `category === "ktv"`、`shape === "KTV"` 或 `kposShape === "KTV"` 兼容识别 KTV 桌位；`defaultSaleItemId` 无有效 KPOS HourlyRate 时不展示开单计时。开单事务再次校验桌型、商品 ID 和费率快照。
- eMenu Landing：移除首页上方独立的计时规则卡片和其中的「开单计时」按钮。KTV 桌未计时时，中央大圆按钮文案由「开始点单」改为「开单计时」并作为唯一计时开单入口；计时中首页计时条删除桌台/商品标题（如 `KTV - KTV1`）和预估费用，只保留每秒更新的已用时长，以及仅在具备结束权限时显示的「结束计时」按钮，不读取 seq 443。开单计时成功后，必须先把返回的完整订单及真实 `orderId` 设为当前订单，再定向刷新该订单并直接进入菜单页，不得再次要求选择订单号；开单或刷新失败时留在首页并提示失败。
- eMenu KTV「开始点单」：KTV 桌未计时时，大圆形「开始点单」必须复用「开单计时」的同一事务，不得走普通开单；规则缺失、读取失败或商品不匹配时阻止开单并提示。KTV 桌已计时时点击「开始点单」直接进入当前计时订单，不重复创建商品或会话。非 KTV 桌保持原普通开单逻辑。两个 KTV 开单入口必须调用同一处理函数，避免行为分叉。
- eMenu 计时状态恢复：订单刷新或轮询写回 `emenu_table.currentOrder` 时，同一订单若服务端暂未返回 `durationBilling`，必须合并保留本地计时会话；服务端已返回会话时以服务端为准，不同订单、无效订单或换桌不得继承。计时中返回首页必须展示计时状态，并按当前权限展示结束入口；无结束权限时只展示计时时长，不得再次展示「开单计时」。
- eMenu 清桌状态：计时会话必须与 `currentOrder.id` 一致。清桌后当前订单为空，或会话 `orderId` 与当前订单不一致时，历史 `timing/ended` 会话一律失效并恢复 `idle`，满足配置的 KTV 新桌重新展示「开单计时」。所有同页 `emenu_table` 写入必须发出状态变化通知，使 Landing 内存状态即时同步，不依赖刷新或重新挂载。
- eMenu 桌台上下文隔离：`tableId + orderId` 共同定义当前上下文。切换桌台或订单时必须清空上一上下文的购物车、会员及临时点单数据，并从新桌当前订单重新读取计时会话；不得把上一桌的订单或计时状态带入新桌。返回原桌时仅恢复原桌自身订单中保存的状态。
- eMenu 开始计时：复用现有 `/order/save` 普通商品下单链路，不依赖 `/order/duration-billing/item/start` 自定义接口。根据 `defaultSaleItemId` 从当前 eMenu 菜单取得完整商品结构，并强制 fresh 查询 KPOS HourlyRate；菜单或费率不可用时阻止开单。开单前预生成 `sessionId`，写入订单级 `emenuKioskextendedInfo.durationBillingPending`（包含 `sessionId`、`saleItemId`、HourlyRate 区间 ID 列表、规范化费率快照及其 hash），并创建数量 1、成交价 ¥0 的已下单商品行；标题使用 POS 商品名称。只有 POS 返回真实 `orderId` 与 `orderItemId` 后才启动计时。首次保存超时或响应丢失时通过 `/table/fetch?id=<tableId>` 获取桌台当前订单，按该标识及商品 ID、数量 1、成交价 ¥0 唯一找回；无法确认时锁定再次开单并提示 POS 员工核对。
- KPOS 多区间保存协议：保存前强制 fresh read，以服务器区间 ID 为基线生成操作计划。区间拓扑和行收费方式不变时，`price`、`fixPrice` 或 `step` 的单独/组合变化均按原 ID 原位更新；档位合并、拆分、公共边界变化或任一行 `fixed ↔ unit` 切换采用整组替换：先按 `from` 从大到小删除旧区间，再按 `from` 从小到大创建目标区间，保证重建首条始终从 0 开始。KPOS 原生页面只允许删除末档且新增首档要求 `from=0`，因此不得使用固定“更新 → 新增 → 删除”顺序。每个成功操作记录返回/回读 ID，任一步失败立即停止，不执行后续操作，不盲目回滚或重放新增；随后强制 re-read。只有回读与目标规范化快照完全一致才报告保存成功。整组替换期间可能短暂无规则，界面必须保持处理中并禁止同商品并发编辑；活动计时继续使用冻结快照。
- 替换恢复态：开始整组替换前持久化一次恢复意图，包含 `saleItemId`、原始区间 ID/原始快照、目标规范化快照、目标 hash、阶段和逐步结果。删除或重建中断后，回读所得原始 HourlyRate 即使不完整也不得进入普通领域编辑器；页面展示失败明细，并只提供“继续恢复”和“关闭”操作。“继续恢复”必须再次 fresh read，核对商品与恢复意图，按当前服务器原始行 `from` 倒序清理残留，再从目标首档正序重建；不得重放已不存在的删除或盲目新增。回读等于目标后清除恢复意图。若服务器已被其他终端改成无法归属该意图的结构，则停止恢复并进入人工处理，不自动覆盖。未知来源的非法数据仍使用普通只读错误态。
- 删除规则协议：删除开始前通过 KPOS FloorPlan 查询所有 `defaultSaleItemId` 相同的桌台；存在绑定时阻止删除并列出桌台，要求先解除绑定。无绑定时按 `from` 从大到小逐条删除，任一步失败立即停止并回读。删除完成后再次查询 FloorPlan 和 HourlyRate；只有仍无桌台绑定且 `hourlyRates=[]` 才报告成功。由于 KPOS 未提供跨 FloorPlan 与 HourlyRate 的事务或版本令牌，两次检查之间仍存在并发竞态；若完成后出现新绑定，必须报告“桌台绑定与规则并发冲突”，该桌台按失效绑定处理并要求人工重新配置，不能宣称原子保护。活动计时会话继续使用冻结快照。
- 迁移协议：旧键只在显式“迁移本地规则”入口读取。先按 `saleItemId` 生成预览；KPOS 已有规则默认保留且禁止自动合并，只有用户逐商品明确确认“以本地规则替换 KPOS”才执行上述保存协议。本地快照 hash 只标识迁移意图，不作为跳过服务器检查的依据；每次执行或重试都必须 fresh read KPOS 并基于实际快照重新规划，只有回读已等于目标快照才跳过写入。迁移记录逐商品的成功/失败状态、本地 hash 和最后回读快照摘要；部分失败只执行回读后仍存在的差异。不可迁移规则显示原因。迁移器之外任何列表、编辑、桌台匹配和 eMenu 路径不得读取旧键。
- eMenu 计时会话：保存 `orderId`、`orderItemId`、商品快照和 KPOS 费率快照。费率在计时期间被修改或删除，不影响当前会话；每桌同时只允许一个有效会话。
- eMenu 已下单展示：使用与普通菜单商品一致的「标题 + Option + 价格」结构，名称取开单时商品快照，数量恒为 1。订单响应转换为购物车商品时，必须把 POS `orderItem.id` 显式保留为 `orderItemId`；仅当订单行对象不存在 `orderItemId` 字段时，兼容读取旧数据的 `key`，若 `orderItemId` 已存在但不匹配则不得再次回退。候选订单行 ID 与会话 `orderItemId` 都先校验为非空，再用 `String(value)` 规范化并完全相等比较。活动计时期间，仅在精确匹配的商品行中，将 `用时 HH:mm:ss` 放在 Option 占位，视觉层级与普通商品的 Option 文本（如「味增汤」）一致，并将价格位置由开单占位价 `$0.00` 替换为 `预估 ¥X.XX`。购物车必须使用独立的“预估”文案，不得修改结束确认弹窗等其他位置的“预估费用”文案。不得使用 `cartItem.id` 匹配，因为该字段是商品 `saleItemId`；也不得按商品名称模糊匹配。订单行或会话标识缺失、非法、错误或无匹配时，任何商品行都不得获得计时增强展示，结束操作继续由既有异常流程提示恢复原计时商品。用时每秒刷新，预估金额使用会话冻结规则和最终计价同一函数；冻结快照缺失或损坏、开始时间非法、计算抛错，以及结果为 `null`、`NaN` 或 `Infinity` 时，价格位置立即统一显示 `预估 --`，不得回退 `$0.00`、旧预估值或部分金额。结束计时保存失败时保持活动态和预估展示；只有 `/order/save` 成功并以成功响应或后续 fetch 确认目标行已持久化后，才在同一价格位置按普通商品货币格式展示服务端目标行最终成交价 `¥X.XX`，且不再显示「预估」前缀。
- eMenu 结束计时：仅服务员显示结束入口；确认时锁定结束时间并计算最终总价，密码授权成功后先通过 `/order/fetch` 读取最新整单，优先按 `orderItemId + sessionId` 定位原商品行；兼容旧会话时，商品 ID 依次读取 `productSnapshot.productId`、`productSnapshot.id`、`ruleSnapshot.productBinding.productId`，仅在候选唯一时回退匹配。随后复用正常订单修改逻辑，以最新整单为基线只替换目标行成交价，同时更新 `price`、`originalSalePrice`、`totalPrice`、`totalAmount`，并将订单状态设为 `PARTIALLY_SUBMITTED`，重算商品小计、税、折扣和订单总额，最后 `/order/save` 整单保存。eMenu 在该请求期间禁止自身重复提交；现有 KPOS 接口没有版本令牌，跨 POS 终端同时修改仍遵循 KPOS 当前整单保存语义，并列为联调风险，不宣称前端可提供原子并发保护。保存成功后才结束会话；结束服务未返回目标商品时不得把本地会话标记为结束；响应丢失时重新 fetch，目标行已经是相同最终价则收敛为成功。不得新增第二条商品或独立 surcharge，不依赖 `/order/duration-billing/item/finish` 自定义接口。
- eMenu 购物车底部操作：存在活动计时且开启「呼叫服务员结账」时，操作区使用一行两列，左侧发送结账呼叫、右侧执行「结束计时」；存在活动计时但该设置关闭时，以一个全宽「结束计时」替代原按钮位置。「结束计时」按钮只显示单行操作名，用时与预估金额归属已下单计时商品行，购物车标签显示为「预估」，不在按钮内重复展示。计时结束后，设置开启则恢复全宽呼叫按钮，设置关闭则不显示二者。购物车「结束计时」必须复用首页相同的费用确认、服务员授权、商品行改价和会话结束事务；KPOS 保存成功后立即以响应订单更新当前订单，并重新读取服务端订单，使 KTV 商品价格位置从活动态的 `预估 ¥X.XX` 切换为最终成交价，不得回落到开单占位价 `$0.00`。呼叫只发送通知，不绕过活动计时对实际结账的限制。
- 异常恢复：改价失败时保持会话可重试；若成功响应丢失，先查询原商品行判断是否已更新。原占位商品被删除或作废时阻止结束计时，并提示 POS 员工恢复原商品行，不自动补建商品。
- 结账约束：订单存在活动计时会话时阻止结账，并明确提示对应桌台。
- 用餐时长限制 seq 674 与展示项 577–580 可并存，但不参与计费。
- 主页密码权限 seq 346 可用于结束计时授权。

## 验收标准

1. 设置页不显示 seq 443，规则管理区始终可访问。
2. 新建规则没有 KTV/VIP 场景字段。
3. 每个区间内固定收费与按单位收费只能二选一；同一商品的不同区间允许混合两种方式。
4. 可创建、编辑并回填纯固定、纯单位和混合收费规则，摘要与 KPOS 字段一致。
5. 可保存并回填 `0–200`、`200–300`、`300 以上` 等从 0 开始的连续区间。
6. 新增/删除区间后起点自动衔接；最后一档既可有限结束，也可设置为“以上”。
7. 首档非 0、断档、重叠、非递增边界、行内混用收费字段、非法金额及非有限值在 Store 层被拒绝。
8. 0、1、199、200、201、250、300、301 分钟按累计模型得到正确价格，非法时长返回 `null`。
9. 四档摘要展示前三档并追加 `共 4 档`。
10. KPOS 已有 HourlyRate 可完整读取并逆映射，不依赖浏览器历史规则。
11. KTV 桌位通过 `defaultSaleItemId` 关联商品规则，不依赖 seq 443 或 `durationBillingRuleId`。
12. eMenu 只在绑定商品存在有效 KPOS HourlyRate 且服务员已登录时展示开单计时。
13. 开始计时后规则快照被冻结；首页计时条持续显示已用时长，预估金额仅在购物车目标商品行展示。
14. 食客模式不显示结束入口；服务员授权失败不结束计时。
15. 规则只能选择 KPOS 返回的 KTV 商品；同一商品不得重复创建规则。
16. KTV 桌台的计时商品必须存在有效 HourlyRate；改成其他桌台类型时警告并清空商品绑定。
17. 开始计时只生成一条数量为 1、金额为 ¥0 的普通已下单商品，重复操作不会重复创建。
18. 活动计时商品行只按「标题 + Option + 价格」展示：标题为开单时名称快照，Option 为 `用时 HH:mm:ss`，价格为 `预估 ¥X.XX`，异常时为 `预估 --`；计价摘要和起止时间不额外占用已下单商品行。
19. 授权成功后只更新原商品行的价格为最终费用，不新增 surcharge 或第二条商品。
20. 固定、单位及混合区间均使用开单时规则快照，并覆盖 0、1、199、200、201、250、300、301 分钟等边界。
21. 商品行被删除或作废时阻止结束；改价失败可幂等重试且不会重复收费。
22. 活动计时会阻止结账、修改桌台类型和更换计时商品。
23. 仅当桌台【KTV/卡拉OK】房间商品 ID 在 KPOS HourlyRate 中存在规则时展示并允许开单计时。
24. 正式 KPOS 只返回 `shape/kposShape: "KTV"`、没有商家扩展 `category` 时，仍能识别为 KTV 桌台并展示入口。
25. 多区间保存的第 N 个 SOAP 操作失败时立即停止；界面分别列出已成功、失败、未执行项，强制回读 KPOS，并且只能基于回读后的新差异手动重试。
26. 保存后的回读快照与目标快照不完全一致时不得提示成功；重复重试不得重复新增已成功区间。
27. 单个商品的 SOAP 行出现 `price` 与 `fixPrice` 混用、数值 0、空值歧义、非法 `step`、首档非 0、断档、重叠或多个无上限档时，仅该商品进入只读错误态，不自动修复，也不阻断其他商品的读取和新建。
28. 实机确认并自动化覆盖 `from=0,to=200,fixPrice=100`、`from=200,to=300,price=5,step=30`、`from=300,to` 缺省且 `price=10,step=60` 的映射与累计计价。
29. 删除前若任一 KPOS 桌台的 `defaultSaleItemId` 绑定该商品，必须阻止删除并列出桌台；无绑定时逐条删除，只有回读为空才提示成功。
30. eMenu 遇到 SOAP 超时、Fault、空响应或认证失效时禁用开单并显示诊断信息，禁止回退 localStorage 或过期缓存。
31. 商品 ID 经统一规范化后，数字与数字字符串可精确匹配；空值、非纯数字或不同 ID 不得误匹配。
32. 展示缓存按 `location.origin + PC License/instanceName` 隔离；切换主机、License 或身份后不得复用上一环境数据。
33. 显式迁移默认保留 KPOS 已有规则；只有逐商品确认“替换 KPOS”才写入。每次重试先回读并只执行剩余差异；回读已等于目标时跳过写入，且逐商品成功/失败、hash 与最后快照摘要可追溯。
34. 真实 SOAP 集成验收覆盖档位合并、档位拆分、公共边界移动、单行 `fixed ↔ unit` 双向切换及混合规则；每次最终回读的 ID、边界、字段模式和价格均与目标规范化快照一致。
35. 删除期间模拟另一终端新增桌台绑定时，完成后二次 FloorPlan 检查必须报告并发冲突，不得提示原子删除成功。
36. 整组替换分别在倒序删除阶段和正序重建阶段注入失败；重新打开页面能识别恢复意图，点击“继续恢复”后从 fresh read 状态收敛到目标快照，且不重复删除或新增。
37. 仅修改单位收费行的 `step` 时按原 HourlyRate ID 更新；SOAP 乱序返回时先按 `from` 规范化，快照 hash、差异比较和回读验收结果稳定一致。
38. 首页不再展示独立计时规则卡片；KTV 桌未计时时中央大圆按钮显示「开单计时」，点击后产生唯一 ¥0 计时商品和会话并进入菜单；已计时时只进入当前订单；规则无效时不回退普通开单；非 KTV 桌仍显示并执行原有「开始点单」。
39. 购物车已下单区域在活动计时下按呼叫结账设置分别呈现“双列呼叫 + 结束计时”或“全宽结束计时”；结束计时复用相同授权改价事务，结束后按钮恢复状态正确。
40. 购物车活动计时商品使用「标题 + Option + 价格」结构：Option 位置每秒刷新 `用时 HH:mm:ss`，价格位置显示 `预估 ¥X.XX`，且结束确认等非购物车位置仍显示“预估费用”。同一订单存在两个相同 `saleItemId` 或同名商品行时，只增强目标 `orderItemId` 行；订单行没有 `orderItemId` 时单独覆盖旧数据 `key` 回退；`orderItemId` 已存在但错误、标识缺失、非法或无匹配时任何行都不得增强。冻结快照或开始时间非法、计算抛错、结果为 `null` 或非有限数时立即显示 `预估 --`。保存失败保持预估展示；保存成功并从服务端确认后，价格位置按普通商品格式显示最终成交价 `¥X.XX`。底部结束计时按钮保持单行。
41. 首页活动计时条只展示每秒更新的已用时长和「结束计时」按钮；不得展示桌台/商品标题或预估费用。无结束权限时仍展示已用时长，但不展示结束按钮。
