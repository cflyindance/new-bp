# 小费分配明细“确认分配”设计

## 背景与目标

当前小费分配明细页底部提供“保存”和“保存并跳转到下一天”，但保存动作不会改变当日分配状态。调整后，明细页作为当天小费正式分配的确认入口：用户可以先查看、修改当前门店当天的小费数据，再通过“确认分配”完成分配，使汇总页当天状态变为“已分配”。

本次只调整确认流程和正式结果落库方式，沿用现有规则显示、金额计算、规则执行和取消分配业务规则。

## 交互方案

### 未分配日期

- 明细数据保持可查看、可修改。
- 底部只显示主按钮“确认分配”。
- 删除“保存”和“保存并跳转到下一天”。
- 点击“确认分配”后，保存当前明细数据，并将当前门店、当前日期加入已分配记录。
- 完成后刷新页面金额与状态，按钮切换为“重新确认分配”，并提示“分配成功”。

### 已分配日期

- 再次进入明细页时仍可查看和修改。
- 底部显示主按钮“重新确认分配”。
- 点击后弹出二次确认框，提示：“该日期已分配，重新确认将覆盖当天原分配结果。”
- 用户取消时，不保存、不修改分配状态。
- 用户确认时，保存当前明细数据并覆盖当前门店、当前日期的原分配结果，完成后提示“重新分配成功”。

## 正式结果与数据范围

- 分配状态继续使用现有 `tipout_allocated` 存储结构。
- 新增正式结果存储 `tipout_allocation_results_v1`，按规范化后的精确 `store + date` 键保存当前页面计算出的池级金额和员工级分配结果；重新确认以新快照替换旧快照。
- 快照至少包含：门店、日期、确认时间、小费池 ID、规则 ID、各输入基数与比例、池金额、员工 ID/角色/工时/比例/分配金额，以及汇总金额。金额继续使用现有计算函数产生，不引入第二套计算公式。
- 手动工时仍由 `TipOutManualHours` 持久化；确认快照记录确认时采用的工时值，以便汇总与薪资读取同一版结果。
- 门店使用规则、筛选器与员工目录共用的完整门店标识作为 canonical store key，不再通过门店名前缀模糊匹配。
- 门店是状态与结果的一级键，日期保存在该门店的日期集合或结果映射中。
- 首次确认只向当前门店的日期集合追加当前日期，并去重。
- 重新确认保持当前日期为已分配，不影响其他日期或其他门店。
- 汇总页读取同一份状态和正式结果快照，因此返回汇总后当天显示“已分配”及本次确认的金额。
- 薪资桥接在存在正式结果快照时优先读取该快照，不存在时沿用现有规则计算；首次确认和重新确认后均调用现有 `TipOutPayrollBridge.syncAfterAllocation(store, date, date)`，保证 Tips/SVCW 与汇总一致。
- 汇总页现有“取消分配”入口、数据写入和薪资同步逻辑完全不变；该入口仅作为演示数据重置使用，不纳入本次正式结果事务改造。
- 取消后对应快照即使仍存在，在未分配状态下也不得参与展示、计算或薪资同步。下一次从汇总页执行分配时，以当前规则重新计算并覆盖同一 `store + date` 的旧快照，不恢复取消前结果。

## 页面与逻辑边界

- 模板只保留一个主操作按钮，并提供稳定 ID 供状态同步。
- 明细渲染时根据当前门店与日期判断是否已分配，并同步按钮文案。
- 确认操作集中在单一函数中：读取范围、判断是否覆盖、校验、生成快照、保存快照、写入状态、同步薪资、重绘与通知。
- 复用浏览器原生确认框或项目现有等价确认能力，不新增复杂弹窗组件。
- 日期或门店无效时不写入状态，并给出错误提示。

## 校验与一致性

- 确认前复用汇总分配的规则校验：当前门店必须存在适用规则，角色或员工引用不得失效。
- 所有金额、工时和比例必须是有限非负数；需要合计 100% 的角色与员工比例继续遵守现有约束。校验失败时聚焦首个错误项，不写快照、不写状态、不触发薪资同步。
- 提交期间禁用按钮并显示“分配中…”或“重新分配中…”，阻止重复提交。
- 写入前保留当前 `store + date` 的旧快照和旧状态。快照或状态写入失败时恢复二者并提示“分配失败，请重试”。
- 状态与快照保存成功后再同步薪资。薪资同步失败时保留已保存的正式分配结果，显示“分配结果已保存，但薪资同步失败，请重试”，按钮恢复可用；再次确认可安全重试并覆盖同一键，不产生重复日期。
- 确认成功后用正式结果刷新或替换 `tipout-date-pool-summary-v1`；不得继续使用进入详情前的陈旧 session 快照。
- 顶层本地 JSON 无法解析时禁止写入并提示数据损坏，避免以空对象覆盖全部门店；只有单个门店或日期节点结构非法时才隔离该节点，并保留同一文档中的其他合法节点。任何写入失败都必须进入错误分支。

## 验收标准

1. 未分配日期进入明细页，只显示“确认分配”。
2. 修改数据后点击“确认分配”，当天在当前门店下变为已分配。
3. 返回汇总页后，当天展示“已分配”。
4. 已分配日期进入明细页，按钮显示“重新确认分配”。
5. 点击“重新确认分配”出现覆盖提示；取消后数据和状态不变。
6. 确认覆盖后仍为已分配，并提示重新分配成功。
7. 操作一个门店和日期不会改变其他门店或日期。
8. 原“保存”和“保存并跳转到下一天”入口不再出现。
9. 汇总页取消分配能力继续可用。
10. 分配成功后薪资 Tips/SVCW 与本次正式结果一致；同步失败会明确提示且允许安全重试。
11. 相似名称门店之间不存在状态或结果串用。
12. 无规则、失效角色/员工、非法数值或比例时不能确认分配。
13. 取消分配逻辑保持不变；取消状态下旧快照不生效，之后重新分配采用当前规则的新结果，不恢复旧快照。

## 验证策略

- 静态验证模板按钮、旧入口移除、状态读写与覆盖确认逻辑。
- 自动验证首次确认去重、门店/日期隔离、重新确认取消分支、正式快照覆盖和薪资桥接读取。
- 自动验证快照写入失败、状态写入失败、薪资同步失败、重复点击、损坏 JSON、相似门店名、陈旧 session 快照、无规则、失效引用及非法数值。
- 自动验证汇总取消后详情按钮恢复为“确认分配”。确认入口应封装为可替换函数，以便测试取消分支。
- 浏览器验证未分配确认、已分配覆盖提示、取消覆盖不改变结果、返回汇总后的状态变化。
