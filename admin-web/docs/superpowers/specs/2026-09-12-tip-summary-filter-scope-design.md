# 小费汇总筛选范围调整设计

## 背景

小费管理包含“日期分配汇总”和“员工分配汇总”两个视图。当前筛选栏混合展示日期、角色、员工等条件，导致日期视图出现无关筛选，员工视图也缺少明确的员工多选能力。本次调整让每个视图只展示与其业务对象有关的条件，并保证筛选、导出和视图切换使用同一套有效状态。

## 目标

- 日期分配汇总不展示角色、员工条件，新增分配状态筛选。
- 员工分配汇总保留日期范围，展示角色、员工和状态筛选。
- 员工筛选为多选下拉，支持全选，并与角色筛选联动。
- 两个视图分别记忆自己的筛选值，隐藏条件不得继续影响当前视图。
- 导出结果与当前视图的有效筛选范围一致。

## 非目标

- 不改变门店筛选的位置和作用范围。
- 不改变小费分配计算、确认分配或取消分配逻辑。
- 不新增后端接口或修改员工、角色的数据源。
- 不改变员工详情页的筛选条件。

## 页面结构

门店继续作为首行独立条件，同时影响两个汇总视图。第二行保留视图 Tab 与筛选工具栏。

### 日期分配汇总

筛选顺序：日期范围、分配状态、展示顺序。

分配状态为单选下拉，选项为“全部状态”“已分配”“未分配”，默认“全部状态”。日期视图不渲染角色和员工筛选，也不读取员工视图保存的角色或员工条件。

### 员工分配汇总

筛选顺序：日期范围、角色、员工、状态。

日期范围保留现有默认值：今天往前一个月，包含今天。角色和员工均使用多选下拉并支持全选。员工筛选不再使用自由文本搜索作为主筛选方式。

## 状态与联动

页面维护两组独立状态：

- 日期视图：`dateRange`、`allocationStatus`、`dateSort`。
- 员工视图：`dateRange`、`roles`、`employeeIds`、`employeeStatus`、`employeeSort`。

门店为共享上下文。切换 Tab 时恢复目标视图上一次的筛选状态，不把来源视图的专属条件带入目标视图。

角色变化时，根据当前门店员工名册重新生成员工选项：

- 未选择角色时，员工下拉展示当前门店全部员工。
- 选择一个或多个角色时，只展示属于这些角色的员工。
- 已选员工若不再属于新的角色范围，则自动从选择中移除。
- 员工选择为空表示不限制员工，即展示当前角色范围内全部员工。
- 角色范围内没有员工时，员工下拉禁用并显示“暂无可选员工”。

门店变化时重新校验角色、员工选择，自动移除新门店中不存在的值。日期变化只刷新汇总数据，不改变角色或员工选择。

## 数据过滤

日期汇总先按门店和日期范围生成日期记录，再按分配状态过滤，最后按日期顺序排序。状态判定沿用列表现有“已分配/未分配”字段，不新增第三种业务状态。

员工汇总先按门店和日期范围生成员工聚合，再依次应用角色、员工和员工状态条件，最后按员工视图现有排序规则排序。角色与员工筛选统一使用员工名册中的稳定 ID 和角色值，不用显示名称作为员工主键。

## 导出约束

- 日期视图导出当前门店、日期范围、分配状态过滤后的日期记录，并遵循当前展示顺序。
- 员工视图导出当前门店、日期范围、角色、员工和状态过滤后的员工记录，并遵循当前员工排序。
- 隐藏筛选条件不得影响导出。

## 空状态与错误处理

- 日期状态筛选无结果时显示“当前筛选范围暂无日期分配数据”。
- 员工筛选无结果时显示“当前筛选范围暂无员工分配汇总数据”。
- 角色范围内无员工时禁用员工下拉，并显示“暂无可选员工”。
- 从本地记忆恢复到失效角色或员工时，静默剔除失效值并刷新选项，不阻断页面。

## 响应式布局

桌面端 Tab 位于左侧，筛选条件在同一白色工具栏内右对齐。空间不足时筛选条件可以换行；移动端依次显示 Tab、日期、其余条件，每个多选控件占满可用宽度。

## 验收标准

1. 日期视图只显示日期范围、分配状态、展示顺序。
2. 日期状态能准确过滤已分配和未分配记录。
3. 员工视图显示日期范围、角色、员工、状态，不显示日期排序条件。
4. 员工多选支持逐项选择、全选、清空和标签回显。
5. 角色变化会更新员工选项并移除越界员工选择。
6. 切换 Tab 后各自筛选值保持，隐藏条件不影响列表、指标或导出。
7. 门店变化后角色、员工选项来自该门店统一员工名册。
8. 两个视图的空状态、刷新恢复和导出范围符合本设计。
