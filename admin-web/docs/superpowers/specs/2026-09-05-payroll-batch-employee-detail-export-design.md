# 薪资员工明细批量导出设计

## 背景与目标

薪资管理当前支持查看和导出单个员工的详细明细或精简明细。本次增加批量导出能力，使用户可以一次导出全部员工或指定员工的薪资详情，并在同一流程内选择明细类型、文件格式和文件组织方式。

目标：

- 支持全部员工和手动选择员工两种导出范围。
- 支持详细明细、精简明细两种内容模板。
- 支持 PDF、CSV 两种格式。
- 支持合并为一个文件，或按员工拆分后打包 ZIP。
- 对未确认、资料不完整或无薪资数据的员工给出明确状态，不静默遗漏。
- 保持现有单个员工详情及导出能力不变。

## 入口与信息架构

在薪资管理页面顶部操作区增加独立按钮“批量导出详情”。该入口与“Employees Detail”“Export ADP Report”等现有操作并列，不要求用户先打开员工详情。

点击后打开批量导出配置弹窗。弹窗按以下顺序组织：

1. 员工范围
2. 明细类型
3. 文件格式
4. 文件组织方式
5. 导出摘要与风险提示
6. 取消、开始导出

## 默认值与记忆策略

首次打开时采用以下默认值：

- 员工范围：全部员工
- 明细类型：精简明细
- 文件格式：PDF
- 文件组织方式：合并为一个文件

完成一次导出后，系统在当前浏览器中记住用户最近一次选择。再次打开弹窗时恢复明细类型、文件格式、文件组织方式和打印分页策略；员工范围仍默认全部员工，避免意外沿用上一次的部分员工集合。

配置在用户点击“开始导出”时写入本地偏好，不以任务最终成功为前提。打印分页策略仅在“精简明细 + PDF”时显示；首次使用默认为“强制一页”，用户可改为“自动分页”。“每位员工一张 A4”表示强制一页模式的目标，自动分页模式允许同一员工跨页。

## 员工范围

提供两种互斥模式：

- 全部员工：使用当前门店、年份和 Period 条件下的员工集合。
- 选择员工：展示可搜索、可多选的员工列表，支持当前结果全选、清空选择和已选数量反馈。

“全选当前结果”指全选当前搜索条件命中的完整结果集，而不是仅选择当前可见页。搜索词变化时，已选员工继续保留；界面同时显示“已选 X 人，其中 Y 人不在当前搜索结果”。“清空选择”清除全部已选员工。

切换门店、年份或 Period 后，待导出员工集合需要重新计算。若配置弹窗处于打开状态，应刷新摘要并清理已不属于当前范围的选中员工。

## 明细、格式和文件组织

### 明细类型

- 精简明细：适合签字和纸质归档，目标为每位员工一张 A4。
- 详细明细：保留现有员工详细明细字段和完整考勤记录，允许跨页。

### 文件格式

- PDF：按页面模板渲染，适用于查看、打印和签字。
- CSV：导出结构化数据，适用于复核和二次处理。界面统一使用“CSV”，不使用“CVS”。

### 文件组织方式

- 合并为一个文件：所有员工按当前员工列表顺序写入一个 PDF 或一个 CSV。
- 每位员工独立文件：按员工生成独立 PDF 或 CSV，最终打包为 ZIP。

## PDF 规则

- 合并 PDF 中每位员工必须从新页开始，避免两位员工共享同一张纸。
- 精简明细默认每位员工一张 A4。
- 精简明细沿用员工详情中的打印分页设置：强制一页或自动分页，并记住用户上次选择。
- 详细明细允许跨页；跨页时重复关键表头，并避免行内容被截断。
- 合并文件显示连续页码，同时保留员工边界。
- Draft 员工的页面显示清晰但不遮挡内容的 Draft 标识。

建议命名：`Payroll_{year}_Period_{period}_{detailType}_{employeeCount}_Employees.pdf`。

## CSV 规则

- CSV 使用 UTF-8 with BOM、逗号分隔、CRLF 换行和双引号转义，兼容 Excel。日期统一为 `YYYY-MM-DD`，时间统一为 `HH:mm`，金额为不含货币符号的两位小数，工时为两位小数，空值输出为空字段。
- 精简明细 CSV 每位员工一行，固定列为：`store_id`、`store_name`、`payroll_year`、`period_number`、`period_start`、`period_end`、`pay_date`、`employee_id`、`employee_name`、`role`、`hire_date`、`regular_hours`、`ot_hours`、`ot2_hours`、`total_hours`、`regular_amount`、`ot_amount`、`ot2_amount`、`tips`、`gratuity`、`gross_total`、`status`、`missing_fields`。
- 详细明细 CSV 对每位员工先输出一行员工汇总，再输出零到多行考勤班次。同一天存在多个 In/Out 片段时输出多行，不合并为带换行的单元格。
- 详细明细 CSV 使用以下完整且固定的有序列清单，不允许运行时增删或重名：`row_type`、`store_id`、`store_name`、`payroll_year`、`period_number`、`period_start`、`period_end`、`pay_date`、`employee_id`、`employee_name`、`role`、`hire_date`、`status`、`missing_fields`、`summary_regular_hours`、`summary_ot_hours`、`summary_ot2_hours`、`summary_total_hours`、`summary_regular_amount`、`summary_ot_amount`、`summary_ot2_amount`、`summary_tips`、`summary_gratuity`、`summary_gross_total`、`work_date`、`week_number`、`clock_in`、`clock_out`、`meal_hours`、`line_regular_hours`、`line_regular_rate`、`line_regular_amount`、`line_ot_hours`、`line_ot_rate`、`line_ot_amount`、`line_ot2_hours`、`line_ot2_rate`、`line_ot2_amount`、`line_amount`。
- `row_type=employee_summary`：门店、区间、员工、状态字段和全部 `summary_*` 字段填值；从 `work_date` 到 `line_amount` 的班次字段全部留空。
- `row_type=shift`：门店、区间、员工和状态字段填值；全部 `summary_*` 字段留空；从 `work_date` 到 `line_amount` 的班次字段按该班次填值。员工没有班次片段时不输出 `shift` 行，但仍保留 `employee_summary` 行，确保固定薪资、仅奖金/小费等员工不会生成零行。
- 合并 CSV 使用上述固定列区分员工数据归属；独立 CSV 使用相同列结构，并以员工编号和姓名命名文件。
- `missing_fields` 使用英文代码并以 `|` 分隔，允许值为 `employee_id`、`employee_ssn`、`hire_date`、`role`、`pay_period`、`pay_date`；没有缺失时为空。
- 无薪资数据的员工进入结果清单；若无可导出的数据行，不在 CSV 中伪造薪资数据。

建议命名：`Payroll_{year}_Period_{period}_{detailType}_{employeeCount}_Employees.csv`。独立文件包命名规则相同，扩展名为 `.zip`。

## 导出摘要与校验

弹窗底部实时展示：

- 员工总数
- 可正常导出人数
- Draft / 信息不完整人数
- 无薪资数据人数
- 预计文件数或预计页数

未确认或资料不完整的员工允许继续导出，但必须被标记为 Draft。没有薪资数据的员工不得被静默跳过，导出结束时必须列出姓名和原因。

员工在一次任务中只归入一个状态，优先级从高到低为：

1. `no_data`：当前门店、年份和 Period 下没有可导出的薪资或考勤记录；不生成该员工文件或数据行。
2. `incomplete`：存在数据，但缺少上述任一必需字段；允许导出并标记 Draft。
3. `unconfirmed`：数据完整但该 Period 尚未确认；允许导出并标记 Draft。
4. `ready`：数据完整且已确认；正常导出。

摘要人数为互斥计数，并满足：员工总数 = ready + incomplete + unconfirmed + no_data。界面中的“Draft / 信息不完整人数”展示 incomplete + unconfirmed，并可展开分别查看。

以下情况禁止开始导出：

- 选择员工模式下未选择任何员工。
- 当前筛选范围没有员工。
- 必需的门店、年份或 Period 条件缺失。

## 任务状态与结果

点击“开始导出”后关闭配置弹窗，并在页面右下角显示非阻塞任务状态：

- 准备数据
- 正在生成，显示已完成员工数 / 总员工数
- 正在合并或打包
- 已完成
- 部分成功
- 失败
- 取消中
- 已取消

用户离开薪资管理子页面再返回时，当前浏览器会话中仍可查看任务状态。完成后提供“下载文件”；部分成功时同时提供“查看失败项”和“仅重试失败员工”。

导出失败不得生成看似成功的空文件。若浏览器下载被拦截，应明确提示用户重新触发下载。

任务及产物规则：

- 已完成：所有非 `no_data` 员工均生成成功，且至少有一个成功员工；允许存在 `no_data` 员工，结果页需列明跳过项。
- 部分成功：至少一个员工成功，且至少一个具有数据的员工生成失败；成功员工仍组成可下载产物。
- 失败：没有任何员工生成成功，包括全部员工均为 `no_data` 的情况；不提供空产物下载。
- “仅重试失败员工”创建一个关联到原任务的新任务，不覆盖原产物；新文件名追加 `_retry_{n}`。
- 当前实现同时只运行一个批量导出任务；新任务开始前需等待当前任务完成或主动取消。

取消行为：

- “准备数据”和“正在生成”阶段允许取消；点击后进入“取消中”，停止调度新的员工，等待当前员工渲染安全结束后丢弃全部临时数据。
- “正在合并或打包”阶段禁用取消，避免产生损坏文件，并提示任务即将完成。
- 取消成功后状态为“已取消”，不提供产物下载；用户可以立即新建任务。
- 取消失败时恢复到原执行状态并显示原因，用户可再次尝试；不得误报为已取消。

本次方案采用浏览器端本地生成，不上传第三方转换服务。SPA 内切换页面时任务继续执行并保存在全局任务状态中；刷新页面、关闭标签页或浏览器后，正在执行的任务终止且无法恢复，界面需在刷新/关闭前给出提示。完成产物仅在当前标签页生命周期内可再次下载。单次最多选择 200 名员工；超出时禁止开始并提示缩小范围。预计页数仅作为估算，显示“约 X 页”，不作为最终页数承诺。

## 权限与敏感数据

- 批量导出入口沿用现有薪资详情导出权限；无该权限的用户不可见入口，也不可通过调用函数绕过校验。
- 任务快照和生成文件只保存在当前浏览器内存，不写入长期本地缓存。
- 文件下载由当前登录会话触发，不生成公开下载 URL。
- 独立文件名中的员工编号和姓名需移除 Windows/macOS 非法字符、控制字符和路径分隔符，连续空白折叠为单个下划线；重名时追加员工内部 ID，单个文件名最长 120 个字符。
- 文件总命名中的 `employeeCount` 表示实际成功写入产物的员工数；`detailType` 固定使用 `Detailed` 或 `Summary`。

## 兼容与边界

- 保留现有单员工详细明细、精简明细、打印、PDF、CSV 和邮件功能。
- 批量导出复用单员工明细的数据口径与模板，避免两个入口计算结果不一致。
- 员工顺序使用当前员工列表的稳定排序；同一任务过程中不受列表后续筛选变化影响。
- 导出开始时创建筛选条件和员工集合快照，避免生成过程中门店、年份或 Period 改变导致混合数据。
- 大批量任务必须逐个员工生成并释放中间渲染资源，防止页面卡死或内存持续增长。

## 验收标准

1. 顶部存在独立的“批量导出详情”入口。
2. 首次打开默认选中全部员工、精简明细、PDF、合并为一个文件。
3. 能切换到手动选择员工，并完成搜索、多选、全选和清空。
4. 详细/精简 × PDF/CSV × 合并/ZIP 的八种组合均可成功生成。
5. 合并 PDF 中每位员工从新页开始；精简明细遵循保存的分页设置。
6. 合并 CSV 能通过员工识别列区分数据归属。
7. Draft 员工允许导出且在 PDF、CSV 中具有明确标记。
8. 无薪资数据员工在结果中有明确原因，不被静默忽略。
9. 页面显示真实导出进度，完成、部分成功和失败状态均可操作。
10. 最近一次导出配置被记住，但手动选择的员工集合不会被自动沿用。
11. 现有单员工查看、打印和导出流程不受影响。
12. 详细 CSV 的每位员工均生成 `employee_summary` 行；有班次时再生成 `shift` 行，有薪资但无班次的员工不会生成零行。
13. 生成阶段可以取消，合并/打包阶段不能取消；已取消任务不产生可下载文件并允许立即重开。
