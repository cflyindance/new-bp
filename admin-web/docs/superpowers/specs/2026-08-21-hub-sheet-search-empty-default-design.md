# 滑层搜索框默认清空设计

## 目标

所有 Hub 二级滑层每次从关闭状态重新打开时，搜索框必须为空，不显示登录邮箱、浏览器自动填充值或上一次打开遗留的查询。滑层保持打开期间的重绘继续保留用户当前搜索词。

## 方案

1. 新增统一的 `resetHubSearchOnOpenTransition(hubId, wasOpen, open)` 辅助函数。通用滑层和全部专用滑层 setter 都调用它；仅在 `wasOpen === false && open === true` 时清除对应 Hub 的内存查询，避免站内导航和重绘丢失输入。
2. 通用搜索输入框保持语义正确的 `type="search"` 与 `autocomplete="off"`，增加稳定且与登录无关的 `name="hub-sheet-navigation-search"`，并关闭拼写检查。
3. 输入框绑定后，若查询状态为空，则立即、下一动画帧以及短延迟后检查 DOM。只要用户尚未通过键盘、指针、粘贴或输入法开始与输入框交互，就清除浏览器延迟注入的值；一旦发生用户交互立即停止清理。延迟回调仅处理仍连接在文档中的原输入框，不影响重绘后的节点。

## 范围

覆盖通用 `subNavPlacement: sheet` 滑层以及库存、商品、营销、促销、会员、礼品卡、报表、打印、预约等专用 Hub 滑层。搜索、清除按钮、IME 输入和滑层内重绘行为保持不变。

## 验证

- 新打开任一滑层时搜索框为空，导航完整显示。
- 输入搜索词后，同一打开周期内重绘仍保留搜索词。
- 关闭并再次打开后搜索词清空。
- 登录邮箱不会出现在搜索框。
- 模拟挂载后延迟写入邮箱时，在没有用户交互的情况下会被清除。
- 键盘、指针、粘贴和 IME 操作开始后，延迟清理不会删除用户输入。
- 通用滑层和每一种专用滑层 setter 均覆盖关闭→打开重置。
- TypeScript 与 Vite 构建通过。
