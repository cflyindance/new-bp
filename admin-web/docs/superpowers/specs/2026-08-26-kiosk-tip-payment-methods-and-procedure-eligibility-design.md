# Kiosk 小费支付方式与流程资格统一设计

> 文档状态：现行权威规格。本文统一定义支付方式、小费展示方式和小费流程的资格联动；与历史阶段稿冲突时以本文为准。`tip-procedure = 2` 的页面按钮职责继续以 [Kiosk 小费前置后的支付方式路由澄清](./2026-08-26-kiosk-tip-before-payment-method-routing-clarification-design.md) 为准。

## 目标

把信用卡/借记卡、柜台支付和礼品卡纳入同一套小费配置模型，保证设置页只能形成合法组合，并让「支付方式选择页面之前」适用于任意至少两种已启用且全部展示小费的支付方式组合。

## 字段与枚举

- POS `KIOSK_PAYMENT_TYPE`：`0` 信用卡/借记卡、`1` 柜台支付、`2` 礼品卡。
- Kiosk `tipping-mode.tipPaymentTypes`：使用相同代码，类型为 `('0'|'1'|'2')[]`。
- Kiosk `tip-procedure.value`：`0` 刷卡之前、`1` 刷卡之后、`2` 支付方式选择页面之前；当没有任何有效流程时允许清空为 `null`。
- `tipping-mode.value` 继续仅作为旧接口兼容字段，不参与新版显隐和资格判断。

## 显示小费选项

「显示小费选项」不显示总开关，常驻展示三个复选项：信用卡/借记卡、柜台支付、礼品卡。

1. 只有 `KIOSK_PAYMENT_TYPE` 已启用的方式，对应小费选项才可勾选；否则禁用且不得保存为已选。
2. 用户取消某个支付方式时，立即自动取消对应小费选项。
3. 重新启用支付方式只恢复可选状态，不自动勾选。
4. 加载中不清理原值；加载完成后与当前支付方式取交集。
5. `tipPaymentTypes` 缺失、`null` 或非法时按旧数据迁移为当前已启用的三种受支持方式；显式空数组保持为空。

## 小费流程资格

资格由当前编辑态支付方式集合 `P` 与小费方式集合 `T` 统一计算。

### 刷卡之前与刷卡之后

值 `0`、`1` 仅在 `0 ∈ P` 且 `0 ∈ T` 时可选。现金或礼品卡是否启用、是否展示小费不影响这两项的资格。

### 支付方式选择页面之前

值 `2` 仅在以下条件同时成立时可选：

- `P` 至少包含两种支付方式；
- 当前启用的每一种支付方式均已勾选小费，即 `P ⊆ T`。

“全部勾选”指当前启用方式的全集，不要求全局三种方式全部启用。例如 `P = {信用卡, 礼品卡}` 且 `T = {信用卡, 礼品卡}` 时值 `2` 有效；漏选其中任一种时无效。

## 资格失效与保存

- 三个单选项始终展示，但分别按上述资格置灰。
- 当前值失效时，若值 `0` 仍有效，立即自动切换为值 `0`。
- 当前值失效且值 `0` 也无效时，不自动替用户选择其他流程：清空为 `null`，仍有效的流程保持可选，并要求用户重新选择后才能保存。
- 只有三个流程均无效时，才清空为 `null` 且三个选项全部置灰；此时允许保存空流程值，不得保留一个无意义的旧值。
- 支付方式或小费选项变化、配置加载完成和点击保存前，都执行同一套规范化与回退规则。
- 设置页负责修复配置合法性；点单运行时读取到历史或异常值 `2` 时仍必须执行“小费页 → Payment Method”，不得降级为小费确认后直接支付。

## 点单运行时

- 三种支付方式均使用 `tipPaymentTypes` 判断是否展示小费。
- 值 `0`、`1` 仍是信用卡专用的刷卡前/后流程。
- 值 `2` 的固定顺序为：选择小费并确认 → 现有 Payment Method 页面 → 用户选择的支付流程。
- Payment Method 选择信用卡时保留小费并进入现有信用卡校验/支付；选择现金时保留小费并沿用确认框及建单流程；选择礼品卡时同样保留小费并进入现有礼品卡支付流程。
- 礼品卡不再清除前置选择的小费、选择元数据或完成标志。

## 验收标准

1. 支付设置和显示小费选项都展示信用卡、现金、礼品卡三种方式。
2. 未启用的支付方式对应小费选项禁用；取消支付方式后对应小费选项立即取消且保存重载后保持。
3. 只有信用卡支付和信用卡小费同时启用时，值 `0`、`1` 可选。
4. 仅启用一种支付方式时值 `2` 禁用。
5. 任意两种或三种支付方式启用且全部勾选小费时值 `2` 可选；少勾任一种即禁用。
6. 当前流程失效后优先回退值 `0`；值 `0` 无效但仍有其他有效流程时清空并要求重新选择；三个流程均无效时清空且全部置灰。
7. 值 `2` 下信用卡、现金、礼品卡都执行“小费页 → Payment Method → 对应支付流程”，并保留已选小费。
8. 异常持久化值 `2` 不会让运行时跳过 Payment Method。
9. 旧数据、非法值、加载竞态和保存前兜底均不会产生支付方式与小费选项不一致的数据。

## 验证策略

- 扩展支付方式规范化和运行时小费判断测试，覆盖代码 `2`。
- 用集合组合测试覆盖单支付、任意双支付、三支付、漏选小费、无信用卡及资格失效回退。
- 覆盖设置保存后返回再进入、Kiosk 页面往返设置页后的持久化重载。
- 覆盖值 `2` 下三种 Payment Method 按钮的路由、小费保留和防止重复进入小费页。
- 运行 KioskLite 全量测试，构建并发布最新嵌入包后执行浏览器完整流程验证。

## 非目标

- 不新增支付方式代码、配置 ID 或后端接口。
- 不改变小费金额、比例、自定义小费、No Tip 和签名规则本身。
