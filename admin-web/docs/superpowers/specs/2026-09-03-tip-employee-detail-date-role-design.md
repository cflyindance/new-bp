# 员工对账明细日期与角色展示调整

## 目标

在原生“小费管理 > 员工对账明细”页面优化核对入口，不改变小费汇总、分配、考勤判断与金额计算逻辑。

## 已确认方案

采用方案 A：在明细页顶部直接提供起止日期选择器。用户修改任一日期后，页面基于员工对账列表已存在的逐日结果重新筛选展示范围，并同步更新顶部汇总；不重新计算或写回分配结果。

## 页面调整

- 顶部保留“返回员工对账”和员工姓名。
- 在员工姓名旁展示只读角色标签，直接使用快照已有的 `role` 展示值；若为空则显示“未设置角色”。若上游传入多个角色组成的字符串，保持原字符串，不在本页重新映射或拆分。
- 对账范围改为两个原生日期输入框，支持选择开始日期和结束日期。
- 移除门店展示字段，但保留路由和快照中的门店上下文，确保返回列表与上下文校验不受影响。
- 移除右上角包含头像、员工姓名和角色的 `.tipout-employee-chip` 卡片；标题区中的员工姓名和新增角色标签保留。
- 移除现有 `#employeeDetailNotice` 状态提示卡片，包括“有 11 天考勤数据待补录”“状态仅用于核对提示，不反向修改现有分配结果。”及右侧状态；不移除表格行内的考勤与分配状态。
- 保留金额概览、逐日明细表和只读说明。

## 交互与边界

- 日期范围默认取进入明细页时快照的 `dateStart` 和 `dateEnd`。
- 日期按本地业务日期字符串 `YYYY-MM-DD` 比较，起止日期均包含在筛选结果内，不进行 UTC 转换。
- 两个日期输入的 `min/max` 唯一来源为快照的 `dateStart/dateEnd`；即使边界日期没有逐日记录，也仍允许选择。
- 开始日期调到结束日期之后时，将结束日期同步为新的开始日期；结束日期调到开始日期之前时，将开始日期同步为新的结束日期。
- 日期变化后仅过滤当前员工快照中已经生成的逐日结果，并按照现有字段及精度规则对可见行求和，更新班次、工时、分配前、扣除、分配获得和实际获得。不得重新运行分配算法、考勤生成逻辑或持久化写入。
- 若选择范围内没有记录，金额归零并展示空表，不修改持久化数据。
- 返回员工对账时沿用当前既有返回逻辑。

## 数据与兼容性

- 继续使用 `tipout-employee-reconciliation-detail-v1` 会话快照。
- 不修改员工聚合去重、角色来源、分配状态、考勤状态、金额生成逻辑或现有金额格式与舍入规则。
- 门店参数仍参与快照匹配，只是不再在明细 UI 中展示。

## 验收

- 页面可选择开始和结束日期，列表与六项汇总随闭区间同步变化，且汇总与可见逐日行一致。
- 修改开始日期越过结束日期时结束日期同步；修改结束日期越过开始日期时开始日期同步。
- 覆盖完整范围、首尾边界、单日和范围内无逐日记录的选择场景。
- 员工姓名旁能看到快照角色标签；角色缺失时显示“未设置角色”。
- 页面不再出现门店字段、右上员工卡片和考勤待补录提示卡片。
- 既有员工对账进入、浏览器历史返回、无历史返回和快照门店不匹配失效场景保持正常。
- 执行 `node scripts/verify-team-tips-native-views.mjs`、`node scripts/verify-tipout-employee-reconciliation.mjs` 与 `npm run build` 均成功退出。
