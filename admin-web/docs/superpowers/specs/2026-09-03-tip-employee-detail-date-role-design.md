# 员工对账明细日期与角色展示调整

## 目标

在原生“小费管理 > 员工对账明细”页面优化核对入口，不改变小费汇总、分配、考勤判断与金额计算逻辑。

## 已确认方案

采用方案 A：在明细页顶部直接提供起止日期选择器。用户修改任一日期后，页面基于员工对账列表已存在的逐日结果重新筛选展示范围，并同步更新顶部汇总；不重新计算或写回分配结果。

## 页面调整

- 顶部保留“返回员工对账”和员工姓名。
- 在员工姓名旁展示只读角色标签。
- 对账范围改为两个原生日期输入框，支持选择开始日期和结束日期。
- 移除门店展示字段，但保留路由和快照中的门店上下文，确保返回列表与上下文校验不受影响。
- 移除右上角员工信息卡片。
- 移除考勤/待分配提示卡片。
- 保留金额概览、逐日明细表和只读说明。

## 交互与边界

- 日期范围默认取进入明细页时的开始和结束日期。
- 开始日期不得晚于结束日期；若用户选择造成倒置，自动把另一端同步到相同日期。
- 可选日期限制在当前快照覆盖范围内，避免脱离已加载数据。
- 日期变化后仅筛选当前员工的逐日数据，并重新汇总班次、工时、分配前、扣除、分配获得和实际获得。
- 若选择范围内没有记录，金额归零并展示空表，不修改持久化数据。
- 返回员工对账时沿用当前既有返回逻辑。

## 数据与兼容性

- 继续使用 `tipout-employee-reconciliation-detail-v1` 会话快照。
- 不修改员工聚合去重、角色来源、分配状态、考勤状态或金额生成逻辑。
- 门店参数仍参与快照匹配，只是不再在明细 UI 中展示。

## 验收

- 页面可选择开始和结束日期，列表与六项汇总随范围同步变化。
- 员工姓名旁能看到角色标签。
- 页面不再出现门店字段、右上员工卡片和考勤待补录提示卡片。
- 既有员工对账进入、返回、快照校验和金额数据保持正常。
- 原生页面验证脚本、员工对账验证脚本和项目构建通过。
