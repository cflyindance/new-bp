# eMenu 调味批量配置加价系数设计

## 背景与目标

在“调味设置 → 批量建立关联 → 设置动作与 Option”中，当前每个 Option 只维护本批默认加价。此次在不改变现有后端关系模型与终端计价协议的前提下，为本批次增加系统生成的加价系数，并把用户输入价格换算为最终实际加价价格。

目标：

- 清晰展示输入价格、加价系数和实际加价价格。
- 可加价 Option 使用大于 0 的随机系数。
- 免费 Option 使用系数 0，且不能输入加价。
- 预览与保存继续使用现有 `priceDelta`，避免扩大 API 和终端改动范围。

## 范围

本次只调整批量建立关联第二步中的动作与 Option 定价列表、行级草稿状态和预览请求转换。

不在本次范围内：

- 不把加价系数持久化到商品关系。
- 不调整单商品抽屉中的关系价格编辑方式。
- 不调整终端展示与交易计价协议。
- 不支持用户手动修改系统生成的系数。

## 列表与交互

Option 列表按以下顺序展示：

`选择 | Option | 输入价格 | 加价系数 | 实际加价价格 | 删除`

内部编码不在定价列表中展示，但搜索仍支持按内部编码匹配 Option。

### 加价系数

- Option 首次加入当前动作时生成一次系数。
- 20% 概率生成 `0.00`，表示免费。
- 80% 概率在 `0.50～2.00` 内生成大于 0 的值，保留两位小数。
- 系数只读，不允许用户修改。
- 切换动作、搜索、进入预览后返回时，已生成系数保持不变。
- 删除 Option 后重新加入，视为新关联并重新生成系数。

### 输入价格

- 系数大于 0 时允许编辑。
- 输入必须是大于或等于 0、最多两位小数的金额；空值暂按 0 计算。
- 现有单项编辑和批量价格填充均编辑“输入价格”。
- 批量价格填充自动跳过系数为 0 的免费 Option。

### 免费 Option

- 系数显示 `0.00` 并附带“免费”状态。
- 输入价格禁用并显示 `—`，不能通过单项或批量操作赋值。
- 实际加价价格固定显示 `$0.00`。

### 实际加价价格

- 计算公式：`实际加价价格 = 输入价格 × 加价系数`。
- 金额在计算后统一四舍五入到两位小数。
- 输入变化后即时刷新，不提供直接编辑入口。

## 状态与数据流

每个动作下的 Option 草稿由单一 `priceDelta` 扩展为批次内定价草稿：

```ts
type BatchOptionPricingDraft = {
  inputPrice: number;
  markupCoefficient: number;
};
```

`actualPrice` 是派生值，不重复存储：

```ts
actualPrice = roundCurrency(inputPrice * markupCoefficient);
```

数据流：

1. 用户把 Option 加入动作。
2. 页面生成一次只读系数，并以输入价格 0 初始化行级草稿。
3. 用户单项输入或对选中 Option 批量填充输入价格。
4. 页面实时计算实际加价价格；免费项始终为 0。
5. 进入预览时，把每条草稿的 `actualPrice` 映射为现有 `optionPrices[].priceDelta`。
6. 后端预览、冲突处理、保存和终端计价继续沿用现有逻辑。

## 随机与金额规则

随机生成应集中在独立、可测试的纯函数中，并允许测试注入随机源：

- 随机值落在免费区间时返回 `0`。
- 其余值线性映射到 `0.50～2.00`，保留两位小数且保证大于 0。
- 生产环境使用浏览器随机源；测试使用固定随机序列覆盖边界。

金额计算使用以分为精度的统一舍入函数，避免 JavaScript 浮点误差影响预览和保存。

## 错误与边界处理

- 非数字、负数或超过两位小数的输入不进入预览；界面保留可理解的校验状态。
- 空输入在编辑过程中显示为空，计算时按 0 处理。
- 系数 0 是唯一免费判定条件，免费项不参与批量填充。
- 系数生成后不得因重新渲染、搜索过滤或步骤切换而变化。
- 若现有预览因版本冲突要求返回设置步骤，原草稿和系数继续保留。

## 测试与验收

### 自动化测试

- 随机系数的免费概率分支、最小值、最大值和两位小数规则。
- `输入价格 × 系数` 的金额舍入。
- 新增 Option 只生成一次系数，删除重加才重新生成。
- 免费行禁用价格输入并固定实际价格为 0。
- 批量填充只更新已选且非免费的 Option。
- 预览请求只提交计算后的 `priceDelta`。
- 现有批量预览、冲突处理和保存验证继续通过。

### 浏览器验收

- 三个价格相关字段的列顺序、只读和禁用状态正确。
- 修改输入价格后实际加价即时更新。
- 批量选择多个 Option 填充价格时免费项保持不变。
- 切换动作、搜索以及预览后返回，系数保持不变。
- 可正常进入预览并完成保存，浏览器控制台无错误。

## 采用方案

采用批次内保存系数、最终只提交实际加价价格的方案。它满足当前交互目标，同时保持既有 API、关系存储和终端计价稳定。若未来需要回看或审计系数，再单独设计持久化字段和迁移方案。
