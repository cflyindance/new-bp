> 状态：视觉方向与交互契约已确认，等待实现计划

> 范围：仅 `src` 主后台；不包含 `TipOut`、`vendor/emenu-new` 及其他嵌入应用

> 页面级标准：[B 平台嵌入 POS 适配页面规范（Figma）](https://www.figma.com/design/nxQmGvAow2dBHNGe0jSGMp/%25E6%2596%2587%25BB%25B62-B%25E5%25B9%25B3%25E5%258F%25B0%25E8%25AE%25BE%25E8%25AE%25A1%25E7%25B3%25BB%25E7%25BB%259F?node-id=37594-13917&p=f&t=L18LDPqCGM9JM8gW-0)

## 1. 背景与目标

当前主后台页面由多个阶段、多个功能域持续扩展，视觉样式、页面骨架、表单组织和交互反馈存在漂移。新功能如果只依赖通用生成提示，会继续产生不同的圆角、间距、颜色、按钮层级和导航方式。

本方案建立一个可被设计、开发和 AI 共同执行的单一标准，目标是：

- 新页面默认具有一致的视觉语言、页面骨架和交互反馈。
- 同类能力优先复用公司组件库，避免重复实现控件。
- 保留项目已确认的一级/二级导航模型，不因页面改版改变用户心智。
- 设计标准可通过 `DESIGN.md`、Design Tokens、页面模板、项目 Skill 和检查清单持续执行。
- 允许渐进迁移，不要求一次性重写全部既有页面。

## 2. 已确认的设计决策

### 2.1 视觉基准

最终视觉基准如下：

![主后台统一设计系统视觉基准](./assets/admin-web-unified-design-system-reference.png)

采用方案 3 的蓝色视觉系统：

- 深墨蓝/石板色用于导航与高对比结构层。
- 清晰的钴蓝色用于主操作、选中、焦点、开关和复选状态。
- 浅蓝灰用于页面背景、分组表头和弱提示面。
- 成功、警告、危险色只表达语义，不作为品牌装饰色。
- 不使用渐变、玻璃拟态、无意义插画、重阴影和大面积装饰性色块。

视觉稿用于定义设计意图和层级，不替代公司组件库的真实尺寸、属性及状态。组件最终表现以 CC FE Kit 当前版本为准。页面结构、页面类型和适配方式以 Figma 页面级规范为参考；本方案已经确认的主后台导航、设置 Hub 分类和蓝色主题优先于 Figma 示例中的业务文案、示例导航与示例颜色。

### 2.2 导航交互

一级导航和二级导航只占用同一个侧栏区域，不能并排常驻：

1. 默认显示一级导航。
2. 点击具有二级入口的一级模块后，二级导航从侧边滑入，并完全覆盖一级导航菜单区域。
3. 主内容区不位移、不缩放、不变暗。
4. 二级导航提供“返回上一级”或语义等价的关闭入口。
5. 返回后恢复一级导航原滚动位置和选中状态。
6. 二级滑层不是模态框：主内容不变暗、不设 focus trap，主内容仍可通过鼠标和键盘访问；被覆盖的一级导航容器必须 `inert` 且不参与 Tab 顺序。
7. 打开后，焦点进入二级滑层的标题/返回入口；关闭后准确恢复到触发该滑层的一级导航项。

确定性的状态转换如下：

| 事件 | 结果 |
|---|---|
| 点击具有二级入口的一级项 | 打开该模块二级滑层并聚焦返回入口；记录一级导航滚动位置 |
| 再次触发当前一级项 | 保持二级滑层打开，不重复动画 |
| 点击二级叶子 | 完成路由切换，当前模块二级滑层保持打开，更新选中项 |
| 同模块内路由变化/浏览器前进后退 | 二级滑层保持打开并同步选中项 |
| 跨模块路由 | 关闭原滑层；若目标路由属于另一有二级导航的模块，则打开目标模块滑层并同步选中项；否则显示一级导航 |
| 直接深链或刷新到二级路由 | 根据路由归属直接恢复对应模块二级滑层和选中项，不播放入场动画 |
| 返回上一级/关闭 | 关闭二级滑层，恢复一级导航滚动位置，并聚焦原一级项 |
| `Escape` | 按“当前弹窗 → 三级导航 → 已输入的滑层搜索 → 二级滑层”依次处理；每次只处理最高优先级一层 |
| 页面存在未保存变更时触发路由 | 先进入统一离开确认；取消则所有导航状态不变，确认后再执行目标状态转换 |
| 权限变化导致当前项不可见 | 跳转到该模块首个有权限叶子；若模块无可见叶子则关闭滑层并回到首页 |

### 2.3 设置配置页作为首个标准模板

第一版以设置配置页为样板，因为它能覆盖主后台最常见的复杂度：多级导航、范围筛选、分组、表单控件、帮助说明、变更状态与保存反馈。

唯一首个样板为：

- 页面：订单中心设置
- 路由：`/orders/settings`
- 纳入：主后台 shell、顶栏范围筛选、覆盖式二级导航、设置内容骨架、字段控件、页面内分区、未保存提示与保存栏。
- 不纳入：订单设置的信息架构重分组、后端协议变化、其他设置 Hub 迁移、深色主题重设计。
- 固定数据：使用项目演示账号下确定性的订单设置 fixture；截图前重置为同一 fixture，不依赖当前日期或随机数据。
- 必测语言：中文为视觉基线；英文做布局溢出 smoke test。
- 必测视口：`1440×1024` 视觉基线、`1280×720` 重点回归视口与 `1024×768` 页面级兼容下限。
- 主题：light 为第一阶段冻结基线；现有 dark mode 只要求功能不崩溃和文本可读，不作为本阶段视觉验收基线。

标准骨架：

```text
全局顶栏：集团/品牌/门店范围 + 全局工具 + 用户
├─ 左侧导航：一级导航，或覆盖其上的当前模块二级导航
└─ 主内容
   ├─ 页面标题、说明、最近保存信息
   ├─ 设置工作区
   │  ├─ 左侧纵向分类导航
   │  └─ 右侧当前分类配置
   │     └─ 功能标题 + 默认说明 + 控件 + 状态/错误
   └─ 固定保存栏：变更提示 + 取消 + 主保存操作
```

设置页不得把所有配置平铺为一个无分类的长页面。CSS 视口 `≥1024px` 时，内容区左侧固定展示当前设置 Hub 的纵向分类导航，右侧一次只展示当前分类；CSS 视口 `<1024px` 时使用顶部分类 Select 作为唯一响应式例外。分类使用稳定 `groupKey`；切换分类不改变一级/二级导航状态，并与同一 `/orders/settings` 草稿桶共享未保存变更。

第一阶段不重组订单设置信息架构，样板严格使用当前代码中的六个正式分类：

| 顺序 | 分类 | `groupKey` |
|---:|---|---|
| 1 | 订单基础 | `order-basics` |
| 2 | 改单与分合单 | `order-edit-split-merge` |
| 3 | 删单与退款 | `order-void-refund` |
| 4 | 折扣 | `order-discount` |
| 5 | 附加费与服务费 | `order-surcharge-fees` |
| 6 | 结算取整 | `order-settlement-rounding` |

分类导航在信息层级上低于模块二级导航，不得使用相同宽度、背景或强调强度造成混淆。纵向分类模式是所有设置 Hub 的设计系统目标态；第一阶段只改造并验收 `/orders/settings`，其他 Hub 随后续业务迭代渐进迁移。

分类路由和状态契约：

| 事件 | 确定行为 |
|---|---|
| 进入 `/orders/settings` | 若当前标签页存在最后访问分类，则使用 `replace` 恢复该分类；否则使用 `replace` 到 `/orders/settings/order-basics`。两者均不增加无意义历史项 |
| 进入合法分类 URL | 展示对应分类并恢复该分类本会话滚动位置 |
| 点击其他分类 | 使用新增历史项的导航；右侧切换内容，一级/二级导航不变 |
| 浏览器前进/后退 | 同时恢复分类选中态和该分类滚动位置 |
| 刷新合法分类 URL | 保持分类；滚动位置恢复到顶部，避免跨页面生命周期的陈旧位置 |
| 未知或已删除 `groupKey` | 使用 `replace` 回到 `order-basics`，并显示一次非阻塞提示 |
| 旧 `groupKey` | 按 `src/config/order-settings-group-keys.ts` 的兼容映射 `replace` 到正式 key，不增加历史项 |
| 离开再返回同一 Hub | 当前标签页生命周期内恢复最后访问分类；新标签页默认 `order-basics` |
| 滚动记忆 | 按 `Hub path + groupKey` 保存于内存，只在当前标签页生命周期有效 |

关键 light 主题对比度基线（相对白色 `#FFFFFF`）：

| Token | 对比度 | 允许用途 |
|---|---:|---|
| `--color-primary` `#146EF5` | `4.59:1` | 普通文本、图标、主控件填充 |
| `--color-focus-ring` `#3B73D1` | `4.61:1` | 焦点边界和非文本 UI |
| `--color-control-border` `#66758A` | `4.69:1` | 必要控件边界 |
| `--color-text-secondary` `#607089` | `5.03:1` | 普通字号辅助文本 |
| `--color-warning` `#8A4B00` | `6.80:1` | 普通字号警告文字 |

空间采用受控刻度，优先使用 `4 / 8 / 12 / 16 / 24 / 32`。默认圆角控制在 `6–8px`，只有浮层或特殊大容器可使用更高层级圆角。阴影仅用于真正具有层级关系的浮层。

### 3.2 排版与信息密度

- 正文与控件文本以 `14px` 为主，辅助文字不低于 `12px`。
- 页面标题、分区标题、字段标签、帮助文本建立固定层级，不允许页面自行发明字号。
- 设置页采用中高信息密度；通过对齐、留白和分隔线提高扫描效率，不依赖大量卡片。
- 中文、英文和数字混排时保持一致行高；金额、数量、时间等可比较数据使用等宽数字。

### 3.3 页面级规范与模板选择

页面级规则来源于 Figma 节点 `37594:13917`。该规范明确展示了表格列表、卡片列表、设置/详情型长页面、全屏表单，以及具有业务样板的 `640px`、`800px`、`1000px` 常规弹窗，并以 `1024×768` 作为最小适配尺寸；其中“大弹窗”分区只有标题、没有可验证的业务样板。Figma 中的门店、员工、薪资等内容是结构示例，不直接复制业务文案、信息架构或视觉品牌。

规范优先级如下：

1. 本文已确认的产品交互契约：主后台导航覆盖方式、设置 Hub 分类、草稿和保存行为。
2. Figma 页面级规范：页面类型、内容骨架、密度、适配和浮层分级。
3. CC FE Kit：控件实现、尺寸档位、状态、可访问性和真实 API。
4. 页面业务需求：只决定字段、数据和业务动作，不得重新发明页面骨架或基础控件。

#### 3.3.1 通用页面骨架

```text
主后台 Shell
├─ 全局/模块导航（沿用覆盖式二级导航契约）
└─ 页面画布
   ├─ 页面头：标题/返回、上下文说明、页面级主操作
   ├─ 可选分区导航或范围筛选
   ├─ 页面主体：列表、卡片、详情、设置或表单
   └─ 可选底部操作/分页区
```

- 页面画布使用浅灰背景，内容表面使用白色；页面根部只保留一个主滚动容器。
- 桌面基线左右内容留白为 `24px`；紧凑视口可降至 `16px`，不得小于 `16px`。
- 页面头、筛选区和主体内容使用同一内容起始线。主操作放在页面头右侧，视图内只有一个主按钮。
- 页面存在返回动作时使用明确返回/关闭入口；标题和操作不得依赖滚动后才可发现。
- 业务内容很长时按语义分区，不用任意卡片切碎内容；分区标题、说明和控件遵循同一垂直节奏。
- `1440×1024` 是视觉基线，`1280×720` 是首阶段回归视口，`1024×768` 是页面级兼容下限。低于 `1024px` 不承诺完整桌面布局。

确定性适配矩阵：

| 条件 | 全局导航 | 设置分类 | 内容列与滚动 |
|---|---|---|---|
| `1440×1024` | `220px` 常驻；二级覆盖同一 `220px` 区域 | `184px` 常驻 | 卡片/普通表单双列；页面主体单一纵向滚动 |
| `1280×720` | 同上 | `184px` 常驻 | 右侧可用区不足 `720px` 时表单降单列；表格仅自身横向滚动 |
| `1024×768` | 同上，这是本项目为保留现有导航心智而与 Figma 1024 示例“隐藏全局侧栏”的明确差异 | `160px` 常驻 | 内容区约 `804px`；扣除边距与分类栏后右侧约 `580–600px`，卡片和表单强制单列 |
| `200%` 缩放后 CSS 视口 `<1024px` | 保留 `220px` 导航及其覆盖式二级交互；不另造移动抽屉 | 分类栏改为内容区顶部的分类 Select，dirty/error 数量合并到选项文本和状态说明 | 主体强制单列；允许表格容器横向滚动；主操作、错误与保存入口始终可达 |

列布局只根据页面主体可用宽度判断：可用宽度 `≥720px` 可使用双列，`<720px` 必须单列。卡片每列最小宽度 `420px`，无法同时容纳两列和 `16px` 间距时降为单列。运行时不得把常规弹窗自动“升级”为另一模式；弹窗模式在设计期选定，只在空间不足时按既定 `24px` 安全边距和内部滚动适配。

#### 3.3.2 表格列表页

适用于结构稳定、需要跨行比较、排序、筛选或批量操作的数据。标准顺序为：

```text
页面头/可选页签
筛选与视图操作（48px）
表头（48px）
数据行（默认 64px）
分页（32px 控件高）
```

- 筛选器从左向右排列，视图切换和新增等页面操作靠右；筛选项过多时收进“更多筛选”，不挤压主操作。
- 表头在数据滚动容器内保持可见；分页固定在列表容器底部，不覆盖最后一行。
- 文本默认左对齐，数值按可比较方向对齐，状态使用语义 Tag，行操作集中在最右列并提供可访问名称。
- 宽表只允许表格容器横向滚动；关键识别列和操作列按业务优先级固定，页面根部不得横向滚动。
- 加载使用保持列宽的骨架；空状态位于表格主体并保留筛选区；错误状态提供重试且保留现有筛选条件。

#### 3.3.3 卡片列表页

适用于单项包含头像、摘要、多个标签或快捷动作，且横向字段比较不是首要任务的对象列表。

- 桌面宽屏默认双列；紧凑宽度降为单列。卡片之间使用统一 `16px` 间距，不允许 Masonry 导致阅读顺序不稳定。
- 每张卡片按“身份摘要 → 关键指标 → 状态/能力 → 更多操作”组织；整卡点击与卡内按钮不可形成冲突命中区。
- 卡片同一行保持等高；字段缺失显示明确空值，不通过移除字段造成布局跳动。
- 只有对象具有独立操作和生命周期时才使用卡片；可比较数据超过 4 个核心字段时优先改用表格。

#### 3.3.4 设置/详情型长页面

- 页面头承载标题、范围筛选和主保存操作；范围变化遵循未保存确认规则。
- 摘要信息可使用一块高对比概览区，之后进入白色内容表面；禁止连续堆叠多个装饰性大卡片。
- 长内容按语义段落分组，段落之间 `24px`，组内字段按 `16px` 节奏。复杂数据可在分区内使用表格。
- CSS 视口宽度 `≥1024px` 时，设置 Hub 必须继续使用本文 2.3 节的“内容区左侧纵向分类 + 右侧当前分类”，不能照搬 Figma 示例中的单一长页来取消分类；仅在 `200%` 缩放等导致 CSS 视口 `<1024px` 时，分类栏按 3.3.1 矩阵折叠为顶部分类 Select。
- 保存入口遵循一个 Hub 一次全局提交；长页面必须给最后一个字段预留保存栏与滚动安全区。

#### 3.3.5 全屏表单

适用于字段跨多个强语义分区、需要持续编辑、内容明显超过常规弹窗高度，或关闭前必须处理草稿的任务。

- 本规范的 `fullscreen-form` 固定定义为“视口级模态任务”，不是 Shell 内独立路由页面：打开时不创建历史项，覆盖整个 Shell，底层 Shell 设为 `inert` 并锁定滚动，焦点限制在任务内。
- 它属于 2.2 节 Escape 优先级中的“当前弹窗”；关闭后恢复到打开它的触发控件。若业务需要可分享 URL、刷新恢复、浏览器前进后退或多次跨会话返回，应改用独立路由页面，不能使用 `fullscreen-form`。
- 顶部操作栏提供关闭/返回、任务标题和唯一主操作；内容滚动时操作栏保持可达。
- 内容区左侧可使用分区锚点导航，右侧为表单；锚点只负责页内定位，不替代主后台一级/二级导航。
- 表单内容使用白色语义分区承载，桌面默认两列字段；长文本、选择组和复合控件跨满两列。
- 保存失败保留当前滚动位置与全部输入；提交校验失败时同步高亮锚点并聚焦首个错误字段。
- `Escape` 不直接丢弃内容；有草稿时进入离开确认，无草稿时关闭；保存中禁止关闭并向辅助技术播报状态；保存失败保持打开、保留输入并提供重试。

#### 3.3.6 常规弹窗分级

Figma 的命名与实际样板尺寸并非一一对应：其“小弹窗”区同时出现 `640px` 和 `800px`，其“中弹窗”实例为 `1000px`（最小视口下 `976px`），而“大弹窗”区没有可验证的业务样板。因此工程命名按确定宽度归一化，不直接照搬分区名：

| `pagePattern` | 确定 `max-width` | Figma 依据 | 使用场景 |
|---|---:|---|---|
| `modal-compact` | `640px` | `37735:54345` | 单一对象、少量字段、简短时间配置 |
| `modal-standard` | `800px` | `37735:54280` | 中等表单、复合但不需要分类栏的编辑 |
| `modal-wide` | `1000px` | `37735:52864`；1024 视口下实例 `37735:52986` 为 `976px` | 分类 + 详情、变更对比、素材选择或宽内容 |
| `fullscreen-form` | 视口级 | 全屏弹窗区实例 | 多分区长表单、独立临时任务流 |

Figma“常规弹窗（大）”由于缺少业务画板，不纳入第一阶段可选模板；需要超过 `1000px` 的普通弹窗必须改用 `fullscreen-form` 或提交设计系统例外评审。

- 弹窗尺寸按内容复杂度选择，不能为了展示更多信息无限增高；内容超高时只滚动弹窗主体，头部和主操作保持可见。
- 标准头部高度参考 `72px`，关闭入口在左、标题居左、主操作在右；按钮文案使用具体动词，不使用泛化“Confirm/确定”。
- 遮罩只用于模态弹窗；容器使用 `role="dialog"`、`aria-modal="true"` 并通过 `aria-labelledby`/`aria-describedby` 关联标题和必要说明。打开后底层内容 `inert`、页面滚动锁定，焦点进入标题或首个可操作元素，使用 focus trap，关闭后恢复触发点。
- 三档常规弹窗统一使用 `width: min(pattern max-width, calc(100vw - 48px))`，高度不超过 `calc(100vh - 48px)`，始终保留至少 `24px` 视口安全边距；因此 `modal-wide` 在 `1024×768` 下恰为 `976×720`，与 Figma 节点 `37735:52986` 一致。若设计评审时已知可用尺寸不足以完成任务，应直接选择 `fullscreen-form`，运行时不自动切换模式，也不通过缩小字号或控件解决。

关闭行为状态契约：

| 状态 | 关闭按钮 / `Escape` / 点击遮罩 |
|---|---|
| pristine | 关闭；点击遮罩默认不关闭编辑型弹窗，纯查看弹窗可关闭 |
| dirty | 进入统一离开确认；取消后焦点回到原关闭入口 |
| validation-error | 视为 dirty，保留错误和输入后进入离开确认 |
| saving | 全部关闭入口禁用，点击遮罩无效，并播报“正在保存” |
| saved | 完成业务回调后关闭并恢复触发点 |
| save-error | 保持打开且视为 dirty，提供重试；关闭仍需确认 |

以上行为优先使用 CC FE Kit `Modal/Confirm` 的真实 API；如无法实现，进入 4.4 节 gap matrix 流程，页面不得自行拼装弹窗焦点管理。

#### 3.3.7 模板选择门禁

新页面在设计和代码评审中必须先声明 `pagePattern`：`table-list`、`card-list`、`settings-detail`、`fullscreen-form`、`modal-compact`、`modal-standard` 或 `modal-wide`。无法匹配时需说明业务差异并由设计系统维护者确认，禁止以“新功能”为理由自由生成新骨架。

选择顺序：先判断是否需要独立路由；再判断核心任务是跨行比较、对象浏览、配置/详情还是集中编辑；最后依据内容复杂度决定页面或弹窗。页面模板只定义结构，不改变 CC FE Kit 的组件优先级。

### 3.4 页面容器与分组

- 一个页面只保留一个主要内容表面，避免“卡片套卡片”。
- 设置分区优先使用标题行、浅色表头和分隔线。
- 只有可独立移动、关闭或拥有独立生命周期的对象才使用卡片。
- 设计系统目标态要求设置 Hub 在 CSS 视口 `≥1024px` 时采用内容区左侧纵向分类导航；`<1024px` 时使用顶部分类 Select。第一阶段只强制 `/orders/settings`，其他 Hub 渐进迁移。分类切换替换右侧配置内容，并按既定状态契约记忆滚动位置。
- 左侧分类导航或其响应式分类 Select 必须显示隐藏分类中的未保存标记和校验错误数量；无 dirty/error 时不得显示无业务含义的数量装饰。
- 固定保存栏出现时不得遮挡最后一项内容，内容区需要保留等量底部空间。

### 3.5 设置字段布局

设置字段不强制只有一种排版，依据控件复杂度使用两种标准模板。

**默认模板：简单设置两列布局**

```text
功能标题                 控件区域
默认说明                 控件区域内左对齐
```

- 左侧信息块依次展示功能标题和默认说明；说明紧跟标题下方，使用较弱文本色。
- 右侧建立稳定控件区域，所有不同类型控件对齐该区域的左边缘，不贴页面右边缘。
- 单个 Switch、Select、Input、短 Radio/Checkbox 组选用此模板。
- Select/Input 使用统一宽度档位；Switch 保持自身宽度；Radio/Checkbox 组从同一起始线横向排列，空间不足时换行。
- 默认说明不得放到控件右侧。控件下方只保留校验错误、动态状态、单位或只与当前控件有关的提示。
- 当当前设置内容区可用宽度 `<720px` 时，简单设置模板确定折叠为“功能标题 → 默认说明 → 控件”的单列顺序；控件仍左对齐且不自动拉伸，除非该控件本身定义为满宽。该响应式折叠不把简单字段重新归类为复杂字段。

**扩展模板：复杂设置三行纵向布局**

```text
功能标题
默认说明
复杂控件或组合配置区域
```

- 适用于长说明、多字段组合、日期/营业时间、动态列表、规则编辑、超过 3 个选项的选择组、需要满宽展示或带预览的控件。
- 复杂控件区域与标题左边缘对齐，可占满右侧内容宽度。
- 同一分区可以混用两种模板，但间距、标题、说明和状态语义必须一致。

例外：表格中的状态开关按状态列居中；卡片/分区标题栏内唯一且明确归属的开关可右对齐。除此之外，不允许为了“整齐”把不同宽度控件统一贴到页面右边缘。

## 4. CC FE Kit 组件治理

### 4.1 优先级

组件来源优先级：

1. CC FE Kit 已提供且满足需求的组件。
2. 项目基于 CC FE Kit 封装的业务组件。
3. 项目已有、经过统一规范审计的共享组件。
4. 仅当以上均不能满足且有明确业务差异时，才允许新建基础组件。

禁止在页面内部重新手写 Button、Input、Select、Checkbox、Radio、Switch、DatePicker、Modal、Alert、Message、Empty、Tooltip 等已有基础控件。

### 4.2 已确认可映射能力

根据公司组件文档导航，首批映射如下：

| 页面需求 | CC FE Kit |
|---|---|
| 主/次/危险操作 | Button |
| 文本与数值输入 | Input / InputNumber / Textarea |
| 单选、多选、开关 | Radio / Checkbox / Switch |
| 普通选择、筛选选择 | Select / SelectFilter |
| 搜索 | SearchInput / AutoComplete |
| 日期与时间相关选择 | DatePicker |
| 确认、弹层和提示 | Confirm / Modal / Alert / Message |
| 空数据和解释 | Empty / Tooltip / Text |
| 布局 | Flex / Splitter |

### 4.3 API 核对门禁

公司组件库文档版本当前显示为 `v0.0.5`。设计规范不臆造组件属性：每次实现前必须打开对应组件页面，核对当前版本的导入方式、属性、事件、尺寸、禁用态、加载态和错误态。若文档不可用或组件不满足需求，必须记录差距后再决定业务封装，不能静默改用自制控件。

### 4.4 CC FE Kit 接入决策与先行验证

当前仓库是 Vite + TypeScript + 原生 DOM/HTML 字符串架构，`package.json` 尚未声明 CC FE Kit、React 或 Ant Design；因此“直接引入组件库”尚未被证明可行。实施计划的第一个任务必须是只读调研加最小技术验证，不能直接开始全页迁移。

验证必须确认并记录：

- 正式 npm 包名、允许安装的版本、内部 registry 与授权方式。
- 组件是否要求 React，以及 React/Ant Design 等 peer dependencies。
- 原生主后台采用整体迁移、局部 React island 还是适配器封装；默认优先最小影响的局部验证，不预先承诺全量迁移。
- CSS reset、主题样式和现有 Tailwind/app.css 的加载顺序。
- Button、Input、Select、Switch、Modal 五个代表组件能否在 `/orders/settings` 的隔离验证容器中正常渲染、响应键盘、切换主题 Token 且不污染现有页面。

通过标准：构建成功、无重复 React/runtime、无全局样式破坏、五类组件交互及焦点正常、主题可映射、bundle 影响已记录。验证未通过时暂停组件迁移，并在 `docs/design-system/cc-fe-kit-gap-matrix.md` 登记：需求、目标组件、阻断原因、临时 fallback、影响页面、负责人、批准人和复查日期。临时 fallback 只能复用当前项目共享组件，不得在业务页面新造基础控件。技术负责人批准后方可使用。

## 5. 交互标准

### 5.1 操作层级

- 每个视图只有一个视觉主操作。
- 取消、返回、重置为次操作；删除、停用等不可逆或高风险操作使用危险语义。
- 操作名称使用“动词 + 对象”，例如“保存设置”“新增时段”，避免含糊的“确定”。
- 高风险操作必须通过 Confirm/Modal 明确对象和后果。

### 5.2 表单反馈

- 校验错误贴近字段展示，并保留用户已输入内容。
- 依赖条件导致字段不可用时优先禁用并说明原因，不直接隐藏关键规则。
- 保存中禁用重复提交并显示加载态。
- 保存成功使用 Message 或等价轻反馈；失败保留未保存状态并给出可执行的重试信息。
- 离开存在未保存变更的页面时使用项目统一离开确认。

### 5.3 页面状态

每个页面或业务组件必须覆盖：

- 默认/有数据
- 加载
- 空状态
- 错误与重试
- 无权限/只读
- 控件禁用
- 保存中、保存成功、保存失败
- 部分数据或部分失败（适用时）

设置页状态闭环：

| 状态 | 用户可见结果 | 可用操作与恢复 |
|---|---|---|
| pristine | 不显示未保存提示；保存按钮禁用 | 可编辑字段 |
| dirty | 显示未保存提示；保存栏出现或进入强调态 | 保存、取消、继续编辑 |
| validation-error | 字段就近错误 + 首个错误摘要 | 保留全部输入；修正后重试 |
| saving | 保存按钮 loading，相关提交入口禁用 | 不清空输入，不允许重复提交 |
| saved | Message 成功提示；最近保存信息更新；回到 pristine | 继续编辑 |
| save-error | 明确错误与重试；保持 dirty | 重试、取消、复制必要信息 |
| cancel | 恢复到最近一次成功保存值 | 回到 pristine |
| stale/conflict | Alert 说明数据已更新 | 重新加载最新值或进入明确的覆盖确认；禁止静默覆盖 |
| readonly | 显示只读原因；控件呈只读而非伪禁用 | 可复制/查看，无保存入口 |
| no-permission | 不展示敏感配置内容 | 提供返回或申请权限指引 |
| partial-failure | 仅批量/分区独立保存场景适用，逐项标明成功与失败 | 保留失败项输入并提供重试 |

“最近保存信息”初始取最近一次成功保存记录；保存失败时不更新。保存栏在 pristine 状态下保留布局位置但按钮禁用，避免页面跳动。

分类与草稿遵循一个 Hub、一个草稿、一次全局提交：

- 分类切换属于 Hub 内导航，不触发页面离开确认，也不丢失任何分类的草稿值。
- 保存作用于整个 `/orders/settings` 草稿桶，不只保存当前可见分类；取消恢复整个 Hub 到最近一次成功保存值。
- 未渲染分类中的 dirty 值、字段错误和服务端错误必须保留。
- dirty 分类必须显示未保存标记；存在校验错误的分类必须显示错误数量，两者均为必需状态。
- 提交时如隐藏分类存在错误，系统自动切换到排序最前的错误分类，滚动并聚焦该分类首个错误字段，同时保留其他分类输入。
- 只有真正离开 `/orders/settings` Hub、跨模块或关闭页面时才触发未保存离开确认；分类间切换不触发。
- partial-failure 仍以整个 Hub 为一次提交结果呈现，但必须把失败项映射回对应分类并提供重试入口。

## 6. 可访问性与响应式

- 所有控件必须有可访问名称，不能只依赖图标表达含义。
- 键盘可到达所有可操作元素；焦点样式使用蓝色焦点环且不可被移除。
- 二级导航滑层打开后管理焦点范围；关闭后恢复到触发项。
- 文本与背景满足 WCAG 2.2 AA：普通文本至少 `4.5:1`，大文本和非文本 UI 至少 `3:1`；状态不能只依赖颜色区分。
- `1440×1024` 为视觉基线，`1280×720` 为第一阶段重点回归视口，`1024×768` 为 Figma 页面级兼容下限；在 `200%` 浏览器缩放下核心操作仍可到达且文本不截断。
- 在 `1024×768` 下，卡片列表和双列表单强制降为单列，溢出的筛选项收进“更多筛选”；导航契约、主操作、错误信息和保存入口不得消失。
- 只有明确标记的表格/宽内容容器允许内部横向滚动；页面根容器禁止同时出现横向和纵向双轴滚动。
- Tab 顺序遵循顶栏 → 当前可见导航 → 主内容 → 保存栏；焦点环不得被移除。
- 二级滑层使用 `180ms` 标准曲线；`prefers-reduced-motion: reduce` 时取消位移动画，只做即时状态切换。

## 7. 三种方案取舍记录

本轮比较了三种方向：

1. 青绿企业型：与当前品牌连续性最好，但改变幅度较小。
2. 暖色运营型：亲和、区分度强，但橙色在高频设置页中容易与警告语义竞争。
3. 蓝色结构型：状态清晰、可扩展性好，适合高密度后台，最终被选中。

最终方案使用方向 3 的蓝色主题，并沿用项目既有的“二级导航覆盖一级导航菜单区域”交互。

## 8. 工程化落地

第一阶段只建立标准和样板，不一次性重构全部页面：

1. 盘点 `src/styles/app.css`、`src/ui` 和现有共享模式。
2. 建立语义 Tokens 与 CC FE Kit 主题映射。
3. 建立统一页面壳、标题区、设置分区、字段行和保存栏。
4. 建立 `table-list`、`card-list`、`settings-detail`、`fullscreen-form`、`modal-compact`、`modal-standard`、`modal-wide` 的页面模板契约。
5. 把现有导航滑层固化为共享交互契约，保持覆盖式行为。
6. 选择一个真实设置配置页完成样板迁移，并覆盖完整状态。
7. 形成 `DESIGN.md` 与项目专属 `admin-web-design-system` Skill。
8. 新页面强制声明 `pagePattern` 并使用对应模板、组件映射和验收清单；旧页面按业务改动逐步迁移。

强制规则的交付证据：

- `docs/design-system/cc-fe-kit-gap-matrix.md`：组件能力与例外登记。
- `docs/design-system/page-review-checklist.md`：页面结构、状态、键盘和响应式 review 清单。
- `docs/design-system/page-patterns.md`：七种 `pagePattern` 的选择树、结构槽位、允许例外与 Figma 节点映射。
- 对新增基础控件 class/原生标签的静态扫描规则；允许项必须指向 gap matrix 编号。
- `/orders/settings` 的状态测试、导航状态机测试和键盘焦点测试。
- `1440×1024`、`1280×720`、`1024×768` 中文结构/视觉截图基线，以及英文溢出 smoke 截图；七种 `pagePattern` 至少各有一份可审计结构基线。
- 视觉回归采用关键区域基线对比；像素阈值在技术验证中根据字体渲染噪声确定并写入测试配置，任何超阈值差异必须人工批准。

## 9. 验收标准

- 新设置页与视觉基准在布局、层级、密度和蓝色语义上保持一致。
- 新页面已声明受支持的 `pagePattern`；页面头、筛选、主体、分页/保存区与对应 Figma 页面级模板一致，例外有批准记录。
- 表格列表、卡片列表、设置/详情、全屏表单以及 compact/standard/wide 弹窗均有明确选择条件，不以业务页面为单位重新发明骨架。
- 二级导航只覆盖一级导航区域，主内容区打开前后位置和宽度不变。
- 深链、刷新、前进后退、跨模块、返回、Escape 优先级和未保存拦截逐项通过导航状态机测试。
- `/orders/settings` 使用六个现有正式 `groupKey`：CSS 视口 `≥1024px` 为左侧纵向分类导航，`<1024px` 为顶部分类 Select；根路径规范化、合法/非法/旧 key、刷新、前进/后退、选中态和会话内滚动记忆通过状态契约测试。
- 跨分类只有一个 Hub 草稿和一次全局保存/取消；隐藏分类 dirty/error 标记、错误数量、自动定位首个错误及输入保留通过测试。
- 内容区可用宽度 `≥720px` 时，简单字段使用“左侧标题与下方说明 + 右侧控件列内左对齐”；`<720px` 时按“标题 → 说明 → 控件”折叠为单列。复杂字段使用“标题 + 说明 + 满宽控件”的三行模板，且不存在不同控件贴页面右边缘造成的起始线跳动。
- 页面中的基础控件均能映射到 CC FE Kit 或有记录完整的例外理由。
- 不出现页面级自定义主色、随机圆角、重复 Button/Input/Switch 实现。
- 键盘导航、焦点恢复、错误提示和未保存离开保护可验证。
- 加载、空、错误、只读、保存成功/失败状态均有明确表现。
- 视觉回归覆盖 `1440×1024`、`1280×720` 和 `1024×768`；中文基线通过，英文无截断或不可达操作。
- WCAG AA 对比度、键盘顺序、焦点恢复、200% 缩放和 reduced-motion 行为通过检查。

- 本阶段不改造 `vendor/emenu-new` 或其发布产物。
- 本阶段不统一嵌入应用内部的技术栈。
- 本阶段不一次性替换所有历史页面。
- 本阶段不以视觉稿替代 CC FE Kit 的 API 文档。
