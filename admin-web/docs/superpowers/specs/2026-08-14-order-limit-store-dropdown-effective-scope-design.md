# 数量与频次规则门店下拉与生效范围调整设计

## 背景

现有数量与频次规则在第 2 步“商品配置”中使用门店表格勾选参与门店，再通过门店标签切换商品配置；实际发布门店则在第 7 步之后的独立页面中再次选择。两处门店选择容易让用户把“已经准备好商品与数量配置的门店”误解为“本次一定生效的门店”。

本次调整把两类范围明确拆开：

- 商品配置门店：表示已经为哪些门店准备了商品范围和数量矩阵。
- 生效门店：表示本次发布实际在哪些门店启用规则。

允许为 A、B 门店都准备完整配置，但本次只让 B 门店生效；A 的配置继续保留，之后可以直接启用。

## 已确认口径

- 商品配置通过单选下拉切换门店。
- 下拉展示全部可用门店，只显示门店名称，不标记“已配置/未配置”。
- 第 2 步不再展示参与门店表格和门店标签。
- 所有已经选择商品的门店都必须完成各自数量矩阵。
- 当前门店表格移动到第 5 步“生效范围”。
- 生效门店表格继续展示全部门店；已添加门店可勾选，未添加门店禁用。
- 至少选择一家生效门店。
- 移除原后置“选择发布门店”页面；第 7 步直接进入现有发布确认页。

## 页面流程

### 第 2 步：商品配置

“选择商品”区块顶部增加“配置门店”单选下拉框，宽度约 320px。选项为全部当前可用门店名称，不显示 MID、地址或配置状态。

新建规则首次进入第 2 步时，下拉显示占位文案“请选择配置门店”，不默认选中第一家门店。这样可以避免用户未注意门店上下文时把商品关联到错误门店。编辑草稿、刷新或从后续步骤返回时，恢复上次正在编辑的有效门店。

未选择门店时，下方显示空状态“请选择门店后配置商品”。选择门店后，直接展示原有“产线 → 组 → 分类 → 菜品”结构选择器，并读取该门店的 `storeConfigs[storeId]`。

切换下拉门店时：

1. 当前门店商品变更已经随操作写入草稿并自动保存。
2. 清空批量选择等临时交互状态。
3. 更新 `activeStoreId`。
4. 加载新门店独立的商品结构与摘要。

仅选择下拉选项不会把门店计为已配置。门店至少选择一个符合当前限购对象的分类或菜品后，才进入商品配置范围。清空全部商品后，该门店恢复为未配置，同时清理该门店数量矩阵。

第 2 步校验保持“至少一家门店已选择商品”。

### 第 4 步：限购数量

保留当前门店切换、人数场景、轮次场景和产线设置结构。门店切换范围仅包含已经选择商品的门店。

所有商品配置门店都必须完成数量矩阵，即使某家门店稍后不会被选为本次生效门店。这样未生效门店仍是一份可随时启用的完整配置，不产生“门店已有商品但数量未准备好”的半成品状态。

单项输入、批量设置和禁止下单仍只作用于当前门店。切换门店、人数、轮次或产线时退出批量模式并清空临时勾选。

### 第 5 步：生效范围

第 5 步内容顺序调整为：

1. 生效门店。
2. 有效日期与营业时段。
3. 生效星期。
4. 会员范围。

“生效门店”使用原后置门店页的表格形式，列为：

1. 勾选框。
2. 门店名。
3. MID。
4. 地址。
5. 商品状态。

状态和选择规则：

- 已添加：该门店已经选择商品，绿色文案，允许勾选。
- 未添加：没有有效商品目标，红色文案，勾选框禁用。
- 已勾选行使用浅蓝色背景。
- 门店第一次从未添加变为已添加时，默认加入生效范围。
- 用户可以取消部分已添加门店，但至少保留一家才能通过第 5 步校验。
- 取消生效只修改生效范围，不删除该门店商品和数量配置。

如果用户返回第 2 步并清空某个已生效门店的商品，该门店立即从生效范围移除；再次进入第 5 步时显示未添加并禁用。

### 第 7 步与发布

第 7 步复核区展示最终 `deployStoreIds` 对应的生效门店。点击“保存并下发”后直接进入 `order-limit-publish-confirm.html`，不再跳转到 `order-limit-store-select.html`。

发布确认页继续执行完整校验并只展示最终生效门店。确认发布后，正式快照只包含最终生效门店对应的 `storeConfigs`。

原 `order-limit-store-select.html` 不再承担选择职责。为了兼容旧书签或草稿链接，访问该页面时重定向到相同草稿的规则编辑页并打开第 5 步；不得形成第二套门店选择状态。

## 数据模型与字段语义

继续使用现有草稿结构：

```js
{
  activeStoreId: "ny-midtown",
  participatingStoreIds: ["ny-midtown", "flushing"],
  deployStoreIds: ["flushing"],
  deployExcludedStoreIds: ["ny-midtown"],
  storeConfigs: {
    "ny-midtown": {
      structureByLine: {},
      productLines: [],
      targetIds: [],
      limits: {},
    },
    flushing: {
      structureByLine: {},
      productLines: [],
      targetIds: [],
      limits: {},
    },
  },
}
```

字段语义调整为：

- `activeStoreId`：第 2 步门店下拉或第 4 步门店切换当前正在编辑的门店。
- `participatingStoreIds`：已经拥有有效商品目标的门店集合；不再表示第 2 步表格勾选结果。
- `storeConfigs`：每家门店独立的商品结构、目标、产线和数量矩阵。允许暂时保留空配置，但空配置不进入 `participatingStoreIds`。
- `deployStoreIds`：第 5 步最终勾选的生效门店。
- `deployExcludedStoreIds`：用户曾主动取消生效的门店，用于刷新、返回和商品重新添加后的选择记忆。

### 商品状态变化

门店从无商品变为有商品时：

1. 加入 `participatingStoreIds`。
2. 如果不在 `deployExcludedStoreIds`，默认加入 `deployStoreIds`。
3. 保留或新建该门店独立数量矩阵。

门店从有商品变为空时：

1. 从 `participatingStoreIds` 移除。
2. 从 `deployStoreIds` 移除。
3. 清空该门店数量矩阵。
4. 保留人工排除记录，使以后重新配置商品时不会推翻之前的取消决定。

用户在第 5 步取消生效时，把门店加入 `deployExcludedStoreIds`；重新勾选时从排除集合移除。

## 校验规则

### 第 2 步

- 规则名称必填。
- 至少一家当前可用门店具有有效商品目标。

### 第 4 步

- 遍历全部 `participatingStoreIds`。
- 每家门店的全部人数、轮次、产线和目标单元格都必须填写非负整数。
- `0` 表示禁止下单，空值表示未配置。

### 第 5 步

- `deployStoreIds` 至少包含一家门店。
- `deployStoreIds` 只能包含具有有效商品目标的当前可用门店。

### 第 7 步与发布确认

- 重新执行第 2 至第 5 步校验，禁止通过直接 URL 绕过。
- 最终生效门店必须具有完整数量矩阵。
- 发布确认页只能读取 `deployStoreIds`，不能自行补选其他已配置门店。

## 历史兼容

- 已有 `storeConfigs` 的草稿和规则不重复迁移，保留每家门店商品与数量配置。
- `participatingStoreIds` 在归一化时按具有有效商品目标的当前可用门店重新计算。
- 现有 `deployStoreIds` 和 `deployExcludedStoreIds` 继续保留，作为第 5 步初始选择状态。
- 历史草稿的 `activeStoreId` 仍有效时恢复该门店；无效时第 2 步显示“请选择配置门店”。
- 没有门店维度的更早历史规则继续沿用既有迁移逻辑。
- 正式发布快照仍裁剪为仅包含 `deployStoreIds` 对应配置。

## 路由调整

- 第 7 步“保存并下发”：`order-limit-rule-editor.html` → `order-limit-publish-confirm.html`。
- 发布确认页返回：回到规则编辑页第 7 步。
- 旧门店选择页：重定向到规则编辑页第 5 步。
- 编辑页增加对明确步骤参数的安全解析，只允许进入已经解锁且不超过第 5 步的兼容重定向目标；正常向前操作仍执行逐步校验。

## 异常与状态清理

- 门店下拉选择到不可用或不存在的 ID 时，恢复占位状态，不创建悬空配置。
- 全局修改限购对象时，沿用重置确认并清空全部门店商品与数量配置，同时清空生效门店选择。
- 修改人数区间、轮次区间或统计周期时，清空全部门店数量矩阵，不修改商品范围和生效门店选择。
- 第 5 步取消到零家时允许继续编辑，但点击下一步时提示“请至少选择一家生效门店”。
- 保存失败沿用现有草稿恢复与错误提示机制。

## 验收标准

1. 第 2 步只展示单选门店下拉，不展示门店表格或门店标签。
2. 下拉展示全部门店名称且不显示配置状态。
3. 新建规则下拉默认为空，选择门店后才展示商品结构。
4. A、B 门店商品和数量矩阵独立保存，切换门店不会相互覆盖。
5. 所有已配置商品门店都必须完成数量矩阵。
6. 第 5 步展示全部门店、MID、地址和商品状态。
7. 未添加门店禁用；已添加门店可勾选并默认生效。
8. A、B 均配置完整但第 5 步只勾选 B 时，A 配置保留且本次不生效。
9. 刷新、返回和重新进入后，商品配置与生效选择保持一致。
10. 清空 A 商品后，A 自动取消生效并在第 5 步变为未添加。
11. 第 7 步只展示最终生效门店，并直接进入发布确认页。
12. 原后置门店页不再提供选择功能，旧链接重定向到第 5 步。
13. 正式发布快照只包含最终生效门店配置。
14. 历史草稿和规则可以继续编辑并保持原有门店数据。
15. 分类限购、菜品限购、单项数量、批量数量、禁止下单和全局场景重置均不回归。

## 测试方案

- 静态专项验证：检查第 2 步下拉、第 5 步表格、路由和数据字段使用位置。
- 既有回归：标题焦点、列表滚动、批量目标选择、未配置状态、门店独立配置。
- 构建验证：执行完整 TypeScript 与 Vite 构建。
- 浏览器流程：
  1. 选择 A 并配置商品。
  2. 切换 B 并配置不同商品。
  3. 分别完成 A、B 数量矩阵。
  4. 第 5 步取消 A，只保留 B。
  5. 返回第 2 步确认 A、B 商品仍在。
  6. 再回到第 5 步确认 A 仍未选中。
  7. 第 7 步确认只展示 B。
  8. 进入发布确认并验证正式快照仅包含 B。
