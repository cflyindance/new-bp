# Kiosk 小费页面置于支付方式选择前设计

## 目标

在 Kiosk 本地配置后台「小费设置 → 选择小费流程」中新增「支付方式选择页面之前」。当信用卡/借记卡与柜台支付均启用且均允许展示小费时，门店可以把点单流程从“先选择支付方式，再选择小费”调整为“先选择小费，再选择支付方式”。

## 现状

- 「选择小费流程」使用 Kiosk 配置 `id: 24`、`key: "tip-procedure"`。
- 现有值：`0` 为「刷卡之前」，`1` 为「刷卡之后」。
- 当仅启用一种支付方式时，现有流程不会展示支付方式选择页，而是直接进入该支付方式对应的后续流程。
- 当信用卡和柜台支付同时启用时，当前先进入 `/paymentType`；选择信用卡且配置为刷卡前小费时，再进入 `/tippingPanel`。
- `/tippingPanel` 确认后当前固定继续信用卡最低消费校验与 `/cardPayment`，因此新流程不能只改入口顺序，还必须让小费页按进入场景决定下一页。

## 配置设计

扩展既有枚举，不新增配置 ID：

```js
{
  id: 24,
  key: 'tip-procedure',
  value: 2
}
```

- `0`：刷卡之前（既有语义不变）；
- `1`：刷卡之后（既有语义不变）；
- `2`：支付方式选择页面之前（新增）。

所有语言增加 `tip-procedure-2`。简体中文准确显示「支付方式选择页面之前」。

## 可选资格与联动

只有同时满足以下条件，值 `2` 才可选择：

1. 「支付设置 → 选择支付方式」同时启用信用卡/借记卡（`0`）和柜台支付（`1`）；
2. 「小费设置 → 显示小费选项」同时勾选信用卡/借记卡和柜台支付。

界面始终展示第三个单选项，但资格不满足时置灰禁用。资格由当前编辑态 POS 支付配置与 Kiosk `tipPaymentTypes` 共同计算，不等待保存后数据。

若当前已经选择值 `2`，之后取消任一支付方式或对应小费选项，系统立即把 `tip-procedure` 自动恢复为值 `0`「刷卡之前」。加载到值 `2` 的历史或异常配置时，在 POS 支付配置加载完成前不改写；加载完成并确认资格不满足后同样回退到 `0`，统一保存时持久化。

## 点单流程

### 双支付方式且选择值 2

在所有原本即将进入 `/paymentType` 的点单入口统一判断：

1. 当前确实同时启用信用卡和柜台支付；
2. 两种方式均启用小费；
3. `tip-procedure.value === 2`。

满足后先进入 `/tippingPanel`。小费确认并保存金额后进入 `/paymentType`，不在此时执行信用卡最低消费检查，也不预先写入信用卡支付方式。用户随后在支付方式选择页选择信用卡或柜台支付，并继续各自既有流程；此前选择的小费金额随订单继续保留。

订单状态增加“支付方式选择前小费已完成”的显式标志和选择元数据 `tipSelection`。元数据至少区分 `percentage`、`custom`、`none`，并保存原始比例或自定义金额，不能只从最终数值反推。小费确认（包括 No Tip）时同时写入最终小费金额、选择元数据和完成标志；`PaymentType` 看到值 `2` 与该标志后直接处理用户所选支付方式，不得再次进入小费页。该标志与元数据在返回小费页修改时保持，重新确认同步覆盖三者；在新订单、重下单、取消当前订单和订单完成清理时随订单状态一起清除。刷新或路由 state 丢失时以订单状态为准，避免重复展示小费；不能只使用一次性的 location state。

返回操作遵循页面栈：支付方式选择页返回小费页，小费页返回其原点单入口。由支付方式页返回小费页时，小费页从订单中的 `tipSelection` 恢复：预设比例恢复对应选中项并按当前订单基数重算，自定义金额恢复自定义选中与原始金额，No Tip 恢复 No Tip；再次确认以当前选择同步覆盖最终金额、元数据和完成标志。

若用户从支付方式页返回小费页后继续返回原点单入口，视为取消本轮结账：立即清零订单小费金额，并清除 `tipSelection` 与完成标志。之后编辑购物车或再次结账必须重新进入小费页并按新订单金额计算，不能复用旧结果。

### 单支付方式

值 `2` 在配置层面不会对单支付方式生效，因为资格不成立并会回退为 `0`。单支付方式继续沿用现有行为：不展示 `/paymentType`，符合小费条件时直接进入小费页，再进入唯一支付方式的后续流程。

### 既有值 0 与 1

- 值 `0` 与值 `1` 的入口、信用卡支付、小费和签名顺序保持不变。
- 新增判断使用严格枚举比较，不能再把所有非零值笼统当作“刷卡之后”，避免值 `2` 被旧的 truthy 判断误判。
- 信用卡支付完成后的“后付小费”仅允许 `tip-procedure === 1` 触发；值 `2` 与值 `0` 都视为小费已在支付前处理，不能进入 `/afterCreditCardPay`。

## 组件与逻辑边界

- 新增共享流程资格/路由判断函数，集中处理支付方式集合、`tipPaymentTypes` 和 `tip-procedure`，供设置页及多个点单入口复用。
- `RadioGroup` 支持按选项禁用，不把业务资格判断写死在通用单选组件中；`ServiceItem` 接收计算后的禁用项。
- `serviceSetting/index.js` 负责当前编辑态资格计算、点击拦截、资格失效后的自动回退，以及保存前兜底。
- 所有现有“进入支付方式选择页”的入口改用同一个路由决策，避免手机号、姓名、CRM、短信判断等入口行为不一致。
- `TippingPanel` 根据显式继续目标处理 `paymentType`、单信用卡和单柜台支付，不再假定确认后一定进入信用卡。其他既有场景继续进入原信用卡校验/支付流程。
- 已知 `id: 24` 消费方（设置保存、`mainPage.updateTipsConfig`、各支付入口、`PaymentType`、`CardPayment.afterPayment`、`ConnectionError` 及小费/签名后续页）全部改为严格枚举或共享判断；完成前用 `rg` 清点，禁止遗留依赖 truthy 的流程判断。

## 状态传递

进入小费页时通过显式导航上下文标记继续目标 `paymentType`、单信用卡或单柜台支付；确认后把“已完成”事实写入订单级状态。导航上下文决定本次确认的直接下一页，订单级状态负责跨返回、刷新及后续支付步骤防重。

不得仅根据 `tip-procedure === 2` 推断下一页，因为单支付、恢复页面或其他旧入口可能直接进入小费页；显式上下文能避免这些场景被错误导向支付方式选择页。若上下文丢失，使用当前订单完成标志与统一支付入口解析器恢复；仍无法确定时清除本轮预支付小费状态并返回安全的统一支付入口，不猜测信用卡。

## 页面停留期间资格变化

小费页确认时重新读取实际支付能力、POS 支付配置和 `tipPaymentTypes`：

- 若仍满足双支付双小费，保存金额与完成标志后进入支付方式页；
- 若退化为唯一可用且允许小费的方式，则保留本次选择，把继续目标切换为该单一方式并走其既有后续流程，不展示支付方式页；
- 若剩余方式不允许小费或无法确定安全目标，则把订单小费清零、清除 `tipSelection` 与完成标志，并交给统一支付入口解析器继续，不把失效小费带入订单。

支付方式页也在实际选择时复核所选方式仍可用；如果订单完成标志缺失，不直接支付，而是回到统一入口重新判定，防止刷新恢复或异常跳转绕过小费规则。

## 异常与兼容

- 未知 `tip-procedure` 值按值 `0` 的安全流程处理。
- POS 支付配置加载中，第三项禁用但不自动改写已保存值；加载完成后再确认资格。
- 资格失效即使未成功保存，点单运行时也会重新校验双支付及双小费条件，不会错误进入“先小费”流程。
- Dual Price 授权逻辑明确覆盖值 `2`：值 `2` 与值 `0` 都属于刷卡前选择小费，未授权时选择/保存值 `2` 必须触发现有密码流程；授权取消或失败不得保存值 `2`；授权成功后保存及重新加载保持值 `2`。`mainPage.updateTipsConfig` 只把未授权的值 `0`/`2` 修正为值 `1`，不能把已授权值 `2` 错误修正。所有后付判断严格使用 `=== 1`。
- 礼品卡不参与该资格，也不新增礼品卡小费流程。
- 配置页资格严格由用户确认的三项设置决定，不额外受设备配置影响；运行时进入新顺序前还必须确认当前设备实际可同时提供信用卡和柜台支付，否则按单支付/安全回退处理。
- 礼品卡即使与卡、柜台支付并存，也不获得小费资格；值 `2` 的支付方式页不得让订单携带预选小费进入礼品卡流程。若现有页面展示礼品卡入口，选择礼品卡前清零本轮小费、`tipSelection` 与完成标志，并沿用礼品卡既有流程。

## 验收标准

1. 「选择小费流程」展示第三项「支付方式选择页面之前」。
2. 仅当支付设置和显示小费选项都同时包含信用卡/借记卡、柜台支付时，第三项可选。
3. 任一条件不满足时第三项置灰且点击无效。
4. 已选第三项后取消任一支付方式或小费选项，立即自动回退为「刷卡之前」。
5. 加载到无效的值 `2` 时，等待支付配置加载完成后回退，保存后刷新仍为值 `0`。
6. 双支付、双小费且值为 `2` 时，点单流程为：小费页 → 支付方式选择页 → 所选支付流程。
7. 小费页确认后不会预设信用卡，也不会提前执行信用卡最低消费校验。
8. 在支付方式选择页选择信用卡或柜台支付，均保留此前选择的小费金额。
9. 支付方式页选择信用卡不会重复进入小费页；刷新支付方式页或丢失 location state 后，订单级完成标志仍能防重。
10. 从支付方式页返回后，小费页准确恢复比例、自定义金额或 No Tip；修改后再次确认覆盖旧值。
11. 从支付方式页返回小费页、再返回原点单入口时，最终金额、选择元数据和完成标志全部清除；修改购物车金额后再次结账必须重新选择并重新计算小费。
12. 单支付方式不展示支付方式选择页，继续直接进入小费页及唯一支付流程。
13. 小费页停留期间资格退化为单一且允许小费的方式时保留本次小费并走该方式；退化为不允许小费或未知目标时清零小费后安全继续。
14. 值 `0`、值 `1` 的既有流程不变，值 `2` 不会被 truthy 判断误当作值 `1`，信用卡完成后不会进入后付小费页。
15. 姓名、手机号、CRM、短信及其他既有支付入口对值 `2` 的行为一致。
16. Dual Price 关闭时值 `2` 正常保存；开启时授权成功可保存并重载，授权失败/取消不可保存；已授权值 `2` 不被启动修正为值 `1`。
17. 小费确认时仍执行售罄复检；进入支付方式页前不执行信用卡最低金额检查；随后选择信用卡时用含小费金额执行检查，选择柜台支付时不执行信用卡最低金额检查且保留小费。
18. 礼品卡入口不携带值 `2` 预选的小费金额，并保持既有礼品卡流程。
19. 资格运行时失效或配置保存失败时，不会进入无效的先小费流程。
20. 签名和其他支付后流程除必要顺序调整外保持不变。

## 验证策略

- 为流程资格、无效值回退和入口路由决策增加单元测试。
- 为小费页确认后的 `paymentType`/单卡/单柜台分流、订单级完成标志和 `tipSelection` 的写入、覆盖与清理增加行为测试。
- 覆盖双支付双小费、单支付、仅一项小费、配置加载中及运行时资格失效。
- 覆盖支付方式页返回小费页后的比例、自定义金额、No Tip 恢复和再次覆盖。
- 覆盖 paymentType → tippingPanel → 原点单入口 → 修改购物车 → 再次结账，确认旧金额、元数据和完成标志均不复用。
- 覆盖路由上下文丢失、刷新恢复、重复确认、未知值按 `0`、礼品卡清零及新订单/重下单清理标志。
- 覆盖 Dual Price 开关、授权成功/失败/取消、保存后重载及所有已知 `id: 24` 消费方的严格枚举行为。
- 分别验证等待小费期间售罄、信用卡最低金额包含小费、柜台支付不触发信用卡最低金额但保留小费。
- 运行 KioskLite 全量测试和生产构建。
- 发布并校验 `dist/kpos/kiosklite` 嵌入包。
- 浏览器验证值 `0`、`1`、`2` 以及支付方式/小费选项取消后的联动。

## 非目标

- 不增加新的支付方式或礼品卡小费支持。
- 不改变小费金额、比例、No Tip 或签名配置本身。
- 不新增后端接口或配置 ID。
