# 菜单与注册中心本地操作记录实施计划

**Goal:** 两个模块独立记录入口，共用本地记录采集、筛选列表及前后差异详情。
**Architecture:** 独立版本化日志存储，操作边界统一收集快照；业务与日志成功分开处理，日志失败保留会话记录并提示。
**Spec:** [已确认规格](../specs/2026-11-16-menu-registry-operation-logs-design.md)
**Tech Stack:** TypeScript、原生 DOM、现有 Tailwind、公用导航滑层。

- [x] operation-log.ts：差异、脱敏、版本校验、持久化与会话失败记录，测试损坏及 quota。
- [x] operation-log-ui.ts：固定模块范围、筛选、20 条分页、只读详情，关闭保留上下文。
- [x] 菜单 store 提交及结构操作采集；注册中心公共写入口采集；无变化不记编辑，取消不记失败。
- [x] menu-routing-navigation / m-platform-runtime：菜单配置下菜单管理和记录，注册中心下项目、页面和记录，旧路由默认兼容。
- [x] 核心校验：tsc、领域测试、真实浏览器操作与模块隔离、无日志空态、存储异常。生产账号权限、服务端发布及全部 UI 前置校验入口仍按交付记录列为验证缺口。

不改变业务发布权限；注册页面的“保存并发布”在日志中标为本地保存。执行边界：不提交、不合并、不推送。
