# Kiosk 支付方式 marginappconfig 持久化实施计划

## 目标

将 `KIOSKLITE.configList[id=70]` 设为全局支付方式权威数据，设置页保存、重新进入和 Kiosk 运行时使用同一解析结果，同时保留 POS `KIOSK_PAYMENT_TYPE` 兼容同步。

## 实施任务

1. 新增共享支付方式配置解析器，覆盖缺失、非法、空值和合法值，并提供 `id=70` upsert。
2. 在默认 KIOSKLITE 配置中增加 `id=70`；旧行加载时避免默认合并自动持久化，显式保存时才迁移。
3. 设置页优先使用 `id=70` 初始化支付复选框；缺失时回退 POS。
4. 删除双价格自动补齐支付方式逻辑；服务设置保存不再修改逐设备 `id=34`。
5. 调整保存顺序：先提交 marginappconfig，再从已提交的 `id=70` 兼容同步 POS。
6. Kiosk 支付路由、小费门禁使用共享解析器，并修复缺少设备信息时的能力回退。
7. 完成 RED/GREEN、全量测试、嵌入包构建和完整浏览器持久化自测。

## POS 兼容同步认证修复

1. 提取严格的管理员 `userId` 校验：只接受有限正整数 number 或十进制正整数字符串。
2. 提取 POS 配置差异分类，区分支付方式兼容镜像与订单类型、短信两个 POS-only 字段。
3. 在任何写入前执行保存门禁：无有效 `userId` 且存在 POS-only 修改时阻止整次保存；只有支付方式变化时允许保存 margin 并跳过 POS 请求。
4. 有有效 `userId` 且支付方式变化时，将现有确认框前移到 margin/POS 写入之前；取消后两个接口均不调用。
5. 将确认框文案从“设备设置”调整为“POS 兼容配置”。
6. RED 覆盖空 `userId` 产生 SOAP 反序列化错误、认证门禁缺失和混合修改风险；GREEN 覆盖无认证支付方式单改、有认证同步、混合修改阻止及确认取消原子性。
7. 运行专项测试与 KioskLite 全量测试；按仓库规则重新构建嵌入包，并在 64907 实测保存无错误、回读保持。

## 回滚

移除 `id=70` 的读取与 upsert，恢复 POS 作为全局支付方式来源；数据库中遗留字段不会影响旧代码。
