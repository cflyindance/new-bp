# 数量与频次规则按门店独立配置实施计划

## 目标

把现有单一商品结构与数量矩阵升级为按门店隔离的配置，同时保留商品选择器、批量数量设置、后置发布门店页和历史规则兼容能力。

## 任务 1：建立失败验证

新增 `scripts/verify-order-limit-store-specific-config.mjs`，验证：

- 草稿存在 `participatingStoreIds`、`activeStoreId`、`storeConfigs`、`deployExcludedStoreIds`。
- 门店配置包含独立 `structureByLine`、`productLines`、`targetIds`、`limits`。
- 商品配置渲染参与门店表格、地址、状态和门店 Tab。
- 数量配置渲染门店 Tab，数量读写使用当前门店配置。
- 后置门店页区分已添加/未添加并禁用未添加门店。
- 全局场景变化清空全部门店 limits。
- 历史配置迁移和正式发布裁剪逻辑存在。

先运行并记录失败，再开始功能代码。

## 任务 2：门店模型与迁移

修改 `dist/Configuration center/assets/order-limit-flow.js`：

1. 为静态门店补充 `address`。
2. 增加空门店配置、深复制、当前门店配置、状态判断、已添加门店列表等纯函数。
3. 默认草稿增加门店字段。
4. 统一归一化旧草稿：
   - 有 `storeConfigs` 时逐店归一化。
   - 有历史 `deployStoreIds` 时深复制顶层旧配置到每个门店。
   - 无历史门店时保存兼容回退，不自动参与。
5. 读取草稿后立即持久化迁移结果。

## 任务 3：改造商品与数量辅助函数

1. `structureItems`、`selectedTargets`、`targetsForLine`、`syncDraftTargetsFromStructure` 改为接收门店配置。
2. `eachLimitCell` 遍历每一家已添加门店。
3. 单元格、完成度、批量设置全部读写当前门店 `limits`。
4. 人数、轮次、统计周期变化调用统一函数清空所有门店数量。

## 任务 4：商品配置页面

1. 在选择商品标题下渲染参与门店表格。
2. 复选框维护 `participatingStoreIds`；新门店创建空配置并设为当前门店。
3. 已配置门店取消时使用现有确认弹窗，确认后删除该门店数据。
4. 渲染已选门店 Tab、当前门店摘要和现有菜单选择器。
5. 选择器事件只写入当前门店；首次添加商品时默认加入 `deployStoreIds`。
6. 增加表格、状态、门店 Tab 和空状态样式。

## 任务 5：数量配置与确认页

1. 数量步骤在产线配置前增加已添加门店 Tab。
2. 门店 Tab 展示完成度并清理批量临时状态。
3. 第七步摘要展示门店数量、目标数量和总矩阵完成度。
4. 步骤校验覆盖全部已添加门店。

## 任务 6：后置门店与发布

1. 后置门店页改为参与门店表格，展示门店名、MID、地址和商品状态。
2. 已添加门店默认选择，用户取消写入 `deployExcludedStoreIds`；未添加门店禁用。
3. 发布确认重新校验最终门店范围及每家门店完整性。
4. 构建正式规则时裁剪未发布门店，并同步裁剪 `editorDraft`。
5. 兼容顶层字段按最终发布门店、首个已添加门店、历史回退顺序生成。

## 任务 7：回归与交付

运行：

- 新增门店配置验证。
- 不限制移除、批量目标选择、规则列表滚动和标题焦点回归脚本。
- JavaScript 语法检查。
- TypeScript `--noEmit`。
- `git diff --check`。

浏览器验证：多门店独立选品、不同上限、切换保持、取消确认、后置状态/默认选择/禁用、直达发布防绕过、分类和菜品两种规则。

验证通过后提交功能分支，使用 `--autostash` 合并到 `main`，再次运行回归并保留本地预览。
