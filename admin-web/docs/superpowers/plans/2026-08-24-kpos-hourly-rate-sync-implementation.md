# KPOS 按时计费同源实施计划

> 日期：2026-08-24（2026-08-25 按实机 HourlyRate 模型更新）  
> 对应权威设计：`docs/superpowers/specs/ktv-duration-billing/README.md`

## 目标

删除按时计价规则对浏览器 localStorage 的运行时依赖，以 KPOS `HourlyRate` SOAP 数据作为商家后台和 eMenu 的唯一事实来源，并实现“每个区间独立选择固定收费或单位收费、各区间逐段累计”的实机模型。

## Task 1：KPOS HourlyRate 客户端

- 在现有 KPOS 客户端中实现 `ListHourlyRatesBySaleItemType`、`SaveHourlyRateType`、`DeleteHourlyRateType`。
- 解析 `saleItems[].hourlyRates[]`，按 `from` 升序规范化并保留 KPOS 真实区间 ID；快照 hash、差异比较和回读验收使用同一顺序。
- 保存前 fresh read 并按拓扑规划：拓扑和行收费方式不变时，`price`、`fixPrice`、`step` 变化按原 ID 更新；拓扑或任一行收费方式变化时倒序删除旧组、正序重建目标组。整组替换前持久化恢复意图；任一步失败停止并强制回读，进入专用替换恢复态。

## Task 2：规则领域映射

- 每个 `saleItemId` 映射为一组规则，商品名称作为只读标题。
- 每一行映射为 `fixed(fixPrice)` 或 `unit(price + step)`，同行严格二选一，同一商品允许混合行。
- UI 与 KPOS 均使用从 0 开始的半开区间 `[from,to)`；首档 `from=0`，后续起点自动衔接，最后一档可有限或无上限。
- 解析时逐商品隔离非法数据：同行混合字段、断档、重叠、同起点重复、多个无上限档等只让该商品进入只读错误态，不阻断其他商品。
- XML 空串/缺字段归一为缺省；数值 0 作为非法价格/步长；单位收费固定向上取整。
- 实现累计求价函数：固定区间进入即收一次；单位区间按该区间交集分钟数 `ceil(duration/step) * price`；总价为所有已进入区间之和。
- 增加 parse→serialize→parse 等价测试，并固定边界 oracle：`0→0、1→100、199→100、200→100、201→105、250→110、300→120、301→130`。

## Task 3：商家后台异步 CRUD

- 列表打开时从 KPOS 查询，不再从 localStorage 初始化。
- 编辑器改为区间行级收费方式选择：每行切换固定收费/单位收费时清空另一方式字段；同一规则内允许混合。
- 首行起点固定为 0，后续起点由上一行终点自动生成；最后一行提供有限结束/无上限选择，至少保留一行。
- 编辑保存按拓扑规划：价格或步长变化按 ID 原位更新；档位合并、拆分、边界移动或行收费方式切换时，按起点倒序删除旧组，再按起点正序重建目标组。
- 实现替换恢复态：保存原始/目标快照、阶段和逐步结果；中断后不进入普通编辑器，用户明确继续时 fresh read、清理当前残留并从目标首档重建，成功回读后清除恢复意图。
- 删除规则等价于删除该商品全部区间，并要求二次确认。
- 删除前后各查询一次 FloorPlan；仍有桌台 `defaultSaleItemId` 绑定该商品时阻止或报告并发冲突。只有二次检查无绑定且回读无剩余区间才成功。
- 移除自定义规则名称、启用状态和备注。

## Task 4：桌台关联改造

- KTV 桌台以 KPOS `defaultSaleItemId` 作为唯一计时关联键。
- 移除新流程对 `durationBillingRuleId` 的读取和写入。
- 切换桌台类型或商品时保持现有活动计时保护。

## Task 5：eMenu KPOS 同源读取

- eMenu 在 KPOS 同源页面以 `credentials: include` 直连 `/kpos/ws/kposService`；桌台加载/切桌时查询，开单前强制 fresh 查询。
- 展示缓存最多 30 秒，按 origin + PC License/instanceName 隔离；主机、License 或身份变化立即失效。
- KPOS 请求失败时不回退本地旧规则，不展示开单计时并提供可诊断错误。
- 开始计时冻结 KPOS 返回的费率快照；计时中 KPOS 规则变化只影响新会话。
- eMenu 预估与结束计时统一调用累计求价逻辑；订单商品开始价保持 ¥0，结束后只更新同一商品行为最终累计费用。

## Task 6：迁移与清理

- 保留旧 localStorage 数据的显式一次性迁移能力，不自动覆盖 KPOS 已有商品规则。
- KPOS 已有规则默认保留且禁止自动合并；只有迁移预览中逐商品明确确认后，才允许把本地规则作为目标快照写入 KPOS。
- 迁移 hash 只标识迁移意图；每次执行或重试 fresh read KPOS 并重算剩余差异，回读等于目标才跳过。记录逐商品状态、hash 和最后回读快照摘要。
- 迁移完成后 localStorage 不参与列表、桌台匹配或 eMenu 计费。

## Task 7：验证与发布

- 单元测试覆盖 SOAP XML、响应解析、双向区间映射和差异同步。
- 集成测试覆盖查询、创建、编辑、删除以及保存后回读。
- 故障测试覆盖第 N 个 SOAP 操作失败、部分成功展示、回读收敛和基于新 diff 的安全重试。
- 真实 SOAP 集成覆盖档位合并、拆分、公共边界移动、单行 `fixed ↔ unit`、单位 `step` 单独变化和混合行，并逐次回读验证最终规范化快照。
- 并发测试覆盖删除前检查通过、删除期间另一终端新增桌台绑定，二次 FloorPlan 检查必须报告冲突。
- 故障恢复测试分别覆盖倒序删除与正序重建中断、页面重开识别恢复意图、继续恢复后无重复操作地收敛。
- 非法响应覆盖同行混合字段、0/空字段、非法 step、首档非 0、乱序、同起点、断档、重叠和多个末档，并验证逐商品错误隔离。
- 覆盖 eMenu 断网/Fault/空响应不回退 localStorage、数字/字符串商品 ID 精确匹配及多主机缓存隔离。
- 浏览器走查商家后台与 KPOS Admin 两端数据一致。
- 走查 KTV 桌台 → eMenu 开单 → 计时 → 结束计价，核对混合累计规则的实时预估和最终商品价。
- 修改 eMenu 源码后执行 `npm run build:emenu-new-embed -- --skip-install` 并核对 `dist/emenu-new`。

## Task 8：eMenu 已下单计时商品信息层级

- KTV 计时商品复用普通菜单商品的「标题 + Option + 价格」结构，不新增独立卡片或额外价格区域。
- 活动计时商品的 Option 位置显示并每秒刷新 `用时 HH:mm:ss`；不再把用时与费用拼接为一行。
- 活动计时商品的价格位置以 `预估费用 ¥X.XX` 替换开单占位价 `$0.00`；异常计价显示 `预估费用 --`。
- 保持 `orderItemId` 精确匹配和旧数据 `key` 回退边界，覆盖普通商品与套餐商品布局；结束计时成功后继续由服务端订单最终价恢复普通价格展示。
- 结束计时兼容旧会话的 `productSnapshot.id` 与规则绑定商品 ID；整单保存时补齐目标行 `totalAmount` 并使用 `PARTIALLY_SUBMITTED` 修改状态，空结果不得提前结束本地会话。
- 购物车结束计时成功后，以保存响应立即更新当前订单并再次 fetch KPOS 订单，确保计时商品展示服务端最终成交价而非 `$0.00`。
- 更新结构回归测试，重新执行计时会话与订单行解析回归，并按项目规则发布、校验 `dist/emenu-new`。
- 购物车计时价格使用独立“预估”翻译键，避免影响结束确认弹窗等仍需显示“预估费用”的位置。
- 首页 `TimingBar` 移除桌台/商品标题和预估费用，仅保留已用时长；有结束权限时同时保留结束按钮。

## 风险与回滚

- KPOS 没有规则名称、启用状态和备注，前端不得伪造跨设备元数据。
- 多区间保存不是原子事务；保存失败后必须重新查询并展示实际服务器状态。
- 回滚只恢复旧前端版本；不得自动把 KPOS 数据反向覆盖为 localStorage 快照。
