# 已选商品搜索与布局实施计划

## 目标

为“查看已选商品”弹窗增加仅匹配商品/分类名称的搜索，并将搜索、门店、产线放到标题下同一筛选区；将批量删除和全部删除移到底部左侧，移除“共 N 条”。

## 实施步骤

1. 扩展已选商品验证脚本：覆盖搜索状态、字段范围、组合筛选、IME 事件、分页/勾选复位、删除按钮位置和计数文案移除。
2. 运行验证，确认旧实现按预期失败。
3. 在弹窗临时状态中增加 `query` 与 `searchComposing`。
4. 扩展筛选函数：菜品规则匹配 `dishName`，分类规则匹配 `categoryName`，并与门店、产线条件组合。
5. 重构弹窗结构：标题下渲染“搜索、门店、产线”筛选行；顶部删除操作移除；底部左侧渲染两个删除按钮，右侧保留分页。
6. 增加搜索输入、`compositionstart` 和 `compositionend` 处理，非组合输入即时搜索；筛选变化统一回到第 1 页并清空勾选。
7. 调整桌面和移动端 CSS，使筛选同排、底部操作区响应式换行。
8. 运行 JavaScript 语法检查与全部订单限购验证脚本。
9. 使用本地浏览器检查布局、搜索/门店/产线组合、分页复位、删除按钮状态和控制台。
10. 检查差异，提交功能分支，合并到 `main` 后复测。

## 不在范围内

- 不搜索门店、产线、组名或完整分类路径。
- 不改变单条、批量和全部删除的确认与删除范围。
- 不把搜索状态写入规则草稿或发布快照。
