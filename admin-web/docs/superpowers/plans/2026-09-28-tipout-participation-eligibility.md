# 参与资格实施记录

用户已确认：三种员工分配方式均支持「仅打卡员工」（默认）与「不限打卡状态」。

## 数据与行为

- `clockin: clock` 保留默认资格；新增 `clockin: unrestricted`，与历史 `noclock` 全手动工时语义区分，历史快照不迁移。
- 平均分配默认仅打卡员工参与，未打卡员工需在明细中明确补录；休息员工默认比例为零。
- 工时分配自动取打卡工时，未打卡默认零，可手动补录；沿用已确认的手动工时优先于上限规则。
- 订单分配按员工有效订单笔数计算；不限打卡允许未打卡且有订单的员工参与；零订单不分配。
- 手动参与标记保存在 editorState，重新打开快照时回填；真实考勤标签保持不变。

## 实现位置

- 模板与 rule-editor：资格选项、动态说明、保存校验。
- tipAllocation：候选资格过滤及订单笔数权重分配。
- details / distribution：传递订单、考勤数据；取消演示用随机平均比例。
- tipout-detail-snapshot：保存与恢复手动参与标记。

## 验证

- `verify-tipout-participation.mjs`：仅打卡和不限打卡、零订单、手动工时、平均分配排除休息员工。
- 现有页面静态检查、考勤标签、发放契约与 TypeScript 检查。
- 浏览器回归：资格切换及提示、订单方式可选、快捷分配与快照、手动工时。
