# KTV 按时计价商品化下单实施计划

> 权威功能设计：[按时计价规则 README](../specs/ktv-duration-billing/README.md)
>
> 本文件只维护实施顺序与验证任务；业务口径以权威设计文档为准。

## 目标

将现有 eMenu 独立计时 surcharge 原型替换为正式商品化链路：规则绑定主机 POS 返回的一个 KTV 商品，KTV 桌台绑定规则，开始计时立即生成 ¥0 普通已下单商品，结束计时经授权后更新同一商品行的最终价格。

## 当前实施状态（2026-08-24）

- 已完成：POS 商品标签/可售状态透传、KTV 商品筛选、规则商品绑定、KTV 桌台类型和绑定约束。
- 已完成：eMenu 开始/结束事务、前端幂等锁、商品行关联字段、移除新订单 surcharge 汇总、活动计时阻止呼叫结账。
- 已完成：主应用 TypeScript 检查、7 组专项测试和 eMenu 生产构建。
- 已完成（待真实 KPOS 联调）：复用现有 `/order/fetch`、正常订单生成逻辑与 `/order/save`，不再等待 POS 增加计时专用接口。

### 普通订单接口复用契约

1. 开始：从当前 eMenu 菜单取得绑定商品完整结构，预生成 `sessionId`，按正常商品结构生成数量 1、成交价 ¥0 的订单行并调用 `/order/save`。
2. 开始恢复：预生成 `sessionId` 写入订单级 `emenuKioskextendedInfo.durationBillingPending`；保存超时或响应丢失时调用 `/table/fetch?id=<tableId>` 取得当前订单，按该标识及商品 ID、数量和 ¥0 成交价唯一找回真实 `orderId` / `orderItemId`。无法确认时禁止自动重试并提示人工核对。
3. 结束：调用 `/order/fetch` 取得最新整单，按 `orderItemId + sessionId` 定位商品，通过正常订单生成逻辑重算目标行、税费、折扣和总额，再调用 `/order/save`。
4. 并发：每次改价前读取最新整单并只补丁目标行；eMenu 请求期间禁止自身重复提交。现有 KPOS 整单保存没有版本令牌，跨终端竞态属于 POS 联调风险，不由前端虚构乐观锁保证。

## 实施原则

- `productId` 是商品唯一身份，名称快照仅供展示和历史审计。
- 桌台只绑定规则，规则只绑定一个商品，不在桌台重复维护商品关系。
- 创建商品成功后才开始计时，改价成功后才结束计时。
- 开始、结束和重试均需幂等；任何路径不得重复创建计时商品或重复收费。
- 数量恒为 1，最终商品单价等于该次计时的最终总金额。
- 移除本流程对 `EMENU_DURATION_BILLING` 独立 surcharge 的写入和汇总，避免双重计费。

## Task 1：主机 POS KTV 商品同步与查询

- 复用桌台编辑器的 `loadKposKtvSaleItems()`，调用 `FindSaleItemsType` 并传入 `onlyKTVItem=true`。
- 规则编辑器和【KTV/卡拉OK】房间共享同一主机、License、SOAP 返回列表和连接级请求缓存。
- 主机未连接、请求失败或无 KTV 商品时禁止保存和启用规则。
- 验证多个 KTV 商品可选择，但一条规则只能选一个。

## Task 2：规则商品绑定模型与编辑器

- 为 `DurationBillingRule` 增加 `productBinding`，包含 `productId`、名称快照、固定标签与快照时间。
- 新建和编辑规则时提供单选商品选择器；保存、启用时执行 Store 层校验。
- 历史未绑定商品的规则保持可读，但标记为“绑定商品不可用”，不得用于新绑定或新计时。
- 增加规则列表的商品名称与失效状态展示。

## Task 3：餐位平面图 KTV 类型与绑定约束

- 为 `FloorPlanTableCategory` 增加 `ktv` 并在桌台编辑器提供“KTV”类型。
- 仅 KTV 桌台显示计价规则选择器，只列出启用且商品有效的规则。
- 从 KTV 切换为其他类型时先警告，再清空 `durationBillingRuleId`。
- 有活动计时会话时禁止切换桌台类型或更换规则。

## Task 4：eMenu 配置桥接与展示资格

- 将桌台类型、规则绑定、商品绑定和规则快照桥接到 eMenu。
- Landing 仅在服务员已登录、桌台类型为 KTV、规则启用且 `defaultSaleItemId === productBinding.productId` 时展示“开单计时”。
- “开单计时”保存成功后先将返回的完整订单和真实 `orderId` 设置为当前订单，定向刷新后直接跳转 `/order` 菜单页，不得再次选择订单号；保存或刷新失败时留在 Landing。
- 订单刷新写回本地桌台状态时，同一订单合并保留本地 `durationBilling`；服务端已有会话时以服务端为准，确保从菜单返回 Landing 后仍展示计时中状态。
- `tableId` 或 `orderId` 变化时重新读取当前上下文的计时会话；沿用现有切桌清理逻辑清空购物车、会员和临时点单数据，禁止继承上一桌状态。
- 清桌后 `currentOrder.id` 为空，或会话 `orderId` 与当前订单不一致时，将历史计时会话视为无效并恢复 `idle`；同页桌台存储写入主动通知计时 Hook，立即重新允许新桌开单计时。
- KTV 桌型兼容 `category: "ktv"`、`shape: "KTV"` 和 `kposShape: "KTV"` 三种来源。
- 开始事务再次执行商品 ID 一致性校验，下单商品只能使用该共同商品 ID。
- 不满足条件时提供明确不可用原因；普通桌台完全不展示入口。

## Task 5：开始计时的 ¥0 商品事务

- 扩展计时会话保存 `orderId`、`orderItemId`、`productSnapshot`、`ruleSnapshot` 和开始幂等键。
- 调用正常 POS 商品下单链路创建数量 1、成交价 ¥0 的已下单商品；商品必须存在于当前 eMenu 菜单，否则阻止开始并提示刷新商品数据。
- 在商品扩展信息中写入计时会话 ID、规则 ID 和计价摘要。
- 仅收到成功的订单及商品行 ID 后启动计时；失败时保持空闲状态。
- 禁用重复点击并验证刷新、超时重试不会创建第二条商品。

## Task 6：购物车普通商品展示

- 复用已下单普通商品结构展示名称、数量和价格，不创建计时专属伪商品类型。
- ¥0 阶段显示规则摘要、已用时长和当前预估金额。
- 计时结束后保留规则摘要、实际时长、起止时间和最终金额用于审计。

## Task 7：结束授权与原商品行改价

- 确认结束时固定 `endedAt`，按规则快照计算最终总价。
- 复用管理员授权流程；授权失败继续计时。
- 基于 `/order/fetch` 最新整单，通过正常订单生成逻辑更新已保存的 `orderItemId`，数量保持 1，成交价为最终总额，并重算税费、折扣和总额后 `/order/save`。
- 改价成功后才将会话标记为 ended；失败时进入可重试状态。
- 重试前查询商品行当前状态；已完成相同改价时直接收敛为 ended。

## Task 8：异常保护与结账约束

- 原商品行被删除或作废时阻止结束，并提示恢复原商品行，不自动补建商品。
- 活动计时会话阻止订单结账，并展示对应桌台。
- 活动会话阻止修改桌台类型、规则和商品绑定。
- 商品或规则在计时期间变化时，当前会话继续使用开单快照；只影响新会话。

## Task 9：移除独立 surcharge 路径

- 删除或停用当前流程写入 `EMENU_DURATION_BILLING` surcharge 的逻辑。
- 调整待下单、已下单和总计汇总，确保最终费用只来自普通商品行。
- 保留历史订单 surcharge 的只读展示兼容，不迁移或重复转换历史订单。

## Task 10：自动化验证与浏览器走查

- Store：商品标签、可售状态、单规则单商品、历史规则兼容。
- 平面图：KTV 类型、规则过滤、切换清绑定、活动会话保护。
- 开始事务：成功、失败、双击、超时重试、刷新恢复。
- 计价边界：单价模式及区间模式的 30、31、60、61 分钟。
- 结束事务：授权失败、改价失败、响应丢失、商品作废、幂等重试。
- 订单：只存在一条计时商品、数量为 1、无新增 surcharge、活动会话阻止结账。
- 使用浏览器完整走查“配置商品 → 创建并启用规则 → KTV 桌台绑定 → eMenu 开始 → 已下单 ¥0 商品 → 结束授权 → 同商品最终价”。
