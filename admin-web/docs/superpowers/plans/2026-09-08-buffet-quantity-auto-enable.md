# 自助餐限购数量值驱动实施计划

**目标：** 移除独立“限购内容”选择，将限制是否启用统一改为由数量值自动推导，并保持历史草稿与运行时字段兼容。

## 任务 1：建立失败测试

- 调整限购数量步骤结构测试，要求不再渲染 `renderBuffetLimitContent` 和 `data-period-block`。
- 新增数量推导测试，覆盖空值、0、正整数、清空值、跨门店汇总和商品范围保留。
- 先运行测试并确认失败。

## 任务 2：实现数量值驱动

- 在 `dist/Configuration center/assets/order-limit-flow.js` 增加按周期扫描数量值并同步 `totalEnabled`、`targetEnabled`、`sameDishEnabled` 的兼容层。
- 数量工作台按规则能力直接展示可配置项，不再依赖手工开关。
- 所有数量输入、例外数量、批量应用和门店复制后同步派生状态。
- 删除限购内容区块入口及其交互处理。

## 任务 3：调整校验与完成度

- 发布校验前先根据数量值同步兼容字段。
- 每个启用周期必须至少存在一个实际数量配置；0 视为有效配置。
- 清空数量只关闭对应限制，不删除已选商品。
- 历史草稿继续读取原数据结构，但保存时写回派生后的兼容字段。

## 任务 4：回归与浏览器验收

- 运行新增测试及全部相关自助餐规则校验。
- 浏览器验证无“限购内容/指定对象额度”开关，数量项直接展示。
- 验证填写、清空、0 值、模板切换及下一步拦截。

## 任务 5：提交并合入 main

- 提交功能分支代码与文档。
- 将功能分支合并到本地 `main` 工作区。
- 在 `main` 上复跑关键测试并报告结果；未收到明确要求前不推送远端。
