# eMenu 调味单商品编辑与拖动排序实施计划

## 目标

把商品行“编辑”改为复用批量关联配置布局的两步向导，并让批量新增和单商品编辑都支持动作及动作内 Option 的持久化拖动排序。

## 实施顺序

1. 新增关系配置草稿模块：有序动作、Option 定价/状态、重排、历史关系初始化和有序保存载荷。
2. 新增排序合同模块：带数字标记的 `sortOrder` 编码、完整格式识别、历史回退、容量与唯一性验证；服务端同步实现。
3. 抽取共享配置工作区渲染：动作列表、Option 表格、选择弹层、价格批量填充、状态模式和拖动手柄。
4. 接入统一 Pointer Events 与键盘重排；搜索时禁用 Option 排序。
5. 重写单商品编辑为两步居中向导：加载历史关系、完整本地预览、完整 PUT、冲突恢复和脏状态保护。
6. 批量向导迁移到共享草稿/工作区，保持商品选择和服务端预览流程不变。
7. 扩展批量预览与提交：构建 configured/preserved 最终关系集、excludedCandidates、完整排序及原子写回。
8. 商品聚合接口改为新格式排序，历史关系使用固定动作顺序回退。
9. 补充中英文文案、类型、结构测试、领域测试和 API 测试。
10. 运行 TypeScript、调味设置专项校验和本地浏览器验收；仅提交本次相关文件。

## 关键验证

- 新增和编辑均能拖动动作与 Option，保存重载后顺序不变。
- Option 不可跨动作拖动，搜索时排序禁用，键盘重排可用。
- 单商品删除、状态、价格、预览和版本冲突均不回归。
- 批量保留未选历史关系，configured/preserved/unavailable 分支符合规格。
- 历史 `sortOrder` 不会被误判为新格式。
