## 交付缺口与边界

1. 当前使用分析仍采用独立内存Demo。管理品牌/门店与分析数据默认主键尚未共源，多数管理详情显示“暂无使用数据”；未按名称/排序乱配统计。接真实数据或统一演示资料仍为独立后续工作，不宣称本轮已完成。
2. 已匹配数据使用原门店/产线/设备统计函数，未改订单口径、7/14/30阈值、License绑定或M/B菜单授权。设备跨历史归属仍由原独立设备视角负责。
3. 旧角色缺catalogVersion时readMState返回兼容副本，不因浏览写存储或日志；授权保存写标记2，防止后续重复导入旧模块门槛。原始旧记录可从保存前localStorage恢复，不做删除。
4. 仅前端原型权限，不代表生产服务端鉴权或按租户/行级的数据访问控制。生产接口接入、CI、构建部署未验证；未修改eMenu源码，未重建嵌入包。
5. 历史操作截图保留原业务参考；涉及旧权限父资源、导航归属或五/三页签的旧截图不作为当前入口依据，当前入口采用本轮实采。其他既有交付缺口不因此关闭。
6. 设计评审按brainstorming技能执行；只读评审通过，增加了跨角色、显式隐藏、越界上下文及实时撤权的验收算例。用户已批准方案，未据技能自动提交设计稿。
