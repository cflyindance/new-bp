# 品类菜单 · 菜单组合配置复制设计方案

> **模块**：前厅管理中心 → 品类管理 → 品类菜单  
> **版本**：v1.1  
> **日期**：2026-07-24  
> **状态**：已确认  
> **参考**：`限购数量-场景条交互设计方案.md` §7「复制到其他场景」  
> **主要落点**：`src/config/foh-category-settings-ui.ts`（可选：`brand-menu-structure-picker-ui.ts`）

---

## 一、背景与目标

### 1.1 现状

品类菜单按「年龄 × 类别」自动生成多行**菜单组合**。每行分别配置：

- **可下单**：按产线勾选组/类/菜（`orderableStructureByLine`）
- **不可下单**：按菜或按类别（`viewOnlyMode` + `viewOnlyStructureByLine` / `viewOnlyCategoryKeys`）

不同菜单组合经常大量共用同一批菜，仅少数增删。当前只能逐行打开弹窗重复勾选，效率低。

### 1.2 目标

1. 从某一菜单组合**一次性**把「可下单 + 不可下单」复制到其他组合  
2. 支持**多目标**勾选  
3. 写入语义固定为**覆盖**（与限购「复制并覆盖」一致）  
4. 交互对齐限购数量「复制到其他场景」，降低学习成本  

### 1.3 非目标

- 不改 `MenuComboConfig` 数据模型语义与字段  
- 不复制 `displayName`、营业时间（属组合身份 / 类别属性）  
- 不做菜品级 diff 预览  
- 不做「仅复制某一产线」  
- 不做合并写入 / 写入方式二选一  
- 不做独立撤销栈（依赖页面未保存/保存流程）  
- 不改后端 API / 下发协议

## 二、方案定稿

**方案 1 · 行操作 + 复制弹窗**

| 对比项 | 方案 1（定稿） | 方案 2 表格多选批量 | 方案 3 编辑弹窗内复制 |
|--------|----------------|---------------------|----------------------|
| 入口 | 行「操作 → 复制」 | 顶栏批量 | 可下单/不可下单弹窗内 |
| 范围 | 整行两套配置 | 同上 | 单侧配置 |
| 心智 | 从源出发，对齐限购 | 步骤更多 | 无法一次带走整行 |
| 结论 | **采用** | 首版不做 | 已排除 |

## 三、交互设计

### 3.1 表格

在现有列（菜单组合 / 营业时间 / 可下单 / 不可下单）后新增 **操作** 列：

- 每行：**复制**（链接按钮样式，与现有「N 道菜」一致）
- 仅存在 1 个菜单组合时：仍展示「复制」；点击后弹窗空态或 toast：「没有可复制的目标」

### 3.2 复制弹窗

点击「复制」打开弹窗：

| 区域 | 说明 |
|------|------|
| 标题 | `复制菜单配置 · 源：{组合标题}` |
| 说明 | 将「可下单 + 不可下单」**复制并覆盖**到所选菜单组合 |
| 目标列表 | 其他菜单组合多选；可附摘要（如「未配置」「可下单 10」） |
| 页脚 | 取消；**复制并覆盖**（未勾选目标时禁用） |

- **无「写入方式」选项**：固定覆盖，目标已有配置直接被源替换  
- 关闭方式：取消、遮罩、Esc（与现有菜单编辑弹窗一致）

### 3.3 流程

```
点行「复制」
  → 打开弹窗（源 = 该行 comboKey）
  → 勾选目标
  → 复制并覆盖
  → 对每个目标应用覆盖规则，写回 menuByCombo
  → 关闭弹窗并刷新表格计数
  → 用户仍需按页面原流程「保存」（及下发，若适用）
```

## 四、数据与写入规则

### 4.1 复制字段

对每个目标 `MenuComboConfig` 写入：

| 字段 | 说明 |
|------|------|
| `orderableStructureByLine` | 可下单 · 按产线 keys |
| `viewOnlyMode` | `dish` \| `category` |
| `viewOnlyStructureByLine` | 不可下单 · 按菜 |
| `viewOnlyCategoryKeys` | 不可下单 · 按类别（其他组合 key） |

**不写入**：`displayName`。

类型约定：`BrandMenuStructureByLine = Record<BrandMenuLineId, string[]>`（kiosk / emenu / sdi）。

### 4.2 覆盖（唯一写入方式）

目标上述字段整块替换为源的**深拷贝**。

- `viewOnlyCategoryKeys`：过滤掉目标自身 `comboKey`，并仅保留仍存在的组合 key  
- 结果：目标与源的可下单 / 不可下单配置一致（含模式）

### 4.3 多目标

对勾选的每个目标**独立**应用覆盖；互不影响。

### 4.4 空源

源可下单与不可下单皆空时仍允许确认：覆盖后目标对应字段被清空。

## 五、实现约束

1. **保持**现有 `menuByCombo` / `MenuComboConfig` 结构与 normalize 逻辑  
2. 建议抽出纯函数，例如：  
   - `cloneBrandMenuStructureByLine`（可放 `brand-menu-structure-picker-ui.ts`）  
   - `applyMenuComboCopyOverwrite(source, target, targetKey, validKeys): MenuComboConfig`  
3. UI 与事件：`renderMenuPanel` / `renderMenuComboRow`、复制弹窗壳、`bindFohCategorySettingsUi` 内绑定  
4. 确认后：`writeFohCategorySettingsState` → remount；不单独触发下发  

---

## 六、验收要点

1. 行上「复制」可打开弹窗；标题含正确源名称；列表不含自身  
2. 可多选目标；弹窗**无**合并/覆盖切换；未选目标时「复制并覆盖」禁用  
3. 确认后：目标与源的可下单、不可下单配置一致（含模式）；表格计数刷新  
4. 不可下单「按类别」：keys 正确复制且不含目标自身  
5. 仅 1 个菜单组合时有合理空态提示  
6. 页面保存后再次进入，复制结果仍在
