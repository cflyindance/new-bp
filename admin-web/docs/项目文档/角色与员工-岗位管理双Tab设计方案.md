# 角色与员工 · 岗位管理双 Tab 设计方案

> **模块**：团队管理 → 角色与员工  
> **版本**：v1.1  
> **日期**：2026-07-24  
> **状态**：已确认  
> **主要落点**：`dist/TipOut/employees.html` / `employees.js` / `employees.css`  
> **路径**：`/team/roles-employees`（嵌入 TipOut 员工页）

---

## 一、背景与目标

### 1.1 现状

- 「角色与员工」嵌入 TipOut `employees.html`，仅有**员工列表**。
- 岗位选项来自：
  - **系统预设**：`DEFAULT_ROLE_OPTIONS`（Server、Bartender、Kitchen、Busser、Cashier、Runner、Host、Floor、Manager、Online）
  - **自定义**：`localStorage` 键 `tipout-employee-role-options-v1`（字符串数组）
- 员工表单内已有「新增岗位」快捷入口；**无**独立岗位列表，也**不能**删除自定义岗位。

### 1.2 目标

1. 在角色与员工页增加**岗位**维护能力（与员工同页双 Tab）
2. 默认展示系统预设岗位，并支持新增自定义岗位
3. 支持删除**非系统预设**岗位；删除前校验：当前筛选门店下若仍有员工使用该岗位，则不可删
4. 文案统一为「岗位」（按钮 / Tab / 列表 / 表单字段）

### 1.3 非目标

- 不做岗位重命名 / 编辑
- 不做列表「占用人数」及点进员工
- 不做按门店隔离的岗位目录（目录仍跨店共用）
- 不做 TipOut 规则引用校验（仅员工占用）
- 不与权限管理中心 RBAC「角色」打通
- 不改员工档案字段语义与小费 / 排班对 `role` 的既有用法

## 三、交互设计

### 3.1 页面结构

```
角色与员工
├── Tab：员工（默认）—— 现有员工列表 +「新增员工」
└── Tab：岗位 —— 岗位列表 +「新增岗位」
```

- 门店筛选与员工 Tab **共用**同一筛选控件（位于内容区上方或与现网一致的位置）。
- 员工表单内「新增岗位」快捷入口 **保留**（与岗位 Tab「新增岗位」写入同一自定义集合）。

### 3.2 岗位 Tab · 列表

| 列 | 说明 |
|----|------|
| 岗位名称 | 显示名 |
| 类型 | `系统预设` / `自定义` |
| 操作 | 系统预设：无删除（展示「—」）；自定义：「删除」 |

- 默认展示：**全部系统预设 + 全部自定义**（按名称排序，与现有选项合并逻辑一致）。
- 空自定义时仍展示系统预设行。

### 3.3 新增岗位

1. 点「新增岗位」（岗位 Tab 或员工表单快捷入口）
2. 打开小弹窗：岗位名称（必填）
3. 规则：
   - 去首尾空格；最长 40
   - 与系统预设或已有自定义 **忽略大小写** 重名 → 拦截并提示
4. 确认后写入自定义集合，刷新岗位列表；若从员工表单打开，则同时把新岗位勾选进当前多选

### 3.4 删除岗位

```
点自定义行「删除」（未选门店时按钮禁用，不可点）
  → 当前门店是否有员工占用该岗位？（token 精确匹配，忽略大小写）
       是 → 提示「当前门店仍有员工使用岗位「{名}」，请先调整员工岗位后再删」，中止
       否 → 二次确认「确认删除？」
            → 确认后从自定义集合移除 → 刷新列表与员工表单岗位选项
```

- **系统预设**：不提供删除入口。
- **占用判定**：当前筛选门店下，对员工 `role` 做 `parseRoleValues` 后，任一 **token 与岗位名忽略大小写精确相等** 即算占用（禁止子串匹配）。
- **不校验**其他门店员工；不校验 TipOut 规则是否引用该岗位名。

### 3.5 文案

统一使用「岗位」：

| 位置 | 文案 |
|------|------|
| Tab | 员工 / 岗位 |
| 岗位 Tab 标题 | 岗位列表 |
| 工具栏按钮 | 新增岗位 |
| 员工表单字段 | 岗位（保持） |
| 员工表格列 | 岗位（保持） |

## 四、数据与规则

### 4.1 存储（沿用）

| 数据 | 来源 |
|------|------|
| 系统预设 | `DEFAULT_ROLE_OPTIONS`（代码常量，不可删） |
| 自定义岗位 | `localStorage["tipout-employee-role-options-v1"]`：`string[]` |
| 员工岗位 | 员工档案 `role`（字符串，可用 `,` / `，` / `、` 分隔多岗位，或数组） |

岗位**目录跨门店共用**；删除占用校验绑定**当前筛选门店**。

### 4.2 合并与相等

- 选项集合 = 系统预设 ∪ 自定义 ∪（员工已引用但未在目录中的历史名，仅用于表单回显，与现网一致）
- 名称相等：`trim` 后忽略大小写比较

### 4.3 与下发 / 变更预览（可选衔接）

若后续接入「复杂功能 CRUD · 集合变更下发」：岗位自定义变更可作为集合 `team.roles`（或等价）单独记一条；首版原型可先只做本地持久化，与员工列表保存流程对齐即可。

## 五、实现约束

1. **落点**：`dist/TipOut/employees.html` / `employees.js` / `employees.css`
2. **复用**：`loadCustomRoles` / `saveCustomRoles` / `getRoleOptions` / `parseRoleValues` / `roleValuesEqual`；岗位 Tab 与表单快捷新增共用读写
3. **新增函数建议**（纯逻辑优先）：
   - `isSystemRole(name): boolean`
   - `isRoleUsedByStoreEmployees(roleName, storeId, employees): boolean`
   - `deleteCustomRole(name): { ok: true } | { ok: false; reason: "system" | "no-store" | "in-use" }`
4. **Tab 状态**：可用内存变量或 `sessionStorage` 记住当前 Tab；默认进入仍为**员工**
5. **边界**：
   - 未选门店：岗位可浏览、可新增；自定义行「删除」**禁用**（tooltip / 旁注：「请先选择门店」），不弹确认框
   - 删除成功后，打开中的员工表单若已勾选该岗位，应从选中项中移除（若表单未打开可忽略）

## 六、验收要点

1. 默认进入员工 Tab；可切换到岗位 Tab，列表含全部系统预设  
2. 可新增自定义岗位；重名（忽略大小写）拦截  
3. 系统预设行无删除；自定义行有删除  
4. 未选门店时自定义行「删除」禁用  
5. 当前店有员工占用 → 无法删除并提示原因；调整岗位或换店无占用后可删  
6. 删除后岗位列表与员工表单选项均不再出现该岗位  
7. 员工表单「新增岗位」仍可用，且与岗位 Tab 数据一致
