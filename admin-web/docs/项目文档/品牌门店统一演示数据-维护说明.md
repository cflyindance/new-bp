# 品牌门店统一演示数据维护说明

## 数据权威与入口

- 集团、品牌、区域、门店身份统一来自 `src/config/enterprise-merchant-store.ts`。
- 统一场景入口位于 `src/demo-scenario/demo-scenario-generator.ts`。
- 浏览器初始化位于 `src/demo-scenario/demo-scenario-browser.ts`。
- 页面或业务模块只能通过 `src/demo-scenario/adapters/` 下的适配器读取业务数据。

## 模板与覆盖

品牌模板定义商品、基础价格和品牌活动。门店只保存售价、库存、上下架等差异。新增门店时先在组织主数据中创建门店，再在 `demo-scenario-catalog.ts` 中配置必要画像；不得在业务页面新增门店数组。

## 日期与稳定性

场景覆盖包含当天在内的最近 30 个本地业务日。固定实体 ID 不随日期变化；订单等事件 ID 由门店、日期和稳定序号组成。所有随机数据必须使用 `demo-scenario-random.ts`，禁止直接使用 `Math.random()`。

## 版本与重置

结构或默认业务数据发生不兼容变化时，提升 `demo-scenario-browser.ts` 中的 `scenarioVersion`。版本变化会清理 `demo-scenario-storage.ts` 明确登记的业务键并重建；不得使用模糊前缀清理。登录、语言、主题、导航和视角偏好不属于业务重置范围。

## 校验

执行：

```bash
npm run verify:demo-scenario
npm run build
```

第一条命令覆盖稳定生成、继承、跨域引用、金额守恒、Scope 隔离、版本重置和全部领域适配器。新增领域或旧数据键时必须同时扩充对应验证脚本。
