### 研发数据与验收

MerchantChangeLogEntry新增可选menuChange：operationId/source/mode/beforeMode（字符串），storeName（可选），added/removed（菜单键数组），choices（菜单目录快照：key/title/parent/path/level/kind/isPage）。仅新菜单保存写入；旧数据不迁移。门店保存同一次请求共用operationId，各店增减保持独立；品牌菜单更新也保存增减与目录快照。保存仍在原版本校验之后与配置一起持久化，失败不新增日志，菜单权限无扩张。choices来自同一菜单路由公共投影，保存名称后改名不会覆盖旧快照。密码不进入新增结构。目录快照会增加本地演示存储量；生产持久化未接入。

算例：两店同次保存生成两条原始记录、一个列表批次；分别新增1个页面与0个页面，详情逐店核对，列表不显示“新增1个页面”冒充所有门店。旧记录含未知键obsolete:key时列表只显示历史菜单数量，详情显示未知名称及原键；没有前置模式则明确缺失。浏览器验证真实变更记录页、批次聚合、中文摘要、树、门店切换、历史缺失和只读行为；回归菜单保存与冲突，类型检查通过。

### 数据、计算与验收

| 对象／字段 | 研发定义 |
| --- | --- |
| StoreCapabilitySnapshot.menuMode | 可选枚举 inherit／independent。仅 inherit 启用动态继承；undefined 是历史独立语义，不能自动视为 inherit。 |
| inherit.enabledKeys 存储 | 保存空数组作为模式记录，不复制品牌菜单；getStoreCapability 返回投影后的有效 enabledKeys。读取不写 localStorage、不生成日志、不增加版本。 |
| independent.enabledKeys 存储 | 保留本店独立勾选键集合。旧有独立配置继续有效，品牌收回后按原规则裁剪。 |
| 继承有效集合 | 品牌各产线实际开通范围与门店视角交集，沿父子结构剔除专属视角及其后代。不扩展品牌未开通的新路由；发布、预设、订阅等运行时可见性门槛继续生效，继承不覆盖它们。 |
| 权限运行时 | 使用有效 getStoreCapability 解析，随后与品牌资源上限、账号角色、绑定门店共同取约束；Admin 品牌视角管理范围不等于全部门店自动越过本店配置。 |
| 保存与日志 | menuMode、独立键、更新时间、操作者在同一快照写入；日志区分继承、独立增量、独立替换，记录有效菜单增减。品牌变更日志说明继承自动同步，独立不自动新增。 |
| 旧配置编辑入口 | 原 saveStoreCapability 仍支持，手动保存视为独立配置，避免编辑后仍残留 inherit 导致勾选无效。 |

算例：品牌开通订单，A 店继承，B 店独立仅订单；品牌再开通报表，A 自动增加报表，B 不增加。品牌收回订单，A 立即不含订单，B 独立项被裁剪；再次开通订单，A 自动恢复，B 需手动开通。品牌管理及品牌／集团门店列表始终不进入继承集合。

## 1. 背景与定位

### 1.1 现状与本次问题

当前原型已具备 M 平台品牌列表、门店列表、组织主数据、品牌/门店能力配置及商家权限工作台。本次把分散入口整理为品牌创建、品牌菜单、品牌门店、品牌管理员开通的连续流程，明确菜单开通与人员授权的边界。

旧方案里“Merchant 内再建 Brand”的概念与当前入驻品牌页面不一致，本次以第 2 节已确认模型统一。旧生命周期、硬件、申请流程不因本次重设计自动重构。生产接口和凭据服务仍属于未接入能力。

### 1.2 企业视角的核心诉求

M 平台面向 **软件服务商 / 餐饮集团总部**，需要管理其名下的 **入驻商户（Tenant / Merchant）**：

| 场景 | 典型问题 |
|------|----------|
| **商户开通** | 新签约客户如何开户、选业态产线、分配初始管理员？ |
| **商户治理** | 哪些商户在营、暂停、已关闭？合同与 License 是否有效？ |
| **连锁扩张** | 某连锁品牌下如何批量开新店、挂区域、启用统一菜单/支付？ |
| **能力开通** | 该品牌能用 Kiosk / 会员 / 报表吗？开通了哪些增值服务？ |
| **合规与审计** | 谁开通/修改/关闭了哪家店？变更是否可追溯？ |

### 1.3 模块定位

沿用 M 平台现有 **「品牌管理中心」**，与现有模块关系：

```
M 平台
├── 菜单路由配置      → 定义「系统能有什么」
├── 平台预设          → 定义「默认开放什么」（业态×产线×四级树）
├── 商户管理中心      → 定义「谁可以用、开哪些店、启用什么」  ← 本方案
├── 权限管理中心      → 定义「企业运营人员谁能管什么」
└── 硬件资产中心      → 定义「设备资产跨商户怎么看」
```

**边界**：

- **M 平台**：商户主数据、生命周期、能力/服务开通、连锁组织树、代入驻与批量治理
- **商家后台**：单商户内日常经营配置（菜单、员工、单店参数）；继承 M 平台下发的范围，可局部覆盖预设可见性

## 2. 概念模型

### 2.1 本次有效组织模型

M 平台菜单路由定义平台已有的后台功能。集团包含品牌，品牌包含门店；品牌账号属于一个品牌，角色在该品牌内复用。现有代码中的 EnterpriseMerchant 对应本次页面上的入驻品牌；不是再新增一层同名 Brand 租户。原 MerchantOrgBrand/Region 保留兼容与区域组织信息，不在本流程重复要求运营选择第二个品牌。

| 关系 | 定义 |
| --- | --- |
| 品牌—门店 | 门店归属，与哪个账号能够管理门店分离；门店 MID 保持稳定 |
| 品牌—菜单 | 品牌获准使用的功能上限，从菜单路由中选择；不是菜品菜单 |
| 门店—菜单 | 本店实际开通范围，不得超出品牌上限；旧门店无配置默认关闭；新关联门店默认继承门店视角品牌菜单 |
| 品牌—角色 | 品牌内复用的岗位定义，包含菜单、内容、设置与操作权限 |
| 账号—角色—门店 | 每一次角色分配都有自己的生效门店；禁止将所有角色与所有门店交叉组合 |

### 2.2 生效规则

普通账号在某店的权限 = 品牌开通范围 ∩ 门店开通范围 ∩ 该账号在该店生效的角色权限。仍保留既有发布、产线、订阅等限制。普通账号品牌视角可查看其至少一家授权门店可用的页面，业务数据范围按当前页面再次裁剪；跨店操作只能在全部目标店均授权时执行。

品牌 Admin 是明确的账号身份：品牌视角看到全部品牌门店及品牌菜单，自动覆盖后续加入的门店；切换门店业务视角后遵守该店菜单开通范围。普通账号不能编辑门店开通、品牌账号或品牌角色。

### 2.3 开通分工

| 配置 | M 平台运营 | 品牌 Admin |
| --- | --- | --- |
| 品牌资料及门店归属 | 在既有运营权限范围维护 | 查看 |
| 品牌菜单上限 | 维护 | 查看，不能扩大 |
| 各店菜单 | 维护 | 维护，同一份配置 |
| 品牌账号、角色及生效门店 | 代配置并留痕 | 维护 |

运营普通关闭与 Admin 普通关闭具有相同配置语义。未新增隐藏的平台锁定规则。

## 3. 商户生命周期

### 3.1 状态机

```mermaid
stateDiagram-v2
  [*] --> draft: 创建草稿
  draft --> onboarding: 提交开通
  onboarding --> active: 引导完成 / 代配置完成
  active --> suspended: 欠费 / 违规 / 主动暂停
  suspended --> active: 恢复
  active --> closing: 发起关闭
  closing --> closed: 冷静期结束 · 数据归档
  suspended --> closed: 强制关闭
  closed --> [*]
```

| 状态 | 说明 | 商家后台 |
|------|------|----------|
| `draft` | 销售/运营录入基本信息，未激活 | 不可登录 |
| `onboarding` | 待完成业态产线选择或 M 平台代配置 | 仅初始管理员可进 `/onboarding` |
| `active` | 正常营业 | 全功能（在能力开通范围内） |
| `suspended` | 暂停服务 | 只读或禁止登录（策略可配置） |
| `closing` | 关闭中，数据导出窗口 | 只读 |
| `closed` | 已关闭，数据归档 | 不可登录 |

### 3.2 开通方式

新建品牌采用三步：品牌信息 → 选择品牌门店 → 开通品牌菜单。确认前展示集团、门店数、菜单节点数；全部校验后创建。账号开通独立进行，创建成功进入 M 品牌管理员页，先开通品牌 Admin；由 Admin 登录商家后台建立角色、普通账号及角色门店分配。

可关联同集团可挂接的独立门店；无候选时允许创建零店品牌，后续继续关联。关联保持 MID，新的品牌归属下默认继承品牌菜单的门店视角范围。已有其他品牌归属的门店不通过普通勾选直接转移。本轮不新增跨品牌迁移流程。

旧自助入驻、POS 申请及生命周期入口保留，不自动批量修改既有账号与角色数据。

---

### 3.3 关闭与合规

- **关闭前检查**：未结账单、活跃 License、硬件在线、子账号
- **冷静期**：默认 30 天只读，允许数据导出
- **审计**：开通/暂停/关闭/能力变更写入 `MerchantChangeLog`（对齐权限中心 change-log 模式）

## 4. 品牌门店与双入口菜单管理

M 平台：品牌列表 → 品牌门店 → 配置菜单。商家后台：品牌 Admin → 门店管理 → 品牌门店 → 配置菜单。两个入口读取与更新同一份门店配置。

支持按名称/MID 搜索、勾选门店、逐店配置、批量增量开通及批量替换。批量默认增量，保留各店原有菜单；替换要求在预览中逐店列出关闭项。取消不写入，保存失败保留选择。候选店归属、品牌上限或门店配置已变化时，旧版本保存失败，运营保留草稿后刷新重试。

品牌页可查看门店状态、已开通页面数、最近修改时间与操作人。零菜单展示未开通，不等同于门店停业。

集团、区域与历史组织树保持既有入口，本轮不新增拖拽换归属。

## 5. 品牌菜单上限与人员授权

品牌菜单来自当前菜单路由，按已选择产线合并可选节点。目录勾选级联选择现有下级，单选下级补齐必要父目录；取消目录移除其下级。目录不与页面混合计入已开通页面数。

新授权保存为显式节点与资源身份快照。品牌新增菜单后 Admin 品牌视角可见，门店不自动开通；新增路由不自动授予既有品牌。清空品牌菜单后保持关闭，不回填默认服务。历史未显式配置的品牌保留既有默认与兼容行为，首次编辑时展示实际解析结果供确认。

收回品牌菜单前展示增减项及受影响门店；保存后裁剪各店超出上限的菜单，原角色授权保留审计记录但不越过上限。再次给品牌开通时，继承门店自动同步；独立配置门店不自动恢复已裁剪项。

角色在品牌内维护，同名重复校验；可分别配置页面、内容、设置只读/可编辑和已注册的操作。账号分配角色时必须选择至少一家本品牌门店。示例：张三的店长角色仅在 A/B 店有效，财务角色仅在 C 店有效，张三不能在 C 店凭店长角色使用订单。

新品牌先显式开通账号，首次登录使用品牌配置，不重新执行商家自选功能引导。普通账号停用后不能登录且已有会话不继续获得授权。必须保留至少一名启用的品牌 Admin；密码与登录约束沿用当前演示登录契约。

## 14. 小结

**商户管理中心** 补齐 M 平台从「配置中心」到「租户运营中心」的关键一环：

1. **管谁**：Enterprise 下所有入驻 Merchant 与组织树（品牌 / 区域 / 门店）
