# TipOut · 按个人销售额占比扣除设计方案

> **模块**：团队管理 / 报表中心 → TipOut 小费池规则 → 小费扣除方规则  
> **版本**：v1.0  
> **日期**：2026-07-14  
> **状态**：已落地（方案 A1；扣除方交互对齐池规则「新增选项」卡片，见 v1.3）  
> **场景**：每位服务员按本人 Net Sale × 占比计提后，从本人小费收入扣除  
> **关联**：[TipOut-销售额取值-含小费订单条件设计方案](./TipOut-销售额取值-含小费订单条件设计方案.md)、[TipOut-销售额取值-支付方式条件设计方案](./TipOut-销售额取值-支付方式条件设计方案.md)、`dist/TipOut/docs/TipOut计算公式.md`

---

## 一、背景与目标

### 1.1 使用场景

需要**每个服务员**按其 **Net Sale** 抽取一定占比（如 **3%**）进入小费池逻辑；算出的金额从**该服务员本人总小费收入**中扣除。

示例：

| 员工 | Net Sale | 占比 | 应扣 | 小费前 | 小费后 |
|------|----------|------|------|--------|--------|
| A | 1000 | 3% | 30 | 100 | 70 |
| B | 2000 | 3% | 60 | 200 | 140 |

### 1.2 现状问题

当前「销售额取值条件」贡献小费池的语义是：

```text
小费池销售额金额 = Σ所选员工符合条件销售额 × 计提占比
```

再在扣除方内按销售比例切开。产品心智是「**先凑总销售额再抽成**」，不是「**每人按自己的 Net Sale 抽成**」。

当取值人群与扣除方碰巧一致时，结果数值可等于 `S_i × r`，但：

- 文案与配置易误解；
- 两边 scope 不一致时，会出现「帮别人垫扣」。

### 1.3 目标

在扣除方新增明确口径，使：

```text
扣额_i = 本人符合条件销售额 S_i × r
分配后小费_i = 分配前小费_i − 实扣_i
```

且 **A 的扣额不受 B 销售额影响**。

## 二、方案选择

| 方案 | 做法 | 结论 |
|------|------|------|
| **A1 扣除方自带占比 + 取值条件** | 不依赖销售额池卡片 | **采用** |
| A2 仍挂销售额池卡片，仅改扣除计算 | 更贴现有结构 | 心智仍绑「池卡片」，不采用为本期主方案 |
| 仅文档引导两边 scope 对齐 | 零开发 | 语义仍不正确，不采用 |
| 改写旧「按照销售额占比」为个人口径 | 破坏兼容 | 不采用 |

**采用方案 A（实现选 A1）**。

## 三、字段、公式与边界

### 3.1 扣除口径一览

| Tab 文案 | key / 落库 | 说明 |
|----------|------------|------|
| 按照销售额占比 | `salesPct` | 现有：总池再分摊，**保留** |
| 按照小费收入 | `tipIncome` | 现有，**保留** |
| **按个人销售额占比** | `personalSalesPct` | **新增** |

### 3.2 核心公式

```text
S_i     = 员工 i 在 personalSalesPct.salesConditions 下的销售额（默认 Net Sales）
r       = personalSalesPct.rate（如 0.03）
应扣_i  = S_i × r
实扣_i  = min(应扣_i, 分配前小费_i)
分配后小费_i = 分配前小费_i − 实扣_i（+ 分得小费，若适用）
未扣足_i = 应扣_i − 实扣_i
```

验收分水岭：**仅变更员工 B 的销售额时，员工 A 的应扣不变。**

### 3.3 建议字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `deductConfig.personalSalesPct.rate` | number | 占比，如 `0.03` |
| `deductConfig.personalSalesPct.scopeType` | `role` \| `employee` | 谁被扣 |
| `deductConfig.personalSalesPct.roles` / `employees` | array | 适用范围 |
| `deductConfig.personalSalesPct.salesConditions` | object | 与销售额条件同构：营业额类型、角色/员工过滤、可选 `orderTipStatus` / `paymentMethods` 等 |

### 3.4 边界

| 场景 | 处理 |
|------|------|
| 小费前 &lt; 应扣 | 实扣到小费清零；记未扣足；不做负小费 |
| S_i = 0 / 无单 | 应扣 = 0 |
| 未配营业额类型 | 默认 Net Sales |
| 不配销售额池卡片 | **仍可**按本口径扣除（A1） |
| 与销售额池卡片并存 | 池卡片走旧总池逻辑；本口径独立按人计算，算式不合并 |
| Service Charge | 不计入「分配前小费」；自愿小费（卡/现金）计入 |

## 四、配置交互与落库

### 4.1 入口

TipOut 规则编辑 → **小费扣除方规则** → 「+ 新增选项」添加卡片（三口径均可**新增多条**）。

### 4.2 面板

| 区块 | 内容 |
|------|------|
| 计提占比 | 默认 **0%**，**必填且须 > 0**（每张卡片各自输入） |
| 适用范围 / 取值条件 | 抽屉设置；**角色默认展示且必选**；默认营业额类型 Net Sales（小费收入占比除外） |
| 说明 | 「每人扣额 = 本人符合条件销售额 × 占比，从本人小费收入扣除；不受其他员工销售额影响。」（个人销售额口径） |

多条个人销售额卡片：按角色分档（如 Server 3% + Bartender 2%）；命中多档时应扣累加后再与小费前取 min。

### 4.3 本场景推荐配置

1. 新增「按照个人销售额占比」  
2. 占比 = 填写大于 0 的数值（默认 0，保存前必填）  
3. 角色 = Server（必选）  
4. 营业额类型 = Net Sales  
5. （可选）含小费订单 / 支付方式过滤  
6. 接收方按店规配置 tip-out 去向  

### 4.4 落库示意

单条仍为对象；多条为数组：

```json
{
  "deductConfig": {
    "personalSalesPct": [
      {
        "rate": 0.03,
        "scopeType": "role",
        "roles": ["Server"],
        "salesConditions": { "revenueType": "Net Sales (税前营业额)", "role": ["Server"] }
      },
      {
        "rate": 0.02,
        "scopeType": "role",
        "roles": ["Bartender"],
        "salesConditions": { "revenueType": "Net Sales (税前营业额)", "role": ["Bartender"] }
      }
    ]
  }
}
```

兼容旧数据：`personalSalesPct` / `salesPct` / `tipIncome` 仍可为单对象。

### 4.5 摘要

`扣除方(个人销售额) Server · 3% · Net Sales`

### 4.6 与销售额池卡片

- A1 **不要求**配置销售额池规则卡片。  
- 本口径扣款进入可分配逻辑后，接收方仍用规则上既有接收方配置（有配置时）。

## 五、同一规则内多扣除口径

| 组合 | 策略 |
|------|------|
| `personalSalesPct` + `salesPct` | **互斥**：不可同时保存生效；保存个人口径时清除或禁用 `salesPct`，避免双扣 |
| `personalSalesPct` + `tipIncome` | 允许并存（按销售抽 + 按小费抽）；本场景文档建议只开个人口径 |
| 仅旧 `salesPct` / `tipIncome` | 行为完全兼容 |

## 六、与周边模块边界

| 模块 | 边界 |
|------|------|
| 销售额池「按照销售额占比」 | 总池语义保留；本方案不改写其公式 |
| 订单小费状态 / 支付方式条件 | 可作为 `personalSalesPct.salesConditions` 子条件复用 |
| 员工小费余额 | 仍用：`分配后 = 分配前 − 扣除 + 分得`；其中「扣除」含本口径实扣 |
| TipOut计算公式.md | 需增补「按个人销售额占比」专节 |

---

## 七、验收标准

1. 扣除方出现第三 Tab「按个人销售额占比」。  
2. A：`S=1000,r=3%,小费前=100` → 应扣 30、小费后 70；B：`S=2000` → 应扣 60、小费后 140。  
3. 隔离性：只改 B 的销售额，A 应扣不变。  
4. 无销售额池卡片时本口径仍可扣。  
5. 与 `salesPct` 互斥，防止双扣。  
6. 小费不足时小费后为 0，可记未扣足。  
7. 仅含旧扣除口径的规则行为不变。

## 八、非本期与风险

### 8.1 非本期

| 主题 | 说明 |
|------|------|
| 将旧 sales_pct 改为个人口径 | 旧口径保留 |
| 负小费 / 下期追扣未扣足 | 仅记差额 |
| 存量规则自动迁移为 personalSalesPct | 不做 |
| 分配页大改版 | 最小可增加应扣/实扣/未扣足展示 |

### 8.2 风险

| 风险 | 缓解 |
|------|------|
| 店主仍去配销售额池 | Tab 文案明确「不依赖销售额池」 |
| 与 sales_pct 双开 | 保存互斥校验 |
