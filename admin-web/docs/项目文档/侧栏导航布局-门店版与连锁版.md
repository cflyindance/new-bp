## 公共菜单交互规则（NAV-20261014-01）

用户确认：导航菜单存在二级菜单时，统一采用排班式覆盖滑层，任意更深父子层级递归复用。

| 元素 | 逻辑说明 |
|---|---|
| 有子菜单的菜单行 | 整行含文字与空白可点击，显示进入箭头；点击进入下一层，不在父项下内嵌展开，不自动切换业务页。 |
| 子导航滑层 | 占用与父层相同区域，顶部和宽度对齐；覆盖父标题、搜索与列表，不在新标题上方保留父标题。商家标识及导航排序沿用原侧栏边界。 |
| 当前层标题 | 使用被点击的菜单名称；每层只展示该菜单当前允许访问的子项。 |
| 返回按钮 | 左上箭头只退一层，首层子导航返回主导航；不回退业务地址，不保存、下发或修改业务数据。 |
| 叶子菜单 | 沿用原目标地址打开页面，保留当前子导航层，当前项高亮；业务页权限和草稿保护沿用原机制。 |
| 深层父项 | 继续按同位置覆盖滑层下钻，不并排展开多层列表；返回逐层恢复。 |
| 可见菜单范围 | 沿用权限、订阅、发布和预设过滤；不新增授权。过滤后无子项不显示空下钻层。 |
| 搜索 | 已有模块搜索仍在父层使用；进入子层清除原搜索，不复制父搜索框、不新增子层搜索能力。 |
| 刷新／切换模块 | 下钻路径仅保存于内存，刷新不恢复；业务页按地址定位。切换模块或关闭滑层清除旧层级。 |

范围：导航菜单父子层级；页面内部页签、业务列表折叠和更多组织分组不属于本规则。无子菜单的链接沿用原打开方式。新菜单必须复用公共逻辑，不新增模块内嵌展开例外。

## 1. 背景

侧栏一级模块共 **27 项**，全部平铺会导致：

- 店长/值班经理难以快速找到「今日经营」相关入口；
- 配置类、审计类模块与营业模块混在一起，认知负担高。

因此采用 **主导航 + 「更多」折叠分组**，并提供 **门店版 / 连锁版** 两套默认预设，可在侧栏底部切换（持久化于 `localStorage` 键 `sidebar-nav-layout-preset-v1`）。

## 2. 划分原则（门店使用场景）

| 维度 | 主导航（高频） | 「更多」（低频） |
|------|----------------|------------------|
| 使用频率 | 每天 / 每班次 | 每周 / 每月 / 出问题时 |
| 操作性质 | 看数、管人、管现场、管菜单 | 配规则、配权限、配模板、查日志 |
| 典型角色 | 店长、值班经理 | IT、总部运营、新店筹建、审计 |
| 时效 | 找入口慢会影响营业 | 晚一点找到影响不大 |

**说明**：后台许多模块以「设置」为主（订单中心、支付中心等），门店日常订单在 POS 处理；侧栏应优先服务 **管理岗**，而非复刻全部业务名。

### 3.2 连锁版（`chain`）

**目标用户**：总部、区域运营、多店督导、权限管理员。

与门店版的差异：**权限管理中心**、**库存管理中心** 提升为 **主导航**（总部更常做授权、多店库存策略）。

**主导航（16 项）**：在门店版 14 项基础上 **增加**：

- 权限管理中心  
- 库存管理中心  

**「更多」（11 项）**：门店版「更多」中 **移除** 上述 2 项，其余保持不变。

## 6. 后续可扩展

1. **按角色自动选预设**：登录后根据账号类型默认门店版或连锁版。  
2. **业态开关**：例如「强库存/WMS」单店将库存保留在主导航。  
3. **最近使用 / 搜索**：硬件、权限等低频但紧急模块，通过主页待办或顶栏搜索补路径。  
4. **主导航上限**：建议可视区保持在 **12～16 项**，「更多」收纳其余配置向模块。
