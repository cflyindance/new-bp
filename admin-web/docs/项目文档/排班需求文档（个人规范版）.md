## 排班二级导航滑层

![排班二级导航滑层](assets/scheduling-navigation/schedule.png)
图注：排班二级导航滑层，排班表选中；本地原生项目 SCHEDULE-20261014-02 验证截图。

入口：点击团队管理菜单中的“排班”。滑层占用原团队管理滑层的完整区域，顶部坐标相同，标题为“排班”；原“团队管理”标题、搜索框与菜单被覆盖，不留在排班标题上方。二级导航仅列排班表、班次、规则设置。点击子项切换业务页面并保留该滑层；点击左上返回按钮恢复团队管理菜单，业务页面地址不变，不保存、不下发。本次不新增搜索能力。刷新按现有内存下钻状态重新显示父菜单，业务页面仍按地址定位。

| 字段 | 逻辑说明 |
|---|---|
| 排班标题 | 与原团队管理标题使用相同 h-14 标题栏和顶部定位，覆盖父标题。 |
| 返回团队管理 | 点击清除当前排班下钻层，恢复团队管理菜单；不退出当前业务页面，无数据写入或取消确认。 |
| 排班表 | 整行点击进入 schedule 页面，当前项高亮，滑层保持显示。 |
| 班次 | 整行点击进入 shifts 页面，当前项高亮，滑层保持显示。 |
| 规则设置 | 整行点击进入 rules 页面，当前项高亮，滑层保持显示。 |

验证：真实浏览器测得切换前后滑层顶部均为 95.25px（当前视口），排班滑层中团队管理标题数量为 0；三个子项和返回路径通过。历史全量字段补齐范围仍未闭合。

## 排班表页面

![排班表页面](assets/scheduling-navigation/schedule.png)
图注：排班表，默认演示数据状态；来源为本地原生项目 2026-10-14 覆盖式滑层变更后页面（SCHEDULE-20261014-02）。

用途／入口：团队管理 → 排班 → 排班表；展示员工 × 日期排班表，默认入口为旧排班根地址。 本文逐项覆盖本次变更的导航元素，页面内部业务沿用产品文档有效定义，历史全量元素规范尚未迁移。

### 左侧导航区域

| 字段 | 逻辑说明 |
|---|---|
| 排班 | 父菜单，展示进入箭头；点击整行进入排班二级导航滑层，顶部与团队管理原标题对齐，覆盖团队管理标题、搜索和菜单。不保存、不下发、不切换业务数据。 |
| 排班表 | 固定名称；点击整行进入 `/team/shift-scheduling/schedule`，展示日期表并选中该子项；旧根地址默认进入此页。 |
| 班次 | 固定名称；点击整行进入 `/team/shift-scheduling/shifts`，展示已创建班次并选中该子项；刷新保留此地址及页面。 |
| 规则设置 | 固定名称；点击整行进入 `/team/shift-scheduling/rules`，展示原有规则开关并选中该子项；与员工打卡的同名入口由父菜单区分。 |

### 页面切换结果

导航来源为统一菜单配置。子项无需额外输入校验，点击更换地址和面板，移除重复顶部页签；切换不会自动保存或下发。跨模块离开沿用既有草稿保护。页面内未提交班次弹框在切换时关闭，无业务写入；失败提示与保存取消逻辑沿用原功能，本次无新增规则。
