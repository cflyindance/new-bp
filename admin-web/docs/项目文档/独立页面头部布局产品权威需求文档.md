## 范围与目的

独立路由的详情、编辑和预览页采用一致页头，便于识别当前对象、返回上下文和页面操作。涵盖权限/员工、硬件编辑、品牌/门店详情及创建、服务包详情/创建/品牌权益、平台预设编辑、下发详情和 PIT 原生详情页。正常对象与不存在状态遵守同一返回位置。

| 页面区域/元素 | 逻辑说明 |
| --- | --- |
| 返回 | 标题左侧，只保留一个主返回入口；沿用原返回列表、父页及查询上下文，离开前执行既有草稿保护 |
| 标题 | 返回右侧，保留业务对象名称和编辑/预览语义；长标题换行，不遮挡操作 |
| 副标题/状态 | 标题下方展示业务已有对象信息和状态，不新造业务字段 |
| 页面操作 | 标题右侧展示原有保存、取消、预览、发布、导出等；可用性与权限保持原定义，不因调整位置而扩大授权 |
| 窄屏 | 操作组换行右对齐，返回和标题保持逻辑顺序，不产生水平溢出 |
| 底部状态 | 可以保留未保存、已保存等状态，不重复页面级返回/保存/预览按钮 |
| 向导 | 上一步、下一步留在步骤区域；最终保存/发布位于页头右侧 |
| 内容操作 | 行内按钮、内容分组、员工工作台维度保存随当前配置维度显示于页头右侧，生效权限不显示保存；添加授权保持内容区域 |

普通列表无返回需求时不增加返回。弹框和抽屉沿用各自布局。iframe 宿主使用本规则；嵌入子应用在自身源码/构建范围落实，不跨文档搬移按钮。本次原生路由清单与嵌入边界见[验证记录](../验证记录/独立页面头部布局验证记录.md)。

## 验收依据

标题左侧可找到唯一主返回；页面级操作在右侧且底部无副本；禁用、只读、保存确认、校验失败、取消和草稿离开保护遵循对应业务规则。硬件表单外保存必须提交原表单，不能因位置变化导致失效。代表页面与实际执行结果分别记录，不把类型检查当作全页面交互验收。
