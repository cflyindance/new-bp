## 路由与对象映射

| 字段 | 逻辑说明 |
| --- | --- |
| team-roles | 既有父导航 ID，保留平台预设过滤口径；children 新增两个叶子节点。 |
| team-employees | 员工管理叶子 ID，路由 `/team/roles-employees/employees`。 |
| team-positions | 岗位管理叶子 ID，路由 `/team/roles-employees/roles`。 |
| view | 原生页面根节点 dataset.employeesView（独立兼容页使用 URL 查询参数）；字符串枚举 employees / roles；由外层路由提供，优先级高于 sessionStorage 中旧 Tab 记忆；缺失或非法时独立页沿用旧逻辑。 |
| 标题 | employees 映射员工管理，roles 映射岗位管理；使用文本写入。 |
| 面板 | 只展示 view 对应列表与新增按钮；隐藏另一个面板；路由切换重新挂载原生页面，保存数据仍来自原有存储。 |
| 门店 | 使用原有全局 scope 与桥接同步；不增加新的存储键、接口、角色授权或岗位目录隔离。 |

## 状态和异常

父菜单展开/收起只改变导航状态，不写业务数据。旧路径规范化使用 replace，默认员工管理。不生成额外历史记录。原生页面初始化失败遵循现有浏览器反馈，不伪造空列表或成功状态。切换外层页面时原有未保存弹框不恢复，返回后读取已保存数据。

## 测试场景

1. 先保留旧 roles Tab 记忆，再进入员工路由：仍显示员工管理和新增员工。
2. 岗位路由直达、刷新：显示岗位管理和新增岗位，无顶部重复 Tab。
3. 两叶子之间点击并前进/后退：路径和内容一致。
4. 门店切换后再切换页面：读取同一个全局门店范围，岗位目录不按门店清空。
5. 独立 employees.html 无 view：仍能使用旧 Tab。
6. 旧父路径与尾斜线：规范到 employees 叶子。

计算、金额精度及业务状态新增：不适用，本次仅导航。
