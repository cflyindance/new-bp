## 服务商员工商户访问授权

共同变更编号：M-MERCHANT-ACCESS-20261102-01；功能分支 codex/provider-merchant-access-20261102，起始 main@ecc540bf。截图来自端口 5301 的独立 Edge 验收上下文，不代表生产数据。

### 商家后台访问角色列表

![商家后台访问角色列表](assets/provider-merchant-access-20261102/roles.png)

图注：访问角色列表，新建角色成功状态。

入口：权限管理中心 → 商家后台访问角色。作用对象是软件服务商员工的商家后台访问角色，与 M 平台角色、品牌内部角色分别存储。

| 字段／操作 | 逻辑说明 |
| --- | --- |
| 访问角色 | 名称去首尾空格，1–30 字，忽略大小写判重；新角色默认空白权限。 |
| 描述 | 0–160 字，可为空。 |
| 关联员工 | 按绑定该角色的员工 ID 去重；同员工多条范围绑定仍计 1 人。 |
| 新建访问角色 | 需要独立的管理商户访问授权动作；填写后保存角色元数据，不自动授予员工或目标商户。 |
| 配置权限 | 全屏打开该角色，编辑统一商家资源目录中的菜单与操作。 |
| 编辑 | 修改名称和描述；失败保留弹框内容，取消不写入。 |
| 复制 | 复制描述和资源授权，不复制名称、员工绑定或系统兼容授权。 |
| 删除 | 已有员工绑定时拒绝，先解除绑定；无绑定时确认后删除，取消不变。 |
| 授权变更记录 | 显示时间、真实操作人、操作和对象；不显示密码。记录不替代商户业务操作审计。 |

### 访问角色权限编辑

![访问角色权限编辑](assets/provider-merchant-access-20261102/role-editor.png)

图注：全屏编辑，订单中心处于可见不可编辑状态。

| 字段／操作 | 逻辑说明 |
| --- | --- |
| 菜单树 | 复用商家权限中心统一资源目录，菜单结构与路由对应；失效资源不生效。 |
| 搜索菜单 | 按菜单名即时筛选，不修改授权草稿。 |
| 目录可见性 | 不可见阻断下级；关闭时保留下级配置，重新开放仍按有效祖先和依赖计算。 |
| 页面权限 | 不可见、可见不可编辑、可编辑；沿用已有页面级控制、内容、分类和字段规则，不制造不存在的操作。 |
| 独立操作 | 默认禁止；页面可见不自动允许编辑、导出等动作。角色匹配后仍需满足资源依赖。 |
| 保存授权 | 显示影响员工数并确认；复核管理权限、授权上限和 revision，成功后写入授权及审计，再通知有效会话重算。 |
| 返回列表 | 无修改直接返回；有修改显示独立放弃确认，可取消继续编辑。 |
| 只读访问 | 可查看，保存及修改操作禁用；保存函数也拒绝无管理动作的调用。 |

### 员工商户访问授权

![员工商户访问授权](assets/provider-merchant-access-20261102/staff-access.png)

图注：同一员工分别绑定两家门店和两个访问角色。

入口：员工与账号 → 商户访问授权。账号启停与 M 平台角色沿用原有管理方式；此页只编辑商户访问绑定。

| 字段／操作 | 逻辑说明 |
| --- | --- |
| 员工 | 展示姓名、登录邮箱及启停状态；来自服务商员工账号，不创建品牌内部员工。 |
| 访问角色 | 当前绑定的商家后台访问角色；角色失效不产生允许权限。 |
| 适用范围 | 每条绑定独立关联角色和品牌／门店范围；不能把不同绑定的角色与范围交叉组合。 |
| 添加访问授权 | 打开范围弹框；加入草稿后，仍需保存授权才生效。 |
| 编辑绑定 | 修改该条角色或范围，保留其他绑定。 |
| 移除绑定 | 加入待保存草稿；保存空绑定列表表示撤销全部商户访问，账号本身不删除。 |
| 系统兼容授权 | 既有演示系统身份 ent001 明确保留全部品牌／门店范围及完整目录；受账号、M 平台动作和商户菜单上限限制，不能复制给普通员工。 |
| 保存授权 | 确认后生效；失败及版本冲突保留草稿，不显示假成功。 |
| 新员工／普通旧员工 | 默认无商户访问授权；不推断旧 enterprise-rbac、品牌 Admin 或员工个人例外。 |

### 商户列表与访问边界

![受限员工的门店列表](assets/provider-merchant-access-20261102/restricted-stores.png)

图注：仅获准一家门店的服务商员工。

| 字段／操作 | 逻辑说明 |
| --- | --- |
| 品牌／门店列表 | M 页面权限和目标范围同时满足；只授权门店时可显示必要的所属品牌名称、BID，但不能直接进入品牌完整详情或品牌代管。 |
| 统计与候选项 | 商户统计、门店分析、订阅主体和硬件设备数据按获准目标过滤；未知归属不当作公开数据。 |
| 进入商家后台 | 品牌和门店分别有独立访问动作；允许只读 M 管理页员工在动作获准时进入，不要求给其品牌编辑权限。 |
| 菜单上限 | 已发布目录、品牌已开通菜单、门店视角上限、当前目标匹配角色共同限制菜单；收费服务的可用性再按服务权益判定。 |
| 身份 | 保留真实服务商 employeeId／邮箱和代管会话 ID，不再借用品牌主管理员邮箱作为权限主体。 |
| 撤权 | 停用、撤销目标范围或进入动作后，已进入会话停止访问，退回首个可访问 M 页面并显示失效提示。菜单收窄时导航和直接地址重新计算，不自动保存旧草稿。 |
| 管理权限 | 授权管理、商户访问和商户业务操作分别判断；不能授予超过本人范围或角色权限的授权。普通商家账号保持原授权链路。 |


## 系统使用分析独立权限目录

![系统使用分析权限目录](./assets/usage-analysis-entry-20261029/permissions.png)

图注：2026-10-29，codex/usage-analysis-entry-20261029，main@f30e8451起始，5257实采；角色编辑中系统使用分析与商户管理中心分别设置模块门槛。

入口：权限管理中心 → 角色与功能权限 → 编辑权限。

| 字段／操作 | 逻辑说明 |
| --- | --- |
| 系统使用分析模块 | m:module:activity-analysis，可见／不可见；独立于m:module:merchants。导航、角色目录与实际资源树一致。 |
| 门店活跃分析 | m:page:merchant-activity，可见／不可见，无业务写操作；父资源为系统使用分析模块。 |
| 设备活跃分析 | m:page:device-activity，可见／不可见；与门店活跃分析分别授权，共用分析模块门槛。 |
| 详情中的使用情况 | 品牌或门店详情权限与门店活跃分析权限同时满足才可进入；单有商户管理编辑权不代表可读分析。 |
| 仅分析角色 | 可查看本人获准范围内的全局分析；无商户管理权限时不显示品牌/门店管理跳转，也不能直达管理详情的使用情况页。 |
| 多角色与停用 | 保留角色允许并集及祖先门槛；停用账号、缺页权和缺模块权均拒绝。浏览期间撤权后下次交互/重渲染不继续访问。 |
| 历史角色兼容 | 缺目录版本标记的旧记录，按角色复制原商户模块门槛到缺失的新分析模块门槛，不新增或修改任何分析页grant。已显式配置的新门槛（包括不可见）不覆盖。 |
| 新角色 | 默认不可见；不因商户管理可见而自动拥有分析权限。 |
| 旧路由 | /m-platform/merchants/activity与device-activity及原明细地址继续使用；地址保留不表示权限仍归商户中心。 |

![只读预设设置](images/m-platform-permissions/readonly-settings.png)

|---|---|
| 只读说明 | 可设置页面仅 read 时展示“当前页面为只读，暂无修改权限。” |
| 导航、搜索、筛选 | 允许正常查看；不因无编辑权全部禁用 |
