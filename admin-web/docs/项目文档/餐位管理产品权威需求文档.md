## 目标与范围

让维护资料与调整空间布局分别有明确入口，减少弹框打断及保存歧义。本次新增餐位管理列表，优化既有平面图；区域管理保留快捷操作，不新增独立菜单，不引入开台、清台、预约、消费或计价新规则。既有数据连接和同步实现参考[历史 KPOS 同步设计](../superpowers/specs/2026-08-21-kpos-floor-plan-live-sync-design.md)，该文件不是本次新增的第四份业务权威。

## 公共业务规则

- 一个区域属于当前门店，一个餐位属于一个区域；列表与平面图共享同一套对象，不复制餐位数据。新增“餐位管理”入口位于“餐位平面图”之前，前厅默认入口仍沿用原平面图。无区域时先创建区域，不能创建无归属餐位。
- 两页属于同一编辑会话，互跳保留草稿，无离页丢弃提示；离开本模块沿用确认离开/取消保护。确认离开恢复业务基线，取消离开返回原地址与草稿。切门店不共用布局和历史。
- 表单“应用属性”、区域弹框“保存”、抽屉“创建餐位”只改变本模块草稿。唯一外部生效入口为底部“保存并下发”，先校验并归并表单，再展示变更，确认下发后才同步；预览和取消确认不写入外部系统。
- 保存失败保留业务草稿、待保存状态和错误提示，允许修正后重试。真实 KPOS 没有跨步骤事务，本次不承诺自动回滚部分成功，不修改/撤销已有操作账本。成功表示既有下发流程接受变更，不额外承诺所有终端已完成同步。
- 餐位管理沿用原平面图能力，权限、订阅及发布/预设过滤均复用原能力键，不创建新的授权范围。深层菜单继续复用 NAV-20261014-01 公共覆盖滑层。
- 当前已有约束继续生效：餐位名称去首尾空格并统一大写、在当前门店所有区域中唯一；人数为正整数；特殊类型需要对应关联字段；真实 KPOS 模式禁止删除区域、正在使用或当前人数大于0的餐位不能删除。

## 餐位管理页面

![餐位管理列表与前厅二级菜单](assets/floor-plan-workbench/management.png)

图注：餐位管理列表与前厅二级菜单；2026-10-15，本地原生 Vite 页面，本次变更版本；数据为隔离测试样例，不是线上门店数据。

入口：前厅管理中心 → 餐位管理。适用当前已选择且有访问权限的门店；品牌视角仍需先选择门店。

| 字段／操作 | 逻辑说明 |
|---|---|
| 名称搜索 | 按餐位名称忽略大小写匹配，输入后即时更新列表；空字符串代表不限制名称。 |
| 区域筛选 | 默认全部区域，按单一区域筛选；与名称条件取交集，筛选不会改变餐位归属。 |
| 重置 | 清空搜索并恢复全部区域，不丢弃业务草稿。 |
| 列表及数量 | 展示筛选后的名称、所属区域、容纳人数与形状；数量为筛选后餐位个数。 |
| 编辑 | 打开右侧属性面板；不弹居中编辑框。 |
| 平面图定位 | 进入同门店、对应区域的平面图并选中餐位，区域与餐位 ID 随跳转携带。 |
| 当前区域快捷操作 | 决定新增餐位的默认区域及区域管理对象，独立于列表的全部区域筛选；界面明确标示“当前区域”。 |

![平面图未选中状态与区域上方切换](assets/floor-plan-workbench/layout.png)

| 字段／操作 | 逻辑说明 |
|---|---|
| 当前区域 | 移到画布上方，切换内容时清空选择；有有效属性输入先加入草稿，非法输入阻断切换。 |
| 单击餐位 | 选中并显示侧面属性面板，保留画布操作能力。 |
| 拖动 | 调整当前餐位位置，自动吸附其他餐位边缘或中心线；到边界显示提示。松开形成一步历史，指针取消不提交位移。 |
| 画布缩放 | 50%至150%，首次按窗口适配；放大/缩小每次10个百分点，适应窗口按容器尺寸计算后限幅。只改变视图，不修改餐位尺寸或草稿。 |
| 撤销与重做 | 撤销/重做本次会话已应用的区域、餐位和布局变更，最多30步；新操作清空重做分支；保存成功、放弃或连接切换清空历史。 |
| 无选择 | 隐藏对齐、分布、统一尺寸、尺寸调整与微调工具，显示区域概况。 |

## 验收与边界

已验证列表搜索、跨区域定位、属性保留和取消、非法值阻断、单选/多选、批量对齐、缩放指针拖动、撤销恢复、空区域新增及本地保存成功。模拟SOAP记录证明确认前与取消时无Save/Delete请求，确认后一次SaveTableType返回503时保留修改值及1项待保存。真实KPOS成功写入、部分成功恢复、终端同步完成状态未执行；本次不宣称端到端真实下发验收。

## 保存中交互保护

![保存期间阻断操作](assets/floor-plan-workbench/saving.png)

图：隔离模拟接口延迟响应期间的保存状态，FOH-20261015-01；失败后保留容量5与待保存草稿。

确认下发后至本次同步成功或失败期间，显示“正在保存餐位配置…请稍候，完成后可继续编辑”。整个应用内容临时设为inert，阻止属性、画布、撤销/重做、放弃、导航、门店及连接切换操作；成功和失败均恢复此前可交互状态，避免请求期间的新输入被回读快照覆盖。浏览器关闭/刷新仍按既有操作账本恢复边界处理，不承诺远端事务回滚。
