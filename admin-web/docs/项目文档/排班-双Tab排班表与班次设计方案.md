## 一、背景与目标

### 1.1 现状

排班页为单一「排班表」视图；班次模板通过工具栏「班次配置」打开弹窗（左列表 + 右详情）维护。首次无本地数据时预置「早班 / 晚班 / 全天」。

### 1.2 问题

- 「排班」与「班次定义」挤在同一屏工具栏入口，心智不如员工打卡页的 Tab 清晰。
- 运营更期望：看排班进「排班表」，管班次进「班次」，默认看到**已经创建**的班次。

### 1.3 设计目标

1. 排班采用与员工打卡一致的左侧展开导航：**排班表**、**班次**、**规则设置**；移除内容区顶部页签。
2. **排班表**：展示当前排班日期表（行为与现网一致）。
3. **班次**：默认展示已创建班次；支持新增 / 编辑 / 删除 / 保存；布局由弹窗改为页内。
4. 去掉工具栏「班次配置」按钮及配置弹窗壳层。
5. 无本地班次数据时仍预置早班 / 晚班 / 全天，作为初始「已创建」数据。
6. 不改动存储 key、排班格子「安排排班」弹窗，以及 `writeShiftTypes` 变更记录行为；`readShiftTypes` 仅按 §5.3 区分「无 key」与「已存 `[]`」。

## 二、方案选择

采用左侧「排班」父菜单进入覆盖式二级导航滑层，展示三个子项。以下为本次有效导航定义，旧双 Tab 方案仅见历史版本。

## 排班二级导航滑层

![排班二级导航滑层](assets/scheduling-navigation/schedule.png)
图注：排班二级导航滑层，排班表选中；本地原生项目 SCHEDULE-20261014-02 验证截图。

入口：点击团队管理菜单中的“排班”。滑层占用原团队管理滑层的完整区域，顶部坐标相同，标题为“排班”；原“团队管理”标题、搜索框与菜单被覆盖，不留在排班标题上方。二级导航仅列排班表、班次、规则设置。点击子项切换业务页面并保留该滑层；点击左上返回按钮恢复团队管理菜单，业务页面地址不变，不保存、不下发。本次不新增搜索能力。刷新按现有内存下钻状态重新显示父菜单，业务页面仍按地址定位。

| 字段 | 逻辑说明 |
|---|---|
| 排班标题 | 与原团队管理标题使用相同 h-14 标题栏和顶部定位，覆盖父标题。 |
| 返回团队管理 | 点击清除当前排班下钻层，恢复团队管理菜单；不退出当前业务页面，无数据写入或取消确认。 |
| 排班表 | 整行点击进入 schedule 页面，当前项高亮，滑层保持显示。 |
| 班次 | 整行点击进入 shifts 页面，当前项高亮，滑层保持显示。 |
| 规则设置 | 整行点击进入 rules 页面，当前项高亮，滑层保持显示。 |

验证：真实浏览器测得切换前后滑层顶部均为 95.25px（当前视口），排班滑层中团队管理标题数量为 0；三个子项和返回路径通过。历史全量字段补齐范围仍未闭合。

## 三、界面设计

### 3.1 左侧二级导航

| 子项 | 路径后缀 | 默认 | 内容 |
|---|---|---|---|
| 排班表 | `/schedule` | 是 | 排班日期表 |
| 班次 | `/shifts` | 否 | 已创建班次管理 |
| 规则设置 | `/rules` | 否 | 是否启用打卡依赖排班 |

路径前缀均为 `/team/shift-scheduling`。父菜单点击进入覆盖式排班二级导航滑层；子项整行点击切换对应内容并高亮当前项。旧根地址进入排班表；直接访问或刷新子地址保留对应页面。三个页面共用原有保存桶，切换不自动保存或下发，跨模块离开仍受原有未保存保护约束。导航变化不改变排班、班次与打卡规则的业务定义。

### 3.2 「排班表」面板

保持现有能力：

- 门店筛选、日期区间、快捷预设、员工筛选、「同步到下周」
- 员工 × 日期格子排班；点击格子打开「安排排班 / 当日班次调整」弹窗
- **移除**工具栏「班次配置」按钮

### 3.3 「班次」面板

页内以**已创建班次列表**为主；新增 / 编辑走弹窗（同一表单，标题区分）。

```
┌─ 班次 ─────────────────────────────────────────┐
│ 门店筛选                      [+ 新增班次]       │
├─────────────────────────────────────────────────┤
│ 已创建班次卡片列表（点卡片 → 编辑弹窗）            │
│ 空态：暂无班次，请点击「新增班次」                 │
└─────────────────────────────────────────────────┘

弹窗「新增班次」/「编辑班次」：
门店、名字、时间、工时、提前打卡、自动下班、颜色
编辑时可删除；[取消] [保存] 立即写回存储
```

## 四、交互与数据流

### 4.1 进入「班次」页面

1. 按当前门店筛选，展示已保存班次卡片列表。
2. 右上「+ 新增班次」打开弹窗；点击卡片打开编辑弹窗。

### 4.2 新增 / 编辑弹窗

- **新增**：须先有门店筛选；预填「新班次」默认时段；保存后写入列表。
- **编辑**：加载该班次；可改字段或删除；保存/删除立即写回 `writeShiftTypes`。
- **取消 / 点遮罩**：关闭弹窗，不写回。
- 切回「排班表」时关闭未保存的弹窗。

### 4.3 与排班表关系

- 格子排班下拉**仅**使用已保存班次（`readShiftTypes()`）。
- 弹窗未点保存前，列表与排班下拉不变。

### 4.4 数据与存储

| 项 | 说明 |
|----|------|
| Storage key | 仍为 `bplant-team-shift-types-v1` |
| 初始预置 | 无本地数据时：早班 / 晚班 / 全天 |
| 变更记录 | 仍走 `recordPageOrImmediateConfigChange`（label「班次类型」） |

## 五、实现要点

### 5.1 主要改动

- 文件：`src/config/team-shift-scheduling-ui.ts`
- 路由决定 `schedule / shifts / rules` 面板，移除顶部页签渲染与点击绑定；切换面板时关闭班次弹框和员工筛选浮层。
- 改造：将 `renderShiftConfigDialog` 内容改为页内 `renderShiftsPanel`（去掉 modal 遮罩与 `shiftConfigDialogOpen` 门控，或等价重构）
- 移除：工具栏「班次配置」按钮；弹窗 backdrop / 仅用于打开配置的对话框壳

### 5.2 尽量不动

- `writeShiftTypes` 的变更记录语义（仍记录 before/after）；`normalizeShiftType`
- 格子编辑弹窗 `renderCellEditDialog` 及排班写入逻辑
- 门店筛选组件与 scope 逻辑（排班表 / 班次各用各自面板内的门店控件，不同时并排两套）

### 5.3 删光与 `readShiftTypes` 调整（必须改）

现网问题：

1. 草稿删至 0 条时会回填 `DEFAULT_SHIFT_TYPES`。
2. `readShiftTypes` 在 **无 key** 或 **`parsed.length === 0`** 时都会回落预置三班。
3. 收集保存时若草稿为空，也可能退回 `readShiftTypes()`，导致无法真正存空。

本方案要求：

| 本地状态 | `readShiftTypes` 行为 |
|----------|----------------------|
| 无该 storage key | 返回预置早班 / 晚班 / 全天 |
| key 存在且值为 `[]` | 返回 `[]`（**不**回落预置） |
| key 存在且为非空数组 | 按现逻辑 normalize 后返回 |

配套改动：

- 草稿删光：**不**回填预置。
- 保存空草稿：写入 `[]`，刷新后仍为空。
- 去掉「空草稿则退回 `readShiftTypes()`」的保存回落。

## 六、验收清单

1. 左侧排班展开「排班表」「班次」「规则设置」，内容区没有重复顶部页签。
2. 默认进入「排班表」，排班日期表行为与改前一致。
3. 切换到「班次」展示已创建班次；无本地数据时为早班 / 晚班 / 全天。
4. 点「新增班次」或列表卡片弹出表单；保存立即持久化；取消关闭弹窗。
5. 工具栏不再出现「班次配置」；班次管理在「班次」页面 + 弹窗完成。
6. 排班格子选班次仍只用已保存班次；未保存的弹窗草稿不影响下拉。
7. 删光全部班次并保存后刷新：列表仍为空；仅从未写过该 storage key 时出现早班 / 晚班 / 全天。
