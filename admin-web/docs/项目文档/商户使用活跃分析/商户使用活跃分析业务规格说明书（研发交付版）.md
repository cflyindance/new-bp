### 研发字段、刷新与兼容规则

| 字段／对象 | 定义 |
| --- | --- |
| ManagedActivityStoreRow | 输入merchantId、merchantName及store.storeId/name/merchantId；来源getEnterpriseStoreList(allEnterprises=true)的当前有效行。函数不修改输入。 |
| ACTIVITY_DEMO_STORE_MIDS | 显式登记demo-all→M1、demo-mixed及demo-unknown→M2、demo-uneven→M3、demo-new→M4、demo-stopped→M5、demo-long→M6、demo-recent→M7、demo-error→M9；此处M数字均补零为8位MID，如M00000001。 |
| createManagedActivityDemo | 调用原纯场景生成器后按登记MID投射管理身份；同MID取产线并集、最早演示openedOn，保留全部业务订单。已知异常优先；未知MID和归属冲突MID不输出统计。 |
| resolveActivityStoreId | 优先数据中精确ID，再用固定alias；目标MID必须存在于当前Dataset，禁止名称模糊匹配。 |
| refreshActivityDemoData | 截至日及按MID排序的身份签名不变则返回false；变化时统一更新Dataset属性及resolvedOrders数组，保持两个导出对象引用稳定。 |
| 输入与去重 | 管理行重复但归属不一致时该MID不生成数据；store.merchantId与行merchantId不一致也拒绝。M2两场景业务ID由同一原生成器递增，不制造ID冲突；重复投递仍由原resolveOrders按MID+业务订单ID去重。 |
| 回归算例 | 8个MID/7个默认品牌；1/7/30/90天，M2点单量等于原mixed+unknown；各店总量=各产线合计+未知来源；同MID转品牌后订单不重生成/不丢失，旧品牌范围不再包含它。 |

### 品牌详情 → 使用情况

![品牌使用情况](../assets/usage-demo-identities-20261029/brand-usage.png)

图注：2026-10-29，codex/usage-demo-identities-20261029，起始main@f58bab26，5258功能预览实采；品牌所属两个MID直接显示匹配统计。

入口：商户管理中心 → 品牌管理 → 品牌详情 → 使用情况。

| 字段／操作 | 逻辑说明 |
| --- | --- |
| 使用情况页签 | 品牌详情页签之一，位于品牌管理员之后、变更记录之前。有门店活跃分析权限时展示；只读管理角色也可浏览。 |
| 当前品牌 | 从品牌详情merchantId取得范围，按分析记录merchantId精确匹配。不按名称、BID、排序位置或历史集团推断关联。 |
| 统计期间 | 与全局门店活跃分析共用今日、近7天、近30天及自定义日期校验；期间只影响订单和使用频率，不改变活跃阈值。 |
| 结果列表与指标 | 有匹配记录时复用门店列表、活跃状态和统计卡；只汇总当前品牌范围。搜索、状态筛选和重置均保留品牌范围。 |
| 暂无使用数据 | 未登记或没有当前有效管理记录的MID显示空态，不回退全局；固定登记演示门店显示已匹配测试统计。 |
| 打开详细分析 | 进入系统使用分析中的当前品牌范围；不修改品牌、菜单、账号或订单。 |
| 查看全局分析 | 明确进入全局门店活跃分析，解除当前品牌限定；仍要求分析页面权限。 |

| 门店活跃分析 | m:page:merchant-activity，可见／不可见，无业务写操作；父资源为系统使用分析模块。 |
| 设备活跃分析 | m:page:device-activity，可见／不可见；与门店活跃分析分别授权，共用分析模块门槛。 |

| 多角色与停用 | 保留角色允许并集及祖先门槛；停用账号、缺页权和缺模块权均拒绝。浏览期间撤权后下次交互/重渲染不继续访问。 |
| 历史角色兼容 | 缺目录版本标记的旧记录，按角色复制原商户模块门槛到缺失的新分析模块门槛，不新增或修改任何分析页grant。已显式配置的新门槛（包括不可见）不覆盖。 |
| 新角色 | 默认不可见；不因商户管理可见而自动拥有分析权限。 |
| 旧路由 | /m-platform/merchants/activity与device-activity及原明细地址继续使用；地址保留不表示权限仍归商户中心。 |

### 目录兼容字段与验收算例

| 字段／操作 | 逻辑说明 |
| --- | --- |
| MState.catalogVersion | 可选字面量2；缺失表示旧目录。readMState校验原记录后返回兼容副本，不因浏览直接写localStorage或递增revision。授权保存将该标记写为2。 |
| 旧角色模块门槛 | 新分析模块键缺失时，原m:module:merchants为read则设read，否则hidden；已有新键保留。各角色分析页grant、员工roleIds、日志与revision不变。 |
| 分离后计算 | 分析页父键仅为m:module:activity-analysis；设置catalogVersion=2后再次读取不复制原商户门槛，防止撤权后重新授予。 |
| 跨角色算例 | A仅有旧商户模块read，B仅有分析页read，员工绑定A+B：旧有效分析可见；兼容后新模块read与页面read并集，仍可见。只绑定B仍不可见。 |
| 隐藏算例 | 旧模块hidden且有分析页read：兼容后仍不可见。主动隐藏新分析模块后保存/刷新也不可见。 |
| 不扩权算例 | 只有商户模块read而无任何分析页grant：复制模块门槛后分析页仍不可见；新创建角色的商户模块read不会自动转换。 |
| 范围算例 | merchant-zhangji范围默认只含M00000001和M00000002；试图下钻茶语M00000003拒绝。旧demo-all解析到M00000001，仍受当前品牌范围校验。 |

## 统一业务口径

| 规则 | 当前定义 |
| --- | --- |
| 产线范围 | POS、Kiosk、eMenu、SDI、OO、POS GO，固定六条。 |
| 点单订单 | 成功提交的原始业务订单；提交后取消仍属于一次点单，取消数单列；草稿不计入。 |
| 去重 | 同一门店内原始业务订单 ID 去重；重传、收款流转不增加点单数。Demo 中重复记录为同一份订单快照。 |
| 点单归属 | 使用下单时来源设备 ID，匹配该时刻唯一有效的 License 绑定关系，取得门店和产线；收款设备不改归属。 |
| 历史绑定 | 绑定区间为 [生效时间, 失效时间)，失效为空表示持续有效。历史订单不随当前设备产线变化而迁移。 |
| 来源待识别 | 来源设备缺失、无匹配绑定或绑定不唯一的订单，仅计入其已知门店总量；不计入产线与设备。 |

| 点单数 | 有效查询期内去重订单数。支付完成数、取消数为其中的状态子集，未支付但已提交订单保留在总数中。 |
| 有订单天数 | 查询期内至少发生 1 笔点单的不同自然日数量。 |
| 日均点单 | 期间点单数 ÷ 含起止日的自然日天数；保留原始计算精度，展示 1 位小数。未营业日期也计入分母。 |
| 最近点单时间 | 截至日期日末以前，全历史最近一次成功提交时间，不受查询起日影响；展示至分钟。 |

| 绑定设备数 | 截至日期日末有效的 License 绑定设备 ID 去重数；不是 License 条数。 |
| 有订单设备数 | 查询期间至少产生 1 笔可归属点单的设备 ID 去重数，包含历史绑定设备。 |

## 活跃状态

活跃状态始终针对截至日期，以全历史最近点单判定；修改查询期间不改变当前活跃状态。

| 状态 | 条件 |
| --- | --- |
| 活跃 | 最近点单距今 0～6 天。 |
| 近期未使用 | 最近点单距今 7～13 天。 |
| 疑似停用 | 最近点单距今 14～29 天，只表示需关注，不判定真实关店。 |
| 长期未使用 | 最近点单距今至少 30 天。 |
| 尚未使用 | 已开通或已绑定，但从未成功提交订单；门店显示演示开通天数，设备显示演示绑定天数，不代替管理资料的日期。 |
| 未开通／未绑定 | 产线未开通，或设备无配置且没有历史点单。未开通产线仍可通过页签查看空设备列表。 |
| 数据异常 | 受控异常门店无法提供订单统计；不作为零订单。当前实现优先标识数据异常。 |

阈值固定为 7/14/30 天，首版无配置页面；不划分统一订单量的高、中、低活跃档位。

### 计算顺序

1. 读取有效管理身份，按固定MID登记表投射截至日期的合成数据；无有效记录不生成门店统计，排除草稿与截至日之后记录。
2. 按门店 ID + 原始业务订单 ID 去重，保留固定原始来源；重复记录为同一订单快照，非状态事件日志。
3. 以订单来源设备、门店、提交时刻匹配唯一有效 License；零条或多条均判为来源待识别。
4. 用全历史匹配对象订单计算最近点单日期及当前状态。
5. 用有效起止日筛选订单，计算数量、支付完成、取消、有订单天数与日均。
6. 取截至日末的有效绑定集合；分别计算当前绑定设备、期间有单设备和绑定集合中的无单设备。
7. null 展示为 —、真实零值为 0；日均仅展示时保留 1 位小数。

### 独立设备统计规则

1. 全量范围是预设设备资产清单，按设备 ID 去重，不依赖先选门店或有订单；共 39 台，包含 1 台未绑定备用终端。
2. 品牌、门店、产线列及对应筛选以截至日末的当前唯一有效绑定为准。未绑定资产不强行归属历史门店；历史归属在详情中可查。
3. 点单量与活跃状态以物理设备 ID 聚合所有历史产线与门店。按当前品牌/门店筛选是在选设备集合，不是在裁剪该设备历史订单。
4. 独立设备抽屉按物理设备聚合，门店设备表按当前门店及所选产线限定；同一设备在某旧产线已久未点单，不妨碍它在新产线仍为活跃。
5. 绑定不唯一不猜测归属。数据异常不作为零订单；设备涉及历史数据异常时，独立统计保守显示不可用，避免将部分已知记录当作完整总量。
6. 六条产线、成功提交计单、取消计入、草稿排除、去重和 7/14/30 天阈值沿用统一定义。来源待识别订单不分摊到设备。
7. 页面仅有不可见/可见权限，与商户活跃页面独立授权，受系统使用分析父资源门禁及角色并集约束；不自动给既有保存角色新增权限。
8. 两个视角读取同一个内存 Demo 快照。有效期间和已应用筛选在各自页面会话内保留；互不覆盖；刷新恢复默认近 7 天、全部条件、第 1 页。
