## 排班二级导航滑层

![排班二级导航滑层](assets/scheduling-navigation/schedule.png)
图注：排班二级导航滑层，排班表选中；本地原生项目 SCHEDULE-20261014-02 验证截图。

入口：点击团队管理菜单中的“排班”。滑层占用原团队管理滑层的完整区域，顶部坐标相同，标题为“排班”；原“团队管理”标题、搜索框与菜单被覆盖，不留在排班标题上方。二级导航仅列排班表、班次、规则设置。点击子项切换业务页面并保留该滑层；点击左上返回按钮恢复团队管理菜单，业务页面地址不变，不保存、不下发。本次不新增搜索能力。刷新按现有内存下钻状态重新显示父菜单，业务页面仍按地址定位。

| 字段 | 逻辑说明 |
|---|---|
| 排班标题 | 与原团队管理标题使用相同 h-14 标题栏和顶部定位，覆盖父标题。 |
| 返回团队管理 | 点击清除当前排班下钻层，恢复团队管理菜单；不退出当前业务页面，无数据写入或取消确认。 |
| 排班表 | 整行点击进入 schedule 页面，当前项高亮，滑层保持显示。 |
| 班次 | 整行点击进入 shifts 页面，当前项高亮，滑层保持显示。 |
| 规则设置 | 整行点击进入 rules 页面，当前项高亮，滑层保持显示。 |

验证：真实浏览器测得切换前后滑层顶部均为 95.25px（当前视口），排班滑层中团队管理标题数量为 0；三个子项和返回路径通过。历史全量字段补齐范围仍未闭合。

## 导航对象与状态

| 字段 | 逻辑说明 |
|---|---|
| 父菜单 | `team-shifts`，路径 `/team/shift-scheduling`；沿用父项身份，点击进入覆盖式二级导航滑层，无业务写入。 |
| 排班表 | `team-shifts-schedule`，路径 `/team/shift-scheduling/schedule`，映射 `schedule` 面板；根地址默认重定向至此。 |
| 班次 | `team-shifts-types`，路径 `/team/shift-scheduling/shifts`，映射 `shifts` 面板。 |
| 规则设置 | `team-shifts-rules`，路径 `/team/shift-scheduling/rules`，映射 `rules` 面板。 |
| 当前面板 | 字符串枚举 `schedule / shifts / rules`，从 hash 路径读取；刷新依据地址，不依赖临时页签记忆。 |
| 保存键 | 三个地址均归一为 `/team/shift-scheduling`，沿用草稿、下发与变更记录。菜单切换不写业务数据。 |
| 临时状态 | 子页面变化时关闭班次编辑、删除确认及员工筛选浮层，清空浮层搜索词；未提交弹框不产生业务写入。 |

权限和模块归属继承原排班入口，本次不新增权限决策。计算、精度、接口字段和后端错误处理不受本次导航调整影响。

## 验收与验证

1. 旧根地址自动到排班表，展示员工日期表。
2. 点击班次显示班次列表；刷新 `/shifts` 保留列表。
3. 点击规则设置显示打卡依赖排班开关；刷新 `/rules` 保留规则面板。
4. 点击排班表返回日期表，左侧仅对应项选中；顶部旧 `data-shift-tab` 数量为 0。
5. 父项点击进入覆盖式滑层；点击“返回团队管理”恢复父菜单，子项整行可点击。
