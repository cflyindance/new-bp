## 菜单组合与状态

![菜单配置，本次实现默认态](assets/category-management/menu.png)

组合数 = 年龄分组数 × 类别数。分组顺序沿用类别顺序，各组按年龄顺序列出。年龄与类别单选筛选取交集，只影响可见行及分组标题；重置恢复全部。没有基础对象时给出基础配置链接。

新增 `MenuComboConfig.configured?: boolean`，无单位、非必填，供兼容旧数据。规范化时：显式 true 保留；旧记录存在可下单菜品、仅可查看菜品或有效组合引用之一时推断 true；自动生成且无内容的默认记录为 false。编辑确认或复制目标成功写入后设 true，取消不改变。渲染文案为已配置／未配置；不等同完整、有效、已保存或已下发。明确确认空配置仍为 true；不新增金额计算或精度规则。

`viewOnlyMode` 保留 dish/category 两种；category 模式的摘要数量是引用组合个数，dish 模式是选菜数量，不把二者统一称为菜品数。原可下单／不可下单两侧配置的数据键不变，界面统一称可下单／仅可查看。

### 复制操作

![复制配置，本次实现未选择目标态](assets/category-management/copy.png)

来源为行的组合 key，排除来源后形成目标集合，不受菜单列表筛选限制。目标为多选，默认空。来源与目标摘要显示原两侧数量，空配置显示内容为空；按钮随目标数量显示“复制并覆盖 N 个组合”。覆盖范围不包含目标显示名称、年龄／类别主数据、营业时间与渠道。

确认后沿用 `applyMenuComboCopy` 深拷贝两侧结构与仅可查看模式，引用排除目标自身、无效 key 并去重；逐个目标标记 configured=true，然后统一写品类草稿。来源内容为空时也允许复制，但确认前明确清空后果；没有合法目标时禁用。取消／关闭不写入。配置读写仍使用既有模块 JSON 和保存保护，无新增后台接口或异步事务。

## 渠道与展示

![渠道与展示，本次实现默认态](assets/category-management/channels.png)

| 元素 | 规则 |
|---|---|
| 渠道 | 只列 eMenu、SDI，来源为已有特殊品类和品类模式适用渠道，不扩展 Kiosk/POS 支持。 |
| 品类模式 | 使用已有 `data-guest-category-mode-lines=601` / `data-guest-category-mode-line` 公共绑定，渠道数组仍由原逻辑写入；用户修改时按是否仍有选中渠道同步主开关；全部取消时写 false，避免旧缺省机制恢复全选。 |
| 展示特殊品类 | 使用原 `data-foh-special-menu-lines` / `data-foh-special-menu-line`，收集两个渠道中选中的值，空数组保持未选择。 |
| 标签点击 | 两列每个完整标签都是对应复选框点击区；aria-label 包含渠道和用途。 |
| 打开页面 | 删除渲染时无条件写 true 的调用；既有缺省迁移仍适用，不把读取页面当作主动修改。 |

公共渠道读取区分缺失配置与显式空数组：已存／草稿值为数组时直接返回规范化结果（包括 `[]`）；只有缺失值才按旧主开关生成默认渠道，避免持久层旧 true 覆盖当前取消选择的草稿。此兼容修复应用于公共品类模式读取，不改变支持渠道集合。

## 保存与异常

复用公共品类保存键、草稿与变更缓冲。过滤、展开更多、打开复制、取消均不创建业务变更；编辑确认、年龄标记变更、渠道复选框变更走原草稿。保存栏计数按配置键，不按受影响行数；整个品类 JSON 可能只计一项。变更预览、丢弃、提交成功失败仍由公共实现负责，本次不宣称新增部分成功或对象级结果。

未确认项与产品版共用 CATEGORY-Q01/Q02/Q03：标记业务语义、渠道最终优先级、特殊品类定义及完整性标准；当前无新终端公式。历史创建和表单规则未在本轮重新验收，不能据本次导航通过宣称全模块终端已通过。
