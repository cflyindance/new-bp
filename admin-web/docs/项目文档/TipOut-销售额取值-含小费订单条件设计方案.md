# TipOut · 销售额取值条件 · 含小费订单过滤设计方案

> **模块**：团队管理 / 报表中心 → TipOut 小费池规则 → 销售额规则  
> **版本**：v1.0  
> **日期**：2026-07-13  
> **状态**：已落地（方案 1：可选条件「订单小费状态」；见 v1.1）  
> **场景**：美国餐馆行业；店主按「已付小费营业总额」计提扣点（如各台 2.5%）  
> **关联**：[订单中心-订单列表表头字段设计方案](./订单中心-订单列表表头字段设计方案.md)、`dist/TipOut/docs/TipOut计算公式.md`

## 一、背景与范围

### 1.1 客户反馈

老板需要按每位（各台）营业总数计提扣点（如 **2.5%**），且：

```text
营业总数 = 营业总额 − 未支付小费营业总额
         = 已付小费营业总额
```

即：**只把「含小费」的订单销售额纳入扣点基数**；不含小费的订单不纳入。

### 1.2 场景总结

| 条件 | 是否纳入销售额（扣点基数） |
|------|---------------------------|
| 包含小费的订单 | 纳入 |
| 不包含小费的订单 | 不纳入 |

### 1.3 本期范围

| 包含 | 不包含 |
|------|--------|
| 销售额取值条件新增「订单小费状态」 | 新营业额类型「已付小费营业总额」 |
| 含小费 / 不含小费判定与计算过滤 | 小费 / 加收 / Tip Claim 等其它条件抽屉 |
| 与现有计提占比（如 2.5%）组合使用 | 分配明细页 tipped / untipped 拆账 KPI |
| 未配置时向后兼容 | 存量规则自动写入 `has_tip`；新增「台」实体 |

### 1.4 锁定口径

| 项 | 结论 |
|----|------|
| 含小费判定 | 卡小费 **或** 现金小费 > `$0`；**不含** Service Charge |
| 金额口径 | 仍跟随条件中的「营业额类型」（Net Sales / Gross Sales 等） |
| 作用范围 | **仅**「销售额」池规则的销售额取值条件 |
| 未配置该条件 | 不按小费过滤（与线上一致，向后兼容） |
| 2.5% | 沿用规则「按销售额占比」计提比例，不另造字段 |

## 二、方案选择

| 方案 | 做法 | 结论 |
|------|------|------|
| **1 可选条件「订单小费状态」** | 销售额条件抽屉新增条件类型 | **采用** |
| 2 新营业额类型 | 在 Net/Gross 旁增加「已付小费营业额」 | 与金额类型正交维度混用，不采用 |
| 3 条件 + 明细拆账 KPI | 方案 1 + 分配页展示 tipped/untipped | 超出本期「取值条件」范围 |

**采用方案 1**：最小改动对齐客户公式；店主配置「含小费」+ 计提 2.5% 即可得到「已付小费营业总额 × 2.5%」。

## 三、字段定义与判定规则

### 3.1 条件类型

| 项 | 值 |
|----|-----|
| 中文名 | 订单小费状态 |
| 英文名 | Order Tip Status |
| 建议 key | `orderTipStatus` |
| 是否必填 | 否；未配置 = 不按小费过滤 |
| 出现位置 | 仅销售额取值条件抽屉「+ 新增条件」 |

### 3.2 枚举

| 取值 | 中文 | 英文 | 订单纳入规则 |
|------|------|------|----------------|
| `has_tip` | 含小费 | Has tip | 卡小费 **或** 现金小费 > `$0` |
| `no_tip` | 不含小费 | No tip | 卡小费 **且** 现金小费均为 `$0`（或空） |

本期客户场景使用 `has_tip`；提供 `no_tip` 便于对账「未支付小费营业总额」。

### 3.3 判定边界

| 场景 | 处理 |
|------|------|
| Service Charge > 0，小费为 0 | 视为 `no_tip`（服务费不算小费） |
| 仅卡小费 / 仅现金小费 > 0 | 视为 `has_tip` |
| 小费后退款至有效小费为 0 | 按**当前有效**卡/现金小费判定 |
| 未结账订单 | 小费通常为 0 → `no_tip`；是否进池仍受既有结账/状态规则约束 |
| 与其它条件关系 | **且（AND）**：角色 ∩ 区域 ∩ 时间 ∩ … ∩ `orderTipStatus` |
| 同规则内重复 | 该条件类型最多 1 个（与「营业额类型」同类约束） |

### 3.4 与客户公式对齐

```text
已付小费营业总额 = Σ 满足(其它条件 ∧ orderTipStatus=has_tip) 的「营业额类型」金额
未付小费营业总额 = Σ 满足(其它条件 ∧ orderTipStatus=no_tip) 的「营业额类型」金额
营业总数（扣点基数）= 已付小费营业总额
店主扣点           = 营业总数 × 计提占比（如 2.5%）
```

等价关系：

```text
营业总数 = 营业总额 − 未支付小费营业总额 = 已付小费营业总额
```

（在「其它条件」相同的前提下。）

小费与服务费分列口径与订单中心列表一致：自愿小费进 Card Tip / Cash Tip；强制加收进 Service Charge。

## 四、配置交互与计算链路

### 4.1 配置入口

路径：TipOut 小费池规则 → **销售额** 规则 → **销售额取值条件**。

「+ 新增条件」菜单增加：**订单小费状态**（与角色、员工、区域、订单类型、菜单、营业额类型、营业时间、班次、周期同级）。

小费取值条件、加收服务费取值条件、计提小费接受方（Tip Claim）取值条件、手动上报小费取值条件：**本期不加**该项。

### 4.2 配置步骤

| 步骤 | 行为 |
|------|------|
| 1 | 点「订单小费状态」→ 出现条件卡片（单选） |
| 2 | 选项：含小费 / 不含小费 |
| 3 | 提交后写入该销售额规则的 `salesConditions` |
| 4 | 删除条件卡片 = 恢复「不按小费过滤」 |

### 4.3 本场景推荐配置

1. 新建/编辑销售额池规则，计提占比 = **2.5%**（或店主实际比例）  
2. 销售额取值条件：按需配置角色 / 员工 / 区域等（表达「各台」）  
3. 营业额类型：按店主习惯选 Net Sales / Gross Sales  
4. 订单小费状态 = **含小费**

### 4.4 计算链路

沿用既有 TipOut 公式，仅在汇总前增加可选过滤：

```text
订单集合
  → 既有条件（角色 / 区域 / 时间 / 菜单 / 营业额类型 …）
  → [可选] orderTipStatus 过滤
  → Σ 营业额类型金额 = 符合条件总销售额 S
  → 小费池销售额金额 = S × r
  → 扣除方角色内按个人销售额比例分摊（见 TipOut计算公式.md）
```

符号版（与现有文档一致，`S` 增加小费状态约束）：

```text
个人扣除_i = ( Σ(所有选中员工) S_j × r ) × S_i / Σ(扣除方角色员工) S_k
```

其中 `S` = 满足区域、时间、菜单、**订单小费状态（若配置）** 等条件的销售额。

### 4.5 数据落库形态（示意）

```json
{
  "salesConditions": {
    "revenueType": "net_sales",
    "orderTipStatus": "has_tip"
  }
}
```

未配置时不写 `orderTipStatus`（或值为空），计算端视为不过滤。

## 六、验收标准

1. 销售额取值条件可增删「订单小费状态」；可选「含小费 / 不含小费」。  
2. `has_tip`：仅卡或现金小费 > `$0` 的订单计入；仅有 Service Charge 不算含小费。  
3. `no_tip`：卡且现金小费均为 `$0` 的订单计入。  
4. 未配置该条件时，计算与线上一致（不按小费过滤）。  
5. 配置 `has_tip` + 计提 2.5% 时：扣点基数 = 已付小费营业总额；池金额 = 该基数 × 2.5%；分摊公式不变。  
6. 条件只出现在销售额抽屉；其它取值条件抽屉无此项。
