## 公共业务规则

- 一个区域属于当前门店，一个餐位属于一个区域；列表与平面图共享同一套对象，不复制餐位数据。新增“餐位管理”入口位于“餐位平面图”之前，前厅默认入口仍沿用原平面图。无区域时先创建区域，不能创建无归属餐位。
- 两页属于同一编辑会话，互跳保留草稿，无离页丢弃提示；离开本模块沿用确认离开/取消保护。确认离开恢复业务基线，取消离开返回原地址与草稿。切门店不共用布局和历史。
- 表单“应用属性”、区域弹框“保存”、抽屉“创建餐位”只改变本模块草稿。唯一外部生效入口为底部“保存并下发”，先校验并归并表单，再展示变更，确认下发后才同步；预览和取消确认不写入外部系统。
- 保存失败保留业务草稿、待保存状态和错误提示，允许修正后重试。真实 KPOS 没有跨步骤事务，本次不承诺自动回滚部分成功，不修改/撤销已有操作账本。成功表示既有下发流程接受变更，不额外承诺所有终端已完成同步。
- 餐位管理沿用原平面图能力，权限、订阅及发布/预设过滤均复用原能力键，不创建新的授权范围。深层菜单继续复用 NAV-20261014-01 公共覆盖滑层。
- 当前已有约束继续生效：餐位名称去首尾空格并统一大写、在当前门店所有区域中唯一；人数为正整数；特殊类型需要对应关联字段；真实 KPOS 模式禁止删除区域、正在使用或当前人数大于0的餐位不能删除。

`areas`保存已应用到业务草稿的值；`tableDialog.mode=edit/create`与`dialogDraft`保存表单输入。dirty和变更预览以投影后的区域集合计算：edit替换对应ID，create暂映射为目标区域的待创建餐位；新增未确认时不得执行下发。

输入事件和select变更更新表单草稿而不重建DOM；编辑输入在切换餐位/区域、多选、撤销/重做、预览及保存前校验，有效值归并到areas，无效值保留并聚焦。尚未输入的表单不做浮点往返转换，不产生虚假diff。取消仅移除dialogDraft。离开整个模块确认丢弃时，从baseline恢复areas并清除历史及表单；模块内互跳不丢弃。

| rotation | number，整数步进，默认0，快捷值0/45/90/135/180/270；本地扩展，不新增KPOS旋转支持。 |
| category | standard/booth/bar/private/ktv，本地扩展分类，默认standard；输入命中既有中文/英文枚举；未识别沿用原值。 |
| durationBillingRuleId | 本次编辑须保留既有绑定值；不因重排表单清空，不新增计价绑定入口或算法。 |

## 画布与历史计算

![画布与上方区域切换](assets/floor-plan-workbench/layout.png)

图注：画布与上方区域切换；2026-10-15，本地原生 Vite 页面，本次变更版本；数据为隔离测试样例，不是线上门店数据。

![三项多选和基准显示](assets/floor-plan-workbench/multi-select.png)

图注：三项多选和基准显示；2026-10-15，本地原生 Vite 页面，本次变更版本；数据为隔离测试样例，不是线上门店数据。

- 逻辑画布恒为1000×650，显示尺寸=(1000z,650z)。首次z=min(容器宽/1000,容器高/650)，再限制为[0.5,1.5]；显示百分比Math.round(100z)。手动每次±0.1，随后限幅；不舍入业务坐标为显示百分比。
- 拖动增量dx=(clientX-startClientX)/z、dy同理，z取实际画布DOM宽/1000；滚动和容器位置不进入相对增量。新增预览使用相同换算。
- 以其他餐位左右/水平中心、上下/垂直中心为目标，与移动餐位相应边缘/中心比较；屏幕容差6px，即逻辑6/z，选择距离最近的合法目标；吸附时显示参考线。边界先限制x∈[0,1000-width]、y∈[0,650-height]，最终坐标取整数；旋转后包围盒沿用历史实现，不新增碰撞承诺。
- 对齐/统一尺寸至少2项，分布至少3项，尺寸和位移至少1项。首个选择为基准；尺寸增减5逻辑单位，统一和对齐沿用floor-plan-geometry，超界则整次拒绝。
- 一次pointerup形成一步历史；pointercancel取消位移；业务数组相同不记历史。撤销把current推入future，重做将current推入past；新业务修改清空future。

## 提交状态机

![确认下发前的变更预览](assets/floor-plan-workbench/save-confirm.png)

图注：确认下发前的变更预览；2026-10-15，本地原生 Vite 页面，本次变更版本；数据为隔离测试样例，不是线上门店数据。

![模拟HTTP503后待保存状态保留](assets/floor-plan-workbench/save-failure.png)

图注：模拟HTTP503后待保存状态保留；2026-10-15，本地原生 Vite 页面，本次变更版本；数据为隔离测试样例，不是线上门店数据。

`编辑输入 → 校验/归并草稿 → 生成diff → 变更确认 → 确认后提交钩子 → 既有下发流程 → saved事件刷新baseline并清空历史`。

`registerPageSavePreCommit`只校验/生成diff，预览复用此钩子；`registerPageSaveCommit`仅在确认框返回有效scope后执行。确认前、查看待保存预览、取消、重复点击均不得发送额外Save/Delete。按规范化页面键设置pending锁，finally释放，失败可再次操作。确认后外部同步失败返回false，不consumePageConfigChanges，不发saved事件，不清空baseline/历史。

真实模式沿用单餐位属性→回读→区域布局的既有顺序及IndexedDB操作账本。部分成功不自动重放或回滚。新增区域同步是否受主机接口限制、失联后的人工对账和最终终端状态属于既有集成边界，未由本次交互重构重新承诺。

|---|---|---|

| 保存成功 | 本地演示创建区域及餐位后确认下发 | 已保存提示、dirty清空、撤销历史清空；仅为本地流程验收 |
