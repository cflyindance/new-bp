# PIT 本地局域网服务器运行手册

## 安全边界

PIT 使用 HTTP，仅支持受信任的同一局域网。严禁把 3020 端口映射、转发或直接开放到公网，也不支持在不可信网络中使用；增加 HTTPS 反向代理本身不会扩大这一支持边界。

## 安装、构建与启动

1. 安装 Node.js 24，并在项目目录执行 `npm install`。
2. 执行 `npm run build`。
3. 执行 `npm run pit:start`。默认监听 `0.0.0.0:3020`，数据目录为 `.data/pit`。
4. 可在 PowerShell 中先设置 `$env:PIT_DATA_DIR='D:\PIT-data'`、`$env:PIT_PORT='3020'` 再启动。
5. 控制台会打印本机地址、私有 IPv4 地址，以及无用户时的一次性首管理员初始化 token。token 仅在服务器本机控制台读取。

## Windows 私网防火墙

以管理员身份在“Windows Defender 防火墙（高级安全）”中新增入站 TCP 3020 规则，只勾选“专用”配置文件，不勾选“公用”。程序不会静默修改防火墙。随后从第二台同局域网电脑访问控制台打印的 `http://192.168.x.x:3020/`，使用非管理员 PIT 账号登录，打开列表、详情并下载一次导出。不可使用公网 IP 或路由器端口转发。

## 首次导入

管理员进入“首次导入”，上传 `.xlsx`，先核对预检总数、重复组、缺失 Ticket、未知状态、未知字典和重点需求匹配，再完成所有阻断决策。正式提交前系统创建操作前备份。首次提交成功后导入永久锁定，不能在线增量导入或覆盖导入；重新初始化必须停服、备份并创建全新数据库。

## 备份、保留与下载

- 服务启动、迁移和正式导入前创建操作备份。
- 每日备份保留最近 14 份；操作前备份保留最近 5 份。
- 手工备份不自动删除。
- 每份备份配套 manifest，包含时间、schema、大小和 SHA-256。

## 停服恢复

1. 停止 PIT 服务，确认没有 PIT Node 进程占用数据目录。
2. 保存当前数据目录副本。
3. 执行 `npm run pit:restore -- pit-manual-20260831.sqlite3`。相对参数以当前 PIT 配置解析出的 `backups` 目录为基准，不是以项目工作目录为基准；也可传入该 `backups` 目录内文件的绝对路径。若设置了 `PIT_DATA_DIR`，请使用该数据目录下的 `backups` 子目录，并在恢复时保持相同配置。
4. 恢复命令会先创建 `pre_restore` 备份，再校验 SQLite 完整性和 migration 版本。失败时程序会自动回滚原数据库；仅当自动回滚校验也失败时，才保持服务停止并按控制台输出的 `pre_restore` 路径手工恢复。
5. 重新执行 `npm run pit:start`，检查 `/api/v1/pit/health` 后，再从第二台局域网电脑复验。
